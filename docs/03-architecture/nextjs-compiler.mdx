Trình biên dịch Next.js, được viết bằng Rust sử dụng [SWC](https://swc.rs/), cho phép Next.js chuyển đổi và thu nhỏ mã JavaScript của bạn cho môi trường production. Điều này thay thế Babel cho các tệp riêng lẻ và Terser để thu nhỏ các gói đầu ra.

Việc biên dịch sử dụng Trình biên dịch Next.js nhanh hơn 17 lần so với Babel và được bật mặc định kể từ Next.js phiên bản 12. Nếu bạn có cấu hình Babel hiện có hoặc đang sử dụng [các tính năng không được hỗ trợ](#unsupported-features), ứng dụng của bạn sẽ từ chối Trình biên dịch Next.js và tiếp tục sử dụng Babel.

## Tại sao lại là SWC?

[SWC](https://swc.rs/) là một nền tảng dựa trên Rust có thể mở rộng cho thế hệ công cụ phát triển nhanh tiếp theo.

SWC có thể được sử dụng để biên dịch, thu nhỏ, đóng gói và hơn thế nữa – và được thiết kế để có thể mở rộng. Nó là thứ bạn có thể gọi để thực hiện các chuyển đổi mã (tích hợp sẵn hoặc tùy chỉnh). Việc chạy các chuyển đổi đó diễn ra thông qua các công cụ cấp cao hơn như Next.js.

Chúng tôi chọn xây dựng dựa trên SWC vì một vài lý do:

- **Khả năng mở rộng:** SWC có thể được sử dụng như một Crate bên trong Next.js, mà không cần phải fork thư viện hoặc tìm cách giải quyết các hạn chế về thiết kế.
- **Hiệu suất:** Chúng tôi đã đạt được Fast Refresh nhanh hơn ~3 lần và build nhanh hơn ~5 lần trong Next.js bằng cách chuyển sang SWC, với nhiều không gian để tối ưu hóa vẫn đang được tiến hành.
- **WebAssembly:** Sự hỗ trợ của Rust cho WASM là điều cần thiết để hỗ trợ mọi nền tảng có thể và đưa việc phát triển Next.js đi khắp mọi nơi.
- **Cộng đồng:** Cộng đồng và hệ sinh thái Rust rất tuyệt vời và vẫn đang phát triển.

## Các tính năng được hỗ trợ

### Styled Components

Chúng tôi đang làm việc để port `babel-plugin-styled-components` sang Trình biên dịch Next.js.

Đầu tiên, hãy cập nhật lên phiên bản mới nhất của Next.js: `npm install next@latest`. Sau đó, cập nhật tệp `next.config.js` của bạn:

```js filename="next.config.js"
module.exports = {
  compiler: {
    styledComponents: true,
  },
}
```

Đối với các trường hợp sử dụng nâng cao, bạn có thể định cấu hình các thuộc tính riêng lẻ cho việc biên dịch styled-components.

> Lưu ý: `ssr` và `displayName` transforms là yêu cầu chính để sử dụng `styled-components` trong Next.js.

```js filename="next.config.js"
module.exports = {
  compiler: {
    // xem https://styled-components.com/docs/tooling#babel-plugin để biết thêm thông tin về các tùy chọn.
    styledComponents: {
      // Được bật mặc định trong development, bị tắt trong production để giảm kích thước tệp,
      // thiết lập này sẽ ghi đè mặc định cho tất cả các môi trường.
      displayName?: boolean,
      // Được bật mặc định.
      ssr?: boolean,
      // Được bật mặc định.
      fileName?: boolean,
      // Trống theo mặc định.
      topLevelImportPaths?: string[],
      // Mặc định là ["index"].
      meaninglessFileNames?: string[],
      // Được bật mặc định.
      minify?: boolean,
      // Được bật mặc định.
      transpileTemplateLiterals?: boolean,
      // Trống theo mặc định.
      namespace?: string,
      // Bị tắt mặc định.
      pure?: boolean,
      // Được bật mặc định.
      cssProp?: boolean,
    },
  },
}
```

### Jest

Trình biên dịch Next.js chuyển đổi (transpiles) các bài kiểm tra của bạn và đơn giản hóa việc định cấu hình Jest cùng với Next.js bao gồm:

- Tự động mock `.css`, `.module.css` (và các biến thể `.scss` của chúng), và import hình ảnh
- Tự động thiết lập `transform` sử dụng SWC
- Tải `.env` (và tất cả các biến thể) vào `process.env`
- Bỏ qua `node_modules` khỏi test resolving và transforms
- Bỏ qua `.next` khỏi test resolving
- Tải `next.config.js` cho các cờ kích hoạt các chuyển đổi SWC thử nghiệm

Đầu tiên, hãy cập nhật lên phiên bản mới nhất của Next.js: `npm install next@latest`. Sau đó, cập nhật tệp `jest.config.js` của bạn:

```js filename="jest.config.js"
const nextJest = require('next/jest')

// Cung cấp đường dẫn đến ứng dụng Next.js của bạn, sẽ cho phép tải các tệp next.config.js và .env
const createJestConfig = nextJest({ dir: './' })

// Bất kỳ cấu hình tùy chỉnh nào bạn muốn chuyển cho Jest
const customJestConfig = {
  setupFilesAfterEnv: ['<rootDir>/jest.setup.js'],
}

// createJestConfig được xuất theo cách này để đảm bảo rằng next/jest có thể tải cấu hình Next.js, vốn là bất đồng bộ
module.exports = createJestConfig(customJestConfig)
```

### Relay

Để kích hoạt hỗ trợ [Relay](https://relay.dev/):

```js filename="next.config.js"
module.exports = {
  compiler: {
    relay: {
      // Điều này nên khớp với relay.config.js
      src: './',
      artifactDirectory: './__generated__',
      language: 'typescript',
      eagerEsModules: false,
    },
  },
}
```

> **Cần biết**: Trong Next.js, tất cả các tệp JavaScript trong thư mục `pages` được coi là các route. Vì vậy, đối với `relay-compiler`, bạn sẽ cần chỉ định cài đặt cấu hình `artifactDirectory` bên ngoài `pages`, nếu không `relay-compiler` sẽ tạo các tệp bên cạnh tệp nguồn trong thư mục `__generated__`, và tệp này sẽ được coi là một route, điều này sẽ làm hỏng các bản build production.

### Remove React Properties

Cho phép xóa các thuộc tính JSX. Điều này thường được sử dụng cho testing. Tương tự như `babel-plugin-react-remove-properties`.

Để xóa các thuộc tính khớp với regex mặc định `^data-test`:

```js filename="next.config.js"
module.exports = {
  compiler: {
    reactRemoveProperties: true,
  },
}
```

Để xóa các thuộc tính tùy chỉnh:

```js filename="next.config.js"
module.exports = {
  compiler: {
    // Các regex được định nghĩa ở đây được xử lý trong Rust nên cú pháp khác với
    // JavaScript `RegExp`s. Xem https://docs.rs/regex.
    reactRemoveProperties: { properties: ['^data-custom$'] },
  },
}
```

### Remove Console

Chuyển đổi này cho phép xóa tất cả các lệnh gọi `console.*` trong mã ứng dụng (không phải `node_modules`). Tương tự như `babel-plugin-transform-remove-console`.

Xóa tất cả các lệnh gọi `console.*`:

```js filename="next.config.js"
module.exports = {
  compiler: {
    removeConsole: true,
  },
}
```

Xóa đầu ra `console.*` ngoại trừ `console.error`:

```js filename="next.config.js"
module.exports = {
  compiler: {
    removeConsole: {
      exclude: ['error'],
    },
  },
}
```

### Legacy Decorators

Next.js sẽ tự động phát hiện `experimentalDecorators` trong `jsconfig.json` hoặc `tsconfig.json`. Legacy decorators thường được sử dụng với các phiên bản cũ hơn của các thư viện như `mobx`.

Cờ này chỉ được hỗ trợ để tương thích với các ứng dụng hiện có. Chúng tôi không khuyên bạn nên sử dụng legacy decorators trong các ứng dụng mới.

Đầu tiên, hãy cập nhật lên phiên bản mới nhất của Next.js: `npm install next@latest`. Sau đó, cập nhật tệp `jsconfig.json` hoặc `tsconfig.json` của bạn:

```js
{
  "compilerOptions": {
    "experimentalDecorators": true
  }
}
```

### importSource

Next.js sẽ tự động phát hiện `jsxImportSource` trong `jsconfig.json` hoặc `tsconfig.json` và áp dụng nó. Điều này thường được sử dụng với các thư viện như [Theme UI](https://theme-ui.com).

Đầu tiên, hãy cập nhật lên phiên bản mới nhất của Next.js: `npm install next@latest`. Sau đó, cập nhật tệp `jsconfig.json` hoặc `tsconfig.json` của bạn:

```js
{
  "compilerOptions": {
    "jsxImportSource": "theme-ui"
  }
}
```

### Emotion

Chúng tôi đang làm việc để port `@emotion/babel-plugin` sang Trình biên dịch Next.js.

Đầu tiên, hãy cập nhật lên phiên bản mới nhất của Next.js: `npm install next@latest`. Sau đó, cập nhật tệp `next.config.js` của bạn:

```js filename="next.config.js"

module.exports = {
  compiler: {
    emotion: boolean | {
      // mặc định là true. Nó sẽ bị tắt khi loại build là production.
      sourceMap?: boolean,
      // mặc định là 'dev-only'.
      autoLabel?: 'never' | 'dev-only' | 'always',
      // mặc định là '[local]'.
      // Các giá trị được phép: `[local]` `[filename]` và `[dirname]`
      // Tùy chọn này chỉ hoạt động khi autoLabel được đặt thành 'dev-only' hoặc 'always'.
      // Nó cho phép bạn xác định định dạng của nhãn kết quả.
      // Định dạng được xác định qua chuỗi trong đó các phần biến được bao quanh trong dấu ngoặc vuông [].
      // Ví dụ labelFormat: "my-classname--[local]", trong đó [local] sẽ được thay thế bằng tên của biến mà kết quả được gán cho.
      labelFormat?: string,
      // mặc định là undefined.
      // Tùy chọn này cho phép bạn cho trình biên dịch biết nó nên xem xét các import nào
      // để xác định những gì nó nên chuyển đổi, vì vậy nếu bạn re-export
      // các export của Emotion, bạn vẫn có thể sử dụng các chuyển đổi.
      importMap?: {
        [packageName: string]: {
          [exportName: string]: {
            canonicalImport?: [string, string],
            styledBaseImport?: [string, string],
          }
        }
      },
    },
  },
}
```

### Minification (Thu nhỏ)

Trình biên dịch swc của Next.js được sử dụng để thu nhỏ theo mặc định kể từ v13. Nó nhanh hơn 7 lần so với Terser.

> **Cần biết:** Bắt đầu từ v15, việc thu nhỏ không thể được tùy chỉnh bằng `next.config.js`. Hỗ trợ cho cờ `swcMinify` đã bị loại bỏ.

### Module Transpilation (Chuyển đổi Module)

Next.js có thể tự động chuyển đổi và đóng gói các phụ thuộc từ các gói cục bộ (như monorepos) hoặc từ các phụ thuộc bên ngoài (`node_modules`). Điều này thay thế gói `next-transpile-modules`.

```js filename="next.config.js"
module.exports = {
  transpilePackages: ['@acme/ui', 'lodash-es'],
}
```

### Modularize Imports (Mô-đun hóa Import)

Tùy chọn này đã được thay thế bởi [`optimizePackageImports`](/docs/app/api-reference/config/next-config-js/optimizePackageImports) trong Next.js 13.5. Chúng tôi khuyên bạn nên nâng cấp để sử dụng tùy chọn mới không yêu cầu cấu hình thủ công các đường dẫn import.

### Define (Thay thế biến trong quá trình build)

Tùy chọn `define` cho phép bạn thay thế tĩnh các biến trong mã của mình tại thời điểm build.
Tùy chọn này nhận một đối tượng dưới dạng các cặp key-value, trong đó các key là các biến cần được thay thế bằng các giá trị tương ứng.

Sử dụng trường `compiler.define` trong `next.config.js` để định nghĩa các biến cho tất cả các môi trường (server, edge, và client). Hoặc, sử dụng `compiler.defineServer` để định nghĩa các biến chỉ cho mã phía máy chủ (server và edge):

```js filename="next.config.js"
module.exports = {
  compiler: {
    define: {
      MY_VARIABLE: 'my-string',
      'process.env.MY_ENV_VAR': 'my-env-var',
    },
    defineServer: {
      MY_SERVER_VARIABLE: 'my-server-var',
    },
  },
}
```

### Build Lifecycle Hooks (Hooks Vòng đời Build)

Trình biên dịch Next.js hỗ trợ các lifecycle hooks cho phép bạn chạy mã tùy chỉnh tại các điểm cụ thể trong quá trình build. Hiện tại, hook sau được hỗ trợ:

#### runAfterProductionCompile

Một hàm hook thực thi sau khi quá trình biên dịch build production kết thúc, nhưng trước khi chạy các tác vụ sau biên dịch như kiểm tra kiểu (type checking) và tạo trang tĩnh. Hook này cung cấp quyền truy cập vào siêu dữ liệu dự án bao gồm thư mục dự án và thư mục đầu ra build, làm cho nó hữu ích cho các công cụ của bên thứ ba để thu thập các kết quả build như sourcemaps.

```js filename="next.config.js"
module.exports = {
  compiler: {
    runAfterProductionCompile: async ({ distDir, projectDir }) => {
      // Mã tùy chỉnh của bạn ở đây
    },
  },
}
```

Hook nhận một đối tượng với các thuộc tính sau:

- `distDir`: Thư mục đầu ra build (mặc định là `.next`)
- `projectDir`: Thư mục gốc của dự án

## Các tính năng thử nghiệm

### SWC Trace profiling

Bạn có thể tạo các dấu vết chuyển đổi nội bộ của SWC dưới dạng [định dạng sự kiện dấu vết](https://docs.google.com/document/d/1CvAClvFfyA5R-PhYUmn5OOQtYMH4h6I0nSsKchNAySU/preview?mode=html#%21=) của chromium.

```js filename="next.config.js"
module.exports = {
  experimental: {
    swcTraceProfiling: true,
  },
}
```

Sau khi được bật, swc sẽ tạo dấu vết có tên là `swc-trace-profile-${timestamp}.json` dưới `.next/`. Trình xem dấu vết của Chromium (chrome://tracing/, https://ui.perfetto.dev/), hoặc trình xem flamegraph tương thích (https://www.speedscope.app/) có thể tải và hiển thị các dấu vết đã tạo.

### SWC Plugins (thử nghiệm)

Bạn có thể định cấu hình chuyển đổi của swc để sử dụng hỗ trợ plugin thử nghiệm của SWC được viết bằng wasm để tùy chỉnh hành vi chuyển đổi.

```js filename="next.config.js"
module.exports = {
  experimental: {
    swcPlugins: [
      [
        'plugin',
        {
          ...pluginOptions,
        },
      ],
    ],
  },
}
```

`swcPlugins` chấp nhận một mảng các bộ giá trị (tuples) để định cấu hình plugin. Một bộ giá trị cho plugin chứa đường dẫn đến plugin và một đối tượng cho cấu hình plugin. Đường dẫn đến plugin có thể là tên gói mô-đun npm hoặc đường dẫn tuyệt đối đến chính tệp nhị phân `.wasm`.

## Các tính năng không được hỗ trợ

Khi ứng dụng của bạn có tệp `.babelrc`, Next.js sẽ tự động quay lại sử dụng Babel để chuyển đổi các tệp riêng lẻ. Điều này đảm bảo khả năng tương thích ngược với các ứng dụng hiện có tận dụng các plugin Babel tùy chỉnh.

Nếu bạn đang sử dụng thiết lập Babel tùy chỉnh, [vui lòng chia sẻ cấu hình của bạn](https://github.com/vercel/next.js/discussions/30174). Chúng tôi đang làm việc để port càng nhiều chuyển đổi Babel thường được sử dụng càng tốt, cũng như hỗ trợ các plugin trong tương lai.
