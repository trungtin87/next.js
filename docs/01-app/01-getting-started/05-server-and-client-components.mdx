Theo mặc định, layouts và pages là [Server Components](https://react.dev/reference/rsc/server-components), cho phép bạn fetch dữ liệu và render các phần của UI trên server, tùy chọn cache kết quả, và stream nó đến client. Khi bạn cần tính tương tác hoặc browser APIs, bạn có thể sử dụng [Client Components](https://react.dev/reference/rsc/use-client) để thêm vào các chức năng.

Trang này giải thích cách Server và Client Components hoạt động trong Next.js và khi nào nên sử dụng chúng, với các ví dụ về cách kết hợp chúng cùng nhau trong ứng dụng của bạn.

## Khi nào sử dụng Server và Client Components?

Môi trường client và server có các khả năng khác nhau. Server và Client components cho phép bạn chạy logic trong mỗi môi trường tùy thuộc vào trường hợp sử dụng của bạn.

Sử dụng **Client Components** khi bạn cần:

- [State](https://react.dev/learn/managing-state) và [event handlers](https://react.dev/learn/responding-to-events). Ví dụ: `onClick`, `onChange`.
- [Lifecycle logic](https://react.dev/learn/lifecycle-of-reactive-effects). Ví dụ: `useEffect`.
- Browser-only APIs. Ví dụ: `localStorage`, `window`, `Navigator.geolocation`, v.v.
- [Custom hooks](https://react.dev/learn/reusing-logic-with-custom-hooks).

Sử dụng **Server Components** khi bạn cần:

- Fetch dữ liệu từ databases hoặc APIs gần nguồn.
- Sử dụng API keys, tokens, và các bí mật khác mà không để lộ cho client.
- Giảm lượng JavaScript gửi đến trình duyệt.
- Cải thiện [First Contentful Paint (FCP)](https://web.dev/fcp/), và stream nội dung dần dần đến client.

Ví dụ, component `<Page>` là một Server Component fetch dữ liệu về một bài đăng, và truyền nó dưới dạng props cho `<LikeButton>`, component này xử lý tính tương tác phía client.

```tsx filename="app/[id]/page.tsx" highlight={1,12} switcher
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const post = await getPost(id)

  return (
    <div>
      <main>
        <h1>{post.title}</h1>
        {/* ... */}
        <LikeButton likes={post.likes} />
      </main>
    </div>
  )
}
```

```jsx filename="app/[id]/page.js" highlight={1,12} switcher
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({ params }) {
  const post = await getPost(params.id)

  return (
    <div>
      <main>
        <h1>{post.title}</h1>
        {/* ... */}
        <LikeButton likes={post.likes} />
      </main>
    </div>
  )
}
```

```tsx filename="app/ui/like-button.tsx" highlight={1} switcher
'use client'

import { useState } from 'react'

  // ...
}
```

```jsx filename="app/ui/like-button.js" highlight={1} switcher

  // ...
```

## Server và Client Components hoạt động như thế nào trong Next.js?

### Trên server

Trên server, Next.js sử dụng các API của React để điều phối việc rendering. Công việc rendering được chia thành các phần (chunks), theo từng route segments riêng lẻ ([layouts và pages](/docs/app/getting-started/layouts-and-pages)):

- **Server Components** được render thành một định dạng dữ liệu đặc biệt gọi là React Server Component Payload (RSC Payload).
- **Client Components** và RSC Payload được sử dụng để [pre-render](/docs/app/guides/caching#rendering-strategies) HTML.

> **React Server Component Payload (RSC) là gì?**
>
> RSC Payload là một biểu diễn nhị phân nhỏ gọn của cây React Server Components đã được render. Nó được React sử dụng trên client để cập nhật DOM của trình duyệt. RSC Payload chứa:
>
> - Kết quả render của Server Components
> - Các placeholders cho nơi Client Components sẽ được render và tham chiếu đến các file JavaScript của chúng
> - Bất kỳ props nào được truyền từ Server Component sang Client Component

### Trên client (lần tải đầu tiên)

Sau đó, trên client:

1. **HTML** được sử dụng để hiển thị ngay lập tức bản xem trước nhanh không tương tác của route cho người dùng.
2. **RSC Payload** được sử dụng để đối chiếu (reconcile) cây Client và Server Component.
3. **JavaScript** được sử dụng để hydrate Client Components và làm cho ứng dụng có tính tương tác.

> **Hydration là gì?**
>
> Hydration là quá trình React gắn các [event handlers](https://react.dev/learn/responding-to-events) vào DOM, để làm cho HTML tĩnh trở nên tương tác.

### Các lần điều hướng tiếp theo

Trong các lần điều hướng tiếp theo:

- **RSC Payload** được prefetched và cached để điều hướng tức thì.
- **Client Components** được render hoàn toàn trên client, không có HTML được render từ server.

## Ví dụ

### Sử dụng Client Components

Bạn có thể tạo một Client Component bằng cách thêm directive [`"use client"`](https://react.dev/reference/react/use-client) ở đầu file, phía trên các imports của bạn.

```tsx filename="app/ui/counter.tsx" highlight={1} switcher
'use client'

import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>{count} likes</p>
      <button onClick={() => setCount(count + 1)}>Click me</button>
    </div>
  )
}
```

```jsx filename="app/ui/counter.js" highlight={1} switcher
'use client'

import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>{count} likes</p>
      <button onClick={() => setCount(count + 1)}>Click me</button>
    </div>
  )
}
```

`"use client"` được sử dụng để khai báo một **ranh giới** giữa các biểu đồ module (cây) Server và Client.

Khi một file được đánh dấu với `"use client"`, **tất cả các imports và child components của nó được coi là một phần của client bundle**. Điều này có nghĩa là bạn không cần thêm directive vào mọi component dành cho client.

### Giảm kích thước JS bundle

Để giảm kích thước của các gói JavaScript client, hãy thêm `'use client'` vào các interactive components cụ thể thay vì đánh dấu các phần lớn của UI là Client Components.

Ví dụ, component `<Layout>` chứa chủ yếu các phần tử tĩnh như logo và các liên kết điều hướng, nhưng bao gồm một thanh tìm kiếm tương tác. `<Search />` là tương tác và cần phải là một Client Component, tuy nhiên, phần còn lại của layout có thể vẫn là một Server Component.

```tsx filename="app/layout.tsx" highlight={12} switcher
// Client Component
import Search from './search'
// Server Component
import Logo from './logo'

// Layout is a Server Component by default
export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <nav>
        <Logo />
        <Search />
      </nav>
      <main>{children}</main>
    </>
  )
}
```

```jsx filename="app/layout.js" highlight={12} switcher
// Client Component
import Search from './search'
// Server Component
import Logo from './logo'

// Layout is a Server Component by default
export default function Layout({ children }) {
  return (
    <>
      <nav>
        <Logo />
        <Search />
      </nav>
      <main>{children}</main>
    </>
  )
}
```

```tsx filename="app/ui/search.tsx" highlight={1} switcher
'use client'

export default function Search() {
  // ...
}
```

```jsx filename="app/ui/search.js" highlight={1} switcher
'use client'

export default function Search() {
  // ...
}
```

### Truyền dữ liệu từ Server sang Client Components

Bạn có thể truyền dữ liệu từ Server Components sang Client Components bằng cách sử dụng props.

```tsx filename="app/[id]/page.tsx" highlight={1,7} switcher
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const post = await getPost(id)

  return <LikeButton likes={post.likes} />
}
```

```jsx filename="app/[id]/page.js" highlight={1,7} switcher
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({ params }) {
  const post = await getPost(params.id)

  return <LikeButton likes={post.likes} />
}
```

```tsx filename="app/ui/like-button.tsx" highlight={1} switcher
'use client'

export default function LikeButton({ likes }: { likes: number }) {
  // ...
}
```

```jsx filename="app/ui/like-button.js" highlight={1} switcher
'use client'

export default function LikeButton({ likes }) {
  // ...
}
```

Ngoài ra, bạn có thể stream dữ liệu từ Server Component sang Client Component với [`use` Hook](https://react.dev/reference/react/use). Xem một [ví dụ](/docs/app/getting-started/fetching-data#streaming-data-with-the-use-hook).

> **Lưu ý**: Props được truyền cho Client Components cần phải [serializable](https://react.dev/reference/react/use-server#serializable-parameters-and-return-values) bởi React.

### Đan xen Server và Client Components

Bạn có thể truyền Server Components như một prop cho một Client Component. Điều này cho phép bạn lồng UI được render bởi server bên trong Client components một cách trực quan.

Một pattern phổ biến là sử dụng `children` để tạo một _slot_ trong một `<ClientComponent>`. Ví dụ, một component `<Cart>` fetch dữ liệu trên server, bên trong một component `<Modal>` sử dụng client state để chuyển đổi khả năng hiển thị.

```tsx filename="app/ui/modal.tsx" switcher
'use client'

export default function Modal({ children }: { children: React.ReactNode }) {
  return <div>{children}</div>
}
```

```jsx filename="app/ui/modal.js" switcher
'use client'

export default function Modal({ children }) {
  return <div>{children}</div>
}
```

Sau đó, trong một parent Server Component (ví dụ `<Page>`), bạn có thể truyền một `<Cart>` làm con của `<Modal>`:

```tsx filename="app/page.tsx"  highlight={7} switcher
import Modal from './ui/modal'
import Cart from './ui/cart'

export default function Page() {
  return (
    <Modal>
      <Cart />
    </Modal>
  )
}
```

```jsx filename="app/page.js" highlight={7} switcher
import Modal from './ui/modal'
import Cart from './ui/cart'

export default function Page() {
  return (
    <Modal>
      <Cart />
    </Modal>
  )
}
```

Trong pattern này, tất cả Server Components sẽ được render trên server trước thời hạn, bao gồm cả những component là props. RSC payload kết quả sẽ chứa các tham chiếu về nơi Client Components sẽ được render trong component tree.

### Context providers

[React context](https://react.dev/learn/passing-data-deeply-with-context) thường được sử dụng để chia sẻ global state như theme hiện tại. Tuy nhiên, React context không được hỗ trợ trong Server Components.

Để sử dụng context, tạo một Client Component chấp nhận `children`:

```tsx filename="app/theme-provider.tsx" switcher
'use client'

import { createContext } from 'react'

export const ThemeContext = createContext({})

export default function ThemeProvider({
  children,
}: {
  children: React.ReactNode
}) {
  return <ThemeContext.Provider value="dark">{children}</ThemeContext.Provider>
}
```

```jsx filename="app/theme-provider.js" switcher
'use client'

import { createContext } from 'react'

export const ThemeContext = createContext({})

export default function ThemeProvider({ children }) {
  return <ThemeContext.Provider value="dark">{children}</ThemeContext.Provider>
}
```

Sau đó, import nó vào một Server Component (ví dụ `layout`):

```tsx filename="app/layout.tsx" switcher
import ThemeProvider from './theme-provider'

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html>
      <body>
        <ThemeProvider>{children}</ThemeProvider>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
import ThemeProvider from './theme-provider'

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <ThemeProvider>{children}</ThemeProvider>
      </body>
    </html>
  )
}
```

Server Component của bạn bây giờ sẽ có thể render trực tiếp provider của bạn, và tất cả các Client Components khác trong ứng dụng của bạn sẽ có thể tiêu thụ context này.

> **Lưu ý**: Bạn nên render providers sâu nhất có thể trong cây - lưu ý cách `ThemeProvider` chỉ bao bọc `{children}` thay vì toàn bộ tài liệu `<html>`. Điều này giúp Next.js dễ dàng tối ưu hóa các phần tĩnh của Server Components của bạn hơn.

### Third-party components

Khi sử dụng một third-party component dựa vào các tính năng client-only, bạn có thể bọc nó trong một Client Component để đảm bảo nó hoạt động như mong đợi.

Ví dụ, `<Carousel />` có thể được import từ package `acme-carousel`. Component này sử dụng `useState`, nhưng nó chưa có directive `"use client"`.

Nếu bạn sử dụng `<Carousel />` bên trong một Client Component, nó sẽ hoạt động như mong đợi:

```tsx filename="app/gallery.tsx" switcher
'use client'

import { useState } from 'react'
import { Carousel } from 'acme-carousel'

export default function Gallery() {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <div>
      <button onClick={() => setIsOpen(true)}>View pictures</button>
      {/* Works, since Carousel is used within a Client Component */}
      {isOpen && <Carousel />}
    </div>
  )
}
```

```jsx filename="app/gallery.js" switcher
'use client'

import { useState } from 'react'
import { Carousel } from 'acme-carousel'

export default function Gallery() {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <div>
      <button onClick={() => setIsOpen(true)}>View pictures</button>
      {/*  Works, since Carousel is used within a Client Component */}
      {isOpen && <Carousel />}
    </div>
  )
}
```

Tuy nhiên, nếu bạn cố gắng sử dụng nó trực tiếp bên trong một Server Component, bạn sẽ thấy một lỗi. Điều này là do Next.js không biết `<Carousel />` đang sử dụng các tính năng client-only.

Để khắc phục điều này, bạn có thể bọc các third-party components dựa vào các tính năng client-only trong Client Components của riêng bạn:

```tsx filename="app/carousel.tsx" switcher
'use client'

import { Carousel } from 'acme-carousel'

export default Carousel
```

```jsx filename="app/carousel.js" switcher
'use client'

import { Carousel } from 'acme-carousel'

export default Carousel
```

Bây giờ, bạn có thể sử dụng `<Carousel />` trực tiếp bên trong một Server Component:

```tsx filename="app/page.tsx" switcher
import Carousel from './carousel'

export default function Page() {
  return (
    <div>
      <p>View pictures</p>
      {/*  Works, since Carousel is a Client Component */}
      <Carousel />
    </div>
  )
}
```

```jsx filename="app/page.js" switcher
import Carousel from './carousel'

export default function Page() {
  return (
    <div>
      <p>View pictures</p>
      {/*  Works, since Carousel is a Client Component */}
      <Carousel />
    </div>
  )
}
```

> **Lời khuyên cho các tác giả thư viện**
>
> Nếu bạn đang xây dựng một thư viện component, hãy thêm directive `"use client"` vào các entry points dựa vào các tính năng client-only. Điều này cho phép người dùng của bạn import components vào Server Components mà không cần tạo wrappers.
>
> Đáng chú ý là một số bundlers có thể loại bỏ các directives `"use client"`. Bạn có thể tìm thấy một ví dụ về cách cấu hình esbuild để bao gồm directive `"use client"` trong các kho lưu trữ [React Wrap Balancer](https://github.com/shuding/react-wrap-balancer/blob/main/tsup.config.ts#L10-L13) và [Vercel Analytics](https://github.com/vercel/analytics/blob/main/packages/web/tsup.config.js#L26-L30).

### Ngăn chặn environment poisoning

Các module JavaScript có thể được chia sẻ giữa cả Server và Client Components modules. Điều này có nghĩa là có thể vô tình import mã server-only vào client. Ví dụ, hãy xem xét hàm sau:

```ts filename="lib/data.ts" switcher
export async function getData() {
  const res = await fetch('https://external-service.com/data', {
    headers: {
      authorization: process.env.API_KEY,
    },
  })

  return res.json()
}
```

```js filename="lib/data.js" switcher
export async function getData() {
  const res = await fetch('https://external-service.com/data', {
    headers: {
      authorization: process.env.API_KEY,
    },
  })

  return res.json()
}
```

Hàm này chứa một `API_KEY` không bao giờ được để lộ cho client.

Trong Next.js, chỉ các biến môi trường có tiền tố `NEXT_PUBLIC_` mới được bao gồm trong client bundle. Nếu các biến không có tiền tố, Next.js thay thế chúng bằng một chuỗi rỗng.

Kết quả là, mặc dù `getData()` có thể được import và thực thi trên client, nó sẽ không hoạt động như mong đợi.

Để ngăn chặn việc sử dụng ngẫu nhiên trong Client Components, bạn có thể sử dụng [`server-only` package](https://www.npmjs.com/package/server-only).

Sau đó, import package vào một file chứa mã server-only:

```js filename="lib/data.js"
import 'server-only'

export async function getData() {
  const res = await fetch('https://external-service.com/data', {
    headers: {
      authorization: process.env.API_KEY,
    },
  })

  return res.json()
}
```

Bây giờ, nếu bạn cố gắng import module vào một Client Component, sẽ có một lỗi build-time.

[`client-only` package](https://www.npmjs.com/package/client-only) tương ứng có thể được sử dụng để đánh dấu các modules chứa logic client-only như mã truy cập đối tượng `window`.

Trong Next.js, việc cài đặt `server-only` hoặc `client-only` là **tùy chọn**. Tuy nhiên, nếu các quy tắc linting của bạn gắn cờ các dependencies thừa, bạn có thể cài đặt chúng để tránh các vấn đề.

```bash package="npm"
npm install server-only
```

```bash package="yarn"
yarn add server-only
```

```bash package="pnpm"
pnpm add server-only
```

```bash package="bun"
bun add server-only
```

Next.js xử lý các imports `server-only` và `client-only` nội bộ để cung cấp các thông báo lỗi rõ ràng hơn khi một module được sử dụng sai môi trường. Nội dung của các packages này từ NPM không được Next.js sử dụng.

Next.js cũng cung cấp các khai báo kiểu riêng cho `server-only` và `client-only`, cho các cấu hình TypeScript nơi [`noUncheckedSideEffectImports`](https://www.typescriptlang.org/tsconfig/#noUncheckedSideEffectImports) đang hoạt động.
