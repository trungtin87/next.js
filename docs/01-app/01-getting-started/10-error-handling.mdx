Lỗi có thể được chia thành hai loại: [expected errors](#handling-expected-errors) và [uncaught exceptions](#handling-uncaught-exceptions). Trang này sẽ hướng dẫn bạn cách xử lý các lỗi này trong ứng dụng Next.js của bạn.

## Xử lý expected errors

Expected errors là những lỗi có thể xảy ra trong quá trình hoạt động bình thường của ứng dụng, chẳng hạn như những lỗi từ [server-side form validation](/docs/app/guides/forms) hoặc failed requests. Những lỗi này nên được xử lý một cách rõ ràng và trả về cho client.

### Server Functions

Bạn có thể sử dụng hook [`useActionState`](https://react.dev/reference/react/useActionState) để xử lý expected errors trong [Server Functions](https://react.dev/reference/rsc/server-functions).

Đối với những lỗi này, tránh sử dụng các khối `try`/`catch` và throw errors. Thay vào đó, mô hình hóa expected errors dưới dạng return values.

```ts filename="app/actions.ts" switcher
'use server'

export async function createPost(prevState: any, formData: FormData) {
  const title = formData.get('title')
  const content = formData.get('content')

  const res = await fetch('https://api.vercel.app/posts', {
    method: 'POST',
    body: { title, content },
  })
  const json = await res.json()

  if (!res.ok) {
    return { message: 'Failed to create post' }
  }
}
```


Bạn có thể truyền action của bạn vào hook `useActionState` và sử dụng `state` được trả về để hiển thị một error message.

```tsx filename="app/ui/form.tsx" highlight={11,19} switcher
'use client'

import { useActionState } from 'react'
import { createPost } from '@/app/actions'

const initialState = {
  message: '',
}

export function Form() {
  const [state, formAction, pending] = useActionState(createPost, initialState)

  return (
    <form action={formAction}>
      <label htmlFor="title">Title</label>
      <input type="text" id="title" name="title" required />
      <label htmlFor="content">Content</label>
      <textarea id="content" name="content" required />
      {state?.message && <p aria-live="polite">{state.message}</p>}
      <button disabled={pending}>Create Post</button>
    </form>
  )
}
```

### Server Components

Khi fetching data bên trong Server Component, bạn có thể sử dụng response để có điều kiện render một error message hoặc [`redirect`](/docs/app/api-reference/functions/redirect).

```tsx filename="app/page.tsx" switcher
export default async function Page() {
  const res = await fetch(`https://...`)
  const data = await res.json()

  if (!res.ok) {
    return 'There was an error.'
  }

  return '...'
}
```

```jsx filename="app/page.js" switcher
export default async function Page() {

  const data = await res.json()

    return 'There was an error.'

}
```

### Not found

Bạn có thể gọi function [`notFound`](/docs/app/api-reference/functions/not-found) trong một route segment và sử dụng file [`not-found.js`](/docs/app/api-reference/file-conventions/not-found) để hiển thị một 404 UI.

```tsx filename="app/blog/[slug]/page.tsx" switcher
import { getPostBySlug } from '@/lib/posts'

export default async function Page({ params }: { params: { slug: string } }) {
  const { slug } = await params
  const post = getPostBySlug(slug)

  if (!post) {
    notFound()
  }

  return <div>{post.title}</div>
}
```


```jsx filename="app/blog/[slug]/not-found.js" switcher
}
```

## Xử lý uncaught exceptions

Uncaught exceptions là những lỗi không mong đợi chỉ ra bugs hoặc vấn đề không nên xảy ra trong quá trình hoạt động bình thường của ứng dụng của bạn. Chúng nên được xử lý bằng cách throwing errors, sau đó sẽ được catch bởi error boundaries.

### Nested error boundaries

Next.js sử dụng error boundaries để xử lý uncaught exceptions. Error boundaries catch errors trong các child components của chúng và hiển thị fallback UI thay vì component tree bị crashed.

Tạo error boundary bằng cách thêm file [`error.js`](/docs/app/api-reference/file-conventions/error) bên trong route segment và export một React component:

```tsx filename="app/dashboard/error.tsx" switcher
'use client' // Error boundaries must be Client Components

import { useEffect } from 'react'

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  useEffect(() => {
    // Log the error to an error reporting service
    console.error(error)
  }, [error])

  return (
    <div>
      <h2>Something went wrong!</h2>
      <button
        onClick={
          // Attempt to recover by trying to re-render the segment
          () => reset()
        }
      >
        Try again
      </button>
    </div>
  )
}
```

```jsx filename="app/dashboard/error.js" switcher

  useEffect(() => {
```

Errors sẽ bubble up đến nearest parent error boundary. Điều này cho phép granular error handling bằng cách đặt các file `error.tsx` ở các levels khác nhau trong [route hierarchy](/docs/app/getting-started/project-structure#component-hierarchy).

Error boundaries không catch errors bên trong event handlers. Chúng được thiết kế để catch errors [during rendering](https://react.dev/reference/react/Component#static-getderivedstatefromerror) để hiển thị **fallback UI** thay vì crash toàn bộ app.

Nói chung, errors trong event handlers hoặc async code không được xử lý bởi error boundaries vì chúng chạy sau khi rendering.

Để xử lý những trường hợp này, catch error một cách thủ công và lưu trữ nó bằng `useState` hoặc `useReducer`, sau đó cập nhật UI để thông báo cho người dùng.

```tsx
'use client'

import { useState } from 'react'

export function Button() {
  const [error, setError] = useState(null)

  const handleClick = () => {
    try {
      // do some work that might fail
      throw new Error('Exception')
    } catch (reason) {
      setError(reason)
    }
  }

  if (error) {
    /* render fallback UI */
  }

  return (
    <button type="button" onClick={handleClick}>
      Click me
    </button>
  )
}
```

Lưu ý rằng unhandled errors bên trong `startTransition` từ `useTransition`, sẽ bubble up đến nearest error boundary.

```tsx
'use client'

import { useTransition } from 'react'

export function Button() {
  const [pending, startTransition] = useTransition()

  const handleClick = () =>
    startTransition(() => {
      throw new Error('Exception')
    })

  return (
    <button type="button" onClick={handleClick}>
      Click me
    </button>
  )
}
```

### Global errors

Ít phổ biến hơn, bạn có thể xử lý errors trong root layout bằng cách sử dụng file [`global-error.js`](/docs/app/api-reference/file-conventions/error#global-error), nằm trong root app directory, ngay cả khi sử dụng [internationalization](/docs/app/guides/internationalization). Global error UI phải định nghĩa các tags `<html>` và `<body>` riêng của nó, vì nó đang thay thế root layout hoặc template khi active.

```tsx filename="app/global-error.tsx" switcher
'use client' // Error boundaries must be Client Components

export default function GlobalError({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    // global-error must include html and body tags
    <html>
      <body>
        <h2>Something went wrong!</h2>
        <button onClick={() => reset()}>Try again</button>
      </body>
    </html>
  )
}
```

