Trang này sẽ hướng dẫn bạn cách fetch dữ liệu trong [Server và Client Components](/docs/app/getting-started/server-and-client-components), và cách [stream](#streaming) các components phụ thuộc vào dữ liệu.

## Fetching data

### Server Components

Bạn có thể fetch dữ liệu trong Server Components bằng cách sử dụng:

1. [`fetch` API](#with-the-fetch-api)
2. Một [ORM hoặc database](#with-an-orm-or-database)

#### Với `fetch` API

Để fetch dữ liệu với `fetch` API, hãy biến component của bạn thành một hàm bất đồng bộ (asynchronous function), và await lệnh gọi `fetch`. Ví dụ:

```tsx filename="app/blog/page.tsx" switcher
export default async function Page() {
  const data = await fetch('https://api.vercel.app/blog')
  const posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

```jsx filename="app/blog/page.js" switcher
export default async function Page() {
  const data = await fetch('https://api.vercel.app/blog')
  const posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

> **Lưu ý:**
>
> - Các phản hồi `fetch` không được cache theo mặc định. Tuy nhiên, Next.js sẽ [pre-render](/docs/app/guides/caching#static-rendering) route và đầu ra sẽ được cache để cải thiện hiệu suất. Nếu bạn muốn chọn tham gia [dynamic rendering](/docs/app/guides/caching#dynamic-rendering), sử dụng tùy chọn `{ cache: 'no-store' }`. Xem [Tham khảo `fetch` API](/docs/app/api-reference/functions/fetch).
> - Trong quá trình phát triển, bạn có thể log các lệnh gọi `fetch` để hiển thị và debug tốt hơn. Xem [tham khảo `logging` API](/docs/app/api-reference/config/next-config-js/logging).

#### Với một ORM hoặc database

Vì Server Components được render trên server, bạn có thể thực hiện các truy vấn cơ sở dữ liệu một cách an toàn bằng cách sử dụng một ORM hoặc database client. Biến component của bạn thành một hàm bất đồng bộ, và await lệnh gọi:

```tsx filename="app/blog/page.tsx" switcher
import { db, posts } from '@/lib/db'

export default async function Page() {
  const allPosts = await db.select().from(posts)
  return (
    <ul>
      {allPosts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

```jsx filename="app/blog/page.js" switcher
import { db, posts } from '@/lib/db'

export default async function Page() {
  const allPosts = await db.select().from(posts)
  return (
    <ul>
      {allPosts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

### Client Components

Có hai cách để fetch dữ liệu trong Client Components, sử dụng:

1. [`use` hook](https://react.dev/reference/react/use) của React
2. Một thư viện cộng đồng như [SWR](https://swr.vercel.app/) hoặc [React Query](https://tanstack.com/query/latest)

#### Streaming data với `use` hook

Bạn có thể sử dụng [`use` hook](https://react.dev/reference/react/use) của React để [stream](#streaming) dữ liệu từ server đến client. Bắt đầu bằng cách fetch dữ liệu trong Server component của bạn, và truyền promise cho Client Component của bạn dưới dạng prop:

```tsx filename="app/blog/page.tsx" switcher
import Posts from '@/app/ui/posts'
import { Suspense } from 'react'

export default function Page() {
  // Don't await the data fetching function
  const posts = getPosts()

  return (
    <Suspense fallback={<div>Loading...</div>}>
      <Posts posts={posts} />
    </Suspense>
  )
}
```

```jsx filename="app/blog/page.js" switcher
import Posts from '@/app/ui/posts'
import { Suspense } from 'react'

export default function Page() {
  // Don't await the data fetching function
  const posts = getPosts()

  return (
    <Suspense fallback={<div>Loading...</div>}>
      <Posts posts={posts} />
    </Suspense>
  )
}
```

Sau đó, trong Client Component của bạn, sử dụng `use` hook để đọc promise:

```tsx filename="app/ui/posts.tsx" switcher
'use client'
import { use } from 'react'

export default function Posts({
  posts,
}: {
  posts: Promise<{ id: string; title: string }[]>
}) {
  const allPosts = use(posts)

  return (
    <ul>
      {allPosts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

```jsx filename="app/ui/posts.js" switcher
'use client'
import { use } from 'react'

export default function Posts({ posts }) {
  const allPosts = use(posts)

  return (
    <ul>
      {allPosts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

Trong ví dụ trên, component `<Posts>` được bọc trong một [`<Suspense>` boundary](https://react.dev/reference/react/Suspense). Điều này có nghĩa là fallback sẽ được hiển thị trong khi promise đang được giải quyết. Tìm hiểu thêm về [streaming](#streaming).

#### Thư viện cộng đồng

Bạn có thể sử dụng một thư viện cộng đồng như [SWR](https://swr.vercel.app/) hoặc [React Query](https://tanstack.com/query/latest) để fetch dữ liệu trong Client Components. Các thư viện này có ngữ nghĩa riêng cho caching, streaming, và các tính năng khác. Ví dụ, với SWR:

```tsx filename="app/blog/page.tsx" switcher
'use client'
import useSWR from 'swr'

const fetcher = (url) => fetch(url).then((r) => r.json())

export default function BlogPage() {
  const { data, error, isLoading } = useSWR(
    'https://api.vercel.app/blog',
    fetcher
  )

  if (isLoading) return <div>Loading...</div>
  if (error) return <div>Error: {error.message}</div>

  return (
    <ul>
      {data.map((post: { id: string; title: string }) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

```jsx filename="app/blog/page.js" switcher
'use client'

import useSWR from 'swr'

const fetcher = (url) => fetch(url).then((r) => r.json())

export default function BlogPage() {
  const { data, error, isLoading } = useSWR(
    'https://api.vercel.app/blog',
    fetcher
  )

  if (isLoading) return <div>Loading...</div>
  if (error) return <div>Error: {error.message}</div>

  return (
    <ul>
      {data.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

## Deduplicate requests và cache data

Một cách để loại bỏ các `fetch` requests trùng lặp là với [request memoization](/docs/app/guides/caching#request-memoization). Với cơ chế này, các lệnh gọi `fetch` sử dụng `GET` hoặc `HEAD` với cùng URL và tùy chọn trong một lần render duy nhất được kết hợp thành một request. Điều này xảy ra tự động, và bạn có thể [chọn không tham gia](/docs/app/guides/caching#opting-out) bằng cách truyền một tín hiệu Abort cho `fetch`.

Request memoization có phạm vi trong vòng đời của một request.

Bạn cũng có thể loại bỏ các `fetch` requests trùng lặp bằng cách sử dụng [Data Cache](/docs/app/guides/caching#data-cache) của Next.js, ví dụ bằng cách đặt `cache: 'force-cache'` trong các tùy chọn `fetch` của bạn.

Data Cache cho phép chia sẻ dữ liệu qua lần render hiện tại và các requests đến.

Nếu bạn _không_ sử dụng `fetch`, và thay vào đó sử dụng một ORM hoặc cơ sở dữ liệu trực tiếp, bạn có thể bọc truy cập dữ liệu của mình với hàm [`cache` của React](https://react.dev/reference/react/cache).

```tsx filename="app/lib/data.ts" switcher
import { cache } from 'react'
import { db, posts, eq } from '@/lib/db'

export const getPost = cache(async (id: string) => {
  const post = await db.query.posts.findFirst({
    where: eq(posts.id, parseInt(id)),
  })
})
```

```jsx filename="app/lib/data.js" switcher
import { cache } from 'react'
import { db, posts, eq } from '@/lib/db'
import { notFound } from 'next/navigation'

export const getPost = cache(async (id) => {
  const post = await db.query.posts.findFirst({
    where: eq(posts.id, parseInt(id)),
  })
})
```

## Streaming

> **Cảnh báo:** Nội dung dưới đây giả định tùy chọn cấu hình [`cacheComponents`](/docs/app/api-reference/config/next-config-js/cacheComponents) được bật trong ứng dụng của bạn. Cờ này đã được giới thiệu trong Next.js 15 canary.

Khi bạn fetch dữ liệu trong Server Components, dữ liệu được fetch và render trên server cho mỗi request. Nếu bạn có bất kỳ requests dữ liệu chậm nào, toàn bộ route sẽ bị chặn không cho render cho đến khi tất cả dữ liệu được fetch.

Để cải thiện thời gian tải ban đầu và trải nghiệm người dùng, bạn có thể sử dụng streaming để chia nhỏ HTML của trang thành các phần (chunks) nhỏ hơn và dần dần gửi các phần đó từ server đến client.

### Với `<Suspense>`

`<Suspense>` cho phép bạn chi tiết hơn về những phần nào của trang để stream. Ví dụ, bạn có thể hiển thị ngay lập tức bất kỳ nội dung trang nào nằm ngoài `<Suspense>` boundary, và stream danh sách các bài đăng blog bên trong boundary.

```tsx filename="app/blog/page.tsx" switcher
import { Suspense } from 'react'
import BlogList from '@/components/BlogList'
import BlogListSkeleton from '@/components/BlogListSkeleton'

export default function BlogPage() {
  return (
    <div>
      {/* This content will be sent to the client immediately */}
      <header>
        <h1>Welcome to the Blog</h1>
        <p>Read the latest posts below.</p>
      </header>
      <main>
        {/* Any content wrapped in a <Suspense> boundary will be streamed */}
        <Suspense fallback={<BlogListSkeleton />}>
          <BlogList />
        </Suspense>
      </main>
    </div>
  )
}
```

```jsx filename="app/blog/page.js" switcher
import { Suspense } from 'react'
```

### Tạo trạng thái đang tải có ý nghĩa

Một trạng thái đang tải tức thì là fallback UI được hiển thị ngay lập tức cho người dùng sau khi điều hướng. Để có trải nghiệm người dùng tốt nhất, chúng tôi khuyên bạn nên thiết kế các trạng thái đang tải có ý nghĩa và giúp người dùng hiểu rằng ứng dụng đang phản hồi. Ví dụ, bạn có thể sử dụng skeletons và spinners, hoặc một phần nhỏ nhưng có ý nghĩa của màn hình tương lai như ảnh bìa, tiêu đề, v.v.

Trong quá trình phát triển, bạn có thể xem trước và kiểm tra trạng thái đang tải của các components bằng cách sử dụng [React Devtools](https://react.dev/learn/react-developer-tools).

### Sequential data fetching

Sequential data fetching xảy ra khi các components lồng nhau trong một cây mỗi cái tự fetch dữ liệu của riêng nó và các requests không được [loại bỏ trùng lặp](/docs/app/guides/caching#request-memoization), dẫn đến thời gian phản hồi lâu hơn.

<Image

Có thể có những trường hợp bạn muốn pattern này vì một fetch phụ thuộc vào kết quả của cái kia.

Ví dụ, component `<Playlists>` sẽ chỉ bắt đầu fetch dữ liệu khi component `<Artist>` đã hoàn tất fetch dữ liệu vì `<Playlists>` phụ thuộc vào prop `artistID`:

```tsx filename="app/artist/[username]/page.tsx" switcher
export default async function Page({
  params,
}: {
  params: Promise<{ username: string }>
}) {
  const { username } = await params
  // Get artist information
  const artist = await getArtist(username)

  return (
    <>
      <h1>{artist.name}</h1>
      {/* Show fallback UI while the Playlists component is loading */}
      <Suspense fallback={<div>Loading...</div>}>
        {/* Pass the artist ID to the Playlists component */}
        <Playlists artistID={artist.id} />
      </Suspense>
    </>
  )
}

async function Playlists({ artistID }: { artistID: string }) {
  // Use the artist ID to fetch playlists
  const playlists = await getArtistPlaylists(artistID)

  return (
    <ul>
      {playlists.map((playlist) => (
        <li key={playlist.id}>{playlist.name}</li>
      ))}
    </ul>
  )
}
```

Điều này sẽ kích hoạt [streaming](#streaming) và ngăn toàn bộ route bị chặn bởi các requests dữ liệu tuần tự.

### Parallel data fetching

Parallel data fetching xảy ra khi các requests dữ liệu trong một route được khởi tạo sớm và bắt đầu cùng một lúc.

Theo mặc định, [layouts và pages](/docs/app/getting-started/layouts-and-pages) được render song song. Vì vậy, mỗi segment bắt đầu fetch dữ liệu càng sớm càng tốt.

Tuy nhiên, trong _bất kỳ_ component nào, nhiều requests `async`/`await` vẫn có thể là tuần tự nếu được đặt sau cái kia. Ví dụ, `getAlbums` sẽ bị chặn cho đến khi `getArtist` được giải quyết:

```tsx filename="app/artist/[username]/page.tsx" switcher
import { getArtist, getAlbums } from '@/app/lib/data'

export default async function Page({ params }) {
  // These requests will be sequential
  const { username } = await params
  const artist = await getArtist(username)
  const albums = await getAlbums(username)
  return <div>{artist.name}</div>
}
```

Bắt đầu nhiều requests bằng cách gọi `fetch`, sau đó await chúng với [`Promise.all`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/all). Requests bắt đầu ngay khi `fetch` được gọi.

```tsx filename="app/artist/[username]/page.tsx" highlight={3,8,23} switcher
import Albums from './albums'

async function getArtist(username: string) {
  const res = await fetch(`https://api.example.com/artist/${username}`)
  return res.json()
}

async function getAlbums(username: string) {
  const res = await fetch(`https://api.example.com/artist/${username}/albums`)
  return res.json()
}

export default async function Page({
  params,
}: {
  params: Promise<{ username: string }>
}) {
  const { username } = await params

  // Initiate requests
  const artistData = getArtist(username)
  const albumsData = getAlbums(username)

  const [artist, albums] = await Promise.all([artistData, albumsData])

  return (
    <>
      <h1>{artist.name}</h1>
      <Albums list={albums} />
    </>
  )
}
```

```jsx filename="app/artist/[username]/page.js" highlight={3,8,19} switcher
import Albums from './albums'

async function getArtist(username) {
  const res = await fetch(`https://api.example.com/artist/${username}`)
  return res.json()
}

async function getAlbums(username) {
  const res = await fetch(`https://api.example.com/artist/${username}/albums`)
  return res.json()
}

export default async function Page({ params }) {
  const { username } = await params

  // Initiate requests
  const artistData = getArtist(username)
  const albumsData = getAlbums(username)

  const [artist, albums] = await Promise.all([artistData, albumsData])

  return (
    <>
      <h1>{artist.name}</h1>
      <Albums list={albums} />
    </>
  )
}
```

> **Lưu ý:** Nếu một request thất bại khi sử dụng `Promise.all`, toàn bộ hoạt động sẽ thất bại. Để xử lý điều này, bạn có thể sử dụng phương thức [`Promise.allSettled`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/allSettled) thay thế.

### Preloading data

Bạn có thể preload dữ liệu bằng cách tạo một hàm tiện ích mà bạn gọi sớm phía trên các requests chặn. `<Item>` render có điều kiện dựa trên hàm `checkIsAvailable()`.

Bạn có thể gọi `preload()` trước `checkIsAvailable()` để khởi tạo sớm các phụ thuộc dữ liệu của `<Item/>`. Vào thời điểm `<Item/>` được render, dữ liệu của nó đã được fetch.

```tsx filename="app/item/[id]/page.tsx" switcher
import { getItem, checkIsAvailable } from '@/lib/data'

export default async function Page({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  // starting loading item data
  preload(id)
  // perform another asynchronous task
  const isAvailable = await checkIsAvailable()

  return isAvailable ? <Item id={id} /> : null
}

export const preload = (id: string) => {
  // void evaluates the given expression and returns undefined
  // https://developer.mozilla.org/docs/Web/JavaScript/Reference/Operators/void
  void getItem(id)
}
export async function Item({ id }: { id: string }) {
  const result = await getItem(id)
  // ...
}
```

Ngoài ra, bạn có thể sử dụng [`cache` function](https://react.dev/reference/react/cache) của React và [`server-only` package](https://www.npmjs.com/package/server-only) để tạo một hàm tiện ích có thể tái sử dụng. Cách tiếp cận này cho phép bạn cache hàm fetch dữ liệu và đảm bảo rằng nó chỉ được thực thi trên server.

```ts filename="utils/get-item.ts" switcher
import { cache } from 'react'
import 'server-only'
import { getItem } from '@/lib/data'

export const preload = (id: string) => {
  void getItem(id)
}

export const getItem = cache(async (id: string) => {
  // ...
})
```
