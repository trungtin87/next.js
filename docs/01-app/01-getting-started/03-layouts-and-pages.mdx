Next.js sử dụng **định tuyến dựa trên hệ thống file (file-system based routing)**, có nghĩa là bạn có thể sử dụng các thư mục và files để định nghĩa routes. Trang này sẽ hướng dẫn bạn cách tạo layouts và pages, và liên kết giữa chúng.

## Tạo một page

Một **page** là UI được render trên một route cụ thể. Để tạo một page, thêm [`page` file](/docs/app/api-reference/file-conventions/page) vào bên trong thư mục `app` và default export một React component. Ví dụ, để tạo một index page (`/`):

  alt="page.js special file"
  srcLight="/docs/light/page-special-file.png"

  width="1600"
  height="282"

```tsx filename="app/page.tsx" switcher
export default function Page() {
  return <h1>Hello Next.js!</h1>
}
```

```jsx filename="app/page.js" switcher
export default function Page() {
  return <h1>Hello Next.js!</h1>
```

## Tạo một layout

Layout là UI được **chia sẻ** giữa nhiều pages. Khi điều hướng (navigation), layouts bảo toàn state, vẫn tương tác được, và không rerender.

Bạn có thể định nghĩa một layout bằng cách default export một React component từ [`layout` file](/docs/app/api-reference/file-conventions/layout). Component này nên chấp nhận một prop `children` có thể là một page hoặc một [layout](#nesting-layouts) khác.

Ví dụ, để tạo một layout chấp nhận index page của bạn làm child, thêm `layout` file vào trong thư mục `app`:

<Image
  alt="layout.js special file"
  srcLight="/docs/light/layout-special-file.png"
  srcDark="/docs/dark/layout-special-file.png"
  width="1600"
  height="363"
/>

```tsx filename="app/layout.tsx" switcher
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>
        {/* Layout UI */}
        {/* Đặt children ở nơi bạn muốn render một page hoặc nested layout */}
        <main>{children}</main>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function DashboardLayout({ children }) {
  return (
    <html lang="en">
      <body>
        {/* Layout UI */}
        {/* Đặt children ở nơi bạn muốn render một page hoặc nested layout */}
        <main>{children}</main>
      </body>
    </html>
  )
}
```

Layout ở trên được gọi là [root layout](/docs/app/api-reference/file-conventions/layout#root-layout) vì nó được định nghĩa ở root của thư mục `app`. Root layout là **bắt buộc** và phải chứa các thẻ `html` và `body`.

## Tạo một nested route

Một nested route là một route được tạo thành từ nhiều URL segments. Ví dụ, route `/blog/[slug]` được tạo thành từ ba segments:

- `/` (Root Segment)
- `blog` (Segment)
- `[slug]` (Leaf Segment)

Trong Next.js:

- **Thư mục (Folders)** được sử dụng để định nghĩa các route segments ánh xạ tới URL segments.
- **Files** (như `page` và `layout`) được sử dụng để tạo UI được hiển thị cho một segment.

Để tạo nested routes, bạn có thể lồng các thư mục vào nhau. Ví dụ, để thêm route cho `/blog`, tạo một thư mục tên `blog` trong thư mục `app`. Sau đó, để làm cho `/blog` có thể truy cập công khai, thêm file `page.tsx`:

<Image
  alt="File hierarchy showing blog folder and a page.js file"
  srcLight="/docs/light/blog-nested-route.png"
  srcDark="/docs/dark/blog-nested-route.png"
  width="1600"
  height="525"
/>

```tsx filename="app/blog/page.tsx" switcher
// Dummy imports
import { getPosts } from '@/lib/posts'
import { Post } from '@/ui/post'

export default async function Page() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <Post key={post.id} post={post} />
      ))}
    </ul>
  )
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
// Dummy imports
import { getPosts } from '@/lib/posts'
import { Post } from '@/ui/post'

export default async function Page() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <Post key={post.id} post={post} />
      ))}
    </ul>
  )
}
```

Bạn có thể tiếp tục lồng các thư mục để tạo nested routes. Ví dụ, để tạo route cho một blog post cụ thể, tạo thư mục `[slug]` mới bên trong `blog` và thêm file `page`:

Bọc tên thư mục trong dấu ngoặc vuông (ví dụ: `[slug]`) tạo một [dynamic route segment](/docs/app/api-reference/file-conventions/dynamic-routes) được sử dụng để generate nhiều pages từ dữ liệu. ví dụ: blog posts, product pages, v.v.

## Lồng layouts (Nesting layouts)

Theo mặc định, layouts trong folder hierarchy cũng được lồng nhau, có nghĩa là chúng bọc child layouts thông qua prop `children`. Bạn có thể lồng layouts bằng cách thêm `layout` vào bên trong các route segments (folders) cụ thể.

Ví dụ, để tạo một layout cho route `/blog`, thêm `layout` file mới vào bên trong thư mục `blog`.

<Image
  alt="File hierarchy showing root layout wrapping the blog layout"
  srcLight="/docs/light/nested-layouts.png"
  srcDark="/docs/dark/nested-layouts.png"
  width="1600"
  height="768"
/>

```tsx filename="app/blog/layout.tsx" switcher
export default function BlogLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return <section>{children}</section>
}
```

```jsx filename="app/blog/layout.js" switcher
export default function BlogLayout({ children }) {
  return <section>{children}</section>
}
```

Nếu bạn kết hợp hai layouts ở trên, root layout (`app/layout.js`) sẽ bọc blog layout (`app/blog/layout.js`), layout này sẽ bọc blog (`app/blog/page.js`) và blog post page (`app/blog/[slug]/page.js`).

## Tạo một dynamic segment

[Dynamic segments](/docs/app/api-reference/file-conventions/dynamic-routes) cho phép bạn tạo các routes được generate từ dữ liệu. Ví dụ, thay vì tạo thủ công một route cho mỗi blog post riêng lẻ, bạn có thể tạo một dynamic segment để generate các routes dựa trên dữ liệu blog post.

Để tạo một dynamic segment, bọc tên segment (thư mục) trong dấu ngoặc vuông: `[segmentName]`. Ví dụ, trong route `app/blog/[slug]/page.tsx`, `[slug]` là dynamic segment.

```tsx filename="app/blog/[slug]/page.tsx" switcher
export default async function BlogPostPage({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </div>
  )
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
export default async function BlogPostPage({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </div>
  )
}
```

Tìm hiểu thêm về [Dynamic Segments](/docs/app/api-reference/file-conventions/dynamic-routes) và prop [`params`](/docs/app/api-reference/file-conventions/page#params-optional).

Các [layouts lồng nhau trong Dynamic Segments](/docs/app/api-reference/file-conventions/layout#params-optional), cũng có thể truy cập prop `params`.

## Rendering với search params

Trong một Server Component **page**, bạn có thể truy cập search parameters bằng cách sử dụng prop [`searchParams`](/docs/app/api-reference/file-conventions/page#searchparams-optional):

```tsx filename="app/page.tsx" switcher
export default async function Page({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const filters = (await searchParams).filters
}
```

```jsx filename="app/page.jsx" switcher
export default async function Page({ searchParams }) {
  const filters = (await searchParams).filters
}
```

Sử dụng `searchParams` chọn page của bạn vào [**dynamic rendering**](/docs/app/guides/caching#dynamic-rendering) vì nó yêu cầu incoming request để đọc search parameters.

Client Components có thể đọc search params bằng cách sử dụng hook [`useSearchParams`](/docs/app/api-reference/functions/use-search-params).

Tìm hiểu thêm về `useSearchParams` trong các routes [statically rendered](/docs/app/api-reference/functions/use-search-params#static-rendering) và [dynamically rendered](/docs/app/api-reference/functions/use-search-params#dynamic-rendering).

### Khi nào sử dụng cái gì

- Sử dụng prop `searchParams` khi bạn cần search parameters để **load dữ liệu cho page** (ví dụ: pagination, filtering từ database).
- Sử dụng `useSearchParams` khi search parameters chỉ được sử dụng **trên client** (ví dụ: filtering một list đã được load qua props).
- Như một tối ưu nhỏ, bạn có thể sử dụng `new URLSearchParams(window.location.search)` trong **callbacks hoặc event handlers** để đọc search params mà không kích hoạt re-renders.

## Liên kết giữa các pages

Bạn có thể sử dụng [`<Link>` component](/docs/app/api-reference/components/link) để điều hướng giữa các routes. `<Link>` là component Next.js tích hợp sẵn mở rộng thẻ HTML `<a>` để cung cấp [prefetching](/docs/app/getting-started/linking-and-navigating#prefetching) và [client-side navigation](/docs/app/getting-started/linking-and-navigating#client-side-transitions).

Ví dụ, để generate một danh sách blog posts, import `<Link>` từ `next/link` và truyền prop `href` cho component:

```tsx filename="app/ui/post.tsx" highlight={1,10} switcher
import Link from 'next/link'

export default async function Post({ post }) {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.slug}>
          <Link href={`/blog/${post.slug}`}>{post.title}</Link>
        </li>
      ))}
    </ul>
  )
}
```

```jsx filename="app/ui/post.js" highlight={1,10}  switcher
import Link from 'next/link'

export default async function Post({ post }) {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.slug}>
          <Link href={`/blog/${post.slug}`}>{post.title}</Link>
        </li>
      ))}
    </ul>
  )
}
```

> **Lưu ý**: `<Link>` là cách chính để điều hướng giữa các routes trong Next.js. Bạn cũng có thể sử dụng [`useRouter` hook](/docs/app/api-reference/functions/use-router) cho việc điều hướng nâng cao hơn.

## Route Props Helpers

Next.js cung cấp các utility types suy luận `params` và named slots từ cấu trúc route của bạn:

- [**PageProps**](/docs/app/api-reference/file-conventions/page#page-props-helper): Props cho `page` components, bao gồm `params` và `searchParams`.
- [**LayoutProps**](/docs/app/api-reference/file-conventions/layout#layout-props-helper): Props cho `layout` components, bao gồm `children` và bất kỳ named slots nào (ví dụ: thư mục như `@analytics`).

Đây là các helpers có sẵn toàn cục (globally available), được generate khi chạy `next dev`, `next build` hoặc [`next typegen`](/docs/app/api-reference/cli/next#next-typegen-options).

```tsx filename="app/blog/[slug]/page.tsx"
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params
  return <h1>Blog post: {slug}</h1>
}
```

```tsx filename="app/dashboard/layout.tsx"
export default function Layout(props: LayoutProps<'/dashboard'>) {
  return (
    <section>
      {props.children}
      {/* Nếu bạn có app/dashboard/@analytics, nó xuất hiện như một typed slot: */}
      {/* {props.analytics} */}
    </section>
  )
}
```

> **Lưu ý**
>
> - Static routes resolve `params` thành `{}`.
> - `PageProps`, `LayoutProps` là global helpers — không cần imports.
> - Types được generate trong quá trình `next dev`, `next build` hoặc `next typegen`.
