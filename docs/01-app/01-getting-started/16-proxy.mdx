## Proxy

Proxy cho phép bạn chạy mã trước khi một yêu cầu được hoàn thành. Sau đó, dựa trên yêu cầu đến, bạn có thể sửa đổi phản hồi bằng cách rewriting, redirecting, sửa đổi request hoặc response headers, hoặc phản hồi trực tiếp.

### Trường hợp sử dụng

Một số kịch bản phổ biến mà Proxy hiệu quả bao gồm:

- Chuyển hướng nhanh sau khi đọc các phần của yêu cầu đến
- Rewriting đến các trang khác nhau dựa trên A/B tests hoặc thử nghiệm
- Sửa đổi headers cho tất cả các trang hoặc một tập hợp con các trang

Proxy _không_ phù hợp cho:

- Data fetching chậm
- Quản lý phiên

Sử dụng fetch với `options.cache`, `options.next.revalidate`, hoặc `options.next.tags`, không có hiệu lực trong Proxy.

### Quy ước

Tạo tệp `proxy.ts` (hoặc `.js`) trong thư mục gốc của dự án, hoặc bên trong `src` nếu có, để nó nằm ở cùng cấp với `pages` hoặc `app`.

> **Lưu ý**: Mặc dù chỉ một tệp `proxy.ts` được hỗ trợ cho mỗi dự án, bạn vẫn có thể tổ chức logic proxy của mình thành các module. Tách các chức năng proxy thành các tệp `.ts` hoặc `.js` riêng biệt và import chúng vào tệp `proxy.ts` chính của bạn. Điều này cho phép quản lý sạch hơn proxy theo route, được tổng hợp trong `proxy.ts` để kiểm soát tập trung. Bằng cách thực thi một tệp proxy duy nhất, nó đơn giản hóa cấu hình, ngăn chặn xung đột tiềm ẩn và tối ưu hóa hiệu suất bằng cách tránh nhiều lớp proxy.

### Ví dụ

```ts filename="proxy.ts" switcher
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

// Hàm này có thể được đánh dấu `async` nếu sử dụng `await` bên trong
export function proxy(request: NextRequest) {
  return NextResponse.redirect(new URL('/home', request.url))
}

// Xem "Matching Paths" bên dưới để tìm hiểu thêm
export const config = {
  matcher: '/about/:path*',
}
```

import { NextResponse } from 'next/server'
