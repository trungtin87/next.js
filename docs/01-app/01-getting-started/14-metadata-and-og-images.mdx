Metadata APIs có thể được sử dụng để định nghĩa application metadata của bạn cho SEO và khả năng chia sẻ web được cải thiện và bao gồm:

1. [Object `metadata` tĩnh](#static-metadata)
2. [Function `generateMetadata` động](#generated-metadata)
3. [File conventions](/docs/app/api-reference/file-conventions/metadata) đặc biệt có thể được sử dụng để thêm [favicons](#favicons) và [OG images](#static-open-graph-images) tĩnh hoặc được generate động.

Với tất cả các options trên, Next.js sẽ tự động generate các tags `<head>` liên quan cho trang của bạn, có thể được kiểm tra trong developer tools của trình duyệt.

Object `metadata` và exports function `generateMetadata` chỉ được hỗ trợ trong Server Components.

## Các trường mặc định

Có hai default `meta` tags luôn được thêm ngay cả khi một route không định nghĩa metadata:

- [Meta charset tag](https://developer.mozilla.org/docs/Web/HTML/Element/meta#attr-charset) đặt character encoding cho website.
- [Meta viewport tag](https://developer.mozilla.org/docs/Web/HTML/Viewport_meta_tag) đặt viewport width và scale cho website để điều chỉnh cho các thiết bị khác nhau.

```html
<meta charset="utf-8" />
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

Các metadata fields khác có thể được định nghĩa với object `Metadata` (cho [static metadata](#static-metadata)) hoặc function `generateMetadata` (cho [generated metadata](#generated-metadata)).

## Static metadata

Để định nghĩa static metadata, export một [`Metadata` object](/docs/app/api-reference/functions/generate-metadata#metadata-object) từ file [`layout.js`](/docs/app/api-reference/file-conventions/layout) hoặc [`page.js`](/docs/app/api-reference/file-conventions/page) tĩnh. Ví dụ, để thêm title và description cho blog route:

```tsx filename="app/blog/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'My Blog',
  description: '...',
}

export default function Layout() {}
```

```jsx filename="app/blog/layout.js" switcher
export const metadata = {
  title: 'My Blog',
  description: '...',
}

export default function Layout() {}
```

Bạn có thể xem danh sách đầy đủ các options có sẵn trong [tài liệu `generateMetadata`](/docs/app/api-reference/functions/generate-metadata#metadata-fields).

## Generated metadata

Bạn có thể sử dụng function [`generateMetadata`](/docs/app/api-reference/functions/generate-metadata) để `fetch` metadata phụ thuộc vào data. Ví dụ, để fetch title và description cho một blog post cụ thể:

```tsx filename="app/blog/[slug]/page.tsx" switcher
import type { Metadata, ResolvingMetadata } from 'next'

type Props = {
  params: Promise<{ slug: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}

export async function generateMetadata(
  { params, searchParams }: Props,
  parent: ResolvingMetadata
): Promise<Metadata> {
  const slug = (await params).slug

  // fetch post information
  const post = await fetch(`https://api.vercel.app/blog/${slug}`).then((res) =>
    res.json()
  )

  return {
    title: post.title,
    description: post.description,
  }
}

export default function Page({ params, searchParams }: Props) {}
```

```jsx filename="app/blog/[slug]/page.js" switcher
export async function generateMetadata({ params, searchParams }, parent) {
  const slug = (await params).slug

  // fetch post information
  const post = await fetch(`https://api.vercel.app/blog/${slug}`).then((res) =>
    res.json()
  )

  return {
    title: post.title,
    description: post.description,
  }
}

export default function Page({ params, searchParams }) {}
```

### Streaming metadata

Đối với các trang được rendered động, Next.js streams metadata riêng biệt, inject nó vào HTML một khi `generateMetadata` resolves, mà không blocking UI rendering.

Streaming metadata cải thiện perceived performance bằng cách cho phép visual content stream trước.

Streaming metadata **bị disabled cho bots và crawlers** mong đợi metadata nằm trong tag `<head>` (ví dụ `Twitterbot`, `Slackbot`, `Bingbot`). Chúng được phát hiện bằng cách sử dụng User Agent header từ incoming request.

Bạn có thể customize hoặc **disable** streaming metadata hoàn toàn, với option [`htmlLimitedBots`](/docs/app/api-reference/config/next-config-js/htmlLimitedBots#disabling) trong Next.js config file của bạn.

Các trang được rendered tĩnh không sử dụng streaming vì metadata được resolve tại build time.

Tìm hiểu thêm về [streaming metadata](/docs/app/api-reference/functions/generate-metadata#streaming-metadata).

### Memoizing data requests

Có thể có trường hợp bạn cần fetch **cùng** data cho metadata và chính page. Để tránh duplicate requests, bạn có thể sử dụng React's [`cache` function](https://react.dev/reference/react/cache) để memoize return value và chỉ fetch data một lần. Ví dụ, để fetch blog post information cho cả metadata và page:

```ts filename="app/lib/data.ts" highlight={5} switcher
import { cache } from 'react'
import { db } from '@/app/lib/db'

// getPost will be used twice, but execute only once
export const getPost = cache(async (slug: string) => {
  const res = await db.query.posts.findFirst({ where: eq(posts.slug, slug) })
  return res
})
```

```js filename="app/lib/data.js" highlight={5} switcher
import { cache } from 'react'
import { db } from '@/app/lib/db'

// getPost will be used twice, but execute only once
export const getPost = cache(async (slug) => {
  const res = await db.query.posts.findFirst({ where: eq(posts.slug, slug) })
  return res
})
```

```tsx filename="app/blog/[slug]/page.tsx" switcher
import { getPost } from '@/app/lib/data'

export async function generateMetadata({
  params,
}: {
  params: { slug: string }
}) {
  const post = await getPost(params.slug)
  return {
    title: post.title,
    description: post.description,
  }
}

export default async function Page({ params }: { params: { slug: string } }) {
  const post = await getPost(params.slug)
  return <div>{post.title}</div>
}
```

```jsx filename="app/blog/[slug]/page.js" switcher

```

## File-based metadata

Các special files sau có sẵn cho metadata:

- [favicon.ico, apple-icon.jpg, và icon.jpg](/docs/app/api-reference/file-conventions/metadata/app-icons)
- [opengraph-image.jpg và twitter-image.jpg](/docs/app/api-reference/file-conventions/metadata/opengraph-image)
- [robots.txt](/docs/app/api-reference/file-conventions/metadata/robots)
- [sitemap.xml](/docs/app/api-reference/file-conventions/metadata/sitemap)

Bạn có thể sử dụng chúng cho static metadata, hoặc bạn có thể programmatically generate những files này bằng code.

## Favicons

Favicons là các icons nhỏ đại diện cho trang web của bạn trong bookmarks và search results. Để thêm favicon vào ứng dụng của bạn, tạo một `favicon.ico` và thêm vào root của app folder.

## Generated Open Graph images

[`ImageResponse` constructor](/docs/app/api-reference/functions/image-response) cho phép bạn generate dynamic images bằng JSX và CSS. Điều này hữu ích cho OG images phụ thuộc vào data.

Ví dụ, để generate một OG image duy nhất cho mỗi blog post, thêm file `opengraph-image.tsx` bên trong thư mục `blog`, và import `ImageResponse` constructor từ `next/og`:

```tsx filename="app/blog/[slug]/opengraph-image.tsx" switcher
import { ImageResponse } from 'next/og'
import { getPost } from '@/app/lib/data'

// Image metadata
export const size = {
  width: 1200,
  height: 630,
}

export const contentType = 'image/png'

// Image generation
export default async function Image({ params }: { params: { slug: string } }) {
  const post = await getPost(params.slug)

  return new ImageResponse(
    (
      // ImageResponse JSX element
      <div
        style={{
          fontSize: 128,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {post.title}
      </div>
    )
  )
}
```

```jsx filename="app/blog/[slug]/opengraph-image.js" switcher
import { ImageResponse } from 'next/og'
import { getPost } from '@/app/lib/data'

// Image metadata
export const size = {
  width: 1200,
  height: 630,
}

export const contentType = 'image/png'

// Image generation
export default async function Image({ params }) {
  const post = await getPost(params.slug)

  return new ImageResponse(
    (
      // ImageResponse JSX element
      <div
        style={{
          fontSize: 128,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {post.title}
      </div>
    )
  )
}
```

`ImageResponse` hỗ trợ các common CSS properties bao gồm flexbox và absolute positioning, custom fonts, text wrapping, centering, và nested images. [Xem danh sách đầy đủ các CSS properties được hỗ trợ](/docs/app/api-reference/functions/image-response).

> **Lưu ý**:
>
> - Examples có sẵn trong [Vercel OG Playground](https://og-playground.vercel.app/).
> - `ImageResponse` sử dụng [`@vercel/og`](https://vercel.com/docs/og-image-generation), [`satori`](https://github.com/vercel/satori), và `resvg` để chuyển đổi HTML và CSS thành PNG.
> - Chỉ flexbox và một tập hợp con các CSS properties được hỗ trợ. Advanced layouts (ví dụ `display: grid`) sẽ không hoạt động.
