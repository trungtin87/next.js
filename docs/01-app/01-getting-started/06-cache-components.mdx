Cache Components là một cách tiếp cận mới để rendering và caching trong Next.js, cung cấp khả năng kiểm soát chi tiết về những gì được cache và khi nào, đồng thời đảm bảo trải nghiệm người dùng tuyệt vời thông qua **Partial Prerendering (PPR)**.

## Cache Components

Khi phát triển các ứng dụng dynamic, bạn phải cân bằng giữa hai cách tiếp cận chính:

- **Các trang hoàn toàn tĩnh (Fully static pages)** tải nhanh nhưng không thể hiển thị dữ liệu được cá nhân hóa hoặc thời gian thực
- **Các trang hoàn toàn động (Fully dynamic pages)** có thể hiển thị dữ liệu mới nhưng yêu cầu render mọi thứ trên mỗi request, dẫn đến tải ban đầu chậm hơn

Khi Cache Components được bật, Next.js coi tất cả các routes là **dynamic theo mặc định**. Mọi request đều render với dữ liệu mới nhất hiện có. Tuy nhiên, hầu hết các trang được tạo thành từ cả các phần tĩnh và động, và không phải tất cả dữ liệu động đều cần được giải quyết từ nguồn trên mỗi request.

Cache Components cho phép bạn đánh dấu dữ liệu, và thậm chí các phần của UI của bạn là có thể cache (cacheable), bao gồm chúng trong quá trình pre-render cùng với các phần tĩnh của trang.

> **Trước Cache Components**, Next.js đã cố gắng tối ưu hóa tĩnh **toàn bộ** trang một cách tự động, điều này có thể dẫn đến hành vi không mong muốn khi thêm mã dynamic.

Cache Components triển khai **Partial Prerendering (PPR)**, và `use cache` để mang lại cho bạn những điều tốt nhất của cả hai thế giới:

<Image
  alt="Partially re-rendered Product Page showing static nav and product information, and dynamic cart and recommended products"
  srcLight="/learn/light/thinking-in-ppr.png"
  srcDark="/learn/dark/thinking-in-ppr.png"
  width="1600"

/>

Khi một người dùng truy cập một route:

- Server gửi một **static shell** chứa nội dung đã được cache, đảm bảo tải ban đầu nhanh
- Các phần dynamic được bọc trong `Suspense` boundaries hiển thị fallback UI trong shell
- Chỉ các phần dynamic mới render để thay thế các fallbacks của chúng, streaming song song khi chúng sẵn sàng
- Bạn có thể bao gồm dữ liệu dynamic khác trong shell ban đầu bằng cách cache nó với `use cache`

## Cách nó hoạt động

> **Lưu ý:** Cache Components là một tính năng opt-in. Bật nó bằng cách đặt cờ `cacheComponents` thành `true` trong file cấu hình Next của bạn. Xem [Bật Cache Components](#enabling-cache-components) để biết thêm chi tiết.

Cache Components cung cấp cho bạn ba công cụ chính để kiểm soát rendering:

### 1. Suspense cho dữ liệu runtime

Một số dữ liệu chỉ có sẵn tại runtime khi một người dùng thực tế thực hiện một request. Các API như [`cookies`](/docs/app/api-reference/functions/cookies), [`headers`](/docs/app/api-reference/functions/headers), và [`searchParams`](/docs/app/api-reference/file-conventions/page#searchparams-optional) truy cập thông tin cụ thể theo request. Bọc các components sử dụng các API này trong `Suspense` boundaries để phần còn lại của trang có thể được pre-render như một static shell.

**Các API Runtime bao gồm:**

- [`cookies`](/docs/app/api-reference/functions/cookies)
- [`headers`](/docs/app/api-reference/functions/headers)
- [`searchParams` prop](/docs/app/api-reference/file-conventions/page#searchparams-optional)
- [`params` prop](/docs/app/api-reference/file-conventions/page#params-optional) - Đây là dữ liệu runtime trừ khi bạn cung cấp ít nhất một giá trị ví dụ thông qua [`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params). Khi được cung cấp, các giá trị param cụ thể đó được coi là tĩnh cho các đường dẫn được prerendered, trong khi các giá trị khác vẫn là runtime

### 2. Suspense cho dữ liệu dynamic

Dữ liệu dynamic như các lệnh gọi [`fetch`](/docs/app/api-reference/functions/fetch) hoặc truy vấn cơ sở dữ liệu (`db.query(...)`) có thể thay đổi giữa các requests nhưng không phải là user-specific. API [`connection`](/docs/app/api-reference/functions/connection) là meta-dynamic—nó đại diện cho việc chờ đợi một điều hướng của người dùng ngay cả khi không có dữ liệu thực tế nào để trả về. Bọc các components sử dụng những thứ này trong `Suspense` boundaries để kích hoạt streaming.

**Các mẫu dữ liệu Dynamic bao gồm:**

- Các request [`fetch`](/docs/app/api-reference/functions/fetch)
- Truy vấn cơ sở dữ liệu
- [`connection`](/docs/app/api-reference/functions/connection)

### 3. Dữ liệu đã cache với `use cache`

Thêm `use cache` vào bất kỳ Server Component nào để làm cho nó được cache và bao gồm nó trong pre-rendered shell. Bạn không thể sử dụng các API runtime từ bên trong một component đã được cache. Bạn cũng có thể đánh dấu các hàm tiện ích là `use cache` và gọi chúng từ Server Components.

```tsx
export async function getProducts() {
  'use cache'
  const data = await db.query('SELECT * FROM products')
  return data
}
```

## Sử dụng Suspense boundaries

React [Suspense](https://react.dev/reference/react/Suspense) boundaries cho phép bạn xác định fallback UI nào sẽ sử dụng khi nó bao bọc dữ liệu dynamic hoặc runtime.

Nội dung bên ngoài boundary, bao gồm fallback UI, được pre-rendered như một static shell, trong khi nội dung bên trong boundary streams vào khi sẵn sàng.

Dưới đây là cách sử dụng `Suspense` với Cache Components:

```tsx filename="app/page.tsx" switcher
import { Suspense } from 'react'

export default function Page() {
  return (
    <>
      <h1>This will be pre-rendered</h1>
      <Suspense fallback={<Skeleton />}>
        <DynamicContent />
      </Suspense>
    </>
  )
}

async function DynamicContent() {
  const res = await fetch('http://api.cms.com/posts')
  const { posts } = await res.json()
  return <div>{/* ... */}</div>
}
```

```jsx filename="app/page.js" switcher
import { Suspense } from 'react'

export default function Page() {
  return (
    <>
      <h1>This will be pre-rendered</h1>
      <Suspense fallback={<Skeleton />}>
        <DynamicContent />
      </Suspense>
    </>
  )
}

async function DynamicContent() {
  const res = await fetch('http://api.cms.com/posts')
  const { posts } = await res.json()
  return <div>{/* ... */}</div>
}
```

Tại build time, Next.js pre-renders nội dung tĩnh và `fallback` UI, trong khi nội dung dynamic bị hoãn lại cho đến khi người dùng yêu cầu route.

> **Lưu ý**: Việc bọc một component trong `Suspense` không làm cho nó trở nên dynamic; việc sử dụng API của bạn mới làm điều đó. `Suspense` hoạt động như một ranh giới đóng gói nội dung dynamic và kích hoạt streaming.

### Thiếu Suspense boundaries

Cache Components bắt buộc mã dynamic phải được bọc trong một `Suspense` boundary. Nếu bạn quên, bạn sẽ thấy lỗi [Uncached data was accessed outside of `<Suspense>`](https://nextjs.org/docs/messages/blocking-route):

> **Uncached data was accessed outside of `<Suspense>`**
>
> Điều này làm chậm trễ việc render toàn bộ trang, dẫn đến trải nghiệm người dùng chậm. Next.js sử dụng lỗi này để đảm bảo ứng dụng của bạn tải ngay lập tức trên mỗi lần điều hướng.
>
> Để khắc phục điều này, bạn có thể:
>
> **Bọc component trong một `<Suspense>`** boundary. Điều này cho phép Next.js stream nội dung của nó đến người dùng ngay khi nó sẵn sàng, mà không chặn phần còn lại của ứng dụng.
>
> hoặc
>
> **Di chuyển asynchronous await vào một Cache Component("use cache")**. Điều này cho phép Next.js prerender tĩnh component như một phần của tài liệu HTML, vì vậy nó hiển thị ngay lập tức cho người dùng.
>
> Lưu ý rằng thông tin cụ thể theo request, chẳng hạn như params, cookies, và headers, không có sẵn trong quá trình static prerendering, vì vậy nó phải được bọc trong `<Suspense>`.

Lỗi này giúp ngăn chặn tình huống mà thay vì nhận được static shell ngay lập tức, người dùng sẽ gặp phải blocking runtime render mà không có gì để hiển thị. Để khắc phục, hãy thêm một `Suspense` boundary hoặc sử dụng `use cache` để cache công việc thay thế.

## Sử dụng `use cache`

Trong khi `Suspense` boundaries quản lý nội dung dynamic, directive [`use cache`](/docs/app/api-reference/directives/use-cache) có sẵn để caching dữ liệu hoặc các tính toán không thay đổi thường xuyên.

### Sử dụng cơ bản

Thêm `use cache` để cache một trang, component, hoặc async function, và xác định thời gian tồn tại với [`cacheLife`](/docs/app/api-reference/functions/cacheLife):

```tsx filename="app/page.tsx" highlight={1,4,5} switcher
import { cacheLife } from 'next/cache'

export default async function Page() {
  'use cache'
  cacheLife('hours')
  // fetch or compute
  return <div>...</div>
}
```

```jsx filename="app/page.js" highlight={1,4,5} switcher
import { cacheLife } from 'next/cache'

export default async function Page() {
  'use cache'
  cacheLife('hours')
  // fetch or compute
  return <div>...</div>
}
```

### Những lưu ý

Khi sử dụng `use cache`, hãy ghi nhớ các ràng buộc này:

#### Các đối số phải serializable

Giống như Server Actions, các đối số cho các hàm được cache phải serializable. Điều này có nghĩa là bạn có thể truyền các primitives, plain objects, và arrays, nhưng không phải class instances, functions, hoặc các kiểu phức tạp khác.

#### Chấp nhận các giá trị unserializable mà không cần introspection

Bạn có thể chấp nhận các giá trị unserializable làm đối số miễn là bạn không kiểm tra (introspect) chúng. Tuy nhiên, bạn có thể trả về chúng. Điều này cho phép các patterns như cached components chấp nhận Server hoặc Client Components làm children:

```tsx filename="app/cached-wrapper.tsx" switcher
import { ReactNode } from 'react'

export async function CachedWrapper({ children }: { children: ReactNode }) {
  'use cache'
  // Don't introspect children, just pass it through
  return (
    <div className="wrapper">
      <header>Cached Header</header>
      {children}
    </div>
  )
}
```

```jsx filename="app/cached-wrapper.js" switcher
export async function CachedWrapper({ children }) {
  'use cache'
  // Don't introspect children, just pass it through
  return (
    <div className="wrapper">
      <header>Cached Header</header>
      {children}
    </div>
  )
}
```

#### Tránh truyền dynamic inputs

Bạn không được truyền dữ liệu dynamic hoặc runtime vào các hàm `use cache` trừ khi bạn tránh kiểm tra chúng. Việc truyền các giá trị từ `cookies()`, `headers()`, hoặc các API runtime khác làm đối số sẽ gây ra lỗi, vì cache key không thể được xác định tại thời điểm pre-render.

### Tagging và revalidating

Gắn thẻ dữ liệu đã cache với [`cacheTag`](/docs/app/api-reference/functions/cacheTag) và revalidate nó sau các mutations bằng cách sử dụng [`updateTag`](/docs/app/api-reference/functions/updateTag) trong Server Actions để cập nhật ngay lập tức, hoặc [`revalidateTag`](/docs/app/api-reference/functions/revalidateTag) nếu sự chậm trễ trong cập nhật là chấp nhận được.

#### Với `updateTag`

Sử dụng `updateTag` khi bạn cần hết hạn và làm mới ngay lập tức dữ liệu đã cache trong cùng một request:

```tsx filename="app/actions.ts" highlight={1,4,5,13}
import { cacheTag, updateTag } from 'next/cache'

export async function getCart() {
  'use cache'
  cacheTag('cart')
  // fetch data
}

export async function updateCart(itemId: string) {
  'use server'
  // write data using the itemId
  // update the user cart
  updateTag('cart')
}
```

#### Với `revalidateTag`

Sử dụng `revalidateTag` khi bạn muốn vô hiệu hóa chỉ các mục đã cache được gắn thẻ đúng cách với hành vi stale-while-revalidate. Điều này lý tưởng cho nội dung tĩnh có thể chấp nhận tính nhất quán cuối cùng (eventual consistency).

```tsx filename="app/actions.ts" highlight={1,4,5,12}
import { cacheTag, revalidateTag } from 'next/cache'

export async function getPosts() {
  'use cache'
  cacheTag('posts')
  // fetch data
}

export async function createPost(post: FormData) {
  'use server'
  // write data using the FormData
  revalidateTag('posts', 'max')
}
```

Để giải thích chi tiết hơn và các ví dụ sử dụng, xem [tham khảo API `use cache`](/docs/app/api-reference/directives/use-cache).

## Bật Cache Components

Bạn có thể bật Cache Components (bao gồm PPR) bằng cách thêm tùy chọn [`cacheComponents`](/docs/app/api-reference/config/next-config-js/cacheComponents) vào file cấu hình Next của bạn:

```ts filename="next.config.ts" highlight={4} switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
}

export default nextConfig
```

```js filename="next.config.js" highlight={3} switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  cacheComponents: true,
}

module.exports = nextConfig
```

### Ảnh hưởng đến cấu hình route segment

Khi Cache Components được bật, một số tùy chọn cấu hình route segment không còn cần thiết hoặc được hỗ trợ. Dưới đây là những thay đổi và cách di chuyển:

#### `dynamic = "force-dynamic"`

**Không cần thiết.** Tất cả các trang đều dynamic theo mặc định khi Cache Components được bật, vì vậy cấu hình này là không cần thiết.

```tsx
// Before - No longer needed
export const dynamic = 'force-dynamic'

export default function Page() {
  return <div>...</div>
}
```

```tsx
// After - Just remove it, pages are dynamic by default
export default function Page() {
  return <div>...</div>
}
```

#### `dynamic = "force-static"`

**Thay thế bằng `use cache`.** Bạn phải thêm `use cache` vào mỗi Layout và Page cho route liên quan thay thế.

Lưu ý: `force-static` trước đây cho phép sử dụng các API runtime như `cookies()`, nhưng điều này không còn được hỗ trợ. Nếu bạn thêm `use cache` và thấy lỗi liên quan đến dữ liệu runtime, bạn phải loại bỏ việc sử dụng các API runtime.

```tsx
// Before
export const dynamic = 'force-static'

export default async function Page() {
  const data = await fetch('https://api.example.com/data')
  return <div>...</div>
}
```

```tsx
// After - Use 'use cache' instead
export default async function Page() {
  'use cache'
  const data = await fetch('https://api.example.com/data')
  return <div>...</div>
}
```

#### `revalidate`

**Thay thế bằng `cacheLife`.** Sử dụng hàm `cacheLife` để xác định thời gian cache thay vì cấu hình route segment.

```tsx
// Before
export const revalidate = 3600 // 1 hour

export default async function Page() {
  return <div>...</div>
}
```

```tsx
// After - Use cacheLife
import { cacheLife } from 'next/cache'

export default async function Page() {
  'use cache'
  cacheLife('hours')
  return <div>...</div>
}
```

#### `fetchCache`

**Không cần thiết.** Với `use cache`, tất cả việc fetch dữ liệu trong phạm vi được cache sẽ tự động được cache, làm cho `fetchCache` không cần thiết.

```tsx
// Before
export const fetchCache = 'force-cache'
```

```tsx
// After - Use 'use cache' to control caching behavior
export default async function Page() {
  'use cache'
  // All fetches here are cached
  return <div>...</div>
}
```

#### `runtime = 'edge'`

**Không được hỗ trợ.** Cache Components yêu cầu Node.js runtime và sẽ báo lỗi với [Edge Runtime](/docs/app/api-reference/edge).

## Trước và sau Cache Components

Hiểu cách Cache Components thay đổi mô hình tư duy của bạn:

### Trước Cache Components

- **Static theo mặc định**: Next.js đã cố gắng pre-render và cache nhiều nhất có thể cho bạn trừ khi bạn chọn không tham gia
- **Kiểm soát cấp độ Route**: Các chuyển đổi như `dynamic`, `revalidate`, `fetchCache` kiểm soát caching cho toàn bộ trang
- **Giới hạn của `fetch`**: Sử dụng `fetch` một mình là không đầy đủ, vì nó không bao gồm các database clients trực tiếp hoặc server-side IO khác. Một `fetch` lồng nhau chuyển sang dynamic (ví dụ: `{ cache: 'no-store' }`) có thể vô tình thay đổi hành vi của toàn bộ route

### Với Cache Components

- **Dynamic theo mặc định**: Mọi thứ đều dynamic theo mặc định. Bạn quyết định phần nào cần cache bằng cách thêm [`use cache`](/docs/app/api-reference/directives/use-cache) ở nơi nó hữu ích
- **Kiểm soát chi tiết**: [`use cache`](/docs/app/api-reference/directives/use-cache) và [`cacheLife`](/docs/app/api-reference/functions/cacheLife) cấp độ File/component/function kiểm soát caching chính xác nơi bạn cần
- **Streaming vẫn giữ nguyên**: Sử dụng `<Suspense>` hoặc một file `loading.(js|tsx)` để stream các phần dynamic trong khi shell hiển thị ngay lập tức
- **Vượt ra ngoài `fetch`**: Sử dụng directive `use cache` caching có thể được áp dụng cho tất cả server IO (các cuộc gọi cơ sở dữ liệu, APIs, tính toán), không chỉ `fetch`. Các cuộc gọi `fetch` lồng nhau sẽ không âm thầm lật toàn bộ route vì hành vi được điều chỉnh bởi các ranh giới cache rõ ràng và `Suspense`

## Ví dụ

### Dynamic APIs

Khi truy cập các API runtime như `cookies()`, Next.js sẽ chỉ pre-render fallback UI phía trên component này.

Trong ví dụ này, chúng tôi không có fallback được xác định, vì vậy Next.js hiển thị một lỗi hướng dẫn chúng tôi cung cấp một cái. Component `<User />` cần được bọc trong `Suspense` vì nó sử dụng API `cookies`:

```jsx filename="app/user.js" switcher
import { cookies } from 'next/headers'

export async function User() {
  const session = (await cookies()).get('session')?.value
  return '...'
}
```

```tsx filename="app/user.tsx" switcher
import { cookies } from 'next/headers'

export async function User() {
  const session = (await cookies()).get('session')?.value
  return '...'
}
```

Bây giờ chúng ta có một `Suspense` boundary xung quanh User component của mình, chúng ta có thể pre-render Page với một Skeleton UI và stream trong `<User />` UI khi một người dùng cụ thể thực hiện một request

```tsx filename="app/page.tsx" switcher
import { Suspense } from 'react'
import { User, AvatarSkeleton } from './user'

export default function Page() {
  return (
    <section>
      <h1>This will be pre-rendered</h1>
      <Suspense fallback={<AvatarSkeleton />}>
        <User />
      </Suspense>
    </section>
  )
}
```

```jsx filename="app/page.js" switcher
import { Suspense } from 'react'
import { User, AvatarSkeleton } from './user'

export default function Page() {
  return (
    <section>
      <h1>This will be pre-rendered</h1>
      <Suspense fallback={<AvatarSkeleton />}>
        <User />
      </Suspense>
    </section>
  )
}
```

### Truyền dynamic props

Components chỉ chọn tham gia dynamic rendering khi giá trị được truy cập. Ví dụ, nếu bạn đang đọc `searchParams` từ một component `<Page />`, bạn có thể chuyển tiếp giá trị này đến một component khác dưới dạng prop:

```tsx filename="app/page.tsx" switcher
import { Table, TableSkeleton } from './table'
import { Suspense } from 'react'

export default function Page({
  searchParams,
}: {
  searchParams: Promise<{ sort: string }>
}) {
  return (
    <section>
      <h1>This will be pre-rendered</h1>
      <Suspense fallback={<TableSkeleton />}>
        <Table searchParams={searchParams.then((search) => search.sort)} />
      </Suspense>
    </section>
  )
}
```

```jsx filename="app/page.js" switcher
import { Table, TableSkeleton } from './table'
import { Suspense } from 'react'

export default function Page({ searchParams }) {
  return (
    <section>
      <h1>This will be pre-rendered</h1>
      <Suspense fallback={<TableSkeleton />}>
        <Table searchParams={searchParams.then((search) => search.sort)} />
      </Suspense>
    </section>
  )
}
```

Bên trong table component, việc truy cập giá trị từ `searchParams` sẽ làm cho component trở nên dynamic trong khi phần còn lại của trang sẽ được pre-rendered.

```tsx filename="app/table.tsx" switcher
export async function Table({ sortPromise }: { sortPromise: Promise<string> }) {
  const sort = (await sortPromise) === 'true'
  return '...'
}
```

```jsx filename="app/table.js" switcher
export async function Table({ sortPromise }) {
  const sort = (await sortPromise) === 'true'
  return '...'
}
```

## Các câu hỏi thường gặp

### Điều này có thay thế Partial Prerendering (PPR) không?

Không. Cache Components **triển khai** PPR như một tính năng. Cờ PPR thử nghiệm cũ đã bị xóa nhưng PPR vẫn ở đây.

PPR cung cấp static shell và cơ sở hạ tầng streaming; `use cache` cho phép bạn bao gồm đầu ra dynamic được tối ưu hóa trong shell đó khi có lợi.

### Tôi nên cache cái gì trước?

Những gì bạn cache nên là một hàm của những gì bạn muốn trạng thái tải UI của mình là. Nếu dữ liệu không phụ thuộc vào dữ liệu runtime và bạn chấp nhận một giá trị đã cache được phục vụ cho nhiều requests trong một khoảng thời gian, hãy sử dụng `use cache` với `cacheLife` để mô tả hành vi đó.

Đối với các hệ thống quản lý nội dung có cơ chế cập nhật, hãy xem xét sử dụng tags với thời lượng cache dài hơn và dựa vào `revalidateTag` để đánh dấu UI tĩnh ban đầu là sẵn sàng cho revalidation. Pattern này cho phép bạn phục vụ các phản hồi nhanh, đã cache trong khi vẫn cập nhật nội dung khi nó thực sự thay đổi, thay vì hết hạn cache một cách phủ đầu.

### Làm thế nào để tôi cập nhật nội dung đã cache một cách nhanh chóng?

Sử dụng [`cacheTag`](/docs/app/api-reference/functions/cacheTag) để gắn thẻ dữ liệu đã cache của bạn, sau đó kích hoạt [`updateTag`](/docs/app/api-reference/functions/updateTag) hoặc [`revalidateTag`](/docs/app/api-reference/functions/revalidateTag).
