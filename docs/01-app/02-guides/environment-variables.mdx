Next.js đi kèm với hỗ trợ tích hợp sẵn cho các biến môi trường, cho phép bạn thực hiện những việc sau:

- [Sử dụng `.env` để tải các biến môi trường](#loading-environment-variables)
- [Đóng gói các biến môi trường cho trình duyệt bằng cách thêm tiền tố `NEXT_PUBLIC_`](#bundling-environment-variables-for-the-browser)

> **Cảnh báo:** Mẫu `create-next-app` mặc định đảm bảo tất cả các tệp `.env` được thêm vào `.gitignore` của bạn. Bạn hầu như không bao giờ muốn commit các tệp này vào kho lưu trữ của mình.

## Tải Biến Môi trường

Next.js có hỗ trợ tích hợp sẵn để tải các biến môi trường từ các tệp `.env*` vào `process.env`.

```txt filename=".env"
DB_HOST=localhost
DB_USER=myuser
DB_PASS=mypassword
```

<PagesOnly>

Điều này tải `process.env.DB_HOST`, `process.env.DB_USER`, và `process.env.DB_PASS` vào môi trường Node.js tự động cho phép bạn sử dụng chúng trong [các phương thức lấy dữ liệu của Next.js](/docs/pages/building-your-application/data-fetching) và [API routes](/docs/pages/building-your-application/routing/api-routes).

Ví dụ, sử dụng [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props):

```js filename="pages/index.js"
export async function getStaticProps() {
  const db = await myDB.connect({
    host: process.env.DB_HOST,
    username: process.env.DB_USER,
    password: process.env.DB_PASS,
  })
  // ...
}
```

</PagesOnly>

<AppOnly>

> **Lưu ý**: Next.js cũng hỗ trợ các biến nhiều dòng bên trong các tệp `.env*` của bạn:
>
> ```bash
> # .env
>
> # bạn có thể viết với ngắt dòng
> PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----
> ...
> Kh9NV...
> ...
> -----END DSA PRIVATE KEY-----"
>
> # hoặc với `\n` bên trong dấu ngoặc kép
> PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nKh9NV...\n-----END DSA PRIVATE KEY-----\n"
> ```

> **Lưu ý**: Nếu bạn đang sử dụng thư mục `/src`, xin lưu ý rằng Next.js sẽ tải các tệp .env **chỉ** từ thư mục cha và **không** từ thư mục `/src`.
> Điều này tải `process.env.DB_HOST`, `process.env.DB_USER`, và `process.env.DB_PASS` vào môi trường Node.js tự động cho phép bạn sử dụng chúng trong [Route Handlers](/docs/app/api-reference/file-conventions/route).

Ví dụ:

```js filename="app/api/route.js"
export async function GET() {
  const db = await myDB.connect({
    host: process.env.DB_HOST,
    username: process.env.DB_USER,
    password: process.env.DB_PASS,
  })
  // ...
}
```

</AppOnly>

### Tải Biến Môi trường với `@next/env`

Nếu bạn cần tải các biến môi trường bên ngoài runtime của Next.js, chẳng hạn như trong tệp cấu hình gốc cho ORM hoặc trình chạy thử nghiệm, bạn có thể sử dụng gói `@next/env`.

Gói này được Next.js sử dụng nội bộ để tải các biến môi trường từ các tệp `.env*`.

Để sử dụng nó, hãy cài đặt gói và sử dụng hàm `loadEnvConfig` để tải các biến môi trường:

```bash
npm install @next/env
```

```tsx filename="envConfig.ts" switcher
import { loadEnvConfig } from '@next/env'

const projectDir = process.cwd()
loadEnvConfig(projectDir)
```

```jsx filename="envConfig.js" switcher
import { loadEnvConfig } from '@next/env'

const projectDir = process.cwd()
loadEnvConfig(projectDir)
```

Sau đó, bạn có thể import cấu hình khi cần thiết. Ví dụ:

```tsx filename="orm.config.ts" switcher
import './envConfig.ts'

export default defineConfig({
  dbCredentials: {
    connectionString: process.env.DATABASE_URL!,
  },
})
```

```jsx filename="orm.config.js" switcher
import './envConfig.js'

export default defineConfig({
  dbCredentials: {
    connectionString: process.env.DATABASE_URL,
  },
})
```

### Tham chiếu Biến Khác

Next.js sẽ tự động mở rộng các biến sử dụng `$` để tham chiếu các biến khác, ví dụ: `$VARIABLE` bên trong các tệp `.env*` của bạn. Điều này cho phép bạn tham chiếu các bí mật khác. Ví dụ:

```txt filename=".env"
TWITTER_USER=nextjs
TWITTER_URL=https://x.com/$TWITTER_USER
```

Trong ví dụ trên, `process.env.TWITTER_URL` sẽ được đặt thành `https://x.com/nextjs`.

> **Cần biết**: Nếu bạn cần sử dụng biến có `$` trong giá trị thực tế, nó cần được escape, ví dụ: `\$`.

## Đóng gói Biến Môi trường cho Trình duyệt

Các biến môi trường không có tiền tố `NEXT_PUBLIC_` chỉ có sẵn trong môi trường Node.js, nghĩa là chúng không thể truy cập được đối với trình duyệt (client chạy trong một _môi trường_ khác).

Để làm cho giá trị của một biến môi trường có thể truy cập được trong trình duyệt, Next.js có thể "inline" một giá trị, tại thời điểm build, vào gói js được gửi đến client, thay thế tất cả các tham chiếu đến `process.env.[variable]` bằng một giá trị được mã hóa cứng. Để bảo nó làm điều này, bạn chỉ cần thêm tiền tố `NEXT_PUBLIC_` vào biến. Ví dụ:

```txt filename="Terminal"
NEXT_PUBLIC_ANALYTICS_ID=abcdefghijk
```

Điều này sẽ bảo Next.js thay thế tất cả các tham chiếu đến `process.env.NEXT_PUBLIC_ANALYTICS_ID` trong môi trường Node.js bằng giá trị từ môi trường mà bạn chạy `next build`, cho phép bạn sử dụng nó ở bất kỳ đâu trong mã của mình. Nó sẽ được inline vào bất kỳ JavaScript nào được gửi đến trình duyệt.

> **Lưu ý**: Sau khi được build, ứng dụng của bạn sẽ không còn phản hồi với các thay đổi đối với các biến môi trường này. Ví dụ, nếu bạn sử dụng quy trình Heroku để quảng bá các slugs được build trong một môi trường sang môi trường khác, hoặc nếu bạn build và triển khai một hình ảnh Docker duy nhất cho nhiều môi trường, tất cả các biến `NEXT_PUBLIC_` sẽ bị đóng băng với giá trị được đánh giá tại thời điểm build, vì vậy các giá trị này cần được đặt phù hợp khi dự án được build. Nếu bạn cần truy cập các giá trị môi trường runtime, bạn sẽ phải thiết lập API của riêng mình để cung cấp chúng cho client (theo yêu cầu hoặc trong quá trình khởi tạo).

```js filename="pages/index.js"
import setupAnalyticsService from '../lib/my-analytics-service'

// 'NEXT_PUBLIC_ANALYTICS_ID' có thể được sử dụng ở đây vì nó được thêm tiền tố 'NEXT_PUBLIC_'.
// Nó sẽ được chuyển đổi tại thời điểm build thành `setupAnalyticsService('abcdefghijk')`.
setupAnalyticsService(process.env.NEXT_PUBLIC_ANALYTICS_ID)

function HomePage() {
  return <h1>Hello World</h1>
}

export default HomePage
```

Lưu ý rằng các tra cứu động sẽ _không_ được inline, chẳng hạn như:

```js
// Điều này sẽ KHÔNG được inline, vì nó sử dụng một biến
const varName = 'NEXT_PUBLIC_ANALYTICS_ID'
setupAnalyticsService(process.env[varName])

// Điều này sẽ KHÔNG được inline, vì nó sử dụng một biến
const env = process.env
setupAnalyticsService(env.NEXT_PUBLIC_ANALYTICS_ID)
```

### Biến Môi trường Runtime

Next.js có thể hỗ trợ cả biến môi trường thời gian build và runtime.

**Theo mặc định, các biến môi trường chỉ có sẵn trên máy chủ**. Để hiển thị một biến môi trường cho trình duyệt, nó phải được thêm tiền tố `NEXT_PUBLIC_`. Tuy nhiên, các biến môi trường công khai này sẽ được inline vào gói JavaScript trong quá trình `next build`.

<PagesOnly>

Để đọc các biến môi trường runtime, chúng tôi khuyên bạn nên sử dụng `getServerSideProps` hoặc [áp dụng dần dần App Router](/docs/app/guides/migrating/app-router-migration).

</PagesOnly>

<AppOnly>

Bạn có thể đọc an toàn các biến môi trường trên máy chủ trong quá trình render động:

```tsx filename="app/page.ts" switcher
import { connection } from 'next/server'

export default async function Component() {
  await connection()
  // cookies, headers, và các Dynamic APIs khác
  // cũng sẽ chọn tham gia render động, có nghĩa là
  // biến env này được đánh giá tại runtime
  const value = process.env.MY_VALUE
  // ...
}
```

```jsx filename="app/page.js" switcher
import { connection } from 'next/server'

export default async function Component() {
  await connection()
  // cookies, headers, và các Dynamic APIs khác
  // cũng sẽ chọn tham gia render động, có nghĩa là
  // biến env này được đánh giá tại runtime
  const value = process.env.MY_VALUE
  // ...
}
```

</AppOnly>

Điều này cho phép bạn sử dụng một hình ảnh Docker duy nhất có thể được quảng bá qua nhiều môi trường với các giá trị khác nhau.

**Cần biết:**

- Bạn có thể chạy mã khi khởi động máy chủ bằng cách sử dụng [`register` function](/docs/app/guides/instrumentation).

## Biến Môi trường Kiểm thử (Test Environment Variables)

Ngoài môi trường `development` và `production`, còn có một tùy chọn thứ 3: `test`. Tương tự như cách bạn có thể đặt mặc định cho môi trường phát triển hoặc sản xuất, bạn có thể làm tương tự với tệp `.env.test` cho môi trường `testing` (mặc dù tệp này không phổ biến như hai tệp trước). Next.js sẽ không tải các biến môi trường từ `.env.development` hoặc `.env.production` trong môi trường `testing`.

Tệp này hữu ích khi chạy các bài kiểm tra với các công cụ như `jest` hoặc `cypress` nơi bạn cần đặt các biến môi trường cụ thể chỉ cho mục đích kiểm thử. Các giá trị mặc định kiểm thử sẽ được tải nếu `NODE_ENV` được đặt thành `test`, mặc dù bạn thường không cần phải làm điều này thủ công vì các công cụ kiểm thử sẽ giải quyết nó cho bạn.

Có một sự khác biệt nhỏ giữa môi trường `test`, và cả `development` và `production` mà bạn cần ghi nhớ: `.env.local` sẽ không được tải, vì bạn mong đợi các bài kiểm tra tạo ra kết quả giống nhau cho mọi người. Bằng cách này, mọi lần thực thi kiểm thử sẽ sử dụng cùng một mặc định env qua các lần thực thi khác nhau bằng cách bỏ qua `.env.local` của bạn (vốn nhằm mục đích ghi đè tập hợp mặc định).

> **Cần biết**: tương tự như Biến Môi trường Mặc định, tệp `.env.test` nên được bao gồm trong kho lưu trữ của bạn, nhưng `.env.test.local` thì không, vì `.env*.local` nhằm mục đích bị bỏ qua thông qua `.gitignore`.

Trong khi chạy các bài kiểm tra đơn vị, bạn có thể đảm bảo tải các biến môi trường của mình giống như cách Next.js làm bằng cách tận dụng hàm `loadEnvConfig` từ gói `@next/env`.

```js
// Đoạn mã dưới đây có thể được sử dụng trong tệp thiết lập toàn cục Jest hoặc tương tự cho thiết lập kiểm thử của bạn
import { loadEnvConfig } from '@next/env'

export default async () => {
  const projectDir = process.cwd()
  loadEnvConfig(projectDir)
}
```

## Thứ tự Tải Biến Môi trường

Các biến môi trường được tìm kiếm ở những nơi sau, theo thứ tự, dừng lại khi tìm thấy biến.

1. `process.env`
1. `.env.$(NODE_ENV).local`
1. `.env.local` (Không được kiểm tra khi `NODE_ENV` là `test`.)
1. `.env.$(NODE_ENV)`
1. `.env`

Ví dụ, nếu `NODE_ENV` là `development` và bạn xác định một biến trong cả `.env.development.local` và `.env`, giá trị trong `.env.development.local` sẽ được sử dụng.

> **Cần biết**: Các giá trị được phép cho `NODE_ENV` là `production`, `development` và `test`.

## Cần biết

- Nếu bạn đang sử dụng một [`/src` directory](/docs/app/api-reference/file-conventions/src-folder), các tệp `.env.*` nên nằm ở thư mục gốc của dự án của bạn.
- Nếu biến môi trường `NODE_ENV` không được gán, Next.js tự động gán `development` khi chạy lệnh `next dev`, hoặc `production` cho tất cả các lệnh khác.
