## Hàm `redirect`

Hàm `redirect` cho phép bạn redirect người dùng đến một URL khác. Bạn có thể gọi `redirect` trong [Server Components](/docs/app/getting-started/server-and-client-components), [Route Handlers](/docs/app/api-reference/file-conventions/route), và [Server Actions](/docs/app/getting-started/updating-data).

`redirect` thường được sử dụng sau một mutation hoặc event. Ví dụ, tạo một bài post:

```ts filename="app/actions.ts" switcher
'use server'

import { redirect } from 'next/navigation'
import { revalidatePath } from 'next/cache'

export async function createPost(id: string) {
  try {
    // Call database
  } catch (error) {
    // Handle errors
  }

  revalidatePath('/posts') // Update cached posts
  redirect(`/post/${id}`) // Navigate to the new post page
}
```

```js filename="app/actions.js" switcher
'use server'

import { redirect } from 'next/navigation'
import { revalidatePath } from 'next/cache'

export async function createPost(id) {
  try {
    // Call database
  } catch (error) {
    // Handle errors
  }

  revalidatePath('/posts') // Update cached posts
  redirect(`/post/${id}`) // Navigate to the new post page
}
```

> **Cần biết**:
>
> - `redirect` trả về mã trạng thái 307 (Temporary Redirect) theo mặc định. Khi được sử dụng trong Server Action, nó trả về 303 (See Other), thường được sử dụng để redirect đến trang thành công như kết quả của một POST request.
> - `redirect` throws một error nên nó nên được gọi **bên ngoài** khối `try` khi sử dụng các câu lệnh `try/catch`.
> - `redirect` có thể được gọi trong Client Components trong quá trình rendering nhưng không phải trong event handlers. Bạn có thể sử dụng [`useRouter` hook](#userouter-hook) thay thế.
> - `redirect` cũng chấp nhận các URL tuyệt đối và có thể được sử dụng để redirect đến các liên kết bên ngoài.
> - Nếu bạn muốn redirect trước quá trình render, hãy sử dụng [`next.config.js`](#redirects-in-nextconfigjs) hoặc [Proxy](#nextresponseredirect-in-proxy).

Xem [API reference `redirect`](/docs/app/api-reference/functions/redirect) để biết thêm thông tin.

## Hàm `permanentRedirect`

Hàm `permanentRedirect` cho phép bạn redirect **vĩnh viễn** người dùng đến một URL khác. Bạn có thể gọi `permanentRedirect` trong [Server Components](/docs/app/getting-started/server-and-client-components), [Route Handlers](/docs/app/api-reference/file-conventions/route), và [Server Actions](/docs/app/getting-started/updating-data).

`permanentRedirect` thường được sử dụng sau một mutation hoặc event thay đổi URL canonical của một entity, chẳng hạn như cập nhật URL profile của người dùng sau khi họ thay đổi username:

```ts filename="app/actions.ts" switcher
'use server'

import { permanentRedirect } from 'next/navigation'
import { revalidateTag } from 'next/cache'

export async function updateUsername(username: string, formData: FormData) {
  try {
    // Call database
  } catch (error) {
    // Handle errors
  }

  revalidateTag('username') // Update all references to the username
  permanentRedirect(`/profile/${username}`) // Navigate to the new user profile
}
```

```js filename="app/actions.js" switcher
'use server'

import { permanentRedirect } from 'next/navigation'
import { revalidateTag } from 'next/cache'

export async function updateUsername(username, formData) {
  try {
    // Call database
  } catch (error) {
    // Handle errors
  }

  revalidateTag('username') // Update all references to the username
  permanentRedirect(`/profile/${username}`) // Navigate to the new user profile
}
```

> **Cần biết**:
>
> - `permanentRedirect` trả về mã trạng thái 308 (permanent redirect) theo mặc định.
> - `permanentRedirect` cũng chấp nhận các URL tuyệt đối và có thể được sử dụng để redirect đến các liên kết bên ngoài.
> - Nếu bạn muốn redirect trước quá trình render, hãy sử dụng [`next.config.js`](#redirects-in-nextconfigjs) hoặc [Proxy](#nextresponseredirect-in-proxy).

Xem [API reference `permanentRedirect`](/docs/app/api-reference/functions/permanentRedirect) để biết thêm thông tin.

## `redirects` trong `next.config.js`

Tùy chọn `redirects` trong tệp `next.config.js` cho phép bạn redirect một đường dẫn request đến sang một đường dẫn đích khác. Điều này hữu ích khi bạn thay đổi cấu trúc URL của các trang hoặc có một danh sách các redirects được biết trước.

`redirects` hỗ trợ [path matching](/docs/app/api-reference/config/next-config-js/redirects#path-matching), [header, cookie, và query matching](/docs/app/api-reference/config/next-config-js/redirects#header-cookie-and-query-matching), mang lại cho bạn sự linh hoạt để redirect người dùng dựa trên một request đến.

Để sử dụng `redirects`, thêm tùy chọn vào tệp `next.config.js` của bạn:

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  async redirects() {
    return [
      // Basic redirect
      {
        source: '/about',
        destination: '/',
        permanent: true,
      },
      // Wildcard path matching
      {
        source: '/blog/:slug',
        destination: '/news/:slug',
        permanent: true,
      },
    ]
  },
}

export default nextConfig
```

```js filename="next.config.js" switcher
module.exports = {
  async redirects() {
    return [
      // Basic redirect
      {
        source: '/about',
        destination: '/',
        permanent: true,
      },
      // Wildcard path matching
      {
        source: '/blog/:slug',
        destination: '/news/:slug',
        permanent: true,
      },
    ]
  },
}
```

Xem [API reference `redirects`](/docs/app/api-reference/config/next-config-js/redirects) để biết thêm thông tin.

> **Cần biết**:
>
> - `redirects` có thể trả về mã trạng thái 307 (Temporary Redirect) hoặc 308 (Permanent Redirect) với tùy chọn `permanent`.
> - `redirects` có thể có giới hạn trên các nền tảng. Ví dụ, trên Vercel, có giới hạn 1,024 redirects. Để quản lý số lượng lớn redirects (1000+), hãy xem xét tạo một giải pháp tùy chỉnh sử dụng [Proxy](/docs/app/api-reference/file-conventions/proxy). Xem [quản lý redirects quy mô lớn](#managing-redirects-at-scale-advanced) để biết thêm.
> - `redirects` chạy **trước** Proxy.

## `NextResponse.redirect` trong Proxy

Proxy cho phép bạn chạy mã trước khi một request được hoàn tất. Sau đó, dựa trên request đến, redirect đến một URL khác bằng cách sử dụng `NextResponse.redirect`. Điều này hữu ích nếu bạn muốn redirect người dùng dựa trên một điều kiện (v.d. xác thực, quản lý session, v.v.) hoặc có [số lượng lớn redirects](#managing-redirects-at-scale-advanced).

Ví dụ, để redirect người dùng đến trang `/login` nếu họ chưa được xác thực:

```ts filename="proxy.ts" switcher
import { NextResponse, NextRequest } from 'next/server'
import { authenticate } from 'auth-provider'

export function proxy(request: NextRequest) {
  const isAuthenticated = authenticate(request)

  // If the user is authenticated, continue as normal
  if (isAuthenticated) {
    return NextResponse.next()
  }

  // Redirect to login page if not authenticated
  return NextResponse.redirect(new URL('/login', request.url))
}

export const config = {
  matcher: '/dashboard/:path*',
}
```

```js filename="proxy.js" switcher
import { NextResponse } from 'next/server'
import { authenticate } from 'auth-provider'

  const isAuthenticated = authenticate(request)

```

> **Cần biết**:
>
> - Proxy chạy **sau** `redirects` trong `next.config.js` và **trước** rendering.

Xem tài liệu [Proxy](/docs/app/api-reference/file-conventions/proxy) để biết thêm thông tin.

## Quản lý redirects quy mô lớn (nâng cao)

Để quản lý số lượng lớn redirects (1000+), bạn có thể xem xét tạo một giải pháp tùy chỉnh sử dụng Proxy. Điều này cho phép bạn xử lý redirects theo chương trình mà không cần phải redeploy ứng dụng của bạn.

Để thực hiện điều này, bạn sẽ cần xem xét:

1. Tạo và lưu trữ một redirect map.
2. Tối ưu hóa hiệu suất tìm kiếm dữ liệu.

> **Ví dụ Next.js**: Xem ví dụ [Proxy với Bloom filter](https://redirects-bloom-filter.vercel.app/) của chúng tôi để xem triển khai các khuyến nghị dưới đây.

### 1. Tạo và lưu trữ một redirect map

Một redirect map là một danh sách các redirects mà bạn có thể lưu trữ trong một cơ sở dữ liệu (thường là một key-value store) hoặc tệp JSON.

Xem xét cấu trúc dữ liệu sau:

```json
{
  "/old": {
    "destination": "/new",
    "permanent": true
  },
  "/blog/post-old": {
    "destination": "/blog/post-new",
    "permanent": true
  }
}
```

Trong [Proxy](/docs/app/api-reference/file-conventions/proxy), bạn có thể đọc từ một cơ sở dữ liệu như [Edge Config](https://vercel.com/docs/edge-config/get-started) của Vercel hoặc [Redis](https://vercel.com/docs/redis), và redirect người dùng dựa trên request đến:

```ts filename="proxy.ts" switcher
import { NextResponse, NextRequest } from 'next/server'
import { get } from '@vercel/edge-config'

type RedirectEntry = {
  destination: string
  permanent: boolean
}

export async function proxy(request: NextRequest) {
  const pathname = request.nextUrl.pathname
  const redirectData = await get(pathname)

  if (redirectData && typeof redirectData === 'string') {
    const redirectEntry: RedirectEntry = JSON.parse(redirectData)
    const statusCode = redirectEntry.permanent ? 308 : 307
    return NextResponse.redirect(redirectEntry.destination, statusCode)
  }

  // No redirect found, continue without redirecting
  return NextResponse.next()
}
```


### 2. Tối ưu hóa hiệu suất tìm kiếm dữ liệu

Việc đọc một tập dữ liệu lớn cho mỗi request đến có thể chậm và đắt. Có hai cách bạn có thể tối ưu hóa hiệu suất tìm kiếm dữ liệu:

- Sử dụng một cơ sở dữ liệu được tối ưu hóa cho việc đọc nhanh
- Sử dụng một chiến lược tìm kiếm dữ liệu như [Bloom filter](https://en.wikipedia.org/wiki/Bloom_filter) để kiểm tra hiệu quả xem một redirect có tồn tại hay không **trước khi** đọc tệp redirects lớn hươn hoặc cơ sở dữ liệu.

Xem xét ví dụ trước đó, bạn có thể import một tệp bloom filter được tạo vào Proxy, sau đó, kiểm tra xem pathname của request đến có tồn tại trong bloom filter hay không.

Nếu có, chuyển tiếp request đến một <AppOnly>[Route Handler](/docs/app/api-reference/file-conventions/route)</AppOnly> <PagesOnly>[API Routes](/docs/pages/building-your-application/routing/api-routes)</PagesOnly> sẽ kiểm tra tệp thực tế và redirect người dùng đến URL phù hợp. Điều này tránh việc import một tệp redirects lớn vào Proxy, có thể làm chậm mọi request đến.

```ts filename="proxy.ts" switcher
import { NextResponse, NextRequest } from 'next/server'
import { ScalableBloomFilter } from 'bloom-filters'
import GeneratedBloomFilter from './redirects/bloom-filter.json'

type RedirectEntry = {
  destination: string
  permanent: boolean
}

// Initialize bloom filter from a generated JSON file
const bloomFilter = ScalableBloomFilter.fromJSON(GeneratedBloomFilter as any)

export async function proxy(request: NextRequest) {
  // Get the path for the incoming request
  const pathname = request.nextUrl.pathname

  // Check if the path is in the bloom filter
  if (bloomFilter.has(pathname)) {
    // Forward the pathname to the Route Handler
    const api = new URL(
      `/api/redirects?pathname=${encodeURIComponent(request.nextUrl.pathname)}`,
      request.nextUrl.origin
    )

    try {
      // Fetch redirect data from the Route Handler
      const redirectData = await fetch(api)

      if (redirectData.ok) {
        const redirectEntry: RedirectEntry | undefined =
          await redirectData.json()

        if (redirectEntry) {
          // Determine the status code
          const statusCode = redirectEntry.permanent ? 308 : 307

          // Redirect to the destination
          return NextResponse.redirect(redirectEntry.destination, statusCode)
        }
      }
    } catch (error) {
      console.error(error)
    }
  }

  // No redirect found, continue the request without redirecting
  return NextResponse.next()
}
```

Sau đó, trong Route Handler:

```ts filename="app/api/redirects/route.ts" switcher
import { NextRequest, NextResponse } from 'next/server'
import redirects from '@/app/redirects/redirects.json'

type RedirectEntry = {
  destination: string
  permanent: boolean
}

export function GET(request: NextRequest) {
  const pathname = request.nextUrl.searchParams.get('pathname')
  if (!pathname) {
    return new Response('Bad Request', { status: 400 })
  }

  // Get the redirect entry from the redirects.json file
  const redirect = (redirects as Record<string, RedirectEntry>)[pathname]

  // Account for bloom filter false positives
  if (!redirect) {
    return new Response('No redirect', { status: 400 })
  }

  // Return the redirect entry
  return NextResponse.json(redirect)
}
```
