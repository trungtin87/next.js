[Content Security Policy (CSP)](https://developer.mozilla.org/docs/Web/HTTP/CSP) rất quan trọng để bảo vệ ứng dụng Next.js của bạn chống lại các mối đe dọa bảo mật khác nhau như cross-site scripting (XSS), clickjacking, và các cuộc tấn công tiêm mã khác.

Bằng cách sử dụng CSP, các nhà phát triển có thể chỉ định nguồn gốc nào được phép cho các nguồn nội dung, scripts, stylesheets, hình ảnh, phông chữ, đối tượng, phương tiện (âm thanh, video), iframes, và nhiều hơn nữa.

## Nonces

Một [nonce](https://developer.mozilla.org/docs/Web/HTML/Global_attributes/nonce) là một chuỗi ký tự ngẫu nhiên, duy nhất được tạo ra để sử dụng một lần. Nó được sử dụng kết hợp với CSP để cho phép chọn lọc các scripts hoặc styles nội tuyến nhất định thực thi, bỏ qua các chỉ thị CSP nghiêm ngặt.

### Tại sao sử dụng nonce?

CSP có thể chặn cả scripts nội tuyến và bên ngoài để ngăn chặn các cuộc tấn công. Một nonce cho phép bạn chạy các scripts cụ thể một cách an toàn—chỉ khi chúng bao gồm giá trị nonce khớp.

Nếu một kẻ tấn công muốn tải một script vào trang của bạn, họ sẽ cần đoán giá trị nonce. Đó là lý do tại sao nonce phải không thể đoán trước và duy nhất cho mỗi yêu cầu.

### Thêm nonce với Proxy

[Proxy](/docs/app/api-reference/file-conventions/proxy) cho phép bạn thêm headers và tạo nonces trước khi trang render.

Mỗi khi một trang được xem, một nonce mới nên được tạo ra. Điều này có nghĩa là bạn **phải sử dụng [dynamic rendering](/docs/app/guides/caching#dynamic-rendering) để thêm nonces**.

Ví dụ:

```ts filename="proxy.ts" switcher
import { NextRequest, NextResponse } from 'next/server'

export function proxy(request: NextRequest) {
  const nonce = Buffer.from(crypto.randomUUID()).toString('base64')
  const cspHeader = `
    default-src 'self';
    script-src 'self' 'nonce-${nonce}' 'strict-dynamic';
    style-src 'self' 'nonce-${nonce}';
    img-src 'self' blob: data:;
    font-src 'self';
    object-src 'none';
    base-uri 'self';
    form-action 'self';
    frame-ancestors 'none';
    upgrade-insecure-requests;
`
  // Thay thế các ký tự xuống dòng và khoảng trắng
  const contentSecurityPolicyHeaderValue = cspHeader
    .replace(/\s{2,}/g, ' ')
    .trim()

  const requestHeaders = new Headers(request.headers)
  requestHeaders.set('x-nonce', nonce)

  requestHeaders.set(
    'Content-Security-Policy',
    contentSecurityPolicyHeaderValue
  )

  const response = NextResponse.next({
    request: {
      headers: requestHeaders,
    },
  })
  response.headers.set(
    'Content-Security-Policy',
    contentSecurityPolicyHeaderValue
  )

  return response
}
```

Theo mặc định, Proxy chạy trên tất cả các yêu cầu. Bạn có thể lọc Proxy để chạy trên các đường dẫn cụ thể bằng cách sử dụng [`matcher`](/docs/app/api-reference/file-conventions/proxy#matcher).

Chúng tôi khuyên bạn nên bỏ qua việc khớp các prefetches (từ `next/link`) và các tài sản tĩnh không cần header CSP.

```ts filename="proxy.ts" switcher
export const config = {
  matcher: [
    /*
     * Khớp tất cả các đường dẫn yêu cầu ngoại trừ các đường dẫn bắt đầu bằng:
     * - api (API routes)
     * - _next/static (static files)
     * - _next/image (image optimization files)
     * - favicon.ico (favicon file)
     */
    {
      source: '/((?!api|_next/static|_next/image|favicon.ico).*)',
      missing: [
        { type: 'header', key: 'next-router-prefetch' },
        { type: 'header', key: 'purpose', value: 'prefetch' },
      ],
    },
  ],
}
```

### Cách nonces hoạt động trong Next.js

Để sử dụng nonce, trang của bạn phải được **render động (dynamically rendered)**. Điều này là do Next.js áp dụng nonces trong quá trình **render phía máy chủ**, dựa trên header CSP có trong yêu cầu. Các trang tĩnh được tạo tại thời điểm build, khi không có header yêu cầu hoặc phản hồi nào tồn tại—vì vậy không thể chèn nonce.

Dưới đây là cách hỗ trợ nonce hoạt động trong một trang được render động:

1. **Proxy tạo ra một nonce**: Proxy của bạn tạo ra một nonce duy nhất cho yêu cầu, thêm nó vào header `Content-Security-Policy` của bạn, và cũng đặt nó trong một header tùy chỉnh `x-nonce`.
2. **Next.js trích xuất nonce**: Trong quá trình render, Next.js phân tích header `Content-Security-Policy` và trích xuất nonce bằng cách sử dụng mẫu `'nonce-{value}'`.
3. **Nonce được áp dụng tự động**: Next.js đính kèm nonce vào:
   - Các scripts framework (React, Next.js runtime)
   - Các gói JavaScript dành riêng cho trang
   - Các styles và scripts nội tuyến được tạo bởi Next.js
   - Bất kỳ thành phần `<Script>` nào sử dụng prop `nonce`

Do hành vi tự động này, bạn không cần phải thêm thủ công một nonce vào mỗi thẻ.

### Bắt buộc render động

Nếu bạn đang sử dụng nonces, bạn có thể cần phải chọn tham gia render động cho các trang một cách rõ ràng:

```tsx filename="pages/_document.tsx" switcher
import Document, {
  Html,
  Head,
  Main,
  NextScript,
  DocumentContext,
  DocumentInitialProps,
} from 'next/document'

interface ExtendedDocumentProps extends DocumentInitialProps {
  nonce?: string
}

class MyDocument extends Document<ExtendedDocumentProps> {
  static async getInitialProps(
    ctx: DocumentContext
  ): Promise<ExtendedDocumentProps> {
    const initialProps = await Document.getInitialProps(ctx)
    const nonce = ctx.req?.headers?.['x-nonce'] as string | undefined

    return {
      ...initialProps,
      nonce,
    }
  }

  render() {
    const { nonce } = this.props

    return (
      <Html lang="en">
        <Head nonce={nonce} />
        <body>
          <Main />
          <NextScript nonce={nonce} />
        </body>
      </Html>
    )
  }
}

export default MyDocument
```

## Render Tĩnh vs Động với CSP

Sử dụng nonces có ý nghĩa quan trọng đối với cách ứng dụng Next.js của bạn render:

### Yêu cầu Render Động

Khi bạn sử dụng nonces trong CSP của mình, **tất cả các trang phải được render động**. Điều này có nghĩa là:

- Các trang sẽ build thành công nhưng có thể gặp lỗi runtime nếu không được cấu hình đúng cho render động
- Mỗi yêu cầu tạo ra một trang mới với một nonce mới
- Tối ưu hóa tĩnh và Incremental Static Regeneration (ISR) bị vô hiệu hóa
- Các trang không thể được cache bởi CDN nếu không có cấu hình bổ sung
- **Partial Prerendering (PPR) không tương thích** với CSP dựa trên nonce vì các shell scripts tĩnh sẽ không có quyền truy cập vào nonce

### Ý nghĩa về Hiệu suất

Sự chuyển đổi từ render tĩnh sang động ảnh hưởng đến hiệu suất:

- **Tải trang ban đầu chậm hơn**: Các trang phải được tạo trên mỗi yêu cầu
- **Tải máy chủ tăng**: Mỗi yêu cầu yêu cầu render phía máy chủ
- **Không có bộ nhớ đệm CDN**: Các trang động không thể được cache tại biên theo mặc định
- **Chi phí lưu trữ cao hơn**: Cần nhiều tài nguyên máy chủ hơn cho render động

### Khi nào nên sử dụng nonces

Cân nhắc nonces khi:

- Bạn có các yêu cầu bảo mật nghiêm ngặt cấm `'unsafe-inline'`
- Ứng dụng của bạn xử lý dữ liệu nhạy cảm
- Bạn cần cho phép các scripts nội tuyến cụ thể trong khi chặn các scripts khác
- Yêu cầu tuân thủ bắt buộc CSP nghiêm ngặt

## Không có Nonces

Đối với các ứng dụng không yêu cầu nonces, bạn có thể đặt header CSP trực tiếp trong tệp [`next.config.js`](/docs/app/api-reference/config/next-config-js) của mình:

```js filename="next.config.js"
const cspHeader = `

    object-src 'none';
    base-uri 'self';

          {
            key: 'Content-Security-Policy',
            value: cspHeader.replace(/\n/g, ''),
          },
        ],
      },
    ]
  },
}
```

## Subresource Integrity (Thử nghiệm)

Như một giải pháp thay thế cho nonces, Next.js cung cấp hỗ trợ thử nghiệm cho CSP dựa trên hash bằng cách sử dụng Subresource Integrity (SRI). Cách tiếp cận này cho phép bạn duy trì việc tạo tĩnh trong khi vẫn có CSP nghiêm ngặt.

> **Cần biết**: Tính năng này đang thử nghiệm và chỉ có sẵn với webpack bundler trong các ứng dụng App Router.

### Cách SRI hoạt động

Thay vì sử dụng nonces, SRI tạo ra các hash mật mã của các tệp JavaScript của bạn tại thời điểm build. Các hash này được thêm vào dưới dạng thuộc tính `integrity` cho các thẻ script, cho phép trình duyệt xác minh rằng các tệp chưa bị sửa đổi trong quá trình truyền tải.

### Bật SRI

Thêm cấu hình SRI thử nghiệm vào `next.config.js` của bạn:

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    sri: {
      algorithm: 'sha256', // hoặc 'sha384' hoặc 'sha512'
    },
  },
}

module.exports = nextConfig
```

### Cấu hình CSP với SRI

Khi SRI được bật, bạn có thể tiếp tục sử dụng các chính sách CSP hiện có của mình. SRI hoạt động độc lập bằng cách thêm các thuộc tính `integrity` vào các tài sản của bạn:

> **Cần biết**: Đối với các tình huống render động, bạn vẫn có thể tạo nonces với proxy nếu cần, kết hợp cả thuộc tính toàn vẹn SRI và các phương pháp tiếp cận CSP dựa trên nonce.

```js filename="next.config.js"
const cspHeader = `
    default-src 'self';
    script-src 'self';
    style-src 'self';
    img-src 'self' blob: data:;
    font-src 'self';
    object-src 'none';
    base-uri 'self';
    form-action 'self';
    frame-ancestors 'none';
    upgrade-insecure-requests;
`

module.exports = {
  experimental: {
    sri: {
      algorithm: 'sha256',
    },
  },
  async headers() {
    return [
      {
        source: '/(.*)',
        headers: [
          {
            key: 'Content-Security-Policy',
            value: cspHeader.replace(/\n/g, ''),
          },
        ],
      },
    ]
  },
}
```

### Lợi ích của SRI so với nonces

- **Tạo tĩnh**: Các trang có thể được tạo tĩnh và lưu trong bộ nhớ cache
- **Tương thích CDN**: Các trang tĩnh hoạt động với bộ nhớ cache CDN
- **Hiệu suất tốt hơn**: Không yêu cầu render phía máy chủ cho mỗi yêu cầu
- **Bảo mật thời gian build**: Các hash được tạo tại thời điểm build, đảm bảo tính toàn vẹn

### Hạn chế của SRI

- **Thử nghiệm**: Tính năng có thể thay đổi hoặc bị xóa
- **Chỉ Webpack**: Không có sẵn với Turbopack
- **Chỉ App Router**: Không được hỗ trợ trong Pages Router
- **Chỉ thời gian build**: Không thể xử lý các scripts được tạo động

## Cân nhắc Phát triển vs Production

Việc triển khai CSP khác nhau giữa môi trường phát triển và production:

### Môi trường Phát triển

Trong quá trình phát triển, bạn sẽ cần bật `'unsafe-eval'` để hỗ trợ các API cung cấp thông tin gỡ lỗi bổ sung:

```ts filename="proxy.ts" switcher
export function proxy(request: NextRequest) {
  const nonce = Buffer.from(crypto.randomUUID()).toString('base64')
  const isDev = process.env.NODE_ENV === 'development'

  const cspHeader = `
    default-src 'self';
    script-src 'self' 'nonce-${nonce}' 'strict-dynamic' ${isDev ? "'unsafe-eval'" : ''};
    style-src 'self' ${isDev ? "'unsafe-inline'" : `'nonce-${nonce}'`};
    img-src 'self' blob: data:;
    font-src 'self';
    object-src 'none';
    base-uri 'self';
    form-action 'self';
    frame-ancestors 'none';
    upgrade-insecure-requests;
`

  // Phần còn lại của triển khai proxy
}
```

### Triển khai Production

Các vấn đề phổ biến trong production:

- **Nonce không được áp dụng**: Đảm bảo proxy của bạn chạy trên tất cả các routes cần thiết
- **Tài sản tĩnh bị chặn**: Xác minh CSP của bạn cho phép các tài sản tĩnh của Next.js
- **Scripts của bên thứ ba**: Thêm các miền cần thiết vào chính sách CSP của bạn

## Khắc phục sự cố

### Scripts của bên thứ ba

<AppOnly>

Khi sử dụng scripts của bên thứ ba với CSP:

```tsx filename="app/layout.tsx" switcher
import { GoogleTagManager } from '@next/third-parties/google'
import { headers } from 'next/headers'

export default async function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  const nonce = (await headers()).get('x-nonce')

  return (
    <html lang="en">
      <body>
        {children}
        <GoogleTagManager gtmId="GTM-XYZ" nonce={nonce} />
      </body>
    </html>
  )
}
```

<PagesOnly>

Khi sử dụng scripts của bên thứ ba với CSP, hãy đảm bảo bạn thêm các miền cần thiết và truyền nonce:

```tsx filename="pages/_app.tsx" switcher
import type { AppProps } from 'next/app'
import Script from 'next/script'

export default function App({ Component, pageProps }: AppProps) {
  const nonce = pageProps.nonce

  return (
    <>
      <Component {...pageProps} />
      <Script
        src="https://www.googletagmanager.com/gtag/js"
        strategy="afterInteractive"
        nonce={nonce}
      />
    </>
  )
}
```

```jsx filename="pages/_app.jsx" switcher
import Script from 'next/script'

export default function App({ Component, pageProps }) {
  const nonce = pageProps.nonce

  return (
    <>
      <Component {...pageProps} />
      <Script
        src="https://www.googletagmanager.com/gtag/js"
        strategy="afterInteractive"
        nonce={nonce}
      />
    </>
  )
}
```

</PagesOnly>

Cập nhật CSP của bạn để cho phép các miền của bên thứ ba:

```ts filename="proxy.ts" switcher
const cspHeader = `
  default-src 'self';
  script-src 'self' 'nonce-${nonce}' 'strict-dynamic' https://www.googletagmanager.com;
  connect-src 'self' https://www.google-analytics.com;
  img-src 'self' data: https://www.google-analytics.com;
`
```


### Các vi phạm CSP phổ biến

1. **Inline styles**: Sử dụng các thư viện CSS-in-JS hỗ trợ nonces hoặc di chuyển styles sang các tệp bên ngoài
2. **Dynamic imports**: Đảm bảo dynamic imports được phép trong chính sách script-src của bạn
3. **WebAssembly**: Thêm `'wasm-unsafe-eval'` nếu sử dụng WebAssembly
4. **Service workers**: Thêm các chính sách phù hợp cho các scripts service worker
