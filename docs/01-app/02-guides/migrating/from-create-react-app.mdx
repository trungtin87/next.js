Hướng dẫn này sẽ giúp bạn di chuyển một trang web Create React App (CRA) hiện có sang Next.js.

## Tại sao nên chuyển đổi?

Có một số lý do khiến bạn có thể muốn chuyển từ Create React App sang Next.js:

### Thời gian tải trang ban đầu chậm

Create React App sử dụng purely client-side rendering. Các ứng dụng chỉ phía client, còn được gọi là [single-page applications (SPAs)](/docs/app/guides/single-page-applications), thường gặp phải thời gian tải trang ban đầu chậm. Điều này xảy ra do một vài lý do:

1. Trình duyệt cần đợi mã React và toàn bộ gói ứng dụng của bạn tải xuống và chạy trước khi mã của bạn có thể gửi yêu cầu tải dữ liệu.
2. Mã ứng dụng của bạn tăng lên với mỗi tính năng và dependency mới mà bạn thêm vào.

### Không có automatic code splitting

Vấn đề trước đây về thời gian tải chậm có thể được giảm nhẹ phần nào bằng code splitting. Tuy nhiên, nếu bạn cố gắng thực hiện code splitting thủ công, bạn có thể vô tình tạo ra network waterfalls. Next.js cung cấp automatic code splitting và tree-shaking được tích hợp vào router và build pipeline của nó.

### Network waterfalls

Một nguyên nhân phổ biến gây ra hiệu suất kém xảy ra khi các ứng dụng thực hiện các yêu cầu client-server tuần tự để fetch dữ liệu. Một mô hình để fetch dữ liệu trong một [SPA](/docs/app/guides/single-page-applications) là render một placeholder, và sau đó fetch dữ liệu sau khi component đã mount. Thật không may, một child component chỉ có thể bắt đầu fetch dữ liệu sau khi parent của nó đã tải xong dữ liệu của chính nó, dẫn đến một “waterfall” (thác nước) các yêu cầu.

Trong khi client-side data fetching được hỗ trợ trong Next.js, Next.js cũng cho phép bạn di chuyển data fetching sang server. Điều này thường loại bỏ hoàn toàn client-server waterfalls.

### Trạng thái tải nhanh và có chủ đích

Với hỗ trợ tích hợp cho [streaming thông qua React Suspense](/docs/app/getting-started/linking-and-navigating#streaming), bạn có thể xác định phần nào của UI tải trước và theo thứ tự nào, mà không tạo ra network waterfalls.

Điều này cho phép bạn xây dựng các trang tải nhanh hơn và loại bỏ [layout shifts](https://vercel.com/blog/how-core-web-vitals-affect-seo).

### Chọn chiến lược data fetching

Tùy thuộc vào nhu cầu của bạn, Next.js cho phép bạn chọn chiến lược data fetching của mình trên cơ sở từng trang hoặc từng component. Ví dụ, bạn có thể fetch dữ liệu từ CMS của mình và render các bài đăng blog tại build time (SSG) để có tốc độ tải nhanh, hoặc fetch dữ liệu tại request time (SSR) khi cần thiết.

### Proxy

[Next.js Proxy](/docs/app/api-reference/file-conventions/proxy) cho phép bạn chạy mã trên server trước khi một yêu cầu được hoàn thành. Ví dụ, bạn có thể tránh flash nội dung chưa được xác thực bằng cách chuyển hướng người dùng đến trang đăng nhập trong proxy cho các trang chỉ dành cho người đã xác thực. Bạn cũng có thể sử dụng nó cho các tính năng như A/B testing, thử nghiệm, và [internationalization](/docs/app/guides/internationalization).

### Tối ưu hóa tích hợp

[Images](/docs/app/api-reference/components/image), [fonts](/docs/app/api-reference/components/font), và [third-party scripts](/docs/app/guides/scripts) thường có tác động lớn đến hiệu suất của ứng dụng. Next.js bao gồm các components và APIs chuyên biệt tự động tối ưu hóa chúng cho bạn.

## Các bước di chuyển

Mục tiêu của chúng tôi là có được một ứng dụng Next.js hoạt động nhanh nhất có thể để bạn có thể áp dụng các tính năng Next.js dần dần. Để bắt đầu, chúng tôi sẽ coi ứng dụng của bạn như một ứng dụng purely client-side ([SPA](/docs/app/guides/single-page-applications)) mà không thay thế ngay router hiện có của bạn. Điều này làm giảm độ phức tạp và xung đột hợp nhất.

> **Lưu ý**: Nếu bạn đang sử dụng các cấu hình CRA nâng cao như trường `homepage` tùy chỉnh trong `package.json` của bạn, một service worker tùy chỉnh, hoặc các tinh chỉnh Babel/webpack cụ thể, vui lòng xem phần **Cân nhắc bổ sung** ở cuối hướng dẫn này để biết các mẹo về cách sao chép hoặc điều chỉnh các tính năng này trong Next.js.

### Bước 1: Cài đặt Next.js Dependency

Cài đặt Next.js trong dự án hiện có của bạn:

```bash filename="Terminal"
npm install next@latest
```

### Bước 2: Tạo File cấu hình Next.js

Tạo một `next.config.ts` tại thư mục gốc của dự án của bạn (cùng cấp với `package.json` của bạn). File này chứa [các tùy chọn cấu hình Next.js](/docs/app/api-reference/config/next-config-js) của bạn.

```js filename="next.config.ts"
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  output: 'export', // Outputs a Single-Page Application (SPA)
  distDir: 'build', // Changes the build output directory to `build`
}

export default nextConfig
```

> **Lưu ý**: Sử dụng `output: 'export'` có nghĩa là bạn đang thực hiện static export. Bạn sẽ **không** có quyền truy cập vào các tính năng phía server như SSR hoặc APIs. Bạn có thể xóa dòng này để tận dụng các tính năng server của Next.js.

### Bước 3: Tạo Root Layout

Một ứng dụng Next.js [App Router](/docs/app) phải bao gồm một file [root layout](/docs/app/api-reference/file-conventions/layout#root-layout), là một [React Server Component](/docs/app/getting-started/server-and-client-components) sẽ bao bọc tất cả các trang của bạn.

Tương đương gần nhất của file root layout trong một ứng dụng CRA là `public/index.html`, bao gồm các thẻ `<html>`, `<head>`, và `<body>` của bạn.

1. Tạo một thư mục `app` mới bên trong thư mục `src` của bạn (hoặc tại thư mục gốc dự án nếu bạn thích `app` ở thư mục gốc).
2. Bên trong thư mục `app`, tạo một file `layout.tsx` (hoặc `layout.js`):

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return '...'
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return '...'
}
```

Bây giờ sao chép nội dung của `index.html` cũ của bạn vào component `<RootLayout>` này. Thay thế `body div#root` (và `body noscript`) bằng `<div id="root">{children}</div>`.

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <head>
        <meta charSet="UTF-8" />
        <link rel="icon" href="%PUBLIC_URL%/favicon.ico" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <title>React App</title>
        <meta name="description" content="Web site created..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <head>
        <meta charset="UTF-8" />
        <link rel="icon" href="%PUBLIC_URL%/favicon.ico" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <title>React App</title>
        <meta name="description" content="Web site created..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

> **Lưu ý**: Next.js bỏ qua `public/manifest.json` của CRA, các biểu tượng bổ sung, và [cấu hình testing](/docs/app/guides/testing) theo mặc định. Nếu bạn cần những thứ này, Next.js có hỗ trợ với [Metadata API](/docs/app/getting-started/metadata-and-og-images) và thiết lập [Testing](/docs/app/guides/testing).

### Bước 4: Metadata

Next.js tự động bao gồm các thẻ `<meta charset="UTF-8" />` và `<meta name="viewport" content="width=device-width, initial-scale=1" />`, vì vậy bạn có thể xóa chúng khỏi `<head>`:

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <head>
        <link rel="icon" href="%PUBLIC_URL%/favicon.ico" />
        <title>React App</title>
        <meta name="description" content="Web site created..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <head>
        <link rel="icon" href="%PUBLIC_URL%/favicon.ico" />
        <title>React App</title>
        <meta name="description" content="Web site created..." />
      </head>
      <body>
        <div id="root">{children}</div>

```

Bất kỳ [metadata files](/docs/app/getting-started/metadata-and-og-images#file-based-metadata) nào như `favicon.ico`, `icon.png`, `robots.txt` đều được tự động thêm vào thẻ `<head>` của ứng dụng miễn là bạn đặt chúng vào cấp cao nhất của thư mục `app`. Sau khi di chuyển [tất cả các file được hỗ trợ](/docs/app/getting-started/metadata-and-og-images#file-based-metadata) vào thư mục `app`, bạn có thể xóa các thẻ `<link>` của chúng một cách an toàn:

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <head>
        <title>React App</title>
        <meta name="description" content="Web site created..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <head>
        <title>React App</title>
        <meta name="description" content="Web site created..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )

```

Cuối cùng, Next.js có thể quản lý các thẻ `<head>` cuối cùng của bạn với [Metadata API](/docs/app/getting-started/metadata-and-og-images). Di chuyển thông tin metadata cuối cùng của bạn vào một [`metadata` object](/docs/app/api-reference/functions/generate-metadata#metadata-object) được export:

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'React App',
  description: 'Web site created with Next.js.',
}

  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )

```

```jsx filename="app/layout.js" switcher
export const metadata = {
  title: 'React App',
  description: 'Web site created with Next.js.',
}

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        <div id="root">{children}</div>
      </body>
    </html>

```

Với những thay đổi trên, bạn đã chuyển từ việc khai báo mọi thứ trong `index.html` sang sử dụng cách tiếp cận dựa trên quy ước của Next.js được tích hợp vào framework ([Metadata API](/docs/app/getting-started/metadata-and-og-images)). Cách tiếp cận này cho phép bạn dễ dàng cải thiện SEO và khả năng chia sẻ web của các trang của mình.

### Bước 5: Styles

Giống như CRA, Next.js hỗ trợ [CSS Modules](/docs/app/getting-started/css#css-modules) ngay lập tức. Nó cũng hỗ trợ [global CSS imports](/docs/app/getting-started/css#global-css).

Nếu bạn có một file CSS toàn cục, hãy import nó vào `app/layout.tsx` của bạn:

```tsx filename="app/layout.tsx" switcher
import '../index.css'

export const metadata = {
  title: 'React App',
  description: 'Web site created with Next.js.',
}

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

Nếu bạn đang sử dụng Tailwind CSS, hãy xem [tài liệu cài đặt](/docs/app/getting-started/css#tailwind-css) của chúng tôi.

### Bước 6: Tạo Entrypoint Page

Create React App sử dụng `src/index.tsx` (hoặc `index.js`) làm điểm vào. Trong Next.js (App Router), mỗi thư mục bên trong thư mục `app` tương ứng với một route, và mỗi thư mục nên có một `page.tsx`.

Vì chúng ta muốn giữ ứng dụng như một SPA hiện tại và chặn **tất cả** các routes, chúng ta sẽ sử dụng một [optional catch-all route](/docs/app/api-reference/file-conventions/dynamic-routes#optional-catch-all-segments).

1. **Tạo một thư mục `[[...slug]]` bên trong `app`.**

```bash
app
 ┣ [[...slug]]
 ┃ ┗ page.tsx
 ┣ layout.tsx
```

2. **Thêm nội dung sau vào `page.tsx`**:

```tsx filename="app/[[...slug]]/page.tsx" switcher
export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return '...' // We'll update this
}
```

```jsx filename="app/[[...slug]]/page.js" switcher
export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return '...' // We'll update this
}
```

Điều này bảo Next.js tạo một route duy nhất cho slug trống (`/`), ánh xạ hiệu quả **tất cả** các routes đến cùng một trang. Trang này là một [Server Component](/docs/app/getting-started/server-and-client-components), được prerendered thành HTML tĩnh.

### Bước 7: Thêm một Client-Only Entrypoint

Tiếp theo, chúng ta sẽ nhúng root App component của CRA của bạn vào bên trong một [Client Component](/docs/app/getting-started/server-and-client-components) để tất cả logic vẫn ở phía client. Nếu đây là lần đầu tiên bạn sử dụng Next.js, bạn nên biết rằng clients components (theo mặc định) vẫn được prerendered trên server. Bạn có thể nghĩ về chúng như có khả năng bổ sung để chạy JavaScript phía client.

Tạo một `client.tsx` (hoặc `client.js`) trong `app/[[...slug]]/`:

```tsx filename="app/[[...slug]]/client.tsx" switcher
'use client'

import dynamic from 'next/dynamic'

const App = dynamic(() => import('../../App'), { ssr: false })

export function ClientOnly() {
  return <App />
}
```

```jsx filename="app/[[...slug]]/client.js" switcher
'use client'

import dynamic from 'next/dynamic'

const App = dynamic(() => import('../../App'), { ssr: false })

export function ClientOnly() {
  return <App />
}
```

- Directive `'use client'` làm cho file này trở thành một **Client Component**.
- `dynamic` import với `ssr: false` vô hiệu hóa server-side rendering cho component `<App />`, làm cho nó thực sự chỉ phía client (SPA).

Bây giờ cập nhật `page.tsx` (hoặc `page.js`) của bạn để sử dụng component mới của bạn:

```tsx filename="app/[[...slug]]/page.tsx" switcher
import { ClientOnly } from './client'

export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return <ClientOnly />
}
```

```jsx filename="app/[[...slug]]/page.js" switcher
import { ClientOnly } from './client'

export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return <ClientOnly />
}
```

### Bước 8: Cập nhật Static Image Imports

Trong CRA, import một file hình ảnh trả về URL công khai của nó dưới dạng chuỗi:

```tsx
import image from './img.png'

export default function App() {
  return <img src={image} />
}
```

Với Next.js, static image imports trả về một đối tượng. Đối tượng sau đó có thể được sử dụng trực tiếp với [`<Image>` component](/docs/app/api-reference/components/image) của Next.js, hoặc bạn có thể sử dụng thuộc tính `src` của đối tượng với thẻ `<img>` hiện có của bạn.

Component `<Image>` có thêm lợi ích của [automatic image optimization](/docs/app/api-reference/components/image). Component `<Image>` tự động đặt các thuộc tính `width` và `height` của `<img>` kết quả dựa trên kích thước của hình ảnh. Điều này ngăn chặn layout shifts khi hình ảnh tải. Tuy nhiên, điều này có thể gây ra sự cố nếu ứng dụng của bạn chứa hình ảnh chỉ có một trong các kích thước của chúng được tạo kiểu mà không có kích thước kia được tạo kiểu thành `auto`. Khi không được tạo kiểu thành `auto`, kích thước sẽ mặc định theo giá trị thuộc tính kích thước của `<img>`, điều này có thể khiến hình ảnh bị méo.

Giữ thẻ `<img>` sẽ giảm lượng thay đổi trong ứng dụng của bạn và ngăn chặn các vấn đề trên. Sau đó, bạn có thể tùy chọn di chuyển sang component `<Image>` để tận dụng việc tối ưu hóa hình ảnh bằng cách [cấu hình một loader](/docs/app/api-reference/components/image#loader), hoặc chuyển sang server Next.js mặc định có tối ưu hóa hình ảnh tự động.

**Chuyển đổi đường dẫn import tuyệt đối cho hình ảnh được import từ `/public` thành import tương đối:**

```tsx
// Before
import logo from '/logo.png'

// After
import logo from '../public/logo.png'
```

**Truyền thuộc tính `src` của hình ảnh thay vì toàn bộ đối tượng hình ảnh vào thẻ `<img>` của bạn:**

```tsx
// Before
<img src={logo} />

// After
<img src={logo.src} />
```

Ngoài ra, bạn có thể tham chiếu URL công khai cho tài sản hình ảnh dựa trên tên file. Ví dụ, `public/logo.png` sẽ phục vụ hình ảnh tại `/logo.png` cho ứng dụng của bạn, đây sẽ là giá trị `src`.

> **Cảnh báo:** Nếu bạn đang sử dụng TypeScript, bạn có thể gặp lỗi kiểu khi truy cập thuộc tính `src`. Để khắc phục chúng, bạn cần thêm `next-env.d.ts` vào [`include` array](https://www.typescriptlang.org/tsconfig#include) của file `tsconfig.json` của bạn. Next.js sẽ tự động tạo file này khi bạn chạy ứng dụng của mình ở bước 9.

### Bước 9: Di chuyển Biến môi trường

Next.js hỗ trợ [biến môi trường](/docs/app/guides/environment-variables) tương tự như CRA nhưng **yêu cầu** tiền tố `NEXT_PUBLIC_` cho bất kỳ biến nào bạn muốn hiển thị trong trình duyệt.

Sự khác biệt chính là tiền tố được sử dụng để hiển thị các biến môi trường ở phía client. Thay đổi tất cả các biến môi trường có tiền tố `REACT_APP_` thành `NEXT_PUBLIC_`.

### Bước 10: Cập nhật Scripts trong `package.json`

Cập nhật các scripts trong `package.json` của bạn để sử dụng các lệnh Next.js. Ngoài ra, thêm `.next` và `next-env.d.ts` vào `.gitignore` của bạn:

```json filename="package.json"
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "npx serve@latest ./build"
  }
}
```

```txt filename=".gitignore"
# ...
.next
next-env.d.ts
```

Bây giờ bạn có thể chạy:

```bash
npm run dev
```

Mở [http://localhost:3000](http://localhost:3000). Bạn sẽ thấy ứng dụng của mình hiện đang chạy trên Next.js (ở chế độ SPA).

### Bước 11: Dọn dẹp

Bây giờ bạn có thể xóa các tạo phẩm dành riêng cho Create React App:

- `public/index.html`
- `src/index.tsx`
- `src/react-app-env.d.ts`
- Thiết lập `reportWebVitals`
- Dependency `react-scripts` (gỡ cài đặt nó khỏi `package.json`)

## Cân nhắc bổ sung

### Sử dụng `homepage` tùy chỉnh trong CRA

Nếu bạn đã sử dụng trường `homepage` trong `package.json` của CRA để phục vụ ứng dụng dưới một subpath cụ thể, bạn có thể sao chép điều đó trong Next.js bằng cách sử dụng [cấu hình `basePath`](/docs/app/api-reference/config/next-config-js/basePath) trong `next.config.ts`:

```ts filename="next.config.ts"
import { NextConfig } from 'next'

const nextConfig: NextConfig = {
  basePath: '/my-subpath',
  // ...
}

export default nextConfig
```

### Xử lý `Service Worker` tùy chỉnh

Nếu bạn đã sử dụng service worker của CRA (ví dụ: `serviceWorker.js` từ `create-react-app`), bạn có thể tìm hiểu cách tạo [Progressive Web Applications (PWAs)](/docs/app/guides/progressive-web-apps) với Next.js.

### Proxying API Requests

Nếu ứng dụng CRA của bạn đã sử dụng trường `proxy` trong `package.json` để chuyển tiếp các yêu cầu đến backend server, bạn có thể sao chép điều này với [Next.js rewrites](/docs/app/api-reference/config/next-config-js/rewrites) trong `next.config.ts`:

```ts filename="next.config.ts"
import { NextConfig } from 'next'

const nextConfig: NextConfig = {
  async rewrites() {
    return [
      {
        source: '/api/:path*',
        destination: 'https://your-backend.com/:path*',
      },
    ]
  },
}
```

### Custom Webpack

Nếu bạn có cấu hình webpack hoặc Babel tùy chỉnh trong CRA, bạn có thể mở rộng cấu hình của Next.js trong `next.config.ts`:

```ts filename="next.config.ts"
import { NextConfig } from 'next'

const nextConfig: NextConfig = {
  webpack: (config, { isServer }) => {
    // Modify the webpack config here
    return config
  },
}

export default nextConfig
```

> **Lưu ý**: Điều này sẽ yêu cầu sử dụng Webpack bằng cách thêm `--webpack` vào script `dev` của bạn.

### Thiết lập TypeScript

Next.js tự động thiết lập TypeScript nếu bạn có `tsconfig.json`. Đảm bảo `next-env.d.ts` được liệt kê trong mảng `include` của `tsconfig.json`:

```json
{
  "include": ["next-env.d.ts", "app/**/*", "src/**/*"]
}
```

## Khả năng tương thích Bundler

Create React App sử dụng webpack để đóng gói. Next.js hiện mặc định sử dụng [Turbopack](/docs/app/api-reference/config/next-config-js/turbopack) để phát triển cục bộ nhanh hơn:

```bash
next dev  # Uses Turbopack by default
```

Để sử dụng Webpack thay thế (tương tự như CRA):

```bash
next dev --webpack
```

Bạn vẫn có thể cung cấp một [cấu hình webpack tùy chỉnh](/docs/app/api-reference/config/next-config-js/webpack) nếu bạn cần di chuyển các cài đặt webpack nâng cao từ CRA.

## Các bước tiếp theo

Nếu mọi thứ hoạt động, bây giờ bạn có một ứng dụng Next.js hoạt động chạy như một single-page application. Bạn chưa tận dụng các tính năng Next.js như server-side rendering hoặc file-based routing, nhưng bây giờ bạn có thể làm như vậy dần dần:

- **Di chuyển từ React Router** sang [Next.js App Router](/docs/app) để:
  - Automatic code splitting
  - [Streaming server rendering](/docs/app/api-reference/file-conventions/loading)
  - [React Server Components](/docs/app/getting-started/server-and-client-components)
- **Tối ưu hóa hình ảnh** với [`<Image>` component](/docs/app/api-reference/components/image)
- **Tối ưu hóa fonts** với [`next/font`](/docs/app/api-reference/components/font)
- **Tối ưu hóa third-party scripts** với [`<Script>` component](/docs/app/guides/scripts)
- **Kích hoạt ESLint** với [các quy tắc được đề xuất](/docs/app/api-reference/config/eslint#setup-eslint) của Next.js

> **Lưu ý**: Sử dụng static export (`output: 'export'`) [hiện không hỗ trợ](https://github.com/vercel/next.js/issues/54393) hook `useParams` hoặc các tính năng server khác. Để sử dụng tất cả các tính năng Next.js, hãy xóa `output: 'export'` khỏi `next.config.ts` của bạn.
