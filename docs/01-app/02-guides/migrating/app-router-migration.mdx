## Nâng cấp

### Phiên bản Node.js

Phiên bản Node.js tối thiểu hiện nay là **v18.17**. Xem [tài liệu Node.js](https://nodejs.org/docs/latest-v18.x/api/) để biết thêm thông tin.

### Phiên bản Next.js

Để cập nhật lên Next.js phiên bản 13, hãy chạy lệnh sau bằng trình quản lý gói ưa thích của bạn:

```bash filename="Terminal"
npm install next@latest react@latest react-dom@latest
```

### Phiên bản ESLint

Nếu bạn đang sử dụng ESLint, bạn cần nâng cấp phiên bản ESLint của mình:

```bash filename="Terminal"
npm install -D eslint-config-next@latest
```

> **Lưu ý**: Bạn có thể cần khởi động lại ESLint server trong VS Code để các thay đổi ESLint có hiệu lực. Mở Command Palette (`cmd+shift+p` trên Mac; `ctrl+shift+p` trên Windows) và tìm kiếm `ESLint: Restart ESLint Server`.

## Nâng cấp các tính năng mới

Next.js 13 đã giới thiệu [App Router](/docs/app) mới với các tính năng và quy ước mới. Router mới có sẵn trong thư mục `app` và cùng tồn tại với thư mục `pages`.

Nâng cấp lên Next.js 13 **không** yêu cầu sử dụng App Router. Bạn có thể tiếp tục sử dụng `pages` với các tính năng mới hoạt động trong cả hai thư mục, chẳng hạn như [Image component](#image-component), [Link component](#link-component), [Script component](#script-component), và [Font optimization](#font-optimization) đã được cập nhật.

### `<Image/>` Component

Next.js 12 đã giới thiệu những cải tiến mới cho Image Component với một import tạm thời: `next/future/image`. Những cải tiến này bao gồm ít JavaScript phía client hơn, cách dễ dàng hơn để mở rộng và tạo kiểu cho hình ảnh, khả năng truy cập tốt hơn và lazy loading gốc của trình duyệt.

Trong phiên bản 13, hành vi mới này hiện là mặc định cho `next/image`.

Có hai codemods để giúp bạn di chuyển sang Image Component mới:

- [**`next-image-to-legacy-image` codemod**](/docs/app/guides/upgrading/codemods#next-image-to-legacy-image): Đổi tên `next/image` imports thành `next/legacy/image` một cách an toàn và tự động. Các components hiện có sẽ duy trì hành vi tương tự.
- [**`next-image-experimental` codemod**](/docs/app/guides/upgrading/codemods#next-image-experimental): Thêm inline styles một cách nguy hiểm và loại bỏ các props không sử dụng. Điều này sẽ thay đổi hành vi của các components hiện có để phù hợp với các mặc định mới. Để sử dụng codemod này, bạn cần chạy `next-image-to-legacy-image` codemod trước.

### `<Link>` Component

[`<Link>` Component](/docs/app/api-reference/components/link) không còn yêu cầu thêm thẻ `<a>` làm con theo cách thủ công nữa. Hành vi này đã được thêm vào như một tùy chọn thử nghiệm trong [phiên bản 12.2](https://nextjs.org/blog/next-12-2) và hiện là mặc định. Trong Next.js 13, `<Link>` luôn render `<a>` và cho phép bạn chuyển tiếp props đến thẻ bên dưới.

Ví dụ:

```jsx
import Link from 'next/link'

// Next.js 12: `<a>` has to be nested otherwise it's excluded
<Link href="/about">
  <a>About</a>
</Link>

// Next.js 13: `<Link>` always renders `<a>` under the hood
<Link href="/about">
  About
</Link>
```

Để nâng cấp các liên kết của bạn lên Next.js 13, bạn có thể sử dụng [`new-link` codemod](/docs/app/guides/upgrading/codemods#new-link).

### `<Script>` Component

Hành vi của [`next/script`](/docs/app/api-reference/components/script) đã được cập nhật để hỗ trợ cả `pages` và `app`, nhưng một số thay đổi cần được thực hiện để đảm bảo quá trình di chuyển suôn sẻ:

- Di chuyển bất kỳ scripts `beforeInteractive` nào bạn đã bao gồm trước đó trong `_document.js` sang file root layout (`app/layout.tsx`).
- Chiến lược `worker` thử nghiệm chưa hoạt động trong `app` và các scripts được biểu thị bằng chiến lược này sẽ phải bị xóa hoặc sửa đổi để sử dụng một chiến lược khác (ví dụ: `lazyOnload`).
- Các trình xử lý `onLoad`, `onReady`, và `onError` sẽ không hoạt động trong Server Components vì vậy hãy đảm bảo di chuyển chúng sang một [Client Component](/docs/app/getting-started/server-and-client-components) hoặc loại bỏ chúng hoàn toàn.

### Font Optimization

Trước đây, Next.js đã giúp bạn tối ưu hóa fonts bằng cách [inlining font CSS](/docs/app/api-reference/components/font). Phiên bản 13 giới thiệu module [`next/font`](/docs/app/api-reference/components/font) mới cung cấp cho bạn khả năng tùy chỉnh trải nghiệm tải font của mình trong khi vẫn đảm bảo hiệu suất tuyệt vời và quyền riêng tư. `next/font` được hỗ trợ trong cả thư mục `pages` và `app`.

Trong khi [inlining CSS](/docs/app/api-reference/components/font) vẫn hoạt động trong `pages`, nó không hoạt động trong `app`. Bạn nên sử dụng [`next/font`](/docs/app/api-reference/components/font) thay thế.

Xem trang [Font Optimization](/docs/app/api-reference/components/font) để tìm hiểu cách sử dụng `next/font`.

## Di chuyển từ `pages` sang `app`

> **🎥 Xem:** Tìm hiểu cách áp dụng dần dần App Router → [YouTube (16 phút)](https://www.youtube.com/watch?v=YQMSietiFm0).

Chuyển sang App Router có thể là lần đầu tiên sử dụng các tính năng React mà Next.js xây dựng dựa trên đó như Server Components, Suspense, và nhiều hơn nữa. Khi kết hợp với các tính năng Next.js mới như [special files](/docs/app/api-reference/file-conventions) và [layouts](/docs/app/api-reference/file-conventions/layout), việc di chuyển có nghĩa là các khái niệm mới, mô hình tư duy và thay đổi hành vi cần tìm hiểu.

Chúng tôi khuyên bạn nên giảm độ phức tạp kết hợp của các bản cập nhật này bằng cách chia nhỏ quá trình di chuyển của bạn thành các bước nhỏ hơn. Thư mục `app` được thiết kế có chủ ý để hoạt động đồng thời với thư mục `pages` để cho phép di chuyển dần dần từng trang.

- Thư mục `app` hỗ trợ nested routes _và_ layouts. [Tìm hiểu thêm](/docs/app/getting-started/layouts-and-pages).
- Sử dụng các thư mục lồng nhau để xác định routes và một file `page.js` đặc biệt để làm cho một phân đoạn route có thể truy cập công khai. [Tìm hiểu thêm](#step-4-migrating-pages).
- [Các quy ước file đặc biệt](/docs/app/api-reference/file-conventions) được sử dụng để tạo UI cho mỗi phân đoạn route. Các file đặc biệt phổ biến nhất là `page.js` và `layout.js`.
  - Sử dụng `page.js` để xác định UI duy nhất cho một route.
  - Sử dụng `layout.js` để xác định UI được chia sẻ qua nhiều routes.
  - Các phần mở rộng file `.js`, `.jsx`, hoặc `.tsx` có thể được sử dụng cho các file đặc biệt.
- Bạn có thể đặt các file khác bên trong thư mục `app` như components, styles, tests, và nhiều hơn nữa. [Tìm hiểu thêm](/docs/app).
- Các hàm data fetching như `getServerSideProps` và `getStaticProps` đã được thay thế bằng [một API mới](/docs/app/getting-started/fetching-data) bên trong `app`. `getStaticPaths` đã được thay thế bằng [`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params).
- `pages/_app.js` và `pages/_document.js` đã được thay thế bằng một `app/layout.js` root layout duy nhất. [Tìm hiểu thêm](/docs/app/api-reference/file-conventions/layout#root-layout).
- `pages/_error.js` đã được thay thế bằng các file đặc biệt `error.js` chi tiết hơn. [Tìm hiểu thêm](/docs/app/getting-started/error-handling).
- `pages/404.js` đã được thay thế bằng file [`not-found.js`](/docs/app/api-reference/file-conventions/not-found).
- `pages/api/*` API Routes đã được thay thế bằng file đặc biệt [`route.js`](/docs/app/api-reference/file-conventions/route) (Route Handler).

### Bước 1: Tạo thư mục `app`

Cập nhật lên phiên bản Next.js mới nhất (yêu cầu 13.4 hoặc cao hơn):

```bash
npm install next@latest
```

Sau đó, tạo một thư mục `app` mới tại thư mục gốc của dự án của bạn (hoặc thư mục `src/`).

### Bước 2: Tạo một Root Layout

Tạo một file `app/layout.tsx` mới bên trong thư mục `app`. Đây là một [root layout](/docs/app/api-reference/file-conventions/layout#root-layout) sẽ áp dụng cho tất cả các routes bên trong `app`.

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  // Layouts must accept a children prop.
  // This will be populated with nested layouts or pages
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({
  // Layouts must accept a children prop.
  // This will be populated with nested layouts or pages
  children,
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

- Thư mục `app` **phải** bao gồm một root layout.
- Root layout phải xác định các thẻ `<html>`, và `<body>` vì Next.js không tự động tạo chúng
- Root layout thay thế các file `pages/_app.tsx` và `pages/_document.tsx`.
- Các phần mở rộng `.js`, `.jsx`, hoặc `.tsx` có thể được sử dụng cho các file layout.

Để quản lý các phần tử HTML `<head>`, bạn có thể sử dụng [hỗ trợ SEO tích hợp](/docs/app/getting-started/metadata-and-og-images):

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'Home',
  description: 'Welcome to Next.js',
}
```

```jsx filename="app/layout.js" switcher
export const metadata = {
  title: 'Home',
  description: 'Welcome to Next.js',
}
```

#### Di chuyển `_document.js` và `_app.js`

Nếu bạn có một file `_app` hoặc `_document` hiện có, bạn có thể sao chép nội dung (ví dụ: global styles) sang root layout (`app/layout.tsx`). Styles trong `app/layout.tsx` sẽ _không_ áp dụng cho `pages/*`. Bạn nên giữ `_app`/`_document` trong khi di chuyển để ngăn các routes `pages/*` của bạn bị hỏng. Sau khi di chuyển hoàn toàn, bạn có thể xóa chúng một cách an toàn.

Nếu bạn đang sử dụng bất kỳ React Context providers nào, chúng sẽ cần được chuyển sang một [Client Component](/docs/app/getting-started/server-and-client-components).

#### Di chuyển pattern `getLayout()` sang Layouts (Tùy chọn)

Next.js khuyến nghị thêm một [thuộc tính vào Page components](/docs/pages/building-your-application/routing/pages-and-layouts#layout-pattern) để đạt được per-page layouts trong thư mục `pages`. Pattern này có thể được thay thế bằng hỗ trợ gốc cho [nested layouts](/docs/app/api-reference/file-conventions/layout) trong thư mục `app`.

<details>
  <summary>Xem ví dụ trước và sau</summary>

**Trước**

```jsx filename="components/DashboardLayout.js"
export default function DashboardLayout({ children }) {
  return (
    <div>
      <h2>My Dashboard</h2>
      {children}
    </div>
  )
}
```

```jsx filename="pages/dashboard/index.js"
import DashboardLayout from '../components/DashboardLayout'

export default function Page() {
  return <p>My Page</p>
}

Page.getLayout = function getLayout(page) {
  return <DashboardLayout>{page}</DashboardLayout>
}
```

**Sau**

- Xóa thuộc tính `Page.getLayout` khỏi `pages/dashboard/index.js` và làm theo [các bước để di chuyển pages](#step-4-migrating-pages) sang thư mục `app`.

  ```jsx filename="app/dashboard/page.js"
  export default function Page() {
    return <p>My Page</p>
  }
  ```

- Di chuyển nội dung của `DashboardLayout` vào một [Client Component](/docs/app/getting-started/server-and-client-components) mới để giữ lại hành vi của thư mục `pages`.

  ```jsx filename="app/dashboard/DashboardLayout.js"
  'use client' // this directive should be at top of the file, before any imports.

  // This is a Client Component
  export default function DashboardLayout({ children }) {
    return (
      <div>
        <h2>My Dashboard</h2>
        {children}
      </div>
    )
  }
  ```

- Import `DashboardLayout` vào một file `layout.js` mới bên trong thư mục `app`.

  ```jsx filename="app/dashboard/layout.js"
  import DashboardLayout from './DashboardLayout'

  // This is a Server Component
  export default function Layout({ children }) {
    return <DashboardLayout>{children}</DashboardLayout>
  }
  ```

- Bạn có thể di chuyển dần dần các phần không tương tác của `DashboardLayout.js` (Client Component) vào `layout.js` (Server Component) để giảm lượng JavaScript component bạn gửi đến client.

</details>

### Bước 3: Di chuyển `next/head`

Trong thư mục `pages`, React component `next/head` được sử dụng để quản lý các phần tử HTML `<head>` như `title` và `meta`. Trong thư mục `app`, `next/head` được thay thế bằng [hỗ trợ SEO tích hợp](/docs/app/getting-started/metadata-and-og-images) mới.

**Trước:**

```tsx filename="pages/index.tsx" switcher
import Head from 'next/head'

export default function Page() {
  return (
    <>
      <Head>
        <title>My page title</title>
      </Head>
    </>
  )
}
```

```jsx filename="pages/index.js" switcher
import Head from 'next/head'

export default function Page() {
  return (
    <>
      <Head>
        <title>My page title</title>
      </Head>
    </>
  )
}
```

**Sau:**

```tsx filename="app/page.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'My Page Title',
}

export default function Page() {
  return '...'
}
```

```jsx filename="app/page.js" switcher
export const metadata = {
  title: 'My Page Title',
}

export default function Page() {
  return '...'
}
```

[Xem tất cả các tùy chọn metadata](/docs/app/api-reference/functions/generate-metadata).

### Bước 4: Di chuyển Pages

- Pages trong [`app` directory](/docs/app) là [Server Components](/docs/app/getting-started/server-and-client-components) theo mặc định. Điều này khác với thư mục `pages` nơi pages là [Client Components](/docs/app/getting-started/server-and-client-components).
- [Data fetching](/docs/app/getting-started/fetching-data) đã thay đổi trong `app`. `getServerSideProps`, `getStaticProps` và `getInitialProps` đã được thay thế bằng một API đơn giản hơn.
- Thư mục `app` sử dụng các thư mục lồng nhau để xác định routes và một file `page.js` đặc biệt để làm cho một phân đoạn route có thể truy cập công khai.
- | `pages` Directory | `app` Directory       | Route          |
  | ----------------- | --------------------- | -------------- |
  | `index.js`        | `page.js`             | `/`            |
  | `about.js`        | `about/page.js`       | `/about`       |
  | `blog/[slug].js`  | `blog/[slug]/page.js` | `/blog/post-1` |

Chúng tôi khuyên bạn nên chia nhỏ việc di chuyển của một page thành hai bước chính:

- Bước 1: Di chuyển Page Component được export mặc định vào một Client Component mới.
- Bước 2: Import Client Component mới vào một file `page.js` mới bên trong thư mục `app`.

> **Lưu ý**: Đây là đường dẫn di chuyển dễ nhất vì nó có hành vi tương đương nhất với thư mục `pages`.

**Bước 1: Tạo một Client Component mới**

- Tạo một file riêng biệt mới bên trong thư mục `app` (ví dụ: `app/home-page.tsx` hoặc tương tự) export một Client Component. Để xác định Client Components, thêm directive `'use client'` vào đầu file (trước bất kỳ imports nào).
  - Tương tự như Pages Router, có một [bước tối ưu hóa](/docs/app/getting-started/server-and-client-components#on-the-client-first-load) để prerender Client Components thành HTML tĩnh khi tải trang ban đầu.
- Di chuyển page component được export mặc định từ `pages/index.js` sang `app/home-page.tsx`.

```tsx filename="app/home-page.tsx" switcher
'use client'

// This is a Client Component (same as components in the `pages` directory)
// It receives data as props, has access to state and effects, and is
// prerendered on the server during the initial page load.
export default function HomePage({ recentPosts }) {
  return (
    <div>
      {recentPosts.map((post) => (
        <div key={post.id}>{post.title}</div>
      ))}
    </div>
  )
}
```

```jsx filename="app/home-page.js" switcher
'use client'

// This is a Client Component. It receives data as props and
// has access to state and effects just like Page components
// in the `pages` directory.
export default function HomePage({ recentPosts }) {
  return (
    <div>
      {recentPosts.map((post) => (
        <div key={post.id}>{post.title}</div>
      ))}
    </div>
  )
}
```

**Bước 2: Tạo một page mới**

- Tạo một file `app/page.tsx` mới bên trong thư mục `app`. Đây là một Server Component theo mặc định.
- Import `home-page.tsx` Client Component vào page.
- Nếu bạn đang fetch dữ liệu trong `pages/index.js`, hãy di chuyển logic fetch dữ liệu trực tiếp vào Server Component bằng cách sử dụng [các API data fetching mới](/docs/app/getting-started/fetching-data). Xem [hướng dẫn nâng cấp data fetching](#step-6-migrating-data-fetching-methods) để biết thêm chi tiết.

  ```tsx filename="app/page.tsx" switcher
  // Import your Client Component
  import HomePage from './home-page'

  async function getPosts() {
    const res = await fetch('https://...')
    const posts = await res.json()
    return posts
  }

  export default async function Page() {
    // Fetch data directly in a Server Component
    const recentPosts = await getPosts()
    // Forward fetched data to your Client Component
    return <HomePage recentPosts={recentPosts} />
  }
  ```

  ```jsx filename="app/page.js" switcher
  // Import your Client Component
  import HomePage from './home-page'

  async function getPosts() {
    const res = await fetch('https://...')
    const posts = await res.json()
  ```

- Nếu page trước đó của bạn đã sử dụng `useRouter`, bạn sẽ cần cập nhật lên các routing hooks mới. [Tìm hiểu thêm](/docs/app/api-reference/functions/use-router).
- Khởi động development server của bạn và truy cập [`http://localhost:3000`](http://localhost:3000). Bạn sẽ thấy index route hiện có của mình, hiện được phục vụ thông qua thư mục app.

### Bước 5: Di chuyển Routing Hooks

Một router mới đã được thêm vào để hỗ trợ hành vi mới trong thư mục `app`.

Trong `app`, bạn nên sử dụng ba hooks mới được import từ `next/navigation`: [`useRouter()`](/docs/app/api-reference/functions/use-router), [`usePathname()`](/docs/app/api-reference/functions/use-pathname), và [`useSearchParams()`](/docs/app/api-reference/functions/use-search-params).

- Hook `useRouter` mới được import từ `next/navigation` và có hành vi khác với hook `useRouter` trong `pages` được import từ `next/router`.
  - [`useRouter` hook được import từ `next/router`](/docs/pages/api-reference/functions/use-router) không được hỗ trợ trong thư mục `app` nhưng có thể tiếp tục được sử dụng trong thư mục `pages`.
- `useRouter` mới không trả về chuỗi `pathname`. Sử dụng hook `usePathname` riêng biệt thay thế.
- `useRouter` mới không trả về đối tượng `query`. Search parameters và dynamic route parameters hiện được tách biệt. Sử dụng các hooks `useSearchParams` và `useParams` thay thế.
- Bạn có thể sử dụng `useSearchParams` và `usePathname` cùng nhau để lắng nghe các thay đổi của trang. Xem phần [Router Events](/docs/app/api-reference/functions/use-router#router-events) để biết thêm chi tiết.
- Các hooks mới này chỉ được hỗ trợ trong Client Components. Chúng không thể được sử dụng trong Server Components.

```tsx filename="app/example-client-component.tsx" switcher
'use client'

import { useRouter, usePathname, useSearchParams } from 'next/navigation'

export default function ExampleClientComponent() {
  const router = useRouter()
  const pathname = usePathname()
  const searchParams = useSearchParams()

  // ...
}
```

```jsx filename="app/example-client-component.js" switcher
'use client'

import { useRouter, usePathname, useSearchParams } from 'next/navigation'

export default function ExampleClientComponent() {
  const router = useRouter()
  const pathname = usePathname()
  const searchParams = useSearchParams()

  // ...
}
```

Ngoài ra, hook `useRouter` mới có các thay đổi sau:

- `isFallback` đã bị xóa vì `fallback` đã [được thay thế](#replacing-fallback).
- Các giá trị `locale`, `locales`, `defaultLocales`, `domainLocales` đã bị xóa vì các tính năng i18n tích hợp sẵn của Next.js không còn cần thiết trong thư mục `app`. [Tìm hiểu thêm về i18n](/docs/app/guides/internationalization).
- `basePath` đã bị xóa. Giải pháp thay thế sẽ không phải là một phần của `useRouter`. Nó chưa được triển khai.
- `asPath` đã bị xóa vì khái niệm `as` đã bị xóa khỏi router mới.
- `isReady` đã bị xóa vì nó không còn cần thiết nữa. Trong quá trình [static rendering](/docs/app/guides/caching#static-rendering), bất kỳ component nào sử dụng hook [`useSearchParams()`](/docs/app/api-reference/functions/use-search-params) sẽ bỏ qua bước prerendering và thay vào đó được render trên client tại runtime.
- `route` đã bị xóa. `usePathname` hoặc `useSelectedLayoutSegments()` cung cấp một giải pháp thay thế.

[Xem tài liệu tham khảo API `useRouter()`](/docs/app/api-reference/functions/use-router).

#### Chia sẻ components giữa `pages` và `app`

Để giữ cho các components tương thích giữa các routers `pages` và `app`, hãy tham khảo [`useRouter` hook từ `next/compat/router`](/docs/pages/api-reference/functions/use-router#the-nextcompatrouter-export).
Đây là hook `useRouter` từ thư mục `pages`, nhưng nhằm mục đích được sử dụng trong khi chia sẻ components giữa các routers. Khi bạn đã sẵn sàng chỉ sử dụng nó trên router `app`, hãy cập nhật lên [`useRouter` mới từ `next/navigation`](/docs/app/api-reference/functions/use-router).

### Bước 6: Di chuyển Data Fetching Methods

Thư mục `pages` sử dụng `getServerSideProps` và `getStaticProps` để fetch dữ liệu cho các trang. Bên trong thư mục `app`, các hàm fetch dữ liệu trước đây này được thay thế bằng một [API đơn giản hơn](/docs/app/getting-started/fetching-data) được xây dựng dựa trên `fetch()` và `async` React Server Components.

```tsx filename="app/page.tsx" switcher
export default async function Page() {
  // This request should be cached until manually invalidated.
  // Similar to `getStaticProps`.
  // `force-cache` is the default and can be omitted.
  const staticData = await fetch(`https://...`, { cache: 'force-cache' })

  // This request should be refetched on every request.
  // Similar to `getServerSideProps`.
  const dynamicData = await fetch(`https://...`, { cache: 'no-store' })

  // This request should be cached with a lifetime of 10 seconds.
  // Similar to `getStaticProps` with the `revalidate` option.
  const revalidatedData = await fetch(`https://...`, {
    next: { revalidate: 10 },
  })

  return <div>...</div>
}
```

#### Server-side Rendering (`getServerSideProps`)

Trong thư mục `pages`, `getServerSideProps` được sử dụng để fetch dữ liệu trên server và chuyển tiếp props đến React component được export mặc định trong file. HTML ban đầu cho trang được prerendered từ server, sau đó là "hydrating" trang trong trình duyệt (làm cho nó tương tác).

```jsx filename="pages/dashboard.js"
// `pages` directory

export async function getServerSideProps() {
  const res = await fetch(`https://...`)
  const projects = await res.json()

  return { props: { projects } }
}

export default function Dashboard({ projects }) {
  return (
    <ul>
      {projects.map((project) => (
        <li key={project.id}>{project.name}</li>
      ))}
    </ul>
  )
}
```

Trong App Router, chúng ta có thể đặt việc fetch dữ liệu của mình bên trong các React components bằng cách sử dụng [Server Components](/docs/app/getting-started/server-and-client-components). Điều này cho phép chúng ta gửi ít JavaScript hơn đến client, trong khi vẫn duy trì HTML được render từ server.

Bằng cách đặt tùy chọn `cache` thành `no-store`, chúng ta có thể chỉ ra rằng dữ liệu đã fetch [không bao giờ được cache](/docs/app/getting-started/fetching-data). Điều này tương tự như `getServerSideProps` trong thư mục `pages`.

#### Truy cập Request Object

Trong thư mục `pages`, bạn có thể truy xuất dữ liệu dựa trên request dựa trên Node.js HTTP API.

Ví dụ, bạn có thể truy xuất đối tượng `req` từ `getServerSideProps` và sử dụng nó để truy xuất cookies và headers của request.

```jsx filename="pages/index.js"
// `pages` directory

export async function getServerSideProps({ req, query }) {
  const authHeader = req.getHeaders()['authorization'];
  const theme = req.cookies['theme'];

  return { props: { ... }}
}

export default function Page(props) {
  return ...
}
```

Thư mục `app` hiển thị các hàm chỉ đọc mới để truy xuất dữ liệu request:

- [`headers`](/docs/app/api-reference/functions/headers): Dựa trên Web Headers API, và có thể được sử dụng bên trong [Server Components](/docs/app/getting-started/server-and-client-components) để truy xuất request headers.
- [`cookies`](/docs/app/api-reference/functions/cookies): Dựa trên Web Cookies API, và có thể được sử dụng bên trong [Server Components](/docs/app/getting-started/server-and-client-components) để truy xuất cookies.

```tsx filename="app/page.tsx" switcher
// `app` directory
import { cookies, headers } from 'next/headers'

async function getData() {
  const authHeader = (await headers()).get('authorization')

  return '...'
}

export default async function Page() {
  // You can use `cookies` or `headers` inside Server Components
  // directly or in your data fetching function
  const theme = (await cookies()).get('theme')
  const data = await getData()
  return '...'
}
```

#### Static Site Generation (`getStaticProps`)

Trong thư mục `pages`, hàm `getStaticProps` được sử dụng để pre-render một trang tại build time. Hàm này có thể được sử dụng để fetch dữ liệu từ một API bên ngoài hoặc trực tiếp từ cơ sở dữ liệu, và truyền dữ liệu này xuống toàn bộ trang khi nó đang được tạo trong quá trình build.

```jsx filename="pages/index.js"
// `pages` directory

export async function getStaticProps() {
  const res = await fetch(`https://...`)
  const projects = await res.json()

  return { props: { projects } }
}

export default function Index({ projects }) {
  return projects.map((project) => <div>{project.name}</div>)
}
```

Trong thư mục `app`, việc fetch dữ liệu với [`fetch()`](/docs/app/api-reference/functions/fetch) sẽ mặc định là `cache: 'force-cache'`, sẽ cache dữ liệu request cho đến khi bị vô hiệu hóa thủ công. Điều này tương tự như `getStaticProps` trong thư mục `pages`.

```jsx filename="app/page.js"
// `app` directory

// This function can be named anything

  return projects.map((project) => <div>{project.name}</div>)
}
```

#### Dynamic paths (`getStaticPaths`)

Trong thư mục `pages`, hàm `getStaticPaths` được sử dụng để xác định các dynamic paths nên được pre-rendered tại build time.

```jsx filename="pages/posts/[id].js"
// `pages` directory
import PostLayout from '@/components/post-layout'

export async function getStaticPaths() {
  return {
    paths: [{ params: { id: '1' } }, { params: { id: '2' } }],
  }
}

export async function getStaticProps({ params }) {
  const res = await fetch(`https://.../posts/${params.id}`)
  const post = await res.json()

  return { props: { post } }
}

export default function Post({ post }) {
  return <PostLayout post={post} />
}
```

Trong thư mục `app`, `getStaticPaths` được thay thế bằng [`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params).

[`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params) hoạt động tương tự như `getStaticPaths`, nhưng có API đơn giản hóa để trả về các tham số route và có thể được sử dụng bên trong [layouts](/docs/app/api-reference/file-conventions/layout). Hình dạng trả về của `generateStaticParams` là một mảng các segments thay vì một mảng các đối tượng `param` lồng nhau hoặc một chuỗi các đường dẫn đã giải quyết.

```jsx filename="app/posts/[id]/page.js"
// `app` directory
import PostLayout from '@/components/post-layout'

export async function generateStaticParams() {
  return [{ id: '1' }, { id: '2' }]
}

async function getPost(params) {
  const res = await fetch(`https://.../posts/${(await params).id}`)
  const post = await res.json()

  return post
}

export default async function Post({ params }) {
  const post = await getPost(params)

  return <PostLayout post={post} />
}
```

Sử dụng tên `generateStaticParams` thích hợp hơn `getStaticPaths` cho mô hình mới trong thư mục `app`. Tiền tố `get` được thay thế bằng `generate` mô tả hơn, phù hợp hơn khi đứng một mình bây giờ khi `getStaticProps` và `getServerSideProps` không còn cần thiết nữa. Hậu tố `Paths` được thay thế bằng `Params`, phù hợp hơn cho nested routing với nhiều dynamic segments.

#### Thay thế `fallback`

Trong thư mục `pages`, thuộc tính `fallback` được trả về từ `getStaticPaths` được sử dụng để xác định hành vi của một trang không được pre-rendered tại build time. Thuộc tính này có thể được đặt thành `true` để hiển thị trang fallback trong khi trang đang được tạo, `false` để hiển thị trang 404, hoặc `blocking` để tạo trang tại request time.

```jsx filename="pages/posts/[id].js"
// `pages` directory

export async function getStaticPaths() {
  return {
    paths: [],
    fallback: 'blocking'
  };
}

export async function getStaticProps({ params }) {
  ...
}

export default function Post({ post }) {
  return ...
}
```

Trong thư mục `app`, thuộc tính [`config.dynamicParams`](/docs/app/api-reference/file-conventions/route-segment-config#dynamicparams) kiểm soát cách các params bên ngoài [`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params) được xử lý:

- **`true`**: (mặc định) Các dynamic segments không có trong `generateStaticParams` được tạo theo yêu cầu.
- **`false`**: Các dynamic segments không có trong `generateStaticParams` sẽ trả về 404.

Điều này thay thế tùy chọn `fallback: true | false | 'blocking'` của `getStaticPaths` trong thư mục `pages`. Tùy chọn `fallback: 'blocking'` không có trong `dynamicParams` vì sự khác biệt giữa `'blocking'` và `true` là không đáng kể với streaming.

```jsx filename="app/posts/[id]/page.js"
// `app` directory

export const dynamicParams = true;

export async function generateStaticParams() {
  return [...]
}

async function getPost(params) {
  ...
}

export default async function Post({ params }) {
  const post = await getPost(params);

  return ...
}
```

Với [`dynamicParams`](/docs/app/api-reference/file-conventions/route-segment-config#dynamicparams) được đặt thành `true` (mặc định), khi một phân đoạn route được yêu cầu mà chưa được tạo, nó sẽ được server-rendered và cached.

#### Incremental Static Regeneration (`getStaticProps` với `revalidate`)

Trong thư mục `pages`, hàm `getStaticProps` cho phép bạn thêm trường `revalidate` để tự động tạo lại trang sau một khoảng thời gian nhất định.

```jsx filename="pages/index.js"
// `pages` directory

export async function getStaticProps() {
  const res = await fetch(`https://.../posts`)
  const posts = await res.json()

  return {
    props: { posts },
    revalidate: 60,
  }
}

export default function Index({ posts }) {
  return (
    <Layout>
      <PostList posts={posts} />
    </Layout>
  )
}
```

Trong thư mục `app`, việc fetch dữ liệu với [`fetch()`](/docs/app/api-reference/functions/fetch) có thể sử dụng `revalidate`, sẽ cache request trong khoảng thời gian giây được chỉ định.

```jsx filename="app/page.js"
// `app` directory

async function getPosts() {
  const res = await fetch(`https://.../posts`, { next: { revalidate: 60 } })
  const data = await res.json()

  return data.posts
}

export default async function PostList() {
  const posts = await getPosts()

  return posts.map((post) => <div>{post.name}</div>)
}
```

## Sử dụng App Router cùng với Pages Router

Khi điều hướng giữa các routes được phục vụ bởi các Next.js routers khác nhau, sẽ có một hard navigation. Automatic link prefetching với `next/link` sẽ không prefetch qua các routers.

Thay vào đó, bạn có thể [tối ưu hóa điều hướng](https://vercel.com/guides/optimizing-hard-navigations) giữa App Router và Pages Router để giữ lại các chuyển đổi trang nhanh và đã được prefetch. [Tìm hiểu thêm](https://vercel.com/guides/optimizing-hard-navigations).

Next.js cung cấp các chuyển đổi Codemod để giúp nâng cấp codebase của bạn khi một tính năng bị phản đối (deprecated). Xem [Codemods](/docs/app/guides/upgrading/codemods) để biết thêm thông tin.
