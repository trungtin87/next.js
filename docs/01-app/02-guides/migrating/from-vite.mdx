Hướng dẫn này sẽ giúp bạn di chuyển một ứng dụng Vite hiện có sang Next.js.

## Tại sao nên chuyển đổi?

Có một số lý do khiến bạn có thể muốn chuyển từ Vite sang Next.js:

### Thời gian tải trang ban đầu chậm

Nếu bạn đã xây dựng ứng dụng của mình với [default Vite plugin for React](https://github.com/vitejs/vite-plugin-react/tree/main/packages/plugin-react), ứng dụng của bạn là một ứng dụng purely client-side. Các ứng dụng chỉ phía client, còn được gọi là single-page applications (SPAs), thường gặp phải thời gian tải trang ban đầu chậm. Điều này xảy ra do một vài lý do:

1. Trình duyệt cần đợi mã React và toàn bộ gói ứng dụng của bạn tải xuống và chạy trước khi mã của bạn có thể gửi yêu cầu tải một số dữ liệu.
2. Mã ứng dụng của bạn tăng lên với mỗi tính năng mới và dependency bổ sung mà bạn thêm vào.

### Không có automatic code splitting

Vấn đề trước đây về thời gian tải chậm có thể được quản lý phần nào bằng code splitting. Tuy nhiên, nếu bạn cố gắng thực hiện code splitting thủ công, bạn thường sẽ làm cho hiệu suất tồi tệ hơn. Rất dễ vô tình tạo ra network waterfalls khi code-splitting thủ công. Next.js cung cấp automatic code splitting được tích hợp vào router của nó.

### Network waterfalls

Một nguyên nhân phổ biến gây ra hiệu suất kém xảy ra khi các ứng dụng thực hiện các yêu cầu client-server tuần tự để fetch dữ liệu. Một mô hình phổ biến để fetch dữ liệu trong một SPA là ban đầu render một placeholder, và sau đó fetch dữ liệu sau khi component đã mount. Thật không may, điều này có nghĩa là một child component fetch dữ liệu không thể bắt đầu fetch cho đến khi parent component đã tải xong dữ liệu của chính nó.

Trong khi việc fetch dữ liệu trên client được hỗ trợ với Next.js, nó cũng cung cấp cho bạn tùy chọn chuyển data fetching sang server, điều này có thể loại bỏ client-server waterfalls.

### Trạng thái tải nhanh và có chủ đích

Với hỗ trợ tích hợp cho [streaming thông qua React Suspense](/docs/app/getting-started/linking-and-navigating#streaming), bạn có thể chủ đích hơn về phần nào của UI bạn muốn tải trước và theo thứ tự nào mà không tạo ra network waterfalls.

Điều này cho phép bạn xây dựng các trang tải nhanh hơn và loại bỏ [layout shifts](https://vercel.com/blog/how-core-web-vitals-affect-seo).

### Chọn chiến lược data fetching

Tùy thuộc vào nhu cầu của bạn, Next.js cho phép bạn chọn chiến lược data fetching của mình trên cơ sở từng trang và component. Bạn có thể quyết định fetch tại build time, tại request time trên server, hoặc trên client. Ví dụ, bạn có thể fetch dữ liệu từ CMS của mình và render các bài đăng blog tại build time, sau đó có thể được cache hiệu quả trên CDN.

### Proxy

[Next.js Proxy](/docs/app/api-reference/file-conventions/proxy) cho phép bạn chạy mã trên server trước khi một yêu cầu được hoàn thành. Điều này đặc biệt hữu ích để tránh flash nội dung chưa được xác thực khi người dùng truy cập trang chỉ dành cho người đã xác thực bằng cách chuyển hướng người dùng đến trang đăng nhập. Proxy cũng hữu ích cho thử nghiệm và [internationalization](/docs/app/guides/internationalization).

### Tối ưu hóa tích hợp

[Images](/docs/app/api-reference/components/image), [fonts](/docs/app/api-reference/components/font), và [third-party scripts](/docs/app/guides/scripts) thường có tác động đáng kể đến hiệu suất của ứng dụng. Next.js đi kèm với các components tích hợp tự động tối ưu hóa những thứ đó cho bạn.

## Các bước di chuyển

Mục tiêu của chúng tôi với việc di chuyển này là có được một ứng dụng Next.js hoạt động nhanh nhất có thể, để bạn có thể áp dụng các tính năng Next.js dần dần. Để bắt đầu, chúng tôi sẽ giữ nó như một ứng dụng purely client-side (SPA) mà không di chuyển router hiện có của bạn. Điều này giúp giảm thiểu khả năng gặp sự cố trong quá trình di chuyển và giảm xung đột hợp nhất.

### Bước 1: Cài đặt Next.js Dependency

Điều đầu tiên bạn cần làm là cài đặt `next` như một dependency:

```bash filename="Terminal"
npm install next@latest
```

### Bước 2: Tạo File cấu hình Next.js

Tạo một `next.config.mjs` tại thư mục gốc của dự án của bạn. File này sẽ chứa [các tùy chọn cấu hình Next.js](/docs/app/api-reference/config/next-config-js) của bạn.

```js filename="next.config.mjs"
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: 'export', // Outputs a Single-Page Application (SPA).
  distDir: './dist', // Changes the build output directory to `./dist/`.
}

export default nextConfig
```

> **Lưu ý:** Bạn có thể sử dụng `.js` hoặc `.mjs` cho file cấu hình Next.js của mình.

### Bước 3: Cập nhật cấu hình TypeScript

Nếu bạn đang sử dụng TypeScript, bạn cần cập nhật file `tsconfig.json` của mình với các thay đổi sau để làm cho nó tương thích với Next.js. Nếu bạn không sử dụng TypeScript, bạn có thể bỏ qua bước này.

1. Xóa [project reference](https://www.typescriptlang.org/tsconfig#references) đến `tsconfig.node.json`
2. Thêm `./dist/types/**/*.ts` và `./next-env.d.ts` vào [`include` array](https://www.typescriptlang.org/tsconfig#include)
3. Thêm `./node_modules` vào [`exclude` array](https://www.typescriptlang.org/tsconfig#exclude)
4. Thêm `{ "name": "next" }` vào [`plugins` array trong `compilerOptions`](https://www.typescriptlang.org/tsconfig#plugins): `"plugins": [{ "name": "next" }]`
5. Đặt [`esModuleInterop`](https://www.typescriptlang.org/tsconfig#esModuleInterop) thành `true`: `"esModuleInterop": true`
6. Đặt [`jsx`](https://www.typescriptlang.org/tsconfig#jsx) thành `react-jsx`: `"jsx": "react-jsx"`
7. Đặt [`allowJs`](https://www.typescriptlang.org/tsconfig#allowJs) thành `true`: `"allowJs": true`
8. Đặt [`forceConsistentCasingInFileNames`](https://www.typescriptlang.org/tsconfig#forceConsistentCasingInFileNames) thành `true`: `"forceConsistentCasingInFileNames": true`
9. Đặt [`incremental`](https://www.typescriptlang.org/tsconfig#incremental) thành `true`: `"incremental": true`

Đây là một ví dụ về `tsconfig.json` hoạt động với những thay đổi đó:

```json filename="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2020",
    "useDefineForClassFields": true,
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "esModuleInterop": true,
    "skipLibCheck": true,
    "moduleResolution": "bundler",
    "allowImportingTsExtensions": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noEmit": true,
    "jsx": "react-jsx",
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "allowJs": true,
    "forceConsistentCasingInFileNames": true,
    "incremental": true,
    "plugins": [{ "name": "next" }]
  },
  "include": ["./src", "./dist/types/**/*.ts", "./next-env.d.ts"],
  "exclude": ["./node_modules"]
}
```

Bạn có thể tìm thêm thông tin về cấu hình TypeScript trên [tài liệu Next.js](/docs/app/api-reference/config/typescript#ide-plugin).

### Bước 4: Tạo Root Layout

Một ứng dụng Next.js [App Router](/docs/app) phải bao gồm một file [root layout](/docs/app/api-reference/file-conventions/layout#root-layout), là một [React Server Component](/docs/app/getting-started/server-and-client-components) sẽ bao bọc tất cả các trang trong ứng dụng của bạn. File này được xác định ở cấp cao nhất của thư mục `app`.

Tương đương gần nhất với file root layout trong một ứng dụng Vite là [file `index.html`](https://vitejs.dev/guide/#index-html-and-project-root), chứa các thẻ `<html>`, `<head>`, và `<body>` của bạn.

Trong bước này, bạn sẽ chuyển đổi file `index.html` của mình thành một file root layout:

1. Tạo một thư mục `app` mới trong thư mục `src` của bạn.
2. Tạo một file `layout.tsx` mới bên trong thư mục `app` đó:

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return '...'
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return '...'
}
```

> **Lưu ý**: Các phần mở rộng `.js`, `.jsx`, hoặc `.tsx` có thể được sử dụng cho các file Layout.

3. Sao chép nội dung của file `index.html` của bạn vào component `<RootLayout>` đã tạo trước đó trong khi thay thế các thẻ `body.div#root` và `body.script` bằng `<div id="root">{children}</div>`:

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <head>
        <meta charset="UTF-8" />
        <link rel="icon" type="image/svg+xml" href="/icon.svg" />
        <meta name="viewport" content="width=device-width, initial-scale=1.0" />
        <title>My App</title>
        <meta name="description" content="My App is a..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <head>
        <meta charset="UTF-8" />
        <link rel="icon" type="image/svg+xml" href="/icon.svg" />
        <meta name="viewport" content="width=device-width, initial-scale=1.0" />
        <title>My App</title>
        <meta name="description" content="My App is a..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

4. Next.js đã bao gồm theo mặc định các thẻ [meta charset](https://developer.mozilla.org/docs/Web/HTML/Element/meta#charset) và [meta viewport](https://developer.mozilla.org/docs/Web/HTML/Viewport_meta_tag), vì vậy bạn có thể xóa chúng khỏi `<head>` của mình một cách an toàn:

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <head>
        <link rel="icon" type="image/svg+xml" href="/icon.svg" />
        <title>My App</title>
        <meta name="description" content="My App is a..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <head>
        <link rel="icon" type="image/svg+xml" href="/icon.svg" />

        <meta name="description" content="My App is a..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

5. Bất kỳ [metadata files](/docs/app/getting-started/metadata-and-og-images#file-based-metadata) nào như `favicon.ico`, `icon.png`, `robots.txt` đều được tự động thêm vào thẻ `<head>` của ứng dụng miễn là bạn đặt chúng vào cấp cao nhất của thư mục `app`. Sau khi di chuyển [tất cả các file được hỗ trợ](/docs/app/getting-started/metadata-and-og-images#file-based-metadata) vào thư mục `app`, bạn có thể xóa các thẻ `<link>` của chúng một cách an toàn:

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,

  return (

      <head>
        <title>My App</title>
        <meta name="description" content="My App is a..." />
      </head>
      <body>
        <div id="root">{children}</div>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {

    <html lang="en">

        <title>My App</title>

      </body>

```

6. Cuối cùng, Next.js có thể quản lý các thẻ `<head>` cuối cùng của bạn với [Metadata API](/docs/app/getting-started/metadata-and-og-images). Di chuyển thông tin metadata cuối cùng của bạn vào một [`metadata` object](/docs/app/api-reference/functions/generate-metadata#metadata-object) được export:

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'My App',
  description: 'My App is a...',

  children,

      <body>

      </body>

```

```jsx filename="app/layout.js" switcher

  description: 'My App is a...',
}

  return (
    <html lang="en">
      <body>
        <div id="root">{children}</div>
      </body>
    </html>

```

Với những thay đổi trên, bạn đã chuyển từ việc khai báo mọi thứ trong `index.html` sang sử dụng cách tiếp cận dựa trên quy ước của Next.js được tích hợp vào framework ([Metadata API](/docs/app/getting-started/metadata-and-og-images)). Cách tiếp cận này cho phép bạn dễ dàng cải thiện SEO và khả năng chia sẻ web của các trang của mình.

### Bước 5: Tạo Entrypoint Page

Trên Next.js, bạn khai báo một điểm vào cho ứng dụng của mình bằng cách tạo một file `page.tsx`. Tương đương gần nhất của file này trên Vite là file `main.tsx` của bạn. Trong bước này, bạn sẽ thiết lập điểm vào của ứng dụng của mình.

1. **Tạo một thư mục `[[...slug]]` trong thư mục `app` của bạn.**

Vì trong hướng dẫn này, chúng tôi nhắm mục tiêu đầu tiên là thiết lập Next.js của chúng tôi như một SPA (Single Page Application), bạn cần điểm vào trang của mình để bắt tất cả các routes có thể có của ứng dụng của bạn. Để làm điều đó, hãy tạo một thư mục `[[...slug]]` mới trong thư mục `app` của bạn.

Thư mục này là cái được gọi là [optional catch-all route segment](/docs/app/api-reference/file-conventions/dynamic-routes#optional-catch-all-segments). Next.js sử dụng một router dựa trên hệ thống file nơi các thư mục được sử dụng để xác định routes. Thư mục đặc biệt này sẽ đảm bảo rằng tất cả các routes của ứng dụng của bạn sẽ được chuyển hướng đến file `page.tsx` chứa nó.

2. **Tạo một file `page.tsx` mới bên trong thư mục `app/[[...slug]]` với nội dung sau:**

```tsx filename="app/[[...slug]]/page.tsx" switcher
import '../../index.css'

export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return '...' // We'll update this
}
```

```jsx filename="app/[[...slug]]/page.js" switcher
import '../../index.css'

export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return '...' // We'll update this
}
```

> **Lưu ý**: Các phần mở rộng `.js`, `.jsx`, hoặc `.tsx` có thể được sử dụng cho các file Page.

File này là một [Server Component](/docs/app/getting-started/server-and-client-components). Khi bạn chạy `next build`, file được prerendered thành một tài sản tĩnh. Nó _không_ yêu cầu bất kỳ mã động nào.

File này import global CSS của chúng tôi và bảo [`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params) chúng tôi chỉ định tạo một route, route index tại `/`.

Bây giờ, hãy di chuyển phần còn lại của ứng dụng Vite của chúng tôi sẽ chạy client-only.

```tsx filename="app/[[...slug]]/client.tsx" switcher
'use client'

import React from 'react'
import dynamic from 'next/dynamic'

const App = dynamic(() => import('../../App'), { ssr: false })

export function ClientOnly() {
  return <App />
}
```

```jsx filename="app/[[...slug]]/client.js" switcher
'use client'

import React from 'react'
import dynamic from 'next/dynamic'

const App = dynamic(() => import('../../App'), { ssr: false })

export function ClientOnly() {
  return <App />
}
```

File này là một [Client Component](/docs/app/getting-started/server-and-client-components), được xác định bởi directive `'use client'`. Client Components vẫn được [prerendered thành HTML](/docs/app/getting-started/server-and-client-components#how-do-server-and-client-components-work-in-nextjs) trên server trước khi được gửi đến client.

Vì chúng ta muốn một ứng dụng client-only để bắt đầu, chúng ta có thể cấu hình Next.js để vô hiệu hóa prerendering từ component `App` trở xuống.

```tsx
const App = dynamic(() => import('../../App'), { ssr: false })
```

Bây giờ, cập nhật trang điểm vào của bạn để sử dụng component mới:

```tsx filename="app/[[...slug]]/page.tsx" switcher
import '../../index.css'
import { ClientOnly } from './client'

export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return <ClientOnly />
}
```

```jsx filename="app/[[...slug]]/page.js" switcher
import '../../index.css'
import { ClientOnly } from './client'

export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return <ClientOnly />
}
```

### Bước 6: Cập nhật Static Image Imports

Next.js xử lý static image imports hơi khác so với Vite. Với Vite, import một file hình ảnh sẽ trả về URL công khai của nó dưới dạng chuỗi:

```tsx filename="App.tsx"
import image from './img.png' // `image` will be '/assets/img.2d8efhg.png' in production

export default function App() {
  return <img src={image} />
}
```

Với Next.js, static image imports trả về một đối tượng. Đối tượng sau đó có thể được sử dụng trực tiếp với [`<Image>` component](/docs/app/api-reference/components/image) của Next.js, hoặc bạn có thể sử dụng thuộc tính `src` của đối tượng với thẻ `<img>` hiện có của bạn.

Component `<Image>` có thêm lợi ích của [automatic image optimization](/docs/app/api-reference/components/image). Component `<Image>` tự động đặt các thuộc tính `width` và `height` của `<img>` kết quả dựa trên kích thước của hình ảnh. Điều này ngăn chặn layout shifts khi hình ảnh tải. Tuy nhiên, điều này có thể gây ra sự cố nếu ứng dụng của bạn chứa hình ảnh chỉ có một trong các kích thước của chúng được tạo kiểu mà không có kích thước kia được tạo kiểu thành `auto`. Khi không được tạo kiểu thành `auto`, kích thước sẽ mặc định theo giá trị thuộc tính kích thước của `<img>`, điều này có thể khiến hình ảnh bị méo.

Giữ thẻ `<img>` sẽ giảm lượng thay đổi trong ứng dụng của bạn và ngăn chặn các vấn đề trên. Sau đó, bạn có thể tùy chọn di chuyển sang component `<Image>` để tận dụng việc tối ưu hóa hình ảnh bằng cách [cấu hình một loader](/docs/app/api-reference/components/image#loader), hoặc chuyển sang server Next.js mặc định có tối ưu hóa hình ảnh tự động.

1. **Chuyển đổi đường dẫn import tuyệt đối cho hình ảnh được import từ `/public` thành import tương đối:**

```tsx
// Before
import logo from '/logo.png'

// After
import logo from '../public/logo.png'
```

2. **Truyền thuộc tính `src` của hình ảnh thay vì toàn bộ đối tượng hình ảnh vào thẻ `<img>` của bạn:**

```tsx
// Before
<img src={logo} />

// After
<img src={logo.src} />
```

Ngoài ra, bạn có thể tham chiếu URL công khai cho tài sản hình ảnh dựa trên tên file. Ví dụ, `public/logo.png` sẽ phục vụ hình ảnh tại `/logo.png` cho ứng dụng của bạn, đây sẽ là giá trị `src`.

> **Cảnh báo:** Nếu bạn đang sử dụng TypeScript, bạn có thể gặp lỗi kiểu khi truy cập thuộc tính `src`. Bạn có thể bỏ qua chúng một cách an toàn ngay bây giờ. Chúng sẽ được sửa vào cuối hướng dẫn này.

### Bước 7: Di chuyển Biến môi trường

Next.js có hỗ trợ cho `.env` [biến môi trường](/docs/app/guides/environment-variables) tương tự như Vite. Sự khác biệt chính là tiền tố được sử dụng để hiển thị các biến môi trường ở phía client.

- Thay đổi tất cả các biến môi trường có tiền tố `VITE_` thành `NEXT_PUBLIC_`.

Vite hiển thị một vài biến môi trường tích hợp trên đối tượng `import.meta.env` đặc biệt không được Next.js hỗ trợ. Bạn cần cập nhật cách sử dụng của chúng như sau:

- `import.meta.env.MODE` ⇒ `process.env.NODE_ENV`
- `import.meta.env.PROD` ⇒ `process.env.NODE_ENV === 'production'`
- `import.meta.env.DEV` ⇒ `process.env.NODE_ENV !== 'production'`
- `import.meta.env.SSR` ⇒ `typeof window !== 'undefined'`

Next.js cũng không cung cấp biến môi trường `BASE_URL` tích hợp. Tuy nhiên, bạn vẫn có thể cấu hình một biến, nếu bạn cần:

1. **Thêm nội dung sau vào file `.env` của bạn:**

```bash filename=".env"
# ...
NEXT_PUBLIC_BASE_PATH="/some-base-path"
```

2. **Đặt [`basePath`](/docs/app/api-reference/config/next-config-js/basePath) thành `process.env.NEXT_PUBLIC_BASE_PATH` trong file `next.config.mjs` của bạn:**

```js filename="next.config.mjs"
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: 'export', // Outputs a Single-Page Application (SPA).
  distDir: './dist', // Changes the build output directory to `./dist/`.
  basePath: process.env.NEXT_PUBLIC_BASE_PATH, // Sets the base path to `/some-base-path`.
}

export default nextConfig
```

3. **Cập nhật việc sử dụng `import.meta.env.BASE_URL` thành `process.env.NEXT_PUBLIC_BASE_PATH`**

### Bước 8: Cập nhật Scripts trong `package.json`

Bây giờ bạn sẽ có thể chạy ứng dụng của mình để kiểm tra xem bạn có di chuyển thành công sang Next.js hay không. Nhưng trước đó, bạn cần cập nhật `scripts` trong `package.json` của mình với các lệnh liên quan đến Next.js, và thêm `.next` và `next-env.d.ts` vào `.gitignore` của bạn:

```json filename="package.json"
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start"
  }
}
```

```txt filename=".gitignore"
# ...
.next
next-env.d.ts
dist
```

Bây giờ hãy chạy `npm run dev`, và mở [`http://localhost:3000`](http://localhost:3000). Bạn sẽ thấy ứng dụng của mình hiện đang chạy trên Next.js.

> **Ví dụ:** Xem [pull request này](https://github.com/inngest/vite-to-nextjs/pull/1) để biết ví dụ hoạt động của một ứng dụng Vite được di chuyển sang Next.js.

### Bước 9: Dọn dẹp

Bây giờ bạn có thể dọn dẹp codebase của mình khỏi các tạo phẩm liên quan đến Vite:

- Xóa `main.tsx`
- Xóa `index.html`
- Xóa `vite-env.d.ts`
- Xóa `tsconfig.node.json`
- Xóa `vite.config.ts`
- Gỡ cài đặt các dependencies của Vite
