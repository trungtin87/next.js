Next.js hỗ trợ đầy đủ việc xây dựng Ứng dụng trang đơn (SPA).

Điều này bao gồm chuyển đổi tuyến đường nhanh chóng với tìm nạp trước, tìm nạp dữ liệu phía máy khách, sử dụng API trình duyệt, tích hợp với các thư viện máy khách của bên thứ ba, tạo các tuyến đường tĩnh, v.v.

Nếu bạn có một SPA hiện có, bạn có thể di chuyển sang Next.js mà không có thay đổi lớn đối với mã của mình. Next.js sau đó cho phép bạn dần dần thêm các tính năng máy chủ khi cần thiết.

## Ứng dụng trang đơn là gì?

Định nghĩa về SPA rất đa dạng. Chúng tôi sẽ định nghĩa một “SPA nghiêm ngặt” là:

- **Kết xuất phía máy khách (CSR)**: Ứng dụng được phục vụ bởi một tệp HTML (ví dụ: `index.html`). Mọi tuyến đường, chuyển đổi trang và tìm nạp dữ liệu đều được xử lý bằng JavaScript trong trình duyệt.
- **Không tải lại toàn bộ trang**: Thay vì yêu cầu một tài liệu mới cho mỗi tuyến đường, JavaScript phía máy khách sẽ thao tác với DOM của trang hiện tại và tìm nạp dữ liệu khi cần.

Các SPA nghiêm ngặt thường yêu cầu một lượng lớn JavaScript để tải trước khi trang có thể tương tác. Hơn nữa, các thác nước dữ liệu máy khách có thể là một thách thức để quản lý. Xây dựng SPA với Next.js có thể giải quyết những vấn đề này.

## Tại sao sử dụng Next.js cho SPA?

Next.js có thể tự động chia mã các gói JavaScript của bạn và tạo nhiều điểm vào HTML cho các tuyến đường khác nhau. Điều này tránh tải mã JavaScript không cần thiết ở phía máy khách, giảm kích thước gói và cho phép tải trang nhanh hơn.

Thành phần [`next/link`](/docs/app/api-reference/components/link) tự động [tìm nạp trước](/docs/app/api-reference/components/link#prefetch) các tuyến đường, giúp bạn chuyển trang nhanh như một SPA nghiêm ngặt, nhưng với lợi thế là duy trì trạng thái định tuyến ứng dụng vào URL để liên kết và chia sẻ.

Next.js có thể bắt đầu như một trang web tĩnh hoặc thậm chí là một SPA nghiêm ngặt trong đó mọi thứ đều được kết xuất phía máy khách. Nếu dự án của bạn phát triển, Next.js cho phép bạn dần dần thêm nhiều tính năng máy chủ hơn (ví dụ: [Thành phần máy chủ React](/docs/app/getting-started/server-and-client-components), [Hành động máy chủ](/docs/app/getting-started/updating-data), v.v.) khi cần thiết.

## Ví dụ

Hãy khám phá các mẫu phổ biến được sử dụng để xây dựng SPA và cách Next.js giải quyết chúng.

### Sử dụng `use` của React trong một Nhà cung cấp ngữ cảnh

Chúng tôi khuyên bạn nên tìm nạp dữ liệu trong một thành phần mẹ (hoặc bố cục), trả về Promise, sau đó giải nén giá trị trong một Thành phần máy khách bằng hook [`use` của React](https://react.dev/reference/react/use).

Next.js có thể bắt đầu tìm nạp dữ liệu sớm trên máy chủ. Trong ví dụ này, đó là bố cục gốc — điểm vào ứng dụng của bạn. Máy chủ có thể ngay lập tức bắt đầu truyền phản hồi đến máy khách.

Bằng cách “nâng” việc tìm nạp dữ liệu của bạn lên bố cục gốc, Next.js bắt đầu các yêu cầu được chỉ định trên máy chủ sớm trước bất kỳ thành phần nào khác trong ứng dụng của bạn. Điều này giúp loại bỏ các thác nước máy khách và ngăn chặn việc có nhiều chuyến đi khứ hồi giữa máy khách và máy chủ. Nó cũng có thể cải thiện đáng kể hiệu suất, vì máy chủ của bạn gần hơn (và lý tưởng nhất là được đặt cùng vị trí) với nơi đặt cơ sở dữ liệu của bạn.

Ví dụ, cập nhật bố cục gốc của bạn để gọi Promise, nhưng _không_ await nó.

```tsx filename="app/layout.tsx" switcher
import { UserProvider } from './user-provider'
import { getUser } from './user' // một số hàm phía máy chủ

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  let userPromise = getUser() // KHÔNG await

  return (
    <html lang="en">
      <body>
        <UserProvider userPromise={userPromise}>{children}</UserProvider>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
import { UserProvider } from './user-provider'
import { getUser } from './user' // một số hàm phía máy chủ

export default function RootLayout({ children }) {
  let userPromise = getUser() // KHÔNG await

  return (
    <html lang="en">
      <body>
        <UserProvider userPromise={userPromise}>{children}</UserProvider>
      </body>
    </html>
  )
}
```

Mặc dù bạn có thể [hoãn và chuyển một Promise duy nhất](/docs/app/getting-started/fetching-data#streaming-data-with-the-use-hook) làm prop cho một Thành phần máy khách, chúng tôi thường thấy mẫu này được kết hợp với một nhà cung cấp ngữ cảnh React. Điều này cho phép truy cập dễ dàng hơn từ các Thành phần máy khách với một Hook React tùy chỉnh.

Bạn có thể chuyển tiếp một Promise đến nhà cung cấp ngữ cảnh React:

```ts filename="app/user-provider.ts" switcher
'use client';

import { createContext, useContext, ReactNode } from 'react';

type User = any;
type UserContextType = {
  userPromise: Promise<User | null>;
};

const UserContext = createContext<UserContextType | null>(null);

export function useUser(): UserContextType {
  let context = useContext(UserContext);
  if (context === null) {
    throw new Error('useUser phải được sử dụng trong một UserProvider');
  }
  return context;
}

export function UserProvider({
  children,
  userPromise
}: {
  children: ReactNode;
  userPromise: Promise<User | null>;
}) {
  return (
    <UserContext.Provider value={{ userPromise }}>
      {children}
    </UserContext.Provider>
  );
}
```

```js filename="app/user-provider.js" switcher
'use client'

import { createContext, useContext, ReactNode } from 'react'

const UserContext = createContext(null)

export function useUser() {
  let context = useContext(UserContext)
  if (context === null) {
    throw new Error('useUser phải được sử dụng trong một UserProvider')
  }
  return context
}

export function UserProvider({ children, userPromise }) {
  return (
    <UserContext.Provider value={{ userPromise }}>
      {children}
    </UserContext.Provider>
  )
}
```

Cuối cùng, bạn có thể gọi hook tùy chỉnh `useUser()` trong bất kỳ Thành phần máy khách nào và giải nén Promise:

```tsx filename="app/profile.tsx" switcher
'use client'

import { use } from 'react'
import { useUser } from './user-provider'

export function Profile() {
  const { userPromise } = useUser()
  const user = use(userPromise)

  return '...'
}
```

```jsx filename="app/profile.js" switcher
'use client'

import { use } from 'react'
import { useUser } from './user-provider'

export function Profile() {
  const { userPromise } = useUser()
  const user = use(userPromise)

  return '...'
}
```

Thành phần sử dụng Promise (ví dụ: `Profile` ở trên) sẽ bị tạm ngưng. Điều này cho phép hydrat hóa một phần. Bạn có thể thấy HTML được truyền trực tuyến và được kết xuất trước trước khi JavaScript tải xong.

### SPA với SWR

[SWR](https://swr.vercel.app) là một thư viện React phổ biến để tìm nạp dữ liệu.

Với SWR 2.3.0 (và React 19+), bạn có thể dần dần áp dụng các tính năng máy chủ cùng với mã tìm nạp dữ liệu máy khách dựa trên SWR hiện có của mình. Đây là một sự trừu tượng hóa của mẫu `use()` ở trên. Điều này có nghĩa là bạn có thể di chuyển việc tìm nạp dữ liệu giữa phía máy khách và máy chủ, hoặc sử dụng cả hai:

- **Chỉ máy khách:** `useSWR(key, fetcher)`
- **Chỉ máy chủ:** `useSWR(key)` + dữ liệu do RSC cung cấp
- **Hỗn hợp:** `useSWR(key, fetcher)` + dữ liệu do RSC cung cấp

Ví dụ, bọc ứng dụng của bạn bằng `<SWRConfig>` và một `fallback`:

```tsx filename="app/layout.tsx" switcher
import { SWRConfig } from 'swr'
import { getUser } from './user' // một số hàm phía máy chủ

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <SWRConfig
      value={{
        fallback: {
          // Chúng tôi KHÔNG await getUser() ở đây
          // Chỉ các thành phần đọc dữ liệu này mới bị tạm ngưng
          '/api/user': getUser(),
        },
      }}
    >
      {children}
    </SWRConfig>
  )
}
```

```js filename="app/layout.js" switcher
import { SWRConfig } from 'swr'
import { getUser } from './user' // một số hàm phía máy chủ

export default function RootLayout({ children }) {
  return (
    <SWRConfig
      value={{
        fallback: {
          // Chúng tôi KHÔNG await getUser() ở đây
          // Chỉ các thành phần đọc dữ liệu này mới bị tạm ngưng
          '/api/user': getUser(),
        },
      }}
    >
      {children}
    </SWRConfig>
  )
}
```

Vì đây là một Thành phần máy chủ, `getUser()` có thể đọc cookie, tiêu đề hoặc nói chuyện với cơ sở dữ liệu của bạn một cách an toàn. Không cần tuyến API riêng biệt. Các thành phần máy khách bên dưới `<SWRConfig>` có thể gọi `useSWR()` với cùng một khóa để truy xuất dữ liệu người dùng. Mã thành phần với `useSWR` **không yêu cầu bất kỳ thay đổi nào** so với giải pháp tìm nạp máy khách hiện có của bạn.

```tsx filename="app/profile.tsx" switcher
'use client'

import useSWR from 'swr'

export function Profile() {
  const fetcher = (url) => fetch(url).then((res) => res.json())
  // Cùng một mẫu SWR mà bạn đã biết
  const { data, error } = useSWR('/api/user', fetcher)

  return '...'
}
```

```jsx filename="app/profile.js" switcher
'use client'

import useSWR from 'swr'

export function Profile() {
  const fetcher = (url) => fetch(url).then((res) => res.json())
  // Cùng một mẫu SWR mà bạn đã biết
  const { data, error } = useSWR('/api/user', fetcher)

  return '...'
}
```

Dữ liệu `fallback` có thể được kết xuất trước và được bao gồm trong phản hồi HTML ban đầu, sau đó được đọc ngay lập tức trong các thành phần con bằng cách sử dụng `useSWR`. Việc thăm dò, xác thực lại và lưu vào bộ nhớ đệm của SWR vẫn chỉ chạy **phía máy khách**, vì vậy nó bảo toàn tất cả khả năng tương tác mà bạn dựa vào cho một SPA.

Vì dữ liệu `fallback` ban đầu được Next.js tự động xử lý, giờ đây bạn có thể xóa mọi logic có điều kiện cần thiết trước đây để kiểm tra xem `data` có phải là `undefined` hay không. Khi dữ liệu đang tải, ranh giới `<Suspense>` gần nhất sẽ bị tạm ngưng.

|                              | SWR                 | RSC                 | RSC + SWR           |
| ---------------------------- | ------------------- | ------------------- | ------------------- |
| Dữ liệu SSR                  | <Cross size={18} /> | <Check size={18} /> | <Check size={18} /> |
| Truyền phát trong khi SSR    | <Cross size={18} /> | <Check size={18} /> | <Check size={18} /> |
| Sao chép yêu cầu             | <Check size={18} /> | <Check size={18} /> | <Check size={18} /> |
| Các tính năng phía máy khách | <Check size={18} /> | <Cross size={18} /> | <Check size={18} /> |

### SPA với React Query

Bạn có thể sử dụng React Query với Next.js trên cả máy khách và máy chủ. Điều này cho phép bạn xây dựng cả các SPA nghiêm ngặt, cũng như tận dụng các tính năng máy chủ trong Next.js được kết hợp với React Query.

Tìm hiểu thêm trong [tài liệu React Query](https://tanstack.com/query/latest/docs/framework/react/guides/advanced-ssr).

### Chỉ kết xuất các thành phần trong trình duyệt

Các thành phần máy khách được [kết xuất trước](https://github.com/reactwg/server-components/discussions/4) trong `next build`. Nếu bạn muốn tắt kết xuất trước cho một Thành phần máy khách và chỉ tải nó trong môi trường trình duyệt, bạn có thể sử dụng [`next/dynamic`](/docs/app/guides/lazy-loading#nextdynamic):

```jsx
import dynamic from 'next/dynamic'

const ClientOnlyComponent = dynamic(() => import('./component'), {
  ssr: false,
})
```

Điều này có thể hữu ích cho các thư viện của bên thứ ba dựa vào các API trình duyệt như `window` hoặc `document`. Bạn cũng có thể thêm một `useEffect` kiểm tra sự tồn tại của các API này, và nếu chúng không tồn tại, trả về `null` hoặc một trạng thái tải sẽ được kết xuất trước.

### Định tuyến nông trên máy khách

Nếu bạn đang di chuyển từ một SPA nghiêm ngặt như [Create React App](/docs/app/guides/migrating/from-create-react-app) hoặc [Vite](/docs/app/guides/migrating/from-vite), bạn có thể có mã hiện có định tuyến nông để cập nhật trạng thái URL. Điều này có thể hữu ích cho các chuyển đổi thủ công giữa các chế độ xem trong ứng dụng của bạn _mà không_ sử dụng định tuyến hệ thống tệp mặc định của Next.js.

Next.js cho phép bạn sử dụng các phương thức [`window.history.pushState`](https://developer.mozilla.org/en-US/docs/Web/API/History/pushState) và [`window.history.replaceState`](https://developer.mozilla.org/en-US/docs/Web/API/History/replaceState) gốc để cập nhật ngăn xếp lịch sử của trình duyệt mà không cần tải lại trang.

Các lệnh gọi `pushState` và `replaceState` tích hợp vào Bộ định tuyến Next.js, cho phép bạn đồng bộ hóa với [`usePathname`](/docs/app/api-reference/functions/use-pathname) và [`useSearchParams`](/docs/app/api-reference/functions/use-search-params).

```tsx fileName="app/ui/sort-products.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SortProducts() {
  const searchParams = useSearchParams()

  function updateSorting(sortOrder: string) {
    const urlSearchParams = new URLSearchParams(searchParams.toString())
    urlSearchParams.set('sort', sortOrder)
    window.history.pushState(null, '', `?${urlSearchParams.toString()}`)
  }

  return (
    <>
      <button onClick={() => updateSorting('asc')}>Sắp xếp tăng dần</button>
      <button onClick={() => updateSorting('desc')}>Sắp xếp giảm dần</button>
    </>
  )
}
```

### Sử dụng Hành động máy chủ trong các thành phần máy khách

Bạn có thể dần dần áp dụng các Hành động máy chủ trong khi vẫn sử dụng các Thành phần máy khách. Điều này cho phép bạn xóa mã soạn sẵn để gọi một tuyến API, và thay vào đó sử dụng các tính năng của React như `useActionState` để xử lý các trạng thái tải và lỗi.

Ví dụ, tạo Hành động máy chủ đầu tiên của bạn:

```tsx filename="app/actions.ts" switcher
'use server'

export async function create() {}
```

```js filename="app/actions.js" switcher
'use server'

export async function create() {}
```

Bạn có thể nhập và sử dụng một Hành động máy chủ từ máy khách, tương tự như gọi một hàm JavaScript. Bạn không cần phải tạo một điểm cuối API theo cách thủ công:

```tsx filename="app/button.tsx" switcher
'use client'

import { create } from './actions'

export function Button() {
  return <button onClick={() => create()}>Tạo</button>
}
```

```jsx filename="app/button.js" switcher
'use client'

import { create } from './actions'

export function Button() {
  return <button onClick={() => create()}>Tạo</button>
}
```

## Xuất tĩnh (tùy chọn)

Next.js cũng hỗ trợ tạo một [trang web hoàn toàn tĩnh](/docs/app/guides/static-exports). Điều này có một số lợi thế so với các SPA nghiêm ngặt:

- **Tự động chia mã**: Thay vì vận chuyển một `index.html` duy nhất, Next.js sẽ tạo một tệp HTML cho mỗi tuyến đường, vì vậy khách truy cập của bạn sẽ nhận được nội dung nhanh hơn mà không cần phải đợi gói JavaScript của máy khách.
- **Cải thiện trải nghiệm người dùng:** Thay vì một bộ khung tối thiểu cho tất cả các tuyến đường, bạn sẽ có các trang được kết xuất đầy đủ cho mỗi tuyến đường. Khi người dùng điều hướng phía máy khách, các chuyển đổi vẫn tức thì và giống như SPA.

Để bật xuất tĩnh, hãy cập nhật cấu hình của bạn:

```ts filename="next.config.ts"
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  output: 'export',
}

export default nextConfig
```

Sau khi chạy `next build`, Next.js sẽ tạo một thư mục `out` với các tài sản HTML/CSS/JS cho ứng dụng của bạn.

> **Lưu ý:** Các tính năng máy chủ Next.js không được hỗ trợ với xuất tĩnh. [Tìm hiểu thêm](/docs/app/guides/static-exports#unsupported-features).
