Observability (Khả năng quan sát) là rất quan trọng để hiểu và tối ưu hóa hành vi và hiệu suất của ứng dụng Next.js của bạn.

Khi các ứng dụng trở nên phức tạp hơn, việc xác định và chẩn đoán các vấn đề có thể phát sinh ngày càng trở nên khó khăn. Bằng cách tận dụng các công cụ observability, chẳng hạn như logging và metrics, các nhà phát triển có thể có được cái nhìn sâu sắc về hành vi của ứng dụng và xác định các khu vực cần tối ưu hóa. Với observability, các nhà phát triển có thể chủ động giải quyết các vấn đề trước khi chúng trở thành vấn đề lớn và cung cấp trải nghiệm người dùng tốt hơn. Do đó, rất khuyến khích sử dụng observability trong các ứng dụng Next.js của bạn để cải thiện hiệu suất, tối ưu hóa tài nguyên và nâng cao trải nghiệm người dùng.

Chúng tôi khuyên bạn nên sử dụng OpenTelemetry để instrument (gắn công cụ đo lường) cho các ứng dụng của mình.
Đó là một cách không phụ thuộc vào nền tảng để instrument các ứng dụng, cho phép bạn thay đổi nhà cung cấp observability của mình mà không cần thay đổi mã.
Đọc [Tài liệu OpenTelemetry chính thức](https://opentelemetry.io/docs/) để biết thêm thông tin về OpenTelemetry và cách nó hoạt động.

Tài liệu này sử dụng các thuật ngữ như _Span_, _Trace_ hoặc _Exporter_ xuyên suốt tài liệu này, tất cả đều có thể được tìm thấy trong [OpenTelemetry Observability Primer](https://opentelemetry.io/docs/concepts/observability-primer/).

Next.js hỗ trợ OpenTelemetry instrumentation ngay lập tức, có nghĩa là chúng tôi đã instrument Next.js.

<PagesOnly>
  Khi bạn bật OpenTelemetry, chúng tôi sẽ tự động bọc tất cả mã của bạn như
  `getStaticProps` trong các _spans_ với các thuộc tính hữu ích.
</PagesOnly>

## Bắt đầu

OpenTelemetry có thể mở rộng nhưng việc thiết lập nó đúng cách có thể khá dài dòng.
Đó là lý do tại sao chúng tôi đã chuẩn bị gói `@vercel/otel` giúp bạn bắt đầu nhanh chóng.

### Sử dụng `@vercel/otel`

Để bắt đầu, hãy cài đặt các gói sau:

```bash filename="Terminal"
npm install @vercel/otel @opentelemetry/sdk-logs @opentelemetry/api-logs @opentelemetry/instrumentation
```

### Cấu hình OpenTelemetry thủ công

Gói `@vercel/otel` cung cấp nhiều tùy chọn cấu hình và sẽ phục vụ hầu hết các trường hợp sử dụng phổ biến. Nhưng nếu nó không phù hợp với nhu cầu của bạn, bạn có thể cấu hình OpenTelemetry thủ công.

Đầu tiên bạn cần cài đặt các gói OpenTelemetry:

```bash filename="Terminal"
npm install @opentelemetry/sdk-node @opentelemetry/resources @opentelemetry/semantic-conventions @opentelemetry/sdk-trace-node @opentelemetry/exporter-trace-otlp-http
```

Bây giờ bạn có thể khởi tạo `NodeSDK` trong `instrumentation.ts` của mình.
Không giống như `@vercel/otel`, `NodeSDK` không tương thích với edge runtime, vì vậy bạn cần đảm bảo rằng bạn chỉ import chúng khi `process.env.NEXT_RUNTIME === 'nodejs'`. Chúng tôi khuyên bạn nên tạo một tệp mới `instrumentation.node.ts` mà bạn import có điều kiện chỉ khi sử dụng node:

```ts filename="instrumentation.ts" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation.node.ts')
  }
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation.node.js')
  }
}
```

```ts filename="instrumentation.node.ts" switcher
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http'
import { resourceFromAttributes } from '@opentelemetry/resources'
import { NodeSDK } from '@opentelemetry/sdk-node'
import { SimpleSpanProcessor } from '@opentelemetry/sdk-trace-node'
import { ATTR_SERVICE_NAME } from '@opentelemetry/semantic-conventions'

const sdk = new NodeSDK({
  resource: resourceFromAttributes({
    [ATTR_SERVICE_NAME]: 'next-app',
  }),
  spanProcessor: new SimpleSpanProcessor(new OTLPTraceExporter()),
})
sdk.start()
```

```js filename="instrumentation.node.js" switcher
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http'
import { resourceFromAttributes } from '@opentelemetry/resources'
import { NodeSDK } from '@opentelemetry/sdk-node'
import { SimpleSpanProcessor } from '@opentelemetry/sdk-trace-node'
import { ATTR_SERVICE_NAME } from '@opentelemetry/semantic-conventions'

const sdk = new NodeSDK({
  resource: resourceFromAttributes({
    [ATTR_SERVICE_NAME]: 'next-app',
  }),
  spanProcessor: new SimpleSpanProcessor(new OTLPTraceExporter()),
})
sdk.start()
```

Làm điều này tương đương với việc sử dụng `@vercel/otel`, nhưng có thể sửa đổi và mở rộng một số tính năng không được `@vercel/otel` để lộ. Nếu hỗ trợ edge runtime là cần thiết, bạn sẽ phải sử dụng `@vercel/otel`.

## Kiểm tra instrumentation của bạn

Bạn cần một OpenTelemetry collector với backend tương thích để kiểm tra OpenTelemetry traces cục bộ.
Chúng tôi khuyên bạn nên sử dụng [môi trường phát triển OpenTelemetry](https://github.com/vercel/opentelemetry-collector-dev-setup) của chúng tôi.

Nếu mọi thứ hoạt động tốt, bạn sẽ có thể thấy root server span được gắn nhãn là `GET /requested/pathname`.
Tất cả các spans khác từ trace cụ thể đó sẽ được lồng dưới nó.

Next.js traces nhiều spans hơn mức được phát ra theo mặc định.
Để xem thêm spans, bạn phải đặt `NEXT_OTEL_VERBOSE=1`.

## Triển khai (Deployment)

### Sử dụng OpenTelemetry Collector

Khi bạn đang deploy với OpenTelemetry Collector, bạn có thể sử dụng `@vercel/otel`.
Nó sẽ hoạt động cả trên Vercel và khi self-hosted (tự host).

#### Deploy trên Vercel

Chúng tôi đảm bảo rằng OpenTelemetry hoạt động ngay lập tức trên Vercel.

Làm theo [tài liệu Vercel](https://vercel.com/docs/concepts/observability/otel-overview/quickstart) để kết nối dự án của bạn với nhà cung cấp observability.

#### Self-hosting

Deploy lên các nền tảng khác cũng rất đơn giản. Bạn sẽ cần khởi động OpenTelemetry Collector của riêng mình để nhận và xử lý dữ liệu telemetry từ ứng dụng Next.js của bạn.

Để làm điều này, hãy làm theo [Hướng dẫn Bắt đầu OpenTelemetry Collector](https://opentelemetry.io/docs/collector/getting-started/), hướng dẫn này sẽ hướng dẫn bạn thiết lập collector và cấu hình nó để nhận dữ liệu từ ứng dụng Next.js của bạn.

Khi bạn đã có collector hoạt động, bạn có thể deploy ứng dụng Next.js của mình lên nền tảng đã chọn theo hướng dẫn deploy tương ứng của họ.

### Custom Exporters

OpenTelemetry Collector là không cần thiết. Bạn có thể sử dụng một OpenTelemetry exporter tùy chỉnh với [`@vercel/otel`](#using-vercelotel) hoặc [cấu hình OpenTelemetry thủ công](#manual-opentelemetry-configuration).

## Custom Spans

Bạn có thể thêm một custom span với [OpenTelemetry APIs](https://opentelemetry.io/docs/instrumentation/js/instrumentation).

```bash filename="Terminal"
npm install @opentelemetry/api
```

Ví dụ sau minh họa một hàm fetch GitHub stars và thêm một custom span `fetchGithubStars` để theo dõi kết quả của fetch request:

```ts
import { trace } from '@opentelemetry/api'

export async function fetchGithubStars() {
  return await trace
    .getTracer('nextjs-example')
    .startActiveSpan('fetchGithubStars', async (span) => {
      try {
        return await getValue()
      } finally {
        span.end()
      }
    })
}
```

Hàm `register` sẽ thực thi trước khi mã của bạn chạy trong một môi trường mới.
Bạn có thể bắt đầu tạo các spans mới, và chúng sẽ được thêm chính xác vào trace đã export.

## Default Spans trong Next.js

Next.js tự động instruments một số spans cho bạn để cung cấp thông tin chi tiết hữu ích về hiệu suất ứng dụng của bạn.

Các thuộc tính trên spans tuân theo [OpenTelemetry semantic conventions](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/). Chúng tôi cũng thêm một số thuộc tính tùy chỉnh dưới namespace `next`:

- `next.span_name` - sao chép tên span
- `next.span_type` - mỗi loại span có một định danh duy nhất
- `next.route` - Mẫu route của request (v.d., `/[param]/user`).
- `next.rsc` (true/false) - Liệu request có phải là RSC request hay không, chẳng hạn như prefetch.
- `next.page`
  - Đây là một giá trị nội bộ được sử dụng bởi app router.
  - Bạn có thể nghĩ về nó như một route đến một tệp đặc biệt (như `page.ts`, `layout.ts`, `loading.ts` và các tệp khác)
  - Nó chỉ có thể được sử dụng như một định danh duy nhất khi được ghép nối với `next.route` vì `/layout` có thể được sử dụng để xác định cả `/(groupA)/layout.ts` và `/(groupB)/layout.ts`

### `[http.method] [next.route]`

- `next.span_type`: `BaseServer.handleRequest`

Span này đại diện cho root span cho mỗi request đến ứng dụng Next.js của bạn. Nó theo dõi phương thức HTTP, route, target, và mã trạng thái của request.

Thuộc tính:

- [Các thuộc tính HTTP chung](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/http/#common-attributes)
  - `http.method`
  - `http.status_code`
- [Các thuộc tính HTTP Server](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/http/#http-server-semantic-conventions)
  - `http.route`
  - `http.target`
- `next.span_name`
- `next.span_type`
- `next.route`

### `render route (app) [next.route]`

- `next.span_type`: `AppRender.getBodyResult`.

Span này đại diện cho quá trình render một route trong app router.

Thuộc tính:

- `next.span_name`
- `next.span_type`
- `next.route`

### `fetch [http.method] [http.url]`

- `next.span_type`: `AppRender.fetch`

Span này đại diện cho fetch request được thực thi trong mã của bạn.

Thuộc tính:

- [Các thuộc tính HTTP chung](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/http/#common-attributes)
  - `http.method`
- [Các thuộc tính HTTP Client](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/http/#http-client)
  - `http.url`
  - `net.peer.name`
  - `net.peer.port` (chỉ khi được chỉ định)
- `next.span_name`
- `next.span_type`

Span này có thể được tắt bằng cách đặt `NEXT_OTEL_FETCH_DISABLED=1` trong môi trường của bạn. Điều này hữu ích khi bạn muốn sử dụng thư viện fetch instrumentation tùy chỉnh.

### `executing api route (app) [next.route]`

- `next.span_type`: `AppRouteRouteHandlers.runHandler`.

Span này đại diện cho việc thực thi API Route Handler trong app router.

Thuộc tính:

- `next.span_name`
- `next.span_type`
- `next.route`

### `getServerSideProps [next.route]`

- `next.span_type`: `Render.getServerSideProps`.

Span này đại diện cho việc thực thi `getServerSideProps` cho một route cụ thể.

Thuộc tính:

- `next.span_name`
- `next.span_type`
- `next.route`

### `getStaticProps [next.route]`

- `next.span_type`: `Render.getStaticProps`.

Span này đại diện cho việc thực thi `getStaticProps` cho một route cụ thể.

Thuộc tính:

- `next.span_name`
- `next.span_type`
- `next.route`

### `render route (pages) [next.route]`

- `next.span_type`: `Render.renderDocument`.

Span này đại diện cho quá trình render tài liệu cho một route cụ thể.

Thuộc tính:

- `next.span_name`
- `next.span_type`
- `next.route`

### `generateMetadata [next.page]`

- `next.span_type`: `ResolveMetadata.generateMetadata`.

Span này đại diện cho quá trình tạo metadata cho một trang cụ thể (một route đơn lẻ có thể có nhiều span này).

Thuộc tính:

- `next.span_name`
- `next.span_type`
- `next.page`

### `resolve page components`

- `next.span_type`: `NextNodeServer.findPageComponents`.

Span này đại diện cho quá trình phân giải các component trang cho một trang cụ thể.

Thuộc tính:

- `next.span_name`
- `next.span_type`
- `next.route`

### `resolve segment modules`

- `next.span_type`: `NextNodeServer.getLayoutOrPageModule`.

Span này đại diện cho việc tải các module mã cho một layout hoặc một trang.

Thuộc tính:

- `next.span_name`
- `next.span_type`
- `next.segment`

### `start response`

- `next.span_type`: `NextNodeServer.startResponse`.

Span có độ dài bằng không này đại diện cho thời điểm byte đầu tiên đã được gửi trong phản hồi.
