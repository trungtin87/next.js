Next.js hỗ trợ mẫu "Backend cho Frontend". Điều này cho phép bạn tạo các public endpoints để xử lý các yêu cầu HTTP và trả về bất kỳ loại nội dung nào—không chỉ HTML. Bạn cũng có thể truy cập các nguồn dữ liệu và thực hiện các tác dụng phụ như cập nhật dữ liệu từ xa.

Nếu bạn đang bắt đầu một dự án mới, việc sử dụng `create-next-app` với cờ `--api` sẽ tự động bao gồm một ví dụ `route.ts` trong thư mục `app/` của dự án mới của bạn, minh họa cách tạo một API endpoint.

```bash filename="Terminal"
npx create-next-app@latest --api
```

> **Thông tin hữu ích**: Các khả năng backend của Next.js không phải là sự thay thế backend hoàn toàn. Chúng đóng vai trò như một lớp API mà:
>
> - có thể truy cập công khai
> - xử lý bất kỳ yêu cầu HTTP nào
> - có thể trả về bất kỳ loại nội dung nào

Để triển khai mẫu này, hãy sử dụng:

- [Route Handlers](/docs/app/api-reference/file-conventions/route)
- [`proxy`](/docs/app/api-reference/file-conventions/proxy)
- Trong Pages Router, [API Routes](/docs/pages/building-your-application/routing/api-routes)

## Public Endpoints

Route Handlers là các public HTTP endpoints. Bất kỳ client nào cũng có thể truy cập chúng.

Tạo một Route Handler bằng cách sử dụng quy ước file `route.ts` hoặc `route.js`:

```ts filename="/app/api/route.ts" switcher
export function GET(request: Request) {}
```

```js filename="/app/api/route.js" switcher
export function GET(request) {}
```

Điều này xử lý các yêu cầu `GET` được gửi đến `/api`.

Sử dụng các khối `try/catch` cho các hoạt động có thể ném ra một ngoại lệ:

```ts filename="/app/api/route.ts" switcher
import { submit } from '@/lib/submit'

export async function POST(request: Request) {
  try {
    await submit(request)
    return new Response(null, { status: 204 })
  } catch (reason) {
    const message =
      reason instanceof Error ? reason.message : 'Unexpected error'

    return new Response(message, { status: 500 })
  }
}
```

```js filename="/app/api/route.js" switcher
import { submit } from '@/lib/submit'

export async function POST(request) {
  try {
    await submit(request)
    return new Response(null, { status: 204 })

      reason instanceof Error ? reason.message : 'Unexpected error'

    return new Response(message, { status: 500 })
  }
}
```

Tránh để lộ thông tin nhạy cảm trong các thông báo lỗi được gửi đến client.

Để hạn chế quyền truy cập, hãy triển khai xác thực và ủy quyền. Xem [Xác thực](/docs/app/guides/authentication).

## Các loại nội dung

Route Handlers cho phép bạn phục vụ các phản hồi không phải UI, bao gồm JSON, XML, hình ảnh, tệp và văn bản thuần túy.

Next.js sử dụng các quy ước file cho các endpoints phổ biến:

- [`sitemap.xml`](/docs/app/api-reference/file-conventions/metadata/sitemap)
- [`opengraph-image.jpg`, `twitter-image`](/docs/app/api-reference/file-conventions/metadata/opengraph-image)
- [favicon, app icon, và apple-icon](/docs/app/api-reference/file-conventions/metadata/app-icons)
- [`manifest.json`](/docs/app/api-reference/file-conventions/metadata/manifest)
- [`robots.txt`](/docs/app/api-reference/file-conventions/metadata/robots)

Bạn cũng có thể xác định các loại tùy chỉnh, chẳng hạn như:

- `llms.txt`
- `rss.xml`
- `.well-known`

Ví dụ, `app/rss.xml/route.ts` tạo một Route Handler cho `rss.xml`.

```ts filename="/app/rss.xml/route.ts" switcher
export async function GET(request: Request) {
  const rssResponse = await fetch(/* rss endpoint */)
  const rssData = await rssResponse.json()

  const rssFeed = `<?xml version="1.0" encoding="UTF-8" ?>
<rss version="2.0">
<channel>
 <title>${rssData.title}</title>
 <description>${rssData.description}</description>
 <link>${rssData.link}</link>
 <copyright>${rssData.copyright}</copyright>
 ${rssData.items.map((item) => {
   return `<item>
    <title>${item.title}</title>
    <description>${item.description}</description>
    <link>${item.link}</link>
    <pubDate>${item.publishDate}</pubDate>
    <guid isPermaLink="false">${item.guid}</guid>
 </item>`
 })}
</channel>
</rss>`

  const headers = new Headers({ 'content-type': 'application/xml' })

  return new Response(rssFeed, { headers })
}
```

### Tiêu thụ request payloads

Sử dụng Request [instance methods](https://developer.mozilla.org/en-US/docs/Web/API/Request#instance_methods) như `.json()`, `.formData()`, hoặc `.text()` để truy cập request body.

Các yêu cầu `GET` và `HEAD` không mang theo body.

```ts filename="/app/api/echo-body/route.ts" switcher
export async function POST(request: Request) {
  const res = await request.json()
  return Response.json({ res })
}
```

```js filename="/app/api/echo-body/route.js" switcher
export async function POST(request) {
  const res = await request.json()
  return Response.json({ res })
}
```

> **Thông tin hữu ích**: Xác thực dữ liệu trước khi chuyển nó sang các hệ thống khác

```ts filename="/app/api/send-email/route.ts" switcher
import { sendMail, validateInputs } from '@/lib/email-transporter'

export async function POST(request: Request) {
  const formData = await request.formData()
  const email = formData.get('email')
  const contents = formData.get('contents')

  try {
    await validateInputs({ email, contents })
    const info = await sendMail({ email, contents })

    return Response.json({ messageId: info.messageId })
  } catch (reason) {
    const message =
      reason instanceof Error ? reason.message : 'Unexpected exception'

    return new Response(message, { status: 500 })
  }
}
```

## Thao tác dữ liệu

Route Handlers có thể chuyển đổi, lọc và tổng hợp dữ liệu từ một hoặc nhiều nguồn. Điều này giữ logic ra khỏi frontend và tránh để lộ các hệ thống nội bộ.

Bạn cũng có thể giảm tải các tính toán nặng cho server và giảm mức sử dụng pin và dữ liệu của client.

```ts file="/app/api/weather/route.ts" switcher
import { parseWeatherData } from '@/lib/weather'

export async function POST(request: Request) {
  const body = await request.json()
  const searchParams = new URLSearchParams({ lat: body.lat, lng: body.lng })

  try {
    const weatherResponse = await fetch(`${weatherEndpoint}?${searchParams}`)

    if (!weatherResponse.ok) {
      /* handle error */
    }

    const weatherData = await weatherResponse.text()
    const payload = parseWeatherData.asJSON(weatherData)

    return new Response(payload, { status: 200 })
  } catch (reason) {
    const message =
      reason instanceof Error ? reason.message : 'Unexpected exception'

    return new Response(message, { status: 500 })
  }
}
```

## Proxy đến một backend

Bạn có thể sử dụng một Route Handler như một `proxy` đến một backend khác. Thêm logic xác thực trước khi chuyển tiếp yêu cầu.

```ts filename="/app/api/[...slug]/route.ts" switcher
import { isValidRequest } from '@/lib/utils'

export async function POST(request: Request, { params }) {
  const clonedRequest = request.clone()
  const isValid = await isValidRequest(clonedRequest)

  if (!isValid) {
    return new Response(null, { status: 400, statusText: 'Bad Request' })
  }

  const { slug } = await params
  const pathname = slug.join('/')
  const proxyURL = new URL(pathname, 'https://nextjs.org')
  const proxyRequest = new Request(proxyURL, request)

  try {
    return fetch(proxyRequest)
  } catch (reason) {
    const message =
      reason instanceof Error ? reason.message : 'Unexpected exception'

    return new Response(message, { status: 500 })
  }
}
```

## NextRequest và NextResponse

Next.js mở rộng các Web APIs [`Request`](https://developer.mozilla.org/en-US/docs/Web/API/Request) và [`Response`](https://developer.mozilla.org/en-US/docs/Web/API/Response) với các phương thức giúp đơn giản hóa các hoạt động phổ biến. Các phần mở rộng này có sẵn trong cả Route Handlers và Proxy.

Cả hai đều cung cấp các phương thức để đọc và thao tác cookie.

`NextRequest` bao gồm thuộc tính [`nextUrl`](/docs/app/api-reference/functions/next-request#nexturl), hiển thị các giá trị đã phân tích cú pháp từ yêu cầu đến, ví dụ, nó giúp dễ dàng truy cập pathname và search params của yêu cầu.

`NextResponse` cung cấp các helpers như `next()`, `json()`, `redirect()`, và `rewrite()`.

Bạn có thể truyền `NextRequest` cho bất kỳ hàm nào mong đợi `Request`. Tương tự, bạn có thể trả về `NextResponse` ở nơi `Response` được mong đợi.

```ts filename="/app/echo-pathname/route.ts" switcher
import { type NextRequest, NextResponse } from 'next/server'

export async function GET(request: NextRequest) {
  const nextUrl = request.nextUrl

  if (nextUrl.searchParams.get('redirect')) {
    return NextResponse.redirect(new URL('/', request.url))
  }

  if (nextUrl.searchParams.get('rewrite')) {
    return NextResponse.rewrite(new URL('/', request.url))
  }

  return NextResponse.json({ pathname: nextUrl.pathname })
}
```


## Webhooks và callback URLs

Sử dụng Route Handlers để nhận thông báo sự kiện từ các ứng dụng của bên thứ ba.

Ví dụ, revalidate một route khi nội dung thay đổi trong CMS. Cấu hình CMS để gọi một endpoint cụ thể khi có thay đổi.

```ts filename="/app/webhook/route.ts" switcher
import { type NextRequest, NextResponse } from 'next/server'

export async function GET(request: NextRequest) {
  const token = request.nextUrl.searchParams.get('token')

  if (token !== process.env.REVALIDATE_SECRET_TOKEN) {
    return NextResponse.json({ success: false }, { status: 401 })
  }

  const tag = request.nextUrl.searchParams.get('tag')

  if (!tag) {
    return NextResponse.json({ success: false }, { status: 400 })
  }

  revalidateTag(tag)

  return NextResponse.json({ success: true })
}
```

Callback URLs là một trường hợp sử dụng khác. Khi người dùng hoàn thành một luồng của bên thứ ba, bên thứ ba sẽ gửi họ đến một callback URL. Sử dụng Route Handler để xác minh phản hồi và quyết định nơi chuyển hướng người dùng.

```ts filename="/app/auth/callback/route.ts" switcher
import { type NextRequest, NextResponse } from 'next/server'

export async function GET(request: NextRequest) {
  const token = request.nextUrl.searchParams.get('session_token')
  const redirectUrl = request.nextUrl.searchParams.get('redirect_url')

  const response = NextResponse.redirect(new URL(redirectUrl, request.url))

  response.cookies.set({
    value: token,
    name: '_token',
    path: '/',
    secure: true,
    httpOnly: true,
    expires: undefined, // session cookie
  })

  return response
}
```

## Proxy

Chỉ cho phép một file `proxy` cho mỗi dự án. Sử dụng `config.matcher` để nhắm mục tiêu các đường dẫn cụ thể. Tìm hiểu thêm về [`proxy`](/docs/app/api-reference/file-conventions/proxy).

Sử dụng `proxy` để tạo phản hồi trước khi yêu cầu đến đường dẫn route.

```ts filename="proxy.ts" switcher
import { isAuthenticated } from '@lib/auth'

export const config = {
  matcher: '/api/:function*',
}

export function proxy(request: Request) {
  if (!isAuthenticated(request)) {
    return Response.json(
      { success: false, message: 'authentication failed' },
      { status: 401 }
    )
  }
}
```

```js filename="proxy.js" switcher
import { isAuthenticated } from '@lib/auth'

  matcher: '/api/:function*',

```

Bạn cũng có thể proxy các yêu cầu bằng cách sử dụng `proxy`:

## Bảo mật

### Làm việc với headers

Hãy thận trọng về nơi các headers đi, và tránh chuyển trực tiếp các headers yêu cầu đến vào phản hồi đi.

- **Upstream request headers**: Trong Proxy, `NextResponse.next({ request: { headers } })` sửa đổi các headers mà server của bạn nhận được và không để lộ chúng cho client.
- **Response headers**: `new Response(..., { headers })`, `NextResponse.json(..., { headers })`, `NextResponse.next({ headers })`, hoặc `response.headers.set(...)` gửi các headers trở lại client. Nếu các giá trị nhạy cảm được thêm vào các headers này, chúng sẽ hiển thị cho clients.

Tìm hiểu thêm trong [NextResponse headers trong Proxy](/docs/app/api-reference/functions/next-response#next).

### Giới hạn tốc độ

Bạn có thể triển khai giới hạn tốc độ trong backend Next.js của mình. Ngoài các kiểm tra dựa trên mã, hãy bật bất kỳ tính năng giới hạn tốc độ nào được cung cấp bởi host của bạn.

```ts filename="/app/resource/route.ts" switcher
import { NextResponse } from 'next/server'
import { checkRateLimit } from '@/lib/rate-limit'

export async function POST(request: Request) {
  const { rateLimited } = await checkRateLimit(request)

  if (rateLimited) {
    return NextResponse.json({ error: 'Rate limit exceeded' }, { status: 429 })
  }

  return new Response(null, { status: 204 })
}
```


### Xác minh payloads

Không bao giờ tin tưởng dữ liệu yêu cầu đến. Xác thực loại nội dung và kích thước, và làm sạch chống lại XSS trước khi sử dụng.

Sử dụng thời gian chờ để ngăn chặn lạm dụng và bảo vệ tài nguyên server.

Lưu trữ các tài sản tĩnh do người dùng tạo trong các dịch vụ chuyên dụng. Khi có thể, hãy tải chúng lên từ trình duyệt và lưu trữ URI trả về trong cơ sở dữ liệu của bạn để giảm kích thước yêu cầu.

### Truy cập vào các tài nguyên được bảo vệ

Luôn xác minh thông tin đăng nhập trước khi cấp quyền truy cập. Không dựa vào proxy một mình để xác thực và ủy quyền.

Xóa dữ liệu nhạy cảm hoặc không cần thiết khỏi các phản hồi và nhật ký backend.

Xoay vòng thông tin đăng nhập và khóa API thường xuyên.

## Preflight Requests

Preflight requests sử dụng phương thức `OPTIONS` để hỏi server xem một yêu cầu có được phép hay không dựa trên nguồn gốc, phương thức và headers.

Nếu `OPTIONS` không được xác định, Next.js sẽ tự động thêm nó và đặt header `Allow` dựa trên các phương thức đã xác định khác.

- [CORS](/docs/app/api-reference/file-conventions/route#cors)

## Các mẫu thư viện

Các thư viện cộng đồng thường sử dụng mẫu factory cho Route Handlers.

```ts filename="/app/api/[...path]/route.ts"
import { createHandler } from 'third-party-library'

const handler = createHandler({
  /* library-specific options */
})

export const GET = handler
// or
export { handler as POST }
```

Điều này tạo ra một trình xử lý được chia sẻ cho các yêu cầu `GET` và `POST`. Thư viện tùy chỉnh hành vi dựa trên `method` và `pathname` trong yêu cầu.

Các thư viện cũng có thể cung cấp một `proxy` factory.

```ts filename="proxy.ts"
import { createMiddleware } from 'third-party-library'

export default createMiddleware()
```

> **Thông tin hữu ích**: Các thư viện của bên thứ ba vẫn có thể gọi `proxy` là `middleware`.

## Những lưu ý

### Server Components

Fetch dữ liệu trong Server Components trực tiếp từ nguồn của nó, không phải qua Route Handlers.

Đối với Server Components được pre-rendered tại build time, việc sử dụng Route Handlers sẽ làm hỏng bước build. Điều này là do, trong khi build, không có server nào lắng nghe các yêu cầu này.

Đối với Server Components được render theo yêu cầu, việc fetch từ Route Handlers chậm hơn do chuyến đi khứ hồi HTTP bổ sung giữa trình xử lý và quy trình render.

> Một yêu cầu `fetch` phía server sử dụng URL tuyệt đối. Điều này ngụ ý một chuyến đi khứ hồi HTTP, đến một server bên ngoài. Trong quá trình phát triển, development server của riêng bạn hoạt động như server bên ngoài. Tại build time, không có server, và tại runtime, server có sẵn thông qua miền công cộng của bạn.

Server Components bao gồm hầu hết các nhu cầu fetch dữ liệu. Tuy nhiên, fetch dữ liệu phía client có thể cần thiết cho:

- Dữ liệu phụ thuộc vào các Web APIs chỉ dành cho client:
  - Geo-location API
  - Storage API
  - Audio API
  - File API
- Dữ liệu được thăm dò thường xuyên

Đối với những trường hợp này, hãy sử dụng các thư viện cộng đồng như [`swr`](https://swr.vercel.app/) hoặc [`react-query`](https://tanstack.com/query/latest/docs/framework/react/overview).

### Server Actions

Server Actions cho phép bạn chạy mã phía server từ client. Mục đích chính của chúng là thay đổi dữ liệu từ frontend client của bạn.

Server Actions được xếp hàng. Sử dụng chúng để fetch dữ liệu sẽ giới thiệu việc thực thi tuần tự.

### Chế độ `export`

Chế độ `export` xuất ra một trang web tĩnh mà không có runtime server. Các tính năng yêu cầu Next.js runtime [không được hỗ trợ](/docs/app/guides/static-exports#unsupported-features), vì chế độ này tạo ra một trang web tĩnh, và không có runtime server.

Trong `export mode`, chỉ các `GET` Route Handlers được hỗ trợ, kết hợp với cấu hình phân đoạn route [`dynamic`](/docs/app/api-reference/file-conventions/route-segment-config#dynamic), được đặt thành `'force-static'`.

Điều này có thể được sử dụng để tạo HTML tĩnh, JSON, TXT, hoặc các tệp khác.

```js filename="app/hello-world/route.ts"
export const dynamic = 'force-static'

export function GET() {
  return new Response('Hello World', { status: 200 })
}
```

### Môi trường triển khai

Một số host triển khai Route Handlers dưới dạng các hàm lambda. Điều này có nghĩa là:

- Route Handlers không thể chia sẻ dữ liệu giữa các yêu cầu.
- Môi trường có thể không hỗ trợ ghi vào File System.
- Các trình xử lý chạy lâu có thể bị chấm dứt do hết thời gian chờ.
- WebSockets sẽ không hoạt động vì kết nối đóng khi hết thời gian chờ, hoặc sau khi phản hồi được tạo.
