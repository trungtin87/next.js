Next.js có hỗ trợ tích hợp để đo lường và báo cáo các chỉ số hiệu suất. Bạn có thể sử dụng hook [`useReportWebVitals`](/docs/app/api-reference/functions/use-report-web-vitals) để tự quản lý báo cáo, hoặc thay vào đó, Vercel cung cấp một [dịch vụ được quản lý](https://vercel.com/analytics?utm_source=next-site&utm_medium=docs&utm_campaign=next-website) để tự động thu thập và trực quan hóa các chỉ số cho bạn.

## Client Instrumentation

Đối với các nhu cầu phân tích và giám sát nâng cao hơn, Next.js cung cấp một file `instrumentation-client.js|ts` chạy trước khi mã frontend của ứng dụng bắt đầu thực thi. Điều này lý tưởng để thiết lập global analytics, theo dõi lỗi, hoặc các công cụ giám sát hiệu suất.

Để sử dụng nó, hãy tạo một file `instrumentation-client.js` hoặc `instrumentation-client.ts` trong thư mục gốc của ứng dụng của bạn:

```js filename="instrumentation-client.js"
// Initialize analytics before the app starts
console.log('Analytics initialized')

// Set up global error tracking
window.addEventListener('error', (event) => {
  // Send to your error tracking service
  reportError(event.error)
})
```

## Tự xây dựng

<PagesOnly>

```jsx filename="pages/_app.js"
import { useReportWebVitals } from 'next/web-vitals'

function MyApp({ Component, pageProps }) {
  useReportWebVitals((metric) => {
    console.log(metric)
  })

  return <Component {...pageProps} />
}
```

Xem [API Reference](/docs/pages/api-reference/functions/use-report-web-vitals) để biết thêm thông tin.

</PagesOnly>

<AppOnly>

```jsx filename="app/_components/web-vitals.js"
'use client'

import { useReportWebVitals } from 'next/web-vitals'

export function WebVitals() {
  useReportWebVitals((metric) => {
    console.log(metric)
  })
}
```

```jsx filename="app/layout.js"
import { WebVitals } from './_components/web-vitals'

export default function Layout({ children }) {
  return (
    <html>
      <body>
        <WebVitals />
        {children}
      </body>
    </html>
  )
}
```

> Vì hook `useReportWebVitals` yêu cầu directive `'use client'`, cách tiếp cận hiệu quả nhất là tạo một component riêng biệt mà root layout import. Điều này giới hạn client boundary chỉ trong component `WebVitals`.

Xem [API Reference](/docs/app/api-reference/functions/use-report-web-vitals) để biết thêm thông tin.

## Web Vitals

[Web Vitals](https://web.dev/vitals/) là một tập hợp các chỉ số hữu ích nhằm mục đích nắm bắt trải nghiệm người dùng của một trang web. Các web vitals sau đây đều được bao gồm:

- [Time to First Byte](https://developer.mozilla.org/docs/Glossary/Time_to_first_byte) (TTFB)
- [First Contentful Paint](https://developer.mozilla.org/docs/Glossary/First_contentful_paint) (FCP)
- [Largest Contentful Paint](https://web.dev/lcp/) (LCP)
- [First Input Delay](https://web.dev/fid/) (FID)
- [Cumulative Layout Shift](https://web.dev/cls/) (CLS)
- [Interaction to Next Paint](https://web.dev/inp/) (INP)

Bạn có thể xử lý tất cả các kết quả của các chỉ số này bằng cách sử dụng thuộc tính `name`.

<PagesOnly>

```jsx filename="pages/_app.js"
import { useReportWebVitals } from 'next/web-vitals'

function MyApp({ Component, pageProps }) {
  useReportWebVitals((metric) => {
    switch (metric.name) {
      case 'FCP': {
        // handle FCP results
      }
      case 'LCP': {
        // handle LCP results
      }
      // ...
    }
  })

  return <Component {...pageProps} />
}
```

</PagesOnly>

## Metrics tùy chỉnh

Ngoài các chỉ số cốt lõi được liệt kê ở trên, còn có một số chỉ số tùy chỉnh bổ sung đo lường thời gian cần thiết để trang hydrate và render:

- `Next.js-hydration`: Khoảng thời gian cần thiết để trang bắt đầu và kết thúc hydrating (tính bằng ms)
- `Next.js-route-change-to-render`: Khoảng thời gian cần thiết để một trang bắt đầu render sau khi thay đổi route (tính bằng ms)
- `Next.js-render`: Khoảng thời gian cần thiết để một trang kết thúc render sau khi thay đổi route (tính bằng ms)

Bạn có thể xử lý tất cả các kết quả của các chỉ số này một cách riêng biệt:

```js
export function reportWebVitals(metric) {
  switch (metric.name) {
    case 'Next.js-hydration':
      // handle hydration results
      break
    case 'Next.js-route-change-to-render':
      // handle route-change to render results
      break
    case 'Next.js-render':
      // handle render results
      break
    default:
      break
  }
}
```

Các chỉ số này hoạt động trong tất cả các trình duyệt hỗ trợ [User Timing API](https://caniuse.com/#feat=user-timing).

## Gửi kết quả đến các hệ thống bên ngoài

Bạn có thể gửi kết quả đến bất kỳ endpoint nào để đo lường và theo dõi hiệu suất người dùng thực trên trang web của mình. Ví dụ:

```js
useReportWebVitals((metric) => {
  const body = JSON.stringify(metric)
  const url = 'https://example.com/analytics'

  // Use `navigator.sendBeacon()` if available, falling back to `fetch()`.
  if (navigator.sendBeacon) {
    navigator.sendBeacon(url, body)
  } else {
    fetch(url, { body, method: 'POST', keepalive: true })
  }
})
```

> **Lưu ý**: Nếu bạn sử dụng [Google Analytics](https://analytics.google.com/analytics/web/), việc sử dụng giá trị `id` có thể cho phép bạn xây dựng phân phối chỉ số theo cách thủ công (để tính toán phần trăm, v.v.)

> ```js
> useReportWebVitals((metric) => {
>   // Use `window.gtag` if you initialized Google Analytics as this example:
>   // https://github.com/vercel/next.js/blob/canary/examples/with-google-analytics
>   window.gtag('event', metric.name, {
>     value: Math.round(
>       metric.name === 'CLS' ? metric.value * 1000 : metric.value
>     ), // values must be integers
>     event_label: metric.id, // id unique to current page load
>     non_interaction: true, // avoids affecting bounce rate.
>   })
> })
> ```
>
> Đọc thêm về [gửi kết quả đến Google Analytics](https://github.com/GoogleChrome/web-vitals#send-the-results-to-google-analytics).
