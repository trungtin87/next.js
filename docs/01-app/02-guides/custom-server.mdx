Next.js bao gồm server riêng của nó với `next start` theo mặc định. Nếu bạn có một backend hiện có, bạn vẫn có thể sử dụng nó với Next.js (đây không phải là custom server). Một custom Next.js server cho phép bạn khởi động server theo chương trình cho các custom patterns. Phần lớn thời gian, bạn sẽ không cần cách tiếp cận này. Tuy nhiên, nó có sẵn nếu bạn cần eject.

> **Nên biết**:
>
> - Trước khi quyết định sử dụng custom server, hãy nhớ rằng nó chỉ nên được sử dụng khi integrated router của Next.js không thể đáp ứng yêu cầu app của bạn. Một custom server sẽ loại bỏ các tối ưu hóa hiệu suất quan trọng, như **[Automatic Static Optimization](/docs/pages/building-your-application/rendering/automatic-static-optimization).**
> - Khi sử dụng standalone output mode, nó không trace custom server files. Mode này output một tệp `server.js` minimal riêng biệt thay thế. Chúng không thể được sử dụng cùng nhau.

Hãy xem [ví dụ sau](https://github.com/vercel/next.js/tree/canary/examples/custom-server) của một custom server:

```ts filename="server.ts" switcher
import { createServer } from 'http'
import { parse } from 'url'
import next from 'next'

const port = parseInt(process.env.PORT || '3000', 10)
const dev = process.env.NODE_ENV !== 'production'
const app = next({ dev })
const handle = app.getRequestHandler()

app.prepare().then(() => {
  createServer((req, res) => {
    const parsedUrl = parse(req.url!, true)
    handle(req, res, parsedUrl)
  }).listen(port)

  console.log(
    `> Server listening at http://localhost:${port} as ${
      dev ? 'development' : process.env.NODE_ENV
    }`
  )
})
```

```js filename="server.js" switcher
import { createServer } from 'http'
import { parse } from 'url'
import next from 'next'

const port = parseInt(process.env.PORT || '3000', 10)
const dev = process.env.NODE_ENV !== 'production'
const app = next({ dev })
const handle = app.getRequestHandler()

app.prepare().then(() => {
  createServer((req, res) => {
    const parsedUrl = parse(req.url, true)
    handle(req, res, parsedUrl)
  }).listen(port)

  console.log(
    `> Server listening at http://localhost:${port} as ${
      dev ? 'development' : process.env.NODE_ENV
    }`
  )
})
```

> `server.js` không chạy qua Next.js Compiler hoặc bundling process. Đảm bảo syntax và source code mà tệp này yêu cầu tương thích với phiên bản Node.js hiện tại bạn đang sử dụng. [Xem ví dụ](https://github.com/vercel/next.js/tree/canary/examples/custom-server).

Để chạy custom server, bạn sẽ cần cập nhật `scripts` trong `package.json` như sau:

```json filename="package.json"
{
  "scripts": {
    "dev": "node server.js",
    "build": "next build",
    "start": "NODE_ENV=production node server.js"
  }
}
```

Ngoài ra, bạn có thể thiết lập `nodemon` ([ví dụ](https://github.com/vercel/next.js/tree/canary/examples/custom-server)). Custom server sử dụng import sau để kết nối server với ứng dụng Next.js:

```js
import next from 'next'

const app = next({})
```

Import `next` ở trên là một hàm nhận một object với các options sau:

| Option       | Type               | Mô tả                                                                           |
| ------------ | ------------------ | ------------------------------------------------------------------------------- |
| `conf`       | `Object`           | Object giống như bạn sẽ sử dụng trong `next.config.js`. Mặc định là `{}`        |
| `dev`        | `Boolean`          | (_Tùy chọn_) Có khởi động Next.js trong dev mode hay không. Mặc định là `false` |
| `dir`        | `String`           | (_Tùy chọn_) Vị trí của dự án Next.js. Mặc định là `'.'`                        |
| `quiet`      | `Boolean`          | (_Tùy chọn_) Ẩn error messages chứa server information. Mặc định là `false`     |
| `hostname`   | `String`           | (_Tùy chọn_) Hostname mà server đang chạy phía sau                              |
| `port`       | `Number`           | (_Tùy chọn_) Port mà server đang chạy phía sau                                  |
| `httpServer` | `node:http#Server` | (_Tùy chọn_) HTTP Server mà Next.js đang chạy phía sau                          |
| `turbopack`  | `Boolean`          | (_Tùy chọn_) Enable Turbopack (enabled theo mặc định)                           |
| `webpack`    | `Boolean`          | (_Tùy chọn_) Enable webpack                                                     |

`app` được trả về sau đó có thể được sử dụng để cho Next.js xử lý requests theo yêu cầu.

## Disable file-system routing

Theo mặc định, `Next` sẽ phục vụ mỗi tệp trong thư mục `pages` dưới một pathname khớp với filename. Nếu dự án của bạn sử dụng custom server, hành vi này có thể dẫn đến cùng một nội dung được phục vụ từ nhiều paths, có thể gây ra vấn đề với SEO và UX.

Để disable hành vi này và ngăn routing dựa trên files trong `pages`, hãy mở `next.config.js` và disable cấu hình `useFileSystemPublicRoutes`:

```js filename="next.config.js"
module.exports = {
  useFileSystemPublicRoutes: false,
}
```

> Lưu ý rằng `useFileSystemPublicRoutes` disable filename routes từ SSR; client-side routing vẫn có thể truy cập các paths đó. Khi sử dụng option này, bạn nên guard against navigation đến routes bạn không muốn theo chương trình.

> Bạn cũng có thể muốn cấu hình client-side router để disallow client-side redirects đến filename routes; để làm điều đó, hãy tham khảo [`router.beforePopState`](/docs/pages/api-reference/functions/use-router#routerbeforepopstate).
