---
title: Codemods
description: Sử dụng codemods để nâng cấp codebase Next.js của bạn khi các tính năng mới được phát hành.
---

Codemods là các phép biến đổi chạy trên codebase của bạn theo chương trình. Điều này cho phép áp dụng một số lượng lớn các thay đổi theo chương trình mà không cần phải đi qua từng tệp theo cách thủ công.

Next.js cung cấp các phép biến đổi Codemod để giúp nâng cấp codebase Next.js của bạn khi một API được cập nhật hoặc không còn được dùng nữa (deprecated).

## Sử dụng

Trong terminal của bạn, điều hướng (`cd`) vào thư mục dự án của bạn, sau đó chạy:

```bash filename="Terminal"
npx @next/codemod <transform> <path>
```

Thay thế `<transform>` và `<path>` bằng các giá trị thích hợp.

- `transform` - tên của phép biến đổi
- `path` - tệp hoặc thư mục để biến đổi
- `--dry` Chạy thử, không có mã nào được chỉnh sửa
- `--print` In ra đầu ra đã thay đổi để so sánh

### 16.0

#### Xóa `experimental_ppr` Route Segment Config khỏi các trang và layouts của App Router

##### `remove-experimental-ppr`

```bash filename="Terminal"
npx @next/codemod@latest remove-experimental-ppr .
```

Codemod này xóa `experimental_ppr` Route Segment Config khỏi các trang và layouts của App Router.

```diff filename="app/page.tsx"
- export const experimental_ppr = true;
```

#### Xóa tiền tố `unstable_` khỏi API đã ổn định

##### `remove-unstable-prefix`

```bash filename="Terminal"
npx @next/codemod@latest remove-unstable-prefix .
```

Codemod này xóa tiền tố `unstable_` khỏi API đã ổn định.

Ví dụ:

```ts
import { unstable_cacheTag as cacheTag } from 'next/cache'

cacheTag()
```

Biến đổi thành:

```ts
import { cacheTag } from 'next/cache'

cacheTag()
```

#### Di chuyển từ quy ước `middleware` không còn được dùng sang `proxy`

##### `middleware-to-proxy`

```bash filename="Terminal"
npx @next/codemod@latest middleware-to-proxy .
```

Codemod này di chuyển các dự án từ việc sử dụng quy ước `middleware` không còn được dùng sang sử dụng quy ước `proxy`. Nó:

- Đổi tên `middleware.<extension>` thành `proxy.<extension>` (ví dụ: `middleware.ts` thành `proxy.ts`)
- Đổi tên named export `middleware` thành `proxy`
- Đổi tên thuộc tính cấu hình Next.js `experimental.middlewarePrefetch` thành `experimental.proxyPrefetch`
- Đổi tên thuộc tính cấu hình Next.js `experimental.middlewareClientMaxBodySize` thành `experimental.proxyClientMaxBodySize`
- Đổi tên thuộc tính cấu hình Next.js `experimental.externalMiddlewareRewritesResolve` thành `experimental.externalProxyRewritesResolve`
- Đổi tên thuộc tính cấu hình Next.js `skipMiddlewareUrlNormalize` thành `skipProxyUrlNormalize`

Ví dụ:

```ts filename="middleware.ts"
import { NextResponse } from 'next/server'

export function middleware() {
  return NextResponse.next()
}
```

Biến đổi thành:

```ts filename="proxy.ts"
import { NextResponse } from 'next/server'

export function proxy() {
  return NextResponse.next()
}
```

#### Di chuyển từ `next lint` sang ESLint CLI

##### `next-lint-to-eslint-cli`

```bash filename="Terminal"
npx @next/codemod@canary next-lint-to-eslint-cli .
```

Codemod này di chuyển các dự án từ việc sử dụng `next lint` sang sử dụng ESLint CLI với cấu hình ESLint cục bộ của bạn. Nó:

- Tạo tệp `eslint.config.mjs` với các cấu hình được đề xuất của Next.js
- Cập nhật các scripts trong `package.json` để sử dụng `eslint .` thay vì `next lint`
- Thêm các phụ thuộc ESLint cần thiết vào `package.json`
- Bảo tồn các cấu hình ESLint hiện có khi tìm thấy

Ví dụ:

```json filename="package.json"
{
  "scripts": {
    "lint": "next lint"
  }
}
```

Trở thành:

```json filename="package.json"
{
  "scripts": {
    "lint": "eslint ."
  }
}
```

Và tạo:

```js filename="eslint.config.mjs"
import { dirname } from 'path'
import { fileURLToPath } from 'url'
import { FlatCompat } from '@eslint/eslintrc'

const __filename = fileURLToPath(import.meta.url)
const __dirname = dirname(__filename)

const compat = new FlatCompat({
  baseDirectory: __dirname,
})

const eslintConfig = [
  ...compat.extends('next/core-web-vitals', 'next/typescript'),
  {
    ignores: [
      'node_modules/**',
      '.next/**',
      'out/**',
      'build/**',
      'next-env.d.ts',
    ],
  },
]

export default eslintConfig
```

#### Di chuyển sang async Dynamic APIs

Các API đã chọn tham gia dynamic rendering trước đây hỗ trợ truy cập đồng bộ giờ đây là bất đồng bộ. Bạn có thể đọc thêm về thay đổi phá vỡ này trong [hướng dẫn nâng cấp](/docs/app/guides/upgrading/version-15).

##### `next-async-request-api`

```bash filename="Terminal"
npx @next/codemod@latest next-async-request-api .
```

Codemod này sẽ biến đổi các API động (`cookies()`, `headers()` và `draftMode()` từ `next/headers`) hiện là bất đồng bộ để được await đúng cách hoặc được bao bọc bằng `React.use()` nếu có thể áp dụng.
Khi không thể di chuyển tự động, codemod sẽ thêm typecast (nếu là tệp TypeScript) hoặc nhận xét để thông báo cho người dùng rằng nó cần được xem xét và cập nhật thủ công.

Ví dụ:

```tsx
import { cookies, headers } from 'next/headers'
const token = cookies().get('token')

function useToken() {
  const token = cookies().get('token')
  return token
}

export default function Page() {
  const name = cookies().get('name')
}

function getHeader() {
  return headers().get('x-foo')
}
```

Biến đổi thành:

```tsx
import { use } from 'react'
import {
  cookies,
  headers,
  type UnsafeUnwrappedCookies,
  type UnsafeUnwrappedHeaders,
} from 'next/headers'
const token = (cookies() as unknown as UnsafeUnwrappedCookies).get('token')

function useToken() {
  const token = use(cookies()).get('token')
  return token
}

export default async function Page() {
  const name = (await cookies()).get('name')
}

function getHeader() {
  return (headers() as unknown as UnsafeUnwrappedHeaders).get('x-foo')
}
```

Khi chúng tôi phát hiện truy cập thuộc tính trên các props `params` hoặc `searchParams` trong các mục nhập page / route (`page.js`, `layout.js`, `route.js`, hoặc `default.js`) hoặc các API `generateMetadata` / `generateViewport`,
nó sẽ cố gắng biến đổi callsite từ hàm đồng bộ sang hàm bất đồng bộ, và await truy cập thuộc tính. Nếu nó không thể được thực hiện bất đồng bộ (chẳng hạn như với Client Component), nó sẽ sử dụng `React.use` để unwrap promise.

Ví dụ:

```tsx
// page.tsx
export default function Page({
  params,
  searchParams,
}: {
  params: { slug: string }
  searchParams: { [key: string]: string | string[] | undefined }
}) {
  const { value } = searchParams
  if (value === 'foo') {
    // ...
  }
}

export function generateMetadata({ params }: { params: { slug: string } }) {
  const { slug } = params
  return {
    title: `My Page - ${slug}`,
  }
}
```

Biến đổi thành:

```tsx
// page.tsx
export default async function Page(props: {
  params: Promise<{ slug: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const searchParams = await props.searchParams
  const { value } = searchParams
  if (value === 'foo') {
    // ...
  }
}

export async function generateMetadata(props: {
  params: Promise<{ slug: string }>
}) {
  const params = await props.params
  const { slug } = params
  return {
    title: `My Page - ${slug}`,
  }
}
```

> **Cần biết:** Khi codemod này xác định một điểm có thể yêu cầu can thiệp thủ công, nhưng chúng tôi không thể xác định bản sửa lỗi chính xác, nó sẽ thêm nhận xét hoặc typecast vào mã để thông báo cho người dùng rằng nó cần được cập nhật thủ công. Những nhận xét này có tiền tố **@next/codemod**, và typecasts có tiền tố `UnsafeUnwrapped`.
> Bản build của bạn sẽ bị lỗi cho đến khi những nhận xét này được xóa rõ ràng. [Đọc thêm](/docs/messages/sync-dynamic-apis).

#### Thay thế các thuộc tính `geo` và `ip` của `NextRequest` bằng `@vercel/functions`

##### `next-request-geo-ip`

```bash filename="Terminal"
npx @next/codemod@latest next-request-geo-ip .
```

Codemod này cài đặt `@vercel/functions` và biến đổi các thuộc tính `geo` và `ip` của `NextRequest` với các tính năng tương ứng của `@vercel/functions`.

Ví dụ:

```ts
import type { NextRequest } from 'next/server'

export function GET(req: NextRequest) {
  const { geo, ip } = req
}
```

Biến đổi thành:

```ts
import type { NextRequest } from 'next/server'
import { geolocation, ipAddress } from '@vercel/functions'

export function GET(req: NextRequest) {
  const geo = geolocation(req)
  const ip = ipAddress(req)
}
```


```jsx filename="pages/index.js"
import Image2 from 'next/image'

export default function Home() {
  return (
    <div>
```

### 9

#### Biến đổi Anonymous Components thành Named Components

##### `name-default-component`

```bash filename="Terminal"
npx @next/codemod name-default-component
```

**Phiên bản 9 trở lên.**

Biến đổi các anonymous components thành named components để đảm bảo chúng hoạt động với [Fast Refresh](https://nextjs.org/blog/next-9-4#fast-refresh).

### 6

#### Sử dụng `withRouter`

##### `url-to-withrouter`

```bash filename="Terminal"
npx @next/codemod url-to-withrouter
```

Biến đổi thuộc tính `url` được tiêm tự động không còn được dùng trên các trang cấp cao nhất để sử dụng `withRouter` và thuộc tính `router` mà nó tiêm vào. Đọc thêm tại đây: [https://nextjs.org/docs/messages/url-deprecated](/docs/messages/url-deprecated)

Ví dụ:

```js filename="From"
import React from 'react'
export default class extends React.Component {
  render() {
    const { pathname } = this.props.url
    return <div>Current pathname: {pathname}</div>
  }
}
```

```js filename="To"
import React from 'react'
import { withRouter } from 'next/router'
export default withRouter(
  class extends React.Component {
    render() {
      const { pathname } = this.props.router
      return <div>Current pathname: {pathname}</div>
    }
  }
)
```

Đây là một trường hợp. Tất cả các trường hợp được biến đổi (và kiểm tra) có thể được tìm thấy trong [thư mục `__testfixtures__`](https://github.com/vercel/next.js/tree/canary/packages/next-codemod/transforms/__testfixtures__/url-to-withrouter).
