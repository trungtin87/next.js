Tài liệu này giải thích cách bạn có thể gỡ lỗi mã frontend và backend Next.js của mình với hỗ trợ source maps đầy đủ bằng cách sử dụng [VS Code debugger](https://code.visualstudio.com/docs/editor/debugging), [Chrome DevTools](https://developers.google.com/web/tools/chrome-devtools), hoặc [Firefox DevTools](https://firefox-source-docs.mozilla.org/devtools-user/).

Bất kỳ trình gỡ lỗi nào có thể gắn vào Node.js cũng có thể được sử dụng để gỡ lỗi ứng dụng Next.js. Bạn có thể tìm thêm chi tiết trong [Hướng dẫn Gỡ lỗi](https://nodejs.org/en/docs/guides/debugging-getting-started/) của Node.js.

## Gỡ lỗi với VS Code

Tạo một tệp có tên `.vscode/launch.json` tại thư mục gốc của dự án của bạn với nội dung sau:

```json filename="launch.json"
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Next.js: debug server-side",
      "type": "node-terminal",
      "request": "launch",
      "command": "npm run dev"
    },
    {
      "name": "Next.js: debug client-side",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:3000"
    },
    {
      "name": "Next.js: debug client-side (Firefox)",
      "type": "firefox",
      "request": "launch",
      "url": "http://localhost:3000",
      "reAttach": true,
      "pathMappings": [
        {
          "url": "webpack://_N_E",
          "path": "${workspaceFolder}"
        }
      ]
    },
    {
      "name": "Next.js: debug full stack",
      "type": "node",
      "request": "launch",
      "program": "${workspaceFolder}/node_modules/next/dist/bin/next",
      "runtimeArgs": ["--inspect"],
      "skipFiles": ["<node_internals>/**"],
      "serverReadyAction": {
        "action": "debugWithEdge",
        "killOnServerStop": true,
        "pattern": "- Local:.+(https?://.+)",
        "uriFormat": "%s",
        "webRoot": "${workspaceFolder}"
      }
    }
  ]
}
```

> **Lưu ý**: Để sử dụng gỡ lỗi Firefox trong VS Code, bạn sẽ cần cài đặt [Firefox Debugger extension](https://marketplace.visualstudio.com/items?itemName=firefox-devtools.vscode-firefox-debug).

`npm run dev` có thể được thay thế bằng `yarn dev` nếu bạn đang sử dụng Yarn hoặc `pnpm dev` nếu bạn đang sử dụng pnpm.

Trong cấu hình "Next.js: debug full stack", `serverReadyAction.action` chỉ định trình duyệt nào sẽ mở khi máy chủ sẵn sàng. `debugWithEdge` có nghĩa là khởi chạy trình duyệt Edge. Nếu bạn đang sử dụng Chrome, hãy thay đổi giá trị này thành `debugWithChrome`.

Nếu bạn đang [thay đổi số cổng](/docs/pages/api-reference/cli/next#next-dev-options) mà ứng dụng của bạn bắt đầu, hãy thay thế `3000` trong `http://localhost:3000` bằng cổng bạn đang sử dụng.

Nếu bạn đang chạy Next.js từ một thư mục khác ngoài thư mục gốc (ví dụ, nếu bạn đang sử dụng Turborepo) thì bạn cần thêm `cwd` vào các tác vụ gỡ lỗi server-side và full stack. Ví dụ, `"cwd": "${workspaceFolder}/apps/web"`.

Bây giờ hãy chuyển đến bảng Debug (`Ctrl+Shift+D` trên Windows/Linux, `⇧+⌘+D` trên macOS), chọn một cấu hình khởi chạy, sau đó nhấn `F5` hoặc chọn **Debug: Start Debugging** từ Command Palette để bắt đầu phiên gỡ lỗi của bạn.

## Sử dụng Trình gỡ lỗi trong Jetbrains WebStorm

Nhấp vào menu thả xuống liệt kê cấu hình runtime, và nhấp vào `Edit Configurations...`. Tạo một cấu hình gỡ lỗi `JavaScript Debug` với `http://localhost:3000` làm URL. Tùy chỉnh theo ý thích của bạn (ví dụ: Trình duyệt để gỡ lỗi, lưu trữ dưới dạng tệp dự án), và nhấp vào `OK`. Chạy cấu hình gỡ lỗi này, và trình duyệt đã chọn sẽ tự động mở. Tại thời điểm này, bạn sẽ có 2 ứng dụng ở chế độ gỡ lỗi: ứng dụng node NextJS, và ứng dụng client/browser.

## Gỡ lỗi với Browser DevTools

### Mã Client-side

Khởi động máy chủ phát triển của bạn như bình thường bằng cách chạy `next dev`, `npm run dev`, hoặc `yarn dev`. Khi máy chủ khởi động, hãy mở `http://localhost:3000` (hoặc URL thay thế của bạn) trong trình duyệt ưa thích của bạn.

Đối với Chrome:

- Mở Chrome's Developer Tools (`Ctrl+Shift+J` trên Windows/Linux, `⌥+⌘+I` trên macOS)
- Đi tới tab **Sources**

Đối với Firefox:

- Mở Firefox's Developer Tools (`Ctrl+Shift+I` trên Windows/Linux, `⌥+⌘+I` trên macOS)
- Đi tới tab **Debugger**

Trong cả hai trình duyệt, bất cứ khi nào mã phía máy khách của bạn đạt đến câu lệnh [`debugger`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Statements/debugger), việc thực thi mã sẽ tạm dừng và tệp đó sẽ xuất hiện trong khu vực gỡ lỗi. Bạn cũng có thể tìm kiếm các tệp để đặt breakpoints thủ công:

- Trong Chrome: Nhấn `Ctrl+P` trên Windows/Linux hoặc `⌘+P` trên macOS
- Trong Firefox: Nhấn `Ctrl+P` trên Windows/Linux hoặc `⌘+P` trên macOS, hoặc sử dụng cây tệp trong bảng điều khiển bên trái

Lưu ý rằng khi tìm kiếm, các tệp nguồn của bạn sẽ có đường dẫn bắt đầu bằng `webpack://_N_E/./`.

### React Developer Tools

Để gỡ lỗi dành riêng cho React, hãy cài đặt tiện ích mở rộng trình duyệt [React Developer Tools](https://react.dev/learn/react-developer-tools). Công cụ thiết yếu này giúp bạn:

- Kiểm tra các thành phần React
- Chỉnh sửa props và state
- Xác định các vấn đề về hiệu suất

### Mã Server-side

Để gỡ lỗi mã Next.js phía máy chủ với browser DevTools, bạn cần truyền cờ [`--inspect`](https://nodejs.org/api/cli.html#cli_inspect_host_port) cho quy trình Node.js cơ bản:

```bash filename="Terminal"
NODE_OPTIONS='--inspect' next dev
```

> **Cần biết**: Sử dụng `NODE_OPTIONS='--inspect=0.0.0.0'` để cho phép truy cập gỡ lỗi từ xa bên ngoài localhost, chẳng hạn như khi chạy ứng dụng trong vùng chứa Docker.

Nếu bạn đang sử dụng `npm run dev` hoặc `yarn dev` thì bạn nên cập nhật script `dev` trong `package.json` của mình:

```json filename="package.json"
{
  "scripts": {
    "dev": "NODE_OPTIONS='--inspect' next dev"
  }
}
```

Khởi chạy máy chủ dev Next.js với cờ `--inspect` sẽ trông giống như thế này:

```bash filename="Terminal"
Debugger listening on ws://127.0.0.1:9229/0cf90313-350d-4466-a748-cd60f4e47c95
For help, see: https://nodejs.org/en/docs/inspector
ready - started server on 0.0.0.0:3000, url: http://localhost:3000
```

Đối với Chrome:

1. Mở một tab mới và truy cập `chrome://inspect`
2. Nhấp vào **Configure...** để đảm bảo cả hai cổng gỡ lỗi đều được liệt kê
3. Thêm cả `localhost:9229` và `localhost:9230` nếu chúng chưa có
4. Tìm ứng dụng Next.js của bạn trong phần **Remote Target**
5. Nhấp vào **inspect** để mở một cửa sổ DevTools riêng biệt
6. Đi tới tab **Sources**

Đối với Firefox:

1. Mở một tab mới và truy cập `about:debugging`
2. Nhấp vào **This Firefox** trong thanh bên trái
3. Trong **Remote Targets**, tìm ứng dụng Next.js của bạn
4. Nhấp vào **Inspect** để mở trình gỡ lỗi
5. Đi tới tab **Debugger**

Gỡ lỗi mã phía máy chủ hoạt động tương tự như gỡ lỗi phía máy khách. Khi tìm kiếm các tệp (`Ctrl+P`/`⌘+P`), các tệp nguồn của bạn sẽ có đường dẫn bắt đầu bằng `webpack://{application-name}/./` (trong đó `{application-name}` sẽ được thay thế bằng tên ứng dụng của bạn theo tệp `package.json`).

### Kiểm tra Lỗi Máy chủ với Browser DevTools

Khi bạn gặp lỗi, việc kiểm tra mã nguồn có thể giúp truy tìm nguyên nhân gốc rễ của lỗi.

Next.js sẽ hiển thị biểu tượng Node.js bên dưới chỉ báo phiên bản Next.js trên lớp phủ lỗi. Bằng cách nhấp vào biểu tượng đó, URL DevTools được sao chép vào clipboard của bạn. Bạn có thể mở một tab trình duyệt mới với URL đó để kiểm tra quy trình máy chủ Next.js.

### Gỡ lỗi trên Windows

Người dùng Windows có thể gặp sự cố khi sử dụng `NODE_OPTIONS='--inspect'` vì cú pháp đó không được hỗ trợ trên các nền tảng Windows. Để giải quyết vấn đề này, hãy cài đặt gói [`cross-env`](https://www.npmjs.com/package/cross-env) như một phụ thuộc phát triển (`-D` với `npm` và `yarn`) và thay thế script `dev` bằng script sau.

```json filename="package.json"
{
  "scripts": {
    "dev": "cross-env NODE_OPTIONS='--inspect' next dev"
  }
}
```

`cross-env` sẽ đặt biến môi trường `NODE_OPTIONS` bất kể bạn đang ở nền tảng nào (bao gồm Mac, Linux, và Windows) và cho phép bạn gỡ lỗi nhất quán trên các thiết bị và hệ điều hành.

> **Cần biết**: Đảm bảo Windows Defender bị vô hiệu hóa trên máy của bạn. Dịch vụ bên ngoài này sẽ kiểm tra _mọi tệp được đọc_, điều này đã được báo cáo là làm tăng đáng kể thời gian Fast Refresh với `next dev`. Đây là một vấn đề đã biết, không liên quan đến Next.js, nhưng nó ảnh hưởng đến việc phát triển Next.js.
