Prefetching làm cho việc điều hướng giữa các route khác nhau trong ứng dụng của bạn cảm thấy tức thì. Next.js cố gắng prefetch một cách thông minh theo mặc định, dựa trên các liên kết được sử dụng trong mã ứng dụng của bạn.

## Prefetching hoạt động như thế nào?

Khi điều hướng giữa các route, trình duyệt yêu cầu các tài sản cho trang như tệp HTML và JavaScript. Prefetching là quá trình fetch các tài nguyên này _trước_ thời hạn, trước khi bạn điều hướng đến một route mới.

Next.js tự động chia nhỏ ứng dụng của bạn thành các đoạn JavaScript nhỏ hơn dựa trên các route. Thay vì tải tất cả mã ngay từ đầu như các SPA truyền thống, chỉ mã cần thiết cho route hiện tại mới được tải. Điều này làm giảm thời gian tải ban đầu trong khi các phần khác của ứng dụng được tải trong nền. Vào thời điểm bạn nhấp vào liên kết, các tài nguyên cho route mới đã được tải vào cache của trình duyệt.

Khi điều hướng đến trang mới, không có tải lại toàn bộ trang hoặc vòng quay tải của trình duyệt. Thay vào đó, Next.js thực hiện một [client-side transition (chuyển đổi phía máy khách)](/docs/app/getting-started/linking-and-navigating#client-side-transitions), làm cho việc điều hướng trang cảm thấy tức thì.

## Prefetching static vs. dynamic routes

|                                                                   | **Trang tĩnh**    | **Trang động**                                                                    |
| ----------------------------------------------------------------- | ----------------- | --------------------------------------------------------------------------------- |
| **Prefetched**                                                    | Có, toàn bộ route | Không, trừ khi [`loading.js`](/docs/app/api-reference/file-conventions/loading)   |
| [**Client Cache TTL**](/docs/app/guides/caching#full-route-cache) | 5 phút (mặc định) | Tắt, trừ khi [được bật](/docs/app/api-reference/config/next-config-js/staleTimes) |
| **Server roundtrip khi click**                                    | Không             | Có, được stream sau [shell](/docs/app/getting-started/cache-components)           |

> **Cần biết:** Trong lần điều hướng ban đầu, trình duyệt fetch HTML, JavaScript, và React Server Components (RSC) Payload. Đối với các lần điều hướng tiếp theo, trình duyệt sẽ fetch RSC Payload cho Server Components và JS bundle cho Client Components.

## Automatic prefetch

```tsx filename="app/ui/nav-link.tsx" switcher
import Link from 'next/link'

export default function NavLink() {
  return <Link href="/about">About</Link>
}
```

```jsx filename="app/ui/nav-link.js" switcher
import Link from 'next/link'

export default function NavLink() {
  return <Link href="/about">About</Link>
}
```

| **Ngữ cảnh**       | **Prefetched payload**               | **Client Cache TTL**                                                              |
| ------------------ | ------------------------------------ | --------------------------------------------------------------------------------- |
| Không `loading.js` | Toàn bộ trang                        | Cho đến khi tải lại ứng dụng                                                      |
| Với `loading.js`   | Layout đến loading boundary đầu tiên | 30s ([có thể cấu hình](/docs/app/api-reference/config/next-config-js/staleTimes)) |

Automatic prefetching chỉ chạy trong production. Vô hiệu hóa với `prefetch={false}` hoặc sử dụng wrapper trong [Disabled Prefetch](#disabled-prefetch).

## Manual prefetch

Để thực hiện manual prefetching, hãy import hook `useRouter` từ `next/navigation`, và gọi `router.prefetch()` để làm nóng các route bên ngoài viewport hoặc để phản hồi analytics, hover, scroll, v.v.

```tsx
'use client'

import { useRouter } from 'next/navigation'
import { CustomLink } from '@components/link'

export function PricingCard() {
  const router = useRouter()

  return (
    <div onMouseEnter={() => router.prefetch('/pricing')}>
      {/* các phần tử UI khác */}
      <CustomLink href="/pricing">View Pricing</CustomLink>
    </div>
  )
}
```

Nếu mục đích là prefetch một URL khi một component tải, hãy xem [ví dụ] về việc mở rộng hoặc từ chối một liên kết.

## Hover-triggered prefetch

> **Tiến hành thận trọng:** Mở rộng `Link` chọn bạn tham gia vào việc duy trì prefetching, cache invalidation, và các mối quan tâm về khả năng truy cập. Chỉ tiến hành nếu các mặc định không đủ.

Next.js cố gắng thực hiện prefetching đúng theo mặc định, nhưng người dùng nâng cao có thể eject và sửa đổi dựa trên nhu cầu của họ. Bạn có quyền kiểm soát giữa hiệu suất và mức tiêu thụ tài nguyên.

Ví dụ, bạn có thể chỉ phải kích hoạt prefetches khi hover, thay vì khi vào viewport (hành vi mặc định):

```tsx
'use client'

import Link from 'next/link'
import { useState } from 'react'

export function HoverPrefetchLink({
  href,
  children,
}: {
  href: string
  children: React.ReactNode
}) {
  const [active, setActive] = useState(false)

  return (
    <Link
      href={href}
      prefetch={active ? null : false}
      onMouseEnter={() => setActive(true)}
    >
      {children}
    </Link>
  )
}
```

`prefetch={null}` khôi phục prefetching mặc định (tĩnh) khi người dùng thể hiện ý định.

## Extending or ejecting link

Bạn có thể mở rộng component `<Link>` để tạo chiến lược prefetching tùy chỉnh của riêng mình. Ví dụ, sử dụng thư viện [ForesightJS](https://foresightjs.com/docs/integrations/nextjs) để prefetch các liên kết bằng cách dự đoán hướng của con trỏ người dùng.

Ngoài ra, bạn có thể sử dụng [`useRouter`](/docs/app/api-reference/functions/use-router) để tạo lại một số hành vi native của `<Link>`. Tuy nhiên, hãy lưu ý điều này chọn bạn tham gia vào việc duy trì prefetching và cache invalidation.

```tsx
'use client'

import { useRouter } from 'next/navigation'
import { useEffect } from 'react'

function ManualPrefetchLink({
  href,
  children,
}: {
  href: string
  children: React.ReactNode
}) {
  const router = useRouter()

  useEffect(() => {
    let cancelled = false
    const poll = () => {
      if (!cancelled) router.prefetch(href, { onInvalidate: poll })
    }
    poll()
    return () => {
      cancelled = true
    }
  }, [href, router])

  return (
    <a
      href={href}
      onClick={(event) => {
        event.preventDefault()
        router.push(href)
      }}
    >
      {children}
    </a>
  )
}
```

[`onInvalidate`](/docs/app/api-reference/functions/use-router#userouter) được gọi khi Next.js nghi ngờ dữ liệu đã cache bị cũ, cho phép bạn làm mới prefetch.

> **Cần biết:** Sử dụng thẻ `a` sẽ gây ra điều hướng toàn trang đến route đích, bạn có thể sử dụng `onClick` để ngăn điều hướng toàn trang, và sau đó gọi `router.push` để điều hướng đến đích.

## Disabled prefetch

Bạn có thể vô hiệu hóa hoàn toàn prefetching cho các route nhất định để kiểm soát chi tiết hơn về mức tiêu thụ tài nguyên.

```tsx
'use client'

import Link, { LinkProps } from 'next/link'

function NoPrefetchLink({
  prefetch,
  ...rest
}: LinkProps & { children: React.ReactNode }) {
  return <Link {...rest} prefetch={false} />
}
```

Ví dụ, bạn vẫn có thể muốn sử dụng nhất quán `<Link>` trong ứng dụng của mình, nhưng các liên kết trong footer của bạn có thể không cần phải được prefetch khi vào viewport.

## Tối ưu hóa prefetching

> **Cần biết:** Layout deduplication và prefetch scheduling là một phần của các tối ưu hóa sắp tới. Hiện có sẵn trong Next.js canary thông qua cờ `experimental.clientSegmentCache`.

### Client cache

Next.js lưu trữ các payloads React Server Component đã prefetch trong bộ nhớ, được khóa bởi các phân đoạn route. Khi điều hướng giữa các route anh em (v.d. `/dashboard/settings` → `/dashboard/analytics`), nó sử dụng lại layout cha và chỉ fetch trang lá đã cập nhật. Điều này làm giảm lưu lượng mạng và cải thiện tốc độ điều hướng.

### Prefetch scheduling

Next.js duy trì một hàng đợi tác vụ nhỏ, thực hiện prefetch theo thứ tự sau:

1. Các liên kết trong viewport
2. Các liên kết hiển thị ý định của người dùng (hover hoặc touch)
3. Các liên kết mới hơn thay thế các liên kết cũ hơn
4. Các liên kết cuộn ra khỏi màn hình bị loại bỏ

Bộ lập lịch ưu tiên các điều hướng có khả năng xảy ra trong khi giảm thiểu các tải xuống không sử dụng.

### Partial Prerendering (PPR)

Khi PPR được bật, một trang được chia thành một shell tĩnh và một phần động được stream:

- Shell, có thể được prefetch, stream ngay lập tức
- Dữ liệu động stream khi sẵn sàng
- Data invalidations (`revalidateTag`, `revalidatePath`) âm thầm làm mới các prefetches liên quan

## Khắc phục sự cố

### Kích hoạt các side-effects không mong muốn trong quá trình prefetching

Nếu các layouts hoặc pages của bạn không [pure (thuần túy)](https://react.dev/learn/keeping-components-pure#purity-components-as-formulas) và có side-effects (v.d. theo dõi analytics), những điều này có thể được kích hoạt khi route được prefetch, không phải khi người dùng truy cập trang.

Để tránh điều này, bạn nên di chuyển các side-effects sang một `useEffect` hook hoặc một Server Action được kích hoạt từ một Client Component.

**Trước**:

```tsx filename="app/dashboard/layout.tsx" switcher
import { trackPageView } from '@/lib/analytics'

export default function Layout({ children }: { children: React.ReactNode }) {
  // Điều này chạy trong quá trình prefetch
  trackPageView()

  return <div>{children}</div>
}
```

```jsx filename="app/dashboard/layout.js" switcher
import { trackPageView } from '@/lib/analytics'

export default function Layout({ children }) {
  // Điều này chạy trong quá trình prefetch
  trackPageView()

  return <div>{children}</div>
}
```

**Sau**:

```tsx filename="app/ui/analytics-tracker.tsx" switcher
'use client'

import { useEffect } from 'react'
import { trackPageView } from '@/lib/analytics'

export function AnalyticsTracker() {
  useEffect(() => {
    trackPageView()
  }, [])

  return null
}
```


```tsx filename="app/dashboard/layout.tsx" switcher
  return (
```

### Ngăn chặn quá nhiều prefetches

Next.js tự động prefetches các liên kết trong viewport khi sử dụng component `<Link>`.

Có thể có các trường hợp bạn muốn ngăn chặn điều này để tránh sử dụng tài nguyên không cần thiết, chẳng hạn như khi render một danh sách lớn các liên kết (v.d. một bảng cuộn vô hạn).

Bạn có thể vô hiệu hóa prefetching bằng cách đặt prop `prefetch` của component `<Link>` thành `false`.

```tsx filename="app/ui/no-prefetch-link.tsx" switcher
<Link prefetch={false} href={`/blog/${post.id}`}>
  {post.title}
</Link>
```

Tuy nhiên, điều này có nghĩa là các route tĩnh sẽ chỉ được fetch khi nhấp, và các route động sẽ đợi server render trước khi điều hướng.

Để giảm sử dụng tài nguyên mà không vô hiệu hóa prefetch hoàn toàn, bạn có thể trì hoãn prefetching cho đến khi người dùng di chuột qua một liên kết. Điều này chỉ nhắm mục tiêu các liên kết mà người dùng có khả năng truy cập.
