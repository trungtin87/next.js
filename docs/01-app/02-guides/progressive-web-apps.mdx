Progressive Web Applications (PWAs) cung cấp khả năng tiếp cận và truy cập của các ứng dụng web kết hợp với các tính năng và trải nghiệm người dùng của các ứng dụng di động native. Với Next.js, bạn có thể tạo các PWA cung cấp trải nghiệm liền mạch, giống ứng dụng trên tất cả các nền tảng mà không cần nhiều codebase hoặc phê duyệt app store.

PWAs cho phép bạn:

- Deploy các bản cập nhật ngay lập tức mà không cần chờ phê duyệt app store
- Tạo các ứng dụng đa nền tảng với một codebase duy nhất
- Cung cấp các tính năng giống native như cài đặt màn hình chính và push notifications

## Tạo PWA với Next.js

### 1. Tạo Web App Manifest

Next.js cung cấp hỗ trợ tích hợp sẵn để tạo [web app manifest](/docs/app/api-reference/file-conventions/metadata/manifest) bằng cách sử dụng App Router. Bạn có thể tạo tệp manifest tĩnh hoặc động:

Ví dụ, tạo một tệp `app/manifest.ts` hoặc `app/manifest.json`:

```tsx filename="app/manifest.ts" switcher
import type { MetadataRoute } from 'next'

export default function manifest(): MetadataRoute.Manifest {
  return {
    name: 'Next.js PWA',
    short_name: 'NextPWA',
    description: 'A Progressive Web App built with Next.js',
    start_url: '/',
    display: 'standalone',
    background_color: '#ffffff',
    theme_color: '#000000',
    icons: [
      {
        src: '/icon-192x192.png',
        sizes: '192x192',
        type: 'image/png',
      },
      {
        src: '/icon-512x512.png',
        sizes: '512x512',
        type: 'image/png',
      },
    ],
  }
}
```

Bạn có thể sử dụng các công cụ như [favicon generators](https://realfavicongenerator.net/) để tạo các bộ biểu tượng khác nhau và đặt các tệp được tạo vào thư mục `public/` của bạn.

### 2. Triển khai Web Push Notifications

Web Push Notifications được hỗ trợ trên tất cả các trình duyệt hiện đại, bao gồm:

- iOS 16.4+ cho các ứng dụng được cài đặt vào màn hình chính
- Safari 16 cho macOS 13 trở lên
- Các trình duyệt dựa trên Chromium
- Firefox

Điều này làm cho PWAs trở thành một giải pháp thay thế khả thi cho các ứng dụng native. Đáng chú ý, bạn có thể kích hoạt lời nhắc cài đặt mà không cần hỗ trợ offline.

Web Push Notifications cho phép bạn tái tương tác với người dùng ngay cả khi họ không đang sử dụng ứng dụng của bạn. Đây là cách triển khai chúng trong ứng dụng Next.js:

Đầu tiên, hãy tạo component trang chính trong `app/page.tsx`. Chúng ta sẽ chia nó thành các phần nhỏ hơn để dễ hiểu hơn. Trước tiên, chúng ta sẽ thêm một số imports và utilities mà chúng ta sẽ cần. Không sao nếu các Server Actions được tham chiếu chưa tồn tại:

```tsx switcher
'use client'

import { useState, useEffect } from 'react'
import { subscribeUser, unsubscribeUser, sendNotification } from './actions'

function urlBase64ToUint8Array(base64String: string) {
  const padding = '='.repeat((4 - (base64String.length % 4)) % 4)
  const base64 = (base64String + padding).replace(/-/g, '+').replace(/_/g, '/')

  const rawData = window.atob(base64)
  const outputArray = new Uint8Array(rawData.length)

  for (let i = 0; i < rawData.length; ++i) {
    outputArray[i] = rawData.charCodeAt(i)
  }
  return outputArray
}
```

Bây giờ hãy thêm một component để quản lý việc đăng ký, hủy đăng ký và gửi push notifications.

```tsx switcher
function PushNotificationManager() {
  const [isSupported, setIsSupported] = useState(false)
  const [subscription, setSubscription] = useState<PushSubscription | null>(
    null
  )
  const [message, setMessage] = useState('')

  useEffect(() => {
    if ('serviceWorker' in navigator && 'PushManager' in window) {
      setIsSupported(true)
      registerServiceWorker()
    }
  }, [])

  async function registerServiceWorker() {
    const registration = await navigator.serviceWorker.register('/sw.js', {
      scope: '/',
      updateViaCache: 'none',
    })
    const sub = await registration.pushManager.getSubscription()
    setSubscription(sub)
  }

  async function subscribeToPush() {
    const registration = await navigator.serviceWorker.ready
    const sub = await registration.pushManager.subscribe({
      userVisibleOnly: true,
      applicationServerKey: urlBase64ToUint8Array(
        process.env.NEXT_PUBLIC_VAPID_PUBLIC_KEY!
      ),
    })
    setSubscription(sub)
    const serializedSub = JSON.parse(JSON.stringify(sub))
    await subscribeUser(serializedSub)
  }

  async function unsubscribeFromPush() {
    await subscription?.unsubscribe()
    setSubscription(null)
    await unsubscribeUser()
  }

  async function sendTestNotification() {
    if (subscription) {
      await sendNotification(message)
      setMessage('')
    }
  }

  if (!isSupported) {
    return <p>Push notifications are not supported in this browser.</p>
  }

  return (
    <div>
      <h3>Push Notifications</h3>
      {subscription ? (
        <>
          <p>You are subscribed to push notifications.</p>
          <button onClick={unsubscribeFromPush}>Unsubscribe</button>
          <input
            type="text"
            placeholder="Enter notification message"
            value={message}
            onChange={(e) => setMessage(e.target.value)}
          />
          <button onClick={sendTestNotification}>Send Test</button>
        </>
      ) : (
        <>
          <p>You are not subscribed to push notifications.</p>
          <button onClick={subscribeToPush}>Subscribe</button>
        </>
      )}
    </div>
  )
}
```

### 3. Triển khai Server Actions

Tạo một tệp mới để chứa các actions của bạn tại `app/actions.ts`. Tệp này sẽ xử lý việc tạo subscriptions, xóa subscriptions và gửi notifications.

```tsx filename="app/actions.ts" switcher
'use server'

import webpush from 'web-push'

webpush.setVapidDetails(
  '<mailto:your-email@example.com>',
  process.env.NEXT_PUBLIC_VAPID_PUBLIC_KEY!,
  process.env.VAPID_PRIVATE_KEY!
)

let subscription: PushSubscription | null = null

export async function subscribeUser(sub: PushSubscription) {
  subscription = sub
  // In a production environment, you would want to store the subscription in a database
  // For example: await db.subscriptions.create({ data: sub })
  return { success: true }
}

export async function unsubscribeUser() {
  subscription = null
  // In a production environment, you would want to remove the subscription from the database
  // For example: await db.subscriptions.delete({ where: { ... } })
  return { success: true }
}

export async function sendNotification(message: string) {
  if (!subscription) {
    throw new Error('No subscription available')
  }

  try {
    await webpush.sendNotification(
      subscription,
      JSON.stringify({
        title: 'Test Notification',
        body: message,
        icon: '/icon.png',
      })
    )
    return { success: true }
  } catch (error) {
    console.error('Error sending push notification:', error)
    return { success: false, error: 'Failed to send notification' }
  }
}
```

### 4. Tạo VAPID Keys

Để sử dụng Web Push API, bạn cần tạo các khóa [VAPID](https://vapidkeys.com/). Cách đơn giản nhất là sử dụng trực tiếp web-push CLI:

Đầu tiên, cài đặt web-push globally:

```bash filename="Terminal"
npm install -g web-push
```

Tạo các khóa VAPID bằng cách chạy:

```bash filename="Terminal"
web-push generate-vapid-keys
```

Sao chép đầu ra và dán các khóa vào tệp `.env` của bạn:

```
NEXT_PUBLIC_VAPID_PUBLIC_KEY=your_public_key_here
VAPID_PRIVATE_KEY=your_private_key_here
```

### 5. Tạo Service Worker

Tạo một tệp `public/sw.js` cho service worker của bạn:

```js filename="public/sw.js"
self.addEventListener('push', function (event) {
  if (event.data) {
    const data = event.data.json()
    const options = {
      body: data.body,
      icon: data.icon || '/icon.png',
      badge: '/badge.png',
      vibrate: [100, 50, 100],
      data: {
        dateOfArrival: Date.now(),
        primaryKey: '2',
      },
    }
    event.waitUntil(self.registration.showNotification(data.title, options))
  }
})

self.addEventListener('notificationclick', function (event) {
  console.log('Notification click received.')
  event.notification.close()
  event.waitUntil(clients.openWindow('<https://your-website.com>'))
})
```

Service worker này hỗ trợ hình ảnh và notifications tùy chỉnh. Nó xử lý các sự kiện push đến và các lần nhấp vào notification.

- Bạn có thể đặt các biểu tượng tùy chỉnh cho notifications bằng cách sử dụng các thuộc tính `icon` và `badge`.
- Mẫu `vibrate` có thể được điều chỉnh để tạo cảnh báo rung tùy chỉnh trên các thiết bị được hỗ trợ.
- Dữ liệu bổ sung có thể được đính kèm vào notification bằng cách sử dụng thuộc tính `data`.

Hãy nhớ kiểm tra kỹ lưỡng service worker của bạn để đảm bảo nó hoạt động như mong đợi trên các thiết bị và trình duyệt khác nhau. Ngoài ra, hãy đảm bảo cập nhật liên kết `'https://your-website.com'` trong event listener `notificationclick` thành URL phù hợp cho ứng dụng của bạn.

### 6. Thêm vào Màn hình Chính

Component `InstallPrompt` được định nghĩa ở bước 2 hiển thị thông báo cho các thiết bị iOS hướng dẫn họ cài đặt vào màn hình chính.

Để đảm bảo ứng dụng của bạn có thể được cài đặt vào màn hình chính di động, bạn phải có:

1. Một web app manifest hợp lệ (được tạo ở bước 1)
2. Website được phục vụ qua HTTPS

Các trình duyệt hiện đại sẽ tự động hiển thị lời nhắc cài đặt cho người dùng khi các tiêu chí này được đáp ứng. Bạn có thể cung cấp nút cài đặt tùy chỉnh với [`beforeinstallprompt`](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event), tuy nhiên, chúng tôi không khuyến nghị điều này vì nó không hoạt động trên nhiều trình duyệt và nền tảng (không hoạt động trên Safari iOS).

### 7. Kiểm tra Cục bộ

Để đảm bảo bạn có thể xem notifications cục bộ, hãy đảm bảo rằng:

- Bạn đang [chạy cục bộ với HTTPS](/docs/app/api-reference/cli/next#using-https-during-development)
  - Sử dụng `next dev --experimental-https` để kiểm tra
- Trình duyệt của bạn (Chrome, Safari, Firefox) đã bật notifications
  - Khi được nhắc cục bộ, chấp nhận quyền sử dụng notifications
  - Đảm bảo notifications không bị tắt toàn cục cho toàn bộ trình duyệt
  - Nếu bạn vẫn không thấy notifications, hãy thử sử dụng trình duyệt khác để debug

### 8. Bảo mật ứng dụng của bạn

Bảo mật là một khía cạnh quan trọng của bất kỳ ứng dụng web nào, đặc biệt là đối với PWAs. Next.js cho phép bạn cấu hình các security headers bằng cách sử dụng tệp `next.config.js`. Ví dụ:

```js filename="next.config.js"
module.exports = {
  async headers() {
    return [
      {
        source: '/(.*)',
        headers: [
          {
            key: 'X-Content-Type-Options',
            value: 'nosniff',
          },
          {
            key: 'X-Frame-Options',
            value: 'DENY',
          },
          {
            key: 'Referrer-Policy',
            value: 'strict-origin-when-cross-origin',
          },
        ],
      },
      {
        source: '/sw.js',
        headers: [
          {
            key: 'Content-Type',
            value: 'application/javascript; charset=utf-8',
          },
          {
            key: 'Cache-Control',
            value: 'no-cache, no-store, must-revalidate',
          },
          {
            key: 'Content-Security-Policy',
            value: "default-src 'self'; script-src 'self'",
          },
        ],
      },
    ]
  },
}
```

Hãy xem qua từng tùy chọn này:

1. Global Headers (áp dụng cho tất cả các routes):
   1. `X-Content-Type-Options: nosniff`: Ngăn chặn MIME type sniffing, giảm nguy cơ tải lên tệp độc hại.
   2. `X-Frame-Options: DENY`: Bảo vệ chống lại các cuộc tấn công clickjacking bằng cách ngăn trang web của bạn bị nhúng trong iframes.
   3. `Referrer-Policy: strict-origin-when-cross-origin`: Kiểm soát lượng thông tin referrer được bao gồm trong các yêu cầu, cân bằng giữa bảo mật và chức năng.
2. Service Worker Specific Headers:
   1. `Content-Type: application/javascript; charset=utf-8`: Đảm bảo service worker được hiểu đúng là JavaScript.
   2. `Cache-Control: no-cache, no-store, must-revalidate`: Ngăn caching của service worker, đảm bảo người dùng luôn nhận được phiên bản mới nhất.
   3. `Content-Security-Policy: default-src 'self'; script-src 'self'`: Triển khai Content Security Policy nghiêm ngặt cho service worker, chỉ cho phép các scripts từ cùng origin.

Tìm hiểu thêm về việc định nghĩa [Content Security Policies](/docs/app/guides/content-security-policy) với Next.js.

## Mở rộng PWA của bạn

1. **Khám phá Khả năng PWA**: PWAs có thể tận dụng các web APIs khác nhau để cung cấp chức năng nâng cao. Hãy xem xét khám phá các tính năng như background sync, periodic background sync, hoặc File System Access API để nâng cao ứng dụng của bạn. Để lấy cảm hứng và thông tin cập nhật về khả năng PWA, bạn có thể tham khảo các tài nguyên như [What PWA Can Do Today](https://whatpwacando.today/).
2. **Static Exports:** Nếu ứng dụng của bạn yêu cầu không chạy server, và thay vào đó sử dụng static export của các tệp, bạn có thể cập nhật cấu hình Next.js để bật thay đổi này. Tìm hiểu thêm trong [tài liệu Next.js Static Export](/docs/app/guides/static-exports). Tuy nhiên, bạn sẽ cần chuyển từ Server Actions sang gọi một API bên ngoài, cũng như di chuyển các headers đã định nghĩa của bạn sang proxy của bạn.
3. **Hỗ trợ Offline**: Để cung cấp chức năng offline, một tùy chọn là [Serwist](https://github.com/serwist/serwist) với Next.js. Bạn có thể tìm thấy ví dụ về cách tích hợp Serwist với Next.js trong [tài liệu](https://github.com/serwist/serwist/tree/main/examples/next-basic) của họ. **Lưu ý:** plugin này hiện yêu cầu cấu hình webpack.
4. **Cân nhắc Bảo mật**: Đảm bảo rằng service worker của bạn được bảo mật đúng cách. Điều này bao gồm sử dụng HTTPS, xác thực nguồn của push messages, và triển khai xử lý lỗi phù hợp.
5. **Trải nghiệm Người dùng**: Hãy xem xét triển khai các kỹ thuật progressive enhancement để đảm bảo ứng dụng của bạn hoạt động tốt ngay cả khi một số tính năng PWA không được hỗ trợ bởi trình duyệt của người dùng.
