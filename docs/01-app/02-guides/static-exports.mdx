Next.js cho phép bắt đầu như một trang web tĩnh hoặc Ứng dụng Trang đơn (SPA), sau đó có thể tùy chọn nâng cấp để sử dụng các tính năng yêu cầu máy chủ.

Khi chạy `next build`, Next.js tạo một tệp HTML cho mỗi tuyến đường. Bằng cách chia một SPA nghiêm ngặt thành các tệp HTML riêng lẻ, Next.js có thể tránh tải mã JavaScript không cần thiết ở phía máy khách, giảm kích thước gói và cho phép tải trang nhanh hơn.

Vì Next.js hỗ trợ xuất tĩnh này, nó có thể được triển khai và lưu trữ trên bất kỳ máy chủ web nào có thể phục vụ các tài sản tĩnh HTML/CSS/JS.

## Cấu hình

Để bật xuất tĩnh, hãy thay đổi chế độ đầu ra bên trong `next.config.js`:

```js filename="next.config.js" highlight={5}
/**
 * @type {import('next').NextConfig}
 */
const nextConfig = {
  output: 'export',

  // Tùy chọn: Thay đổi liên kết `/me` -> `/me/` và phát ra `/me.html` -> `/me/index.html`
  // trailingSlash: true,

  // Tùy chọn: Ngăn tự động `/me` -> `/me/`, thay vào đó giữ nguyên `href`
  // skipTrailingSlashRedirect: true,

  // Tùy chọn: Thay đổi thư mục đầu ra `out` -> `dist`
  // distDir: 'dist',
}

module.exports = nextConfig
```

Sau khi chạy `next build`, Next.js sẽ tạo một thư mục `out` với các tài sản HTML/CSS/JS cho ứng dụng của bạn.

Bạn có thể sử dụng [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) và [`getStaticPaths`](/docs/pages/building-your-application/data-fetching/get-static-paths) để tạo một tệp HTML cho mỗi trang trong thư mục `pages` của bạn (hoặc nhiều hơn cho [các tuyến đường động](/docs/app/api-reference/file-conventions/dynamic-routes)).

## Các tính năng được hỗ trợ

Cốt lõi của Next.js đã được thiết kế để hỗ trợ xuất tĩnh.

### Thành phần máy chủ

Khi bạn chạy `next build` để tạo một bản xuất tĩnh, các Thành phần máy chủ được sử dụng bên trong thư mục `app` sẽ chạy trong quá trình xây dựng, tương tự như việc tạo trang web tĩnh truyền thống.

Thành phần kết quả sẽ được hiển thị thành HTML tĩnh cho lần tải trang ban đầu và một tải trọng tĩnh để điều hướng máy khách giữa các tuyến đường. Không có thay đổi nào được yêu cầu đối với các Thành phần máy chủ của bạn khi sử dụng xuất tĩnh, trừ khi chúng sử dụng [các hàm máy chủ động](#unsupported-features).

```tsx filename="app/page.tsx" switcher
export default async function Page() {
  // Lệnh tìm nạp này sẽ chạy trên máy chủ trong `next build`
  const res = await fetch('https://api.example.com/...')
  const data = await res.json()

  return <main>...</main>
}
```

### Thành phần máy khách

Nếu bạn muốn thực hiện tìm nạp dữ liệu trên máy khách, bạn có thể sử dụng Thành phần máy khách với [SWR](https://github.com/vercel/swr) để ghi nhớ các yêu cầu.

```tsx filename="app/other/page.tsx" switcher
'use client'

import useSWR from 'swr'

const fetcher = (url: string) => fetch(url).then((r) => r.json())

export default function Page() {
  const { data, error } = useSWR(
    `https://jsonplaceholder.typicode.com/posts/1`,
    fetcher
  )
  if (error) return 'Không thể tải'
  if (!data) return 'Đang tải...'

  return data.title
}
```

```jsx filename="app/other/page.js" switcher
'use client'

import useSWR from 'swr'

const fetcher = (url) => fetch(url).then((r) => r.json())

export default function Page() {
  const { data, error } = useSWR(
    `https://jsonplaceholder.typicode.com/posts/1`,
    fetcher
  )
  if (error) return 'Không thể tải'
  if (!data) return 'Đang tải...'

  return data.title
}
```

Vì các chuyển đổi tuyến đường xảy ra ở phía máy khách, điều này hoạt động giống như một SPA truyền thống. Ví dụ, tuyến đường chỉ mục sau đây cho phép bạn điều hướng đến các bài đăng khác nhau trên máy khách:

```tsx filename="app/page.tsx" switcher
import Link from 'next/link'

export default function Page() {
  return (
    <>
      <h1>Trang chỉ mục</h1>
      <hr />
      <ul>
        <li>
          <Link href="/post/1">Bài đăng 1</Link>
        </li>
        <li>
          <Link href="/post/2">Bài đăng 2</Link>
        </li>
      </ul>
    </>
  )
}
```

```jsx filename="app/page.js" switcher
import Link from 'next/link'

export default function Page() {
  return (
    <>
      <h1>Trang chỉ mục</h1>
      <p>
        <Link href="/other">Trang khác</Link>
      </p>
    </>
  )
}
```

### Tối ưu hóa hình ảnh

[Tối ưu hóa hình ảnh](/docs/app/api-reference/components/image) thông qua `next/image` có thể được sử dụng với một bản xuất tĩnh bằng cách xác định một trình tải hình ảnh tùy chỉnh trong `next.config.js`. Ví dụ, bạn có thể tối ưu hóa hình ảnh với một dịch vụ như Cloudinary:

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: 'export',
  images: {
    loader: 'custom',
    loaderFile: './my-loader.ts',
  },
}

module.exports = nextConfig
```

Trình tải tùy chỉnh này sẽ xác định cách tìm nạp hình ảnh từ một nguồn từ xa. Ví dụ, trình tải sau đây sẽ xây dựng URL cho Cloudinary:

```ts filename="my-loader.ts" switcher
export default function cloudinaryLoader({
  src,
  width,
  quality,
}: {
  src: string
  width: number
  quality?: number
}) {
  const params = ['f_auto', 'c_limit', `w_${width}`, `q_${quality || 'auto'}`]
  return `https://res.cloudinary.com/demo/image/upload/${params.join(
    ','
  )}${src}`
}
```

```js filename="my-loader.js" switcher
export default function cloudinaryLoader({ src, width, quality }) {
  const params = ['f_auto', 'c_limit', `w_${width}`, `q_${quality || 'auto'}`]
  return `https://res.cloudinary.com/demo/image/upload/${params.join(
    ','
  )}${src}`
}
```

Sau đó, bạn có thể sử dụng `next/image` trong ứng dụng của mình, xác định các đường dẫn tương đối đến hình ảnh trong Cloudinary:

```tsx filename="app/page.tsx" switcher
import Image from 'next/image'

export default function Page() {
  return <Image alt="turtles" src="/turtles.jpg" width={300} height={300} />
}
```

```jsx filename="app/page.js" switcher
import Image from 'next/image'

export default function Page() {
  return <Image alt="turtles" src="/turtles.jpg" width={300} height={300} />
}
```

### Trình xử lý tuyến đường

Trình xử lý tuyến đường sẽ hiển thị một phản hồi tĩnh khi chạy `next build`. Chỉ hỗ trợ động từ HTTP `GET`. Điều này có thể được sử dụng để tạo các tệp HTML, JSON, TXT hoặc các tệp khác tĩnh từ dữ liệu được lưu trong bộ nhớ cache hoặc không được lưu trong bộ nhớ cache. Ví dụ:

```ts filename="app/data.json/route.ts" switcher
export async function GET() {
  return Response.json({ name: 'Lee' })
}
```

```js filename="app/data.json/route.js" switcher
export async function GET() {
  return Response.json({ name: 'Lee' })
}
```

Tệp `app/data.json/route.ts` ở trên sẽ hiển thị thành một tệp tĩnh trong `next build`, tạo ra `data.json` chứa `{ name: 'Lee' }`.

Nếu bạn cần đọc các giá trị động từ yêu cầu đến, bạn không thể sử dụng một bản xuất tĩnh.

### API trình duyệt

Các thành phần máy khách được hiển thị trước thành HTML trong `next build`. Vì [API Web](https://developer.mozilla.org/docs/Web/API) như `window`, `localStorage` và `navigator` không có sẵn trên máy chủ, bạn cần truy cập các API này một cách an toàn chỉ khi chạy trong trình duyệt. Ví dụ:

```jsx
'use client';

import { useEffect } from 'react';

export default function ClientComponent() {
  useEffect(() => {
    // Bây giờ bạn có quyền truy cập vào `window`
    console.log(window.innerHeight);
  }, [])

  return ...;
}
```

## Triển khai

Với một bản xuất tĩnh, Next.js có thể được triển khai và lưu trữ trên bất kỳ máy chủ web nào có thể phục vụ các tài sản tĩnh HTML/CSS/JS.

Khi chạy `next build`, Next.js tạo ra bản xuất tĩnh vào thư mục `out`. Ví dụ, giả sử bạn có các tuyến đường sau:

- `/`
- `/blog/[id]`

Sau khi chạy `next build`, Next.js sẽ tạo các tệp sau:

- `/out/index.html`
- `/out/404.html`
- `/out/blog/post-1.html`
- `/out/blog/post-2.html`

Nếu bạn đang sử dụng một máy chủ tĩnh như Nginx, bạn có thể định cấu hình ghi lại từ các yêu cầu đến các tệp chính xác:

```nginx filename="nginx.conf"
server {
  listen 80;
  server_name acme.com;

  root /var/www/out;

  location / {
      try_files $uri $uri.html $uri/ =404;
  }

  # Điều này là cần thiết khi `trailingSlash: false`.
  # Bạn có thể bỏ qua điều này khi `trailingSlash: true`.
  location /blog/ {
      rewrite ^/blog/(.*)$ /blog/$1.html break;
  }

  error_page 404 /404.html;
  location = /404.html {
      internal;
  }
}
```
