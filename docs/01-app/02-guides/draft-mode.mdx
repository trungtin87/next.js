**Draft Mode** cho phép bạn xem trước nội dung bản nháp từ headless CMS trong ứng dụng Next.js của bạn. Điều này hữu ích cho các trang tĩnh được tạo tại thời điểm build vì nó cho phép bạn chuyển sang [render động](/docs/app/guides/caching#dynamic-rendering) và xem các thay đổi bản nháp mà không cần phải build lại toàn bộ trang web của bạn.

Trang này hướng dẫn cách kích hoạt và sử dụng Draft Mode.

## Bước 1: Tạo một Route Handler

Tạo một [Route Handler](/docs/app/api-reference/file-conventions/route). Nó có thể có bất kỳ tên nào, ví dụ, `app/api/draft/route.ts`.

```ts filename="app/api/draft/route.ts" switcher
export async function GET(request: Request) {
  return new Response('')
}
```

```js filename="app/api/draft/route.js" switcher
export async function GET() {
  return new Response('')
}
```

Sau đó, import hàm [`draftMode`](/docs/app/api-reference/functions/draft-mode) và gọi phương thức `enable()`.

```ts filename="app/api/draft/route.ts" switcher
import { draftMode } from 'next/headers'

export async function GET(request: Request) {
  const draft = await draftMode()
  draft.enable()
  return new Response('Draft mode is enabled')
}
```

```js filename="app/api/draft/route.js" switcher
import { draftMode } from 'next/headers'

export async function GET(request) {
  const draft = await draftMode()
  draft.enable()
  return new Response('Draft mode is enabled')
}
```

Điều này sẽ đặt một **cookie** để kích hoạt draft mode. Các yêu cầu tiếp theo chứa cookie này sẽ kích hoạt draft mode và thay đổi hành vi của các trang được tạo tĩnh.

Bạn có thể kiểm tra điều này thủ công bằng cách truy cập `/api/draft` và xem các công cụ dành cho nhà phát triển của trình duyệt. Chú ý header phản hồi `Set-Cookie` với một cookie có tên `__prerender_bypass`.

## Bước 2: Truy cập Route Handler từ Headless CMS của bạn

> Các bước này giả định rằng headless CMS bạn đang sử dụng hỗ trợ đặt **URL bản nháp tùy chỉnh**. Nếu không, bạn vẫn có thể sử dụng phương pháp này để bảo mật các URL bản nháp của mình, nhưng bạn sẽ cần phải xây dựng và truy cập URL bản nháp theo cách thủ công. Các bước cụ thể sẽ khác nhau tùy thuộc vào headless CMS bạn đang sử dụng.

Để truy cập an toàn Route Handler từ headless CMS của bạn:

1. Tạo một **chuỗi token bí mật** bằng cách sử dụng trình tạo token bạn chọn. Bí mật này sẽ chỉ được biết bởi ứng dụng Next.js và headless CMS của bạn.
2. Nếu headless CMS của bạn hỗ trợ đặt URL bản nháp tùy chỉnh, hãy chỉ định URL bản nháp (điều này giả định rằng Route Handler của bạn nằm tại `app/api/draft/route.ts`). Ví dụ:

```bash filename="Terminal"
https://<your-site>/api/draft?secret=<token>&slug=<path>
```

> - `<your-site>` nên là miền triển khai của bạn.
> - `<token>` nên được thay thế bằng token bí mật bạn đã tạo.
> - `<path>` nên là đường dẫn cho trang mà bạn muốn xem. Nếu bạn muốn xem `/posts/one`, thì bạn nên sử dụng `&slug=/posts/one`.
>
> Headless CMS của bạn có thể cho phép bạn bao gồm một biến trong URL bản nháp để `<path>` có thể được đặt động dựa trên dữ liệu của CMS như sau: `&slug=/posts/{entry.fields.slug}`

3. Trong Route Handler của bạn, kiểm tra xem bí mật có khớp không và tham số `slug` có tồn tại không (nếu không, yêu cầu sẽ thất bại), gọi `draftMode.enable()` để đặt cookie. Sau đó, chuyển hướng trình duyệt đến đường dẫn được chỉ định bởi `slug`:

```ts filename="app/api/draft/route.ts" switcher
import { draftMode } from 'next/headers'
import { redirect } from 'next/navigation'

export async function GET(request: Request) {
  // Phân tích các tham số chuỗi truy vấn
  const { searchParams } = new URL(request.url)
  const secret = searchParams.get('secret')
  const slug = searchParams.get('slug')

  // Kiểm tra bí mật và các tham số tiếp theo
  // Bí mật này chỉ nên được biết bởi Route Handler này và CMS
  if (secret !== 'MY_SECRET_TOKEN' || !slug) {
    return new Response('Invalid token', { status: 401 })
  }

  // Fetch headless CMS để kiểm tra xem `slug` được cung cấp có tồn tại không
  // getPostBySlug sẽ thực hiện logic fetching cần thiết đến headless CMS
  const post = await getPostBySlug(slug)

  // Nếu slug không tồn tại, ngăn chặn draft mode được kích hoạt
  if (!post) {
    return new Response('Invalid slug', { status: 401 })
  }

  // Kích hoạt Draft Mode bằng cách đặt cookie
  const draft = await draftMode()
  draft.enable()

  // Chuyển hướng đến đường dẫn từ bài đăng đã fetch
  // Chúng tôi không chuyển hướng đến searchParams.slug vì điều đó có thể dẫn đến các lỗ hổng chuyển hướng mở
  redirect(post.slug)
}
```


Nếu thành công, trình duyệt sẽ được chuyển hướng đến đường dẫn bạn muốn xem với cookie draft mode.

## Bước 3: Xem trước Nội dung Bản nháp

Bước tiếp theo là cập nhật trang của bạn để kiểm tra giá trị của `draftMode().isEnabled`.

Nếu bạn yêu cầu một trang có cookie được đặt, thì dữ liệu sẽ được fetch tại **thời gian yêu cầu** (thay vì tại thời điểm build).

Hơn nữa, giá trị của `isEnabled` sẽ là `true`.

```tsx filename="app/page.tsx" switcher
// trang fetch dữ liệu
import { draftMode } from 'next/headers'

async function getData() {
  const { isEnabled } = await draftMode()

  const url = isEnabled
    ? 'https://draft.example.com'
    : 'https://production.example.com'

  const res = await fetch(url)

  return res.json()
}

export default async function Page() {
  const { title, desc } = await getData()

  return (
    <main>
      <h1>{title}</h1>
      <p>{desc}</p>
    </main>
  )
}
```

Nếu bạn truy cập draft Route Handler (với `secret` và `slug`) từ headless CMS của bạn hoặc thủ công bằng cách sử dụng URL, bây giờ bạn sẽ có thể xem nội dung bản nháp. Và, nếu bạn cập nhật bản nháp của mình mà không xuất bản, bạn sẽ có thể xem bản nháp.
