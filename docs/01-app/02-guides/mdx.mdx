[Markdown](https://daringfireball.net/projects/markdown/syntax) là một ngôn ngữ đánh dấu nhẹ được sử dụng để định dạng văn bản. Nó cho phép bạn viết bằng cú pháp văn bản thuần túy và chuyển đổi nó thành HTML hợp lệ về mặt cấu trúc. Nó thường được sử dụng để viết nội dung trên các trang web và blog.

Bạn viết...

```md
I **love** using [Next.js](https://nextjs.org/)
```

Kết quả:

```html
<p>I <strong>love</strong> using <a href="https://nextjs.org/">Next.js</a></p>
```

[MDX](https://mdxjs.com/) là một tập hợp siêu của markdown cho phép bạn viết [JSX](https://react.dev/learn/writing-markup-with-jsx) trực tiếp trong các tệp markdown của mình. Đây là một cách mạnh mẽ để thêm tính tương tác động và nhúng các React component vào nội dung của bạn.

Next.js có thể hỗ trợ cả nội dung MDX cục bộ bên trong ứng dụng của bạn, cũng như các tệp MDX từ xa được fetch động trên server. Plugin Next.js xử lý việc chuyển đổi markdown và React components thành HTML, bao gồm hỗ trợ sử dụng trong Server Components (mặc định trong App Router).

> **Cần biết**: Xem template [Portfolio Starter Kit](https://vercel.com/templates/next.js/portfolio-starter-kit) để có một ví dụ hoạt động hoàn chỉnh.

## Cài đặt dependencies

Gói `@next/mdx`, và các gói liên quan, được sử dụng để cấu hình Next.js để nó có thể xử lý markdown và MDX. **Nó lấy dữ liệu từ các tệp cục bộ**, cho phép bạn tạo các trang với phần mở rộng `.md` hoặc `.mdx`, trực tiếp trong thư mục `/pages` hoặc `/app` của bạn.

Cài đặt các gói này để render MDX với Next.js:

```bash filename="Terminal"
npm install @next/mdx @mdx-js/loader @mdx-js/react @types/mdx
```

## Cấu hình `next.config.mjs`

Cập nhật tệp `next.config.mjs` tại thư mục gốc của dự án của bạn để cấu hình nó sử dụng MDX:

```js filename="next.config.mjs"
import createMDX from '@next/mdx'

/** @type {import('next').NextConfig} */
const nextConfig = {
  // Cấu hình `pageExtensions` để bao gồm các tệp markdown và MDX
  pageExtensions: ['js', 'jsx', 'md', 'mdx', 'ts', 'tsx'],
  // Tùy chọn, thêm bất kỳ cấu hình Next.js nào khác bên dưới
}

const withMDX = createMDX({
  // Thêm các markdown plugins ở đây, nếu muốn
})

// Hợp nhất cấu hình MDX với cấu hình Next.js
export default withMDX(nextConfig)
```

Điều này cho phép các tệp `.mdx` hoạt động như các trang, routes, hoặc imports trong ứng dụng của bạn.

### Xử lý các tệp `.md`

Theo mặc định, `next/mdx` chỉ biên dịch các tệp có phần mở rộng `.mdx`. Để xử lý các tệp `.md` với webpack, hãy cập nhật tùy chọn `extension`:

```js filename="next.config.mjs"
const withMDX = createMDX({
  extension: /\.(md|mdx)$/,
})
```

## Thêm tệp `mdx-components.tsx`

Tạo một tệp `mdx-components.tsx` (hoặc `.js`) trong thư mục gốc của dự án của bạn để định nghĩa các MDX Components toàn cục. Ví dụ, ở cùng cấp với `pages` hoặc `app`, hoặc bên trong `src` nếu có.

```tsx filename="mdx-components.tsx" switcher
import type { MDXComponents } from 'mdx/types'

const components: MDXComponents = {}

export function useMDXComponents(): MDXComponents {
  return components
}
```

```js filename="mdx-components.js" switcher
const components = {}

export function useMDXComponents() {
  return components
}
```

> **Cần biết**:
>
> - `mdx-components.tsx` là **bắt buộc** để sử dụng `@next/mdx` với App Router và sẽ không hoạt động nếu thiếu nó.
> - Tìm hiểu thêm về [quy ước tệp `mdx-components.tsx`](/docs/app/api-reference/file-conventions/mdx-components).
> - Tìm hiểu cách [sử dụng style và component tùy chỉnh](#using-custom-styles-and-components).

## Render MDX

Bạn có thể render MDX bằng cách sử dụng file based routing của Next.js hoặc bằng cách import các tệp MDX vào các trang khác.

### Sử dụng file based routing

Khi sử dụng file based routing, bạn có thể sử dụng các trang MDX giống như bất kỳ trang nào khác.

<AppOnly>

Trong các ứng dụng App Router, điều đó bao gồm khả năng sử dụng [metadata](/docs/app/getting-started/metadata-and-og-images).

Tạo một trang MDX mới trong thư mục `/app`:

```txt
  my-project
  ├── app
  │   └── mdx-page
  │       └── page.(mdx/md)
  |── mdx-components.(tsx/js)
  └── package.json
```

</AppOnly>

<PagesOnly>

Tạo một trang MDX mới trong thư mục `/pages`:

```txt
  my-project
  |── mdx-components.(tsx/js)
  ├── pages
  │   └── mdx-page.(mdx/md)
  └── package.json
```

</PagesOnly>

Bạn có thể sử dụng MDX trong các tệp này, và thậm chí import các React component, trực tiếp bên trong trang MDX của bạn:

```mdx
import { MyComponent } from 'my-component'

# Welcome to my MDX page!

This is some **bold** and _italics_ text.

This is a list in markdown:

- One
- Two
- Three

Checkout my React component:

<MyComponent />
```

Điều hướng đến route `/mdx-page` sẽ hiển thị trang MDX đã render của bạn.

### Sử dụng dynamic imports

Bạn có thể import các MDX component động thay vì sử dụng filesystem routing cho các tệp MDX.

Ví dụ, bạn có thể có một phân đoạn route động tải các MDX component từ một thư mục riêng biệt:

<Image
  alt="Route segments for dynamic MDX components"
  srcLight="/docs/light/mdx-files.png"
  srcDark="/docs/dark/mdx-files.png"
  width="1600"
  height="849"
/>

[`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params) có thể được sử dụng để prerender các route được cung cấp. Bằng cách đánh dấu `dynamicParams` là `false`, việc truy cập một route không được định nghĩa trong `generateStaticParams` sẽ trả về 404.

```tsx filename="app/blog/[slug]/page.tsx" switcher
export default async function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const { default: Post } = await import(`@/content/${slug}.mdx`)

  return <Post />
}

export function generateStaticParams() {
  return [{ slug: 'welcome' }, { slug: 'about' }]
}

export const dynamicParams = false
```

```jsx filename="app/blog/[slug]/page.js" switcher
export default async function Page({ params }) {
  const { slug } = await params
  const { default: Post } = await import(`@/content/${slug}.mdx`)

  return <Post />
}

export function generateStaticParams() {
  return [{ slug: 'welcome' }, { slug: 'about' }]
}

export const dynamicParams = false
```

> **Cần biết**: Đảm bảo bạn chỉ định phần mở rộng tệp `.mdx` trong import của mình. Mặc dù không bắt buộc phải sử dụng [module path aliases](/docs/app/getting-started/installation#set-up-absolute-imports-and-module-path-aliases) (v.d., `@/content`), nhưng nó giúp đơn giản hóa đường dẫn import của bạn.

## Sử dụng style và component tùy chỉnh

Markdown, khi được render, ánh xạ tới các phần tử HTML gốc. Ví dụ, viết markdown sau:

```md
## This is a heading

This is a list in markdown:

- One
- Two
- Three
```

Tạo ra HTML sau:

```html
<h2>This is a heading</h2>

<p>This is a list in markdown:</p>

<ul>
  <li>One</li>
  <li>Two</li>
  <li>Three</li>
</ul>
```

Để style cho markdown của bạn, bạn có thể cung cấp các component tùy chỉnh ánh xạ tới các phần tử HTML được tạo ra. Style và component có thể được triển khai toàn cục, cục bộ, và với các layout được chia sẻ.

### Style và component toàn cục

Thêm style và component trong `mdx-components.tsx` sẽ ảnh hưởng đến _tất cả_ các tệp MDX trong ứng dụng của bạn.

```tsx filename="mdx-components.tsx" switcher
import type { MDXComponents } from 'mdx/types'
import Image, { ImageProps } from 'next/image'

// Tệp này cho phép bạn cung cấp các React component tùy chỉnh
// để sử dụng trong các tệp MDX. Bạn có thể import và sử dụng bất kỳ
// React component nào bạn muốn, bao gồm inline styles,
// component từ các thư viện khác, và hơn thế nữa.

const components = {
  // Cho phép tùy chỉnh các component tích hợp sẵn, v.d. để thêm styling.
  h1: ({ children }) => (
    <h1 style={{ color: 'red', fontSize: '48px' }}>{children}</h1>
  ),
  img: (props) => (
    <Image
      sizes="100vw"
      style={{ width: '100%', height: 'auto' }}
      {...(props as ImageProps)}
    />
  ),
} satisfies MDXComponents

export function useMDXComponents(): MDXComponents {
  return components
}
```

```js filename="mdx-components.js" switcher
import Image from 'next/image'

// Tệp này cho phép bạn cung cấp các React component tùy chỉnh
// để sử dụng trong các tệp MDX. Bạn có thể import và sử dụng bất kỳ
// React component nào bạn muốn, bao gồm inline styles,
// component từ các thư viện khác, và hơn thế nữa.

const components = {
  // Cho phép tùy chỉnh các component tích hợp sẵn, v.d. để thêm styling.
  h1: ({ children }) => (
    <h1 style={{ color: 'red', fontSize: '48px' }}>{children}</h1>
  ),
  img: (props) => (
    <Image sizes="100vw" style={{ width: '100%', height: 'auto' }} {...props} />
  ),
}

export function useMDXComponents() {
  return components
}
```

### Style và component cục bộ

Bạn có thể áp dụng style và component cục bộ cho các trang cụ thể bằng cách truyền chúng vào các MDX component đã import. Những cái này sẽ hợp nhất với và ghi đè [style và component toàn cục](#global-styles-and-components).

<AppOnly>

```tsx filename="app/mdx-page/page.tsx" switcher
import Welcome from '@/markdown/welcome.mdx'

function CustomH1({ children }) {
  return <h1 style={{ color: 'blue', fontSize: '100px' }}>{children}</h1>
}

const overrideComponents = {
  h1: CustomH1,
}

export default function Page() {
  return <Welcome components={overrideComponents} />
}
```

### Sử dụng Tailwind typography plugin

Nếu bạn đang sử dụng [Tailwind](https://tailwindcss.com) để style cho ứng dụng của mình, việc sử dụng [`@tailwindcss/typography` plugin](https://tailwindcss.com/docs/plugins#typography) sẽ cho phép bạn tái sử dụng cấu hình Tailwind và style của mình trong các tệp markdown.

Plugin thêm một tập hợp các class `prose` có thể được sử dụng để thêm các style typography vào các khối nội dung đến từ các nguồn, như markdown.

## Frontmatter

Frontmatter là một cặp key/value giống như YAML có thể được sử dụng để lưu trữ dữ liệu về một trang. `@next/mdx` **không** hỗ trợ frontmatter theo mặc định, mặc dù có nhiều giải pháp để thêm frontmatter vào nội dung MDX của bạn, chẳng hạn như:

- [remark-frontmatter](https://github.com/remarkjs/remark-frontmatter)
- [remark-mdx-frontmatter](https://github.com/remcohaszing/remark-mdx-frontmatter)
- [gray-matter](https://github.com/jonschlinkert/gray-matter)

`@next/mdx` **cho phép** bạn sử dụng các export giống như bất kỳ JavaScript component nào khác:

```mdx filename="content/blog-post.mdx" switcher
export const metadata = {
  author: 'John Doe',
}

# Blog post
```

Metadata bây giờ có thể được tham chiếu bên ngoài tệp MDX:

<AppOnly>

## remark và rehype Plugins

Bạn có thể tùy chọn cung cấp các plugin remark và rehype để chuyển đổi nội dung MDX.

Ví dụ, bạn có thể sử dụng [`remark-gfm`](https://github.com/remarkjs/remark-gfm) để hỗ trợ GitHub Flavored Markdown.

Vì hệ sinh thái remark và rehype chỉ là ESM, bạn sẽ cần sử dụng `next.config.mjs` hoặc `next.config.ts` làm tệp cấu hình.

```js filename="next.config.mjs"
import remarkGfm from 'remark-gfm'
import createMDX from '@next/mdx'

/** @type {import('next').NextConfig} */
const nextConfig = {
  // Cho phép phần mở rộng .mdx cho các tệp
  pageExtensions: ['js', 'jsx', 'md', 'mdx', 'ts', 'tsx'],
  // Tùy chọn, thêm bất kỳ cấu hình Next.js nào khác bên dưới
}

const withMDX = createMDX({
  // Thêm các markdown plugins ở đây, nếu muốn
  options: {
    remarkPlugins: [remarkGfm],
    rehypePlugins: [],
  },
})

// Kết hợp cấu hình MDX và Next.js
export default withMDX(nextConfig)
```

### Sử dụng Plugins với Turbopack

Để sử dụng các plugin với [Turbopack](/docs/app/api-reference/turbopack), hãy nâng cấp lên `@next/mdx` mới nhất và chỉ định tên plugin bằng một chuỗi:

```js filename="next.config.mjs"
import createMDX from '@next/mdx'

/** @type {import('next').NextConfig} */
const nextConfig = {
  pageExtensions: ['js', 'jsx', 'md', 'mdx', 'ts', 'tsx'],
}

const withMDX = createMDX({
  options: {
    remarkPlugins: [
      // Không có tùy chọn
      'remark-gfm',
      // Có tùy chọn
      ['remark-toc', { heading: 'The Table' }],
    ],
    rehypePlugins: [
      // Không có tùy chọn
      'rehype-slug',
      // Có tùy chọn
      ['rehype-katex', { strict: true, throwOnError: true }],
    ],
  },
})

export default withMDX(nextConfig)
```

> **Cần biết**:
>
> Các plugin remark và rehype không có tùy chọn có thể tuần tự hóa (serializable options) chưa thể được sử dụng với [Turbopack](/docs/app/api-reference/turbopack), vì các hàm JavaScript không thể được truyền sang Rust.

## Remote MDX

Nếu các tệp hoặc nội dung MDX của bạn nằm ở _nơi khác_, bạn có thể fetch nó động trên server. Điều này hữu ích cho nội dung được lưu trữ trong CMS, cơ sở dữ liệu, hoặc bất kỳ nơi nào khác. Một gói cộng đồng cho mục đích sử dụng này là [`next-mdx-remote-client`](https://github.com/ipikuka/next-mdx-remote-client?tab=readme-ov-file#the-part-associated-with-nextjs-app-router).

> **Cần biết**: Vui lòng tiến hành thận trọng. MDX biên dịch thành JavaScript và được thực thi trên server. Bạn chỉ nên fetch nội dung MDX từ một nguồn đáng tin cậy, nếu không điều này có thể dẫn đến thực thi mã từ xa (RCE).

Ví dụ sau sử dụng `next-mdx-remote-client`:

<AppOnly>

```tsx filename="app/mdx-page-remote/page.tsx" switcher
import { MDXRemote } from 'next-mdx-remote-client/rsc'

export default async function RemoteMdxPage() {
  // MDX text - có thể từ cơ sở dữ liệu, CMS, fetch, bất cứ đâu...
  const res = await fetch('https://...')
  const markdown = await res.text()
  return <MDXRemote source={markdown} />
}
```


</AppOnly>

## Tìm hiểu sâu: Làm thế nào để bạn chuyển đổi markdown thành HTML?

React không hiểu markdown một cách tự nhiên. Văn bản thuần túy markdown cần phải được chuyển đổi thành HTML trước. Điều này có thể được thực hiện với `remark` và `rehype`.

`remark` là một hệ sinh thái các công cụ xung quanh markdown. `rehype` cũng tương tự, nhưng dành cho HTML. Ví dụ, đoạn mã sau chuyển đổi markdown thành HTML:

```js
import { unified } from 'unified'
import remarkParse from 'remark-parse'
import remarkRehype from 'remark-rehype'
import rehypeSanitize from 'rehype-sanitize'
import rehypeStringify from 'rehype-stringify'

main()

async function main() {
  const file = await unified()
    .use(remarkParse) // Chuyển đổi thành markdown AST
    .use(remarkRehype) // Chuyển đổi thành HTML AST
    .use(rehypeSanitize) // Làm sạch đầu vào HTML
    .use(rehypeStringify) // Chuyển đổi AST thành HTML được tuần tự hóa
    .process('Hello, Next.js!')

  console.log(String(file)) // <p>Hello, Next.js!</p>
}
```

Hệ sinh thái `remark` và `rehype` chứa các plugin cho [syntax highlighting](https://github.com/atomiks/rehype-pretty-code), [linking headings](https://github.com/rehypejs/rehype-autolink-headings), [tạo mục lục](https://github.com/remarkjs/remark-toc), và nhiều hơn nữa.

Khi sử dụng `@next/mdx` như đã trình bày ở trên, bạn **không** cần phải sử dụng `remark` hoặc `rehype` trực tiếp, vì nó được xử lý cho bạn. Chúng tôi mô tả nó ở đây để hiểu sâu hơn về những gì gói `@next/mdx` đang làm bên dưới.

## Sử dụng trình biên dịch MDX dựa trên Rust (thử nghiệm)

Next.js hỗ trợ một trình biên dịch MDX mới được viết bằng Rust. Trình biên dịch này vẫn đang trong giai đoạn thử nghiệm và không được khuyến nghị cho sử dụng production. Để sử dụng trình biên dịch mới, bạn cần cấu hình `next.config.js` khi bạn truyền nó cho `withMDX`:

```js filename="next.config.js"
module.exports = withMDX({
  experimental: {
    mdxRs: true,
  },
})
```

`mdxRs` cũng chấp nhận một đối tượng để cấu hình cách chuyển đổi các tệp mdx.

```js filename="next.config.js"
module.exports = withMDX({
  experimental: {
    mdxRs: {
      jsxRuntime?: string            // Custom jsx runtime
      jsxImportSource?: string       // Custom jsx import source,
      mdxType?: 'gfm' | 'commonmark' // Cấu hình loại cú pháp mdx nào sẽ được sử dụng để phân tích cú pháp & chuyển đổi
    },
  },
})
```
