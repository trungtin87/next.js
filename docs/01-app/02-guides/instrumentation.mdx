Instrumentation là quá trình sử dụng code để tích hợp các công cụ monitoring và logging vào ứng dụng của bạn. Điều này cho phép bạn theo dõi hiệu suất và hành vi của ứng dụng của bạn, và debug các vấn đề trong production.

## Quy ước

Để thiết lập instrumentation, hãy tạo tệp `instrumentation.ts|js` trong **thư mục root** của dự án của bạn (hoặc bên trong thư mục [`src`](/docs/app/api-reference/file-conventions/src-folder) nếu sử dụng).

Sau đó, export một hàm `register` trong tệp. Hàm này sẽ được gọi **một lần** khi một Next.js server instance mới được khởi tạo.

Ví dụ, để sử dụng Next.js với [OpenTelemetry](https://opentelemetry.io/) và [@vercel/otel](https://vercel.com/docs/observability/otel-overview):

```ts filename="instrumentation.ts" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

```js filename="instrumentation.js" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

Xem [ví dụ Next.js với OpenTelemetry](https://github.com/vercel/next.js/tree/canary/examples/with-opentelemetry) để có một implementation đầy đủ.

> **Nên biết**:
>
> - Tệp `instrumentation` nên ở root của dự án của bạn và không nằm bên trong thư mục `app` hoặc `pages`. Nếu bạn đang sử dụng thư mục `src`, thì hãy đặt tệp bên trong `src` cùng với `pages` và `app`.
> - Nếu bạn sử dụng [tùy chọn cấu hình `pageExtensions`](/docs/app/api-reference/config/next-config-js/pageExtensions) để thêm một suffix, bạn cũng sẽ cần cập nhật tên tệp `instrumentation` để khớp.

## Ví dụ

### Import các tệp với side effects

Đôi khi, có thể hữu ích khi import một tệp trong code của bạn vì các side effects mà nó sẽ gây ra. Ví dụ, bạn có thể import một tệp định nghĩa một tập hợp các biến toàn cục, nhưng không bao giờ sử dụng rõ ràng tệp đã import trong code của bạn. Bạn vẫn sẽ có quyền truy cập vào các biến toàn cục mà package đã khai báo.

Chúng tôi khuyến nghị import các tệp bằng cú pháp `import` của JavaScript trong hàm `register` của bạn. Ví dụ sau minh họa cách sử dụng cơ bản của `import` trong một hàm `register`:

```ts filename="instrumentation.ts" switcher
export async function register() {
  await import('package-with-side-effect')
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  await import('package-with-side-effect')
}
```

> **Nên biết:**
>
> Chúng tôi khuyến nghị import tệp từ bên trong hàm `register`, thay vì ở đầu tệp. Bằng cách làm điều này, bạn có thể colocate tất cả các side effects của bạn ở một nơi trong code của bạn, và tránh bất kỳ hậu quả không mong muốn nào từ việc import toàn cầu ở đầu tệp.

### Import code cụ thể cho runtime

Next.js gọi `register` trong tất cả các môi trường, vì vậy điều quan trọng là phải import có điều kiện bất kỳ code nào không hỗ trợ các runtime cụ thể (ví dụ: [Edge hoặc Node.js](/docs/app/api-reference/edge)). Bạn có thể sử dụng biến môi trường `NEXT_RUNTIME` để lấy môi trường hiện tại:

```ts filename="instrumentation.ts" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation-node')
  }

  if (process.env.NEXT_RUNTIME === 'edge') {
    await import('./instrumentation-edge')
  }
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation-node')
  }

  if (process.env.NEXT_RUNTIME === 'edge') {
    await import('./instrumentation-edge')
  }
}
```
