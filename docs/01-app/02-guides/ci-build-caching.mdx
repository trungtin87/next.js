---
title: Cách cấu hình Continuous Integration (CI) build caching
nav_title: CI Build Caching
description: Tìm hiểu cách cấu hình CI để cache các bản build Next.js
---

Để cải thiện hiệu suất build, Next.js lưu một cache vào `.next/cache` được chia sẻ giữa các bản build.

Để tận dụng cache này trong môi trường Tích hợp liên tục (CI), quy trình làm việc CI của bạn sẽ cần được định cấu hình để duy trì chính xác cache giữa các bản build.

> Nếu CI của bạn không được định cấu hình để duy trì `.next/cache` giữa các bản build, bạn có thể thấy lỗi [Không phát hiện Cache](/docs/messages/no-cache).

Dưới đây là một số cấu hình cache ví dụ cho các nhà cung cấp CI phổ biến:

## Vercel

Next.js caching được định cấu hình tự động cho bạn. Bạn không cần thực hiện hành động nào. Nếu bạn đang sử dụng Turborepo trên Vercel, [tìm hiểu thêm tại đây](https://vercel.com/docs/monorepos/turborepo).

## CircleCI

Chỉnh sửa bước `save_cache` của bạn trong `.circleci/config.yml` để bao gồm `.next/cache`:

```yaml
steps:
  - save_cache:
      key: dependency-cache-{{ checksum "yarn.lock" }}
      paths:
        - ./node_modules
        - ./.next/cache
```

Nếu bạn không có khóa `save_cache`, vui lòng làm theo [tài liệu của CircleCI về thiết lập build caching](https://circleci.com/docs/2.0/caching/).

## Travis CI

Thêm hoặc hợp nhất phần sau vào `.travis.yml` của bạn:

```yaml
cache:
  directories:
    - $HOME/.cache/yarn
    - node_modules
    - .next/cache
```

## GitLab CI

Thêm hoặc hợp nhất phần sau vào `.gitlab-ci.yml` của bạn:

```yaml
cache:
  key: ${CI_COMMIT_REF_SLUG}
  paths:
    - node_modules/
    - .next/cache/
```

## Netlify CI

Sử dụng [Netlify Plugins](https://www.netlify.com/products/build/plugins/) với [`@netlify/plugin-nextjs`](https://www.npmjs.com/package/@netlify/plugin-nextjs).

## AWS CodeBuild

Thêm (hoặc hợp nhất vào) phần sau vào `buildspec.yml` của bạn:

```yaml
cache:
  paths:
    - 'node_modules/**/*' # Cache `node_modules` for faster `yarn` or `npm i`
    - '.next/cache/**/*' # Cache Next.js for faster application rebuilds
```

## GitHub Actions

Sử dụng [actions/cache](https://github.com/actions/cache) của GitHub, thêm bước sau vào tệp quy trình làm việc của bạn:

```yaml
uses: actions/cache@v4
with:
  # See here for caching with `yarn`, `bun` or other package managers https://github.com/actions/cache/blob/main/examples.md or you can leverage caching with actions/setup-node https://github.com/actions/setup-node
  path: |
    ~/.npm
    ${{ github.workspace }}/.next/cache
  # Generate a new cache whenever packages or source files change.
  key: ${{ runner.os }}-nextjs-${{ hashFiles('**/package-lock.json') }}-${{ hashFiles('**/*.js', '**/*.jsx', '**/*.ts', '**/*.tsx') }}
  # If source files changed but packages didn't, rebuild from a prior cache.
  restore-keys: |
    ${{ runner.os }}-nextjs-${{ hashFiles('**/package-lock.json') }}-
```

## Bitbucket Pipelines

Thêm hoặc hợp nhất phần sau vào `bitbucket-pipelines.yml` của bạn ở cấp cao nhất (cùng cấp với `pipelines`):

```yaml
definitions:
  caches:
    nextcache: .next/cache
```

Sau đó tham chiếu nó trong phần `caches` của `step` trong pipeline của bạn:

```yaml
- step:
    name: your_step_name
    caches:
      - node
      - nextcache
```

## Heroku

Sử dụng [custom cache](https://devcenter.heroku.com/articles/nodejs-support#custom-caching) của Heroku, thêm một mảng `cacheDirectories` trong package.json cấp cao nhất của bạn:

```javascript
"cacheDirectories": [".next/cache"]
```

## Azure Pipelines

Sử dụng [Cache task](https://docs.microsoft.com/en-us/azure/devops/pipelines/tasks/utility/cache) của Azure Pipelines, thêm tác vụ sau vào tệp yaml pipeline của bạn ở đâu đó trước tác vụ thực thi `next build`:

```yaml
- task: Cache@2
  displayName: 'Cache .next/cache'
  inputs:
    key: next | $(Agent.OS) | yarn.lock
    path: '$(System.DefaultWorkingDirectory)/.next/cache'
```

## Jenkins (Pipeline)

Sử dụng plugin [Job Cacher](https://www.jenkins.io/doc/pipeline/steps/jobcacher/) của Jenkins, thêm bước build sau vào `Jenkinsfile` của bạn, nơi bạn thường chạy `next build` hoặc `npm install`:

```yaml
stage("Restore npm packages") {
    steps {
        // Writes lock-file to cache based on the GIT_COMMIT hash
        writeFile file: "next-lock.cache", text: "$GIT_COMMIT"

        cache(caches: [
            arbitraryFileCache(
                path: "node_modules",
                includes: "**/*",
                cacheValidityDecidingFile: "package-lock.json"
            )
        ]) {
            sh "npm install"
        }
    }
}
stage("Build") {
    steps {
        // Writes lock-file to cache based on the GIT_COMMIT hash
        writeFile file: "next-lock.cache", text: "$GIT_COMMIT"

        cache(caches: [
            arbitraryFileCache(
                path: ".next/cache",
                includes: "**/*",
                cacheValidityDecidingFile: "next-lock.cache"
            )
        ]) {
            // aka `next build`
            sh "npm run build"
        }
    }
}
```
