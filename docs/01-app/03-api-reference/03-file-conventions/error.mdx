Một file **error** cho phép bạn xử lý các lỗi runtime không mong muốn và hiển thị fallback UI.

```tsx filename="app/dashboard/error.tsx" switcher
'use client' // Error boundaries phải là Client Components

import { useEffect } from 'react'

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  useEffect(() => {
    // Log lỗi vào một error reporting service
    console.error(error)
  }, [error])

  return (
    <div>
      <h2>Something went wrong!</h2>
      <button
        onClick={
          // Cố gắng khôi phục bằng cách thử re-render segment
          () => reset()
        }
      >
        Try again
      </button>
    </div>
  )
}
```

`error.js` bao bọc một route segment và các nested children của nó trong một [React Error Boundary](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary). Khi một lỗi được ném ra bên trong boundary, component `error` sẽ hiển thị dưới dạng fallback UI.

> **Lưu ý**:
>
> - [React DevTools](https://react.dev/learn/react-developer-tools) cho phép bạn bật/tắt error boundaries để kiểm tra các trạng thái lỗi.
> - Nếu bạn muốn lỗi bubble up đến parent error boundary, bạn có thể `throw` khi rendering component `error`.

## Tham khảo

### Props

#### `error`

Một instance của object [`Error`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Error) được chuyển tiếp đến `error.js` Client Component.

> **Lưu ý:** Trong quá trình development, object `Error` được chuyển tiếp đến client sẽ được serialize và bao gồm `message` của lỗi gốc để gỡ lỗi dễ dàng hơn. Tuy nhiên, **hành vi này khác trong production** để tránh rò rỉ các chi tiết có khả năng nhạy cảm có trong lỗi cho client.

#### `error.message`

- Các lỗi được chuyển tiếp từ Client Components hiển thị `Error` message gốc.
- Các lỗi được chuyển tiếp từ Server Components hiển thị một thông báo chung với một identifier. Điều này là để ngăn rò rỉ các chi tiết nhạy cảm. Bạn có thể sử dụng identifier, dưới `errors.digest`, để khớp với các server-side logs tương ứng.

#### `error.digest`

Một hash được tạo tự động của lỗi được ném ra. Nó có thể được sử dụng để khớp với lỗi tương ứng trong server-side logs.

#### `reset`

Nguyên nhân của một lỗi đôi khi có thể là tạm thời. Trong những trường hợp này, thử lại có thể giải quyết vấn đề.

Một error component có thể sử dụng hàm `reset()` để nhắc người dùng cố gắng khôi phục từ lỗi. Khi được thực thi, hàm sẽ cố gắng re-render nội dung của error boundary. Nếu thành công, fallback error component sẽ được thay thế bằng kết quả của việc re-render.

## Ví dụ

### Global Error

Mặc dù ít phổ biến hơn, bạn có thể xử lý lỗi trong root layout hoặc template sử dụng `global-error.jsx`, nằm trong thư mục root app, ngay cả khi tận dụng [internationalization](/docs/app/guides/internationalization). Global error UI phải định nghĩa các thẻ `<html>` và `<body>` của riêng nó, global styles, fonts, hoặc các dependencies khác mà trang lỗi của bạn yêu cầu. File này thay thế root layout hoặc template khi hoạt động.

> **Lưu ý**: Error boundaries phải là [Client Components](/docs/app/getting-started/server-and-client-components#using-client-components), điều này có nghĩa là các exports [`metadata` và `generateMetadata`](/docs/app/getting-started/metadata-and-og-images) không được hỗ trợ trong `global-error.jsx`. Như một giải pháp thay thế, bạn có thể sử dụng React component [`<title>`](https://react.dev/reference/react-dom/components/title).

```tsx filename="app/global-error.tsx" switcher
'use client' // Error boundaries phải là Client Components

export default function GlobalError({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    // global-error phải bao gồm các thẻ html và body
    <html>
      <body>
        <h2>Something went wrong!</h2>
        <button onClick={() => reset()}>Try again</button>
      </body>
    </html>
  )
}
```

```jsx filename="app/global-error.js" switcher

}
```

### Khôi phục lỗi nhẹ nhàng với custom error boundary

Khi rendering thất bại trên client, có thể hữu ích khi hiển thị UI được server render đã biết cuối cùng để có trải nghiệm người dùng tốt hơn.

`GracefullyDegradingErrorBoundary` là một ví dụ về custom error boundary chụp và bảo tồn HTML hiện tại trước khi lỗi xảy ra. Nếu lỗi rendering xảy ra, nó re-render HTML đã chụp và hiển thị một thanh thông báo liên tục để thông báo cho người dùng.

```tsx filename="app/dashboard/error.tsx" switcher
'use client'

import React, { Component, ErrorInfo, ReactNode } from 'react'

interface ErrorBoundaryProps {
  children: ReactNode
  onError?: (error: Error, errorInfo: ErrorInfo) => void
}

interface ErrorBoundaryState {
  hasError: boolean
}

export class GracefullyDegradingErrorBoundary extends Component<
  ErrorBoundaryProps,
  ErrorBoundaryState
> {
  private contentRef: React.RefObject<HTMLDivElement | null>

  constructor(props: ErrorBoundaryProps) {
    super(props)
    this.state = { hasError: false }
    this.contentRef = React.createRef()
  }

  static getDerivedStateFromError(_: Error): ErrorBoundaryState {
    return { hasError: true }
  }

  componentDidCatch(error: Error, errorInfo: ErrorInfo) {
    if (this.props.onError) {
      this.props.onError(error, errorInfo)
    }
  }

  render() {
    if (this.state.hasError) {
      // Render nội dung HTML hiện tại mà không cần hydration
      return (
        <>
          <div
            ref={this.contentRef}
            suppressHydrationWarning
            dangerouslySetInnerHTML={{
              __html: this.contentRef.current?.innerHTML || '',
            }}
          />
          <div className="fixed bottom-0 left-0 right-0 bg-red-600 text-white py-4 px-6 text-center">
            <p className="font-semibold">
              An error occurred during page rendering
            </p>
          </div>
        </>
      )
    }

    return <div ref={this.contentRef}>{this.props.children}</div>
  }
}

export default GracefullyDegradingErrorBoundary
```
