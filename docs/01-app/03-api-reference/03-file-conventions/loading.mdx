File đặc biệt `loading.js` giúp bạn tạo Loading UI có ý nghĩa với [React Suspense](https://react.dev/reference/react/Suspense). Với quy ước này, bạn có thể hiển thị một [trạng thái loading tức thì](#instant-loading-states) từ server trong khi nội dung của một route segment đang stream vào. Nội dung mới sẽ tự động được hoán đổi vào sau khi hoàn tất.

```tsx filename="app/feed/loading.tsx" switcher
export default function Loading() {
  // Hoặc một custom loading skeleton component
  return <p>Loading...</p>
}
```

```jsx filename="app/feed/loading.js" switcher
export default function Loading() {
  // Hoặc một custom loading skeleton component
  return <p>Loading...</p>
}
```

Bên trong file `loading.js`, bạn có thể thêm bất kỳ loading UI nhẹ nào. Bạn có thể thấy hữu ích khi sử dụng [React Developer Tools](https://react.dev/learn/react-developer-tools) để bật/tắt thủ công các Suspense boundaries.

Mặc định, file này là một [Server Component](/docs/app/getting-started/server-and-client-components) - nhưng cũng có thể được sử dụng như một Client Component thông qua directive `"use client"`.

## Tham khảo

### Tham số

Các Loading UI components không chấp nhận bất kỳ tham số nào.

## Hành vi

### Điều hướng

- Fallback UI được [prefetched](/docs/app/getting-started/linking-and-navigating#prefetching), làm cho việc điều hướng trở nên ngay lập tức trừ khi prefetching chưa hoàn tất.
- Điều hướng có thể bị gián đoạn (interruptible), nghĩa là việc thay đổi routes không cần phải đợi nội dung của route tải đầy đủ trước khi điều hướng đến một route khác.
- Shared layouts vẫn tương tác được trong khi các route segments mới đang tải.

### Trạng thái Loading tức thì

Một trạng thái loading tức thì là fallback UI được hiển thị ngay lập tức khi điều hướng. Bạn có thể pre-render các chỉ báo loading như skeletons và spinners, hoặc một phần nhỏ nhưng có ý nghĩa của màn hình tương lai như ảnh bìa, tiêu đề, v.v. Điều này giúp người dùng hiểu rằng ứng dụng đang phản hồi và cung cấp trải nghiệm người dùng tốt hơn.

Tạo một trạng thái loading bằng cách thêm một file `loading.js` bên trong một thư mục.

### SEO

- Đối với các bot chỉ scrape static HTML, và không thể thực thi JavaScript như một trình duyệt đầy đủ, chẳng hạn như Twitterbot, Next.js resolve [`generateMetadata`](/docs/app/api-reference/functions/generate-metadata) trước khi streaming UI, và metadata được đặt trong `<head>` của HTML ban đầu.
- Nếu không, [streaming metadata](/docs/app/api-reference/functions/generate-metadata#streaming-metadata) có thể được sử dụng. Next.js tự động phát hiện user agents để chọn giữa hành vi blocking và streaming.
- Vì streaming là server-rendered, nó không ảnh hưởng đến SEO. Bạn có thể sử dụng công cụ [Rich Results Test](https://search.google.com/test/rich-results) từ Google để xem trang của bạn xuất hiện như thế nào đối với các trình thu thập thông tin web của Google và xem serialized HTML ([nguồn](https://web.dev/rendering-on-the-web/#seo-considerations)).

### Mã trạng thái (Status Codes)

Khi streaming, một mã trạng thái `200` sẽ được trả về để báo hiệu rằng yêu cầu đã thành công.

Server vẫn có thể giao tiếp lỗi hoặc vấn đề cho client bên trong chính nội dung được stream, ví dụ, khi sử dụng [`redirect`](/docs/app/api-reference/functions/redirect) hoặc [`notFound`](/docs/app/api-reference/functions/not-found). Bởi vì response headers đã được gửi đến client, mã trạng thái của response không thể được cập nhật.

Ví dụ, khi một trang 404 được stream đến client, Next.js bao gồm một thẻ `<meta name="robots" content="noindex">` trong HTML được stream. Điều này ngăn các công cụ tìm kiếm lập chỉ mục URL đó ngay cả khi trạng thái HTTP là 200. Xem hướng dẫn của Google về [`robots` meta tag](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag).

Một số trình thu thập thông tin có thể gắn nhãn các phản hồi này là “soft 404s”. Trong trường hợp streaming, điều này không dẫn đến việc lập chỉ mục vì trang được đánh dấu rõ ràng là `noindex` trong HTML.

Nếu bạn cần một trạng thái 404, để tuân thủ hoặc phân tích, hãy đảm bảo tài nguyên tồn tại trước khi response body được stream, để server có thể đặt mã trạng thái HTTP.

Bạn có thể chạy kiểm tra này trong [`proxy`](/docs/app/api-reference/file-conventions/proxy) để viết lại các slugs bị thiếu thành một route not-found, hoặc [tạo ra một phản hồi 404](/docs/app/api-reference/file-conventions/proxy#producing-a-response). Giữ cho các kiểm tra proxy nhanh chóng, và tránh fetch toàn bộ nội dung ở đó.

<details>
<summary>Khi nào response body được stream?</summary>

Response body bắt đầu streaming khi một Suspense fallback render (ví dụ, một `loading.tsx`) hoặc khi một Server Component suspend dưới một `Suspense` boundary. Đặt `notFound()` trước các boundaries đó và trước bất kỳ `await` nào có thể suspend.

Để bắt đầu streaming, response headers phải được thiết lập. Đây là lý do tại sao không thể thay đổi mã trạng thái sau khi streaming bắt đầu.

</details>

### Giới hạn trình duyệt

[Một số trình duyệt](https://bugs.webkit.org/show_bug.cgi?id=252413) buffer một streaming response. Bạn có thể không thấy phản hồi được stream cho đến khi phản hồi vượt quá 1024 bytes. Điều này thường chỉ ảnh hưởng đến các ứng dụng “hello world”, nhưng không ảnh hưởng đến các ứng dụng thực tế.

## Ví dụ

### Streaming với Suspense

Ngoài `loading.js`, bạn cũng có thể tạo thủ công các Suspense Boundaries cho các UI components của riêng bạn. App Router hỗ trợ streaming với [Suspense](https://react.dev/reference/react/Suspense).

`<Suspense>` hoạt động bằng cách bao bọc một component thực hiện một hành động bất đồng bộ (ví dụ: fetch data), hiển thị fallback UI (ví dụ: skeleton, spinner) trong khi nó đang diễn ra, và sau đó hoán đổi component của bạn vào sau khi hành động hoàn tất.

```tsx filename="app/dashboard/page.tsx" switcher
import { Suspense } from 'react'
import { PostFeed, Weather } from './Components'

export default function Posts() {
  return (
    <section>
      <Suspense fallback={<p>Loading feed...</p>}>
        <PostFeed />
      </Suspense>
      <Suspense fallback={<p>Loading weather...</p>}>
        <Weather />
      </Suspense>
    </section>
  )
}
```

```jsx filename="app/dashboard/page.js" switcher
import { Suspense } from 'react'
import { PostFeed, Weather } from './Components'

export default function Posts() {
  return (
    <section>
      <Suspense fallback={<p>Loading feed...</p>}>
        <PostFeed />
      </Suspense>
      <Suspense fallback={<p>Loading weather...</p>}>
        <Weather />
      </Suspense>
    </section>
  )
}
```

Bằng cách sử dụng Suspense, bạn nhận được các lợi ích của:

1. **Streaming Server Rendering** - Render dần dần HTML từ server đến client.
2. **Selective Hydration** - React ưu tiên các components nào để làm cho tương tác trước dựa trên tương tác của người dùng.

Để biết thêm các ví dụ và trường hợp sử dụng Suspense, vui lòng xem [Tài liệu React](https://react.dev/reference/react/Suspense).
