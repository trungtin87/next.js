Next.js có thể phục vụ các tệp tĩnh, như hình ảnh, dưới một thư mục có tên `public` trong thư mục gốc. Các tệp bên trong `public` sau đó có thể được tham chiếu bởi mã của bạn bắt đầu từ URL cơ sở (`/`).

Ví dụ, tệp `public/avatars/me.png` có thể được xem bằng cách truy cập đường dẫn `/avatars/me.png`. Mã để hiển thị hình ảnh đó có thể trông như:

```jsx filename="avatar.js"
import Image from 'next/image'

export function Avatar({ id, alt }) {
  return <Image src={`/avatars/${id}.png`} alt={alt} width="64" height="64" />
}

export function AvatarOfMe() {
  return <Avatar id="me" alt="A portrait of me" />
}
```

## Caching

Next.js không thể cache an toàn các tài sản trong thư mục `public` vì chúng có thể thay đổi. Các header caching mặc định được áp dụng là:

```jsx
Cache-Control: public, max-age=0
```

## Robots, Favicons, và các tệp khác

<PagesOnly>

Thư mục này cũng hữu ích cho `robots.txt`, `favicon.ico`, Google Site Verification, và bất kỳ tệp tĩnh nào khác (bao gồm `.html`). Nhưng hãy đảm bảo không có tệp tĩnh nào có cùng tên với tệp trong thư mục `pages/`, vì điều này sẽ dẫn đến lỗi. [Đọc thêm](/docs/messages/conflicting-public-file-page).

</PagesOnly>

<AppOnly>

Đối với các tệp metadata tĩnh, chẳng hạn như `robots.txt`, `favicon.ico`, v.v., bạn nên sử dụng [các tệp metadata đặc biệt](/docs/app/api-reference/file-conventions/metadata) bên trong thư mục `app`.

</AppOnly>
