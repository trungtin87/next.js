Các file conventions `opengraph-image` và `twitter-image` cho phép bạn đặt Open Graph và Twitter images cho một route segment.

Chúng hữu ích để đặt các hình ảnh xuất hiện trên các mạng xã hội và ứng dụng nhắn tin khi người dùng chia sẻ một liên kết đến trang web của bạn.

Có hai cách để đặt Open Graph và Twitter images:

- [Sử dụng image files (.jpg, .png, .gif)](#image-files-jpg-png-gif)
- [Sử dụng code để tạo images (.js, .ts, .tsx)](#generate-images-using-code-js-ts-tsx)

## Image files (.jpg, .png, .gif)

Sử dụng một image file để đặt shared image của route segment bằng cách đặt một image file `opengraph-image` hoặc `twitter-image` trong segment.

Next.js sẽ đánh giá file và tự động thêm các thẻ thích hợp vào phần tử `<head>` của ứng dụng của bạn.

| File convention                                 | Các loại file được hỗ trợ       |
| ----------------------------------------------- | ------------------------------- |
| [`opengraph-image`](#opengraph-image)           | `.jpg`, `.jpeg`, `.png`, `.gif` |
| [`twitter-image`](#twitter-image)               | `.jpg`, `.jpeg`, `.png`, `.gif` |
| [`opengraph-image.alt`](#opengraph-imagealttxt) | `.txt`                          |
| [`twitter-image.alt`](#twitter-imagealttxt)     | `.txt`                          |

> **Lưu ý**:
>
> Kích thước file `twitter-image` không được vượt quá [5MB](https://developer.x.com/en/docs/x-for-websites/cards/overview/summary), và kích thước file `opengraph-image` không được vượt quá [8MB](https://developers.facebook.com/docs/sharing/webmasters/images). Nếu kích thước image file vượt quá các giới hạn này, build sẽ thất bại.

### `opengraph-image`

Thêm một image file `opengraph-image.(jpg|jpeg|png|gif)` vào bất kỳ route segment nào.

```html filename="<head> output"
<meta property="og:image" content="<generated>" />
<meta property="og:image:type" content="<generated>" />
<meta property="og:image:width" content="<generated>" />
<meta property="og:image:height" content="<generated>" />
```

### `twitter-image`

Thêm một image file `twitter-image.(jpg|jpeg|png|gif)` vào bất kỳ route segment nào.

```html filename="<head> output"
<meta name="twitter:image" content="<generated>" />
<meta name="twitter:image:type" content="<generated>" />
<meta name="twitter:image:width" content="<generated>" />
<meta name="twitter:image:height" content="<generated>" />
```

### `opengraph-image.alt.txt`

Thêm một file `opengraph-image.alt.txt` đi kèm trong cùng route segment với image `opengraph-image.(jpg|jpeg|png|gif)` mà nó là alt text.

```txt filename="opengraph-image.alt.txt"
About Acme
```

```html filename="<head> output"
<meta property="og:image:alt" content="About Acme" />
```

### `twitter-image.alt.txt`

Thêm một file `twitter-image.alt.txt` đi kèm trong cùng route segment với image `twitter-image.(jpg|jpeg|png|gif)` mà nó là alt text.

```txt filename="twitter-image.alt.txt"
About Acme
```

```html filename="<head> output"
<meta property="twitter:image:alt" content="About Acme" />
```

## Tạo images sử dụng code (.js, .ts, .tsx)

Ngoài việc sử dụng [literal image files](#image-files-jpg-png-gif), bạn có thể **tạo** images bằng lập trình sử dụng code.

Tạo shared image của route segment bằng cách tạo một route `opengraph-image` hoặc `twitter-image` export mặc định một function.

| File convention   | Các loại file được hỗ trợ |
| ----------------- | ------------------------- |
| `opengraph-image` | `.js`, `.ts`, `.tsx`      |
| `twitter-image`   | `.js`, `.ts`, `.tsx`      |

> **Lưu ý**:
>
> - Mặc định, các images được tạo được [**tối ưu hóa tĩnh**](/docs/app/guides/caching#static-rendering) (được tạo tại build time và cached) trừ khi chúng sử dụng [Dynamic APIs](/docs/app/guides/caching#dynamic-rendering) hoặc uncached data.
> - Bạn có thể tạo nhiều Images trong cùng một file sử dụng [`generateImageMetadata`](/docs/app/api-reference/functions/generate-image-metadata).
> - `opengraph-image.js` và `twitter-image.js` là các Route Handlers đặc biệt được cache mặc định trừ khi nó sử dụng một tùy chọn [Dynamic API](/docs/app/guides/caching#dynamic-apis) hoặc [dynamic config](/docs/app/guides/caching#segment-config-options).

Cách dễ nhất để tạo một image là sử dụng API [ImageResponse](/docs/app/api-reference/functions/image-response) từ `next/og`.

```tsx filename="app/about/opengraph-image.tsx" switcher
import { ImageResponse } from 'next/og'
import { readFile } from 'node:fs/promises'
import { join } from 'node:path'

// Image metadata
export const alt = 'About Acme'
export const size = {
  width: 1200,
  height: 630,
}

export const contentType = 'image/png'

// Image generation
export default async function Image() {
  // Font loading, process.cwd() is Next.js project directory
  const interSemiBold = await readFile(
    join(process.cwd(), 'assets/Inter-SemiBold.ttf')
  )

  return new ImageResponse(
    (
      // ImageResponse JSX element
      <div
        style={{
          fontSize: 128,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        About Acme
      </div>
    ),
    // ImageResponse options
    {
      // Để thuận tiện, chúng ta có thể sử dụng lại config size của opengraph-image đã export
      // để cũng đặt width và height của ImageResponse.
      ...size,
      fonts: [
        {
          name: 'Inter',
          data: interSemiBold,
          style: 'normal',
          weight: 400,
        },
      ],
    }
  )
}
```

### Props

Function export mặc định nhận các props sau:

#### `params` (tùy chọn)

Một promise resolve thành một object chứa object [dynamic route parameters](/docs/app/api-reference/file-conventions/dynamic-routes) từ root segment xuống đến segment mà `opengraph-image` hoặc `twitter-image` được đặt cùng.

> **Lưu ý**: Nếu bạn sử dụng [`generateImageMetadata`](/docs/app/api-reference/functions/generate-image-metadata), function cũng sẽ nhận một prop `id` là một promise resolving thành giá trị `id` từ một trong các items được trả về bởi `generateImageMetadata`.

```tsx filename="app/shop/[slug]/opengraph-image.tsx" switcher
export default async function Image({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  // ...
}
```

```jsx filename="app/shop/[slug]/opengraph-image.js" switcher
export default async function Image({ params }) {
  const { slug } = await params
  // ...
}
```

| Route                                      | URL         | `params`                           |
| ------------------------------------------ | ----------- | ---------------------------------- |
| `app/shop/opengraph-image.js`              | `/shop`     | `undefined`                        |
| `app/shop/[slug]/opengraph-image.js`       | `/shop/1`   | `Promise<{ slug: '1' }>`           |
| `app/shop/[tag]/[item]/opengraph-image.js` | `/shop/1/2` | `Promise<{ tag: '1', item: '2' }>` |

### Returns

Function export mặc định nên trả về một `Blob` | `ArrayBuffer` | `TypedArray` | `DataView` | `ReadableStream` | `Response`.

> **Lưu ý**: `ImageResponse` thỏa mãn return type này.

#### Route Segment Config

`opengraph-image` và `twitter-image` là các [Route Handlers](/docs/app/api-reference/file-conventions/route) chuyên biệt có thể sử dụng các tùy chọn [route segment configuration](/docs/app/api-reference/file-conventions/route-segment-config) giống như Pages và Layouts.

### Ví dụ

#### Sử dụng external data

Ví dụ này sử dụng object `params` và external data để tạo image.

> **Lưu ý**:
> Mặc định, image được tạo này sẽ được [tối ưu hóa tĩnh](/docs/app/guides/caching#static-rendering). Bạn có thể cấu hình [`options`](/docs/app/api-reference/functions/fetch) của `fetch` riêng lẻ hoặc [options](/docs/app/api-reference/file-conventions/route-segment-config#revalidate) của route segments để thay đổi hành vi này.

```tsx filename="app/posts/[slug]/opengraph-image.tsx" switcher
import { ImageResponse } from 'next/og'

export const alt = 'About Acme'
export const size = {
  width: 1200,
  height: 630,
}
export const contentType = 'image/png'

export default async function Image({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await fetch(`https://.../posts/${slug}`).then((res) =>
    res.json()
  )

  return new ImageResponse(
    (
      <div
        style={{
          fontSize: 48,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {post.title}
      </div>
    ),
    {
      ...size,
    }
  )
}
```


#### Sử dụng Node.js runtime với local assets

Các ví dụ này sử dụng Node.js runtime để fetch một local image từ file system và truyền nó vào thuộc tính `src` của `<img>`, dưới dạng base64 string hoặc `ArrayBuffer`. Đặt local asset tương đối với project root, không phải file source ví dụ.

```tsx filename="app/opengraph-image.tsx" switcher
import { ImageResponse } from 'next/og'
import { join } from 'node:path'
import { readFile } from 'node:fs/promises'

export default async function Image() {
  const logoData = await readFile(join(process.cwd(), 'logo.png'), 'base64')
  const logoSrc = `data:image/png;base64,${logoData}`

  return new ImageResponse(
    (
      <div
        style={{
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        <img src={logoSrc} height="100" />
      </div>
    )
  )
}
```


Truyền một `ArrayBuffer` vào thuộc tính `src` của một phần tử `<img>` không phải là một phần của HTML spec. Rendering engine được sử dụng bởi `next/og` hỗ trợ nó, nhưng vì các định nghĩa TypeScript tuân theo spec, bạn cần một directive `@ts-expect-error` hoặc tương tự để sử dụng [tính năng](https://github.com/vercel/satori/issues/606#issuecomment-2144000453) này.

```tsx filename="app/opengraph-image.tsx" switcher
import { ImageResponse } from 'next/og'
import { join } from 'node:path'
import { readFile } from 'node:fs/promises'

export default async function Image() {
  const logoData = await readFile(join(process.cwd(), 'logo.png'))
  const logoSrc = Uint8Array.from(logoData).buffer

  return new ImageResponse(
    (
      <div
        style={{
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {/* @ts-expect-error Satori accepts ArrayBuffer/typed arrays for <img src> at runtime */}
        <img src={logoSrc} height="100" />
      </div>
    )
  )
}
```
