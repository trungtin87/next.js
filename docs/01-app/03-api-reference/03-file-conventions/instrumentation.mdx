Tệp `instrumentation.js|ts` được sử dụng để tích hợp các công cụ observability vào ứng dụng của bạn, cho phép bạn theo dõi hiệu suất và hành vi, và debug các vấn đề trong production.

Để sử dụng nó, hãy đặt tệp trong **root** của ứng dụng của bạn hoặc bên trong thư mục [`src`](/docs/app/api-reference/file-conventions/src-folder) nếu sử dụng.

## Exports

### `register` (tùy chọn)

Tệp export một hàm `register` được gọi **một lần** khi một Next.js server instance mới được khởi tạo. `register` có thể là một async function.

```ts filename="instrumentation.ts" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

```js filename="instrumentation.js" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

### `onRequestError` (tùy chọn)

Bạn có thể tùy chọn export một hàm `onRequestError` để theo dõi các lỗi **server** đến bất kỳ custom observability provider nào.

- Nếu bạn đang chạy bất kỳ async tasks nào trong `onRequestError`, hãy đảm bảo chúng được awaited. `onRequestError` sẽ được kích hoạt khi Next.js server bắt được lỗi.
- Instance `error` có thể không phải là error instance gốc được ném, vì nó có thể được xử lý bởi React nếu gặp phải trong quá trình Server Components rendering. Nếu điều này xảy ra, bạn có thể sử dụng thuộc tính `digest` trên error để xác định loại lỗi thực tế.

```ts filename="instrumentation.ts" switcher
import { type Instrumentation } from 'next'

export const onRequestError: Instrumentation.onRequestError = async (
  err,
  request,
  context
) => {
  await fetch('https://.../report-error', {
    method: 'POST',
    body: JSON.stringify({
      message: err.message,
      request,
      context,
    }),
    headers: {
      'Content-Type': 'application/json',
    },
  })
}
```

```js filename="instrumentation.js" switcher
export async function onRequestError(err, request, context) {
  await fetch('https://.../report-error', {
    method: 'POST',
    body: JSON.stringify({
      message: err.message,
      request,
      context,
    }),
    headers: {
      'Content-Type': 'application/json',
    },
  })
}
```

#### Parameters

Hàm chấp nhận ba parameters: `error`, `request`, và `context`.

```ts filename="Types"
export function onRequestError(
  error: { digest: string } & Error,
  request: {
    path: string // resource path, e.g. /blog?name=foo
    method: string // request method. e.g. GET, POST, etc
    headers: { [key: string]: string | string[] }
  },
  context: {
    routerKind: 'Pages Router' | 'App Router' // the router type
    routePath: string // the route file path, e.g. /app/blog/[dynamic]
    routeType: 'render' | 'route' | 'action' | 'proxy' // the context in which the error occurred
    renderSource:
      | 'react-server-components'
      | 'react-server-components-payload'
      | 'server-rendering'
    revalidateReason: 'on-demand' | 'stale' | undefined // undefined is a normal request without revalidation
    renderType: 'dynamic' | 'dynamic-resume' // 'dynamic-resume' for PPR
  }
): void | Promise<void>
```

- `error`: Lỗi đã bắt được (type luôn là `Error`), và một thuộc tính `digest` là ID duy nhất của lỗi.
- `request`: Thông tin request read-only liên quan đến lỗi.
- `context`: Ngữ cảnh mà lỗi xảy ra. Đây có thể là loại router (App hoặc Pages Router), và/hoặc (Server Components (`'render'`), Route Handlers (`'route'`), Server Actions (`'action'`), hoặc Proxy (`'proxy'`)).

### Chỉ định runtime

Tệp `instrumentation.js` hoạt động trong cả Node.js và Edge runtime, tuy nhiên, bạn có thể sử dụng `process.env.NEXT_RUNTIME` để nhắm mục tiêu một runtime cụ thể.

```js filename="instrumentation.js"
export function register() {
  if (process.env.NEXT_RUNTIME === 'edge') {
    return require('./register.edge')
  } else {
    return require('./register.node')
  }
}

export function onRequestError() {
  if (process.env.NEXT_RUNTIME === 'edge') {
    return require('./on-request-error.edge')
  } else {
    return require('./on-request-error.node')
  }
}
```
