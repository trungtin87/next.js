File `layout` được sử dụng để định nghĩa một layout trong ứng dụng Next.js của bạn.

```tsx filename="app/dashboard/layout.tsx" switcher
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return <section>{children}</section>
}
```

```jsx filename="app/dashboard/layout.js" switcher
export default function DashboardLayout({ children }) {
  return <section>{children}</section>
}
```

Một **root layout** là layout cao nhất trong thư mục root `app`. Nó được sử dụng để định nghĩa các thẻ `<html>` và `<body>` và các UI được chia sẻ toàn cục khác.

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

## Tham khảo

### Props

#### `children` (bắt buộc)

Các Layout components nên chấp nhận và sử dụng một prop `children`. Trong quá trình rendering, `children` sẽ được điền với các route segments mà layout đang bao bọc. Những cái này chủ yếu sẽ là component của một child [Layout](/docs/app/api-reference/file-conventions/page) (nếu nó tồn tại) hoặc [Page](/docs/app/api-reference/file-conventions/page), nhưng cũng có thể là các file đặc biệt khác như [Loading](/docs/app/api-reference/file-conventions/loading) hoặc [Error](/docs/app/getting-started/error-handling) khi áp dụng.

#### `params` (tùy chọn)

Một promise resolve thành một object chứa object [dynamic route parameters](/docs/app/api-reference/file-conventions/dynamic-routes) từ root segment xuống đến layout đó.

```tsx filename="app/dashboard/[team]/layout.tsx" switcher
export default async function Layout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Promise<{ team: string }>
}) {
  const { team } = await params
}
```

```jsx filename="app/dashboard/[team]/layout.js" switcher
export default async function Layout({ children, params }) {
  const { team } = await params
}
```

| Example Route                     | URL            | `params`                           |
| --------------------------------- | -------------- | ---------------------------------- |
| `app/dashboard/[team]/layout.js`  | `/dashboard/1` | `Promise<{ team: '1' }>`           |
| `app/shop/[tag]/[item]/layout.js` | `/shop/1/2`    | `Promise<{ tag: '1', item: '2' }>` |
| `app/blog/[...slug]/layout.js`    | `/blog/1/2`    | `Promise<{ slug: ['1', '2'] }>`    |

- Vì prop `params` là một promise. Bạn phải sử dụng `async/await` hoặc hàm [`use`](https://react.dev/reference/react/use) của React để truy cập các giá trị.
  - Trong phiên bản 14 và cũ hơn, `params` là một synchronous prop. Để giúp tương thích ngược, bạn vẫn có thể truy cập nó một cách đồng bộ trong Next.js 15, nhưng hành vi này sẽ bị deprecated trong tương lai.

### Layout Props Helper

Bạn có thể type layouts với `LayoutProps` để nhận được `params` được typed mạnh và các named slots được suy ra từ cấu trúc thư mục của bạn. `LayoutProps` là một helper có sẵn toàn cục.

```tsx filename="app/dashboard/layout.tsx"
export default function Layout(props: LayoutProps<'/dashboard'>) {
  return (
    <section>
      {props.children}
      {/* Nếu bạn có app/dashboard/@analytics, nó xuất hiện như một typed slot: */}
      {/* {props.analytics} */}
    </section>
  )
}
```

> **Lưu ý**:
>
> - Types được tạo trong quá trình `next dev`, `next build` hoặc `next typegen`.
> - Sau khi tạo type, helper `LayoutProps` có sẵn toàn cục. Nó không cần phải được import.

### Root Layout

Thư mục `app` **phải** bao gồm một **root layout**, là layout cao nhất trong thư mục root `app`. Thông thường, root layout là `app/layout.js`.

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html>
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html>
      <body>{children}</body>
    </html>
  )
}
```

- Root layout **phải** định nghĩa các thẻ `<html>` và `<body>`.
  - Bạn **không nên** thêm thủ công các thẻ `<head>` như `<title>` và `<meta>` vào root layouts. Thay vào đó, bạn nên sử dụng [Metadata API](/docs/app/getting-started/metadata-and-og-images) tự động xử lý các yêu cầu nâng cao như streaming và de-duplicating các phần tử `<head>`.
- Bạn có thể sử dụng [route groups](/docs/app/api-reference/file-conventions/route-groups) để tạo **nhiều root layouts**.
  - Điều hướng **giữa nhiều root layouts** sẽ gây ra một **full page load** (trái ngược với client-side navigation). Ví dụ, điều hướng từ `/cart` sử dụng `app/(shop)/layout.js` đến `/blog` sử dụng `app/(marketing)/layout.js` sẽ gây ra một full page load. Điều này **chỉ** áp dụng cho nhiều root layouts.
- Root layout có thể nằm dưới một **dynamic segment**, ví dụ khi triển khai [internationalization](/docs/app/guides/internationalization) với `app/[lang]/layout.js`.

## Caveats

### Request Object

Layouts được cache trong client trong quá trình điều hướng để tránh các yêu cầu server không cần thiết.

[Layouts](/docs/app/api-reference/file-conventions/layout) không rerender. Chúng có thể được cache và tái sử dụng để tránh tính toán không cần thiết khi điều hướng giữa các trang. Bằng cách hạn chế layouts truy cập raw request, Next.js có thể ngăn chặn việc thực thi mã người dùng có khả năng chậm hoặc tốn kém trong layout, điều này có thể ảnh hưởng tiêu cực đến hiệu suất.

Để truy cập request object, bạn có thể sử dụng các APIs [`headers`](/docs/app/api-reference/functions/headers) và [`cookies`](/docs/app/api-reference/functions/cookies) trong [Server Components](/docs/app/getting-started/server-and-client-components) và Functions.

```tsx filename="app/shop/layout.tsx" switcher
import { cookies } from 'next/headers'

export default async function Layout({ children }) {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}
```

```jsx filename="app/shop/layout.js" switcher
import { cookies } from 'next/headers'

export default async function Layout({ children }) {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}
```

### Query params

Layouts không rerender khi điều hướng, vì vậy chúng không thể truy cập search params nếu không chúng sẽ trở nên cũ (stale).

Để truy cập các query parameters đã cập nhật, bạn có thể sử dụng prop [`searchParams`](/docs/app/api-reference/file-conventions/page#searchparams-optional) của Page, hoặc đọc chúng bên trong một Client Component sử dụng hook [`useSearchParams`](/docs/app/api-reference/functions/use-search-params). Vì Client Components re-render khi điều hướng, chúng có quyền truy cập vào các query parameters mới nhất.

```tsx filename="app/ui/search.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function Search() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  return '...'
}
```

```jsx filename="app/ui/search.js" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function Search() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  return '...'
}
```

```tsx filename="app/shop/layout.tsx" switcher
import Search from '@/app/ui/search'

  return (
    <>
      <Search />
      {children}
    </>
```


### Pathname

Layouts không re-render khi điều hướng, vì vậy chúng không truy cập pathname nếu không chúng sẽ trở nên cũ (stale).

Để truy cập pathname hiện tại, bạn có thể đọc nó bên trong một Client Component sử dụng hook [`usePathname`](/docs/app/api-reference/functions/use-pathname). Vì Client Components re-render trong quá trình điều hướng, chúng có quyền truy cập vào pathname mới nhất.

```tsx filename="app/ui/breadcrumbs.tsx" switcher
'use client'

import { usePathname } from 'next/navigation'

// Simplified breadcrumbs logic
export default function Breadcrumbs() {
  const pathname = usePathname()
  const segments = pathname.split('/')

  return (
    <nav>
      {segments.map((segment, index) => (
        <span key={index}>
          {' > '}
          {segment}
        </span>
      ))}
    </nav>
  )
}
```


### Fetching Data

Layouts không thể truyền dữ liệu cho `children` của chúng. Tuy nhiên, bạn có thể fetch cùng một dữ liệu trong một route nhiều lần, và sử dụng React [`cache`](https://react.dev/reference/react/cache) để dedupe các requests mà không ảnh hưởng đến hiệu suất.

Ngoài ra, khi sử dụng [`fetch`](/docs/app/api-reference/functions/fetch) trong Next.js, các requests được tự động deduped.

```tsx filename="app/lib/data.ts" switcher
export async function getUser(id: string) {
  const res = await fetch(`https://.../users/${id}`)
  return res.json()
}
```

```tsx filename="app/dashboard/layout.tsx" switcher
import { getUser } from '@/app/lib/data'
import { UserName } from '@/app/ui/user-name'

export default async function Layout({ children }) {
  const user = await getUser('1')

  return (
    <>
      <nav>
        {/* ... */}
        <UserName user={user.name} />
      </nav>
      {children}
    </>
  )
}
```


### Accessing child segments

Layouts không có quyền truy cập vào các route segments bên dưới chính nó. Để truy cập tất cả các route segments, bạn có thể sử dụng [`useSelectedLayoutSegment`](/docs/app/api-reference/functions/use-selected-layout-segment) hoặc [`useSelectedLayoutSegments`](/docs/app/api-reference/functions/use-selected-layout-segments) trong một Client Component.

```tsx filename="app/ui/nav-link.tsx" switcher
'use client'

import Link from 'next/link'
import { useSelectedLayoutSegment } from 'next/navigation'

export default function NavLink({
  slug,
  children,
}: {
  slug: string
  children: React.ReactNode
}) {
  const segment = useSelectedLayoutSegment()
  const isActive = slug === segment

  return (
    <Link
      href={`/blog/${slug}`}
      // Change style depending on whether the link is active
      style={{ fontWeight: isActive ? 'bold' : 'normal' }}
    >
      {children}
    </Link>
  )
}
```

```jsx filename="app/ui/nav-link.js" switcher
'use client'

import Link from 'next/link'
import { useSelectedLayoutSegment } from 'next/navigation'

export default function NavLinks({ slug, children }) {
  const segment = useSelectedLayoutSegment()
  const isActive = slug === segment

  return (
    <Link
      href={`/blog/${slug}`}
      style={{ fontWeight: isActive ? 'bold' : 'normal' }}
    >
      {children}
    </Link>
  )
}
```

```tsx filename="app/blog/layout.tsx" switcher
import { NavLink } from './nav-link'
import getPosts from './get-posts'

export default async function Layout({
  children,
}: {
  children: React.ReactNode
}) {
  const featuredPosts = await getPosts()
  return (
    <div>
      {featuredPosts.map((post) => (
        <div key={post.id}>
          <NavLink slug={post.slug}>{post.title}</NavLink>
        </div>
      ))}
      <div>{children}</div>
    </div>
  )
}
```

## Ví dụ

### Metadata

Bạn có thể sửa đổi các phần tử HTML `<head>` như `title` và `meta` sử dụng [`metadata` object](/docs/app/api-reference/functions/generate-metadata#the-metadata-object) hoặc [`generateMetadata` function](/docs/app/api-reference/functions/generate-metadata#generatemetadata-function).

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'Next.js',
}

export default function Layout({ children }: { children: React.ReactNode }) {
  return '...'
}
```

```jsx filename="app/layout.js" switcher
export const metadata = {
  title: 'Next.js',
}

export default function Layout({ children }) {
  return '...'
}
```

> **Lưu ý**: Bạn **không nên** thêm thủ công các thẻ `<head>` như `<title>` và `<meta>` vào root layouts. Thay vào đó, sử dụng [Metadata APIs](/docs/app/api-reference/functions/generate-metadata) tự động xử lý các yêu cầu nâng cao như streaming và de-duplicating các phần tử `<head>`.

### Active Nav Links

Bạn có thể sử dụng hook [`usePathname`](/docs/app/api-reference/functions/use-pathname) để xác định xem một nav link có đang active hay không.

Vì `usePathname` là một client hook, bạn cần tách các nav links thành một Client Component, có thể được import vào layout của bạn:

```tsx filename="app/ui/nav-links.tsx" switcher
'use client'

import { usePathname } from 'next/navigation'
import Link from 'next/link'

export function NavLinks() {
  const pathname = usePathname()

  return (
    <nav>
      <Link className={`link ${pathname === '/' ? 'active' : ''}`} href="/">
        Home
      </Link>

      <Link
        className={`link ${pathname === '/about' ? 'active' : ''}`}
        href="/about"
      >
        About
      </Link>
    </nav>
  )
}
```

```jsx filename="app/ui/nav-links.js" switcher
'use client'

import { usePathname } from 'next/navigation'
```

### Hiển thị nội dung dựa trên `params`

Sử dụng [dynamic route segments](/docs/app/api-reference/file-conventions/dynamic-routes), bạn có thể hiển thị hoặc fetch nội dung cụ thể dựa trên prop `params`.

```tsx filename="app/dashboard/layout.tsx" switcher
export default async function DashboardLayout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Promise<{ team: string }>
}) {
  const { team } = await params

  return (
    <section>
      <header>
        <h1>Welcome to {team}'s Dashboard</h1>
      </header>
      <main>{children}</main>
    </section>
  )
}
```

```jsx filename="app/dashboard/layout.js" switcher
export default async function DashboardLayout({ children, params }) {
  const { team } = await params

  return (
    <section>
      <header>
        <h1>Welcome to {team}'s Dashboard</h1>
      </header>
      <main>{children}</main>
    </section>
  )
}
```

### Đọc `params` trong Client Components

Để sử dụng `params` trong một Client Component (không thể là `async`), bạn có thể sử dụng hàm [`use`](https://react.dev/reference/react/use) của React để đọc promise:

```tsx filename="app/page.tsx" switcher
'use client'

import { use } from 'react'

export default function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = use(params)
}
```

```js filename="app/page.js" switcher
'use client'

import { use } from 'react'

export default function Page({ params }) {
  const { slug } = use(params)
}
```
