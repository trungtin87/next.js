---

> **Lưu ý**:
>
> - Các tùy chọn được nêu trên trang này bị vô hiệu hóa nếu cờ [`cacheComponents`](/docs/app/api-reference/config/next-config-js/cacheComponents) được bật, và cuối cùng sẽ bị deprecated trong tương lai.
> - Các tùy chọn Route Segment chỉ có hiệu lực trong Server Component Pages, Layouts, hoặc Route Handlers.
> - `generateStaticParams` không thể được sử dụng bên trong một file `'use client'`.

Các tùy chọn Route Segment cho phép bạn cấu hình hành vi của một [Page](/docs/app/api-reference/file-conventions/layout), [Layout](/docs/app/api-reference/file-conventions/layout), hoặc [Route Handler](/docs/app/api-reference/file-conventions/route) bằng cách export trực tiếp các biến sau:

| Tùy chọn                              | Kiểu                                                                                                                      | Mặc định                         |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| [`dynamic`](#dynamic)                 | `'auto' \| 'force-dynamic' \| 'error' \| 'force-static'`                                                                  | `'auto'`                         |
| [`dynamicParams`](#dynamicparams)     | `boolean`                                                                                                                 | `true`                           |
| [`revalidate`](#revalidate)           | `false \| 0 \| number`                                                                                                    | `false`                          |
| [`fetchCache`](#fetchcache)           | `'auto' \| 'default-cache' \| 'only-cache' \| 'force-cache' \| 'force-no-store' \| 'default-no-store' \| 'only-no-store'` | `'auto'`                         |
| [`runtime`](#runtime)                 | `'nodejs' \| 'edge'`                                                                                                      | `'nodejs'`                       |
| [`preferredRegion`](#preferredregion) | `'auto' \| 'global' \| 'home' \| string \| string[]`                                                                      | `'auto'`                         |
| [`maxDuration`](#maxduration)         | `number`                                                                                                                  | Được đặt bởi nền tảng triển khai |

## Tùy chọn

### `dynamic`

Thay đổi hành vi dynamic của một layout hoặc page thành hoàn toàn static hoặc hoàn toàn dynamic.

```tsx filename="layout.tsx | page.tsx | route.ts" switcher
export const dynamic = 'auto'
// 'auto' | 'force-dynamic' | 'error' | 'force-static'
```

```js filename="layout.js | page.js | route.js" switcher
export const dynamic = 'auto'
// 'auto' | 'force-dynamic' | 'error' | 'force-static'
```

> **Lưu ý**: Mô hình mới trong thư mục `app` ủng hộ việc kiểm soát caching chi tiết ở cấp độ request `fetch` hơn là mô hình nhị phân tất cả hoặc không có gì của `getServerSideProps` và `getStaticProps` ở cấp độ page trong thư mục `pages`. Tùy chọn `dynamic` là một cách để opt back in vào mô hình trước đó như một sự tiện lợi và cung cấp một lộ trình di chuyển đơn giản hơn.

- **`'auto'`** (mặc định): Tùy chọn mặc định để cache nhiều nhất có thể mà không ngăn cản bất kỳ components nào opt vào hành vi dynamic.
- **`'force-dynamic'`**: Bắt buộc [dynamic rendering](/docs/app/guides/caching#dynamic-rendering), điều này sẽ dẫn đến việc routes được render cho mỗi người dùng tại request time. Tùy chọn này tương đương với:
  - Đặt tùy chọn của mọi request `fetch()` trong một layout hoặc page thành `{ cache: 'no-store', next: { revalidate: 0 } }`.
  - Đặt segment config thành `export const fetchCache = 'force-no-store'`

- **`'error'`**: Bắt buộc static rendering và cache dữ liệu của một layout hoặc page bằng cách gây ra lỗi nếu bất kỳ components nào sử dụng [Dynamic APIs](/docs/app/guides/caching#dynamic-rendering) hoặc dữ liệu không được cache. Tùy chọn này tương đương với:
  - `getStaticProps()` trong thư mục `pages`.
  - Đặt tùy chọn của mọi request `fetch()` trong một layout hoặc page thành `{ cache: 'force-cache' }`.
  - Đặt segment config thành `fetchCache = 'only-cache'`.
- **`'force-static'`**: Bắt buộc static rendering và cache dữ liệu của một layout hoặc page bằng cách buộc [`cookies`](/docs/app/api-reference/functions/cookies), [`headers()`](/docs/app/api-reference/functions/headers) và [`useSearchParams()`](/docs/app/api-reference/functions/use-search-params) trả về giá trị rỗng. Có thể [`revalidate`](#revalidate), [`revalidatePath`](/docs/app/api-reference/functions/revalidatePath), hoặc [`revalidateTag`](/docs/app/api-reference/functions/revalidateTag), trong pages hoặc layouts được render với `force-static`.

> **Lưu ý**:
>
> - Hướng dẫn về [cách di chuyển](/docs/app/guides/migrating/app-router-migration#step-6-migrating-data-fetching-methods) từ `getServerSideProps` và `getStaticProps` sang `dynamic: 'force-dynamic'` và `dynamic: 'error'` có thể được tìm thấy trong [hướng dẫn nâng cấp](/docs/app/guides/migrating/app-router-migration#step-6-migrating-data-fetching-methods).

### `dynamicParams`

Kiểm soát điều gì xảy ra khi một dynamic segment được truy cập mà không được tạo với [generateStaticParams](/docs/app/api-reference/functions/generate-static-params).

```tsx filename="layout.tsx | page.tsx" switcher
export const dynamicParams = true // true | false
```

```js filename="layout.js | page.js | route.js" switcher
export const dynamicParams = true // true | false
```

- **`true`** (mặc định): Các dynamic segments không được bao gồm trong `generateStaticParams` được tạo theo yêu cầu (on demand).
- **`false`**: Các dynamic segments không được bao gồm trong `generateStaticParams` sẽ trả về 404.

> **Lưu ý**:
>
> - Tùy chọn này thay thế tùy chọn `fallback: true | false | blocking` của `getStaticPaths` trong thư mục `pages`.
> - Để render tĩnh tất cả các paths lần đầu tiên chúng được truy cập, bạn sẽ cần trả về một mảng rỗng trong `generateStaticParams` hoặc sử dụng `export const dynamic = 'force-static'`.
> - Khi `dynamicParams = true`, segment sử dụng [Streaming Server Rendering](/docs/app/getting-started/linking-and-navigating#streaming).

### `revalidate`

Đặt thời gian revalidation mặc định cho một layout hoặc page. Tùy chọn này không ghi đè giá trị `revalidate` được đặt bởi các requests `fetch` riêng lẻ.

```tsx filename="layout.tsx | page.tsx | route.ts" switcher
export const revalidate = false
// false | 0 | number
```

```js filename="layout.js | page.js | route.js" switcher
export const revalidate = false
// false | 0 | number
```

- **`false`** (mặc định): Heuristic mặc định để cache bất kỳ requests `fetch` nào đặt tùy chọn `cache` của chúng thành `'force-cache'` hoặc được phát hiện trước khi một [Dynamic API](/docs/app/guides/caching#dynamic-rendering) được sử dụng. Về mặt ngữ nghĩa tương đương với `revalidate: Infinity` có nghĩa là tài nguyên nên được cache vô thời hạn. Vẫn có thể cho các requests `fetch` riêng lẻ sử dụng `cache: 'no-store'` hoặc `revalidate: 0` để tránh bị cache và làm cho route được render dynamic. Hoặc đặt `revalidate` thành một số dương thấp hơn mặc định của route để tăng tần suất revalidation của một route.
- **`0`**: Đảm bảo một layout hoặc page luôn được [render dynamic](/docs/app/guides/caching#dynamic-rendering) ngay cả khi không có Dynamic APIs hoặc data fetches không được cache nào được phát hiện. Tùy chọn này thay đổi mặc định của các requests `fetch` không đặt tùy chọn `cache` thành `'no-store'` nhưng giữ nguyên các requests `fetch` opt vào `'force-cache'` hoặc sử dụng một `revalidate` dương.
- **`number`**: (tính bằng giây) Đặt tần suất revalidation mặc định của một layout hoặc page thành `n` giây.

> **Lưu ý**:
>
> - Giá trị revalidate cần phải có thể phân tích tĩnh. Ví dụ `revalidate = 600` là hợp lệ, nhưng `revalidate = 60 * 10` thì không.
> - Giá trị revalidate không khả dụng khi sử dụng `runtime = 'edge'`.
> - Trong Development, Pages _luôn_ được render on-demand và không bao giờ được cache. Điều này cho phép bạn thấy các thay đổi ngay lập tức mà không cần đợi thời gian revalidation trôi qua.

#### Tần suất Revalidation

- `revalidate` thấp nhất trên mỗi layout và page của một route đơn lẻ sẽ xác định tần suất revalidation của _toàn bộ_ route. Điều này đảm bảo rằng các child pages được revalidate thường xuyên như các parent layouts của chúng.
- Các requests `fetch` riêng lẻ có thể đặt `revalidate` thấp hơn `revalidate` mặc định của route để tăng tần suất revalidation của toàn bộ route. Điều này cho phép bạn opt-in dynamic vào revalidation thường xuyên hơn cho các routes nhất định dựa trên một số tiêu chí.

### `fetchCache`

<details>
  <summary>Đây là một tùy chọn nâng cao chỉ nên được sử dụng nếu bạn đặc biệt cần ghi đè hành vi mặc định.</summary>

Mặc định, Next.js **sẽ cache** bất kỳ requests `fetch()` nào có thể truy cập được **trước khi** bất kỳ [Dynamic APIs](/docs/app/guides/caching#dynamic-rendering) nào được sử dụng và **sẽ không cache** các requests `fetch` được phát hiện **sau khi** Dynamic APIs được sử dụng.

`fetchCache` cho phép bạn ghi đè tùy chọn `cache` mặc định của tất cả các requests `fetch` trong một layout hoặc page.

```tsx filename="layout.tsx | page.tsx | route.ts" switcher
export const fetchCache = 'auto'
// 'auto' | 'default-cache' | 'only-cache'
// 'force-cache' | 'force-no-store' | 'default-no-store' | 'only-no-store'
```

```js filename="layout.js | page.js | route.js" switcher
export const fetchCache = 'auto'
// 'auto' | 'default-cache' | 'only-cache'
// 'force-cache' | 'force-no-store' | 'default-no-store' | 'only-no-store'
```

- **`'auto'`** (mặc định): Tùy chọn mặc định để cache các requests `fetch` trước Dynamic APIs với tùy chọn `cache` mà chúng cung cấp và không cache các requests `fetch` sau Dynamic APIs.
- **`'default-cache'`**: Cho phép bất kỳ tùy chọn `cache` nào được truyền cho `fetch` nhưng nếu không có tùy chọn nào được cung cấp thì đặt tùy chọn `cache` thành `'force-cache'`. Điều này có nghĩa là ngay cả các requests `fetch` sau Dynamic APIs cũng được coi là static.
- **`'only-cache'`**: Đảm bảo tất cả các requests `fetch` opt vào caching bằng cách thay đổi mặc định thành `cache: 'force-cache'` nếu không có tùy chọn nào được cung cấp và gây ra lỗi nếu bất kỳ requests `fetch` nào sử dụng `cache: 'no-store'`.
- **`'force-cache'`**: Đảm bảo tất cả các requests `fetch` opt vào caching bằng cách đặt tùy chọn `cache` của tất cả các requests `fetch` thành `'force-cache'`.
- **`'default-no-store'`**: Cho phép bất kỳ tùy chọn `cache` nào được truyền cho `fetch` nhưng nếu không có tùy chọn nào được cung cấp thì đặt tùy chọn `cache` thành `'no-store'`. Điều này có nghĩa là ngay cả các requests `fetch` trước Dynamic APIs cũng được coi là dynamic.
- **`'only-no-store'`**: Đảm bảo tất cả các requests `fetch` opt out khỏi caching bằng cách thay đổi mặc định thành `cache: 'no-store'` nếu không có tùy chọn nào được cung cấp và gây ra lỗi nếu bất kỳ requests `fetch` nào sử dụng `cache: 'force-cache'`
- **`'force-no-store'`**: Đảm bảo tất cả các requests `fetch` opt out khỏi caching bằng cách đặt tùy chọn `cache` của tất cả các requests `fetch` thành `'no-store'`. Điều này buộc tất cả các requests `fetch` phải được fetch lại mỗi request ngay cả khi chúng cung cấp tùy chọn `'force-cache'`.

#### Hành vi Cross-route segment

- Bất kỳ tùy chọn nào được đặt trên mỗi layout và page của một route đơn lẻ cần phải tương thích với nhau.
  - Nếu cả `'only-cache'` và `'force-cache'` đều được cung cấp, thì `'force-cache'` thắng. Nếu cả `'only-no-store'` và `'force-no-store'` đều được cung cấp, thì `'force-no-store'` thắng. Tùy chọn force thay đổi hành vi trên toàn bộ route vì vậy một segment đơn lẻ với `'force-*'` sẽ ngăn chặn bất kỳ lỗi nào gây ra bởi `'only-*'`.
  - Mục đích của các tùy chọn `'only-*'` và `'force-*'` là để đảm bảo toàn bộ route hoặc là hoàn toàn static hoặc là hoàn toàn dynamic. Điều này có nghĩa là:
    - Sự kết hợp của `'only-cache'` và `'only-no-store'` trong một route đơn lẻ là không được phép.
    - Sự kết hợp của `'force-cache'` và `'force-no-store'` trong một route đơn lẻ là không được phép.
  - Một parent không thể cung cấp `'default-no-store'` nếu một child cung cấp `'auto'` hoặc `'*-cache'` vì điều đó có thể làm cho cùng một fetch có hành vi khác nhau.
- Thường được khuyến nghị để các shared parent layouts là `'auto'` và tùy chỉnh các tùy chọn nơi các child segments khác biệt.

</details>

### `runtime`

Chúng tôi khuyên bạn nên sử dụng Node.js runtime để render ứng dụng của bạn. Tùy chọn này không thể được sử dụng trong [Proxy](/docs/app/api-reference/file-conventions/proxy).

> **Lưu ý**: Sử dụng `runtime: 'edge'` là **không được hỗ trợ** cho Cache Components.

```tsx filename="layout.tsx | page.tsx | route.ts" switcher
export const runtime = 'nodejs'
// 'nodejs' | 'edge'
```

```js filename="layout.js | page.js | route.js" switcher
export const runtime = 'nodejs'
// 'nodejs' | 'edge'
```

- **`'nodejs'`** (mặc định)
- **`'edge'`**

### `preferredRegion`

```tsx filename="layout.tsx | page.tsx | route.ts" switcher
export const preferredRegion = 'auto'
// 'auto' | 'global' | 'home' | ['iad1', 'sfo1']
```

```js filename="layout.js | page.js | route.js" switcher
export const preferredRegion = 'auto'
// 'auto' | 'global' | 'home' | ['iad1', 'sfo1']
```

Hỗ trợ cho `preferredRegion`, và các regions được hỗ trợ, phụ thuộc vào nền tảng triển khai của bạn.

> **Lưu ý**:
>
> - Nếu một `preferredRegion` không được chỉ định, nó sẽ kế thừa tùy chọn của parent layout gần nhất.
> - Root layout mặc định là `all` regions.

### `maxDuration`

Mặc định, Next.js không giới hạn việc thực thi logic server-side (render một page hoặc xử lý một API).
Các nền tảng triển khai có thể sử dụng `maxDuration` từ output build của Next.js để thêm các giới hạn thực thi cụ thể.

**Lưu ý**: Cài đặt này yêu cầu Next.js `13.4.10` hoặc cao hơn.

```tsx filename="layout.tsx | page.tsx | route.ts" switcher
export const maxDuration = 5
```

```js filename="layout.js | page.js | route.js" switcher
export const maxDuration = 5
```

> **Lưu ý**:
>
> - Nếu sử dụng [Server Actions](/docs/app/getting-started/updating-data), đặt `maxDuration` ở cấp độ page để thay đổi timeout mặc định của tất cả các Server Actions được sử dụng trên page.

### `generateStaticParams`

Hàm `generateStaticParams` có thể được sử dụng kết hợp với [dynamic route segments](/docs/app/api-reference/file-conventions/dynamic-routes) để định nghĩa danh sách các tham số route segment sẽ được tạo tĩnh tại build time thay vì on-demand tại request time.

Xem [API reference](/docs/app/api-reference/functions/generate-static-params) để biết thêm chi tiết.
