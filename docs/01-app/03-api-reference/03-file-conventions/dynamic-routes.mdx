Khi bạn không biết trước tên route segment chính xác và muốn tạo routes từ dynamic data, bạn có thể sử dụng Dynamic Segments được điền vào tại request time hoặc prerendered tại build time.

## Quy ước

Một Dynamic Segment có thể được tạo bằng cách bao quanh tên folder trong dấu ngoặc vuông: `[folderName]`. Ví dụ, một blog có thể bao gồm route `app/blog/[slug]/page.js` nơi `[slug]` là Dynamic Segment cho các bài đăng blog.

```tsx filename="app/blog/[slug]/page.tsx" switcher
export default async function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  return <div>My Post: {slug}</div>
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
export default async function Page({ params }) {
  const { slug } = await params
  return <div>My Post: {slug}</div>
}
```

Dynamic Segments được truyền dưới dạng prop `params` cho các hàm [`layout`](/docs/app/api-reference/file-conventions/layout), [`page`](/docs/app/api-reference/file-conventions/page), [`route`](/docs/app/api-reference/file-conventions/route), và [`generateMetadata`](/docs/app/api-reference/functions/generate-metadata#generatemetadata-function).

| Route                     | Example URL | `params`        |
| ------------------------- | ----------- | --------------- |
| `app/blog/[slug]/page.js` | `/blog/a`   | `{ slug: 'a' }` |
| `app/blog/[slug]/page.js` | `/blog/b`   | `{ slug: 'b' }` |
| `app/blog/[slug]/page.js` | `/blog/c`   | `{ slug: 'c' }` |

### Trong Client Components

Trong một Client Component **page**, dynamic segments từ props có thể được truy cập bằng cách sử dụng hook [`use`](https://react.dev/reference/react/use).

```tsx filename="app/blog/[slug]/page.tsx" switcher
'use client'
import { use } from 'react'

export default function BlogPostPage({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = use(params)

  return (
    <div>
      <p>{slug}</p>
    </div>
  )
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
'use client'
import { use } from 'react'
import { useParams } from 'next/navigation'

export default function BlogPostPage({ params }) {
  const { slug } = use(params)

  return (
    <div>
      <p>{slug}</p>
    </div>
  )
}
```

Ngoài ra, Client Components có thể sử dụng hook [`useParams`](/docs/app/api-reference/functions/use-params) để truy cập `params` ở bất kỳ đâu trong Client Component tree.

### Catch-all Segments

Dynamic Segments có thể được mở rộng để **catch-all** (bắt tất cả) các segments tiếp theo bằng cách thêm dấu ba chấm bên trong dấu ngoặc vuông `[...folderName]`.

Ví dụ, `app/shop/[...slug]/page.js` sẽ khớp với `/shop/clothes`, nhưng cũng khớp với `/shop/clothes/tops`, `/shop/clothes/tops/t-shirts`, và vân vân.

| Route                        | Example URL   | `params`                    |
| ---------------------------- | ------------- | --------------------------- |
| `app/shop/[...slug]/page.js` | `/shop/a`     | `{ slug: ['a'] }`           |
| `app/shop/[...slug]/page.js` | `/shop/a/b`   | `{ slug: ['a', 'b'] }`      |
| `app/shop/[...slug]/page.js` | `/shop/a/b/c` | `{ slug: ['a', 'b', 'c'] }` |

### Optional Catch-all Segments

Catch-all Segments có thể được làm thành **optional** (tùy chọn) bằng cách bao gồm tham số trong dấu ngoặc vuông kép: `[[...folderName]]`.

Ví dụ, `app/shop/[[...slug]]/page.js` sẽ **cũng** khớp với `/shop`, ngoài `/shop/clothes`, `/shop/clothes/tops`, `/shop/clothes/tops/t-shirts`.

Sự khác biệt giữa **catch-all** và **optional catch-all** segments là với optional, route không có tham số cũng được khớp (`/shop` trong ví dụ trên).

| Route                          | Example URL   | `params`                    |
| ------------------------------ | ------------- | --------------------------- |
| `app/shop/[[...slug]]/page.js` | `/shop`       | `{ slug: undefined }`       |
| `app/shop/[[...slug]]/page.js` | `/shop/a`     | `{ slug: ['a'] }`           |
| `app/shop/[[...slug]]/page.js` | `/shop/a/b`   | `{ slug: ['a', 'b'] }`      |
| `app/shop/[[...slug]]/page.js` | `/shop/a/b/c` | `{ slug: ['a', 'b', 'c'] }` |

### TypeScript

Khi sử dụng TypeScript, bạn có thể thêm types cho `params` tùy thuộc vào route segment đã cấu hình của bạn — sử dụng [`PageProps<'/route'>`](/docs/app/api-reference/file-conventions/page#page-props-helper), [`LayoutProps<'/route'>`](/docs/app/api-reference/file-conventions/layout#layout-props-helper), hoặc [`RouteContext<'/route'>`](/docs/app/api-reference/file-conventions/route#route-context-helper) để type `params` trong `page`, `layout`, và `route` tương ứng.

Route `params` values được typed là `string`, `string[]`, hoặc `undefined` (cho optional catch-all segments), bởi vì giá trị của chúng không được biết cho đến runtime. Người dùng có thể nhập bất kỳ URL nào vào thanh địa chỉ, và các broad types này giúp đảm bảo rằng mã ứng dụng của bạn xử lý tất cả các trường hợp có thể xảy ra này.

| Route                               | `params` Type Definition                 |
| ----------------------------------- | ---------------------------------------- |
| `app/blog/[slug]/page.js`           | `{ slug: string }`                       |
| `app/shop/[...slug]/page.js`        | `{ slug: string[] }`                     |
| `app/shop/[[...slug]]/page.js`      | `{ slug?: string[] }`                    |
| `app/[categoryId]/[itemId]/page.js` | `{ categoryId: string, itemId: string }` |

Nếu bạn đang làm việc trên một route nơi `params` chỉ có thể có một số lượng giá trị hợp lệ cố định, chẳng hạn như một `[locale]` param với một tập hợp mã ngôn ngữ đã biết, bạn có thể sử dụng runtime validation để xử lý bất kỳ params không hợp lệ nào mà người dùng có thể nhập, và để phần còn lại của ứng dụng của bạn làm việc với type hẹp hơn từ tập hợp đã biết của bạn.

```tsx filename="/app/[locale]/page.tsx"
import { notFound } from 'next/navigation'
import type { Locale } from '@i18n/types'
import { isValidLocale } from '@i18n/utils'

function assertValidLocale(value: string): asserts value is Locale {
  if (!isValidLocale(value)) notFound()
}

export default async function Page(props: PageProps<'/[locale]'>) {
  const { locale } = await props.params // locale is typed as string
  assertValidLocale(locale)
  // locale is now typed as Locale
}
```

## Hành vi

- Vì prop `params` là một promise. Bạn phải sử dụng `async`/`await` hoặc hàm use của React để truy cập các giá trị.
  - Trong phiên bản 14 và cũ hơn, `params` là một synchronous prop. Để giúp tương thích ngược, bạn vẫn có thể truy cập nó một cách đồng bộ trong Next.js 15, nhưng hành vi này sẽ bị deprecated trong tương lai.

## Ví dụ

### Với `generateStaticParams`

Hàm [`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params) có thể được sử dụng để [tạo tĩnh](/docs/app/guides/caching#static-rendering) các routes tại build time thay vì theo yêu cầu tại request time.

```tsx filename="app/blog/[slug]/page.tsx" switcher
export async function generateStaticParams() {
  const posts = await fetch('https://.../posts').then((res) => res.json())

  return posts.map((post) => ({
    slug: post.slug,
  }))
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
export async function generateStaticParams() {
  const posts = await fetch('https://.../posts').then((res) => res.json())

  return posts.map((post) => ({
    slug: post.slug,
  }))
}
```

Khi sử dụng `fetch` bên trong hàm `generateStaticParams`, các requests được [tự động deduplicated](/docs/app/guides/caching#request-memoization). Điều này tránh nhiều cuộc gọi mạng cho cùng một dữ liệu Layouts, Pages, và các hàm `generateStaticParams` khác, tăng tốc độ build time.
