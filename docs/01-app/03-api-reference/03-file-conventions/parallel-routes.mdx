Parallel Routes (Các tuyến song song) cho phép bạn render đồng thời hoặc có điều kiện một hoặc nhiều pages trong cùng một layout. Chúng hữu ích cho các phần có tính dynamic cao của một ứng dụng, chẳng hạn như dashboards và feeds trên các trang xã hội.

Ví dụ, xem xét một dashboard, bạn có thể sử dụng parallel routes để render đồng thời các trang `team` và `analytics`:

## Quy ước

### Slots

Parallel routes được tạo bằng cách sử dụng các **slots** được đặt tên. Slots được định nghĩa với quy ước `@folder`. Ví dụ, cấu trúc file sau định nghĩa hai slots: `@analytics` và `@team`:

<Image
  alt="Cấu trúc File-system Parallel Routes"
  srcLight="/docs/light/parallel-routes-file-system.png"
  srcDark="/docs/dark/parallel-routes-file-system.png"
  width="1600"
  height="687"
/>

Slots được truyền dưới dạng props cho parent layout được chia sẻ. Đối với ví dụ trên, component trong `app/layout.js` bây giờ chấp nhận các props slots `@analytics` và `@team`, và có thể render chúng song song cùng với prop `children`:

```tsx filename="app/layout.tsx" switcher
export default function Layout({
  children,
  team,
  analytics,
}: {
  children: React.ReactNode
  analytics: React.ReactNode
  team: React.ReactNode
}) {
  return (
    <>
      {children}
      {team}
      {analytics}
    </>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function Layout({ children, team, analytics }) {
  return (
    <>
      {children}
      {team}
      {analytics}
    </>
  )
}
```

Tuy nhiên, slots **không phải** là route segments và không ảnh hưởng đến cấu trúc URL. Ví dụ, đối với `/@analytics/views`, URL sẽ là `/views` vì `@analytics` là một slot. Slots được kết hợp với component [Page](/docs/app/api-reference/file-conventions/page) thông thường để tạo thành trang cuối cùng được liên kết với route segment. Vì lý do này, bạn không thể có các slots [static](/docs/app/guides/caching#static-rendering) và [dynamic](/docs/app/guides/caching#dynamic-rendering) riêng biệt ở cùng một cấp độ route segment. Nếu một slot là dynamic, tất cả các slots ở cấp độ đó phải là dynamic.

> **Lưu ý**:
>
> - Prop `children` là một slot ngầm định không cần phải map với một folder. Điều này có nghĩa là `app/page.js` tương đương với `app/@children/page.js`.

### `default.js`

Bạn có thể định nghĩa một file `default.js` để render như một fallback cho các slots không khớp trong quá trình tải ban đầu hoặc tải lại toàn trang.

Xem xét cấu trúc thư mục sau. Slot `@team` có một trang `/settings`, nhưng `@analytics` thì không.

<Image
  alt="Parallel Routes unmatched routes"
  srcLight="/docs/light/parallel-routes-unmatched-routes.png"
  srcDark="/docs/dark/parallel-routes-unmatched-routes.png"
  width="1600"
  height="930"
/>

Khi điều hướng đến `/settings`, slot `@team` sẽ render trang `/settings` trong khi duy trì trang đang hoạt động hiện tại cho slot `@analytics`.

Khi refresh, Next.js sẽ render một `default.js` cho `@analytics`. Nếu `default.js` không tồn tại, một `404` được render thay thế.

Ngoài ra, vì `children` là một slot ngầm định, bạn cũng cần tạo một file `default.js` để render một fallback cho `children` khi Next.js không thể khôi phục trạng thái hoạt động của parent page.

## Hành vi

Mặc định, Next.js theo dõi _trạng thái_ (hoặc subpage) đang hoạt động cho mỗi slot. Tuy nhiên, nội dung được render trong một slot sẽ phụ thuộc vào loại điều hướng:

- [**Soft Navigation**](/docs/app/getting-started/linking-and-navigating#client-side-transitions): Trong quá trình client-side navigation, Next.js sẽ thực hiện một [partial render](/docs/app/getting-started/linking-and-navigating#client-side-transitions), thay đổi subpage trong slot, trong khi duy trì các subpages đang hoạt động của slot khác, ngay cả khi chúng không khớp với URL hiện tại.
- **Hard Navigation**: Sau khi tải toàn trang (browser refresh), Next.js không thể xác định trạng thái hoạt động cho các slots không khớp với URL hiện tại. Thay vào đó, nó sẽ render một file [`default.js`](#defaultjs) cho các slots không khớp, hoặc `404` nếu `default.js` không tồn tại.

> **Lưu ý**:
>
> - `404` cho các routes không khớp giúp đảm bảo rằng bạn không vô tình render một parallel route trên một trang mà nó không được dự định.

## Ví dụ

### Với `useSelectedLayoutSegment(s)`

Cả [`useSelectedLayoutSegment`](/docs/app/api-reference/functions/use-selected-layout-segment) và [`useSelectedLayoutSegments`](/docs/app/api-reference/functions/use-selected-layout-segments) đều chấp nhận một tham số `parallelRoutesKey`, cho phép bạn đọc route segment đang hoạt động trong một slot.

```tsx filename="app/layout.tsx" switcher
'use client'

import { useSelectedLayoutSegment } from 'next/navigation'

export default function Layout({ auth }: { auth: React.ReactNode }) {
  const loginSegment = useSelectedLayoutSegment('auth')
  // ...
}
```

```jsx filename="app/layout.js" switcher
'use client'

import { useSelectedLayoutSegment } from 'next/navigation'

export default function Layout({ auth }) {
  const loginSegment = useSelectedLayoutSegment('auth')
  // ...
}
```

Khi một người dùng điều hướng đến `app/@auth/login` (hoặc `/login` trong thanh URL), `loginSegment` sẽ bằng chuỗi `"login"`.

### Conditional Routes

Bạn có thể sử dụng Parallel Routes để render routes có điều kiện dựa trên các điều kiện nhất định, chẳng hạn như vai trò người dùng. Ví dụ, để render một trang dashboard khác nhau cho các vai trò `/admin` hoặc `/user`:

<Image
  alt="Sơ đồ Conditional routes"
  srcLight="/docs/light/conditional-routes-ui.png"
  srcDark="/docs/dark/conditional-routes-ui.png"
  width="1600"
  height="898"
/>

```tsx filename="app/dashboard/layout.tsx" switcher
import { checkUserRole } from '@/lib/auth'

export default function Layout({
  user,
  admin,
}: {
  user: React.ReactNode
  admin: React.ReactNode
}) {
  const role = checkUserRole()
  return role === 'admin' ? admin : user
}
```

```jsx filename="app/dashboard/layout.js" switcher
import { checkUserRole } from '@/lib/auth'

export default function Layout({ user, admin }) {
  const role = checkUserRole()
  return role === 'admin' ? admin : user
}
```

### Tab Groups

Bạn có thể thêm một `layout` bên trong một slot để cho phép người dùng điều hướng slot một cách độc lập. Điều này hữu ích để tạo các tabs.

Ví dụ, slot `@analytics` có hai subpages: `/page-views` và `/visitors`.

<Image
  alt="Analytics slot với hai subpages và một layout"
  srcLight="/docs/light/parallel-routes-tab-groups.png"
  srcDark="/docs/dark/parallel-routes-tab-groups.png"
  width="1600"
  height="768"
/>

Bên trong `@analytics`, tạo một file [`layout`](/docs/app/api-reference/file-conventions/layout) để chia sẻ các tabs giữa hai trang:

```tsx filename="app/@analytics/layout.tsx" switcher
import Link from 'next/link'

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <nav>
        <Link href="/page-views">Page Views</Link>
        <Link href="/visitors">Visitors</Link>
      </nav>
      <div>{children}</div>
    </>
  )
}
```

```jsx filename="app/@analytics/layout.js" switcher
import Link from 'next/link'

export default function Layout({ children }) {
  return (
    <>
      <nav>
        <Link href="/page-views">Page Views</Link>
        <Link href="/visitors">Visitors</Link>
      </nav>
      <div>{children}</div>
    </>
  )
}
```

### Modals

Parallel Routes có thể được sử dụng cùng với [Intercepting Routes](/docs/app/api-reference/file-conventions/intercepting-routes) để tạo các modals hỗ trợ deep linking. Điều này cho phép bạn giải quyết các thách thức phổ biến khi xây dựng modals, chẳng hạn như:

- Làm cho nội dung modal **có thể chia sẻ qua URL**.
- **Bảo tồn ngữ cảnh** khi trang được refresh, thay vì đóng modal.
- **Đóng modal khi điều hướng quay lại (backwards navigation)** thay vì đi đến route trước đó.
- **Mở lại modal khi điều hướng chuyển tiếp (forwards navigation)**.

Xem xét UI pattern sau, nơi một người dùng có thể mở một login modal từ một layout sử dụng client-side navigation, hoặc truy cập một trang `/login` riêng biệt:

Để triển khai pattern này, bắt đầu bằng cách tạo một route `/login` render trang login **chính** của bạn.

<Image

```tsx filename="app/login/page.tsx" switcher
import { Login } from '@/app/ui/login'

export default function Page() {
  return <Login />
}
```

```jsx filename="app/login/page.js" switcher
import { Login } from '@/app/ui/login'

export default function Page() {
  return <Login />
}
```

Sau đó, bên trong slot `@auth`, thêm file [`default.js`](/docs/app/api-reference/file-conventions/default) trả về `null`. Điều này đảm bảo rằng modal không được render khi nó không hoạt động.

```tsx filename="app/@auth/default.tsx" switcher
export default function Default() {
  return null
}
```

```jsx filename="app/@auth/default.js" switcher
export default function Default() {
  return null
}
```

Bên trong slot `@auth` của bạn, chặn route `/login` bằng cách import component `<Modal>` và children của nó vào file `@auth/(.)login/page.tsx`, và cập nhật tên thư mục thành `/@auth/(.)login/page.tsx`.

```tsx filename="app/@auth/(.)login/page.tsx" switcher
import { Modal } from '@/app/ui/modal'
import { Login } from '@/app/ui/login'

export default function Page() {
  return (
    <Modal>
      <Login />
    </Modal>
  )
}
```

```jsx filename="app/@auth/(.)login/page.js" switcher
import { Modal } from '@/app/ui/modal'
import { Login } from '@/app/ui/login'

export default function Page() {
  return (
    <Modal>
      <Login />
    </Modal>
  )
}
```

> **Lưu ý:**
>
> - Quy ước `(.)` được sử dụng cho intercepting routes. Xem tài liệu [Intercepting Routes](/docs/app/api-reference/file-conventions/intercepting-routes#convention) để biết thêm thông tin.
> - Bằng cách tách chức năng `<Modal>` khỏi nội dung modal (`<Login>`), bạn có thể đảm bảo bất kỳ nội dung nào bên trong modal, ví dụ [forms](/docs/app/guides/forms), là Server Components. Xem [Interleaving Client and Server Components](/docs/app/getting-started/server-and-client-components#examples#supported-pattern-passing-server-components-to-client-components-as-props) để biết thêm thông tin.

#### Mở modal

Bây giờ, bạn có thể tận dụng Next.js router để mở và đóng modal. Điều này đảm bảo URL được cập nhật chính xác khi modal mở, và khi điều hướng lùi và tiến.

Để mở modal, truyền slot `@auth` dưới dạng prop cho parent layout và render nó cùng với prop `children`.

```tsx filename="app/layout.tsx" switcher
import Link from 'next/link'

export default function Layout({
  auth,
  children,
}: {
  auth: React.ReactNode
  children: React.ReactNode
}) {
  return (
    <>
      <nav>
        <Link href="/login">Open modal</Link>
      </nav>
      <div>{auth}</div>
      <div>{children}</div>
    </>
  )
}
```

```jsx filename="app/layout.js" switcher
import Link from 'next/link'

export default function Layout({ auth, children }) {
  return (
    <>
      <nav>
        <Link href="/login">Open modal</Link>
      </nav>
      <div>{auth}</div>
      <div>{children}</div>
    </>
  )
}
```

Khi người dùng nhấp vào `<Link>`, modal sẽ mở thay vì điều hướng đến trang `/login`. Tuy nhiên, khi refresh hoặc tải ban đầu, điều hướng đến `/login` sẽ đưa người dùng đến trang login chính.

#### Đóng modal

Bạn có thể đóng modal bằng cách gọi `router.back()` hoặc bằng cách sử dụng component `Link`.

```tsx filename="app/ui/modal.tsx" switcher
'use client'

import { useRouter } from 'next/navigation'

export function Modal({ children }: { children: React.ReactNode }) {
  const router = useRouter()

  return (
    <>
      <button
        onClick={() => {
          router.back()
        }}
      >
        Close modal
      </button>
      <div>{children}</div>
    </>
  )
}
```

```jsx filename="app/ui/modal.js" switcher
'use client'

import { useRouter } from 'next/navigation'

export function Modal({ children }) {
  const router = useRouter()

  return (
    <>
      <button
        onClick={() => {
          router.back()
        }}
      >
        Close modal
      </button>
      <div>{children}</div>
    </>
  )
}
```

Khi sử dụng component `Link` để điều hướng khỏi một trang không nên render slot `@auth` nữa, chúng ta cần đảm bảo parallel route khớp với một component trả về `null`. Ví dụ, khi điều hướng quay lại trang root, chúng ta tạo một component `@auth/page.tsx`:

```tsx filename="app/ui/modal.tsx" switcher
import Link from 'next/link'

export function Modal({ children }: { children: React.ReactNode }) {
  return (
    <>
      <Link href="/">Close modal</Link>
      <div>{children}</div>
    </>
  )
}
```

```jsx filename="app/ui/modal.js" switcher
import Link from 'next/link'

export function Modal({ children }) {
  return (
    <>
      <Link href="/">Close modal</Link>
      <div>{children}</div>
    </>
  )
}
```

```tsx filename="app/@auth/page.tsx" switcher
export default function Page() {
  return null
}
```

```jsx filename="app/@auth/page.js" switcher
export default function Page() {
  return null
}
```

Hoặc nếu điều hướng đến bất kỳ trang nào khác (chẳng hạn như `/foo`, `/foo/bar`, v.v.), bạn có thể sử dụng một catch-all slot:

```tsx filename="app/@auth/[...catchAll]/page.tsx" switcher
export default function CatchAll() {
  return null
}
```

```jsx filename="app/@auth/[...catchAll]/page.js" switcher
export default function CatchAll() {
  return null
}
```

> **Lưu ý:**
>
> - Chúng ta sử dụng một catch-all route trong slot `@auth` của mình để đóng modal vì cách parallel routes hoạt động. Vì client-side navigations đến một route không còn khớp với slot sẽ vẫn hiển thị, chúng ta cần khớp slot với một route trả về `null` để đóng modal.
> - Các ví dụ khác có thể bao gồm mở một photo modal trong một gallery trong khi cũng có một trang `/photo/[id]` chuyên dụng, hoặc mở một giỏ hàng trong một side modal.
> - [Xem một ví dụ](https://github.com/vercel-labs/nextgram) về modals với Intercepted và Parallel Routes.
