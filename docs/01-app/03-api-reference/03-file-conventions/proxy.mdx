> **Lưu ý**: File convention `middleware` đã bị deprecated và được đổi tên thành `proxy`. Xem [Di chuyển sang Proxy](#migration-to-proxy) để biết thêm chi tiết.

File `proxy.js|ts` được sử dụng để viết [Proxy](/docs/app/getting-started/proxy) và chạy mã trên server trước khi một yêu cầu được hoàn thành. Sau đó, dựa trên yêu cầu đến, bạn có thể sửa đổi phản hồi bằng cách viết lại (rewriting), chuyển hướng (redirecting), sửa đổi request hoặc response headers, hoặc phản hồi trực tiếp.

Proxy thực thi trước khi các routes được render. Nó đặc biệt hữu ích để triển khai logic server-side tùy chỉnh như xác thực, logging, hoặc xử lý chuyển hướng.

> **Lưu ý**:
>
> Proxy được thiết kế để được gọi riêng biệt với mã render của bạn và trong các trường hợp được tối ưu hóa được triển khai đến CDN của bạn để xử lý redirect/rewrite nhanh chóng, bạn không nên cố gắng dựa vào các modules hoặc globals được chia sẻ.
>
> Để truyền thông tin từ Proxy đến ứng dụng của bạn, sử dụng [headers](#setting-headers), [cookies](#using-cookies), [rewrites](/docs/app/api-reference/functions/next-response#rewrite), [redirects](/docs/app/api-reference/functions/next-response#redirect), hoặc URL.

Tạo một file `proxy.ts` (hoặc `.js`) trong project root, hoặc bên trong `src` nếu có, để nó nằm cùng cấp với `pages` hoặc `app`.

Nếu bạn đã tùy chỉnh [`pageExtensions`](/docs/app/api-reference/config/next-config-js/pageExtensions), ví dụ thành `.page.ts` hoặc `.page.js`, hãy đặt tên file của bạn là `proxy.page.ts` hoặc `proxy.page.js` tương ứng.

```tsx filename="proxy.ts" switcher
import { NextResponse, NextRequest } from 'next/server'

// Hàm này có thể được đánh dấu là `async` nếu sử dụng `await` bên trong
export function proxy(request: NextRequest) {
  return NextResponse.redirect(new URL('/home', request.url))
}

export const config = {
  matcher: '/about/:path*',
}
```

```js filename="proxy.js" switcher
import { NextResponse } from 'next/server'

// Hàm này có thể được đánh dấu là `async` nếu sử dụng `await` bên trong
export function proxy(request) {
  return NextResponse.redirect(new URL('/home', request.url))
}

export const config = {
  matcher: '/about/:path*',
}
```

## Exports

### Proxy function

File phải export một hàm duy nhất, hoặc dưới dạng default export hoặc được đặt tên là `proxy`. Lưu ý rằng nhiều proxy từ cùng một file không được hỗ trợ.

```js filename="proxy.js"
// Ví dụ về default export
export default function proxy(request) {
  // Logic Proxy
}
```

### Config object (tùy chọn)

Tùy chọn, một config object có thể được export cùng với hàm Proxy. Object này bao gồm [matcher](#matcher) để chỉ định các paths nơi Proxy áp dụng.

### Matcher

Tùy chọn `matcher` cho phép bạn nhắm mục tiêu các paths cụ thể để Proxy chạy trên đó. Bạn có thể chỉ định các paths này theo nhiều cách:

- Đối với một path đơn lẻ: Sử dụng trực tiếp một chuỗi để định nghĩa path, như `'/about'`.
- Đối với nhiều paths: Sử dụng một mảng để liệt kê nhiều paths, chẳng hạn như `matcher: ['/about', '/contact']`, áp dụng Proxy cho cả `/about` và `/contact`.

```js filename="proxy.js"
export const config = {
  matcher: ['/about/:path*', '/dashboard/:path*'],
}
```

Ngoài ra, tùy chọn `matcher` hỗ trợ các đặc tả path phức tạp thông qua regular expressions, chẳng hạn như `matcher: ['/((?!api|_next/static|_next/image|.*\\.png$).*)']`, cho phép kiểm soát chính xác các paths nào được bao gồm hoặc loại trừ.

Tùy chọn `matcher` chấp nhận một mảng các objects với các keys sau:

- `source`: Path hoặc pattern được sử dụng để khớp với các request paths. Nó có thể là một chuỗi để khớp path trực tiếp hoặc một pattern để khớp phức tạp hơn.
- `regexp` (tùy chọn): Một chuỗi regular expression tinh chỉnh việc khớp dựa trên source. Nó cung cấp thêm quyền kiểm soát đối với các paths nào được bao gồm hoặc loại trừ.
- `locale` (tùy chọn): Một boolean, khi được đặt thành `false`, bỏ qua routing dựa trên locale trong việc khớp path.
- `has` (tùy chọn): Chỉ định các điều kiện dựa trên sự hiện diện của các yếu tố request cụ thể như headers, query parameters, hoặc cookies.
- `missing` (tùy chọn): Tập trung vào các điều kiện nơi các yếu tố request nhất định bị thiếu, như thiếu headers hoặc cookies.

```js filename="proxy.js"
export const config = {
  matcher: [
    {
      source: '/api/*',
      regexp: '^/api/(.*)',
      locale: false,
      has: [
        { type: 'header', key: 'Authorization', value: 'Bearer Token' },
        { type: 'query', key: 'userId', value: '123' },
      ],
      missing: [{ type: 'cookie', key: 'session', value: 'active' }],
    },
  ],
}
```

Các matchers đã cấu hình:

1. PHẢI bắt đầu bằng `/`
2. Có thể bao gồm các tham số được đặt tên: `/about/:path` khớp với `/about/a` và `/about/b` nhưng không khớp với `/about/a/c`
3. Có thể có các modifiers trên các tham số được đặt tên (bắt đầu bằng `:`): `/about/:path*` khớp với `/about/a/b/c` vì `*` là _zero or more_. `?` là _zero or one_ và `+` là _one or more_
4. Có thể sử dụng regular expression được bao quanh trong dấu ngoặc đơn: `/about/(.*)` giống như `/about/:path*`

Đọc thêm chi tiết trên tài liệu [path-to-regexp](https://github.com/pillarjs/path-to-regexp#path-to-regexp-1).

> **Lưu ý**:
>
> - Các giá trị `matcher` cần phải là hằng số để chúng có thể được phân tích tĩnh tại build-time. Các giá trị dynamic như biến sẽ bị bỏ qua.
> - Để tương thích ngược, Next.js luôn coi `/public` là `/public/index`. Do đó, một matcher của `/public/:path` sẽ khớp.

## Params

### `request`

Khi định nghĩa Proxy, hàm export mặc định chấp nhận một tham số duy nhất, `request`. Tham số này là một instance của `NextRequest`, đại diện cho HTTP request đến.

```tsx filename="proxy.ts" switcher
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  // Logic Proxy ở đây
}
```

```js filename="proxy.js" switcher
export function proxy(request) {
  // Logic Proxy ở đây
}
```

> **Lưu ý**:
>
> - `NextRequest` là một type đại diện cho các HTTP requests đến trong Next.js Proxy, trong khi [`NextResponse`](#nextresponse) là một class được sử dụng để thao tác và gửi lại các HTTP responses.

## NextResponse

API `NextResponse` cho phép bạn:

- `redirect` request đến một URL khác
- `rewrite` response bằng cách hiển thị một URL đã cho
- Đặt request headers cho API Routes, `getServerSideProps`, và các đích đến `rewrite`
- Đặt response cookies
- Đặt response headers

## Thứ tự thực thi

Proxy sẽ được gọi cho **mọi route trong project của bạn**. Do đó, điều quan trọng là sử dụng [matchers](#matcher) để nhắm mục tiêu chính xác hoặc loại trừ các routes cụ thể. Sau đây là thứ tự thực thi:

1. `headers` từ `next.config.js`
2. `redirects` từ `next.config.js`
3. Proxy (`rewrites`, `redirects`, v.v.)
4. `beforeFiles` (`rewrites`) từ `next.config.js`
5. Filesystem routes (`public/`, `_next/static/`, `pages/`, `app/`, v.v.)
6. `afterFiles` (`rewrites`) từ `next.config.js`
7. Dynamic Routes (`/blog/[slug]`)
8. `fallback` (`rewrites`) từ `next.config.js`

## Runtime

Proxy mặc định sử dụng Node.js runtime. Tùy chọn cấu hình [`runtime`](/docs/app/api-reference/file-conventions/route-segment-config#runtime) không có sẵn trong các file Proxy. Đặt tùy chọn cấu hình `runtime` trong Proxy sẽ ném ra lỗi.

## Các cờ Proxy nâng cao

Trong `v13.1` của Next.js, hai cờ bổ sung đã được giới thiệu cho proxy, `skipMiddlewareUrlNormalize` và `skipTrailingSlashRedirect` để xử lý các trường hợp sử dụng nâng cao.

`skipTrailingSlashRedirect` vô hiệu hóa các chuyển hướng Next.js để thêm hoặc xóa dấu gạch chéo ở cuối. Điều này cho phép xử lý tùy chỉnh bên trong proxy để duy trì dấu gạch chéo ở cuối cho một số paths nhưng không cho những paths khác, điều này có thể làm cho việc di chuyển gia tăng dễ dàng hơn.

```js filename="next.config.js"
module.exports = {
  skipTrailingSlashRedirect: true,
}
```

```js filename="proxy.js"
const legacyPrefixes = ['/docs', '/blog']

export default async function proxy(req) {
  const { pathname } = req.nextUrl

  if (legacyPrefixes.some((prefix) => pathname.startsWith(prefix))) {
    return NextResponse.next()
  }

  // áp dụng xử lý trailing slash
  if (
    !pathname.endsWith('/') &&
    !pathname.match(/((?!\.well-known(?:\/.*)?)(?:[^/]+\/)*[^/]+\.\w+)/)
  ) {
    return NextResponse.redirect(
      new URL(`${req.nextUrl.pathname}/`, req.nextUrl)
    )
  }
}
```

`skipMiddlewareUrlNormalize` cho phép vô hiệu hóa việc chuẩn hóa URL trong Next.js để làm cho việc xử lý các lượt truy cập trực tiếp và client-transitions giống nhau. Trong một số trường hợp nâng cao, tùy chọn này cung cấp quyền kiểm soát hoàn toàn bằng cách sử dụng URL gốc.

```js filename="next.config.js"
module.exports = {
  skipMiddlewareUrlNormalize: true,
}
```

```js filename="proxy.js"
export default async function proxy(req) {
  const { pathname } = req.nextUrl

  // GET /_next/data/build-id/hello.json

  console.log(pathname)
  // với cờ này bây giờ là /_next/data/build-id/hello.json
  // không có cờ này sẽ được chuẩn hóa thành /hello
}
```

### Sử dụng Cookies

Cookies là các headers thông thường. Trên một `Request`, chúng được lưu trữ trong header `Cookie`. Trên một `Response` chúng nằm trong header `Set-Cookie`. Next.js cung cấp một cách thuận tiện để truy cập và thao tác các cookies này thông qua extension `cookies` trên `NextRequest` và `NextResponse`.

1. Đối với các requests đến, `cookies` đi kèm với các phương thức sau: `get`, `getAll`, `set`, và `delete` cookies. Bạn có thể kiểm tra sự tồn tại của một cookie với `has` hoặc xóa tất cả cookies với `clear`.
2. Đối với các responses đi, `cookies` có các phương thức sau `get`, `getAll`, `set`, và `delete`.

```ts filename="proxy.ts" switcher
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  // Giả sử một header "Cookie:nextjs=fast" hiện diện trên request đến
  // Lấy cookies từ request sử dụng API `RequestCookies`
  let cookie = request.cookies.get('nextjs')
  console.log(cookie) // => { name: 'nextjs', value: 'fast', Path: '/' }
  const allCookies = request.cookies.getAll()
  console.log(allCookies) // => [{ name: 'nextjs', value: 'fast' }]

  request.cookies.has('nextjs') // => true
  request.cookies.delete('nextjs')
  request.cookies.has('nextjs') // => false

  // Đặt cookies trên response sử dụng API `ResponseCookies`
  const response = NextResponse.next()
  response.cookies.set('vercel', 'fast')
  response.cookies.set({
    name: 'vercel',
    value: 'fast',
    path: '/',
  })
  cookie = response.cookies.get('vercel')
  console.log(cookie) // => { name: 'vercel', value: 'fast', Path: '/' }
  // Response đi sẽ có header `Set-Cookie:vercel=fast;path=/`.

  return response
}
```


### Đặt Headers

Bạn có thể đặt request và response headers sử dụng API `NextResponse` (đặt _request_ headers có sẵn kể từ Next.js v13.0.0).

```ts filename="proxy.ts" switcher
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  // Clone request headers và đặt một header mới `x-hello-from-proxy1`
  const requestHeaders = new Headers(request.headers)
  requestHeaders.set('x-hello-from-proxy1', 'hello')

  // Bạn cũng có thể đặt request headers trong NextResponse.next
  const response = NextResponse.next({
    request: {
      // Request headers mới
      headers: requestHeaders,
    },
  })

  // Đặt một response header mới `x-hello-from-proxy2`
  response.headers.set('x-hello-from-proxy2', 'hello')
  return response
}
```

```js filename="proxy.js" switcher
import { NextResponse } from 'next/server'

export function proxy(request) {
  // Clone request headers và đặt một header mới `x-hello-from-proxy1`
  const requestHeaders = new Headers(request.headers)
  requestHeaders.set('x-hello-from-proxy1', 'hello')

  // Bạn cũng có thể đặt request headers trong NextResponse.next
  const response = NextResponse.next({
    request: {
      // Request headers mới
      headers: requestHeaders,
    },
  })

  // Đặt một response header mới `x-hello-from-proxy2`
  response.headers.set('x-hello-from-proxy2', 'hello')
  return response
}
```

Lưu ý rằng đoạn mã sử dụng:

- `NextResponse.next({ request: { headers: requestHeaders } })` để làm cho `requestHeaders` có sẵn ở thượng nguồn (upstream)
- **KHÔNG** `NextResponse.next({ headers: requestHeaders })` cái mà làm cho `requestHeaders` có sẵn cho clients

Tìm hiểu thêm trong [NextResponse headers trong Proxy](/docs/app/api-reference/functions/next-response#next).

> **Lưu ý**: Tránh đặt headers lớn vì nó có thể gây ra lỗi [431 Request Header Fields Too Large](https://developer.mozilla.org/docs/Web/HTTP/Status/431) tùy thuộc vào cấu hình backend web server của bạn.

### CORS

Bạn có thể đặt CORS headers trong Proxy để cho phép các yêu cầu cross-origin, bao gồm các yêu cầu [simple](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS#simple_requests) và [preflighted](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS#preflighted_requests).

```tsx filename="proxy.ts" switcher
import { NextRequest, NextResponse } from 'next/server'

const allowedOrigins = ['https://acme.com', 'https://my-app.org']

const corsOptions = {
  'Access-Control-Allow-Methods': 'GET, POST, PUT, DELETE, OPTIONS',
  'Access-Control-Allow-Headers': 'Content-Type, Authorization',
}

export function proxy(request: NextRequest) {
  // Kiểm tra origin từ request
  const origin = request.headers.get('origin') ?? ''
  const isAllowedOrigin = allowedOrigins.includes(origin)

  // Xử lý preflighted requests
  const isPreflight = request.method === 'OPTIONS'

  if (isPreflight) {
    const preflightHeaders = {
      ...(isAllowedOrigin && { 'Access-Control-Allow-Origin': origin }),
      ...corsOptions,
    }
    return NextResponse.json({}, { headers: preflightHeaders })
  }

  // Xử lý simple requests
  const response = NextResponse.next()

  if (isAllowedOrigin) {
    response.headers.set('Access-Control-Allow-Origin', origin)
  }

  Object.entries(corsOptions).forEach(([key, value]) => {
    response.headers.set(key, value)
  })

  return response
}

export const config = {
  matcher: '/api/:path*',
}
```

### Tạo ra một phản hồi

Bạn có thể phản hồi từ Proxy trực tiếp bằng cách trả về một instance `Response` hoặc `NextResponse`. (Điều này có sẵn kể từ [Next.js v13.1.0](https://nextjs.org/blog/next-13-1#nextjs-advanced-proxy))

```ts filename="proxy.ts" switcher
import type { NextRequest } from 'next/server'
import { isAuthenticated } from '@lib/auth'

// Giới hạn proxy cho các paths bắt đầu bằng `/api/`
export const config = {
  matcher: '/api/:function*',
}

export function proxy(request: NextRequest) {
  // Gọi hàm xác thực của chúng tôi để kiểm tra request
  if (!isAuthenticated(request)) {
    // Phản hồi với JSON chỉ ra một thông báo lỗi
    return Response.json(
      { success: false, message: 'authentication failed' },
      { status: 401 }
    )
  }
}
```


### Negative matching

Config `matcher` cho phép regex đầy đủ vì vậy việc khớp như negative lookaheads hoặc khớp ký tự được hỗ trợ. Một ví dụ về negative lookahead để khớp tất cả ngoại trừ các paths cụ thể có thể được nhìn thấy ở đây:

```js filename="proxy.js"
export const config = {
  matcher: [
    /*
     * Khớp tất cả các request paths ngoại trừ các paths bắt đầu bằng:
     * - api (API routes)
     * - _next/static (static files)
     * - _next/image (image optimization files)
     * - favicon.ico, sitemap.xml, robots.txt (metadata files)
     */
    '/((?!api|_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)',
  ],
}
```

Bạn cũng có thể bỏ qua Proxy cho các requests nhất định bằng cách sử dụng các mảng `missing` hoặc `has`, hoặc kết hợp cả hai:

```js filename="proxy.js"
export const config = {
  matcher: [
    /*
     * Khớp tất cả các request paths ngoại trừ các paths bắt đầu bằng:
     * - api (API routes)
     * - _next/static (static files)
     * - _next/image (image optimization files)
     * - favicon.ico, sitemap.xml, robots.txt (metadata files)
     */
    {
      source:
        '/((?!api|_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)',
      missing: [
        { type: 'header', key: 'next-router-prefetch' },
        { type: 'header', key: 'purpose', value: 'prefetch' },
      ],
    },

    {
      source:
        '/((?!api|_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)',
      has: [
        { type: 'header', key: 'next-router-prefetch' },
        { type: 'header', key: 'purpose', value: 'prefetch' },
      ],
    },

    {
      source:
        '/((?!api|_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)',
      has: [{ type: 'header', key: 'x-present' }],
      missing: [{ type: 'header', key: 'x-missing', value: 'prefetch' }],
    },
  ],
}
```

### `waitUntil` và `NextFetchEvent`

Object `NextFetchEvent` mở rộng object [`FetchEvent`](https://developer.mozilla.org/docs/Web/API/FetchEvent) gốc, và bao gồm phương thức [`waitUntil()`](https://developer.mozilla.org/docs/Web/API/ExtendableEvent/waitUntil).

Phương thức `waitUntil()` nhận một promise làm đối số, và kéo dài thời gian tồn tại của Proxy cho đến khi promise giải quyết (settles). Điều này hữu ích để thực hiện công việc trong nền.

```ts filename="proxy.ts"
import { NextResponse } from 'next/server'
import type { NextFetchEvent, NextRequest } from 'next/server'

export function proxy(req: NextRequest, event: NextFetchEvent) {
  event.waitUntil(
    fetch('https://my-analytics-platform.com', {
      method: 'POST',
      body: JSON.stringify({ pathname: req.nextUrl.pathname }),
    })
  )

  return NextResponse.next()
}
```

### Unit testing (experimental)

Bắt đầu từ Next.js 15.1, package `next/experimental/testing/server` chứa các tiện ích để giúp unit test các file proxy. Unit testing proxy có thể giúp đảm bảo rằng nó chỉ chạy trên các paths mong muốn và logic routing tùy chỉnh hoạt động như dự định trước khi mã đến production.

Hàm `unstable_doesProxyMatch` có thể được sử dụng để khẳng định liệu proxy có chạy cho URL, headers, và cookies được cung cấp hay không.

```js
import { unstable_doesProxyMatch } from 'next/experimental/testing/server'

expect(
  unstable_doesProxyMatch({
    config,
    nextConfig,
    url: '/test',
  })
).toEqual(false)
```

Toàn bộ hàm proxy cũng có thể được test.

```js
import { isRewrite, getRewrittenUrl } from 'next/experimental/testing/server'

const request = new NextRequest('https://nextjs.org/docs')
const response = await proxy(request)
expect(isRewrite(response)).toEqual(true)
expect(getRewrittenUrl(response)).toEqual('https://other-domain.com/docs')
// getRedirectUrl cũng có thể được sử dụng nếu phản hồi là một chuyển hướng
```

## Di chuyển sang Proxy

### Tại sao thay đổi

Lý do đằng sau việc đổi tên `middleware` là thuật ngữ "middleware" thường có thể bị nhầm lẫn với Express.js middleware, dẫn đến việc hiểu sai mục đích của nó. Ngoài ra, Middleware có khả năng cao, vì vậy nó có thể khuyến khích việc sử dụng; tuy nhiên, tính năng này được khuyến nghị sử dụng như một phương sách cuối cùng.

Next.js đang tiến tới cung cấp các APIs tốt hơn với công thái học (ergonomics) tốt hơn để các nhà phát triển có thể đạt được mục tiêu của họ mà không cần Middleware. Đây là lý do đằng sau việc đổi tên `middleware`.

### Tại sao "Proxy"

Cái tên Proxy làm rõ những gì Middleware có khả năng làm. Thuật ngữ "proxy" ngụ ý rằng nó có một ranh giới mạng phía trước ứng dụng, đó là hành vi của Middleware. Ngoài ra, Middleware mặc định chạy tại [Edge Runtime](/docs/app/api-reference/edge), có thể chạy gần client hơn, tách biệt khỏi vùng của ứng dụng. Những hành vi này phù hợp hơn với thuật ngữ "proxy" và cung cấp mục đích rõ ràng hơn của tính năng.

### Cách di chuyển

Chúng tôi khuyên người dùng tránh dựa vào Middleware trừ khi không còn lựa chọn nào khác. Mục tiêu của chúng tôi là cung cấp cho họ các APIs với công thái học tốt hơn để họ có thể đạt được mục tiêu của mình mà không cần Middleware.

Thuật ngữ “middleware” thường gây nhầm lẫn cho người dùng với Express.js middleware, điều này có thể khuyến khích việc sử dụng sai. Để làm rõ hướng đi của chúng tôi, chúng tôi đang đổi tên file convention thành “proxy.” Điều này làm nổi bật rằng chúng tôi đang rời xa Middleware, chia nhỏ các tính năng quá tải của nó, và làm cho Proxy rõ ràng trong mục đích của nó.

Next.js cung cấp một codemod để di chuyển từ `middleware.ts` sang `proxy.ts`. Bạn có thể chạy lệnh sau để di chuyển:

```bash
npx @next/codemod@canary middleware-to-proxy .
```

Codemod sẽ đổi tên file và tên hàm từ `middleware` thành `proxy`.

```diff
// middleware.ts -> proxy.ts

- export function middleware() {
+ export function proxy() {
```
