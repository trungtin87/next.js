Component `<Form>` mở rộng phần tử HTML `<form>` để cung cấp <AppOnly>[**prefetching**](/docs/app/getting-started/linking-and-navigating#prefetching) của [loading UI](/docs/app/api-reference/file-conventions/loading),</AppOnly> **client-side navigation** khi submit, và **progressive enhancement**.

Nó hữu ích cho các form cập nhật URL search params vì nó giảm thiểu code boilerplate cần thiết để đạt được những điều trên.

Cách sử dụng cơ bản:

<AppOnly>

```tsx filename="/app/ui/search.tsx" switcher
import Form from 'next/form'

export default function Page() {
  return (
    <Form action="/search">
      {/* Khi submit, giá trị input sẽ được thêm vào
          URL, ví dụ: /search?query=abc */}
      <input name="query" />
      <button type="submit">Submit</button>
    </Form>
  )
}
```

```jsx filename="/app/ui/search.js" switcher
import Form from 'next/form'

export default function Search() {
  return (
    <Form action="/search">
      {/* Khi submit, giá trị input sẽ được thêm vào

      <input name="query" />
      <button type="submit">Submit</button>
    </Form>
  )
}
```

## Tham khảo

Hành vi của component `<Form>` phụ thuộc vào việc prop `action` được truyền một `string` hay `function`.

<AppOnly>

- Khi `action` là một **string**, `<Form>` hoạt động như một native HTML form sử dụng phương thức **`GET`**. Dữ liệu form được encode vào URL dưới dạng search params, và khi form được submit, nó điều hướng đến URL được chỉ định. Ngoài ra, Next.js:
  - [Prefetches](/docs/app/getting-started/linking-and-navigating#prefetching) đường dẫn khi form hiển thị, điều này preload shared UI (ví dụ: `layout.js` và `loading.js`), dẫn đến điều hướng nhanh hơn.
  - Thực hiện [client-side navigation](/docs/app/getting-started/linking-and-navigating#client-side-transitions) thay vì full page reload khi form được submit. Điều này giữ lại shared UI và client-side state.
- Khi `action` là một **function** (Server Action), `<Form>` hoạt động như một [React form](https://react.dev/reference/react-dom/components/form), thực thi action khi form được submit.

</AppOnly>

<PagesOnly>

- Khi `action` là một **string**, `<Form>` hoạt động như một native HTML form sử dụng phương thức **`GET`**. Dữ liệu form được encode vào URL dưới dạng search params, và khi form được submit, nó điều hướng đến URL được chỉ định. Ngoài ra, Next.js:

</PagesOnly>

### Props của `action` (string)

<PagesOnly>

Khi `action` là một string, component `<Form>` hỗ trợ các props sau:

| Prop | Ví dụ | Type | Bắt buộc |\n| --------- | ------------------ | ------------------------------- | -------- |
| `action` | `action="/search"` | `string` (URL hoặc relative path) | Có |
| `replace` | `replace={false}` | `boolean` | - |
| `scroll` | `scroll={true}` | `boolean` | - |

- **`action`**: URL hoặc path để điều hướng đến khi form được submit.
  - Một empty string `""` sẽ điều hướng đến cùng route với search params được cập nhật.
- **`replace`**: Thay thế current history state thay vì thêm một state mới vào [browser's history](https://developer.mozilla.org/en-US/docs/Web/API/History_API) stack. Mặc định là `false`.
- **`scroll`**: Kiểm soát hành vi scroll trong quá trình điều hướng. Mặc định là `true`, có nghĩa là nó sẽ scroll đến đầu route mới, và duy trì vị trí scroll cho điều hướng backwards và forwards.

</PagesOnly>

<AppOnly>

Khi `action` là một string, component `<Form>` hỗ trợ các props sau:

| Prop       | Ví dụ              | Type                              | Bắt buộc |
| ---------- | ------------------ | --------------------------------- | -------- |
| `action`   | `action="/search"` | `string` (URL hoặc relative path) | Có       |
| `replace`  | `replace={false}`  | `boolean`                         | -        |
| `scroll`   | `scroll={true}`    | `boolean`                         | -        |
| `prefetch` | `prefetch={true}`  | `boolean`                         | -        |

- **`action`**: URL hoặc path để điều hướng đến khi form được submit.
  - Một empty string `""` sẽ điều hướng đến cùng route với search params được cập nhật.
- **`replace`**: Thay thế current history state thay vì thêm một state mới vào [browser's history](https://developer.mozilla.org/en-US/docs/Web/API/History_API) stack. Mặc định là `false`.
- **`scroll`**: Kiểm soát hành vi scroll trong quá trình điều hướng. Mặc định là `true`, có nghĩa là nó sẽ scroll đến đầu route mới, và duy trì vị trí scroll cho điều hướng backwards và forwards.
- **`prefetch`**: Kiểm soát xem path có nên được prefetch khi form hiển thị trong viewport của người dùng hay không. Mặc định là `true`.

### Props của `action` (function)

Khi `action` là một function, component `<Form>` hỗ trợ prop sau:

| Prop     | Ví dụ               | Type                       | Bắt buộc |
| -------- | ------------------- | -------------------------- | -------- |
| `action` | `action={myAction}` | `function` (Server Action) | Có       |

- **`action`**: Server Action sẽ được gọi khi form được submit. Xem [tài liệu React](https://react.dev/reference/react-dom/components/form#props) để biết thêm.

> **Lưu ý:** Khi `action` là một function, các props `replace` và `scroll` bị bỏ qua.

</AppOnly>

### Lưu ý

<AppOnly>

- **`formAction`**: Có thể được sử dụng trong `<button>` hoặc `<input type="submit">` fields để override prop `action`. Next.js sẽ thực hiện client-side navigation, tuy nhiên, cách tiếp cận này không hỗ trợ prefetching.
  - Khi sử dụng [`basePath`](/docs/app/api-reference/config/next-config-js/basePath), bạn cũng phải bao gồm nó trong `formAction` path. ví dụ: `formAction="/base-path/search"`.
- **`key`**: Truyền prop `key` cho string `action` không được hỗ trợ. Nếu bạn muốn trigger re-render hoặc thực hiện mutation, hãy cân nhắc sử dụng function `action` thay thế.

</AppOnly>

- **`onSubmit`**: Có thể được sử dụng để xử lý logic submit form. Tuy nhiên, gọi `event.preventDefault()` sẽ override hành vi của `<Form>` như điều hướng đến URL được chỉ định.
- **[`method`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#method), [`encType`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#enctype), [`target`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#target)**: Không được hỗ trợ vì chúng override hành vi của `<Form>`.
  - Tương tự, `formMethod`, `formEncType`, và `formTarget` có thể được sử dụng để override các props `method`, `encType`, và `target` tương ứng, và sử dụng chúng sẽ fallback về hành vi native của trình duyệt.
  - Nếu bạn cần sử dụng các props này, hãy sử dụng phần tử HTML `<form>` thay thế.
- **`<input type="file">`**: Sử dụng input type này khi `action` là một string sẽ khớp với hành vi trình duyệt bằng cách submit filename thay vì file object.

<AppOnly>

## Ví dụ

### Form tìm kiếm dẫn đến trang kết quả tìm kiếm

Bạn có thể tạo một form tìm kiếm điều hướng đến trang kết quả tìm kiếm bằng cách truyền path làm `action`:

```tsx filename="/app/page.tsx" switcher
import Form from 'next/form'

export default function Page() {
  return (
    <Form action="/search">
      <input name="query" />
      <button type="submit">Submit</button>
    </Form>
  )
}
```

```jsx filename="/app/page.js" switcher
import Form from 'next/form'

export default function Page() {
  return (
    <Form action="/search">
      <input name="query" />
      <button type="submit">Submit</button>
    </Form>
  )
}
```

Khi người dùng cập nhật query input field và submit form, dữ liệu form sẽ được encode vào URL dưới dạng search params, ví dụ: `/search?query=abc`.

> **Lưu ý:** Nếu bạn truyền empty string `""` cho `action`, form sẽ điều hướng đến cùng route với search params được cập nhật.

Trên trang kết quả, bạn có thể truy cập query bằng cách sử dụng prop [`searchParams`](/docs/app/api-reference/file-conventions/page#searchparams-optional) của `page.js` và sử dụng nó để fetch dữ liệu từ nguồn bên ngoài.

```tsx filename="/app/search/page.tsx" switcher
import { getSearchResults } from '@/lib/search'

export default async function SearchPage({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const results = await getSearchResults((await searchParams).query)

  return <div>...</div>
}
```

```jsx filename="/app/search/page.js" switcher
import { getSearchResults } from '@/lib/search'

export default async function SearchPage({ searchParams }) {
  const results = await getSearchResults((await searchParams).query)

  return <div>...</div>
}
```

Khi `<Form>` hiển thị trong viewport của người dùng, shared UI (như `layout.js` và `loading.js`) trên trang `/search` sẽ được prefetch. Khi submit, form sẽ ngay lập tức điều hướng đến route mới và hiển thị loading UI trong khi kết quả đang được fetch. Bạn có thể thiết kế fallback UI bằng cách sử dụng [`loading.js`](/docs/app/api-reference/file-conventions/loading):

```tsx filename="/app/search/loading.tsx" switcher
export default function Loading() {
  return <div>Loading...</div>
}
```

```jsx filename="/app/search/loading.js" switcher
export default function Loading() {
  return <div>Loading...</div>
}
```

Để cover các trường hợp khi shared UI chưa được load, bạn có thể hiển thị phản hồi tức thì cho người dùng bằng cách sử dụng [`useFormStatus`](https://react.dev/reference/react-dom/hooks/useFormStatus).

Đầu tiên, tạo một component hiển thị loading state khi form đang pending:

```tsx filename="/app/ui/search-button.tsx" switcher
'use client'
import { useFormStatus } from 'react-dom'

export default function SearchButton() {
  const status = useFormStatus()
  return (
    <button type="submit">{status.pending ? 'Đang tìm...' : 'Tìm kiếm'}</button>
  )
}
```

```jsx filename="/app/ui/search-button.js" switcher
'use client'
import { useFormStatus } from 'react-dom'

export default function SearchButton() {
  const status = useFormStatus()
  return (
    <button type="submit">{status.pending ? 'Đang tìm...' : 'Tìm kiếm'}</button>
  )
}
```

```jsx filename="/app/ui/search-button.js" switcher
}
```

### Mutations với Server Actions

Bạn có thể thực hiện mutations bằng cách truyền một function cho prop `action`.

```tsx filename="/app/posts/create/page.tsx" switcher
import Form from 'next/form'
import { createPost } from '@/posts/actions'

export default function Page() {
  return (
    <Form action={createPost}>
      <input name="title" />
      {/* ... */}
      <button type="submit">Tạo Post</button>
    </Form>
  )
}
```

```jsx filename="/app/posts/create/page.js" switcher
import Form from 'next/form'
import { createPost } from '@/posts/actions'

export default function Page() {
  return (
    <Form action={createPost}>
      <input name="title" />
      {/* ... */}
      <button type="submit">Tạo Post</button>
    </Form>
  )
}
```

Sau một mutation, thông thường là redirect đến resource mới. Bạn có thể sử dụng function [`redirect`](/docs/app/guides/redirecting) từ `next/navigation` để điều hướng đến trang post mới.

> **Lưu ý:** Vì "destination" của form submission không được biết cho đến khi action được thực thi, `<Form>` không thể tự động prefetch shared UI.

```tsx filename="/app/posts/actions.ts" switcher
'use server'
import { redirect } from 'next/navigation'

export async function createPost(formData: FormData) {
  // Tạo một post mới
  // ...

  // Redirect đến post mới
  redirect(`/posts/${data.id}`)
}
```

```jsx filename="/app/posts/actions.js" switcher
'use server'
import { redirect } from 'next/navigation'

export async function createPost(formData) {
  // Tạo một post mới
  // ...

  // Redirect đến post mới
  redirect(`/posts/${data.id}`)
}
```

Sau đó, trong trang mới, bạn có thể fetch dữ liệu bằng cách sử dụng prop `params`:

```tsx filename="/app/posts/[id]/page.tsx" switcher
import { getPost } from '@/posts/data'

export default async function PostPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const data = await getPost(id)

  return (
    <div>
      <h1>{data.title}</h1>
      {/* ... */}
    </div>
  )
}
```

