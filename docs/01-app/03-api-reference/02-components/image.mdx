Next.js Image component mở rộng phần tử HTML `<img>` để tối ưu hóa hình ảnh tự động.

```jsx filename="app/page.js"
import Image from 'next/image'

export default function Page() {
  return (
    <Image
      src="/profile.png"
      width={500}
      height={500}
      alt="Picture of the author"
    />
  )
}
```

<PagesOnly>

> **Good to know**: If you are using a version of Next.js prior to 13, you'll want to use the [next/legacy/image](/docs/pages/api-reference/components/image-legacy) documentation since the component was renamed.

</PagesOnly>

#### `src`

Nguồn của hình ảnh. Có thể là một trong những cái sau:

Một internal path string.

```jsx
<Image src="/profile.png" />
```

Một absolute external URL (phải được cấu hình với [remotePatterns](#remotepatterns)).

```jsx
<Image src="https://example.com/profile.png" />
```

Một static import.

```jsx
import profile from './profile.png'

export default function Page() {
  return <Image src={profile} />
}
```

> **Lưu ý:** Vì lý do bảo mật, Image Optimization API sử dụng [loader](#loader) mặc định sẽ _không_ forward headers khi fetch hình ảnh `src`.
> Nếu hình ảnh `src` yêu cầu authentication, hãy cân nhắc sử dụng property [unoptimized](#unoptimized) để vô hiệu hóa Image Optimization.

#### `alt`

Property `alt` được sử dụng để mô tả hình ảnh cho screen readers và search engines. Nó cũng là fallback text nếu hình ảnh bị vô hiệu hóa hoặc xảy ra lỗi trong quá trình loading hình ảnh.

Nó nên chứa text có thể thay thế hình ảnh [mà không thay đổi ý nghĩa của trang](https://html.spec.whatwg.org/multipage/images.html#general-guidelines). Nó không nhằm mục đích bổ sung cho hình ảnh và không nên lặp lại thông tin đã được cung cấp trong captions ở trên hoặc dưới hình ảnh.

Nếu hình ảnh là [purely decorative](https://html.spec.whatwg.org/multipage/images.html#a-purely-decorative-image-that-doesn't-add-any-information) hoặc [không dành cho người dùng](https://html.spec.whatwg.org/multipage/images.html#an-image-not-intended-for-the-user), property `alt` nên là một empty string (`alt=""`).

> Tìm hiểu thêm về [image accessibility guidelines](https://html.spec.whatwg.org/multipage/images.html#alt).

#### `width` và `height`

Các properties `width` và `height` đại diện cho kích thước hình ảnh [intrinsic](https://developer.mozilla.org/en-US/docs/Glossary/Intrinsic_Size) tính bằng pixels. Property này được sử dụng để suy ra **aspect ratio** chính xác được sử dụng bởi trình duyệt để dành không gian cho hình ảnh và tránh layout shift trong quá trình loading. Nó không xác định _rendered size_ của hình ảnh, điều này được kiểm soát bởi CSS.

```jsx
<Image src="/profile.png" width={500} height={500} />
```

Bạn **phải** đặt cả hai properties `width` và `height` trừ khi:

- Hình ảnh được statically imported.
- Hình ảnh có [`fill` property](#fill)

Nếu height và width không biết, chúng tôi khuyến nghị sử dụng [`fill` property](#fill).

#### `fill`

Một boolean khiến hình ảnh mở rộng đến kích thước của parent element.

```js
<Image src="/profile.png" fill={true} />
```

**Positioning**:

- Parent element **phải** gán `position: "relative"`, `"fixed"`, `"absolute"`.
- Mặc định, phần tử `<img>` sử dụng `position: "absolute"`.

**Object Fit**:

Nếu không có styles nào được áp dụng cho hình ảnh, hình ảnh sẽ kéo giãn để vừa với container. Bạn có thể sử dụng `objectFit` để kiểm soát cropping và scaling.

- `"contain"`: Hình ảnh sẽ được thu nhỏ để vừa với container và bảo toàn aspect ratio.
- `"cover"`: Hình ảnh sẽ lấp đầy container và bị cropped.

> Tìm hiểu thêm về [`position`](https://developer.mozilla.org/en-US/docs/Web/CSS/position) và [`object-fit`](https://developer.mozilla.org/docs/Web/CSS/object-fit).

#### `loader`

Một custom function được sử dụng để tạo image URL. Function nhận các parameters sau, và trả về một URL string cho hình ảnh:

- [`src`](#src)
- [`width`](#width-and-height)
- [`quality`](#quality)

<AppOnly>

```js
'use client'

import Image from 'next/image'

const imageLoader = ({ src, width, quality }) => {
  return `https://example.com/${src}?w=${width}&q=${quality || 75}`
}

export default function Page() {
  return (
    <Image
      loader={imageLoader}
      src="me.png"
      alt="Picture of the author"
      width={500}
      height={500}
    />
  )
}
```

> **Lưu ý**: Sử dụng props như `onLoad`, chấp nhận một function, yêu cầu sử dụng [Client Components](https://react.dev/reference/rsc/use-client) để serialize function được cung cấp.

</AppOnly>

#### `sizes`

Định nghĩa kích thước của hình ảnh ở các breakpoints khác nhau. Được trình duyệt sử dụng để chọn kích thước phù hợp nhất từ `srcset` được tạo.

```jsx
import Image from 'next/image'

export default function Page() {
  return (
    <div className="grid-element">
      <Image
        fill
        src="/example.png"
        sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
      />
    </div>
  )
}
```

`sizes` nên được sử dụng khi:

- Hình ảnh đang sử dụng prop [`fill`](#fill)
- CSS được sử dụng để làm cho hình ảnh responsive

Nếu `sizes` bị thiếu, trình duyệt giả định hình ảnh sẽ rộng bằng viewport (`100vw`). Điều này có thể khiến các hình ảnh lớn không cần thiết được download.

Ngoài ra, `sizes` ảnh hưởng cách `srcset` được tạo:

- Không có `sizes`: Next.js tạo một `srcset` giới hạn (ví dụ: 1x, 2x), phù hợp cho hình ảnh kích thước cố định.
- Với `sizes`: Next.js tạo một `srcset` đầy đủ (ví dụ: 640w, 750w, etc.), được tối ưu hóa cho responsive layouts.

> Tìm hiểu thêm về `srcset` và `sizes` trên [web.dev](https://web.dev/learn/design/responsive-images/#sizes) và [mdn](https://developer.mozilla.org/docs/Web/HTML/Element/img#sizes).

#### `quality`

Một integer giữa `1` và `100` đặt chất lượng của hình ảnh được tối ưu hóa. Giá trị cao hơn tăng kích thước file và độ trung thực hình ảnh. Giá trị thấp hơn giảm kích thước file nhưng có thể ảnh hưởng độ sắc nét.

```jsx
// Chất lượng mặc định là 75
<Image quality={75} />
```

Nếu bạn đã cấu hình [qualities](#qualities) trong `next.config.js`, giá trị phải khớp với một trong các entries được phép.

> **Lưu ý**: Nếu hình ảnh gốc đã có chất lượng thấp, việc đặt giá trị chất lượng cao sẽ tăng kích thước file mà không cải thiện ngoại hình.

#### `style`

Cho phép truyền CSS styles cho phần tử image bên dưới.

```jsx
const imageStyle = {
  borderRadius: '50%',
  border: '1px solid #fff',
  width: '100px',
  height: 'auto',
}

export default function ProfileImage() {
  return <Image src="..." style={imageStyle} />
}
```

> **Lưu ý**: Nếu bạn đang sử dụng prop `style` để đặt custom width, hãy chắc chắn cũng đặt `height: 'auto'` để bảo toàn aspect ratio của hình ảnh.

#### `preload`

Một boolean cho biết liệu hình ảnh có nên được preload hay không.

```jsx
// Preload mặc định là false
<Image preload={false} />
```

- `true`: [Preloads](https://web.dev/preload-responsive-images/) hình ảnh bằng cách chèn một `<link>` vào `<head>`.
- `false`: Không preload hình ảnh.

**Khi nào sử dụng:**

- Hình ảnh là phần tử [Largest Contentful Paint (LCP)](https://nextjs.org/learn/seo/web-performance/lcp).
- Hình ảnh ở trên fold, thường là hero image.
- Bạn muốn bắt đầu loading hình ảnh trong `<head>`, trước khi nó được khám phá sau đó trong `<body>`.

**Khi không nên sử dụng:**

- Khi bạn có nhiều hình ảnh có thể được coi là phần tử [Largest Contentful Paint (LCP)](https://nextjs.org/learn/seo/web-performance/lcp) tùy thuộc vào viewport.
- Khi property `loading` được sử dụng.
- Khi property `fetchPriority` được sử dụng.

Trong hầu hết các trường hợp, bạn nên sử dụng `loading="eager"` hoặc `fetchPriority="high"` thay vì `preload`.

#### `priority`

Bắt đầu với Next.js 16, property `priority` đã bị deprecated để ưu tiên property [`preload`](#preload) nhằm làm rõ hành vi.

#### `loading`

Kiểm soát khi nào hình ảnh nên bắt đầu loading.

```jsx
// Mặc định là lazy
<Image loading="lazy" />
```

- `lazy`: Trì hoãn loading hình ảnh cho đến khi nó đạt đến khoảng cách được tính toán từ viewport.
- `eager`: Load hình ảnh ngay lập tức, bất kể vị trí của nó trong trang.

Sử dụng `eager` chỉ khi bạn muốn đảm bảo hình ảnh được load ngay lập tức.

> Tìm hiểu thêm về [`loading` attribute](https://developer.mozilla.org/docs/Web/HTML/Element/img#loading).

#### `placeholder`

Chỉ định một placeholder để sử dụng trong khi hình ảnh đang loading, cải thiện hiệu suất loading cảm nhận.

```jsx
// mặc định là empty
<Image placeholder="empty" />
```

- `empty`: Không có placeholder trong khi hình ảnh đang loading.
- `blur`: Sử dụng phiên bản bị làm mờ của hình ảnh làm placeholder. Phải được sử dụng với property [`blurDataURL`](#blurdataurl).
- `data:image/...`: Sử dụng [Data URL](https://developer.mozilla.org/docs/Web/HTTP/Basics_of_HTTP/Data_URIs) làm placeholder.

**Ví dụ:**

- [`blur` placeholder](https://image-component.nextjs.gallery/placeholder)
- [Shimmer effect với data URL `placeholder` prop](https://image-component.nextjs.gallery/shimmer)
- [Color effect với `blurDataURL` prop](https://image-component.nextjs.gallery/color)

> Tìm hiểu thêm về [`placeholder` attribute](https://developer.mozilla.org/docs/Web/HTML/Element/img#placeholder).

#### `blurDataURL`

Một [Data URL](https://developer.mozilla.org/docs/Web/HTTP/Basics_of_HTTP/Data_URIs) để
được sử dụng làm placeholder image trước khi hình ảnh load thành công. Có thể được tự động đặt hoặc sử dụng với property [`placeholder="blur"`](#placeholder).

```jsx
<Image placeholder="blur" blurDataURL="..." />
```

Hình ảnh được tự động phóng to và làm mờ, vì vậy một hình ảnh rất nhỏ (10px hoặc nhỏ hơn) được khuyến nghị.

**Tự động**

Nếu `src` là một static import của file `jpg`, `png`, `webp`, hoặc `avif`, `blurDataURL` được thêm tự động—trừ khi hình ảnh được animated.

**Đặt thủ công**

Nếu hình ảnh là dynamic hoặc remote, bạn phải cung cấp `blurDataURL` tự mình. Để tạo một cái, bạn có thể sử dụng:

- [Một online tool như png-pixel.com](https://png-pixel.com)
- [Một library như Plaiceholder](https://github.com/joe-bell/plaiceholder)

Một blurDataURL lớn có thể làm giảm hiệu suất. Giữ nó nhỏ và đơn giản.

**Ví dụ:**

- [Default `blurDataURL` prop](https://image-component.nextjs.gallery/placeholder)
- [Color effect với `blurDataURL` prop](https://image-component.nextjs.gallery/color)

#### `onLoad`

Một callback function được gọi một lần hình ảnh được load hoàn toàn và [placeholder](#placeholder) đã được loại bỏ.

```jsx
<Image onLoad={(e) => console.log(e.target.naturalWidth)} />
```

Callback function sẽ được gọi với một argument, event có một `target` tham chiếu đến phần tử `<img>` bên dưới.

> **Lưu ý**: Sử dụng props như `onLoad`, chấp nhận một function, yêu cầu sử dụng [Client Components](https://react.dev/reference/rsc/use-client) để serialize function được cung cấp.

</AppOnly>

Một callback function được gọi nếu hình ảnh không load được.

```jsx
<Image onError={(e) => console.error(e.target.id)} />
```

> **Lưu ý**: Sử dụng props như `onError`, chấp nhận một function, yêu cầu sử dụng [Client Components](https://react.dev/reference/rsc/use-client) để serialize function được cung cấp.

#### `unoptimized`

Một boolean cho biết liệu hình ảnh có nên được tối ưu hóa hay không. Điều này hữu ích cho các hình ảnh không hưởng lợi từ tối ưu hóa như hình ảnh nhỏ (nhỏ hơn 1KB), vector images (SVG), hoặc animated images (GIF).

```js
import Image from 'next/image'

const UnoptimizedImage = (props) => {
  // Mặc định là false
  return <Image {...props} unoptimized />
}
```

- `true`: Hình ảnh nguồn sẽ được phục vụ nguyên bản từ `src` thay vì thay đổi chất lượng, kích thước, hoặc format.
- `false`: Hình ảnh nguồn sẽ được tối ưu hóa.

Kể từ Next.js 12.3.0, prop này có thể được gán cho tất cả hình ảnh bằng cách cập nhật `next.config.js` với cấu hình sau:

```js filename="next.config.js"
module.exports = {
  images: {
    unoptimized: true,
  },
}
```

#### `overrideSrc`

Khi cung cấp prop `src` cho component `<Image>`, cả thuộc tính `srcset` và `src` đều được tạo tự động cho `<img>` kết quả.

```jsx filename="input.js"
<Image src="/profile.jpg" />
```

```html filename="output.html"
<img
  srcset="
    /_next/image?url=%2Fprofile.jpg&w=640&q=75 1x,
    /_next/image?url=%2Fprofile.jpg&w=828&q=75 2x
  "
  src="/_next/image?url=%2Fprofile.jpg&w=828&q=75"
/>
```

Trong một số trường hợp, không mong muốn có thuộc tính `src` được tạo và bạn có thể muốn override nó bằng cách sử dụng prop `overrideSrc`.

Ví dụ, khi nâng cấp một website hiện có từ `<img>` sang `<Image>`, bạn có thể muốn duy trì cùng một thuộc tính `src` cho mục đích SEO như xếp hạng hình ảnh hoặc tránh recrawl.

```jsx filename="input.js"
<Image src="/profile.jpg" overrideSrc="/override.jpg" />
```

```html filename="output.html"
<img
  srcset="
    /_next/image?url=%2Fprofile.jpg&w=640&q=75 1x,
    /_next/image?url=%2Fprofile.jpg&w=828&q=75 2x
  "
  src="/override.jpg"
/>
```

#### `decoding`

Một gợi ý cho trình duyệt cho biết liệu nó có nên đợi hình ảnh được decode trước khi hiển thị các cập nhật nội dung khác hay không.

```jsx
// Mặc định là async
<Image decoding="async" />
```

- `async`: Decode hình ảnh bất đồng bộ và cho phép nội dung khác được render trước khi nó hoàn thành.
- `sync`: Decode hình ảnh đồng bộ để hiển thị nguyên tử với nội dung khác.
- `auto`: Không có sở thích. Trình duyệt chọn cách tiếp cận tốt nhất.

> Tìm hiểu thêm về [`decoding` attribute](https://developer.mozilla.org/docs/Web/HTML/Element/img#decoding).

### Tùy chọn cấu hình

Bạn có thể cấu hình Image Component trong `next.config.js`. Các tùy chọn sau đây có sẵn:

#### `localPatterns`

Sử dụng `localPatterns` trong file `next.config.js` của bạn để cho phép hình ảnh từ các local paths cụ thể được tối ưu hóa và chặn tất cả các cái khác.

```js filename="next.config.js"
module.exports = {
  images: {
    localPatterns: [
      {
        pathname: '/assets/images/**',
        search: '',
      },
    ],
  },
}
```

Ví dụ trên sẽ đảm bảo property `src` của `next/image` phải bắt đầu với `/assets/images/` và không được có query string. Cố gắng tối ưu hóa bất kỳ path nào khác sẽ phản hồi với lỗi `400` Bad Request.

> **Lưu ý**: Bỏ qua property `search` cho phép tất cả search parameters có thể cho phép các kẻ xấu tối ưu hóa URLs bạn không dự định. Hãy thử sử dụng một giá trị cụ thể như `search: '?v=2'` để đảm bảo khớp chính xác.

#### `remotePatterns`

Sử dụng `remotePatterns` trong file `next.config.js` của bạn để cho phép hình ảnh từ các external paths cụ thể và chặn tất cả các cái khác. Điều này đảm bảo rằng chỉ các external images từ account của bạn mới có thể được phục vụ.

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [new URL('https://example.com/account123/**')],
  },
}
```

Bạn cũng có thể cấu hình `remotePatterns` sử dụng object:

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'example.com',
        port: '',
        pathname: '/account123/**',
        search: '',
      },
    ],
  },
}
```

Ví dụ trên sẽ đảm bảo property `src` của `next/image` phải bắt đầu với `https://example.com/account123/` và không được có query string. Bất kỳ protocol, hostname, port, hoặc unmatched path nào khác sẽ phản hồi với `400` Bad Request.

**Wildcard Patterns:**

Wildcard patterns có thể được sử dụng cho cả `pathname` và `hostname` và có cú pháp sau:

- `*` khớp một path segment hoặc subdomain duy nhất
- `**` khớp bất kỳ số lượng path segments nào ở cuối hoặc subdomains ở đầu. Cú pháp này không hoạt động ở giữa pattern.

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: '**.example.com',
        port: '',
        search: '',
      },
    ],
  },
}
```

Điều này cho phép các subdomains như `image.example.com`. Query strings và custom ports vẫn bị chặn.

> **Lưu ý**: Khi bỏ qua `protocol`, `port`, `pathname`, hoặc `search` thì wildcard `**` được ngụ ý. Điều này không được khuyến nghị vì nó có thể cho phép các kẻ xấu tối ưu hóa urls bạn không dự định.

**Query Strings**:

Bạn cũng có thể hạn chế query strings sử dụng property `search`:

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'assets.example.com',
        search: '?v=1727111025337',
      },
    ],
  },
}
```

Ví dụ trên sẽ đảm bảo property `src` của `next/image` phải bắt đầu với `https://assets.example.com` và phải có chính xác query string `?v=1727111025337`. Bất kỳ protocol hoặc query string nào khác sẽ phản hồi với `400` Bad Request.

#### `loaderFile`

`loaderFiles` cho phép bạn sử dụng một image optimization service tùy chỉnh thay vì Next.js.

```js filename="next.config.js"
module.exports = {

    loader: 'custom',
    loaderFile: './my/image/loader.js',
  },
}
```

```js filename="my/image/loader.js"
export default function myImageLoader({ src, width, quality }) {
  return `https://example.com/${src}?w=${width}&q=${quality || 75}`
}
```

</AppOnly>

<PagesOnly>

```js filename="my/image/loader.js"
export default function myImageLoader({ src, width, quality }) {
```

- [Custom Image Loader Configuration](/docs/app/api-reference/config/next-config-js/images#example-loader-configuration)

> Ngoài ra, bạn có thể sử dụng prop [`loader`](#loader) để cấu hình mỗi instance của `next/image`.

#### `path`

Nếu bạn muốn thay đổi hoặc prefix default path cho Image Optimization API, bạn có thể làm như vậy với property `path`. Giá trị mặc định cho `path` là `/_next/image`.

```js filename="next.config.js"
module.exports = {
  images: {
    path: '/my-prefix/_next/image',
  },
}
```

#### `deviceSizes`

`deviceSizes` cho phép bạn chỉ định danh sách các device width breakpoints. Những widths này được sử dụng khi component `next/image` sử dụng prop [`sizes`](#sizes) để đảm bảo hình ảnh chính xác được phục vụ cho device của người dùng.

Nếu không có cấu hình nào được cung cấp, mặc định dưới đây được sử dụng:

```js filename="next.config.js"
module.exports = {
  images: {
    deviceSizes: [640, 750, 828, 1080, 1200, 1920, 2048, 3840],
  },
}
```

#### `imageSizes`

`imageSizes` cho phép bạn chỉ định danh sách các image widths. Những widths này được nối với array của [device sizes](#devicesizes) để tạo thành array đầy đủ các sizes được sử dụng để tạo image [srcset](https://developer.mozilla.org/docs/Web/API/HTMLImageElement/srcset).

Nếu không có cấu hình nào được cung cấp, mặc định dưới đây được sử dụng:

```js filename="next.config.js"
module.exports = {
  images: {
    imageSizes: [32, 48, 64, 96, 128, 256, 384],
  },
}
```

`imageSizes` chỉ được sử dụng cho các images cung cấp một prop [`sizes`](#sizes), cho biết rằng hình ảnh nhỏ hơn full width của màn hình. Do đó, các sizes trong `imageSizes` nên đều nhỏ hơn size nhỏ nhất trong `deviceSizes`.

#### `qualities`

`qualities` cho phép bạn chỉ định danh sách các image quality values.

Nếu không có cấu hình nào được cung cấp, mặc định dưới đây được sử dụng:

```js filename="next.config.js"
module.exports = {
  images: {
    qualities: [75],
  },
}
```

> **Lưu ý:** Trường này là bắt buộc bắt đầu với Next.js 16 vì truy cập không hạn chế có thể cho phép các kẻ xấu tối ưu hóa nhiều qualities hơn bạn dự định.

Bạn có thể thêm nhiều image qualities vào allowlist, như sau:

```js filename="next.config.js"
module.exports = {
  images: {
    qualities: [25, 50, 75, 100],
  },
}
```

Trong ví dụ trên, chỉ bốn qualities được phép: 25, 50, 75, và 100.

Nếu prop [`quality`](#quality) không khớp với giá trị nào trong array này, giá trị được phép gần nhất sẽ được sử dụng.

Nếu REST API được truy cập trực tiếp với một quality không khớp với giá trị nào trong array này, server sẽ trả về phản hồi 400 Bad Request.

#### `formats`

`formats` cho phép bạn chỉ định danh sách các định dạng hình ảnh sẽ được sử dụng.

```js filename="next.config.js"
module.exports = {
  images: {
    // Default
    formats: ['image/webp'],
  },
}
```

Next.js tự động phát hiện các định dạng hình ảnh được trình duyệt hỗ trợ thông qua header `Accept` của request để xác định định dạng đầu ra tốt nhất.

Nếu header `Accept` khớp với nhiều hơn một trong các định dạng đã cấu hình, kết quả khớp đầu tiên trong mảng sẽ được sử dụng. Do đó, thứ tự mảng rất quan trọng. Nếu không có kết quả khớp (hoặc hình ảnh nguồn là animated), nó sẽ sử dụng định dạng của hình ảnh gốc.

Bạn có thể kích hoạt hỗ trợ AVIF, nó sẽ fallback về định dạng gốc của hình ảnh src nếu trình duyệt [không hỗ trợ AVIF](https://caniuse.com/avif):

```js filename="next.config.js"
module.exports = {
  images: {
    formats: ['image/avif'],
  },
}
```

> **Cần biết**:
>
> - Chúng tôi vẫn khuyên dùng WebP cho hầu hết các trường hợp sử dụng.
> - AVIF thường mất thời gian mã hóa lâu hơn 50% nhưng nén nhỏ hơn 20% so với WebP. Điều này có nghĩa là lần đầu tiên hình ảnh được yêu cầu, nó thường sẽ chậm hơn, nhưng các yêu cầu tiếp theo được cache sẽ nhanh hơn.
> - Nếu bạn tự host với Proxy/CDN phía trước Next.js, bạn phải cấu hình Proxy để chuyển tiếp header `Accept`.

#### `minimumCacheTTL`

`minimumCacheTTL` cho phép bạn cấu hình Time to Live (TTL) tính bằng giây cho các hình ảnh được tối ưu hóa đã cache. Trong nhiều trường hợp, tốt hơn là sử dụng [Static Image Import](/docs/app/getting-started/images#local-images) sẽ tự động hash nội dung file và cache hình ảnh mãi mãi với header `Cache-Control` là `immutable`.

Nếu không có cấu hình nào được cung cấp, mặc định dưới đây được sử dụng.

```js filename="next.config.js"
module.exports = {
  images: {
    minimumCacheTTL: 14400, // 4 hours
  },
}
```

Bạn có thể tăng TTL để giảm số lượng revalidations và có khả năng giảm chi phí:

```js filename="next.config.js"
module.exports = {
  images: {
    minimumCacheTTL: 2678400, // 31 days
  },
}
```

Thời hạn (hay đúng hơn là Max Age) của hình ảnh được tối ưu hóa được xác định bởi `minimumCacheTTL` hoặc header `Cache-Control` của hình ảnh upstream, tùy theo cái nào lớn hơn.

Nếu bạn cần thay đổi hành vi caching cho mỗi hình ảnh, bạn có thể cấu hình [`headers`](/docs/app/api-reference/config/next-config-js/headers) để đặt header `Cache-Control` trên hình ảnh upstream (ví dụ: `/some-asset.jpg`, không phải bản thân `/_next/image`).

Hiện tại không có cơ chế nào để invalidate cache, vì vậy tốt nhất là giữ `minimumCacheTTL` thấp. Nếu không, bạn có thể cần thay đổi thủ công prop [`src`](#src) hoặc xóa file đã cache trong `<distDir>/cache/images`.

#### `disableStaticImages`

`disableStaticImages` cho phép bạn vô hiệu hóa static image imports.

Hành vi mặc định cho phép bạn import các file tĩnh như `import icon from './icon.png'` và sau đó truyền nó vào property `src`. Trong một số trường hợp, bạn có thể muốn vô hiệu hóa tính năng này nếu nó xung đột với các plugin khác mong đợi import hoạt động khác đi.

Bạn có thể vô hiệu hóa static image imports bên trong `next.config.js` của bạn:

```js filename="next.config.js"
module.exports = {
  images: {
    disableStaticImages: true,
  },
}
```

#### `maximumRedirects`

Loader tối ưu hóa hình ảnh mặc định sẽ theo dõi các chuyển hướng HTTP khi fetch các hình ảnh từ xa tối đa 3 lần.

```js filename="next.config.js"
module.exports = {
  images: {
    maximumRedirects: 3,
  },
}
```

Bạn có thể cấu hình số lượng chuyển hướng để theo dõi khi fetch các hình ảnh từ xa. Đặt giá trị thành `0` sẽ vô hiệu hóa việc theo dõi chuyển hướng.

```js filename="next.config.js"
module.exports = {
  images: {
    maximumRedirects: 0,
  },
}
```

#### `dangerouslyAllowLocalIP`

Trong những trường hợp hiếm hoi khi tự host Next.js trên một mạng riêng (private network), bạn có thể muốn cho phép tối ưu hóa hình ảnh từ các địa chỉ IP cục bộ trên cùng một mạng. Điều này không được khuyến nghị cho hầu hết người dùng vì nó có thể cho phép người dùng độc hại truy cập nội dung trên mạng nội bộ của bạn.

Theo mặc định, giá trị là false.

```js filename="next.config.js"
module.exports = {
  images: {
    dangerouslyAllowLocalIP: false,
  },
}
```

Nếu bạn cần tối ưu hóa hình ảnh từ xa được host ở nơi khác trong mạng cục bộ của bạn, bạn có thể đặt giá trị thành true.

```js filename="next.config.js"
module.exports = {
  images: {
    dangerouslyAllowLocalIP: true,
  },
}
```

#### `dangerouslyAllowSVG`

`dangerouslyAllowSVG` cho phép bạn phục vụ hình ảnh SVG.

```js filename="next.config.js"
module.exports = {
  images: {
    dangerouslyAllowSVG: true,
  },
}
```

Theo mặc định, Next.js không tối ưu hóa hình ảnh SVG vì một vài lý do:

- SVG là định dạng vector nghĩa là nó có thể được thay đổi kích thước mà không mất dữ liệu.
- SVG có nhiều tính năng giống như HTML/CSS, điều này có thể dẫn đến các lỗ hổng bảo mật nếu không có [Content Security Policy (CSP) headers](/docs/app/api-reference/config/next-config-js/headers#content-security-policy) phù hợp.

Chúng tôi khuyên bạn nên sử dụng prop [`unoptimized`](#unoptimized) khi prop [`src`](#src) được biết là SVG. Điều này xảy ra tự động khi `src` kết thúc bằng `".svg"`.

```jsx
<Image src="/my-image.svg" unoptimized />
```

Ngoài ra, chúng tôi thực sự khuyên bạn cũng nên đặt `contentDispositionType` để buộc trình duyệt tải xuống hình ảnh, cũng như `contentSecurityPolicy` để ngăn các script nhúng trong hình ảnh thực thi.

```js filename="next.config.js"
module.exports = {
  images: {
    dangerouslyAllowSVG: true,
    contentDispositionType: 'attachment',
    contentSecurityPolicy: "default-src 'self'; script-src 'none'; sandbox;",
  },
}
```

#### `contentDispositionType`

`contentDispositionType` cho phép bạn cấu hình header [`Content-Disposition`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Content-Disposition#as_a_response_header_for_the_main_body).

```js filename="next.config.js"
module.exports = {
  images: {
    contentDispositionType: 'inline',
  },
}
```

#### `contentSecurityPolicy`

`contentSecurityPolicy` cho phép bạn cấu hình header [`Content-Security-Policy`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP) cho hình ảnh. Điều này đặc biệt quan trọng khi sử dụng [`dangerouslyAllowSVG`](#dangerouslyallowsvg) để ngăn các script nhúng trong hình ảnh thực thi.

```js filename="next.config.js"
module.exports = {
  images: {
    contentSecurityPolicy: "default-src 'self'; script-src 'none'; sandbox;",
  },
}
```

Theo mặc định, [loader](#loader) đặt header [`Content-Disposition`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Content-Disposition#as_a_response_header_for_the_main_body) thành `attachment` để tăng cường bảo vệ vì API có thể phục vụ các hình ảnh từ xa tùy ý.

Giá trị mặc định là `attachment` buộc trình duyệt tải xuống hình ảnh khi truy cập trực tiếp. Điều này đặc biệt quan trọng khi [`dangerouslyAllowSVG`](#dangerouslyallowsvg) là true.

Bạn có thể tùy chọn cấu hình `inline` để cho phép trình duyệt render hình ảnh khi truy cập trực tiếp, mà không cần tải xuống.

### Các tùy chọn cấu hình đã deprecated

#### `domains`

> **Cảnh báo**: Đã deprecated kể từ Next.js 14 để ủng hộ [`remotePatterns`](#remotepatterns) nghiêm ngặt nhằm bảo vệ ứng dụng của bạn khỏi người dùng độc hại.

Tương tự như [`remotePatterns`](#remotepatterns), cấu hình `domains` có thể được sử dụng để cung cấp danh sách các hostname được phép cho hình ảnh bên ngoài. Tuy nhiên, cấu hình `domains` không hỗ trợ khớp wildcard pattern và nó không thể hạn chế protocol, port, hoặc pathname.

Vì hầu hết các server hình ảnh từ xa được chia sẻ giữa nhiều tenants, việc sử dụng `remotePatterns` an toàn hơn để đảm bảo chỉ các hình ảnh dự định mới được tối ưu hóa.

Dưới đây là ví dụ về property `domains` trong file `next.config.js`:

```js filename="next.config.js"
module.exports = {
  images: {
    domains: ['assets.acme.com'],
  },
}
```

## Functions

### `getImageProps`

Hàm `getImageProps` có thể được sử dụng để lấy các props sẽ được truyền cho phần tử `<img>` bên dưới, và thay vào đó truyền chúng cho component, style, canvas khác, v.v.

```jsx
import { getImageProps } from 'next/image'

const { props } = getImageProps({
  src: 'https://example.com/image.jpg',
  alt: 'A scenic mountain view',
  width: 1200,
  height: 800,
})

function ImageWithCaption() {
  return (
    <figure>
      <img {...props} />
      <figcaption>A scenic mountain view</figcaption>
    </figure>
  )
}
```

Điều này cũng tránh gọi React `useState()` nên nó có thể dẫn đến hiệu suất tốt hơn, nhưng nó không thể được sử dụng với prop [`placeholder`](#placeholder) vì placeholder sẽ không bao giờ bị loại bỏ.

## Known browser bugs

Component `next/image` này sử dụng [lazy loading](https://caniuse.com/loading-lazy-attr) gốc của trình duyệt, có thể fallback về eager loading cho các trình duyệt cũ hơn trước Safari 15.4. Khi sử dụng blur-up placeholder, các trình duyệt cũ hơn trước Safari 12 sẽ fallback về empty placeholder. Khi sử dụng styles với `width`/`height` là `auto`, có thể gây ra [Layout Shift](https://web.dev/cls/) trên các trình duyệt cũ hơn trước Safari 15 mà không [bảo toàn aspect ratio](https://caniuse.com/mdn-html_elements_img_aspect_ratio_computed_from_attributes). Để biết thêm chi tiết, xem [video MDN này](https://www.youtube.com/watch?v=4-d_SoCHeWE).

- [Safari 15 - 16.3](https://bugs.webkit.org/show_bug.cgi?id=243601) hiển thị một đường viền màu xám trong khi loading. Safari 16.4 [đã sửa vấn đề này](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/#:~:text=Now%20in%20Safari%2016.4%2C%20a%20gray%20line%20no%20longer%20appears%20to%20mark%20the%20space%20where%20a%20lazy%2Dloaded%20image%20will%20appear%20once%20it%E2%80%99s%20been%20loaded.). Các giải pháp khả thi:
  - Sử dụng CSS `@supports (font: -apple-system-body) and (-webkit-appearance: none) { img[loading="lazy"] { clip-path: inset(0.6px) } }`
  - Sử dụng [`loading="eager"`](#loading) nếu hình ảnh ở trên fold
- [Firefox 67+](https://bugzilla.mozilla.org/show_bug.cgi?id=1556156) hiển thị background trắng trong khi loading. Các giải pháp khả thi:
  - Kích hoạt [AVIF `formats`](#formats)
  - Sử dụng [`placeholder`](#placeholder)

### Styling images

Styling Image component tương tự như styling một phần tử `<img>` bình thường, nhưng có một vài hướng dẫn cần ghi nhớ:

Sử dụng `className` hoặc `style`, không phải `styled-jsx`. Trong hầu hết các trường hợp, chúng tôi khuyên bạn nên sử dụng prop `className`. Đây có thể là một [CSS Module](/docs/app/getting-started/css) đã import, một [global stylesheet](/docs/app/getting-started/css#global-css), v.v.

```jsx
import styles from './styles.module.css'

export default function MyImage() {
  return <Image className={styles.image} src="/my-image.png" alt="My Image" />
}
```

Bạn cũng có thể sử dụng prop `style` để gán inline styles.

```jsx
export default function MyImage() {
  return (
    <Image style={{ borderRadius: '8px' }} src="/my-image.png" alt="My Image" />
  )
}
```

Khi sử dụng `fill`, phần tử cha phải có `position: relative` hoặc `display: block`. Điều này là cần thiết để render chính xác phần tử hình ảnh trong chế độ layout đó.

```jsx
<div style={{ position: 'relative' }}>
  <Image fill src="/my-image.png" alt="My Image" />
</div>
```

Bạn không thể sử dụng [styled-jsx](/docs/app/guides/css-in-js) vì nó bị scope vào component hiện tại (trừ khi bạn đánh dấu style là `global`).

### Responsive images với static export

Khi bạn import một static image, Next.js tự động đặt width và height của nó dựa trên file. Bạn có thể làm cho hình ảnh responsive bằng cách đặt style:

<Image
  alt="Responsive image filling the width and height of its parent container"
  srcLight="/docs/light/responsive-image.png"
  srcDark="/docs/dark/responsive-image.png"
  width="1600"
  height="629"
/>

```jsx
import Image from 'next/image'
import mountains from '../public/mountains.jpg'

export default function Responsive() {
  return (
    <div style={{ display: 'flex', flexDirection: 'column' }}>
      <Image
        alt="Mountains"
        // Importing an image will
        // automatically set the width and height
        src={mountains}
        sizes="100vw"
        // Make the image display full width
        // and preserve its aspect ratio
        style={{
          width: '100%',
          height: 'auto',
        }}
      />
    </div>
  )
}
```

### Responsive images với remote URL

Nếu hình ảnh nguồn là dynamic hoặc remote URL, bạn phải cung cấp props width và height để Next.js có thể tính toán aspect ratio:

```jsx filename="components/page.js"
import Image from 'next/image'

export default function Page({ photoUrl }) {
  return (
    <Image
      src={photoUrl}
      alt="Picture of the author"
      sizes="100vw"
      style={{
        width: '100%',
        height: 'auto',
      }}
      width={500}
      height={300}
    />
  )
}
```

### Responsive image với `fill`

Nếu bạn không biết aspect ratio của hình ảnh, bạn có thể thêm [`fill` prop](#fill) với prop `objectFit` được đặt thành `cover`. Điều này sẽ làm cho hình ảnh lấp đầy toàn bộ chiều rộng của container cha của nó.

<Image
  alt="Grid of images filling parent container width"
  srcLight="/docs/light/fill-container.png"
  srcDark="/docs/dark/fill-container.png"
  width="1600"
  height="529"
/>

```jsx
import Image from 'next/image'
import mountains from '../public/mountains.jpg'

export default function Fill() {
  return (
    <div
      style={{
        display: 'grid',
        gridGap: '8px',
        gridTemplateColumns: 'repeat(auto-fit, minmax(400px, auto))',
      }}
    >
      <div style={{ position: 'relative', width: '400px' }}>
        <Image
          alt="Mountains"
          src={mountains}
          fill
          sizes="(min-width: 808px) 50vw, 100vw"
          style={{
            objectFit: 'cover', // cover, contain, none
          }}
        />
      </div>
      {/* And more images in the grid... */}
    </div>
  )
}
```

### Remote images

Để sử dụng hình ảnh từ xa, property `src` phải là một URL string.

```jsx filename="app/page.js"
import Image from 'next/image'

export default function Page() {
  return (
    <Image
      src="https://s3.amazonaws.com/my-bucket/profile.png"
      alt="Picture of the author"
      width={500}
      height={500}
    />
  )
}
```

Vì Next.js không có quyền truy cập vào các file từ xa trong quá trình build, bạn sẽ cần cung cấp các props [`width`](/docs/app/api-reference/components/image#width-and-height), [`height`](/docs/app/api-reference/components/image#width-and-height) và tùy chọn [`blurDataURL`](/docs/app/api-reference/components/image#blurdataurl) thủ công.

Các thuộc tính `width` và `height` được sử dụng để suy ra aspect ratio chính xác của hình ảnh và tránh layout shift từ việc load hình ảnh. `width` và `height` _không_ xác định kích thước render của file hình ảnh.

Để cho phép tối ưu hóa hình ảnh một cách an toàn, hãy định nghĩa danh sách các URL patterns được hỗ trợ trong `next.config.js`. Hãy cụ thể nhất có thể để ngăn chặn việc sử dụng độc hại. Ví dụ, cấu hình sau sẽ chỉ cho phép hình ảnh từ một AWS S3 bucket cụ thể:

```js filename="next.config.js"
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 's3.amazonaws.com',
        port: '',
        pathname: '/my-bucket/**',
        search: '',
      },
    ],
  },
}
```

### Theme detection

Nếu bạn muốn hiển thị một hình ảnh khác nhau cho chế độ sáng và tối, bạn có thể tạo một component mới bao bọc hai components `<Image>` và hiển thị cái chính xác dựa trên CSS media query.

```css filename="components/theme-image.module.css"
.imgDark {
  display: none;
}

@media (prefers-color-scheme: dark) {
  .imgLight {
    display: none;
  }
  .imgDark {
    display: unset;
  }
}
```

```tsx filename="components/theme-image.tsx" switcher
import styles from './theme-image.module.css'
import Image, { ImageProps } from 'next/image'

type Props = Omit<ImageProps, 'src' | 'preload' | 'loading'> & {
  srcLight: string
  srcDark: string
}

const ThemeImage = (props: Props) => {
  const { srcLight, srcDark, ...rest } = props

  return (
    <>
      <Image {...rest} src={srcLight} className={styles.imgLight} />
      <Image {...rest} src={srcDark} className={styles.imgDark} />
    </>
  )
}
```

```jsx filename="components/theme-image.js" switcher
import styles from './theme-image.module.css'
import Image from 'next/image'

const ThemeImage = (props) => {
  const { srcLight, srcDark, ...rest } = props

  return (
    <>
      <Image {...rest} src={srcLight} className={styles.imgLight} />
      <Image {...rest} src={srcDark} className={styles.imgDark} />
    </>
  )
}
```

> **Cần biết**: Hành vi mặc định của `loading="lazy"` đảm bảo rằng chỉ hình ảnh chính xác mới được load. Bạn không thể sử dụng `preload` hoặc `loading="eager"` vì điều đó sẽ khiến cả hai hình ảnh đều load. Thay vào đó, bạn có thể sử dụng [`fetchPriority="high"`](https://developer.mozilla.org/docs/Web/API/HTMLImageElement/fetchPriority).

### Art direction

Nếu bạn muốn hiển thị một hình ảnh khác nhau cho mobile và desktop, đôi khi được gọi là [Art Direction](https://developer.mozilla.org/en-US/docs/Learn/HTML/Multimedia_and_embedding/Responsive_images#art_direction), bạn có thể cung cấp các props `src`, `width`, `height`, và `quality` khác nhau cho `getImageProps()`.

```jsx filename="app/page.js"
import { getImageProps } from 'next/image'

export default function Home() {
  const common = { alt: 'Art Direction Example', sizes: '100vw' }
  const {
    props: { srcSet: desktop },
  } = getImageProps({
    ...common,
    width: 1440,
    height: 875,
    quality: 80,
    src: '/desktop.jpg',
  })
  const {
    props: { srcSet: mobile, ...rest },
  } = getImageProps({
    ...common,
    width: 750,
    height: 1334,
    quality: 70,
    src: '/mobile.jpg',
  })

  return (
    <picture>
      <source media="(min-width: 1000px)" srcSet={desktop} />
      <source media="(min-width: 500px)" srcSet={mobile} />
      <img {...rest} style={{ width: '100%', height: 'auto' }} />
    </picture>
  )
}
```

### Background CSS

Bạn thậm chí có thể chuyển đổi chuỗi `srcSet` thành hàm CSS [`image-set()`](https://developer.mozilla.org/en-US/docs/Web/CSS/image/image-set) để tối ưu hóa một background image.

```jsx filename="app/page.js"
import { getImageProps } from 'next/image'

function getBackgroundImage(srcSet = '') {
  const imageSet = srcSet
    .split(', ')
    .map((str) => {
      const [url, dpi] = str.split(' ')
      return `url("${url}") ${dpi}`
    })
    .join(', ')
  return `image-set(${imageSet})`
}

export default function Home() {
  const {
    props: { srcSet },
  } = getImageProps({ alt: '', width: 128, height: 128, src: '/img.png' })
  const backgroundImage = getBackgroundImage(srcSet)
  const style = { height: '100vh', width: '100vw', backgroundImage }

  return (
    <main style={style}>
      <h1>Hello World</h1>
    </main>
  )
}
```
