`<Link>` là một React component mở rộng phần tử HTML `<a>` để cung cấp [prefetching](/docs/app/getting-started/linking-and-navigating#prefetching) và client-side navigation giữa các routes. Đây là cách chính để điều hướng giữa các routes trong Next.js.

Cách sử dụng cơ bản:

<AppOnly>

```tsx filename="app/page.tsx" switcher
import Link from 'next/link'

export default function Page() {
  return <Link href="/dashboard">Dashboard</Link>
}
```

```jsx filename="app/page.js" switcher
import Link from 'next/link'

export default function Page() {
  return <Link href="/dashboard">Dashboard</Link>
}
```

</AppOnly>

<PagesOnly>

## Tham khảo

### `scroll`

**Mặc định là `true`.** Hành vi scroll mặc định của `<Link>` trong Next.js **là duy trì vị trí scroll**, tương tự như cách trình duyệt xử lý điều hướng back và forwards. Khi bạn điều hướng đến một [Page](/docs/app/api-reference/file-conventions/page) mới, vị trí scroll sẽ giữ nguyên miễn là Page hiển thị trong viewport. Tuy nhiên, nếu Page không hiển thị trong viewport, Next.js sẽ scroll đến đầu phần tử Page đầu tiên.

Khi `scroll = {false}`, Next.js sẽ không cố gắng scroll đến phần tử Page đầu tiên.

> **Lưu ý:** Next.js kiểm tra `scroll: false` trước khi quản lý hành vi scroll. Nếu scrolling được kích hoạt, nó xác định DOM node liên quan cho điều hướng và kiểm tra mỗi phần tử cấp cao nhất. Tất cả các phần tử không thể scroll và những phần tử không có HTML được render sẽ bị bỏ qua, bao gồm các phần tử sticky hoặc fixed positioned, và các phần tử không hiển thị như những phần tử được tính toán với `getBoundingClientRect`. Next.js sau đó tiếp tục qua các siblings cho đến khi nó xác định một phần tử có thể scroll hiển thị trong viewport.

```tsx filename="app/page.tsx" switcher
  return (
    <Link href="/dashboard" scroll={false}>
      Dashboard
```

### `prefetch`

<AppOnly>

Prefetching xảy ra khi một component `<Link />` vào viewport của người dùng (ban đầu hoặc thông qua scroll). Next.js prefetch và load route được liên kết (được biểu thị bởi `href`) và dữ liệu của nó ở background để cải thiện hiệu suất của client-side navigations. Nếu dữ liệu được prefetch đã hết hạn vào thời điểm người dùng di chuột qua `<Link />`, Next.js sẽ cố gắng prefetch lại. **Prefetching chỉ được kích hoạt trong production**.

Các giá trị sau có thể được truyền cho prop `prefetch`:

- **`"auto"` hoặc `null` (mặc định)**: Hành vi prefetch phụ thuộc vào route là static hay dynamic. Đối với static routes, toàn bộ route sẽ được prefetch (bao gồm tất cả dữ liệu của nó). Đối với dynamic routes, partial route xuống đến segment gần nhất có boundary [`loading.js`](/docs/app/api-reference/file-conventions/loading#instant-loading-states) sẽ được prefetch.
- `true`: Toàn bộ route sẽ được prefetch cho cả static và dynamic routes.
- `false`: Prefetching sẽ không bao giờ xảy ra cả khi vào viewport và khi hover.

```tsx filename="app/page.tsx" switcher
import Link from 'next/link'

export default function Page() {
  return (
    <Link href="/dashboard" prefetch={false}>
      Dashboard
    </Link>
  )
}
```

```jsx filename="app/page.js" switcher
import Link from 'next/link'

export default function Page() {
  return (
    <Link href="/dashboard" prefetch={false}>
      Dashboard
    </Link>
  )
}
```

</AppOnly>

### `locale`

Locale đang hoạt động được tự động thêm vào trước. `locale` cho phép cung cấp một locale khác. Khi `false`, `href` phải bao gồm locale vì hành vi mặc định bị vô hiệu hóa.

```tsx filename="pages/index.tsx" switcher
import Link from 'next/link'

export default function Home() {
  return (
    <>
      {/* Hành vi mặc định: locale được thêm vào trước */}
      <Link href="/dashboard">Dashboard (với locale)</Link>

      {/* Vô hiệu hóa việc thêm locale vào trước */}
      <Link href="/dashboard" locale={false}>
        Dashboard (không có locale)
      </Link>

      {/* Chỉ định một locale khác */}
      <Link href="/dashboard" locale="fr">
        Dashboard (French)
      </Link>
    </>
  )
}
```

### `as`

Decorator tùy chọn cho path sẽ được hiển thị trong thanh URL của trình duyệt. Trước Next.js 9.5.3, điều này được sử dụng cho dynamic routes, kiểm tra [tài liệu trước đây](https://github.com/vercel/next.js/blob/v9.5.2/docs/api-reference/next/link.md#dynamic-routes) của chúng tôi để xem cách nó hoạt động.

Khi path này khác với path được cung cấp trong `href`, hành vi `href`/`as` trước đây được sử dụng như được hiển thị trong [tài liệu trước đây](https://github.com/vercel/next.js/blob/v9.5.2/docs/api-reference/next/link.md#dynamic-routes).

</PagesOnly>

### `onNavigate`

Một event handler được gọi trong quá trình client-side navigation. Handler nhận một event object bao gồm phương thức `preventDefault()`, cho phép bạn hủy điều hướng nếu cần.

```tsx filename="app/page.tsx" switcher
import Link from 'next/link'

export default function Page() {
  return (
    <Link
      href="/dashboard"
      onNavigate={(e) => {
        // Chỉ thực thi trong SPA navigation
        console.log('Đang điều hướng...')

        // Tùy chọn ngăn điều hướng
        // e.preventDefault()
      }}
    >
      Dashboard
    </Link>
  )
}
```

```jsx filename="app/page.js" switcher
import Link from 'next/link'

export default function Page() {
  return (
    <Link
      href="/dashboard"
      onNavigate={(e) => {
        // Chỉ thực thi trong SPA navigation
        console.log('Đang điều hướng...')

        // Tùy chọn ngăn điều hướng
        // e.preventDefault()
      }}
    >
      Dashboard
    </Link>
  )
}
```

> **Lưu ý:** Mặc dù `onClick` và `onNavigate` có vẻ tương tự, chúng phục vụ các mục đích khác nhau. `onClick` thực thi cho tất cả các click events, trong khi `onNavigate` chỉ chạy trong client-side navigation. Một số khác biệt chính:
>
> - Khi sử dụng modifier keys (`Ctrl`/`Cmd` + Click), `onClick` thực thi nhưng `onNavigate` không vì Next.js ngăn điều hướng mặc định cho các tab mới.
> - External URLs sẽ không trigger `onNavigate` vì nó chỉ dành cho client-side và same-origin navigations.
> - Links với thuộc tính `download` sẽ hoạt động với `onClick` nhưng không với `onNavigate` vì trình duyệt sẽ coi URL được liên kết là một download.

### Liên kết đến dynamic route segments

Khi liên kết đến [dynamic segments](/docs/app/api-reference/file-conventions/dynamic-routes), bạn có thể sử dụng [template literals và interpolation](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Template_literals) để tạo danh sách các links. Ví dụ, để tạo danh sách các blog posts:

```tsx filename="app/blog/post-list.tsx" switcher
import Link from 'next/link'

interface Post {
  id: number
  title: string
  slug: string
}

export default function PostList({ posts }: { posts: Post[] }) {
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>
          <Link href={`/blog/${post.slug}`}>{post.title}</Link>
        </li>
      ))}
    </ul>
  )
}
```


### Kiểm tra active links

Bạn có thể sử dụng [`usePathname()`](/docs/app/api-reference/functions/use-pathname) để xác định xem một link có đang active hay không. Ví dụ, để thêm class vào active link, bạn có thể kiểm tra xem `pathname` hiện tại có khớp với `href` của link hay không:

```tsx filename="app/ui/nav-links.tsx" switcher
'use client'

import { usePathname } from 'next/navigation'
import Link from 'next/link'

export function Links() {
  const pathname = usePathname()

  return (
    <nav>
      <Link className={`link ${pathname === '/' ? 'active' : ''}`} href="/">
        Home
      </Link>

      <Link
        className={`link ${pathname === '/about' ? 'active' : ''}`}
        href="/about"
      >
        About
      </Link>
    </nav>
  )
}
```


### Scroll đến một `id`

Nếu bạn muốn scroll đến một `id` cụ thể khi điều hướng, bạn có thể thêm URL của mình với `#` hash link hoặc chỉ truyền hash link cho prop `href`. Điều này có thể thực hiện được vì `<Link>` render thành phần tử `<a>`.

```jsx
<Link href="/dashboard#settings">Settings</Link>

// Output
<a href="/dashboard#settings">Settings</a>
```

### Truyền URL Object

`Link` cũng có thể nhận một URL object và nó sẽ tự động format nó để tạo URL string:

```tsx filename="pages/index.ts" switcher
import Link from 'next/link'

function Home() {
  return (
    <ul>
      <li>
        <Link
          href={{
            pathname: '/about',
            query: { name: 'test' },
          }}
        >
          About us
        </Link>
      </li>
      <li>
        <Link
          href={{
            pathname: '/blog/[slug]',
            query: { slug: 'my-post' },
          }}
        >
          Blog Post
        </Link>
      </li>
    </ul>
  )
}

export default Home
```

```jsx filename="pages/index.js" switcher
import Link from 'next/link'

function Home() {
```

Bạn có thể sử dụng mọi property như được định nghĩa trong [tài liệu Node.js URL module](https://nodejs.org/api/url.html#url_url_strings_and_url_objects).

### Vô hiệu hóa scroll đến đầu trang

<AppOnly>

Hành vi scroll mặc định của `<Link>` trong Next.js **là duy trì vị trí scroll**, tương tự như cách trình duyệt xử lý điều hướng back và forwards. Khi bạn điều hướng đến một [Page](/docs/app/api-reference/file-conventions/page) mới, vị trí scroll sẽ giữ nguyên miễn là Page hiển thị trong viewport.

Tuy nhiên, nếu Page không hiển thị trong viewport, Next.js sẽ scroll đến đầu phần tử Page đầu tiên. Nếu bạn muốn vô hiệu hóa hành vi này, bạn có thể truyền `scroll={false}` cho component `<Link>`, hoặc `scroll: false` cho `router.push()` hoặc `router.replace()`.

```jsx filename="app/page.js" switcher
import Link from 'next/link'

export default function Page() {
  return (
    <Link href="/#hashid" scroll={false}>
      Vô hiệu hóa scroll đến đầu
    </Link>
  )
}
```

```tsx filename="app/page.tsx" switcher
import Link from 'next/link'

  return (

      Vô hiệu hóa scroll đến đầu
```

```jsx
// useRouter

```

</AppOnly>

### Prefetching links trong Proxy

Thông thường sử dụng [Proxy](/docs/app/api-reference/file-conventions/proxy) cho authentication hoặc các mục đích khác liên quan đến việc rewrite người dùng đến một trang khác. Để component `<Link />` prefetch links đúng cách với rewrites thông qua Proxy, bạn cần cho Next.js biết cả URL để hiển thị và URL để prefetch. Điều này là bắt buộc để tránh các fetches không cần thiết đến proxy để biết route chính xác để prefetch.

Ví dụ, nếu bạn muốn phục vụ một route `/dashboard` có authenticated và visitor views, bạn có thể thêm điều sau vào Proxy của mình để redirect người dùng đến trang chính xác:

```ts filename="proxy.ts" switcher
import { NextResponse } from 'next/server'

export function proxy(request: Request) {
  const nextUrl = request.nextUrl
  if (nextUrl.pathname === '/dashboard') {
    if (request.cookies.authToken) {
      return NextResponse.rewrite(new URL('/auth/dashboard', request.url))
    } else {
      return NextResponse.rewrite(new URL('/public/dashboard', request.url))
    }
  }
}
```


### Chặn điều hướng

Bạn có thể sử dụng prop `onNavigate` để chặn điều hướng khi đáp ứng các điều kiện nhất định, chẳng hạn như khi một form có các thay đổi chưa được lưu. Khi bạn cần chặn điều hướng qua nhiều components trong ứng dụng của mình (như ngăn điều hướng từ bất kỳ link nào trong khi form đang được chỉnh sửa), React Context cung cấp một cách sạch sẽ để chia sẻ blocking state này. Đầu tiên, tạo một context để theo dõi navigation blocking state:

```tsx filename="app/contexts/navigation-blocker.tsx" switcher
'use client'

import { createContext, useState, useContext } from 'react'

interface NavigationBlockerContextType {
  isBlocked: boolean
  setIsBlocked: (isBlocked: boolean) => void
}

export const NavigationBlockerContext =
  createContext<NavigationBlockerContextType>({
    isBlocked: false,
    setIsBlocked: () => {},
  })

export function NavigationBlockerProvider({
  children,
}: {
  children: React.ReactNode
}) {
  const [isBlocked, setIsBlocked] = useState(false)

  return (
    <NavigationBlockerContext.Provider value={{ isBlocked, setIsBlocked }}>
      {children}
    </NavigationBlockerContext.Provider>
  )
}

export function useNavigationBlocker() {
  return useContext(NavigationBlockerContext)
}
```
