Tài liệu API này sẽ giúp bạn hiểu cách sử dụng [props](#props) có sẵn cho Script Component. Để biết về tính năng và cách sử dụng, vui lòng xem trang [Optimizing Scripts](/docs/app/guides/scripts).

```tsx filename="app/dashboard/page.tsx" switcher
import Script from 'next/script'

export default function Dashboard() {
  return (
    <>
      <Script src="https://example.com/script.js" />
    </>
  )
}
```

```jsx filename="app/dashboard/page.js" switcher
import Script from 'next/script'

  return (
    <>
      <Script src="https://example.com/script.js" />
    </>
  )

```

## Props

Đây là tóm tắt các props có sẵn cho Script Component:

| Prop                    | Ví dụ                             | Type     | Bắt buộc                               |
| ----------------------- | --------------------------------- | -------- | -------------------------------------- |
| [`src`](#src)           | `src="http://example.com/script"` | String   | Bắt buộc trừ khi sử dụng inline script |
| [`strategy`](#strategy) | `strategy="lazyOnload"`           | String   | -                                      |
| [`onLoad`](#onload)     | `onLoad={onLoadFunc}`             | Function | -                                      |
| [`onReady`](#onready)   | `onReady={onReadyFunc}`           | Function | -                                      |
| [`onError`](#onerror)   | `onError={onErrorFunc}`           | Function | -                                      |

## Props bắt buộc

Component `<Script />` yêu cầu các properties sau.

### `src`

Một path string chỉ định URL của external script. Đây có thể là absolute external URL hoặc internal path. Property `src` là bắt buộc trừ khi sử dụng inline script.

## Props tùy chọn

Component `<Script />` chấp nhận một số properties bổ sung ngoài những properties bắt buộc.

### `strategy`

Chiến lược loading của script. Có bốn chiến lược khác nhau có thể được sử dụng:

- `beforeInteractive`: Load trước bất kỳ Next.js code nào và trước khi page hydration xảy ra.
- `afterInteractive`: (**mặc định**) Load sớm nhưng sau khi một số hydration trên trang xảy ra.
- `lazyOnload`: Load trong thời gian browser idle.
- `worker`: (thử nghiệm) Load trong web worker.

### `beforeInteractive`

Các scripts load với chiến lược `beforeInteractive` được inject vào initial HTML từ server, được download trước bất kỳ Next.js module nào, và được thực thi theo thứ tự chúng được đặt.

Các scripts được đánh dấu với chiến lược này được preload và fetch trước bất kỳ first-party code nào, nhưng việc thực thi của chúng **không block page hydration khỏi việc xảy ra**.

<AppOnly>

Các scripts `beforeInteractive` phải được đặt bên trong root layout (`app/layout.tsx`) và được thiết kế để load các scripts cần thiết cho toàn bộ site (tức là script sẽ load khi bất kỳ trang nào trong ứng dụng đã được load server-side).

</AppOnly>

<PagesOnly>

Các scripts `beforeInteractive` phải được đặt bên trong Document Component (`pages/_document.js`) và được thiết kế để load các scripts cần thiết cho toàn bộ site (tức là script sẽ load khi bất kỳ trang nào trong ứng dụng đã được load server-side).

</PagesOnly>

**Chiến lược này chỉ nên được sử dụng cho các scripts quan trọng cần được fetch càng sớm càng tốt.**

<AppOnly>

```tsx filename="app/layout.tsx" switcher

  children,

  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>
        {children}
        <Script
          src="https://example.com/script.js"
          strategy="beforeInteractive"
        />
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher

  return (

        {children}

        />
      </body>
    </html>
  )

```

</AppOnly>

```jsx filename="pages/_document.js"

  return (
    <Html>
```

> **Lưu ý:** Các scripts với `beforeInteractive` sẽ luôn được inject vào `head` của HTML document bất kể nó được đặt ở đâu trong component.

Một số ví dụ về scripts nên được fetch càng sớm càng tốt với `beforeInteractive` bao gồm:

- Bot detectors
- Cookie consent managers

### `afterInteractive`

Các scripts sử dụng chiến lược `afterInteractive` được inject vào HTML client-side và sẽ load sau khi một số (hoặc tất cả) hydration xảy ra trên trang. **Đây là chiến lược mặc định** của Script component và nên được sử dụng cho bất kỳ script nào cần load càng sớm càng tốt nhưng không trước bất kỳ first-party Next.js code nào.

Các scripts `afterInteractive` có thể được đặt bên trong bất kỳ page hoặc layout nào và sẽ chỉ load và execute khi trang (hoặc nhóm trang) đó được mở trong trình duyệt.

```jsx filename="app/page.js"
import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script src="https://example.com/script.js" strategy="afterInteractive" />
    </>
  )
}
```

Một số ví dụ về scripts là ứng cử viên tốt cho `afterInteractive` bao gồm:

- Tag managers
- Analytics

### `lazyOnload`

Các scripts sử dụng chiến lược `lazyOnload` được inject vào HTML client-side trong thời gian browser idle và sẽ load sau khi tất cả resources trên trang đã được fetch. Chiến lược này nên được sử dụng cho bất kỳ background hoặc low priority scripts nào không cần load sớm.

Các scripts `lazyOnload` có thể được đặt bên trong bất kỳ page hoặc layout nào và sẽ chỉ load và execute khi trang (hoặc nhóm trang) đó được mở trong trình duyệt.

```jsx filename="app/page.js"
import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script src="https://example.com/script.js" strategy="lazyOnload" />
    </>
  )
}
```

Ví dụ về các scripts không cần load ngay lập tức và có thể được fetch với `lazyOnload` bao gồm:

- Chat support plugins
- Social media widgets

### `worker`

> **Cảnh báo:** Chiến lược `worker` chưa ổn định và chưa hoạt động với App Router. Sử dụng một cách thận trọng.

Các scripts sử dụng chiến lược `worker` được off-load vào web worker để giải phóng main thread và đảm bảo rằng chỉ các critical, first-party resources được xử lý trên đó. Mặc dù chiến lược này có thể được sử dụng cho bất kỳ script nào, nó là một use case nâng cao không được đảm bảo hỗ trợ tất cả third-party scripts.

Để sử dụng `worker` làm chiến lược, cờ `nextScriptWorkers` phải được kích hoạt trong `next.config.js`:

```js filename="next.config.js"
module.exports = {
  experimental: {
    nextScriptWorkers: true,
  },
}
```

Các scripts `worker` **hiện chỉ có thể được sử dụng trong thư mục `pages/`**:

```tsx filename="pages/home.tsx" switcher
import Script from 'next/script'

export default function Home() {
  return (
    <>
      <Script src="https://example.com/script.js" strategy="worker" />
    </>
  )
}
```

```jsx filename="pages/home.js" switcher

export default function Home() {
  return (
    <>
      <Script src="https://example.com/script.js" strategy="worker" />
    </>
  )

```

### `onLoad`

> **Cảnh báo:** `onLoad` chưa hoạt động với Server Components và chỉ có thể được sử dụng trong Client Components. Hơn nữa, `onLoad` không thể được sử dụng với `beforeInteractive` – hãy cân nhắc sử dụng `onReady` thay thế.

Một số third-party scripts yêu cầu người dùng chạy JavaScript code một lần sau khi script đã hoàn tất loading để instantiate content hoặc gọi một function. Nếu bạn đang loading một script với `afterInteractive` hoặc `lazyOnload` làm loading strategy, bạn có thể execute code sau khi nó đã load bằng cách sử dụng property `onLoad`.

Đây là một ví dụ về việc thực thi một lodash method chỉ sau khi library đã được load.

```tsx filename="app/page.tsx" switcher
'use client'

import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script
        src="https://cdnjs.cloudflare.com/ajax/libs/lodash.js/4.17.20/lodash.min.js"
        onLoad={() => {
          console.log(_.sample([1, 2, 3, 4]))
        }}
      />
    </>
  )
}
```

```jsx filename="app/page.js" switcher
'use client'

import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script
        src="https://cdnjs.cloudflare.com/ajax/libs/lodash.js/4.17.20/lodash.min.js"
        onLoad={() => {
          console.log(_.sample([1, 2, 3, 4]))
        }}
      />
    </>
  )
}
```

### `onReady`

> **Cảnh báo:** `onReady` chưa hoạt động với Server Components và chỉ có thể được sử dụng trong Client Components.

Một số third-party scripts yêu cầu người dùng chạy JavaScript code sau khi script đã hoàn tất loading và mỗi lần component được mount (sau một route navigation chẳng hạn). Bạn có thể execute code sau load event của script khi nó load lần đầu tiên và sau đó sau mỗi lần component re-mount tiếp theo bằng cách sử dụng property `onReady`.

Đây là một ví dụ về cách re-instantiate một Google Maps JS embed mỗi lần component được mount:

<AppOnly>

```tsx filename="app/page.tsx" switcher
'use client'

import { useRef } from 'react'
import Script from 'next/script'

export default function Page() {
  const mapRef = useRef()

  return (
    <>
      <div ref={mapRef}></div>
      <Script
        id="google-maps"
        src="https://maps.googleapis.com/maps/api/js"
        onReady={() => {
          new google.maps.Map(mapRef.current, {
            center: { lat: -34.397, lng: 150.644 },
            zoom: 8,
          })
        }}
      />
    </>
  )
}
```

### `onError`

> **Cảnh báo:** `onError` chưa hoạt động với Server Components và chỉ có thể được sử dụng trong Client Components. `onError` không thể được sử dụng với loading strategy `beforeInteractive`.

Đôi khi việc bắt lỗi khi một script không load được là hữu ích. Những lỗi này có thể được xử lý với property `onError`:

<AppOnly>

```tsx filename="app/page.tsx" switcher
'use client'

import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script
        src="https://example.com/script.js"
        onError={(e: Error) => {
          console.error('Script failed to load', e)
        }}
      />
    </>
  )
}
```

```jsx filename="app/page.js" switcher
'use client'

import Script from 'next/script'

export default function Page() {

        src="https://example.com/script.js"
```
