Chỉ thị `use cache` cho phép bạn đánh dấu một route, React component, hoặc một hàm là có thể cache được. Nó có thể được sử dụng ở đầu file để chỉ ra rằng tất cả exports trong file nên được cache, hoặc inline ở đầu hàm hoặc component để cache giá trị trả về.

> **Lưu ý:** Để cache nội dung dành riêng cho người dùng cần truy cập cookies hoặc headers, xem [`'use cache: private'`](/docs/app/api-reference/directives/use-cache-private).

## Cách sử dụng

`use cache` là một tính năng của Cache Components. Để kích hoạt nó, thêm tùy chọn [`cacheComponents`](/docs/app/api-reference/config/next-config-js/cacheComponents) vào file `next.config.ts` của bạn:

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
}

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  cacheComponents: true,
}

module.exports = nextConfig
```

Sau đó, thêm `use cache` ở cấp file, component, hoặc function:

```tsx
// Cấp file
'use cache'

export default async function Page() {
  // ...
}

// Cấp component
export async function MyComponent() {
  'use cache'
  return <></>
}

// Cấp function
export async function getData() {
  'use cache'
  const data = await fetch('/api/data')
  return data
}
```

## Cách `use cache` hoạt động

### Cache keys

Khóa của một cache entry được tạo bằng cách sử dụng phiên bản serialized của các đầu vào, bao gồm:

- Build ID (được tạo cho mỗi lần build)
- Function ID (một định danh bảo mật duy nhất cho hàm)
- Các đối số hàm [serializable](https://react.dev/reference/rsc/use-server#serializable-parameters-and-return-values) (hoặc props).

Các đối số được truyền vào hàm được cache, cũng như bất kỳ giá trị nào nó đọc từ phạm vi cha tự động trở thành một phần của khóa. Điều này có nghĩa là, cùng một cache entry sẽ được sử dụng lại miễn là các đầu vào của nó giống nhau.

## Đối số không thể serialize

Bất kỳ đối số, props, hoặc giá trị đóng không thể serialize nào sẽ biến thành tham chiếu bên trong hàm được cache, và chỉ có thể được truyền qua mà không thể kiểm tra hoặc sửa đổi. Các giá trị không thể serialize này sẽ được điền vào tại thời điểm request và sẽ không trở thành một phần của cache key.

Ví dụ, một hàm được cache có thể nhận JSX làm prop `children` và trả về `<div>{children}</div>`, nhưng nó sẽ không thể kiểm tra đối tượng `children` thực tế. Điều này cho phép bạn lồng nội dung không được cache bên trong một component được cache.

```tsx filename="app/ui/cached-component.tsx" switcher
function CachedComponent({ children }: { children: ReactNode }) {
  'use cache'
  return <div>{children}</div>
}
```

```jsx filename="app/ui/cached-component.js" switcher
function CachedComponent({ children }) {
  'use cache'
  return <div>{children}</div>
}
```

## Giá trị trả về

Giá trị trả về của hàm có thể cache phải là serializable. Điều này đảm bảo rằng dữ liệu được cache có thể được lưu trữ và truy xuất một cách chính xác.

## `use cache` tại thời điểm build

Khi được sử dụng ở đầu một [layout](/docs/app/api-reference/file-conventions/layout) hoặc [page](/docs/app/api-reference/file-conventions/page), route segment sẽ được prerender, cho phép nó sau này được [revalidate](#during-revalidation).

Điều này có nghĩa là `use cache` không thể được sử dụng với [runtime data](/docs/app/getting-started/cache-components#1-suspense-for-runtime-data) như `cookies` hoặc `headers`.

> **Lưu ý:** Nếu bạn cần cache nội dung phụ thuộc vào cookies, headers, hoặc search params, hãy sử dụng [`'use cache: private'`](/docs/app/api-reference/directives/use-cache-private) thay thế.

## `use cache` tại runtime

Trên **server**, các cache entries của từng component hoặc hàm sẽ được cache trong bộ nhớ.

Sau đó, trên **client**, bất kỳ nội dung nào được trả về từ server cache sẽ được lưu trữ trong bộ nhớ của trình duyệt trong suốt phiên làm việc hoặc cho đến khi được [revalidate](#during-revalidation).

## Trong quá trình revalidation

Mặc định, `use cache` có chu kỳ revalidation phía server là **15 phút**. Mặc dù chu kỳ này có thể hữu ích cho nội dung không yêu cầu cập nhật thường xuyên, bạn có thể sử dụng các API `cacheLife` và `cacheTag` để cấu hình khi nào các cache entries riêng lẻ nên được revalidate.

- [`cacheLife`](/docs/app/api-reference/functions/cacheLife): Cấu hình thời gian tồn tại của cache entry.
- [`cacheTag`](/docs/app/api-reference/functions/cacheTag): Tạo tags để revalidate theo yêu cầu.

Cả hai API này đều tích hợp qua các lớp caching client và server, có nghĩa là bạn có thể cấu hình ngữ nghĩa caching của mình ở một nơi và áp dụng chúng ở mọi nơi.

Xem tài liệu API [`cacheLife`](/docs/app/api-reference/functions/cacheLife) và [`cacheTag`](/docs/app/api-reference/functions/cacheTag) để biết thêm thông tin.

## Ví dụ

### Cache toàn bộ route với `use cache`

Để prerender toàn bộ route, thêm `use cache` vào đầu **cả hai** file `layout` và `page`. Mỗi segment này được coi là các entry point riêng biệt trong ứng dụng của bạn, và sẽ được cache độc lập.

```tsx filename="app/layout.tsx" switcher
'use cache'

export default function Layout({ children }: { children: ReactNode }) {
  return <div>{children}</div>
}
```

```jsx filename="app/page.tsx" switcher
'use cache'

export default function Layout({ children }) {
  return <div>{children}</div>
}
```

Bất kỳ component nào được import và lồng trong file `page` đều là một phần của cache output liên kết với `page`.

```tsx filename="app/page.tsx" switcher
'use cache'

async function Users() {
  const users = await fetch('/api/users')
  // lặp qua users
}

export default function Page() {
  return (
    <main>
      <Users />
    </main>
  )
}
```

```jsx filename="app/page.js" switcher
'use cache'

async function Users() {
  const users = await fetch('/api/users')
  // lặp qua users
}

export default function Page() {
  return (
    <main>
      <Users />
    </main>
  )
}
```

> **Lưu ý**:
>
> - Nếu `use cache` chỉ được thêm vào `layout` hoặc `page`, chỉ route segment đó và bất kỳ component nào được import vào nó sẽ được cache.
> - Nếu bất kỳ children lồng nhau nào trong route sử dụng [Dynamic APIs](/docs/app/guides/caching#dynamic-rendering), thì route sẽ opt out khỏi pre-rendering.

### Cache output của component với `use cache`

Bạn có thể sử dụng `use cache` ở cấp component để cache bất kỳ fetches hoặc tính toán nào được thực hiện trong component đó. Cache entry sẽ được sử dụng lại miễn là các props được serialize tạo ra cùng một giá trị trong mỗi instance.

```tsx filename="app/components/bookings.tsx" highlight={2} switcher
export async function Bookings({ type = 'haircut' }: BookingsProps) {
  'use cache'
  async function getBookingsData() {
    const data = await fetch(`/api/bookings?type=${encodeURIComponent(type)}`)
    return data
  }
  return //...
}

interface BookingsProps {
  type: string
}
```

```jsx filename="app/components/bookings.js" highlight={2} switcher
export async function Bookings({ type = 'haircut' }) {
  'use cache'
  async function getBookingsData() {
    const data = await fetch(`/api/bookings?type=${encodeURIComponent(type)}`)
    return data
  }
  return //...
}
```

### Cache output của hàm với `use cache`

Vì bạn có thể thêm `use cache` vào bất kỳ hàm bất đồng bộ nào, bạn không bị giới hạn chỉ cache components hoặc routes. Bạn có thể muốn cache một network request, một database query, hoặc một tính toán chậm.

```tsx filename="app/actions.ts" highlight={2} switcher
export async function getData() {
  'use cache'

  const data = await fetch('/api/data')
  return data
}
```

```jsx filename="app/actions.js" highlight={2} switcher
export async function getData() {
  'use cache'

  const data = await fetch('/api/data')
  return data
}
```

### Interleaving

Trong React, composition với `children` hoặc slots là một pattern nổi tiếng để xây dựng các component linh hoạt. Khi sử dụng `use cache`, bạn có thể tiếp tục compose UI của mình theo cách này. Bất cứ thứ gì được bao gồm như `children`, hoặc các compositional slots khác, trong JSX được trả về sẽ được truyền qua component được cache mà không ảnh hưởng đến cache entry của nó.

Miễn là bạn không tham chiếu trực tiếp bất kỳ JSX slots nào bên trong thân của hàm có thể cache, sự hiện diện của chúng trong output được trả về sẽ không ảnh hưởng đến cache entry.

```tsx filename="app/page.tsx" switcher
export default async function Page() {
  const uncachedData = await getData()
  return (
    // Truyền compositional slots làm props, ví dụ: header và children
    <CacheComponent header={<h1>Home</h1>}>
      {/* DynamicComponent được cung cấp như children slot */}
      <DynamicComponent data={uncachedData} />
    </CacheComponent>
  )
}

async function CacheComponent({
  header, // header: một compositional slot, được inject như một prop
  children, // children: một slot khác cho nested composition
}: {
  header: ReactNode
  children: ReactNode
}) {
  'use cache'
  const cachedData = await fetch('/api/cached-data')
  return (
    <div>
      {header}
      <PrerenderedComponent data={cachedData} />
      {children}
    </div>
  )
}
```

```jsx filename="app/page.js" switcher
export default async function Page() {
  const uncachedData = await getData()
  return (
    // Truyền compositional slots làm props, ví dụ: header và children
    <CacheComponent header={<h1>Home</h1>}>
      {/* DynamicComponent được cung cấp như children slot */}
      <DynamicComponent data={uncachedData} />
    </CacheComponent>
  )
}

async function CacheComponent({
  header, // header: một compositional slot, được inject như một prop
  children, // children: một slot khác cho nested composition
}) {
  'use cache'
  const cachedData = await fetch('/api/cached-data')
  return (
    <div>
      {header}
      <PrerenderedComponent data={cachedData} />
      {children}
    </div>
  )
}
```

Bạn cũng có thể truyền Server Actions qua các cached components đến Client Components mà không gọi chúng bên trong hàm có thể cache.

```tsx filename="app/page.tsx" switcher
import ClientComponent from './ClientComponent'

export default async function Page() {
  const performUpdate = async () => {
    'use server'
    // Thực hiện một số cập nhật phía server
    await db.update(...)
  }

  return <CacheComponent performUpdate={performUpdate} />
}

async function CachedComponent({
  performUpdate,
}: {
  performUpdate: () => Promise<void>
}) {
  'use cache'
  // Không gọi performUpdate ở đây
  return <ClientComponent action={performUpdate} />
}
```

```jsx filename="app/page.js" switcher
import ClientComponent from './ClientComponent'

export default async function Page() {
  const performUpdate = async () => {
    'use server'
    // Thực hiện một số cập nhật phía server

  }

  return <CacheComponent performUpdate={performUpdate} />
}

async function CachedComponent({ performUpdate }) {
  'use cache'
  // Không gọi performUpdate ở đây
  return <ClientComponent action={performUpdate} />
}
```

```tsx filename="app/ClientComponent.tsx" switcher
'use client'

export default function ClientComponent({
  action,
}: {
  action: () => Promise<void>
}) {
  return <button onClick={action}>Update</button>
}
```

```jsx filename="app/ClientComponent.js" switcher

```
