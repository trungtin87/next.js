Hàm `cacheLife` được sử dụng để đặt thời gian tồn tại cache của một hàm hoặc component. Nó nên được sử dụng cùng với directive [`use cache`](/docs/app/api-reference/directives/use-cache), và trong phạm vi của hàm hoặc component.

## Sử dụng

Để sử dụng `cacheLife`, hãy bật [cờ `cacheComponents`](/docs/app/api-reference/config/next-config-js/cacheComponents) trong file `next.config.js` của bạn:

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
}

export default nextConfig
```

```js filename="next.config.js" switcher
const nextConfig = {
  cacheComponents: true,
}

export default nextConfig
```

Sau đó, import và gọi hàm `cacheLife` trong phạm vi của hàm hoặc component:

```tsx filename="app/page.tsx" highlight={5} switcher
'use cache'
import { cacheLife } from 'next/cache'

export default async function Page() {
  cacheLife('hours')
  return <div>Page</div>
}
```

```jsx filename="app/page.js" highlight={5} switcher
'use cache'
import { cacheLife } from 'next/cache'

export default async function Page() {
  cacheLife('hours')
  return <div>Page</div>
}
```

## Tham khảo

### Các cache profiles mặc định

Next.js cung cấp một tập hợp các cache profiles được đặt tên mô phỏng theo các khoảng thời gian khác nhau. Nếu bạn không chỉ định một cache profile trong hàm `cacheLife` cùng với directive `use cache`, Next.js sẽ tự động áp dụng cache profile `default`.

Tuy nhiên, chúng tôi khuyên bạn luôn thêm một cache profile khi sử dụng directive `use cache` để định nghĩa rõ ràng hành vi caching.

| **Profile** | `stale` | `revalidate` | `expire` | **Mô tả**                                                                 |
| ----------- | ------- | ------------ | -------- | ------------------------------------------------------------------------- |
| `default`   | 5 phút  | 15 phút      | 1 năm    | Profile mặc định, phù hợp cho nội dung không cần cập nhật thường xuyên    |
| `seconds`   | 30 giây | 1 giây       | 1 phút   | Cho nội dung thay đổi nhanh chóng yêu cầu cập nhật gần như thời gian thực |
| `minutes`   | 5 phút  | 1 phút       | 1 giờ    | Cho nội dung cập nhật thường xuyên trong vòng một giờ                     |
| `hours`     | 5 phút  | 1 giờ        | 1 ngày   | Cho nội dung cập nhật hàng ngày nhưng có thể hơi cũ                       |
| `days`      | 5 phút  | 1 ngày       | 1 tuần   | Cho nội dung cập nhật hàng tuần nhưng có thể cũ một ngày                  |
| `weeks`     | 5 phút  | 1 tuần       | 30 ngày  | Cho nội dung cập nhật hàng tháng nhưng có thể cũ một tuần                 |
| `max`       | 5 phút  | 30 ngày      | 1 năm    | Cho nội dung rất ổn định hiếm khi cần cập nhật                            |

Các giá trị chuỗi được sử dụng để tham chiếu cache profiles không mang ý nghĩa cố hữu; thay vào đó chúng đóng vai trò là các nhãn ngữ nghĩa. Điều này cho phép bạn hiểu rõ hơn và quản lý nội dung được cache trong codebase của mình.

> **Lưu ý:** Cập nhật các tùy chọn cấu hình [`staleTimes`](/docs/app/api-reference/config/next-config-js/staleTimes) và [`expireTime`](/docs/app/api-reference/config/next-config-js/expireTime) cũng cập nhật các thuộc tính `stale` và `expire` của cache profile `default`.

### Các cache profiles tùy chỉnh

Bạn có thể cấu hình các cache profiles tùy chỉnh bằng cách thêm chúng vào tùy chọn [`cacheLife`](/docs/app/api-reference/config/next-config-js/cacheLife) trong file `next.config.ts` của bạn.

Cache profiles là các objects chứa các thuộc tính sau:

| **Thuộc tính** | **Giá trị** | **Mô tả**                                                                                                             | **Yêu cầu**                          |
| -------------- | ----------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| `stale`        | `number`    | Thời lượng client nên cache một giá trị mà không cần kiểm tra server.                                                 | Tùy chọn                             |
| `revalidate`   | `number`    | Tần suất cache nên refresh trên server; các giá trị cũ có thể được phục vụ trong khi revalidating.                    | Tùy chọn                             |
| `expire`       | `number`    | Thời lượng tối đa mà một giá trị có thể duy trì cũ trước khi chuyển sang dynamic fetching; phải dài hơn `revalidate`. | Tùy chọn - Phải dài hơn `revalidate` |

Thuộc tính "stale" khác với cài đặt [`staleTimes`](/docs/app/api-reference/config/next-config-js/staleTimes) ở chỗ nó kiểm soát cụ thể client-side router caching. Trong khi `staleTimes` là một cài đặt global ảnh hưởng đến tất cả các instances của cả dữ liệu dynamic và static, cấu hình `cacheLife` cho phép bạn định nghĩa thời gian "stale" trên cơ sở từng hàm hoặc từng route.

### Thời gian `stale` trong client router cache

Thuộc tính "stale" không đặt header `Cache-control: max-age`. Thay vào đó, nó kiểm soát client-side router cache. Server gửi giá trị này đến client thông qua response header `x-nextjs-stale-time` (tính bằng giây), mà client router sử dụng để xác định bao lâu để cache route trước khi cần revalidate.

**Client thực thi thời gian stale tối thiểu là 30 giây**: Điều này đảm bảo rằng dữ liệu đã prefetch vẫn có thể sử dụng đủ lâu để người dùng nhấp vào các liên kết sau khi chúng đã được prefetch. Nếu không có mức tối thiểu này, thời gian stale rất ngắn sẽ khiến dữ liệu đã prefetch hết hạn trước khi nó có thể được sử dụng, làm cho việc prefetching không hiệu quả.

Mức tối thiểu này chỉ áp dụng cho việc hết hạn dựa trên thời gian. Khi bạn gọi [`revalidateTag`](/docs/app/api-reference/functions/revalidateTag), [`revalidatePath`](/docs/app/api-reference/functions/revalidatePath), [`updateTag`](/docs/app/api-reference/functions/updateTag), hoặc [`refresh`](/docs/app/api-reference/functions/refresh) từ một Server Action, toàn bộ client cache sẽ bị xóa ngay lập tức, bỏ qua hoàn toàn thời gian stale.

## Ví dụ

### Định nghĩa các cache profiles tái sử dụng

Bạn có thể tạo một cache profile tái sử dụng bằng cách định nghĩa chúng trong file `next.config.ts` của bạn. Chọn một tên phù hợp với trường hợp sử dụng của bạn và đặt giá trị cho các thuộc tính `stale`, `revalidate`, và `expire`. Bạn có thể tạo bao nhiêu cache profiles tùy chỉnh nếu cần. Mỗi profile có thể được tham chiếu bởi tên của nó dưới dạng một giá trị chuỗi được truyền cho hàm `cacheLife`.

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  cacheLife: {
    biweekly: {
      stale: 60 * 60 * 24 * 14, // 14 ngày
      revalidate: 60 * 60 * 24, // 1 ngày
      expire: 60 * 60 * 24 * 14, // 14 ngày
    },
  },
}

module.exports = nextConfig
```

```js filename="next.config.js" switcher
const nextConfig = {
  cacheComponents: true,
  cacheLife: {
    biweekly: {
      stale: 60 * 60 * 24 * 14, // 14 ngày
      revalidate: 60 * 60 * 24, // 1 ngày
      expire: 60 * 60 * 24 * 14, // 14 ngày
    },
  },
}

module.exports = nextConfig
```

Ví dụ trên cache trong 14 ngày, kiểm tra cập nhật hàng ngày, và hết hạn cache sau 14 ngày. Sau đó, bạn có thể tham chiếu profile này trong toàn bộ ứng dụng của mình bằng tên của nó:

```tsx filename="app/page.tsx" highlight={5}
'use cache'
import { cacheLife } from 'next/cache'

export default async function Page() {
  cacheLife('biweekly')
  return <div>Page</div>
}
```

### Ghi đè các cache profiles mặc định

Mặc dù các cache profiles mặc định cung cấp một cách hữu ích để suy nghĩ về độ mới hoặc cũ của bất kỳ phần output có thể cache nào, bạn có thể thích các profiles được đặt tên khác nhau để phù hợp hơn với các chiến lược caching của ứng dụng của bạn.

Bạn có thể ghi đè các cache profiles được đặt tên mặc định bằng cách tạo một cấu hình mới có cùng tên với các mặc định.

Ví dụ dưới đây cho thấy cách ghi đè cache profile "days" mặc định:

```ts filename="next.config.ts"
const nextConfig = {
  cacheComponents: true,
  cacheLife: {
    days: {
      stale: 3600, // 1 giờ
      revalidate: 900, // 15 phút
      expire: 86400, // 1 ngày
    },
  },
}

module.exports = nextConfig
```

### Định nghĩa cache profiles inline

Đối với các trường hợp sử dụng cụ thể, bạn có thể đặt một cache profile tùy chỉnh bằng cách truyền một object cho hàm `cacheLife`:

```tsx filename="app/page.tsx" highlight={5-9} switcher
'use cache'
import { cacheLife } from 'next/cache'

export default async function Page() {
  cacheLife({
    stale: 3600, // 1 giờ
    revalidate: 900, // 15 phút
    expire: 86400, // 1 ngày
  })

  return <div>Page</div>
}
```

```jsx filename="app/page.js" highlight={5-9} switcher
'use cache'
import { cacheLife } from 'next/cache'

export default async function Page() {
  cacheLife({
    stale: 3600, // 1 giờ
    revalidate: 900, // 15 phút
    expire: 86400, // 1 ngày
  })

  return <div>Page</div>
}
```

Cache profile inline này sẽ chỉ được áp dụng cho hàm hoặc file mà nó được tạo ra. Nếu bạn muốn tái sử dụng cùng một profile trong toàn bộ ứng dụng của mình, bạn có thể [thêm cấu hình](#defining-reusable-cache-profiles) vào thuộc tính `cacheLife` của file `next.config.ts` của bạn.

### Sử dụng lồng nhau của `use cache` và `cacheLife`

Khi định nghĩa nhiều hành vi caching trong cùng một route hoặc component tree, nếu các caches bên trong chỉ định profile `cacheLife` riêng của chúng, cache bên ngoài sẽ tôn trọng thời lượng cache ngắn nhất trong số chúng. **Điều này chỉ áp dụng nếu cache bên ngoài không có profile `cacheLife` rõ ràng của riêng nó được định nghĩa.**

Ví dụ, nếu bạn thêm directive `use cache` vào page của mình, mà không chỉ định một cache profile, cache profile mặc định sẽ được áp dụng ngầm (`cacheLife("default")`). Nếu một component được import vào page cũng sử dụng directive `use cache` với cache profile riêng của nó, các cache profiles bên ngoài và bên trong được so sánh, và thời lượng ngắn nhất được đặt trong các profiles sẽ được áp dụng.

```tsx filename="app/components/parent.tsx" highlight={5,6}
// Parent component
import { cacheLife } from 'next/cache'
import { ChildComponent } from './child'

export async function ParentComponent() {
  'use cache'
  cacheLife('days')

  return (
    <div>
      <ChildComponent />
    </div>
  )
}
```

Và trong một file riêng biệt, chúng tôi đã định nghĩa Child component đã được import:

```tsx filename="app/components/child.tsx" highlight={4,5}
// Child component
import { cacheLife } from 'next/cache'

export async function ChildComponent() {
  'use cache'
  cacheLife('hours')
  return <div>Child Content</div>

  // Cache của component này sẽ tôn trọng profile 'hours' ngắn hơn
}
```
