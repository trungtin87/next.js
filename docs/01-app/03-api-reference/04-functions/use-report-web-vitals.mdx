Hook `useReportWebVitals` cho phép bạn báo cáo [Core Web Vitals](https://web.dev/vitals/), và có thể được sử dụng kết hợp với dịch vụ phân tích của bạn.

Các hàm mới được truyền cho `useReportWebVitals` được gọi với các số liệu có sẵn cho đến thời điểm đó. Để ngăn chặn việc báo cáo dữ liệu trùng lặp, hãy đảm bảo rằng tham chiếu hàm callback không thay đổi (như được hiển thị trong các ví dụ mã bên dưới).

<PagesOnly>

```jsx filename="pages/_app.js"
import { useReportWebVitals } from 'next/web-vitals'

const logWebVitals = (metric) => {
  console.log(metric)
}

function MyApp({ Component, pageProps }) {
  useReportWebVitals(logWebVitals)

  return <Component {...pageProps} />
}
```

</PagesOnly>

<AppOnly>

```jsx filename="app/_components/web-vitals.js"
'use client'

import { useReportWebVitals } from 'next/web-vitals'

const logWebVitals = (metric) => {
  console.log(metric)
}

export function WebVitals() {
  useReportWebVitals(logWebVitals)

  return null
}
```

```jsx filename="app/layout.js"
import { WebVitals } from './_components/web-vitals'

export default function Layout({ children }) {
  return (
    <html>
      <body>
        <WebVitals />
        {children}
      </body>
    </html>
  )
}
```

> Vì hook `useReportWebVitals` yêu cầu chỉ thị `'use client'`, cách tiếp cận hiệu quả nhất là tạo một thành phần riêng biệt mà root layout import. Điều này giới hạn ranh giới client chỉ dành riêng cho thành phần `WebVitals`.

</AppOnly>

## useReportWebVitals

Đối tượng `metric` được truyền làm đối số của hook bao gồm một số thuộc tính:

- `id`: Định danh duy nhất cho số liệu trong ngữ cảnh tải trang hiện tại
- `name`: Tên của số liệu hiệu suất. Các giá trị có thể bao gồm tên của các số liệu [Web Vitals](#web-vitals) (TTFB, FCP, LCP, FID, CLS) cụ thể cho một ứng dụng web.
- `delta`: Sự khác biệt giữa giá trị hiện tại và giá trị trước đó của số liệu. Giá trị thường tính bằng mili giây và đại diện cho sự thay đổi giá trị của số liệu theo thời gian.
- `entries`: Một mảng các [Performance Entries](https://developer.mozilla.org/docs/Web/API/PerformanceEntry) liên quan đến số liệu. Những mục này cung cấp thông tin chi tiết về các sự kiện hiệu suất liên quan đến số liệu.
- `navigationType`: Chỉ ra [loại điều hướng](https://developer.mozilla.org/docs/Web/API/PerformanceNavigationTiming/type) đã kích hoạt việc thu thập số liệu. Các giá trị có thể bao gồm `"navigate"`, `"reload"`, `"back_forward"`, và `"prerender"`.
- `rating`: Đánh giá định tính về giá trị số liệu, cung cấp đánh giá về hiệu suất. Các giá trị có thể là `"good"`, `"needs-improvement"`, và `"poor"`. Xếp hạng thường được xác định bằng cách so sánh giá trị số liệu với các ngưỡng được xác định trước cho biết hiệu suất chấp nhận được hay dưới mức tối ưu.
- `value`: Giá trị thực tế hoặc thời lượng của mục nhập hiệu suất, thường tính bằng mili giây. Giá trị cung cấp thước đo định lượng về khía cạnh hiệu suất đang được theo dõi bởi số liệu. Nguồn của giá trị phụ thuộc vào số liệu cụ thể đang được đo và có thể đến từ nhiều [Performance API](https://developer.mozilla.org/docs/Web/API/Performance_API) khác nhau.

## Web Vitals

[Web Vitals](https://web.dev/vitals/) là một tập hợp các số liệu hữu ích nhằm mục đích nắm bắt trải nghiệm người dùng của một trang web. Các web vitals sau đây đều được bao gồm:

- [Time to First Byte](https://developer.mozilla.org/docs/Glossary/Time_to_first_byte) (TTFB)
- [First Contentful Paint](https://developer.mozilla.org/docs/Glossary/First_contentful_paint) (FCP)
- [Largest Contentful Paint](https://web.dev/lcp/) (LCP)
- [First Input Delay](https://web.dev/fid/) (FID)
- [Cumulative Layout Shift](https://web.dev/cls/) (CLS)
- [Interaction to Next Paint](https://web.dev/inp/) (INP)

Bạn có thể xử lý tất cả kết quả của các số liệu này bằng cách sử dụng thuộc tính `name`.

<PagesOnly>

```jsx filename="pages/_app.js"
import { useReportWebVitals } from 'next/web-vitals'

const handleWebVitals = (metric) => {
  switch (metric.name) {
    case 'FCP': {
      // xử lý kết quả FCP
    }
    case 'LCP': {
      // xử lý kết quả LCP
    }
    // ...
  }
}

function MyApp({ Component, pageProps }) {
  useReportWebVitals(handleWebVitals)

  return <Component {...pageProps} />
}
```

</PagesOnly>

## Số liệu tùy chỉnh (Custom Metrics)

Ngoài các số liệu cốt lõi được liệt kê ở trên, còn có một số số liệu tùy chỉnh bổ sung đo lường thời gian cần thiết để trang hydrate và render:

- `Next.js-hydration`: Thời gian cần thiết để trang bắt đầu và kết thúc quá trình hydrate (tính bằng ms)
- `Next.js-route-change-to-render`: Thời gian cần thiết để trang bắt đầu render sau khi thay đổi route (tính bằng ms)
- `Next.js-render`: Thời gian cần thiết để trang kết thúc render sau khi thay đổi route (tính bằng ms)

Bạn có thể xử lý tất cả kết quả của các số liệu này một cách riêng biệt:

```jsx filename="pages/_app.js"
import { useReportWebVitals } from 'next/web-vitals'

function handleCustomMetrics(metrics) {
  switch (metric.name) {
    case 'Next.js-hydration':
      // xử lý kết quả hydration
      break
    case 'Next.js-route-change-to-render':
      // xử lý kết quả route-change to render
      break
    case 'Next.js-render':
      // xử lý kết quả render
      break
    default:
      break
  }
}

function MyApp({ Component, pageProps }) {
  useReportWebVitals(handleCustomMetrics)

  return <Component {...pageProps} />
}
```

Các số liệu này hoạt động trong tất cả các trình duyệt hỗ trợ [User Timing API](https://caniuse.com/#feat=user-timing).

</PagesOnly>

## Gửi kết quả đến hệ thống bên ngoài

Bạn có thể gửi kết quả đến bất kỳ endpoint nào để đo lường và theo dõi hiệu suất người dùng thực trên trang web của mình. Ví dụ:

```js
function postWebVitals(metrics) {
  const body = JSON.stringify(metric)
  const url = 'https://example.com/analytics'

  // Sử dụng `navigator.sendBeacon()` nếu có sẵn, quay lại `fetch()`.
  if (navigator.sendBeacon) {
    navigator.sendBeacon(url, body)
  } else {
    fetch(url, { body, method: 'POST', keepalive: true })
  }
}

useReportWebVitals(postWebVitals)
```

> **Cần biết**: Nếu bạn sử dụng [Google Analytics](https://analytics.google.com/analytics/web/), việc sử dụng giá trị `id` có thể cho phép bạn xây dựng phân phối số liệu thủ công (để tính toán phần trăm, v.v.)

> ```js
> useReportWebVitals(metric => {
>   // Sử dụng `window.gtag` nếu bạn đã khởi tạo Google Analytics như ví dụ này:
>   // https://github.com/vercel/next.js/blob/canary/examples/with-google-analytics
>   window.gtag('event', metric.name, {
>     value: Math.round(metric.name === 'CLS' ? metric.value * 1000 : metric.value), // giá trị phải là số nguyên
>     event_label: metric.id, // id duy nhất cho lần tải trang hiện tại
>     non_interaction: true, // tránh ảnh hưởng đến tỷ lệ thoát.
>   });
> }
> ```
>
> Đọc thêm về [gửi kết quả đến Google Analytics](https://github.com/GoogleChrome/web-vitals#send-the-results-to-google-analytics).
