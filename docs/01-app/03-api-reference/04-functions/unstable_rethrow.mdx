---
title: unstable_rethrow
description: Tài liệu tham khảo API cho hàm unstable_rethrow.
version: unstable
---

`unstable_rethrow` có thể được sử dụng để tránh bắt các lỗi nội bộ được ném bởi Next.js khi cố gắng xử lý các lỗi được ném trong code ứng dụng của bạn.

Ví dụ, gọi hàm `notFound` sẽ ném một lỗi nội bộ Next.js và render component [`not-found.js`](/docs/app/api-reference/file-conventions/not-found). Tuy nhiên, nếu được sử dụng bên trong khối `try` của câu lệnh `try/catch`, lỗi sẽ bị bắt, ngăn `not-found.js` render:

```tsx filename="@/app/ui/component.tsx"
import { notFound } from 'next/navigation'

export default async function Page() {
  try {
    const post = await fetch('https://.../posts/1').then((res) => {
      if (res.status === 404) notFound()
      if (!res.ok) throw new Error(res.statusText)
      return res.json()
    })
  } catch (err) {
    console.error(err)
  }
}
```

Bạn có thể sử dụng API `unstable_rethrow` để ném lại lỗi nội bộ và tiếp tục với hành vi mong đợi:

```tsx filename="@/app/ui/component.tsx"
import { notFound, unstable_rethrow } from 'next/navigation'

export default async function Page() {
  try {
    const post = await fetch('https://.../posts/1').then((res) => {
      if (res.status === 404) notFound()
      if (!res.ok) throw new Error(res.statusText)
      return res.json()
    })
  } catch (err) {
    unstable_rethrow(err)
    console.error(err)
  }
}
```

Các API Next.js sau dựa vào việc ném một lỗi mà nên được ném lại và được xử lý bởi chính Next.js:

- [`notFound()`](/docs/app/api-reference/functions/not-found)
- [`redirect()`](/docs/app/guides/redirecting#redirect-function)
- [`permanentRedirect()`](/docs/app/guides/redirecting#permanentredirect-function)

Nếu một route segment được đánh dấu để ném một lỗi trừ khi nó là static, một lời gọi Dynamic API cũng sẽ ném một lỗi mà tương tự không nên được bắt bởi nhà phát triển. Lưu ý rằng Partial Prerendering (PPR) ảnh hưởng đến hành vi này. Các API này là:

- [`cookies`](/docs/app/api-reference/functions/cookies)
- [`headers`](/docs/app/api-reference/functions/headers)
- [`searchParams`](/docs/app/api-reference/file-conventions/page#searchparams-optional)
- `fetch(..., { cache: 'no-store' })`
- `fetch(..., { next: { revalidate: 0 } })`

> **Nên biết**:
>
> - Phương thức này nên được gọi ở đầu khối catch, truyền đối tượng lỗi làm đối số duy nhất của nó. Nó cũng có thể được sử dụng trong một handler `.catch` của một promise.
> - Bạn có thể tránh sử dụng `unstable_rethrow` nếu bạn đóng gói các lời gọi API của bạn mà ném và để **caller** xử lý ngoại lệ.
> - Chỉ sử dụng `unstable_rethrow` nếu các ngoại lệ bị bắt của bạn có thể bao gồm cả lỗi ứng dụng và ngoại lệ được kiểm soát bởi framework (như `redirect()` hoặc `notFound()`).
> - Bất kỳ việc dọn dẹp tài nguyên nào (như xóa intervals, timers, v.v.) sẽ phải xảy ra trước lời gọi đến `unstable_rethrow` hoặc trong một khối `finally`.
