`revalidateTag` cho phép bạn invalidate [cached data](/docs/app/guides/caching) on-demand cho một cache tag cụ thể.

Hàm này lý tưởng cho nội dung mà một chút delay trong cập nhật là chấp nhận được, chẳng hạn như blog posts, product catalogs, hoặc documentation. Người dùng nhận được stale content trong khi fresh data tải ở background.

## Cách sử dụng

`revalidateTag` có thể được gọi trong Server Functions và Route Handlers.

`revalidateTag` không thể được gọi trong Client Components hoặc Proxy, vì nó chỉ hoạt động trong server environments.

### Hành vi Revalidation

Hành vi revalidation phụ thuộc vào việc bạn có cung cấp tham số thứ hai hay không:

- **Với `profile="max"` (khuyến nghị)**: Tag entry được đánh dấu là stale, và lần tiếp theo một resource với tag đó được truy cập, nó sẽ sử dụng stale-while-revalidate semantics. Điều này có nghĩa là stale content được phục vụ trong khi fresh content được fetch ở background.
- **Với custom cache life profile**: Để sử dụng nâng cao, bạn có thể chỉ định bất kỳ cache life profile nào mà ứng dụng của bạn đã định nghĩa, cho phép các hành vi revalidation tùy chỉnh phù hợp với yêu cầu caching cụ thể của bạn.
- **Không có tham số thứ hai (deprecated)**: Tag entry hết hạn ngay lập tức, và request tiếp theo đến resource đó sẽ là một blocking revalidate/cache miss. Hành vi này hiện đã deprecated, và bạn nên sử dụng `profile="max"` hoặc migrate sang [`updateTag`](/docs/app/api-reference/functions/updateTag).

> **Nên biết**: Khi sử dụng `profile="max"`, `revalidateTag` đánh dấu tagged data là stale, nhưng fresh data chỉ được fetch khi các trang sử dụng tag đó được truy cập tiếp theo. Điều này có nghĩa là gọi `revalidateTag` sẽ không ngay lập tức kích hoạt nhiều revalidations cùng lúc. Invalidation chỉ xảy ra khi bất kỳ trang nào sử dụng tag đó được truy cập tiếp theo.

## Parameters

```ts
revalidateTag(tag: string, profile?: string | { expire?: number }): void;
```

- `tag`: Một string đại diện cho cache tag liên kết với dữ liệu bạn muốn revalidate. Không được vượt quá 256 ký tự. Giá trị này phân biệt chữ hoa chữ thường.
- `profile`: Một string chỉ định hành vi revalidation. Giá trị khuyến nghị là `"max"` cung cấp stale-while-revalidate semantics, hoặc bất kỳ default hoặc custom profiles nào được định nghĩa trong [`cacheLife`](/docs/app/api-reference/config/next-config-js/cacheLife). Ngoài ra, bạn có thể truyền một object với thuộc tính `expire` cho hành vi expiration tùy chỉnh.

Tags phải được gán cho cached data trước. Bạn có thể làm điều này theo hai cách:

- Sử dụng tùy chọn [`next.tags`](/docs/app/guides/caching#fetch-optionsnexttags-and-revalidatetag) với `fetch` để caching external API requests:

```tsx
fetch(url, { next: { tags: ['posts'] } })
```

- Sử dụng [`cacheTag`](/docs/app/api-reference/functions/cacheTag) bên trong cached functions hoặc components với directive `'use cache'`:

```tsx
import { cacheTag } from 'next/cache'

async function getData() {
  'use cache'
  cacheTag('posts')
  // ...
}
```

## Returns

`revalidateTag` không trả về giá trị.

## Mối quan hệ với `revalidatePath`

`revalidateTag` invalidates dữ liệu với các tags cụ thể trên tất cả các trang sử dụng các tags đó, trong khi [`revalidatePath`](/docs/app/api-reference/functions/revalidatePath) invalidates các page hoặc layout paths cụ thể.

> **Nên biết**: Các hàm này phục vụ các mục đích khác nhau và có thể cần được sử dụng cùng nhau để có tính nhất quán dữ liệu toàn diện. Để biết các ví dụ chi tiết và cân nhắc, hãy xem [relationship with revalidateTag and updateTag](/docs/app/api-reference/functions/revalidatePath#relationship-with-revalidatetag-and-updatetag) để biết thêm thông tin.

## Ví dụ

Các ví dụ sau đây minh họa cách sử dụng `revalidateTag` trong các ngữ cảnh khác nhau. Trong cả hai trường hợp, chúng ta đang sử dụng `profile="max"` để đánh dấu dữ liệu là stale và sử dụng stale-while-revalidate semantics, đây là cách tiếp cận được khuyến nghị cho hầu hết các trường hợp sử dụng.

### Server Action

```ts filename="app/actions.ts" switcher
'use server'

import { revalidateTag } from 'next/cache'

export default async function submit() {
  await addPost()
  revalidateTag('posts', 'max')
}
```

```js filename="app/actions.js" switcher
'use server'

import { revalidateTag } from 'next/cache'

export default async function submit() {
  await addPost()
  revalidateTag('posts', 'max')
}
```

### Route Handler

```ts filename="app/api/revalidate/route.ts" switcher
import type { NextRequest } from 'next/server'
import { revalidateTag } from 'next/cache'

export async function GET(request: NextRequest) {
  const tag = request.nextUrl.searchParams.get('tag')

  if (tag) {
    revalidateTag(tag, 'max')
    return Response.json({ revalidated: true, now: Date.now() })
  }

  return Response.json({
    revalidated: false,
    now: Date.now(),
    message: 'Missing tag to revalidate',
  })
}
```

```js filename="app/api/revalidate/route.js" switcher
import { revalidateTag } from 'next/cache'

export async function GET(request) {
  const tag = request.nextUrl.searchParams.get('tag')

  if (tag) {
    revalidateTag(tag, 'max')
    return Response.json({ revalidated: true, now: Date.now() })
  }

  return Response.json({
    revalidated: false,
    now: Date.now(),
    message: 'Missing tag to revalidate',
  })

```

> **Nên biết**: Đối với webhooks hoặc third-party services cần immediate expiration, bạn có thể truyền `{ expire: 0 }` làm tham số thứ hai: `revalidateTag(tag, { expire: 0 })`. Pattern này cần thiết khi các hệ thống bên ngoài gọi Route Handlers của bạn và yêu cầu dữ liệu hết hạn ngay lập tức. Đối với tất cả các trường hợp khác, khuyến nghị sử dụng [`updateTag`](/docs/app/api-reference/functions/updateTag) trong Server Actions để cập nhật ngay lập tức thay thế.
