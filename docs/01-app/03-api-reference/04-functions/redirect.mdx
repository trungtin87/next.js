Hàm `redirect` cho phép bạn chuyển hướng người dùng đến một URL khác. `redirect` có thể được sử dụng trong khi render trong [Server và Client Components](/docs/app/getting-started/server-and-client-components), [Route Handlers](/docs/app/api-reference/file-conventions/route), và [Server Actions](/docs/app/getting-started/updating-data).

Khi được sử dụng trong [ngữ cảnh streaming](/docs/app/getting-started/linking-and-navigating#streaming), điều này sẽ chèn một thẻ meta để phát ra chuyển hướng ở phía máy khách. Khi được sử dụng trong một server action, nó sẽ phục vụ phản hồi chuyển hướng HTTP 303 cho người gọi. Nếu không, nó sẽ phục vụ phản hồi chuyển hướng HTTP 307 cho người gọi.

Nếu một tài nguyên không tồn tại, bạn có thể sử dụng hàm [`notFound`](/docs/app/api-reference/functions/not-found) thay thế.

## Tham khảo

### Parameters (Tham số)

Hàm `redirect` chấp nhận hai đối số:

```js
redirect(path, type)
```

| Tham số | Kiểu                                                                 | Mô tả                                                                  |
| ------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `path`  | `string`                                                             | URL để chuyển hướng đến. Có thể là đường dẫn tương đối hoặc tuyệt đối. |
| `type`  | `'replace'` (mặc định) hoặc `'push'` (mặc định trong Server Actions) | Loại chuyển hướng để thực hiện.                                        |

Theo mặc định, `redirect` sẽ sử dụng `push` (thêm một mục mới vào ngăn xếp lịch sử trình duyệt) trong [Server Actions](/docs/app/getting-started/updating-data) và `replace` (thay thế URL hiện tại trong ngăn xếp lịch sử trình duyệt) ở mọi nơi khác. Bạn có thể ghi đè hành vi này bằng cách chỉ định tham số `type`.

Đối tượng `RedirectType` chứa các tùy chọn có sẵn cho tham số `type`.

```ts
import { redirect, RedirectType } from 'next/navigation'

redirect('/redirect-to', RedirectType.replace)
// hoặc
redirect('/redirect-to', RedirectType.push)
```

Tham số `type` không có hiệu lực khi được sử dụng trong Server Components.

### Returns (Giá trị trả về)

`redirect` không trả về giá trị.

## Hành vi

- Trong Server Actions và Route Handlers, redirect nên được gọi **bên ngoài** khối `try` khi sử dụng các câu lệnh `try/catch`.
- Nếu bạn muốn trả về chuyển hướng HTTP 308 (Vĩnh viễn) thay vì 307 (Tạm thời), bạn có thể sử dụng hàm [`permanentRedirect`](/docs/app/api-reference/functions/permanentRedirect) thay thế.
- `redirect` ném ra một lỗi vì vậy nó nên được gọi **bên ngoài** khối `try` khi sử dụng các câu lệnh `try/catch`.
- `redirect` có thể được gọi trong Client Components trong quá trình render nhưng không phải trong trình xử lý sự kiện. Bạn có thể sử dụng hook [`useRouter`](/docs/app/api-reference/functions/use-router) thay thế.
- `redirect` cũng chấp nhận các URL tuyệt đối và có thể được sử dụng để chuyển hướng đến các liên kết bên ngoài.
- Nếu bạn muốn chuyển hướng trước quá trình render, hãy sử dụng [`next.config.js`](/docs/app/guides/redirecting#redirects-in-nextconfigjs) hoặc [Proxy](/docs/app/guides/redirecting#nextresponseredirect-in-proxy).

## Ví dụ

### Server Component

Việc gọi hàm `redirect()` ném ra lỗi `NEXT_REDIRECT` và chấm dứt việc render phân đoạn route mà nó được ném ra.

```tsx filename="app/team/[id]/page.tsx" switcher
import { redirect } from 'next/navigation'

async function fetchTeam(id: string) {
  const res = await fetch('https://...')
  if (!res.ok) return undefined
  return res.json()
}

export default async function Profile({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const team = await fetchTeam(id)

  if (!team) {
    redirect('/login')
  }

  // ...
}
```

```jsx filename="app/team/[id]/page.js" switcher
import { redirect } from 'next/navigation'

async function fetchTeam(id) {
  const res = await fetch('https://...')
  if (!res.ok) return undefined
  return res.json()
}

export default async function Profile({ params }) {
  const { id } = await params
  const team = await fetchTeam(id)

  if (!team) {
    redirect('/login')
  }

  // ...
}
```

> **Cần biết**: `redirect` không yêu cầu bạn sử dụng `return redirect()` vì nó sử dụng kiểu [`never`](https://www.typescriptlang.org/docs/handbook/2/functions.html#never) của TypeScript.

### Client Component

`redirect` có thể được sử dụng trực tiếp trong một Client Component.

```tsx filename="components/client-redirect.tsx" switcher
'use client'

import { redirect, usePathname } from 'next/navigation'

export function ClientRedirect() {
  const pathname = usePathname()

  if (pathname.startsWith('/admin') && !pathname.includes('/login')) {
    redirect('/admin/login')
  }

  return <div>Login Page</div>
}
```

```jsx filename="components/client-redirect.jsx" switcher
'use client'

import { redirect, usePathname } from 'next/navigation'

export function ClientRedirect() {
  const pathname = usePathname()

  if (pathname.startsWith('/admin') && !pathname.includes('/login')) {
    redirect('/admin/login')
  }

  return <div>Login Page</div>
}
```

> **Cần biết**: Khi sử dụng `redirect` trong một Client Component khi tải trang ban đầu trong quá trình Server-Side Rendering (SSR), nó sẽ thực hiện chuyển hướng phía máy chủ.

`redirect` có thể được sử dụng trong một Client Component thông qua một Server Action. Nếu bạn cần sử dụng trình xử lý sự kiện để chuyển hướng người dùng, bạn có thể sử dụng hook [`useRouter`](/docs/app/api-reference/functions/use-router).

```tsx filename="app/client-redirect.tsx" switcher
'use client'

import { navigate } from './actions'

export function ClientRedirect() {
  return (
    <form action={navigate}>
      <input type="text" name="id" />
      <button>Submit</button>
    </form>
  )
}
```

```jsx filename="app/client-redirect.jsx" switcher
'use client'

import { navigate } from './actions'

export function ClientRedirect() {
  return (
    <form action={navigate}>
      <input type="text" name="id" />
      <button>Submit</button>
    </form>
  )
}
```

```ts filename="app/actions.ts" switcher
'use server'

import { redirect } from 'next/navigation'

export async function navigate(data: FormData) {
  redirect(`/posts/${data.get('id')}`)
}
```

```js filename="app/actions.js" switcher
'use server'

import { redirect } from 'next/navigation'

export async function navigate(data) {
  redirect(`/posts/${data.get('id')}`)
}
```

## FAQ

### Tại sao `redirect` sử dụng 307 và 308?

Khi sử dụng `redirect()`, bạn có thể nhận thấy rằng các mã trạng thái được sử dụng là `307` cho chuyển hướng tạm thời, và `308` cho chuyển hướng vĩnh viễn. Trong khi theo truyền thống, `302` được sử dụng cho chuyển hướng tạm thời, và `301` cho chuyển hướng vĩnh viễn, nhiều trình duyệt đã thay đổi phương thức yêu cầu của chuyển hướng, từ yêu cầu `POST` sang `GET` khi sử dụng `302`, bất kể phương thức yêu cầu gốc là gì.

Lấy ví dụ sau về chuyển hướng từ `/users` sang `/people`, nếu bạn thực hiện yêu cầu `POST` đến `/users` để tạo người dùng mới, và tuân theo chuyển hướng tạm thời `302`, phương thức yêu cầu sẽ được thay đổi từ `POST` sang `GET`. Điều này không hợp lý, vì để tạo người dùng mới, bạn nên thực hiện yêu cầu `POST` đến `/people`, chứ không phải yêu cầu `GET`.

Việc giới thiệu mã trạng thái `307` có nghĩa là phương thức yêu cầu được bảo tồn là `POST`.

- `302` - Chuyển hướng tạm thời, sẽ thay đổi phương thức yêu cầu từ `POST` sang `GET`
- `307` - Chuyển hướng tạm thời, sẽ bảo tồn phương thức yêu cầu là `POST`

Phương thức `redirect()` sử dụng `307` theo mặc định, thay vì chuyển hướng tạm thời `302`, có nghĩa là các yêu cầu của bạn sẽ _luôn_ được bảo tồn là yêu cầu `POST`.

[Tìm hiểu thêm](https://developer.mozilla.org/docs/Web/HTTP/Redirections) về Chuyển hướng HTTP.
