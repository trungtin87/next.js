> **Cảnh báo:** API này sẽ được thay thế bởi [`use cache`](/docs/app/api-reference/directives/use-cache) khi nó đạt đến độ ổn định.

`unstable_cache` cho phép bạn cache kết quả của các hoạt động tốn kém, như truy vấn cơ sở dữ liệu, và tái sử dụng chúng qua nhiều requests.

```jsx
import { getUser } from './data';
import { unstable_cache } from 'next/cache';

const getCachedUser = unstable_cache(
  async (id) => getUser(id),
  ['my-app-user']
);

export default async function Component({ userID }) {
  const user = await getCachedUser(userID);
  ...
}
```

> **Lưu ý**:
>
> - Truy cập các nguồn dữ liệu dynamic như `headers` hoặc `cookies` bên trong một phạm vi cache không được hỗ trợ. Nếu bạn cần dữ liệu này bên trong một hàm được cache, hãy sử dụng `headers` bên ngoài hàm được cache và truyền dữ liệu dynamic cần thiết vào như một đối số.
> - API này sử dụng [Data Cache](/docs/app/guides/caching#data-cache) tích hợp sẵn của Next.js để duy trì kết quả qua các requests và deployments.

## Tham số

```jsx
const data = unstable_cache(fetchData, keyParts, options)()
```

- `fetchData`: Đây là một hàm bất đồng bộ fetch dữ liệu bạn muốn cache. Nó phải là một hàm trả về một `Promise`.
- `keyParts`: Đây là một mảng bổ sung các keys để thêm nhận dạng cho cache. Theo mặc định, `unstable_cache` đã sử dụng các đối số và phiên bản stringified của hàm của bạn làm cache key. Nó là tùy chọn trong hầu hết các trường hợp; lần duy nhất bạn cần sử dụng nó là khi bạn sử dụng các biến bên ngoài mà không truyền chúng dưới dạng tham số. Tuy nhiên, điều quan trọng là thêm các closures được sử dụng trong hàm nếu bạn không truyền chúng dưới dạng tham số.
- `options`: Đây là một object kiểm soát cách cache hoạt động. Nó có thể chứa các thuộc tính sau:
  - `tags`: Một mảng các tags có thể được sử dụng để kiểm soát việc invalidate cache. Next.js sẽ không sử dụng cái này để xác định duy nhất hàm.
  - `revalidate`: Số giây sau đó cache nên được revalidate. Bỏ qua hoặc truyền `false` để cache vô thời hạn hoặc cho đến khi các phương thức `revalidateTag()` hoặc `revalidatePath()` khớp được gọi.

## Giá trị trả về

`unstable_cache` trả về một hàm mà khi được gọi, trả về một Promise giải quyết thành dữ liệu đã cache. Nếu dữ liệu không có trong cache, hàm được cung cấp sẽ được gọi, và kết quả của nó sẽ được cache và trả về.

## Ví dụ

```tsx filename="app/page.tsx" switcher
import { unstable_cache } from 'next/cache'

export default async function Page({
  params,
}: {
  params: Promise<{ userId: string }>
}) {
  const { userId } = await params
  const getCachedUser = unstable_cache(
    async () => {
      return { id: userId }
    },
    [userId], // thêm user ID vào cache key
    {
      tags: ['users'],
      revalidate: 60,
    }
  )

  //...
}
```
