`usePathname` là một **Client Component** hook cho phép bạn đọc **pathname** của URL hiện tại.

> **Nên biết**: Khi [`cacheComponents`](/docs/app/api-reference/config/next-config-js/cacheComponents) được enable, `usePathname` có thể yêu cầu một `Suspense` boundary xung quanh nó nếu route của bạn có dynamic param. Nếu bạn sử dụng `generateStaticParams` thì `Suspense` boundary là tùy chọn

```tsx filename="app/example-client-component.tsx" switcher
'use client'

import { usePathname } from 'next/navigation'

export default function ExampleClientComponent() {
  const pathname = usePathname()
  return <p>Current pathname: {pathname}</p>
}
```

```jsx filename="app/example-client-component.js" switcher
'use client'

import { usePathname } from 'next/navigation'

export default function ExampleClientComponent() {
  const pathname = usePathname()
  return <p>Current pathname: {pathname}</p>
}
```

`usePathname` có chủ ý yêu cầu sử dụng [Client Component](/docs/app/getting-started/server-and-client-components). Điều quan trọng cần lưu ý là Client Components không phải là de-optimization. Chúng là một phần không thể thiếu của kiến trúc [Server Components](/docs/app/getting-started/server-and-client-components).

Ví dụ, một Client Component với `usePathname` sẽ được render thành HTML trên initial page load. Khi điều hướng đến một route mới, component này không cần được re-fetched. Thay vào đó, component được tải xuống một lần (trong client JavaScript bundle), và re-renders dựa trên current state.

> **Nên biết**:
>
> - Đọc URL hiện tại từ [Server Component](/docs/app/getting-started/server-and-client-components) không được hỗ trợ. Thiết kế này là có chủ ý để hỗ trợ layout state được preserve qua các page navigations.
> - Nếu trang của bạn đang được statically pre-rendered và app của bạn có [rewrites](/docs/app/api-reference/config/next-config-js/rewrites) trong `next.config` hoặc tệp [Proxy](/docs/app/api-reference/file-conventions/proxy), việc đọc pathname với `usePathname()` có thể dẫn đến hydration mismatch errors—vì giá trị ban đầu đến từ server và có thể không khớp với browser pathname thực tế sau khi routing. Xem [ví dụ](#avoid-hydration-mismatch-with-rewrites) của chúng tôi để biết cách giảm thiểu vấn đề này.

<details>

<summary>Tương thích với Pages Router</summary>

Nếu bạn có các components sử dụng `usePathname` và chúng được import vào routes trong Pages Router, hãy lưu ý rằng `usePathname` có thể trả về `null` nếu router chưa được khởi tạo. Điều này có thể xảy ra trong các trường hợp như [fallback routes](/docs/pages/api-reference/functions/get-static-paths#fallback-true) hoặc trong quá trình [Automatic Static Optimization](https://nextjs.org/docs/pages/building-your-application/rendering/static#automatic-static-optimization) trong Pages Router.

Để tăng cường tương thích giữa các routing systems, nếu dự án của bạn chứa cả thư mục `app` và `pages`, Next.js sẽ tự động điều chỉnh return type của `usePathname`.

</details>

## Parameters

```tsx
const pathname = usePathname()
```

`usePathname` không nhận bất kỳ parameters nào.

## Returns

`usePathname` trả về một string của pathname của URL hiện tại. Ví dụ:

| URL                 | Giá trị trả về        |
| ------------------- | --------------------- |
| `/`                 | `'/'`                 |
| `/dashboard`        | `'/dashboard'`        |
| `/dashboard?v=2`    | `'/dashboard'`        |
| `/blog/hello-world` | `'/blog/hello-world'` |

## Ví dụ

### Làm điều gì đó để phản hồi route change

```tsx filename="app/example-client-component.tsx" switcher
'use client'

import { useEffect } from 'react'
import { usePathname, useSearchParams } from 'next/navigation'

function ExampleClientComponent() {
  const pathname = usePathname()
  const searchParams = useSearchParams()
  useEffect(() => {
    // Do something here...
  }, [pathname, searchParams])
}
```

### Tránh hydration mismatch với rewrites

Khi một trang được pre-rendered, HTML được tạo cho source pathname. Nếu trang sau đó được truy cập thông qua một rewrite bằng cách sử dụng `next.config` hoặc `Proxy`, browser URL có thể khác, và `usePathname()` sẽ đọc rewritten pathname trên client.

Để tránh hydration mismatches, hãy thiết kế UI sao cho chỉ một phần nhỏ, isolated phụ thuộc vào client pathname. Render một stable fallback trên server và cập nhật phần đó sau khi mount.

```tsx filename="app/example-client-component.tsx" switcher
'use client'

import { useEffect, useState } from 'react'
import { usePathname } from 'next/navigation'

export default function PathnameBadge() {
  const pathname = usePathname()
  const [clientPathname, setClientPathname] = useState('')

  useEffect(() => {
    setClientPathname(pathname)
  }, [pathname])

  return (
    <p>
      Current pathname: <span>{clientPathname}</span>
    </p>
  )
}
```

```jsx filename="app/example-client-component.js" switcher
'use client'

import { useEffect, useState } from 'react'
import { usePathname } from 'next/navigation'

export default function PathnameBadge() {
  const pathname = usePathname()
  const [clientPathname, setClientPathname] = useState('')

  useEffect(() => {
    setClientPathname(pathname)
  }, [pathname])

  return (
    <p>
      Current pathname: <span>{clientPathname}</span>
    </p>
  )
}
```
