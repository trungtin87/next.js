`after` cho phép bạn lên lịch công việc sẽ được thực thi sau khi một response (hoặc prerender) hoàn tất. Điều này hữu ích cho các tác vụ và side effects khác không nên chặn response, chẳng hạn như logging và analytics.

Nó có thể được sử dụng trong [Server Components](/docs/app/getting-started/server-and-client-components) (bao gồm [`generateMetadata`](/docs/app/api-reference/functions/generate-metadata)), [Server Actions](/docs/app/getting-started/updating-data), [Route Handlers](/docs/app/api-reference/file-conventions/route), và [Proxy](/docs/app/api-reference/file-conventions/proxy).

Hàm chấp nhận một callback sẽ được thực thi sau khi response (hoặc prerender) hoàn tất:

```tsx filename="app/layout.tsx" switcher
import { after } from 'next/server'
// Custom logging function
import { log } from '@/app/utils'

export default function Layout({ children }: { children: React.ReactNode }) {
  after(() => {
    // Thực thi sau khi layout được render và gửi đến người dùng
    log()
  })
  return <>{children}</>
}
```

```jsx filename="app/layout.jsx" switcher
import { after } from 'next/server'
// Custom logging function
import { log } from '@/app/utils'

export default function Layout({ children }) {
  after(() => {
    // Thực thi sau khi layout được render và gửi đến người dùng
    log()
  })
  return <>{children}</>
}
```

> **Lưu ý:** `after` không phải là một [Dynamic API](/docs/app/guides/caching#dynamic-rendering) và việc gọi nó không làm cho một route trở nên dynamic. Nếu nó được sử dụng bên trong một static page, callback sẽ thực thi tại build time, hoặc bất cứ khi nào một page được revalidate.

## Tham khảo

### Tham số

- Một hàm callback sẽ được thực thi sau khi response (hoặc prerender) hoàn tất.

### Thời lượng

`after` sẽ chạy trong thời gian mặc định của nền tảng hoặc max duration đã cấu hình của route của bạn. Nếu nền tảng của bạn hỗ trợ, bạn có thể cấu hình giới hạn timeout bằng cách sử dụng route segment config [`maxDuration`](/docs/app/api-reference/file-conventions/route-segment-config#maxduration).

## Lưu ý

- `after` sẽ được thực thi ngay cả khi response không hoàn thành thành công. Bao gồm khi một lỗi được ném ra hoặc khi `notFound` hoặc `redirect` được gọi.
- Bạn có thể sử dụng React `cache` để deduplicate các hàm được gọi bên trong `after`.
- `after` có thể được lồng bên trong các lệnh gọi `after` khác, ví dụ, bạn có thể tạo các hàm tiện ích bao bọc các lệnh gọi `after` để thêm chức năng bổ sung.

## Ví dụ

### Với request APIs

Bạn có thể sử dụng request APIs như [`cookies`](/docs/app/api-reference/functions/cookies) và [`headers`](/docs/app/api-reference/functions/headers) bên trong `after` trong [Server Actions](/docs/app/getting-started/updating-data) và [Route Handlers](/docs/app/api-reference/file-conventions/route). Điều này hữu ích cho việc logging hoạt động sau một mutation. Ví dụ:

```ts filename="app/api/route.ts" highlight={2,7-9} switcher
import { after } from 'next/server'
import { cookies, headers } from 'next/headers'
import { logUserAction } from '@/app/utils'

export async function POST(request: Request) {
  // Thực hiện mutation
  // ...

  // Log hoạt động người dùng cho analytics
  after(async () => {
    const userAgent = (await headers().get('user-agent')) || 'unknown'
    const sessionCookie =
      (await cookies().get('session-id'))?.value || 'anonymous'

    logUserAction({ sessionCookie, userAgent })
  })

  return new Response(JSON.stringify({ status: 'success' }), {
    status: 200,
    headers: { 'Content-Type': 'application/json' },
  })
}
```

```js filename="app/api/route.js" highlight={2,7-9} switcher
import { after } from 'next/server'
import { cookies, headers } from 'next/headers'
import { logUserAction } from '@/app/utils'

  // ...

  // Log hoạt động người dùng cho analytics

```

Tuy nhiên, bạn không thể sử dụng các request APIs này bên trong `after` trong [Server Components](/docs/app/getting-started/server-and-client-components). Điều này là do Next.js cần biết phần nào của cây truy cập request APIs để hỗ trợ [Cache Components](/docs/app/getting-started/cache-components), nhưng `after` chạy sau vòng đời rendering của React.

<details id="after-serverless">
  <summary>Tham khảo: hỗ trợ `after` cho các nền tảng serverless</summary>

Sử dụng `after` trong ngữ cảnh serverless yêu cầu đợi các tác vụ bất đồng bộ hoàn tất sau khi phản hồi đã được gửi. Trong Next.js và Vercel, điều này đạt được bằng cách sử dụng một primitive gọi là `waitUntil(promise)`, kéo dài thời gian tồn tại của lệnh gọi serverless cho đến khi tất cả các promises được truyền cho [`waitUntil`](https://vercel.com/docs/functions/functions-api-reference#waituntil) đã giải quyết (settled).

Nếu bạn muốn người dùng của mình có thể chạy `after`, bạn sẽ phải cung cấp triển khai `waitUntil` của mình hoạt động theo cách tương tự.

Khi `after` được gọi, Next.js sẽ truy cập `waitUntil` như thế này:

```jsx
const RequestContext = globalThis[Symbol.for('@next/request-context')]
const contextValue = RequestContext?.get()
const waitUntil = contextValue?.waitUntil
```

Điều này có nghĩa là `globalThis[Symbol.for('@next/request-context')]` được mong đợi chứa một object như thế này:

```tsx
type NextRequestContext = {
  get(): NextRequestContextValue | undefined
}

type NextRequestContextValue = {
  waitUntil?: (promise: Promise<any>) => void
}
```

Đây là một ví dụ về triển khai.

```tsx
import { AsyncLocalStorage } from 'node:async_hooks'

const RequestContextStorage = new AsyncLocalStorage<NextRequestContextValue>()

// Định nghĩa và inject accessor mà next.js sẽ sử dụng
const RequestContext: NextRequestContext = {
  get() {
    return RequestContextStorage.getStore()
  },
}
globalThis[Symbol.for('@next/request-context')] = RequestContext

const handler = (req, res) => {
  const contextValue = { waitUntil: YOUR_WAITUNTIL }
  // Cung cấp giá trị
  return RequestContextStorage.run(contextValue, () => nextJsHandler(req, res))
}
```
