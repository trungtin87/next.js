NextResponse mở rộng [Web Response API](https://developer.mozilla.org/docs/Web/API/Response) với các convenience methods bổ sung.

## `cookies`

Đọc hoặc mutate header [`Set-Cookie`](https://developer.mozilla.org/docs/Web/HTTP/Headers/Set-Cookie) của response.

### `set(name, value)`

Với một name, set một cookie với giá trị đã cho trên response.

```ts
// Given incoming request /home
let response = NextResponse.next()
// Set a cookie to hide the banner
response.cookies.set('show-banner', 'false')
// Response will have a `Set-Cookie:show-banner=false;path=/home` header
return response
```

### `get(name)`

Với một cookie name, trả về giá trị của cookie. Nếu cookie không được tìm thấy, `undefined` được trả về. Nếu nhiều cookies được tìm thấy, cái đầu tiên được trả về.

```ts
// Given incoming request /home
let response = NextResponse.next()
// { name: 'show-banner', value: 'false', Path: '/home' }
response.cookies.get('show-banner')
```

### `getAll()`

Với một cookie name, trả về các giá trị của cookie. Nếu không có name nào được cung cấp, trả về tất cả cookies trên response.

```ts
// Given incoming request /home
let response = NextResponse.next()
// [
//   { name: 'experiments', value: 'new-pricing-page', Path: '/home' },
//   { name: 'experiments', value: 'winter-launch', Path: '/home' },
// ]
response.cookies.getAll('experiments')
// Alternatively, get all cookies for the response
response.cookies.getAll()
```

### `delete(name)`

Với một cookie name, xóa cookie khỏi response.

```ts
// Given incoming request /home
let response = NextResponse.next()
// Returns true for deleted, false if nothing is deleted
response.cookies.delete('experiments')
```

## `json()`

Tạo một response với JSON body đã cho.

```ts filename="app/api/route.ts" switcher
import { NextResponse } from 'next/server'

export async function GET(request: Request) {
  return NextResponse.json({ error: 'Internal Server Error' }, { status: 500 })
}
```

```js filename="app/api/route.js" switcher
import { NextResponse } from 'next/server'

export async function GET(request) {
  return NextResponse.json({ error: 'Internal Server Error' }, { status: 500 })
}
```

## `redirect()`

Tạo một response chuyển hướng đến một [URL](https://developer.mozilla.org/docs/Web/API/URL).

```ts
import { NextResponse } from 'next/server'

return NextResponse.redirect(new URL('/new', request.url))
```

[URL](https://developer.mozilla.org/docs/Web/API/URL) có thể được tạo và sửa đổi trước khi được sử dụng trong phương thức `NextResponse.redirect()`. Ví dụ, bạn có thể sử dụng thuộc tính `request.nextUrl` để lấy URL hiện tại, và sau đó sửa đổi nó để chuyển hướng đến một URL khác.

```ts
import { NextResponse } from 'next/server'

// Given an incoming request...
const loginUrl = new URL('/login', request.url)
// Add ?from=/incoming-url to the /login URL
loginUrl.searchParams.set('from', request.nextUrl.pathname)
// And redirect to the new URL
return NextResponse.redirect(loginUrl)
```

## `rewrite()`

Tạo một response viết lại (proxies) [URL](https://developer.mozilla.org/docs/Web/API/URL) đã cho trong khi vẫn giữ nguyên URL gốc.

```ts
import { NextResponse } from 'next/server'

// Incoming request: /about, browser shows /about
// Rewritten request: /proxy, browser shows /about
return NextResponse.rewrite(new URL('/proxy', request.url))
```

## `next()`

Phương thức `next()` hữu ích cho Proxy, vì nó cho phép bạn return sớm và tiếp tục routing.

```ts
import { NextResponse } from 'next/server'

return NextResponse.next()
```

Bạn cũng có thể chuyển tiếp `headers` lên upstream khi tạo response, sử dụng `NextResponse.next({ request: { headers } })`:

```ts
import { NextResponse } from 'next/server'

// Given an incoming request...
const newHeaders = new Headers(request.headers)
// Add a new header
newHeaders.set('x-version', '123')
// Forward the modified request headers upstream
return NextResponse.next({
  request: {
    // New request headers
    headers: newHeaders,
  },
})
```

Điều này chuyển tiếp `newHeaders` lên upstream đến trang đích, route, hoặc server action, và không để lộ chúng cho client. Mặc dù pattern này hữu ích để truyền dữ liệu lên upstream, nó nên được sử dụng thận trọng vì các headers chứa dữ liệu này có thể được chuyển tiếp đến các dịch vụ bên ngoài.

Ngược lại, `NextResponse.next({ headers })` là một cách viết tắt để gửi headers từ proxy đến client. Điều này **KHÔNG** phải là thực hành tốt và nên tránh. Trong số các lý do khác, vì việc đặt response headers như `Content-Type`, có thể ghi đè các kỳ vọng của framework (ví dụ, `Content-Type` được sử dụng bởi Server Actions), dẫn đến failed submissions hoặc broken streaming responses.

```ts
import { type NextRequest, NextResponse } from 'next/server'

async function proxy(request: NextRequest) {
  const headers = await injectAuth(request.headers)
  // DO NOT forward headers like this
  return NextResponse.next({ headers })
}
```

Nói chung, tránh sao chép tất cả incoming request headers vì làm như vậy có thể làm rò rỉ dữ liệu nhạy cảm cho clients hoặc upstream services.

Ưu tiên cách tiếp cận phòng thủ bằng cách tạo một tập hợp con các incoming request headers sử dụng allow-list. Ví dụ, bạn có thể loại bỏ các headers `x-*` tùy chỉnh và chỉ chuyển tiếp các headers đã biết là an toàn:

```ts
import { type NextRequest, NextResponse } from 'next/server'

function proxy(request: NextRequest) {
  const incoming = new Headers(request.headers)
  const forwarded = new Headers()

  for (const [name, value] of incoming) {
    const headerName = name.toLowerCase()
    // Keep only known-safe headers, discard custom x-* and other sensitive ones
    if (
      !headerName.startsWith('x-') &&
      headerName !== 'authorization' &&
      headerName !== 'cookie'
    ) {
      // Preserve original header name casing
      forwarded.set(name, value)
    }
  }

  return NextResponse.next({
    request: {
      headers: forwarded,
    },
  })
}
```
