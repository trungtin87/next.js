**Trong phiên bản 15, chúng tôi khuyên bạn nên sử dụng [`connection`](/docs/app/api-reference/functions/connection) thay vì `unstable_noStore`.**

`unstable_noStore` có thể được sử dụng để chọn không tham gia (opt out) static rendering một cách khai báo và chỉ ra rằng một component cụ thể không nên được cache.

```jsx
import { unstable_noStore as noStore } from 'next/cache';

export default async function ServerComponent() {
  noStore();
  const result = await db.query(...);
  ...
}
```

> **Thông tin hữu ích**:
>
> - `unstable_noStore` tương đương với `cache: 'no-store'` trên một `fetch`
> - `unstable_noStore` được ưu tiên hơn `export const dynamic = 'force-dynamic'` vì nó chi tiết hơn và có thể được sử dụng trên cơ sở từng component

- Sử dụng `unstable_noStore` bên trong [`unstable_cache`](/docs/app/api-reference/functions/unstable_cache) sẽ không chọn không tham gia static generation. Thay vào đó, nó sẽ tuân theo cấu hình cache để xác định xem có cache kết quả hay không.

## Cách sử dụng

Nếu bạn không muốn truyền các tùy chọn bổ sung cho `fetch`, như `cache: 'no-store'`, `next: { revalidate: 0 }` hoặc trong trường hợp `fetch` không khả dụng, bạn có thể sử dụng `noStore()` như một sự thay thế cho tất cả các trường hợp sử dụng này.

```jsx
import { unstable_noStore as noStore } from 'next/cache';

export default async function ServerComponent() {
  noStore();
  const result = await db.query(...);
  ...
}
```

## Lịch sử phiên bản

| Phiên bản | Thay đổi                                                     |
| --------- | ------------------------------------------------------------ |
| `v15.0.0` | `unstable_noStore` không được khuyến khích cho `connection`. |
| `v14.0.0` | `unstable_noStore` được giới thiệu.                          |
