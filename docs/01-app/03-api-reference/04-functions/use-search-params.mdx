`useSearchParams` là một **Client Component** hook cho phép bạn đọc **query string** của URL hiện tại.

`useSearchParams` trả về một phiên bản **read-only** của giao diện [`URLSearchParams`](https://developer.mozilla.org/docs/Web/API/URLSearchParams).

```tsx filename="app/dashboard/search-bar.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // URL -> `/dashboard?search=my-project`
  // `search` -> 'my-project'
  return <>Search: {search}</>
}
```

```jsx filename="app/dashboard/search-bar.js" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // URL -> `/dashboard?search=my-project`
  // `search` -> 'my-project'
  return <>Search: {search}</>
}
```

## Parameters

```tsx
const searchParams = useSearchParams()
```

`useSearchParams` không nhận bất kỳ tham số nào.

## Returns

`useSearchParams` trả về một phiên bản **read-only** của giao diện [`URLSearchParams`](https://developer.mozilla.org/docs/Web/API/URLSearchParams), bao gồm các phương thức tiện ích để đọc query string của URL:

- [`URLSearchParams.get()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/get): Trả về giá trị đầu tiên liên quan đến tham số tìm kiếm. Ví dụ:

  | URL                  | `searchParams.get("a")`                                                                                                 |
  | -------------------- | ----------------------------------------------------------------------------------------------------------------------- |
  | `/dashboard?a=1`     | `'1'`                                                                                                                   |
  | `/dashboard?a=`      | `''`                                                                                                                    |
  | `/dashboard?b=3`     | `null`                                                                                                                  |
  | `/dashboard?a=1&a=2` | `'1'` _- sử dụng [`getAll()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/getAll) để lấy tất cả giá trị_ |

- [`URLSearchParams.has()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/has): Trả về một giá trị boolean cho biết liệu tham số đã cho có tồn tại hay không. Ví dụ:

  | URL              | `searchParams.has("a")` |
  | ---------------- | ----------------------- |
  | `/dashboard?a=1` | `true`                  |
  | `/dashboard?b=3` | `false`                 |

- Tìm hiểu thêm về các phương thức **read-only** khác của [`URLSearchParams`](https://developer.mozilla.org/docs/Web/API/URLSearchParams), bao gồm [`getAll()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/getAll), [`keys()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/keys), [`values()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/values), [`entries()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/entries), [`forEach()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/forEach), và [`toString()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/toString).

> **Cần biết**:
>
> - `useSearchParams` là một hook [Client Component](/docs/app/getting-started/server-and-client-components) và **không được hỗ trợ** trong [Server Components](/docs/app/getting-started/server-and-client-components) để ngăn chặn các giá trị cũ (stale values) trong quá trình [partial rendering](/docs/app/getting-started/linking-and-navigating#client-side-transitions).
> - Nếu bạn muốn fetch dữ liệu trong một Server Component dựa trên search params, thường là một lựa chọn tốt hơn để đọc [`searchParams` prop](/docs/app/api-reference/file-conventions/page#searchparams-optional) của Page tương ứng. Sau đó bạn có thể truyền nó xuống qua props cho bất kỳ component nào (Server hoặc Client) bên trong Page đó.
> - Nếu một ứng dụng bao gồm thư mục `/pages`, `useSearchParams` sẽ trả về `ReadonlyURLSearchParams | null`. Giá trị `null` là để tương thích trong quá trình di chuyển vì search params không thể được biết trong quá trình pre-rendering của một trang không sử dụng `getServerSideProps`

## Hành vi (Behavior)

### Static Rendering

Nếu một route được [render tĩnh](/docs/app/guides/caching#static-rendering), việc gọi `useSearchParams` sẽ khiến cây Client Component lên đến [`Suspense` boundary](/docs/app/api-reference/file-conventions/loading#examples) gần nhất được render phía client (client-side rendered).

Điều này cho phép một phần của route được render tĩnh trong khi phần động sử dụng `useSearchParams` được render phía client.

Chúng tôi khuyên bạn nên bọc Client Component sử dụng `useSearchParams` trong một `<Suspense/>` boundary. Điều này sẽ cho phép bất kỳ Client Components nào ở trên nó được render tĩnh và gửi như một phần của HTML ban đầu. [Ví dụ](/docs/app/api-reference/functions/use-search-params#static-rendering).

Ví dụ:

```tsx filename="app/dashboard/search-bar.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // Điều này sẽ không được log trên server khi sử dụng static rendering
  console.log(search)

  return <>Search: {search}</>
}
```

```jsx filename="app/dashboard/search-bar.js" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // Điều này sẽ không được log trên server khi sử dụng static rendering
  console.log(search)

  return <>Search: {search}</>
}
```

```tsx filename="app/dashboard/page.tsx" switcher
import { Suspense } from 'react'
import SearchBar from './search-bar'

// Component này được truyền như một fallback cho Suspense boundary
// sẽ được render thay thế cho search bar trong HTML ban đầu.
// Khi giá trị có sẵn trong quá trình React hydration, fallback
// sẽ được thay thế bằng component `<SearchBar>`.
function SearchBarFallback() {
  return <>placeholder</>
}

export default function Page() {
  return (
    <>
      <nav>
        <Suspense fallback={<SearchBarFallback />}>
          <SearchBar />
        </Suspense>
      </nav>
      <h1>Dashboard</h1>
    </>
  )
}
```

> **Cần biết**:
>
> - Trong development, các routes được render theo yêu cầu (on-demand), vì vậy `useSearchParams` không suspend và mọi thứ có thể có vẻ hoạt động mà không cần `Suspense`.
> - Trong các bản build production, một [trang tĩnh](/docs/app/guides/caching#static-rendering) gọi `useSearchParams` từ một Client Component phải được bọc trong một `Suspense` boundary, nếu không bản build sẽ thất bại với lỗi [Missing Suspense boundary with useSearchParams](/docs/messages/missing-suspense-with-csr-bailout).
> - Nếu bạn có ý định để route được render động, hãy ưu tiên sử dụng hàm [`connection`](/docs/app/api-reference/functions/connection) trước trong một Server Component để chờ một request đến, điều này loại trừ mọi thứ bên dưới khỏi prerendering. Xem điều gì làm cho một route trở nên động trong hướng dẫn [Dynamic Rendering](/docs/app/guides/caching#dynamic-rendering).
> - Nếu bạn đã ở trong một Server Component Page, hãy xem xét sử dụng [`searchParams` prop](/docs/app/api-reference/file-conventions/page#searchparams-optional) và truyền các giá trị cho Client Components.
> - Bạn cũng có thể truyền Page [`searchParams` prop](/docs/app/api-reference/file-conventions/page#searchparams-optional) trực tiếp cho một Client Component và unwrap nó với `use()` của React. Mặc dù điều này sẽ suspend, vì vậy Client Component nên được bọc với một `Suspense` boundary.

### Dynamic Rendering

Nếu một route được [render động](/docs/app/guides/caching#dynamic-rendering), `useSearchParams` sẽ có sẵn trên server trong quá trình render server ban đầu của Client Component.

Ví dụ:

```tsx filename="app/dashboard/search-bar.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // Điều này sẽ được log trên server trong quá trình render ban đầu
  // và trên client trong các lần điều hướng tiếp theo.
  console.log(search)

  return <>Search: {search}</>
}
```

```jsx filename="app/dashboard/search-bar.js" switcher

  // và trên client trong các lần điều hướng tiếp theo.
  console.log(search)

  return <>Search: {search}</>
}
```

>
> - Trước đây, việc đặt `export const dynamic = 'force-dynamic'` trên trang được sử dụng để buộc render động. Ưu tiên sử dụng [`connection()`](/docs/app/api-reference/functions/connection) thay thế, vì nó liên kết ngữ nghĩa render động với request đến.

### Server Components

#### Pages

Để truy cập search params trong [Pages](/docs/app/api-reference/file-conventions/page) (Server Components), sử dụng [`searchParams`](/docs/app/api-reference/file-conventions/page#searchparams-optional) prop.

#### Layouts

Không giống như Pages, [Layouts](/docs/app/api-reference/file-conventions/layout) (Server Components) **không** nhận `searchParams` prop. Điều này là do một layout được chia sẻ [không được render lại trong quá trình điều hướng](/docs/app/getting-started/linking-and-navigating#client-side-transitions) điều này có thể dẫn đến `searchParams` cũ giữa các lần điều hướng. Xem [giải thích chi tiết](/docs/app/api-reference/file-conventions/layout#query-params).

Thay vào đó, sử dụng Page [`searchParams`](/docs/app/api-reference/file-conventions/page) prop hoặc [`useSearchParams`](/docs/app/api-reference/functions/use-search-params) hook trong một Client Component, cái mà được render lại trên client với `searchParams` mới nhất.

## Ví dụ

### Cập nhật `searchParams`

Bạn có thể sử dụng [`useRouter`](/docs/app/api-reference/functions/use-router) hoặc [`Link`](/docs/app/api-reference/components/link) để đặt `searchParams` mới. Sau khi một điều hướng được thực hiện, [`page.js`](/docs/app/api-reference/file-conventions/page) hiện tại sẽ nhận được một [`searchParams` prop](/docs/app/api-reference/file-conventions/page#searchparams-optional) đã được cập nhật.

```tsx filename="app/example-client-component.tsx" switcher
'use client'

export default function ExampleClientComponent() {
  const router = useRouter()
  const pathname = usePathname()
  const searchParams = useSearchParams()

  // Lấy một chuỗi searchParams mới bằng cách merge searchParams
  // hiện tại với một cặp key/value được cung cấp
  const createQueryString = useCallback(
    (name: string, value: string) => {
      const params = new URLSearchParams(searchParams.toString())
      params.set(name, value)

      return params.toString()
    },
    [searchParams]
  )

  return (
    <>
      <p>Sort By</p>

      {/* sử dụng useRouter */}
      <button
        onClick={() => {
          // <pathname>?sort=asc
          router.push(pathname + '?' + createQueryString('sort', 'asc'))
        }}
      >
        ASC
      </button>

      {/* sử dụng <Link> */}
      <Link
        href={
          // <pathname>?sort=desc
          pathname + '?' + createQueryString('sort', 'desc')
        }
      >
        DESC
      </Link>
    </>
  )
}
```
