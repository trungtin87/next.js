Next.js mở rộng [Web `fetch()` API](https://developer.mozilla.org/docs/Web/API/Fetch_API) để cho phép mỗi request trên server thiết lập ngữ nghĩa caching và revalidation liên tục của riêng nó.

Trong trình duyệt, tùy chọn `cache` chỉ ra cách một fetch request sẽ tương tác với HTTP cache của _trình duyệt_. Với phần mở rộng này, `cache` chỉ ra cách một fetch request _server-side_ sẽ tương tác với [Data Cache](/docs/app/guides/caching#data-cache) liên tục của framework.

Bạn có thể gọi `fetch` với `async` và `await` trực tiếp bên trong Server Components.

```tsx filename="app/page.tsx" switcher
export default async function Page() {
  let data = await fetch('https://api.vercel.app/blog')
  let posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

```jsx filename="app/page.js" switcher
export default async function Page() {
  let data = await fetch('https://api.vercel.app/blog')
  let posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

## `fetch(url, options)`

Vì Next.js mở rộng [Web `fetch()` API](https://developer.mozilla.org/docs/Web/API/Fetch_API), bạn có thể sử dụng bất kỳ [tùy chọn gốc nào có sẵn](https://developer.mozilla.org/docs/Web/API/fetch#parameters).

### `options.cache`

Cấu hình cách request nên tương tác với Next.js [Data Cache](/docs/app/guides/caching#data-cache).

```ts
fetch(`https://...`, { cache: 'force-cache' | 'no-store' })
```

- **`auto no cache`** (mặc định): Next.js fetch tài nguyên từ remote server trên mỗi request trong development, nhưng sẽ fetch một lần trong `next build` vì route sẽ được prerender tĩnh. Nếu [Dynamic APIs](/docs/app/guides/caching#dynamic-rendering) được phát hiện trên route, Next.js sẽ fetch tài nguyên trên mỗi request.
- **`no-store`**: Next.js fetch tài nguyên từ remote server trên mỗi request, ngay cả khi Dynamic APIs không được phát hiện trên route.
- **`force-cache`**: Next.js tìm kiếm một request khớp trong Data Cache của nó.
  - Nếu có một kết quả khớp và nó còn mới (fresh), nó sẽ được trả về từ cache.
  - Nếu không có kết quả khớp hoặc kết quả khớp đã cũ (stale), Next.js sẽ fetch tài nguyên từ remote server và cập nhật cache với tài nguyên đã tải xuống.

### `options.next.revalidate`

```ts
fetch(`https://...`, { next: { revalidate: false | 0 | number } })
```

Đặt thời gian tồn tại cache của một tài nguyên (tính bằng giây). [Data Cache](/docs/app/guides/caching#data-cache).

- **`false`** - Cache tài nguyên vô thời hạn. Về mặt ngữ nghĩa tương đương với `revalidate: Infinity`. HTTP cache có thể loại bỏ các tài nguyên cũ hơn theo thời gian.
- **`0`** - Ngăn chặn tài nguyên bị cache.
- **`number`** - (tính bằng giây) Chỉ định tài nguyên nên có thời gian tồn tại cache tối đa là `n` giây.

> **Lưu ý**:
>
> - Nếu một request `fetch()` riêng lẻ đặt một số `revalidate` thấp hơn [mặc định `revalidate`](/docs/app/api-reference/file-conventions/route-segment-config#revalidate) của một route, khoảng thời gian revalidation của toàn bộ route sẽ bị giảm.
> - Nếu hai fetch requests với cùng một URL trong cùng một route có các giá trị `revalidate` khác nhau, giá trị thấp hơn sẽ được sử dụng.
> - Các tùy chọn xung đột như `{ revalidate: 3600, cache: 'no-store' }` không được phép, cả hai sẽ bị bỏ qua, và trong chế độ development một cảnh báo sẽ được in ra terminal.

### `options.next.tags`

```ts
fetch(`https://...`, { next: { tags: ['collection'] } })
```

Đặt các cache tags của một tài nguyên. Dữ liệu sau đó có thể được revalidate theo yêu cầu bằng cách sử dụng [`revalidateTag`](/docs/app/api-reference/functions/revalidateTag). Độ dài tối đa cho một tag tùy chỉnh là 256 ký tự và số lượng tag items tối đa là 128.

## Troubleshooting

### Fetch mặc định `auto no store` và `cache: 'no-store'` không hiển thị dữ liệu mới trong development

Next.js cache các phản hồi `fetch` trong Server Components qua Hot Module Replacement (HMR) trong local development để phản hồi nhanh hơn và giảm chi phí cho các lệnh gọi API bị tính phí.

Theo mặc định, [HMR cache](/docs/app/api-reference/config/next-config-js/serverComponentsHmrCache) áp dụng cho tất cả các fetch requests, bao gồm cả những requests với tùy chọn mặc định `auto no cache` và `cache: 'no-store'`. Điều này có nghĩa là các requests không được cache sẽ không hiển thị dữ liệu mới giữa các lần refresh HMR. Tuy nhiên, cache sẽ bị xóa khi điều hướng hoặc tải lại toàn trang.

Xem tài liệu [`serverComponentsHmrCache`](/docs/app/api-reference/config/next-config-js/serverComponentsHmrCache) để biết thêm thông tin.

### Hard refresh và caching trong development

Trong chế độ development, nếu request bao gồm header `cache-control: no-cache`, `options.cache`, `options.next.revalidate`, và `options.next.tags` sẽ bị bỏ qua, và request `fetch` được phục vụ từ nguồn.

Các trình duyệt thường bao gồm `cache-control: no-cache` khi cache bị vô hiệu hóa trong developer tools hoặc trong quá trình hard refresh.
