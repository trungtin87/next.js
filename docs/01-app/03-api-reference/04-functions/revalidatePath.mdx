`revalidatePath` cho phép bạn invalidate [cached data](/docs/app/guides/caching) theo yêu cầu cho một path cụ thể.

## Sử dụng

`revalidatePath` có thể được gọi trong Server Functions và Route Handlers.

`revalidatePath` không thể được gọi trong Client Components hoặc Proxy, vì nó chỉ hoạt động trong môi trường server.

> **Nên biết**:
>
> - **Server Functions**: Cập nhật UI ngay lập tức (nếu đang xem path bị ảnh hưởng). Hiện tại, nó cũng khiến tất cả các trang đã truy cập trước đó refresh khi được điều hướng lại. Hành vi này là tạm thời và sẽ được cập nhật trong tương lai để chỉ áp dụng cho path cụ thể.
> - **Route Handlers**: Đánh dấu path để revalidation. Revalidation được thực hiện trong lần truy cập tiếp theo đến path được chỉ định. Điều này có nghĩa là gọi `revalidatePath` với một dynamic route segment sẽ không ngay lập tức kích hoạt nhiều revalidations cùng một lúc. Invalidation chỉ xảy ra khi path được truy cập lần tiếp theo.

## Tham số

```tsx
revalidatePath(path: string, type?: 'page' | 'layout'): void;
```

- `path`: Hoặc một route pattern tương ứng với dữ liệu bạn muốn revalidate, ví dụ `/product/[slug]`, hoặc một URL cụ thể, `/product/123`. Không thêm `/page` hoặc `/layout`, sử dụng tham số `type` thay thế. Không được vượt quá 1024 ký tự. Giá trị này phân biệt chữ hoa chữ thường.
- `type`: (tùy chọn) chuỗi `'page'` hoặc `'layout'` để thay đổi loại path cần revalidate. Nếu `path` chứa một dynamic segment, ví dụ `/product/[slug]`, tham số này là bắt buộc. Nếu `path` là một URL cụ thể, `/product/1`, bỏ qua `type`.

Sử dụng một URL cụ thể khi bạn muốn refresh một [trang đơn lẻ](#revalidating-a-specific-url). Sử dụng một route pattern cộng với `type` để refresh [nhiều URLs](#revalidating-a-page-path).

## Giá trị trả về

`revalidatePath` không trả về giá trị.

## Những gì có thể bị invalidated

Tham số path có thể trỏ đến pages, layouts, hoặc route handlers:

- **Pages**: Invalidates trang cụ thể
- **Layouts**: Invalidates layout (`layout.tsx` tại segment đó), tất cả nested layouts bên dưới nó, và tất cả pages bên dưới chúng
- **Route Handlers**: Invalidates Data Cache entries được truy cập bên trong route handlers. Ví dụ `revalidatePath("/api/data")` invalidates GET handler này:

```ts filename="app/api/data/route.ts"
export async function GET() {
  const data = await fetch('https://api.vercel.app/blog', {
    cache: 'force-cache',
  })

  return Response.json(await data.json())
}
```

## Mối quan hệ với `revalidateTag` và `updateTag`

`revalidatePath`, [`revalidateTag`](/docs/app/api-reference/functions/revalidateTag) và [`updateTag`](/docs/app/api-reference/functions/updateTag) phục vụ các mục đích khác nhau:

- **`revalidatePath`**: Invalidates một page hoặc layout path cụ thể
- **`revalidateTag`**: Đánh dấu dữ liệu với các tags cụ thể là **stale**. Áp dụng trên tất cả các trang sử dụng các tags đó
- **`updateTag`**: Làm hết hạn dữ liệu với các tags cụ thể. Áp dụng trên tất cả các trang sử dụng các tags đó

Khi bạn gọi `revalidatePath`, chỉ path được chỉ định nhận dữ liệu mới trong lần truy cập tiếp theo. Các trang khác sử dụng cùng data tags sẽ tiếp tục phục vụ cached data cho đến khi các tags cụ thể đó cũng được revalidated:

```tsx
// Page A: /blog
const posts = await fetch('https://api.vercel.app/blog', {
  next: { tags: ['posts'] },
})

// Page B: /dashboard
const recentPosts = await fetch('https://api.vercel.app/blog?limit=5', {
  next: { tags: ['posts'] },
})
```

Sau khi gọi `revalidatePath('/blog')`:

- **Page A (/blog)**: Hiển thị dữ liệu mới (page re-rendered)
- **Page B (/dashboard)**: Vẫn hiển thị stale data (cache tag 'posts' không bị invalidated)

Tìm hiểu về sự khác biệt giữa [`revalidateTag` và `updateTag`](/docs/app/api-reference/functions/updateTag#differences-from-revalidatetag).

### Xây dựng các tiện ích revalidation

`revalidatePath` và `updateTag` là các primitives bổ sung thường được sử dụng cùng nhau trong các hàm tiện ích để đảm bảo tính nhất quán dữ liệu toàn diện trên ứng dụng của bạn:

```ts
'use server'

import { revalidatePath, updateTag } from 'next/cache'

export async function updatePost() {
  await updatePostInDatabase()

  revalidatePath('/blog') // Refresh the blog page
  updateTag('posts') // Refresh all pages using 'posts' tag
}
```

Mẫu này đảm bảo rằng cả trang cụ thể và bất kỳ trang nào khác sử dụng cùng dữ liệu đều duy trì nhất quán.

## Ví dụ

### Revalidating một URL cụ thể

```ts
import { revalidatePath } from 'next/cache'
revalidatePath('/blog/post-1')
```

Điều này sẽ invalidate một URL cụ thể để revalidation trong lần truy cập trang tiếp theo.

### Revalidating một Page path

```ts
import { revalidatePath } from 'next/cache'
revalidatePath('/blog/[slug]', 'page')
// or with route groups
revalidatePath('/(main)/blog/[slug]', 'page')
```

Điều này sẽ invalidate bất kỳ URL nào khớp với tệp `page` được cung cấp để revalidation trong lần truy cập trang tiếp theo. Điều này sẽ _không_ invalidate các trang bên dưới trang cụ thể. Ví dụ, `/blog/[slug]` sẽ không invalidate `/blog/[slug]/[author]`.

### Revalidating một Layout path

```ts
import { revalidatePath } from 'next/cache'
revalidatePath('/blog/[slug]', 'layout')
// or with route groups
revalidatePath('/(main)/post/[slug]', 'layout')
```

Điều này sẽ invalidate bất kỳ URL nào khớp với tệp `layout` được cung cấp để revalidation trong lần truy cập trang tiếp theo. Điều này sẽ khiến các trang bên dưới có cùng layout bị invalidated và revalidated trong lần truy cập tiếp theo. Ví dụ, trong trường hợp trên, `/blog/[slug]/[another]` cũng sẽ bị invalidated và revalidated trong lần truy cập tiếp theo.

### Revalidating tất cả dữ liệu

```ts
import { revalidatePath } from 'next/cache'

revalidatePath('/', 'layout')
```

Điều này sẽ xóa Client-side Router Cache, và invalidate Data Cache để revalidation trong lần truy cập trang tiếp theo.

### Server Function

```ts filename="app/actions.ts" switcher
'use server'

import { revalidatePath } from 'next/cache'

export default async function submit() {
  await submitForm()
  revalidatePath('/')
}
```

### Route Handler

```ts filename="app/api/revalidate/route.ts" switcher
import { revalidatePath } from 'next/cache'
import type { NextRequest } from 'next/server'

export async function GET(request: NextRequest) {
  const path = request.nextUrl.searchParams.get('path')

  if (path) {
    revalidatePath(path)
    return Response.json({ revalidated: true, now: Date.now() })
  }

  return Response.json({
    revalidated: false,
    now: Date.now(),
    message: 'Missing path to revalidate',
  })
}
```

```js filename="app/api/revalidate/route.js" switcher
  })
}
```
