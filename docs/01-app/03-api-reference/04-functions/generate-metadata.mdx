Bạn có thể sử dụng object `metadata` hoặc hàm `generateMetadata` để định nghĩa metadata.

## Object `metadata`

Để định nghĩa static metadata, export một [`Metadata` object](#metadata-fields) từ file `layout.js` hoặc `page.js`.

```tsx filename="layout.tsx | page.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: '...',
  description: '...',
}

export default function Page() {}
```

```jsx filename="layout.js | page.js" switcher
export const metadata = {
  title: '...',
  description: '...',
}

export default function Page() {}
```

> Xem [Metadata Fields](#metadata-fields) để biết danh sách đầy đủ các tùy chọn được hỗ trợ.

## Hàm `generateMetadata`

Dynamic metadata phụ thuộc vào **thông tin động**, chẳng hạn như route parameters hiện tại, dữ liệu bên ngoài, hoặc `metadata` trong các parent segments, có thể được thiết lập bằng cách export một hàm `generateMetadata` trả về một [`Metadata` object](#metadata-fields).

Việc resolve `generateMetadata` là một phần của quá trình render trang. Nếu trang có thể được pre-rendered và `generateMetadata` không giới thiệu hành vi động, metadata kết quả sẽ được bao gồm trong HTML ban đầu của trang.

Ngược lại, metadata được resolve từ `generateMetadata` [có thể được stream](/docs/app/api-reference/functions/generate-metadata#streaming-metadata) sau khi gửi UI ban đầu.

```tsx filename="app/products/[id]/page.tsx" switcher
import type { Metadata, ResolvingMetadata } from 'next'

type Props = {
  params: Promise<{ id: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}

export async function generateMetadata(
  { params, searchParams }: Props,
  parent: ResolvingMetadata
): Promise<Metadata> {
  // read route params
  const { id } = await params

  // fetch data
  const product = await fetch(`https://.../${id}`).then((res) => res.json())

  // optionally access and extend (rather than replace) parent metadata
  const previousImages = (await parent).openGraph?.images || []

  return {
    title: product.title,
    openGraph: {
      images: ['/some-specific-page-image.jpg', ...previousImages],
    },
  }
}

export default function Page({ params, searchParams }: Props) {}
```

```jsx filename="app/products/[id]/page.js" switcher
export async function generateMetadata({ params, searchParams }, parent) {
  // read route params
  const { id } = await params

  // fetch data
  const product = await fetch(`https://.../${id}`).then((res) => res.json())

  // optionally access and extend (rather than replace) parent metadata
  const previousImages = (await parent).openGraph?.images || []

  return {
    title: product.title,
    openGraph: {
      images: ['/some-specific-page-image.jpg', ...previousImages],
    },
  }
}

export default function Page({ params, searchParams }) {}
```

Để hoàn thành type cho `params` và `searchParams`, bạn có thể type argument đầu tiên với [`PageProps<'/route'>`](/docs/app/api-reference/file-conventions/page#page-props-helper) hoặc [`LayoutProps<'/route'>`](/docs/app/api-reference/file-conventions/layout#layout-props-helper) cho pages và layouts tương ứng.

> **Cần biết**:
>
> - Metadata có thể được thêm vào các file `layout.js` và `page.js`.
> - Next.js sẽ tự động resolve metadata, và tạo các thẻ `<head>` liên quan cho trang.
> - Các export object `metadata` và hàm `generateMetadata` **chỉ được hỗ trợ trong Server Components**.
> - Bạn không thể export cả object `metadata` và hàm `generateMetadata` từ cùng một route segment.
> - Các request `fetch` bên trong `generateMetadata` được tự động [memoized](/docs/app/guides/caching#request-memoization) cho cùng một dữ liệu giữa `generateMetadata`, `generateStaticParams`, Layouts, Pages, và Server Components.
> - React [`cache` có thể được sử dụng](/docs/app/guides/caching#react-cache-function) nếu `fetch` không khả dụng.
> - [File-based metadata](/docs/app/api-reference/file-conventions/metadata) có độ ưu tiên cao hơn và sẽ ghi đè object `metadata` và hàm `generateMetadata`.

## Tham khảo

### Parameters

Hàm `generateMetadata` chấp nhận các parameters sau:

- `props` - Một object chứa các parameters của route hiện tại:
  - `params` - Một object chứa object [dynamic route parameters](/docs/app/api-reference/file-conventions/dynamic-routes) từ root segment xuống đến segment mà `generateMetadata` được gọi. Ví dụ:

    | Route                           | URL         | `params`                  |
    | ------------------------------- | ----------- | ------------------------- |
    | `app/shop/[slug]/page.js`       | `/shop/1`   | `{ slug: '1' }`           |
    | `app/shop/[tag]/[item]/page.js` | `/shop/1/2` | `{ tag: '1', item: '2' }` |
    | `app/shop/[...slug]/page.js`    | `/shop/1/2` | `{ slug: ['1', '2'] }`    |

  - `searchParams` - Một object chứa [search params](https://developer.mozilla.org/docs/Learn/Common_questions/What_is_a_URL#parameters) của URL hiện tại. Ví dụ:

    | URL             | `searchParams`       |
    | --------------- | -------------------- |
    | `/shop?a=1`     | `{ a: '1' }`         |
    | `/shop?a=1&b=2` | `{ a: '1', b: '2' }` |
    | `/shop?a=1&a=2` | `{ a: ['1', '2'] }`  |

- `parent` - Một promise của metadata đã được resolve từ các parent route segments.

### Returns

`generateMetadata` nên trả về một [`Metadata` object](#metadata-fields) chứa một hoặc nhiều metadata fields.

> **Cần biết**:
>
> - Nếu metadata không phụ thuộc vào thông tin runtime, nó nên được định nghĩa bằng cách sử dụng static [`metadata` object](#the-metadata-object) thay vì `generateMetadata`.
> - Các request `fetch` được tự động [memoized](/docs/app/guides/caching#request-memoization) cho cùng một dữ liệu giữa `generateMetadata`, `generateStaticParams`, Layouts, Pages, và Server Components. React [`cache` có thể được sử dụng](/docs/app/guides/caching#react-cache-function) nếu `fetch` không khả dụng.
> - `searchParams` chỉ có sẵn trong các segments `page.js`.
> - Các phương thức Next.js [`redirect()`](/docs/app/api-reference/functions/redirect) và [`notFound()`](/docs/app/api-reference/functions/not-found) cũng có thể được sử dụng bên trong `generateMetadata`.

### Metadata Fields

Các fields sau đây được hỗ trợ:

#### `title`

Thuộc tính `title` được sử dụng để đặt tiêu đề của tài liệu. Nó có thể được định nghĩa là một [string](#string) đơn giản hoặc một tùy chọn [template object](#template).

##### String

```jsx filename="layout.js | page.js"
export const metadata = {
  title: 'Next.js',
}
```

```html filename="<head> output" hideLineNumbers
<title>Next.js</title>
```

##### `default`

`title.default` có thể được sử dụng để cung cấp một **fallback title** cho các child route segments không định nghĩa `title`.

```tsx filename="app/layout.tsx"
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    default: 'Acme',
  },
}
```

```tsx filename="app/about/page.tsx"
import type { Metadata } from 'next'

export const metadata: Metadata = {}

// Output: <title>Acme</title>
```

##### `template`

`title.template` có thể được sử dụng để thêm prefix hoặc suffix vào `titles` được định nghĩa trong các **child** route segments.

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    template: '%s | Acme',
    default: 'Acme', // a default is required when creating a template
  },
}
```

```jsx filename="app/layout.js" switcher
export const metadata = {
  title: {
    template: '%s | Acme',
    default: 'Acme', // a default is required when creating a template
  },
}
```

```tsx filename="app/about/page.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'About',
}

// Output: <title>About | Acme</title>
```

```jsx filename="app/about/page.js" switcher
export const metadata = {
  title: 'About',
}

// Output: <title>About | Acme</title>
```

> **Cần biết**:
>
> - `title.template` áp dụng cho các **child** route segments và **không** áp dụng cho segment mà nó được định nghĩa. Điều này có nghĩa là:
>   - `title.default` là **bắt buộc** khi bạn thêm `title.template`.
>   - `title.template` được định nghĩa trong `layout.js` sẽ không áp dụng cho `title` được định nghĩa trong `page.js` của cùng một route segment.
>   - `title.template` được định nghĩa trong `page.js` không có tác dụng vì page luôn là terminating segment (nó không có bất kỳ children route segments nào).
> - `title.template` **không có tác dụng** nếu một route chưa định nghĩa `title` hoặc `title.default`.

##### `absolute`

`title.absolute` có thể được sử dụng để cung cấp một title **bỏ qua** `title.template` được đặt trong các parent segments.

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    template: '%s | Acme',
  },
}
```

```jsx filename="app/layout.js" switcher
export const metadata = {
  title: {
    template: '%s | Acme',
  },
}
```

```tsx filename="app/about/page.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    absolute: 'About',
  },
}

// Output: <title>About</title>
```

```jsx filename="app/about/page.js" switcher
export const metadata = {
  title: {
    absolute: 'About',
  },
}

// Output: <title>About</title>
```

> **Cần biết**:
>
> - `layout.js`
>   - `title` (string) và `title.default` định nghĩa default title cho các child segments (những cái không định nghĩa `title` riêng của chúng). Nó sẽ bổ sung `title.template` từ parent segment gần nhất nếu tồn tại.
>   - `title.absolute` định nghĩa default title cho các child segments. Nó bỏ qua `title.template` từ các parent segments.
>   - `title.template` định nghĩa một title template mới cho các child segments.
> - `page.js`
>   - Nếu một page không định nghĩa title riêng của nó, title đã được resolve của parents gần nhất sẽ được sử dụng.
>   - `title` (string) định nghĩa routes title. Nó sẽ bổ sung `title.template` từ parent segment gần nhất nếu tồn tại.
>   - `title.absolute` định nghĩa route title. Nó bỏ qua `title.template` từ các parent segments.
>   - `title.template` không có tác dụng trong `page.js` vì một page luôn là terminating segment của một route.

#### `metadataBase`

`metadataBase` là một tùy chọn tiện lợi để đặt base URL prefix cho các `metadata` fields yêu cầu một fully qualified URL.

- `metadataBase` cho phép các `metadata` fields dựa trên URL được định nghĩa trong **current route segment và bên dưới** sử dụng một **relative path** thay vì một absolute URL bắt buộc khác.
- Relative path của field sẽ được kết hợp với `metadataBase` để tạo thành một fully qualified URL.

```jsx filename="layout.js | page.js"
export const metadata = {
  metadataBase: new URL('https://acme.com'),
  alternates: {
    canonical: '/',
    languages: {
      'en-US': '/en-US',
      'de-DE': '/de-DE',
    },
  },
  openGraph: {
    images: '/og-image.png',
  },
}
```

```html filename="<head> output" hideLineNumbers
<link rel="canonical" href="https://acme.com" />
<link rel="alternate" hreflang="en-US" href="https://acme.com/en-US" />
<link rel="alternate" hreflang="de-DE" href="https://acme.com/de-DE" />
<meta property="og:image" content="https://acme.com/og-image.png" />
```

> **Cần biết**:
>
> - `metadataBase` thường được đặt trong root `app/layout.js` để áp dụng cho các `metadata` fields dựa trên URL trên tất cả các routes.
> - Tất cả các `metadata` fields dựa trên URL yêu cầu absolute URLs có thể được cấu hình với tùy chọn `metadataBase`.
> - `metadataBase` có thể chứa một subdomain ví dụ `https://app.acme.com` hoặc base path ví dụ `https://acme.com/start/from/here`
> - Nếu một `metadata` field cung cấp một absolute URL, `metadataBase` sẽ bị bỏ qua.
> - Sử dụng một relative path trong một `metadata` field dựa trên URL mà không cấu hình `metadataBase` sẽ gây ra lỗi build.
> - Next.js sẽ chuẩn hóa các dấu gạch chéo trùng lặp giữa `metadataBase` (ví dụ `https://acme.com/`) và một relative field (ví dụ `/path`) thành một dấu gạch chéo đơn (ví dụ `https://acme.com/path`)

#### URL Composition

URL composition ưu tiên ý định của developer hơn ngữ nghĩa duyệt thư mục mặc định.

- Trailing slashes giữa `metadataBase` và `metadata` fields được chuẩn hóa.
- Một "absolute" path trong một `metadata` field (thường sẽ thay thế toàn bộ URL path) được coi là một "relative" path (bắt đầu từ cuối của `metadataBase`).

Ví dụ, với `metadataBase` sau:

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  metadataBase: new URL('https://acme.com'),
}
```

```jsx filename="app/layout.js" switcher
export const metadata = {
  metadataBase: new URL('https://acme.com'),
}
```

Bất kỳ `metadata` fields nào kế thừa `metadataBase` ở trên và đặt giá trị riêng của chúng sẽ được resolve như sau:

| `metadata` field                 | Resolved URL                     |
| -------------------------------- | -------------------------------- |
| `/`                              | `https://acme.com`               |
| `./`                             | `https://acme.com`               |
| `payments`                       | `https://acme.com/payments`      |
| `/payments`                      | `https://acme.com/payments`      |
| `./payments`                     | `https://acme.com/payments`      |
| `../payments`                    | `https://acme.com/payments`      |
| `https://beta.acme.com/payments` | `https://beta.acme.com/payments` |

### Resource hints

Phần tử `<link>` có một số từ khóa `rel` có thể được sử dụng để gợi ý cho trình duyệt rằng một tài nguyên bên ngoài có khả năng sẽ cần thiết. Trình duyệt sử dụng thông tin này để áp dụng các tối ưu hóa preloading tùy thuộc vào từ khóa.

Mặc dù Metadata API không hỗ trợ trực tiếp các gợi ý này, bạn có thể sử dụng các phương thức [`ReactDOM` mới](https://github.com/facebook/react/pull/26237) để chèn chúng một cách an toàn vào `<head>` của tài liệu.

```tsx filename="app/preload-resources.tsx" switcher
'use client'

import ReactDOM from 'react-dom'

export function PreloadResources() {
  ReactDOM.preload('...', { as: '...' })
  ReactDOM.preconnect('...', { crossOrigin: '...' })
  ReactDOM.prefetchDNS('...')

  return '...'
}
```

```jsx filename="app/preload-resources.js" switcher

```

## Hành vi

### Các trường mặc định

Có hai thẻ `meta` mặc định luôn được thêm vào ngay cả khi một route không định nghĩa metadata:

- [Thẻ meta charset](https://developer.mozilla.org/docs/Web/HTML/Element/meta#attr-charset) đặt mã hóa ký tự cho trang web.
- [Thẻ meta viewport](https://developer.mozilla.org/docs/Web/HTML/Viewport_meta_tag) đặt chiều rộng và tỷ lệ viewport cho trang web để điều chỉnh cho các thiết bị khác nhau.

```html
<meta charset="utf-8" />
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

> **Cần biết**: Bạn có thể ghi đè thẻ meta [`viewport`](/docs/app/api-reference/functions/generate-metadata#viewport) mặc định.

### Streaming metadata

Streaming metadata cho phép Next.js render và gửi UI ban đầu đến trình duyệt, mà không cần đợi `generateMetadata` hoàn thành.

Khi `generateMetadata` resolve, các thẻ metadata kết quả được thêm vào thẻ `<body>`. Chúng tôi đã xác minh rằng metadata được diễn giải chính xác bởi các bot thực thi JavaScript và kiểm tra toàn bộ DOM (ví dụ: `Googlebot`).

Đối với các **HTML-limited bots** không thể thực thi JavaScript (ví dụ: `facebookexternalhit`), metadata tiếp tục chặn render trang. Metadata kết quả sẽ có sẵn trong thẻ `<head>`.

Next.js tự động phát hiện **HTML-limited bots** bằng cách xem xét User Agent header. Bạn có thể sử dụng tùy chọn [`htmlLimitedBots`](/docs/app/api-reference/config/next-config-js/htmlLimitedBots) trong file cấu hình Next.js của bạn để ghi đè [danh sách User Agent](https://github.com/vercel/next.js/blob/canary/packages/next/src/shared/lib/router/utils/html-bots.ts) mặc định.

Để tắt hoàn toàn streaming metadata:

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const config: NextConfig = {
  htmlLimitedBots: /.*/,
}

export default config
```

```js filename="next.config.js" switcher
module.exports = {
  htmlLimitedBots: /.*/,
}
```

Streaming metadata cải thiện hiệu suất cảm nhận bằng cách giảm [TTFB](https://developer.mozilla.org/docs/Glossary/Time_to_first_byte) và có thể giúp giảm thời gian [LCP](https://developer.mozilla.org/docs/Glossary/Largest_contentful_paint).

Ghi đè `htmlLimitedBots` có thể dẫn đến thời gian phản hồi lâu hơn. Streaming metadata là một tính năng nâng cao, và mặc định là đủ cho hầu hết các trường hợp.

### Thứ tự

Metadata được đánh giá theo thứ tự, bắt đầu từ root segment xuống đến segment gần nhất với segment `page.js` cuối cùng. Ví dụ:

1. `app/layout.tsx` (Root Layout)
2. `app/blog/layout.tsx` (Nested Blog Layout)
3. `app/blog/[slug]/page.tsx` (Blog Page)

### Gộp (Merging)

Theo [thứ tự đánh giá](#ordering), các Metadata objects được export từ nhiều segments trong cùng một route được merge **nông (shallowly)** với nhau để tạo thành metadata output cuối cùng của một route. Các key trùng lặp được **thay thế** dựa trên thứ tự của chúng.

Điều này có nghĩa là metadata với các fields lồng nhau như [`openGraph`](/docs/app/api-reference/functions/generate-metadata#opengraph) và [`robots`](/docs/app/api-reference/functions/generate-metadata#robots) được định nghĩa trong một segment trước đó sẽ bị **ghi đè** bởi segment cuối cùng định nghĩa chúng.

#### Ghi đè fields

```jsx filename="app/layout.js"
export const metadata = {
  title: 'Acme',
  openGraph: {
    title: 'Acme',
    description: 'Acme is a...',
  },
}
```

```jsx filename="app/blog/page.js"
export const metadata = {
  title: 'Blog',
  openGraph: {
    title: 'Blog',
  },
}

// Output:
// <title>Blog</title>
// <meta property="og:title" content="Blog" />
```

Trong ví dụ trên:

- `title` từ `app/layout.js` bị **thay thế** bởi `title` trong `app/blog/page.js`.
- Tất cả các fields `openGraph` từ `app/layout.js` bị **thay thế** trong `app/blog/page.js` vì `app/blog/page.js` đặt metadata `openGraph`. Lưu ý sự vắng mặt của `openGraph.description`.

Nếu bạn muốn chia sẻ một số fields lồng nhau giữa các segments trong khi ghi đè các fields khác, bạn có thể tách chúng ra thành một biến riêng biệt:

```jsx filename="app/shared-metadata.js"
export const openGraphImage = { images: ['http://...'] }
```

```jsx filename="app/page.js"
import { openGraphImage } from './shared-metadata'

export const metadata = {
  openGraph: {
    ...openGraphImage,
    title: 'Home',
  },
}
```

```jsx filename="app/about/page.js"
import { openGraphImage } from '../shared-metadata'

export const metadata = {
  openGraph: {
    ...openGraphImage,
    title: 'About',
  },
}
```

Trong ví dụ trên, OG image được chia sẻ giữa `app/layout.js` và `app/about/page.js` trong khi titles là khác nhau.

#### Kế thừa fields

```jsx filename="app/layout.js"
export const metadata = {
  title: 'Acme',
  openGraph: {
    title: 'Acme',
    description: 'Acme is a...',
  },
}
```

```jsx filename="app/about/page.js"
export const metadata = {
  title: 'About',
}

// Output:
// <title>About</title>
// <meta property="og:title" content="Acme" />
// <meta property="og:description" content="Acme is a..." />
```

**Ghi chú**

- `title` từ `app/layout.js` bị **thay thế** bởi `title` trong `app/about/page.js`.
- Tất cả các fields `openGraph` từ `app/layout.js` được **kế thừa** trong `app/about/page.js` vì `app/about/page.js` không đặt metadata `openGraph`.
