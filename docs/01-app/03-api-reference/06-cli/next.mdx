Next.js CLI cho phép bạn phát triển, build, khởi động ứng dụng của mình và hơn thế nữa.

Sử dụng cơ bản:

```bash filename="Terminal"
npx next [command] [options]
```

## Tham khảo

Các tùy chọn sau có sẵn:

| Tùy chọn              | Mô tả                               |
| --------------------- | ----------------------------------- |
| `-h` hoặc `--help`    | Hiển thị tất cả các tùy chọn có sẵn |
| `-v` hoặc `--version` | Xuất ra số phiên bản Next.js        |

### Các lệnh (Commands)

Các lệnh sau có sẵn:

| Lệnh                                   | Mô tả                                                                                                     |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| [`dev`](#next-dev-options)             | Khởi động Next.js ở chế độ development với Hot Module Reloading, báo cáo lỗi, và hơn thế nữa.             |
| [`build`](#next-build-options)         | Tạo một bản build production được tối ưu hóa cho ứng dụng của bạn. Hiển thị thông tin về từng route.      |
| [`start`](#next-start-options)         | Khởi động Next.js ở chế độ production. Ứng dụng nên được biên dịch với `next build` trước.                |
| [`info`](#next-info-options)           | In ra các chi tiết liên quan về hệ thống hiện tại có thể được sử dụng để báo cáo lỗi Next.js.             |
| [`telemetry`](#next-telemetry-options) | Cho phép bạn bật hoặc tắt việc thu thập telemetry hoàn toàn ẩn danh của Next.js.                          |
| [`typegen`](#next-typegen-options)     | Tạo các định nghĩa TypeScript cho routes, pages, layouts, và route handlers mà không cần chạy full build. |

> **Cần biết**: Chạy `next` mà không có lệnh là một bí danh cho `next dev`.

### Tùy chọn `next dev`

`next dev` khởi động ứng dụng ở chế độ development với Hot Module Reloading (HMR), báo cáo lỗi, và hơn thế nữa. Các tùy chọn sau có sẵn khi chạy `next dev`:

| Tùy chọn                                 | Mô tả                                                                                                                             |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `-h, --help`                             | Hiển thị tất cả các tùy chọn có sẵn.                                                                                              |
| `[directory]`                            | Một thư mục để build ứng dụng trong đó. Nếu không được cung cấp, thư mục hiện tại sẽ được sử dụng.                                |
| `--turbopack`                            | Buộc bật [Turbopack](/docs/app/api-reference/turbopack) (được bật mặc định). Cũng có sẵn dưới dạng `--turbo`.                     |
| `--webpack`                              | Sử dụng Webpack thay vì trình đóng gói [Turbopack](/docs/app/api-reference/turbopack) mặc định cho development.                   |
| `-p` hoặc `--port <port>`                | Chỉ định số cổng để khởi động ứng dụng. Mặc định: 3000, env: PORT                                                                 |
| `-H` hoặc `--hostname <hostname>`        | Chỉ định tên máy chủ để khởi động ứng dụng. Hữu ích để làm cho ứng dụng có sẵn cho các thiết bị khác trên mạng. Mặc định: 0.0.0.0 |
| `--experimental-https`                   | Khởi động máy chủ với HTTPS và tạo chứng chỉ tự ký (self-signed certificate).                                                     |
| `--experimental-https-key <path>`        | Đường dẫn đến tệp khóa HTTPS.                                                                                                     |
| `--experimental-https-cert <path>`       | Đường dẫn đến tệp chứng chỉ HTTPS.                                                                                                |
| `--experimental-https-ca <path>`         | Đường dẫn đến tệp chứng chỉ authority HTTPS.                                                                                      |
| `--experimental-upload-trace <traceUrl>` | Báo cáo một tập hợp con của dấu vết gỡ lỗi (debugging trace) đến một URL HTTP từ xa.                                              |

### Tùy chọn `next build`

`next build` tạo một bản build production được tối ưu hóa cho ứng dụng của bạn. Đầu ra hiển thị thông tin về từng route. Ví dụ:

```bash filename="Terminal"
Route (app)
┌ ○ /_not-found
└ ƒ /products/[id]

○  (Static)   prerendered as static content
ƒ  (Dynamic)  server-rendered on demand
```

Các tùy chọn sau có sẵn cho lệnh `next build`:

| Tùy chọn                           | Mô tả                                                                                                                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-h, --help`                       | Hiển thị tất cả các tùy chọn có sẵn.                                                                                                                                                        |
| `[directory]`                      | Một thư mục để build ứng dụng trên đó. Nếu không được cung cấp, thư mục hiện tại sẽ được sử dụng.                                                                                           |
| `--turbopack`                      | Buộc bật [Turbopack](/docs/app/api-reference/turbopack) (được bật mặc định). Cũng có sẵn dưới dạng `--turbo`.                                                                               |
| `--webpack`                        | Build sử dụng Webpack.                                                                                                                                                                      |
| `-d` hoặc `--debug`                | Bật đầu ra build chi tiết hơn. Với cờ này được bật, đầu ra build bổ sung như rewrites, redirects, và headers sẽ được hiển thị.                                                              |
|                                    |
| `--profile`                        | Bật [profiling cho React](https://react.dev/reference/react/Profiler) trong production.                                                                                                     |
| `--no-lint`                        | Tắt linting. _Lưu ý: linting sẽ bị xóa khỏi `next build` trong Next 16. Nếu bạn đang sử dụng Next 15.5+ với một linter khác ngoài `eslint`, linting trong quá trình build sẽ không xảy ra._ |
| `--no-mangling`                    | Tắt [mangling](https://en.wikipedia.org/wiki/Name_mangling). Điều này có thể ảnh hưởng đến hiệu suất và chỉ nên được sử dụng cho mục đích gỡ lỗi.                                           |
| `--experimental-app-only`          | Chỉ build các routes của App Router.                                                                                                                                                        |
| `--experimental-build-mode [mode]` | Sử dụng chế độ build thử nghiệm. (lựa chọn: "compile", "generate", mặc định: "default")                                                                                                     |
| `--debug-prerender`                | Gỡ lỗi lỗi prerender trong development.                                                                                                                                                     |
| `--debug-build-paths=<patterns>`   | Chỉ build các routes cụ thể để gỡ lỗi.                                                                                                                                                      |

### Tùy chọn `next start`

`next start` khởi động ứng dụng ở chế độ production. Ứng dụng nên được biên dịch với [`next build`](#next-build-options) trước.

Các tùy chọn sau có sẵn cho lệnh `next start`:

| Tùy chọn                                | Mô tả                                                                                                                |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `-h` hoặc `--help`                      | Hiển thị tất cả các tùy chọn có sẵn.                                                                                 |
| `[directory]`                           | Một thư mục để khởi động ứng dụng trên đó. Nếu không có thư mục nào được cung cấp, thư mục hiện tại sẽ được sử dụng. |
| `-p` hoặc `--port <port>`               | Chỉ định số cổng để khởi động ứng dụng. (mặc định: 3000, env: PORT)                                                  |
| `-H` hoặc `--hostname <hostname>`       | Chỉ định tên máy chủ để khởi động ứng dụng (mặc định: 0.0.0.0).                                                      |
| `--keepAliveTimeout <keepAliveTimeout>` | Chỉ định lượng mili giây tối đa để chờ trước khi đóng các kết nối không hoạt động.                                   |

### Tùy chọn `next info`

Thông tin này bao gồm nền tảng/kiến trúc/phiên bản Hệ điều hành, Binaries (Node.js, npm, Yarn, pnpm), phiên bản gói (`next`, `react`, `react-dom`), và hơn thế nữa.

### Tùy chọn `next telemetry`

Next.js thu thập dữ liệu telemetry **hoàn toàn ẩn danh** về việc sử dụng chung. Việc tham gia vào chương trình ẩn danh này là tùy chọn, và bạn có thể chọn không tham gia nếu bạn không muốn chia sẻ thông tin.

Các tùy chọn sau có sẵn cho lệnh `next telemetry`:

| Tùy chọn     | Mô tả                                |
| ------------ | ------------------------------------ |
| `-h, --help` | Hiển thị tất cả các tùy chọn có sẵn. |
| `--enable`   | Bật thu thập telemetry của Next.js.  |
| `--disable`  | Tắt thu thập telemetry của Next.js.  |

Tìm hiểu thêm về [Telemetry](/telemetry).

### Tùy chọn `next typegen`

`next typegen` tạo các định nghĩa TypeScript cho các routes của ứng dụng của bạn mà không cần thực hiện full build. Điều này hữu ích cho việc tự động hoàn thành của IDE và kiểm tra kiểu CI (CI type-checking) của việc sử dụng route.

Trước đây, các loại route chỉ được tạo trong quá trình `next dev` hoặc `next build`, điều này có nghĩa là chạy `tsc --noEmit` trực tiếp sẽ không xác thực các loại route của bạn. Bây giờ bạn có thể tạo các loại một cách độc lập và xác thực chúng bên ngoài:

```bash filename="Terminal"
# Tạo các loại route trước, sau đó xác thực với TypeScript
next typegen && tsc --noEmit

# Hoặc trong quy trình làm việc CI để kiểm tra kiểu mà không cần build
next typegen && npm run type-check
```

Các tùy chọn sau có sẵn cho lệnh `next typegen`:

| Tùy chọn      | Mô tả                                                                                           |
| ------------- | ----------------------------------------------------------------------------------------------- |
| `-h, --help`  | Hiển thị tất cả các tùy chọn có sẵn.                                                            |
| `[directory]` | Một thư mục để tạo các loại trên đó. Nếu không được cung cấp, thư mục hiện tại sẽ được sử dụng. |

Các tệp đầu ra được ghi vào `<distDir>/types` (thường là: `.next/dev/types` hoặc `.next/types`, xem [`isolatedDevBuild`](/docs/app/api-reference/config/next-config-js/isolatedDevBuild)):

```bash filename="Terminal"
next typegen
# hoặc cho một ứng dụng cụ thể
next typegen ./apps/web
```

Ngoài ra, `next typegen` tạo một tệp `next-env.d.ts`. Chúng tôi khuyên bạn nên thêm `next-env.d.ts` vào tệp `.gitignore` của mình.

Tệp `next-env.d.ts` được bao gồm vào tệp `tsconfig.json` của bạn, để làm cho các loại Next.js có sẵn cho dự án của bạn.

Để đảm bảo `next-env.d.ts` hiện diện trước khi kiểm tra kiểu, hãy chạy `next typegen`. Các lệnh `next dev` và `next build` cũng tạo tệp `next-env.d.ts`, nhưng thường không mong muốn chạy những lệnh này chỉ để kiểm tra kiểu, ví dụ trong môi trường CI/CD.

> **Cần biết**: `next typegen` tải cấu hình Next.js của bạn (`next.config.js`, `next.config.mjs`, hoặc `next.config.ts`) bằng cách sử dụng giai đoạn build production. Đảm bảo bất kỳ biến môi trường và phụ thuộc cần thiết nào đều có sẵn để cấu hình có thể tải chính xác.

## Ví dụ

### Gỡ lỗi lỗi prerender

Nếu bạn gặp lỗi prerendering trong quá trình `next build`, bạn có thể chuyển cờ `--debug-prerender` để nhận đầu ra chi tiết hơn:

```bash filename="Terminal"
next build --debug-prerender
```

Điều này cho phép một số tùy chọn thử nghiệm để làm cho việc gỡ lỗi dễ dàng hơn:

- Tắt thu nhỏ mã máy chủ (server code minification):
  - `experimental.serverMinification = false`
  - `experimental.turbopackMinify = false`
- Tạo source maps cho các gói máy chủ:
  - `experimental.serverSourceMaps = true`
- Bật tiêu thụ source map trong các tiến trình con được sử dụng cho prerendering:
  - `enablePrerenderSourceMaps = true`
- Tiếp tục build ngay cả sau lỗi prerender đầu tiên, vì vậy bạn có thể thấy tất cả các vấn đề cùng một lúc:
  - `experimental.prerenderEarlyExit = false`

Điều này giúp hiển thị các stack traces và khung mã dễ đọc hơn trong đầu ra build.

> **Cảnh báo**: `--debug-prerender` chỉ dành cho việc gỡ lỗi trong development. Không triển khai các bản build được tạo với `--debug-prerender` lên production, vì nó có thể ảnh hưởng đến hiệu suất.

### Build các routes cụ thể

Bạn có thể chỉ build các routes cụ thể trong App và Pages Routers bằng cách sử dụng tùy chọn `--debug-build-paths`. Điều này hữu ích cho việc gỡ lỗi nhanh hơn khi làm việc với các ứng dụng lớn. Tùy chọn `--debug-build-paths` chấp nhận các đường dẫn tệp được phân tách bằng dấu phẩy và hỗ trợ các mẫu glob:

```bash filename="Terminal"
# Build một route cụ thể
next build --debug-build-paths="app/page.tsx"

# Build nhiều hơn một route
next build --debug-build-paths="app/page.tsx,pages/index.tsx"

# Sử dụng các mẫu glob
next build --debug-build-paths="app/**/page.tsx"
next build --debug-build-paths="pages/*.tsx"
```

### Thay đổi cổng mặc định

Theo mặc định, Next.js sử dụng `http://localhost:3000` trong quá trình development và với `next start`. Cổng mặc định có thể được thay đổi với tùy chọn `-p`, như sau:

```bash filename="Terminal"
next dev -p 4000
```

Hoặc sử dụng biến môi trường `PORT`:

```bash filename="Terminal"
PORT=4000 next dev
```

> **Cần biết**: `PORT` không thể được đặt trong `.env` vì việc khởi động máy chủ HTTP xảy ra trước khi bất kỳ mã nào khác được khởi tạo.

### Sử dụng HTTPS trong quá trình development

Đối với một số trường hợp sử dụng nhất định như webhooks hoặc xác thực, bạn có thể sử dụng [HTTPS](https://developer.mozilla.org/en-US/docs/Glossary/HTTPS) để có môi trường an toàn trên `localhost`. Next.js có thể tạo chứng chỉ tự ký với `next dev` bằng cách sử dụng cờ `--experimental-https`:

```bash filename="Terminal"
next dev --experimental-https
```

Với chứng chỉ đã tạo, máy chủ phát triển Next.js sẽ tồn tại tại `https://localhost:3000`. Cổng mặc định `3000` được sử dụng trừ khi một cổng được chỉ định với `-p`, `--port`, hoặc `PORT`.

Bạn cũng có thể cung cấp chứng chỉ và khóa tùy chỉnh với `--experimental-https-key` và `--experimental-https-cert`. Tùy chọn, bạn cũng có thể cung cấp chứng chỉ CA tùy chỉnh với `--experimental-https-ca`.

```bash filename="Terminal"
next dev --experimental-https --experimental-https-key ./certificates/localhost-key.pem --experimental-https-cert ./certificates/localhost.pem
```

`next dev --experimental-https` chỉ dành cho development và tạo chứng chỉ được tin cậy cục bộ với [`mkcert`](https://github.com/FiloSottile/mkcert). Trong production, hãy sử dụng các chứng chỉ được cấp đúng cách từ các cơ quan đáng tin cậy.

### Định cấu hình thời gian chờ cho proxy hạ nguồn (downstream proxies)

Khi triển khai Next.js đằng sau một proxy hạ nguồn (ví dụ: bộ cân bằng tải như AWS ELB/ALB), điều quan trọng là phải định cấu hình máy chủ HTTP cơ bản của Next với [keep-alive timeouts](https://nodejs.org/api/http.html#http_server_keepalivetimeout) _lớn hơn_ thời gian chờ của proxy hạ nguồn. Nếu không, khi đạt đến thời gian chờ keep-alive cho một kết nối TCP nhất định, Node.js sẽ ngay lập tức chấm dứt kết nối đó mà không thông báo cho proxy hạ nguồn. Điều này dẫn đến lỗi proxy bất cứ khi nào nó cố gắng sử dụng lại một kết nối mà Node.js đã chấm dứt.

Để định cấu hình các giá trị thời gian chờ cho máy chủ Next.js production, hãy chuyển `--keepAliveTimeout` (tính bằng mili giây) cho `next start`, như sau:

```bash filename="Terminal"
next start --keepAliveTimeout 70000
```

### Truyền các đối số Node.js

Bạn có thể truyền bất kỳ [đối số node](https://nodejs.org/api/cli.html#cli_node_options_options) nào cho các lệnh `next`. Ví dụ:

```bash filename="Terminal"
NODE_OPTIONS='--throw-deprecation' next
NODE_OPTIONS='-r esm' next
NODE_OPTIONS='--inspect' next
```

| Phiên bản | Thay đổi                                                                         |
| --------- | -------------------------------------------------------------------------------- |
| `v16.0.0` | Các chỉ số kích thước gói JS đã bị xóa khỏi `next build`                         |
| `v15.5.0` | Thêm lệnh `next typegen`                                                         |
| `v15.4.0` | Thêm tùy chọn `--debug-prerender` cho `next build` để giúp gỡ lỗi lỗi prerender. |
