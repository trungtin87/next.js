version: experimental
---

Tùy chọn thử nghiệm `serverComponentsHmrCache` cho phép bạn cache các phản hồi `fetch` trong Server Components qua các lần làm mới Hot Module Replacement (HMR) trong quá trình phát triển cục bộ. Điều này dẫn đến phản hồi nhanh hơn và giảm chi phí cho các cuộc gọi API tính phí.

Theo mặc định, HMR cache áp dụng cho tất cả các yêu cầu `fetch`, bao gồm cả những yêu cầu với tùy chọn `cache: 'no-store'`. Điều này có nghĩa là các yêu cầu không được cache sẽ không hiển thị dữ liệu mới giữa các lần làm mới HMR. Tuy nhiên, cache sẽ được xóa khi điều hướng hoặc tải lại toàn bộ trang.

Bạn có thể vô hiệu hóa HMR cache bằng cách đặt `serverComponentsHmrCache` thành `false` trong tệp `next.config.js` của bạn:

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    serverComponentsHmrCache: false, // mặc định là true
  },
}

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    serverComponentsHmrCache: false, // mặc định là true
  },
}

module.exports = nextConfig
```

> **Thông tin hữu ích:** Để quan sát tốt hơn, chúng tôi khuyên bạn nên sử dụng tùy chọn [`logging.fetches`](/docs/app/api-reference/config/next-config-js/logging) để ghi lại các lần truy cập và bỏ lỡ cache fetch trong console trong quá trình phát triển.
