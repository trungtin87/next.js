Trong quá trình build, Next.js sẽ tự động theo dõi từng trang và các dependencies của nó để xác định tất cả các tệp cần thiết cho việc triển khai phiên bản production của ứng dụng của bạn.

Tính năng này giúp giảm đáng kể kích thước của các bản triển khai. Trước đây, khi triển khai với Docker, bạn sẽ cần cài đặt tất cả các tệp từ `dependencies` của gói để chạy `next start`. Bắt đầu từ Next.js 12, bạn có thể tận dụng Output File Tracing trong thư mục `.next/` để chỉ bao gồm các tệp cần thiết.

Hơn nữa, điều này loại bỏ nhu cầu về target `serverless` không dùng nữa, có thể gây ra nhiều vấn đề khác nhau và cũng tạo ra sự trùng lặp không cần thiết.

## Cách nó hoạt động

Trong quá trình `next build`, Next.js sẽ sử dụng [`@vercel/nft`](https://github.com/vercel/nft) để phân tích tĩnh việc sử dụng `import`, `require`, và `fs` để xác định tất cả các tệp mà một trang có thể tải.

Production server của Next.js cũng được theo dõi các tệp cần thiết và xuất ra tại `.next/next-server.js.nft.json` có thể được tận dụng trong production.

Để tận dụng các tệp `.nft.json` được phát ra thư mục output `.next`, bạn có thể đọc danh sách các tệp trong mỗi trace tương đối với tệp `.nft.json` và sau đó sao chép chúng đến vị trí triển khai của bạn.

## Tự động sao chép các tệp được theo dõi

Next.js có thể tự động tạo một thư mục `standalone` sao chép chỉ các tệp cần thiết cho một bản triển khai production bao gồm các tệp chọn lọc trong `node_modules`.

Để tận dụng việc sao chép tự động này, bạn có thể kích hoạt nó trong `next.config.js` của mình:

```js filename="next.config.js"
module.exports = {
  output: 'standalone',
}
```

Điều này sẽ tạo ra một thư mục tại `.next/standalone` sau đó có thể được triển khai riêng mà không cần cài đặt `node_modules`.

Ngoài ra, một tệp `server.js` tối thiểu cũng được xuất ra có thể được sử dụng thay vì `next start`. Server tối thiểu này không sao chép các thư mục `public` hoặc `.next/static` theo mặc định vì những thư mục này lý tưởng nhất nên được xử lý bởi CDN, mặc dù các thư mục này có thể được sao chép thủ công vào các thư mục `standalone/public` và `standalone/.next/static`, sau đó tệp `server.js` sẽ phục vụ chúng tự động.

Để sao chép chúng thủ công, bạn có thể sử dụng công cụ dòng lệnh `cp` sau khi `next build`:

```bash filename="Terminal"
cp -r public .next/standalone/ && cp -r .next/static .next/standalone/.next/
```

Để khởi động tệp `server.js` tối thiểu của bạn cục bộ, hãy chạy lệnh sau:

```bash filename="Terminal"
node .next/standalone/server.js
```

## Lưu ý

- Trong khi theo dõi trong các thiết lập monorepo, thư mục dự án được sử dụng để theo dõi theo mặc định. Đối với `next build packages/web-app`, `packages/web-app` sẽ là tracing root và bất kỳ tệp nào bên ngoài thư mục đó sẽ không được bao gồm. Để bao gồm các tệp bên ngoài thư mục này, bạn có thể đặt `outputFileTracingRoot` trong `next.config.js` của mình.

```js filename="packages/web-app/next.config.js"
const path = require('path')

module.exports = {
  // this includes files from the monorepo base two directories up
  outputFileTracingRoot: path.join(__dirname, '../../'),
}
```

- Có một số trường hợp Next.js có thể không bao gồm các tệp cần thiết, hoặc có thể bao gồm sai các tệp không sử dụng. Trong những trường hợp đó, bạn có thể tận dụng `outputFileTracingExcludes` và `outputFileTracingIncludes` tương ứng trong `next.config.js`. Mỗi tùy chọn chấp nhận một object có các key là **route globs** (được khớp với [picomatch](https://www.npmjs.com/package/picomatch#basic-globbing) so với đường dẫn route, ví dụ `/api/hello`) và có các value là **glob patterns được giải quyết từ project root** chỉ định các tệp để bao gồm hoặc loại trừ trong trace.

> **Nên biết**:
> Trong một monorepo, `project root` đề cập đến Next.js project root (thư mục chứa next.config.js, ví dụ: packages/web-app), không nhất thiết là monorepo root.

```js filename="next.config.js"
module.exports = {
  outputFileTracingExcludes: {
    '/api/hello': ['./un-necessary-folder/**/*'],
  },
  outputFileTracingIncludes: {
    '/api/another': ['./necessary-folder/**/*'],
    '/api/login/\\[\\[\\.\\.\\.slug\\]\\]': [
      './node_modules/aws-crt/dist/bin/**/*',
    ],
  },
}
```

Sử dụng thư mục `src/` không thay đổi cách bạn viết các tùy chọn này:

- **Keys** vẫn khớp với đường dẫn route (`'/api/hello'`, `'/products/[id]'`, v.v.).
- **Values** có thể tham chiếu đến các đường dẫn dưới `src/` vì chúng được giải quyết tương đối với project root.

```js filename="next.config.js"
module.exports = {
  outputFileTracingIncludes: {
    '/products/*': ['src/lib/payments/**/*'],
    '/*': ['src/config/runtime/**/*.json'],
  },
  outputFileTracingExcludes: {
    '/api/*': ['src/temp/**/*', 'public/large-logs/**/*'],
  },
}
```

Bạn cũng có thể nhắm mục tiêu tất cả các routes bằng cách sử dụng một global key như `'/*'`:

```js filename="next.config.js"
module.exports = {
  outputFileTracingIncludes: {
    '/*': ['src/i18n/locales/**/*.json'],
  },
}
```

Các tùy chọn này được áp dụng cho server traces và không ảnh hưởng đến các routes không tạo ra tệp server trace:

- Edge Runtime routes không bị ảnh hưởng.
- Các trang hoàn toàn tĩnh không bị ảnh hưởng.

Trong monorepos hoặc khi bạn cần bao gồm các tệp bên ngoài thư mục app, hãy kết hợp `outputFileTracingRoot` với includes:

```js filename="next.config.js"
const path = require('path')

module.exports = {
  // Trace from the monorepo root
  outputFileTracingRoot: path.join(__dirname, '../../'),
  outputFileTracingIncludes: {
    '/route1': ['../shared/assets/**/*'],
  },
}
```

> **Nên biết**:
>
> - Ưu tiên dấu gạch chéo (`/`) trong các patterns để tương thích đa nền tảng.
> - Giữ các patterns càng hẹp càng tốt để tránh traces quá lớn (tránh `**/*` tại repo root).

Các include patterns phổ biến cho native/runtime assets:

```js filename="next.config.js"
module.exports = {
  outputFileTracingIncludes: {
    '/*': ['node_modules/sharp/**/*', 'node_modules/aws-crt/dist/bin/**/*'],
  },
}
```
