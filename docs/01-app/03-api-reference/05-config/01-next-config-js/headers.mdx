Headers cho phép bạn đặt HTTP headers tùy chỉnh trên phản hồi cho một request đến trên một đường dẫn nhất định.

Để đặt HTTP headers tùy chỉnh bạn có thể sử dụng khóa `headers` trong `next.config.js`:

```js filename="next.config.js"
module.exports = {
  async headers() {
    return [
      {
        source: '/about',
        headers: [
          {
            key: 'x-custom-header',
            value: 'my custom header value',
          },
          {
            key: 'x-another-custom-header',
            value: 'my other custom header value',
          },
        ],
      },
    ]
  },
}
```

`headers` là một hàm async mong đợi trả về một mảng chứa các objects với các thuộc tính `source` và `headers`:

- `source` là mẫu đường dẫn request đến.
- `headers` là một mảng của các objects response header, với các thuộc tính `key` và `value`.
- `basePath`: `false` hoặc `undefined` - nếu false basePath sẽ không được bao gồm khi khớp, chỉ có thể được sử dụng cho external rewrites.
- `locale`: `false` hoặc `undefined` - liệu locale có nên không được bao gồm khi khớp hay không.
- `has` là một mảng của [has objects](#header-cookie-and-query-matching) với các thuộc tính `type`, `key` và `value`.
- `missing` là một mảng của [missing objects](#header-cookie-and-query-matching) với các thuộc tính `type`, `key` và `value`.

Headers được kiểm tra trước hệ thống tệp bao gồm pages và các tệp `/public`.

## Hành vi ghi đè Header

Nếu hai headers khớp với cùng một đường dẫn và đặt cùng một header key, header key cuối cùng sẽ ghi đè cái đầu tiên. Sử dụng các headers bên dưới, đường dẫn `/hello` sẽ dẫn đến header `x-hello` là `world` do giá trị header cuối cùng được đặt là `world`.

```js filename="next.config.js"
module.exports = {
  async headers() {
    return [
      {
        source: '/:path*',
        headers: [
          {
            key: 'x-hello',
            value: 'there',
          },
        ],
      },
      {
        source: '/hello',
        headers: [
          {
            key: 'x-hello',
            value: 'world',
          },
        ],
      },
    ]
  },
}
```

## Path Matching

Khớp đường dẫn được cho phép, ví dụ `/blog/:slug` sẽ khớp `/blog/hello-world` (không có nested paths):

```js filename="next.config.js"
module.exports = {
  async headers() {
    return [
      {
        source: '/blog/:slug',
        headers: [
          {
            key: 'x-slug',
            value: ':slug', // Matched parameters can be used in the value
          },
          {
            key: 'x-slug-:slug', // Matched parameters can be used in the key
            value: 'my other custom header value',
          },
        ],
      },
    ]
  },
}
```

### Wildcard Path Matching

Để khớp một wildcard path bạn có thể sử dụng `*` sau một tham số, ví dụ `/blog/:slug*` sẽ khớp `/blog/a/b/c/d/hello-world`:

```js filename="next.config.js"
module.exports = {
  async headers() {
    return [
      {
        source: '/blog/:slug*',
        headers: [
          {
            key: 'x-slug',
            value: ':slug*', // Matched parameters can be used in the value
          },
          {
            key: 'x-slug-:slug*', // Matched parameters can be used in the key
            value: 'my other custom header value',
          },
        ],
      },
    ]
  },
}
```

### Regex Path Matching

Để khớp một regex path bạn có thể bọc regex trong dấu ngoặc đơn sau một tham số, ví dụ `/blog/:slug(\\d{1,})` sẽ khớp `/blog/123` nhưng không khớp `/blog/abc`:

```js filename="next.config.js"
module.exports = {
  async headers() {
    return [
      {
        source: '/blog/:post(\\d{1,})',
        headers: [
          {
            key: 'x-post',
            value: ':post',
          },
        ],
      },
    ]
  },
}
```

Các ký tự sau `(`, `)`, `{`, `}`, `:`, `*`, `+`, `?` được sử dụng cho regex path matching, vì vậy khi được sử dụng trong `source` như các giá trị không đặc biệt, chúng phải được escape bằng cách thêm `\\` trước chúng:

```js filename="next.config.js"
module.exports = {
  async headers() {
    return [
      {
        // this will match `/english(default)/something` being requested
        source: '/english\\(default\\)/:slug',
        headers: [
          {
            key: 'x-header',
            value: 'value',
          },
        ],
      },
    ]
  },
}
```

## Header, Cookie, và Query Matching

Để chỉ áp dụng một header khi các giá trị header, cookie, hoặc query cũng khớp với trường `has` hoặc không khớp với trường `missing`. Cả `source` và tất cả các mục `has` phải khớp và tất cả các mục `missing` phải không khớp để header được áp dụng.

Các mục `has` và `missing` có thể có các trường sau:

- `type`: `String` - phải là `header`, `cookie`, `host`, hoặc `query`.
- `key`: `String` - key từ loại đã chọn để khớp.
- `value`: `String` hoặc `undefined` - giá trị để kiểm tra, nếu undefined bất kỳ giá trị nào cũng sẽ khớp. Một chuỗi giống regex có thể được sử dụng để bắt một phần cụ thể của giá trị, ví dụ nếu giá trị `first-(?<paramName>.*)` được sử dụng cho `first-second` thì `second` sẽ có thể sử dụng được trong destination với `:paramName`.

```js filename="next.config.js"
module.exports = {
  async headers() {
    return [
      // if the header `x-add-header` is present,
      // the `x-another-header` header will be applied
      {
        source: '/:path*',
        has: [
          {
            type: 'header',
            key: 'x-add-header',
          },
        ],
        headers: [
          {
            key: 'x-another-header',
            value: 'hello',
          },
        ],
      },
      // if the header `x-no-header` is not present,
      // the `x-another-header` header will be applied
      {
        source: '/:path*',
        missing: [
          {
            type: 'header',
            key: 'x-no-header',
          },
        ],
        headers: [
          {
            key: 'x-another-header',
            value: 'hello',
          },
        ],
      },
      // if the source, query, and cookie are matched,
      // the `x-authorized` header will be applied
      {
        source: '/specific/:path*',
        has: [
          {
            type: 'query',
            key: 'page',
            // the page value will not be available in the
            // header key/values since value is provided and
            // doesn't use a named capture group e.g. (?<page>home)
            value: 'home',
          },
          {
            type: 'cookie',
            key: 'authorized',
            value: 'true',
          },
        ],
        headers: [
          {
            key: 'x-authorized',
            value: ':authorized',
          },
        ],
      },
      // if the header `x-authorized` is present and
      // contains a matching value, the `x-another-header` will be applied
      {
        source: '/:path*',
        has: [
          {
            type: 'header',
            key: 'x-authorized',
            value: '(?<authorized>yes|true)',
          },
        ],
        headers: [
          {
            key: 'x-another-header',
            value: ':authorized',
          },
        ],
      },
      // if the host is `example.com`,
      // this header will be applied
      {
        source: '/:path*',
        has: [
          {
            type: 'host',
            value: 'example.com',
          },
        ],
        headers: [
          {
            key: 'x-another-header',
            value: ':authorized',
          },
        ],
      },
    ]
  },
}
```

## Headers với hỗ trợ basePath

Khi tận dụng [hỗ trợ `basePath`](/docs/app/api-reference/config/next-config-js/basePath) với headers mỗi `source` được tự động thêm tiền tố với `basePath` trừ khi bạn thêm `basePath: false` vào header:

```js filename="next.config.js"
module.exports = {
  basePath: '/docs',

  async headers() {
    return [
      {
        source: '/with-basePath', // becomes /docs/with-basePath
        headers: [
          {
            key: 'x-hello',
            value: 'world',
          },
        ],
      },
      {
        source: '/without-basePath', // is not modified since basePath: false is set
        headers: [
          {
            key: 'x-hello',
            value: 'world',
          },
        ],
        basePath: false,
      },
    ]
  },
}
```

## Headers với hỗ trợ i18n

<AppOnly>

Khi tận dụng [hỗ trợ `i18n`](/docs/app/guides/internationalization) với headers mỗi `source` được tự động thêm tiền tố để xử lý các `locales` đã cấu hình trừ khi bạn thêm `locale: false` vào header. Nếu `locale: false` được sử dụng bạn phải thêm tiền tố `source` với một locale để nó được khớp chính xác.

</AppOnly>

<PagesOnly>

Khi tận dụng [hỗ trợ `i18n`](/docs/pages/guides/internationalization) với headers mỗi `source` được tự động thêm tiền tố để xử lý các `locales` đã cấu hình trừ khi bạn thêm `locale: false` vào header. Nếu `locale: false` được sử dụng bạn phải thêm tiền tố `source` với một locale để nó được khớp chính xác.

</PagesOnly>

```js filename="next.config.js"
module.exports = {
  i18n: {
    locales: ['en', 'fr', 'de'],
    defaultLocale: 'en',
  },

  async headers() {
    return [
      {
        source: '/with-locale', // automatically handles all locales
        headers: [
          {
            key: 'x-hello',
            value: 'world',
          },
        ],
      },
      {
        // does not handle locales automatically since locale: false is set
        source: '/nl/with-locale-manual',
        locale: false,
        headers: [
          {
            key: 'x-hello',
            value: 'world',
          },
        ],
      },
      {
        // this matches '/' since `en` is the defaultLocale
        source: '/en',
        locale: false,
        headers: [
          {
            key: 'x-hello',
            value: 'world',
          },
        ],
      },
      {
        // this gets converted to /(en|fr|de)/(.*) so will not match the top-level
        // `/` or `/fr` routes like /:path* would
        source: '/(.*)',
        headers: [
          {
            key: 'x-hello',
            value: 'world',
          },
        ],
      },
    ]
  },
}
```

## Cache-Control

Next.js đặt header `Cache-Control` là `public, max-age=31536000, immutable` cho các tài sản thực sự bất biến (truly immutable assets). Nó không thể bị ghi đè. Các tệp bất biến này chứa một SHA-hash trong tên tệp, vì vậy chúng có thể được cache an toàn vô thời hạn. Ví dụ, [Static Image Imports](/docs/app/getting-started/images#local-images). Bạn không thể đặt headers `Cache-Control` trong `next.config.js` cho các tài sản này.

Tuy nhiên, bạn có thể đặt headers `Cache-Control` cho các phản hồi hoặc dữ liệu khác.

<AppOnly>

Tìm hiểu thêm về [caching](/docs/app/guides/caching) với App Router.

</AppOnly>

<PagesOnly>

Nếu bạn cần revalidate cache của một trang đã được [tạo tĩnh](/docs/pages/building-your-application/rendering/static-site-generation), bạn có thể làm như vậy bằng cách đặt prop `revalidate` trong hàm [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) của trang.

Để cache phản hồi từ một [API Route](/docs/pages/building-your-application/routing/api-routes), bạn có thể sử dụng `res.setHeader`:

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

type ResponseData = {
  message: string
}

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<ResponseData>
) {
  res.setHeader('Cache-Control', 's-maxage=86400')
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

```js filename="pages/api/hello.js" switcher
export default function handler(req, res) {
  res.setHeader('Cache-Control', 's-maxage=86400')
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

Bạn cũng có thể sử dụng caching headers (`Cache-Control`) bên trong `getServerSideProps` để cache các phản hồi động. Ví dụ, sử dụng [`stale-while-revalidate`](https://web.dev/stale-while-revalidate/).

```ts filename="pages/index.tsx" switcher
import { GetStaticProps, GetStaticPaths, GetServerSideProps } from 'next'

// This value is considered fresh for ten seconds (s-maxage=10).
// If a request is repeated within the next 10 seconds, the previously
// cached value will still be fresh. If the request is repeated before 59 seconds,
// the cached value will be stale but still render (stale-while-revalidate=59).
//
// In the background, a revalidation request will be made to populate the cache
// with a fresh value. If you refresh the page, you will see the new value.
export const getServerSideProps = (async (context) => {
  context.res.setHeader(
    'Cache-Control',
    'public, s-maxage=10, stale-while-revalidate=59'
  )

  return {
    props: {},
  }
}) satisfies GetServerSideProps
```

```js filename="pages/index.js" switcher

export async function getServerSideProps({ req, res }) {
```

## Tùy chọn

### CORS

[Cross-Origin Resource Sharing (CORS)](https://developer.mozilla.org/docs/Web/HTTP/CORS) là một tính năng bảo mật cho phép bạn kiểm soát trang web nào có thể truy cập tài nguyên của bạn. Bạn có thể đặt header `Access-Control-Allow-Origin` để cho phép một origin cụ thể truy cập <PagesOnly>API Endpoints</PagesOnly><AppOnly>Route Handlers</AppOnly> của bạn.

```js
async headers() {
    return [
      {
        source: "/api/:path*",
        headers: [
          {
            key: "Access-Control-Allow-Origin",
            value: "*", // Set your origin
          },
          {
            key: "Access-Control-Allow-Methods",
            value: "GET, POST, PUT, DELETE, OPTIONS",
          },
          {
            key: "Access-Control-Allow-Headers",
            value: "Content-Type, Authorization",
          },
        ],
      },
    ];
  },
```

### X-DNS-Prefetch-Control

[Header này](https://developer.mozilla.org/docs/Web/HTTP/Headers/X-DNS-Prefetch-Control) kiểm soát DNS prefetching, cho phép các trình duyệt chủ động thực hiện phân giải tên miền trên các liên kết bên ngoài, hình ảnh, CSS, JavaScript, và nhiều hơn nữa. Việc prefetching này được thực hiện trong nền, vì vậy [DNS](https://developer.mozilla.org/docs/Glossary/DNS) có nhiều khả năng được phân giải vào thời điểm các mục được tham chiếu cần thiết. Điều này làm giảm độ trễ khi người dùng nhấp vào một liên kết.

```js
{
  key: 'X-DNS-Prefetch-Control',
  value: 'on'
}
```

### Strict-Transport-Security

[Header này](https://developer.mozilla.org/docs/Web/HTTP/Headers/Strict-Transport-Security) thông báo cho các trình duyệt rằng nó chỉ nên được truy cập bằng HTTPS, thay vì sử dụng HTTP. Sử dụng cấu hình bên dưới, tất cả các tên miền phụ hiện tại và tương lai sẽ sử dụng HTTPS trong `max-age` là 2 năm. Điều này chặn quyền truy cập vào các trang hoặc tên miền phụ chỉ có thể được phục vụ qua HTTP.

```js
{
  key: 'Strict-Transport-Security',
  value: 'max-age=63072000; includeSubDomains; preload'
}
```

### X-Frame-Options

[Header này](https://developer.mozilla.org/docs/Web/HTTP/Headers/X-Frame-Options) cho biết liệu trang web có được phép hiển thị trong một `iframe` hay không. Điều này có thể ngăn chặn các cuộc tấn công clickjacking.

**Header này đã được thay thế bởi tùy chọn `frame-ancestors` của CSP**, có hỗ trợ tốt hơn trong các trình duyệt hiện đại (xem [Content Security Policy](/docs/app/guides/content-security-policy) để biết chi tiết cấu hình).

```js
{
  key: 'X-Frame-Options',
  value: 'SAMEORIGIN'
}
```

### Permissions-Policy

[Header này](https://developer.mozilla.org/docs/Web/HTTP/Headers/Permissions-Policy) cho phép bạn kiểm soát các tính năng và API nào có thể được sử dụng trong trình duyệt. Trước đây nó được đặt tên là `Feature-Policy`.

```js
{
  key: 'Permissions-Policy',
  value: 'camera=(), microphone=(), geolocation=(), browsing-topics=()'
}
```

### X-Content-Type-Options

[Header này](https://developer.mozilla.org/docs/Web/HTTP/Headers/X-Content-Type-Options) ngăn trình duyệt cố gắng đoán loại nội dung nếu header `Content-Type` không được đặt rõ ràng. Điều này có thể ngăn chặn các khai thác XSS cho các trang web cho phép người dùng tải lên và chia sẻ tệp.

Ví dụ, một người dùng cố gắng tải xuống một hình ảnh, nhưng nó được xử lý như một `Content-Type` khác như một tệp thực thi, điều này có thể độc hại. Header này cũng áp dụng cho việc tải xuống các tiện ích mở rộng trình duyệt. Giá trị hợp lệ duy nhất cho header này là `nosniff`.

```js
{
  key: 'X-Content-Type-Options',
  value: 'nosniff'
}
```

### Referrer-Policy

[Header này](https://developer.mozilla.org/docs/Web/HTTP/Headers/Referrer-Policy) kiểm soát lượng thông tin mà trình duyệt bao gồm khi điều hướng từ trang web hiện tại (origin) sang trang web khác.

```js
{
  key: 'Referrer-Policy',
  value: 'origin-when-cross-origin'
}
```
