Redirects cho phép bạn chuyển hướng một đường dẫn request đến một đường dẫn đích khác.

Để sử dụng redirects bạn có thể sử dụng khóa `redirects` trong `next.config.js`:

```js filename="next.config.js"
module.exports = {
  async redirects() {
    return [
      {
        source: '/about',
        destination: '/',
        permanent: true,
      },
    ]
  },
}
```

`redirects` là một hàm async mong đợi trả về một mảng chứa các objects với các thuộc tính `source`, `destination`, và `permanent`:

- `source` là mẫu đường dẫn request đến.
- `destination` là đường dẫn bạn muốn định tuyến đến.
- `permanent` `true` hoặc `false` - nếu `true` sẽ sử dụng mã trạng thái 308 hướng dẫn clients/search engines cache redirect mãi mãi, nếu `false` sẽ sử dụng mã trạng thái 307 là tạm thời và không được cache.

> **Tại sao Next.js sử dụng 307 và 308?** Theo truyền thống, 302 được sử dụng cho chuyển hướng tạm thời, và 301 cho chuyển hướng vĩnh viễn, nhưng nhiều trình duyệt đã thay đổi phương thức request của chuyển hướng thành `GET`, bất kể phương thức ban đầu. Ví dụ, nếu trình duyệt thực hiện request `POST /v1/users` trả về mã trạng thái `302` với location `/v2/users`, request tiếp theo có thể là `GET /v2/users` thay vì `POST /v2/users` như mong đợi. Next.js sử dụng mã trạng thái chuyển hướng tạm thời 307, và chuyển hướng vĩnh viễn 308 để bảo toàn rõ ràng phương thức request được sử dụng.

- `basePath`: `false` hoặc `undefined` - nếu false `basePath` sẽ không được bao gồm khi khớp, chỉ có thể được sử dụng cho external redirects.
- `locale`: `false` hoặc `undefined` - liệu locale có nên không được bao gồm khi khớp hay không.
- `has` là một mảng của [has objects](#header-cookie-and-query-matching) với các thuộc tính `type`, `key` và `value`.
- `missing` là một mảng của [missing objects](#header-cookie-and-query-matching) với các thuộc tính `type`, `key` và `value`.

Redirects được kiểm tra trước hệ thống tệp bao gồm pages và các tệp `/public`.

Khi sử dụng Pages Router, redirects không được áp dụng cho client-side routing (`Link`, `router.push`) trừ khi [Proxy](/docs/app/api-reference/file-conventions/proxy) hiện diện và khớp với đường dẫn.

Khi một redirect được áp dụng, bất kỳ giá trị query nào được cung cấp trong request sẽ được chuyển qua redirect destination. Ví dụ, xem cấu hình redirect sau:

```js
{
  source: '/old-blog/:path*',
  destination: '/blog/:path*',
  permanent: false
}
```

> **Nên biết**: Hãy nhớ bao gồm dấu gạch chéo `/` trước dấu hai chấm `:` trong các tham số đường dẫn của `source` và `destination`, nếu không đường dẫn sẽ được coi là một chuỗi ký tự và bạn có nguy cơ gây ra vòng lặp chuyển hướng vô hạn.

Khi `/old-blog/post-1?hello=world` được yêu cầu, client sẽ được chuyển hướng đến `/blog/post-1?hello=world`.

## Path Matching

Khớp đường dẫn được cho phép, ví dụ `/old-blog/:slug` sẽ khớp `/old-blog/hello-world` (không có nested paths):

```js filename="next.config.js"
module.exports = {
  async redirects() {
    return [
      {
        source: '/old-blog/:slug',
        destination: '/news/:slug', // Matched parameters can be used in the destination
        permanent: true,
      },
    ]
  },
}
```

### Wildcard Path Matching

Để khớp một wildcard path bạn có thể sử dụng `*` sau một tham số, ví dụ `/blog/:slug*` sẽ khớp `/blog/a/b/c/d/hello-world`:

```js filename="next.config.js"
module.exports = {
  async redirects() {
    return [
      {
        source: '/blog/:slug*',
        destination: '/news/:slug*', // Matched parameters can be used in the destination
        permanent: true,
      },
    ]
  },
}
```

### Regex Path Matching

Để khớp một regex path bạn có thể bọc regex trong dấu ngoặc đơn sau một tham số, ví dụ `/post/:slug(\\d{1,})` sẽ khớp `/post/123` nhưng không khớp `/post/abc`:

```js filename="next.config.js"
module.exports = {
  async redirects() {
    return [
      {
        source: '/post/:slug(\\d{1,})',
        destination: '/news/:slug', // Matched parameters can be used in the destination
        permanent: false,
      },
    ]
  },
}
```

Các ký tự sau `(`, `)`, `{`, `}`, `:`, `*`, `+`, `?` được sử dụng cho regex path matching, vì vậy khi được sử dụng trong `source` như các giá trị không đặc biệt, chúng phải được escape bằng cách thêm `\\` trước chúng:

```js filename="next.config.js"
module.exports = {
  async redirects() {
    return [
      {
        // this will match `/english(default)/something` being requested
        source: '/english\\(default\\)/:slug',
        destination: '/en-us/:slug',
        permanent: false,
      },
    ]
  },
}
```

## Header, Cookie, và Query Matching

Để chỉ khớp một redirect khi các giá trị header, cookie, hoặc query cũng khớp với trường `has` hoặc không khớp với trường `missing`. Cả `source` và tất cả các mục `has` phải khớp và tất cả các mục `missing` phải không khớp để redirect được áp dụng.

Các mục `has` và `missing` có thể có các trường sau:

- `type`: `String` - phải là `header`, `cookie`, `host`, hoặc `query`.
- `key`: `String` - key từ loại đã chọn để khớp.
- `value`: `String` hoặc `undefined` - giá trị để kiểm tra, nếu undefined bất kỳ giá trị nào cũng sẽ khớp. Một chuỗi giống regex có thể được sử dụng để bắt một phần cụ thể của giá trị, ví dụ nếu giá trị `first-(?<paramName>.*)` được sử dụng cho `first-second` thì `second` sẽ có thể sử dụng được trong destination với `:paramName`.

```js filename="next.config.js"
module.exports = {
  async redirects() {
    return [
      // if the header `x-redirect-me` is present,
      // this redirect will be applied
      {
        source: '/:path((?!another-page$).*)',
        has: [
          {
            type: 'header',
            key: 'x-redirect-me',
          },
        ],
        permanent: false,
        destination: '/another-page',
      },
      // if the header `x-dont-redirect` is present,
      // this redirect will NOT be applied
      {
        source: '/:path((?!another-page$).*)',
        missing: [
          {
            type: 'header',
            key: 'x-do-not-redirect',
          },
        ],
        permanent: false,
        destination: '/another-page',
      },
      // if the source, query, and cookie are matched,
      // this redirect will be applied
      {
        source: '/specific/:path*',
        has: [
          {
            type: 'query',
            key: 'page',
            // the page value will not be available in the
            // destination since value is provided and doesn't
            // use a named capture group e.g. (?<page>home)
            value: 'home',
          },
          {
            type: 'cookie',
            key: 'authorized',
            value: 'true',
          },
        ],
        permanent: false,
        destination: '/another/:path*',
      },
      // if the header `x-authorized` is present and
      // contains a matching value, this redirect will be applied
      {
        source: '/',
        has: [
          {
            type: 'header',
            key: 'x-authorized',
            value: '(?<authorized>yes|true)',
          },
        ],
        permanent: false,
        destination: '/home?authorized=:authorized',
      },
      // if the host is `example.com`,
      // this redirect will be applied
      {
        source: '/:path((?!another-page$).*)',
        has: [
          {
            type: 'host',
            value: 'example.com',
          },
        ],
        permanent: false,
        destination: '/another-page',
      },
    ]
  },
}
```

### Redirects với hỗ trợ basePath

Khi tận dụng [hỗ trợ `basePath`](/docs/app/api-reference/config/next-config-js/basePath) với redirects mỗi `source` và `destination` được tự động thêm tiền tố với `basePath` trừ khi bạn thêm `basePath: false` vào redirect:

```js filename="next.config.js"
module.exports = {
  basePath: '/docs',

  async redirects() {
    return [
      {
        source: '/with-basePath', // automatically becomes /docs/with-basePath
        destination: '/another', // automatically becomes /docs/another
        permanent: false,
      },
      {
        // does not add /docs since basePath: false is set
        source: '/without-basePath',
        destination: 'https://example.com',
        basePath: false,
        permanent: false,
      },
    ]
  },
}
```

### Redirects với hỗ trợ i18n

<AppOnly>

Khi triển khai redirects với quốc tế hóa (internationalization) trong App Router, bạn có thể bao gồm locales trong redirects của `next.config.js`, nhưng chỉ dưới dạng các đường dẫn được mã hóa cứng (hardcoded).

Để xử lý locale động hoặc theo yêu cầu, hãy sử dụng [dynamic route segments và proxy](/docs/app/guides/internationalization), có thể chuyển hướng dựa trên ngôn ngữ ưa thích của người dùng.

```js filename="next.config.js"
module.exports = {
  async redirects() {
    return [
      {
        // Manually handle locale prefixes for App Router
        source: '/en/old-path',
        destination: '/en/new-path',
        permanent: false,
      },
      {
        // Redirect for all locales using a parameter
        source: '/:locale/old-path',
        destination: '/:locale/new-path',
        permanent: false,
      },
      {
        // Redirect from one locale to another
        source: '/de/old-path',
        destination: '/en/new-path',
        permanent: false,
      },
      {
        // Catch-all redirect for multiple locales
        source: '/:locale(en|fr|de)/:path*',
        destination: '/:locale/new-section/:path*',
        permanent: false,
      },
    ]
  },
}
```

</AppOnly>

<PagesOnly>

Khi tận dụng [hỗ trợ `i18n`](/docs/pages/guides/internationalization) với redirects mỗi `source` và `destination` được tự động thêm tiền tố để xử lý các `locales` đã cấu hình trừ khi bạn thêm `locale: false` vào redirect. Nếu `locale: false` được sử dụng bạn phải thêm tiền tố `source` và `destination` với một locale để nó được khớp chính xác.

```js filename="next.config.js"
module.exports = {
  i18n: {
    locales: ['en', 'fr', 'de'],
    defaultLocale: 'en',
  },

  async redirects() {
    return [
      {
        source: '/with-locale', // automatically handles all locales
        destination: '/another', // automatically passes the locale on
        permanent: false,
      },
      {
        // does not handle locales automatically since locale: false is set
        source: '/nl/with-locale-manual',
        destination: '/nl/another',
        locale: false,
        permanent: false,
      },
      {
        // this matches '/' since `en` is the defaultLocale
        source: '/en',
        destination: '/en/another',
        locale: false,
        permanent: false,
      },
      // it's possible to match all locales even when locale: false is set
      {
        source: '/:locale/page',
        destination: '/en/newpage',
        permanent: false,
        locale: false,
      },
      {
        // this gets converted to /(en|fr|de)/(.*) so will not match the top-level
        // `/` or `/fr` routes like /:path* would
        source: '/(.*)',
        destination: '/another',
        permanent: false,
      },
    ]
  },
}
```

</PagesOnly>

Trong một số trường hợp hiếm hoi, bạn có thể cần gán một mã trạng thái tùy chỉnh cho các HTTP Clients cũ hơn để chuyển hướng đúng cách. Trong những trường hợp này, bạn có thể sử dụng thuộc tính `statusCode` thay vì thuộc tính `permanent`, nhưng không phải cả hai. Để đảm bảo khả năng tương thích với IE11, header `Refresh` được tự động thêm cho mã trạng thái 308.

## Các Redirects khác

- Bên trong [API Routes](/docs/pages/building-your-application/routing/api-routes) và [Route Handlers](/docs/app/api-reference/file-conventions/route), bạn có thể chuyển hướng dựa trên request đến.
- Bên trong [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) và [`getServerSideProps`](/docs/pages/building-your-application/data-fetching/get-server-side-props), bạn có thể chuyển hướng các trang cụ thể tại thời điểm request.
