> Tính năng này là độc quyền cho `next export` và hiện tại **deprecated** để ủng hộ `getStaticPaths` với `pages` hoặc `generateStaticParams` với `app`.

`exportPathMap` cho phép bạn chỉ định một mapping của request paths đến page destinations, sẽ được sử dụng trong quá trình export. Các paths được định nghĩa trong `exportPathMap` cũng sẽ có sẵn khi sử dụng [`next dev`](/docs/app/api-reference/cli/next#next-dev-options).

Hãy bắt đầu với một ví dụ, để tạo một `exportPathMap` tùy chỉnh cho một ứng dụng với các trang sau:

- `pages/index.js`
- `pages/about.js`
- `pages/post.js`

Mở `next.config.js` và thêm cấu hình `exportPathMap` sau:

```js filename="next.config.js"
module.exports = {
  exportPathMap: async function (
    defaultPathMap,
    { dev, dir, outDir, distDir, buildId }
  ) {
    return {
      '/': { page: '/' },
      '/about': { page: '/about' },
      '/p/hello-nextjs': { page: '/post', query: { title: 'hello-nextjs' } },
      '/p/learn-nextjs': { page: '/post', query: { title: 'learn-nextjs' } },
      '/p/deploy-nextjs': { page: '/post', query: { title: 'deploy-nextjs' } },
    }
  },
}
```

> **Nên biết**: trường `query` trong `exportPathMap` không thể được sử dụng với [các trang được tối ưu hóa tĩnh tự động](/docs/pages/building-your-application/rendering/automatic-static-optimization) hoặc [các trang `getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) vì chúng được render thành các tệp HTML tại thời điểm build và thông tin query bổ sung không thể được cung cấp trong quá trình `next export`.

Các trang sau đó sẽ được export dưới dạng các tệp HTML, ví dụ, `/about` sẽ trở thành `/about.html`.

`exportPathMap` là một hàm `async` nhận 2 tham số: tham số đầu tiên là `defaultPathMap`, là map mặc định được sử dụng bởi Next.js. Tham số thứ hai là một đối tượng với:

- `dev` - `true` khi `exportPathMap` được gọi trong development. `false` khi chạy `next export`. Trong development `exportPathMap` được sử dụng để định nghĩa routes.
- `dir` - Đường dẫn tuyệt đối đến thư mục dự án
- `outDir` - Đường dẫn tuyệt đối đến thư mục `out/` ([có thể cấu hình với `-o`](#customizing-the-output-directory)). Khi `dev` là `true` giá trị của `outDir` sẽ là `null`.
- `distDir` - Đường dẫn tuyệt đối đến thư mục `.next/` (có thể cấu hình với cấu hình [`distDir`](/docs/pages/api-reference/config/next-config-js/distDir))
- `buildId` - Build id được tạo

Đối tượng được trả về là một map của các trang trong đó `key` là `pathname` và `value` là một đối tượng chấp nhận các trường sau:

- `page`: `String` - trang bên trong thư mục `pages` để render
- `query`: `Object` - đối tượng `query` được truyền đến `getInitialProps` khi prerendering. Mặc định là `{}`

> `pathname` được export cũng có thể là một filename (ví dụ, `/readme.md`), nhưng bạn có thể cần đặt header `Content-Type` thành `text/html` khi phục vụ nội dung của nó nếu nó khác với `.html`.

## Thêm trailing slash

Có thể cấu hình Next.js để export các trang dưới dạng các tệp `index.html` và yêu cầu trailing slashes, `/about` trở thành `/about/index.html` và có thể route thông qua `/about/`. Đây là hành vi mặc định trước Next.js 9.

Để chuyển lại và thêm một trailing slash, hãy mở `next.config.js` và kích hoạt cấu hình `trailingSlash`:

```js filename="next.config.js"
module.exports = {
  trailingSlash: true,
}
```

## Tùy chỉnh thư mục output

<AppOnly>

[`next export`](/docs/app/guides/static-exports) sẽ sử dụng `out` làm thư mục output mặc định, bạn có thể tùy chỉnh điều này bằng cách sử dụng tham số `-o`, như sau:

</AppOnly>

<PagesOnly>

[`next export`](/docs/pages/guides/static-exports) sẽ sử dụng `out` làm thư mục output mặc định, bạn có thể tùy chỉnh điều này bằng cách sử dụng tham số `-o`, như sau:

</PagesOnly>

```bash filename="Terminal"
next export -o outdir
```

> **Cảnh báo**: Sử dụng `exportPathMap` đã bị deprecated và bị ghi đè bởi `getStaticPaths` bên trong `pages`. Chúng tôi không khuyến nghị sử dụng chúng cùng nhau.
