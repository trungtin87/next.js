## Sử dụng

Tùy chọn `taint` cho phép hỗ trợ các React APIs thử nghiệm để tainting objects và values. Tính năng này giúp ngăn chặn dữ liệu nhạy cảm vô tình bị truyền xuống client. Khi được kích hoạt, bạn có thể sử dụng:

- [`experimental_taintObjectReference`](https://react.dev/reference/react/experimental_taintObjectReference) để taint objects references.
- [`experimental_taintUniqueValue`](https://react.dev/reference/react/experimental_taintUniqueValue) để taint unique values.

> **Nên biết**: Kích hoạt cờ này cũng kích hoạt React `experimental` channel cho thư mục `app`.

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    taint: true,
  },
}

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    taint: true,
  },
}

module.exports = nextConfig
```

> **Cảnh báo:** Đừng dựa vào taint API như cơ chế duy nhất của bạn để ngăn chặn việc để lộ dữ liệu nhạy cảm cho client. Xem [khuyến nghị bảo mật](/blog/security-nextjs-server-components-actions) của chúng tôi.

Các taint APIs cho phép bạn phòng thủ, bằng cách đánh dấu khai báo và rõ ràng dữ liệu không được phép đi qua ranh giới Server-Client. Khi một object hoặc value, được truyền qua ranh giới Server-Client, React sẽ ném ra một lỗi.

Điều này hữu ích cho các trường hợp:

- Các phương thức để đọc dữ liệu nằm ngoài tầm kiểm soát của bạn
- Bạn phải làm việc với các hình dạng dữ liệu nhạy cảm không được định nghĩa bởi bạn
- Dữ liệu nhạy cảm được truy cập trong quá trình render Server Component

Khuyến nghị mô hình hóa dữ liệu và APIs của bạn sao cho dữ liệu nhạy cảm không được trả về các contexts nơi nó không cần thiết.

## Caveats

- Tainting chỉ có thể theo dõi các objects theo tham chiếu (reference). Sao chép một object tạo ra một phiên bản untainted, làm mất tất cả các đảm bảo được đưa ra bởi API. Bạn sẽ cần phải taint bản sao.
- Tainting không thể theo dõi dữ liệu được dẫn xuất từ một tainted value. Bạn cũng cần phải taint giá trị được dẫn xuất.
- Values được tainted miễn là tham chiếu vòng đời của chúng nằm trong phạm vi. Xem [`experimental_taintUniqueValue` parameters reference](https://react.dev/reference/react/experimental_taintUniqueValue#parameters), để biết thêm thông tin.

## Ví dụ

### Tainting một object reference

Trong trường hợp này, hàm `getUserDetails` trả về dữ liệu về một người dùng nhất định. Chúng ta taint tham chiếu user object, để nó không thể vượt qua ranh giới Server-Client. Ví dụ, giả sử `UserCard` là một Client Component.

```ts switcher
import { experimental_taintObjectReference } from 'react'

function getUserDetails(id: string): UserDetails {
  const user = await db.queryUserById(id)

  experimental_taintObjectReference(
    'Do not use the entire user info object. Instead, select only the fields you need.',
    user
  )

  return user
}
```

```js switcher
import { experimental_taintObjectReference } from 'react'

function getUserDetails(id) {
  const user = await db.queryUserById(id)

  experimental_taintObjectReference(
    'Do not use the entire user info object. Instead, select only the fields you need.',
    user
  )

  return user
}
```

Chúng ta vẫn có thể truy cập các trường riêng lẻ từ object `userDetails` đã bị tainted.

```tsx filename="app/contact/page.tsx switcher
export async function ContactPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const userDetails = await getUserDetails(id)

  return (
    <UserCard
      firstName={userDetails.firstName}
      lastName={userDetails.lastName}
    />
  )
}
```

```jsx filename="app/contact/page.js switcher
export async function ContactPage({ params }) {
  const { id } = await params
  const userDetails = await getUserDetails(id)

  return (
    <UserCard
      firstName={userDetails.firstName}
      lastName={userDetails.lastName}
    />
  )
}
```

Bây giờ, việc truyền toàn bộ object cho Client Component sẽ ném ra một lỗi.

```tsx switcher
export async function ContactPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const userDetails = await getUserDetails(id)

  // Throws an error
  return <UserCard user={userDetails} />
}
```

### Tainting một unique value

Trong trường hợp này, chúng ta có thể truy cập cấu hình server bằng cách awaiting các cuộc gọi đến `config.getConfigDetails`. Tuy nhiên, cấu hình hệ thống chứa `SERVICE_API_KEY` mà chúng ta không muốn để lộ cho clients.

Chúng ta có thể taint giá trị `config.SERVICE_API_KEY`.

```ts switcher
import { experimental_taintUniqueValue } from 'react'

function getSystemConfig(): SystemConfig {
  const config = await config.getConfigDetails()

  experimental_taintUniqueValue(
    'Do not pass configuration tokens to the client',
    config,
    config.SERVICE_API_KEY
  )

  return config
}
```

```js switcher
import { experimental_taintUniqueValue } from 'react'

function getSystemConfig() {
  const config = await config.getConfigDetails()

  experimental_taintUniqueValue(
    'Do not pass configuration tokens to the client',
    config,
    config.SERVICE_API_KEY
  )

  return config
}
```

Chúng ta vẫn có thể truy cập các thuộc tính khác của object `systemConfig`.

```tsx
export async function Dashboard() {
  const systemConfig = await getSystemConfig()

  return <ClientDashboard version={systemConfig.SERVICE_API_VERSION} />
}
```

Tuy nhiên, việc truyền `SERVICE_API_KEY` cho `ClientDashboard` sẽ ném ra một lỗi.

```tsx
export async function Dashboard() {
  const systemConfig = await getSystemConfig()
  // Someone makes a mistake in a PR
  const version = systemConfig.SERVICE_API_KEY

  return <ClientDashboard version={version} />
}
```

Lưu ý rằng, ngay cả khi `systemConfig.SERVICE_API_KEY` được gán lại cho một biến mới. Việc truyền nó cho một Client Component vẫn ném ra một lỗi.

Trong khi đó, một giá trị được dẫn xuất từ một tainted unique value, sẽ bị lộ cho client.

```tsx
export async function Dashboard() {
  const systemConfig = await getSystemConfig()
  // Someone makes a mistake in a PR
  const version = `version::${systemConfig.SERVICE_API_KEY}`

  return <ClientDashboard version={version} />
}
```

Một cách tiếp cận tốt hơn là loại bỏ `SERVICE_API_KEY` khỏi dữ liệu được trả về bởi `getSystemConfig`.
