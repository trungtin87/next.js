Bạn có thể cấu hình vị trí cache Next.js nếu bạn muốn persist các cached pages và dữ liệu vào durable storage, hoặc chia sẻ cache trên nhiều containers hoặc instances của ứng dụng Next.js của bạn.

> **Nên biết**: Cấu hình `cacheHandler` được sử dụng cụ thể bởi Next.js cho các hoạt động server cache như lưu trữ và revalidate ISR và route handler responses. Nó không được sử dụng bởi `'use cache'`, `'use cache: remote'`, cũng như `'use cache: private'`, chúng quản lý cache của riêng chúng một cách độc lập.

```js filename="next.config.js"
module.exports = {
  cacheHandler: require.resolve('./cache-handler.js'),
  cacheMaxMemorySize: 0, // disable default in-memory caching
}
```

Xem một ví dụ về [custom cache handler](/docs/app/guides/self-hosting#configuring-caching) và tìm hiểu thêm về implementation.

## Tham khảo API

Cache handler có thể triển khai các phương thức sau: `get`, `set`, `revalidateTag`, và `resetRequestCache`.

### `get()`

| Tham số | Kiểu     | Mô tả                       |
| ------- | -------- | --------------------------- |
| `key`   | `string` | Key đến giá trị được cache. |

Trả về giá trị được cache hoặc `null` nếu không tìm thấy.

### `set()`

| Tham số | Kiểu             | Mô tả                         |
| ------- | ---------------- | ----------------------------- |
| `key`   | `string`         | Key để lưu trữ dữ liệu dưới.  |
| `data`  | Data hoặc `null` | Dữ liệu sẽ được cache.        |
| `ctx`   | `{ tags: [] }`   | Các cache tags được cung cấp. |

Trả về `Promise<void>`.

### `revalidateTag()`

| Tham số | Kiểu                     | Mô tả                         |
| ------- | ------------------------ | ----------------------------- |
| `tag`   | `string` hoặc `string[]` | Các cache tags để revalidate. |

Trả về `Promise<void>`. Tìm hiểu thêm về [revalidating data](/docs/app/guides/incremental-static-regeneration) hoặc hàm [`revalidateTag()`](/docs/app/api-reference/functions/revalidateTag).

### `resetRequestCache()`

Phương thức này reset cache in-memory tạm thời cho một request duy nhất trước request tiếp theo.

Trả về `void`.

**Nên biết:**

- `revalidatePath` là một convenience layer trên các cache tags. Gọi `revalidatePath` sẽ gọi hàm `revalidateTag` của bạn, sau đó bạn có thể chọn nếu bạn muốn tag các cache keys dựa trên path.
