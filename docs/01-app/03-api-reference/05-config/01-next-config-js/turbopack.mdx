Tùy chọn `turbopack` cho phép bạn tùy chỉnh [Turbopack](/docs/app/api-reference/turbopack) để chuyển đổi các file khác nhau và thay đổi cách các module được resolve.

> **Cần biết**: Tùy chọn `turbopack` trước đây có tên là `experimental.turbo` trong các phiên bản Next.js từ 13.0.0 đến 15.2.x. Tùy chọn `experimental.turbo` sẽ bị xóa trong Next.js 16.
>
> Nếu bạn đang sử dụng phiên bản cũ hơn của Next.js, hãy chạy `npx @next/codemod@latest next-experimental-turbo-to-turbopack .` để tự động di chuyển cấu hình của bạn.

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  turbopack: {
    // ...
  },
}

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  turbopack: {
    // ...
  },
}

module.exports = nextConfig
```

> **Cần biết**:
>
> - Turbopack cho Next.js không yêu cầu loaders hoặc cấu hình loader cho chức năng tích hợp sẵn. Turbopack có hỗ trợ tích hợp sẵn cho CSS và biên dịch JavaScript hiện đại, vì vậy không cần `css-loader`, `postcss-loader`, hoặc `babel-loader` nếu bạn đang sử dụng `@babel/preset-env`.

## Tham khảo

### Tùy chọn

Các tùy chọn sau có sẵn cho cấu hình `turbopack`:

| Tùy chọn            | Mô tả                                                                                                                               |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `root`              | Đặt thư mục gốc của ứng dụng. Phải là một đường dẫn tuyệt đối.                                                                      |
| `rules`             | Danh sách các webpack loaders được hỗ trợ để áp dụng khi chạy với Turbopack.                                                        |
| `resolveAlias`      | Map các import được alias tới các module để load thay thế.                                                                          |
| `resolveExtensions` | Danh sách các phần mở rộng để resolve khi import files.                                                                             |
| `debugIds`          | Kích hoạt tạo [debug IDs](https://github.com/tc39/ecma426/blob/main/proposals/debug-id.md) trong JavaScript bundles và source maps. |

### Các loader được hỗ trợ

Các loader sau đã được kiểm tra để hoạt động với việc triển khai webpack loader của Turbopack, nhưng nhiều webpack loader khác cũng có thể hoạt động tốt ngay cả khi không được liệt kê ở đây:

- [`babel-loader`](https://www.npmjs.com/package/babel-loader) [_(Được cấu hình tự động nếu tìm thấy file cấu hình Babel)_](/docs/app/api-reference/turbopack#language-features)
- [`@svgr/webpack`](https://www.npmjs.com/package/@svgr/webpack)
- [`svg-inline-loader`](https://www.npmjs.com/package/svg-inline-loader)
- [`yaml-loader`](https://www.npmjs.com/package/yaml-loader)
- [`string-replace-loader`](https://www.npmjs.com/package/string-replace-loader)
- [`raw-loader`](https://www.npmjs.com/package/raw-loader)
- [`sass-loader`](https://www.npmjs.com/package/sass-loader) [_(Được cấu hình tự động)_](/docs/app/api-reference/turbopack#css-and-styling)
- [`graphql-tag/loader`](https://www.npmjs.com/package/graphql-tag)

#### Các tính năng Webpack loader còn thiếu

Turbopack sử dụng thư viện [`loader-runner`](https://github.com/webpack/loader-runner) để thực thi các webpack loaders, cung cấp hầu hết các API loader tiêu chuẩn. Tuy nhiên, một số tính năng không được hỗ trợ:

**Module loading:**

- [`importModule`](https://webpack.js.org/api/loaders/#thisimportmodule) - Không hỗ trợ
- [`loadModule`](https://webpack.js.org/api/loaders/#thisloadmodule) - Không hỗ trợ

**File system và output:**

- [`fs`](https://webpack.js.org/api/loaders/#thisfs) - Hỗ trợ một phần: chỉ `fs.readFile` hiện được triển khai.
- [`emitFile`](https://webpack.js.org/api/loaders/#thisemitfile) - Không hỗ trợ

**Context properties:**

- [`version`](https://webpack.js.org/api/loaders/#thisversion) - Không hỗ trợ
- [`mode`](https://webpack.js.org/api/loaders/#thismode) - Không hỗ trợ
- [`target`](https://webpack.js.org/api/loaders/#thistarget) - Không hỗ trợ

**Utilities:**

- [`utils`](https://webpack.js.org/api/loaders/#thisutils) - Không hỗ trợ
- [`resolve`](https://webpack.js.org/api/loaders/#thisresolve) - Không hỗ trợ (sử dụng [`getResolve`](https://webpack.js.org/api/loaders/#thisgetresolve) thay thế)

Nếu bạn có một loader phụ thuộc nghiêm trọng vào một trong những tính năng này, vui lòng gửi một issue.

## Ví dụ

### Thư mục gốc (Root directory)

Turbopack sử dụng thư mục gốc để resolve các modules. Các file bên ngoài project root không được resolve.

Next.js tự động phát hiện thư mục gốc của dự án của bạn. Nó thực hiện điều này bằng cách tìm kiếm một trong các file sau:

- `pnpm-lock.yaml`
- `package-lock.json`
- `yarn.lock`
- `bun.lock`
- `bun.lockb`

Nếu bạn có cấu trúc dự án khác, ví dụ nếu bạn không sử dụng workspaces, bạn có thể thiết lập thủ công tùy chọn `root`:

```js filename="next.config.js"
const path = require('path')
module.exports = {
  turbopack: {
    root: path.join(__dirname, '..'),
  },
}
```

### Cấu hình webpack loaders

Nếu bạn cần hỗ trợ loader ngoài những gì được tích hợp sẵn, nhiều webpack loaders đã hoạt động với Turbopack. Hiện tại có một số hạn chế:

- Chỉ một tập hợp con cốt lõi của webpack loader API được triển khai. Hiện tại, có đủ độ bao phủ cho một số loaders phổ biến, và chúng tôi sẽ mở rộng hỗ trợ API của mình trong tương lai.
- Chỉ các loaders trả về mã JavaScript được hỗ trợ. Các loaders chuyển đổi file như stylesheets hoặc images hiện không được hỗ trợ.
- Các tùy chọn được truyền cho webpack loaders phải là các kiểu dữ liệu nguyên thủy (primitives), objects, và arrays JavaScript thuần túy. Ví dụ, không thể truyền các module plugin `require()` làm giá trị tùy chọn.

Để cấu hình loaders, thêm tên của các loaders bạn đã cài đặt và bất kỳ tùy chọn nào trong `next.config.js`, ánh xạ phần mở rộng file tới danh sách các loaders. Các quy tắc (rules) được đánh giá theo thứ tự.

Dưới đây là một ví dụ sử dụng loader [`@svgr/webpack`](https://www.npmjs.com/package/@svgr/webpack), cho phép import các file `.svg` và render chúng như các React components.

```js filename="next.config.js"
module.exports = {
  turbopack: {
    rules: {
      '*.svg': {
        loaders: ['@svgr/webpack'],
        as: '*.js',
      },
    },
  },
}
```

> **Cần biết**: Các globs được sử dụng trong object `rules` khớp dựa trên tên file, trừ khi glob chứa ký tự `/`, điều này sẽ khiến nó khớp dựa trên đường dẫn file đầy đủ tương đối với dự án. Các đường dẫn file Windows được chuẩn hóa để sử dụng dấu phân cách đường dẫn kiểu unix `/`.
>
> Turbopack sử dụng phiên bản sửa đổi của [thư viện Rust `globset`](https://docs.rs/globset/latest/globset/).

Đối với các loaders yêu cầu các tùy chọn cấu hình, bạn có thể sử dụng định dạng object thay vì string:

```js filename="next.config.js"
module.exports = {
  turbopack: {
    rules: {
      '*.svg': {
        loaders: [
          {
            loader: '@svgr/webpack',
            options: {
              icon: true,
            },
          },
        ],
        as: '*.js',
      },
    },
  },
}
```

> **Cần biết**: Trước phiên bản Next.js 13.4.4, `turbopack.rules` có tên là `turbo.loaders` và chỉ chấp nhận các phần mở rộng file như `.mdx` thay vì `*.mdx`.

### Các điều kiện webpack loader nâng cao

Bạn có thể hạn chế thêm nơi một loader chạy bằng cách sử dụng cú pháp `condition` nâng cao:

```js filename="next.config.js"
module.exports = {
  turbopack: {
    rules: {
      // '*' will match all file paths, but we restrict where our
      // rule runs with a condition.
      '*': {
        condition: {
          all: [
            // 'foreign' is a built-in condition.
            { not: 'foreign' },
            // 'path' can be a RegExp or a glob string. A RegExp matches
            // anywhere in the full project-relative file path.
            { path: /^img\/[0-9]{3}\// },
            {
              any: [
                { path: '*.svg' },
                // 'content' is always a RegExp, and can match
                // anywhere in the file.
                { content: /\<svg\W/ },
              ],
            },
          ],
        },
        loaders: ['@svgr/webpack'],
        as: '*.js',
      },
    },
  },
}
```

- Các toán tử boolean được hỗ trợ là `{all: [...]}`, `{any: [...]}` và `{not: ...}`.
- Các toán tử tùy chỉnh được hỗ trợ là `{path: string | RegExp}` và `{content: RegExp}`. Nếu `path` và `content` được chỉ định trong cùng một object, nó hoạt động như một `and` ngầm định.

Ngoài ra, một số điều kiện tích hợp sẵn được hỗ trợ:

- `browser`: Khớp mã sẽ thực thi trên client. Mã server có thể được khớp bằng cách sử dụng `{not: 'browser'}`.
- `foreign`: Khớp mã trong `node_modules`, cũng như một số nội bộ của Next.js. Thông thường bạn sẽ muốn hạn chế loaders với `{not: 'foreign'}`. Điều này có thể cải thiện hiệu suất bằng cách giảm số lượng file mà loader được gọi trên đó.
- `development`: Khớp khi sử dụng `next dev`.
- `production`: Khớp khi sử dụng `next build`.
- `node`: Khớp mã sẽ chạy trên runtime Node.js mặc định.
- `edge-light`: Khớp mã sẽ chạy trên [Edge runtime](/docs/app/api-reference/edge).

Rules có thể là một object hoặc một mảng các objects. Một mảng thường hữu ích để mô hình hóa các điều kiện rời rạc:

```js filename="next.config.js"
module.exports = {
  turbopack: {
    rules: {
      '*.svg': [
        {
          condition: 'browser',
          loaders: ['@svgr/webpack'],
          as: '*.js',
        },
        {
          condition: { not: 'browser' },
          loaders: [require.resolve('./custom-svg-loader.js')],
          as: '*.js',
        },
      ],
    },
  },
}
```

> **Cần biết**: Tất cả các quy tắc khớp được thực thi theo thứ tự.

### Resolving aliases

Turbopack có thể được cấu hình để sửa đổi việc resolve module thông qua aliases, tương tự như cấu hình [`resolve.alias`](https://webpack.js.org/configuration/resolve/#resolvealias) của webpack.

Để cấu hình resolve aliases, ánh xạ các patterns được import tới đích đến mới của chúng trong `next.config.js`:

```js filename="next.config.js"
module.exports = {
  turbopack: {
    resolveAlias: {
      underscore: 'lodash',
      mocha: { browser: 'mocha/browser-entry.js' },
    },
  },
}
```

Điều này alias các import của gói `underscore` tới gói `lodash`. Nói cách khác, `import underscore from 'underscore'` sẽ load module `lodash` thay vì `underscore`.

Turbopack cũng hỗ trợ aliasing có điều kiện thông qua trường này, tương tự như [conditional exports](https://nodejs.org/docs/latest-v18.x/api/packages.html#conditional-exports) của Node.js. Hiện tại chỉ điều kiện `browser` được hỗ trợ. Trong trường hợp trên, các import của module `mocha` sẽ được alias tới `mocha/browser-entry.js` khi Turbopack nhắm mục tiêu môi trường browser.

### Resolving custom extensions

Turbopack có thể được cấu hình để resolve các modules với các phần mở rộng tùy chỉnh, tương tự như cấu hình [`resolve.extensions`](https://webpack.js.org/configuration/resolve/#resolveextensions) của webpack.

Để cấu hình resolve extensions, sử dụng trường `resolveExtensions` trong `next.config.js`:

```js filename="next.config.js"
module.exports = {
  turbopack: {
    resolveExtensions: ['.mdx', '.tsx', '.ts', '.jsx', '.js', '.mjs', '.json'],
  },
}
```

Điều này ghi đè các resolve extensions ban đầu bằng danh sách được cung cấp. Hãy chắc chắn bao gồm các phần mở rộng mặc định.

Để biết thêm thông tin và hướng dẫn về cách di chuyển ứng dụng của bạn sang Turbopack từ webpack, xem [tài liệu của Turbopack về khả năng tương thích webpack](https://turbo.build/pack/docs/migrating-from-webpack).

### Debug IDs

Turbopack có thể được cấu hình để tạo [debug IDs](https://github.com/tc39/ecma426/blob/main/proposals/debug-id.md) trong JavaScript bundles và source maps.

Để cấu hình debug IDs, sử dụng trường `debugIds` trong `next.config.js`:

```js filename="next.config.js"
module.exports = {
  turbopack: {
    debugIds: true,
  },
}
```

Tùy chọn này tự động thêm một polyfill cho debug IDs vào JavaScript bundle để đảm bảo khả năng tương thích. Các debug IDs có sẵn trong biến toàn cục `globalThis._debugIds`.
