CSS Chunking là một chiến lược được sử dụng để cải thiện hiệu suất của ứng dụng web của bạn bằng cách chia và sắp xếp lại các tệp CSS thành các chunk. Điều này cho phép bạn chỉ tải CSS cần thiết cho một route cụ thể, thay vì tải tất cả CSS của ứng dụng cùng một lúc.

Bạn có thể kiểm soát cách các tệp CSS được chia thành chunk bằng cách sử dụng tùy chọn `experimental.cssChunking` trong tệp `next.config.js` của bạn:

```tsx filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig = {
  experimental: {
    cssChunking: true, // mặc định
  },
} satisfies NextConfig

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    cssChunking: true, // mặc định
  },
}

module.exports = nextConfig
```

## Tùy chọn

- **`true` (mặc định)**: Next.js sẽ cố gắng merge các tệp CSS bất cứ khi nào có thể, xác định các phụ thuộc rõ ràng và ngầm định giữa các tệp từ thứ tự import để giảm số lượng chunk và do đó giảm số lượng yêu cầu.
- **`false`**: Next.js sẽ không cố gắng merge hoặc sắp xếp lại các tệp CSS của bạn.
- **`'strict'`**: Next.js sẽ tải các tệp CSS theo đúng thứ tự chúng được import vào các tệp của bạn, điều này có thể dẫn đến nhiều chunk và yêu cầu hơn.

Bạn có thể cân nhắc sử dụng `'strict'` nếu bạn gặp phải hành vi CSS không mong muốn. Ví dụ, nếu bạn import `a.css` và `b.css` trong các tệp khác nhau bằng cách sử dụng thứ tự `import` khác nhau (`a` trước `b`, hoặc `b` trước `a`), `true` sẽ merge các tệp theo bất kỳ thứ tự nào và giả định không có phụ thuộc giữa chúng. Tuy nhiên, nếu `b.css` phụ thuộc vào `a.css`, bạn có thể muốn sử dụng `'strict'` để ngăn các tệp bị merge, và thay vào đó, tải chúng theo thứ tự chúng được import - điều này có thể dẫn đến nhiều chunk và yêu cầu hơn.

Đối với hầu hết các ứng dụng, chúng tôi khuyên bạn nên sử dụng `true` vì nó dẫn đến ít yêu cầu hơn và hiệu suất tốt hơn.
