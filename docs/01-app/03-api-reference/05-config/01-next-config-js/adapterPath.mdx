---

Next.js cung cấp một API thử nghiệm cho phép bạn tạo các adapter tùy chỉnh để hook vào quá trình build. Điều này hữu ích cho các nền tảng triển khai hoặc tích hợp build tùy chỉnh cần sửa đổi cấu hình Next.js hoặc xử lý output của build.

## Cấu hình

Để sử dụng một adapter, hãy chỉ định đường dẫn đến module adapter của bạn trong `experimental.adapterPath`:

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    adapterPath: require.resolve('./my-adapter.js'),
  },
}

module.exports = nextConfig
```

## Tạo một Adapter

Một adapter là một module export một object triển khai interface `NextAdapter`:

```typescript
export interface NextAdapter {
  name: string
  modifyConfig?: (
    config: NextConfigComplete,
    ctx: {
      phase: PHASE_TYPE
    }
  ) => Promise<NextConfigComplete> | NextConfigComplete
  onBuildComplete?: (ctx: {
    routes: {
      headers: Array<ManifestHeaderRoute>
      redirects: Array<ManifestRedirectRoute>
      rewrites: {
        beforeFiles: Array<ManifestRewriteRoute>
        afterFiles: Array<ManifestRewriteRoute>
        fallback: Array<ManifestRewriteRoute>
      }
      dynamicRoutes: ReadonlyArray<ManifestRoute>
    }
    outputs: AdapterOutputs
    projectDir: string
    repoRoot: string
    distDir: string
    config: NextConfigComplete
    nextVersion: string
  }) => Promise<void> | void
}
```

### Cấu trúc Adapter cơ bản

Dưới đây là một ví dụ adapter tối thiểu:

```js filename="my-adapter.js"
/** @type {import('next').NextAdapter} */
const adapter = {
  name: 'my-custom-adapter',

  async modifyConfig(config, { phase }) {
    // Sửa đổi cấu hình Next.js dựa trên giai đoạn build
    if (phase === 'phase-production-build') {
      return {
        ...config,
        // Thêm các sửa đổi của bạn
      }
    }
    return config
  },

  async onBuildComplete({
    routes,
    outputs,
    projectDir,
    repoRoot,
    distDir,
    config,
    nextVersion,
  }) {
    // Xử lý output của build
    console.log('Build completed with', outputs.pages.length, 'pages')

    // Truy cập các loại output khác nhau
    for (const page of outputs.pages) {
      console.log('Page:', page.pathname, 'at', page.filePath)
    }

    for (const apiRoute of outputs.pagesApi) {
      console.log('API Route:', apiRoute.pathname, 'at', apiRoute.filePath)
    }

    for (const appPage of outputs.appPages) {
      console.log('App Page:', appPage.pathname, 'at', appPage.filePath)
    }

    for (const prerender of outputs.prerenders) {
      console.log('Prerendered:', prerender.pathname)
    }
  },
}

module.exports = adapter
```

## Tài liệu tham khảo API

### `modifyConfig(config, context)`

Được gọi cho bất kỳ lệnh CLI nào tải next.config để cho phép sửa đổi cấu hình.

**Tham số:**

- `config`: Object cấu hình Next.js hoàn chỉnh
- `context.phase`: Giai đoạn build hiện tại (xem [phases](/docs/app/api-reference/config/next-config-js#phase))

**Trả về:** Object cấu hình đã sửa đổi (có thể là async)

### `onBuildComplete(context)`

Được gọi sau khi quá trình build hoàn tất với thông tin chi tiết về routes và outputs.

**Tham số:**

- `routes`: Object chứa route manifests cho headers, redirects, rewrites, và dynamic routes
  - `routes.headers`: Mảng các object header route với các trường `source`, `sourceRegex`, `headers`, `has`, `missing`, và tùy chọn `priority`
  - `routes.redirects`: Mảng các object redirect route với các trường `source`, `sourceRegex`, `destination`, `statusCode`, `has`, `missing`, và tùy chọn `priority`
  - `routes.rewrites`: Object với các mảng `beforeFiles`, `afterFiles`, và `fallback`, mỗi mảng chứa các object rewrite route với các trường `source`, `sourceRegex`, `destination`, `has`, và `missing`
  - `routes.dynamicRoutes`: Mảng các object dynamic route với các trường `source`, `sourceRegex`, `destination`, `has`, và `missing`
- `outputs`: Thông tin chi tiết về tất cả các build outputs được tổ chức theo loại
- `projectDir`: Đường dẫn tuyệt đối đến thư mục dự án Next.js
- `repoRoot`: Đường dẫn tuyệt đối đến thư mục gốc repository được phát hiện
- `distDir`: Đường dẫn tuyệt đối đến thư mục build output
- `config`: Cấu hình Next.js cuối cùng (đã áp dụng `modifyConfig`)
- `nextVersion`: Phiên bản Next.js đang được sử dụng
- `buildId`: Định danh duy nhất cho bản build hiện tại

## Các loại Output

Object `outputs` chứa các mảng của các loại output khác nhau:

### Pages (`outputs.pages`)

Các trang React từ thư mục `pages/`:

```typescript
{
  type: 'PAGES'
  id: string           // Route identifier
  filePath: string     // Path to the built file
  pathname: string     // URL pathname
  sourcePage: string   // Original source file path in pages/ directory
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>  // Traced dependencies (key: relative path from repo root, value: absolute path)
  wasmAssets?: Record<string, string>  // Bundled wasm files (key: name, value: absolute path)
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>  // Environment variables (edge runtime only)
  }
}
```

### API Routes (`outputs.pagesApi`)

Các API routes từ `pages/api/`:

```typescript
{
  type: 'PAGES_API'
  id: string
  filePath: string
  pathname: string
  sourcePage: string   // Original relative source file path
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>
  wasmAssets?: Record<string, string>
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>
  }
}
```

### App Pages (`outputs.appPages`)

Các trang React từ thư mục `app/` với `page.{js,ts,jsx,tsx}`:

```typescript
{
  type: 'APP_PAGE'
  id: string
  filePath: string
  pathname: string     // Includes .rsc suffix for RSC routes
  sourcePage: string   // Original relative source file path
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>
  wasmAssets?: Record<string, string>
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>
  }
}
```

### App Routes (`outputs.appRoutes`)

API và metadata routes từ `app/` với `route.{js,ts,jsx,tsx}`:

```typescript
{
  type: 'APP_ROUTE'
  id: string
  filePath: string
  pathname: string
  sourcePage: string
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>
  wasmAssets?: Record<string, string>
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>
  }
}
```

### Prerenders (`outputs.prerenders`)

Các routes kích hoạt ISR và static prerenders:

```typescript
{
  type: 'PRERENDER'
  id: string
  pathname: string
  parentOutputId: string  // ID of the source page/route
  groupId: number        // Revalidation group identifier (prerenders with same groupId revalidate together)
  pprChain?: {
    headers: Record<string, string>  // PPR chain headers (e.g., 'x-nextjs-resume': '1')
  }
  parentFallbackMode?: 'blocking' | false | null  // Fallback mode from getStaticPaths
  fallback?: {
    filePath: string
    initialStatus?: number
    initialHeaders?: Record<string, string | string[]>
    initialExpiration?: number
    initialRevalidate?: number
    postponedState?: string  // PPR postponed state
  }
  config: {
    allowQuery?: string[]     // Allowed query parameters
    allowHeader?: string[]    // Allowed headers for ISR
    bypassFor?: RouteHas[]    // Cache bypass conditions
    renderingMode?: RenderingMode
    bypassToken?: string
  }
}
```

### Static Files (`outputs.staticFiles`)

Static assets và các trang được tối ưu hóa tĩnh tự động:

```typescript
{
  type: 'STATIC_FILE'
  id: string
  filePath: string
  pathname: string
}
```

### Middleware (`outputs.middleware`)

Hàm Middleware (nếu có):

```typescript
{
  type: 'MIDDLEWARE'
  id: string
  filePath: string
  pathname: string      // Always '/_middleware'
  sourcePage: string    // Always 'middleware'
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>
  wasmAssets?: Record<string, string>
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>
    matchers?: Array<{
      source: string
      sourceRegex: string
      has: RouteHas[] | undefined
      missing: RouteHas[] | undefined
    }>
  }
}
```

## Thông tin Routes

Object `routes` trong `onBuildComplete` cung cấp thông tin routing đầy đủ với các patterns đã xử lý sẵn sàng cho việc triển khai:

### Headers

Mỗi header route bao gồm:

- `source`: Route pattern gốc (ví dụ: `/about`)
- `sourceRegex`: Regex đã biên dịch để khớp requests
- `headers`: Các cặp key-value của headers để áp dụng
- `has`: Các điều kiện tùy chọn phải được đáp ứng
- `missing`: Các điều kiện tùy chọn phải không được đáp ứng
- `priority`: Cờ tùy chọn cho các routes nội bộ

### Redirects

Mỗi redirect route bao gồm:

- `source`: Route pattern gốc
- `sourceRegex`: Regex đã biên dịch để khớp
- `destination`: URL đích (có thể bao gồm các nhóm đã bắt)
- `statusCode`: Mã trạng thái HTTP (301, 302, 307, 308)
- `has`: Các điều kiện dương tính tùy chọn
- `missing`: Các điều kiện âm tính tùy chọn
- `priority`: Cờ tùy chọn cho các routes nội bộ

### Rewrites

Rewrites được phân loại thành ba giai đoạn:

- `beforeFiles`: Được kiểm tra trước hệ thống tệp (bao gồm pages và public files)
- `afterFiles`: Được kiểm tra sau pages/public files nhưng trước dynamic routes
- `fallback`: Được kiểm tra sau tất cả các routes khác

Mỗi rewrite bao gồm `source`, `sourceRegex`, `destination`, `has`, và `missing`.

### Dynamic Routes

Được tạo từ các dynamic route segments (ví dụ: `[slug]`, `[...path]`). Mỗi cái bao gồm:

- `source`: Route pattern
- `sourceRegex`: Regex đã biên dịch với các named capture groups
- `destination`: Đích nội bộ với thay thế tham số
- `has`: Các điều kiện dương tính tùy chọn
- `missing`: Các điều kiện âm tính tùy chọn

## Các trường hợp sử dụng

Các trường hợp sử dụng phổ biến cho adapters bao gồm:

- **Tích hợp Nền tảng Triển khai**: Tự động cấu hình build outputs cho các nền tảng hosting cụ thể
- **Xử lý Asset**: Chuyển đổi hoặc tối ưu hóa build outputs
- **Tích hợp Giám sát**: Thu thập số liệu build và thông tin route
- **Đóng gói Tùy chỉnh**: Đóng gói outputs theo các định dạng cụ thể của nền tảng
- **Xác thực Build**: Đảm bảo outputs đáp ứng các yêu cầu cụ thể
- **Tạo Route**: Sử dụng thông tin route đã xử lý để tạo configs routing cụ thể của nền tảng
