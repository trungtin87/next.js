Rewrites cho phép bạn ánh xạ một đường dẫn request đến một đường dẫn đích khác.

<AppOnly>

Rewrites hoạt động như một URL proxy và che giấu đường dẫn đích, làm cho nó có vẻ như người dùng chưa thay đổi vị trí của họ trên trang web. Ngược lại, [redirects](/docs/app/api-reference/config/next-config-js/redirects) sẽ định tuyến lại đến một trang mới và hiển thị các thay đổi URL.

</AppOnly>

<PagesOnly>

Rewrites hoạt động như một URL proxy và che giấu đường dẫn đích, làm cho nó có vẻ như người dùng chưa thay đổi vị trí của họ trên trang web. Ngược lại, [redirects](/docs/pages/api-reference/config/next-config-js/redirects) sẽ định tuyến lại đến một trang mới và hiển thị các thay đổi URL.

</PagesOnly>

Để sử dụng rewrites bạn có thể sử dụng khóa `rewrites` trong `next.config.js`:

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      {
        source: '/about',
        destination: '/',
      },
    ]
  },
}
```

Rewrites được áp dụng cho client-side routing. Trong ví dụ trên, điều hướng đến `<Link href="/about">` sẽ phục vụ nội dung từ `/` trong khi giữ URL là `/about`.

`rewrites` là một hàm async mong đợi trả về hoặc một mảng hoặc một object của các mảng (xem bên dưới) chứa các objects với các thuộc tính `source` và `destination`:

- `source`: `String` - là mẫu đường dẫn request đến.
- `destination`: `String` là đường dẫn bạn muốn định tuyến đến.
- `basePath`: `false` hoặc `undefined` - nếu false basePath sẽ không được bao gồm khi khớp, chỉ có thể được sử dụng cho external rewrites.
- `locale`: `false` hoặc `undefined` - liệu locale có nên không được bao gồm khi khớp hay không.
- `has` là một mảng của [has objects](#header-cookie-and-query-matching) với các thuộc tính `type`, `key` và `value`.
- `missing` là một mảng của [missing objects](#header-cookie-and-query-matching) với các thuộc tính `type`, `key` và `value`.

Khi hàm `rewrites` trả về một mảng, rewrites được áp dụng sau khi kiểm tra hệ thống tệp (pages và các tệp `/public`) và trước dynamic routes. Khi hàm `rewrites` trả về một object của các mảng với một hình dạng cụ thể, hành vi này có thể được thay đổi và kiểm soát chặt chẽ hơn, kể từ `v10.1` của Next.js:

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return {
      beforeFiles: [
        // These rewrites are checked after headers/redirects
        // and before all files including _next/public files which
        // allows overriding page files
        {
          source: '/some-page',
          destination: '/somewhere-else',
          has: [{ type: 'query', key: 'overrideMe' }],
        },
      ],
      afterFiles: [
        // These rewrites are checked after pages/public files
        // are checked but before dynamic routes
        {
          source: '/non-existent',
          destination: '/somewhere-else',
        },
      ],
      fallback: [
        // These rewrites are checked after both pages/public files
        // and dynamic routes are checked
        {
          source: '/:path*',
          destination: `https://my-old-site.com/:path*`,
        },
      ],
    }
  },
}
```

> **Nên biết**: rewrites trong `beforeFiles` không kiểm tra hệ thống tệp/dynamic routes ngay sau khi khớp một source, chúng tiếp tục cho đến khi tất cả `beforeFiles` đã được kiểm tra.

Thứ tự Next.js routes được kiểm tra là:

<AppOnly>

1. [headers](/docs/app/api-reference/config/next-config-js/headers) được kiểm tra/áp dụng
2. [redirects](/docs/app/api-reference/config/next-config-js/redirects) được kiểm tra/áp dụng
3. [proxy](/docs/app/api-reference/file-conventions/proxy)
4. `beforeFiles` rewrites được kiểm tra/áp dụng
5. static files từ [thư mục public](/docs/app/api-reference/file-conventions/public-folder), các tệp `_next/static`, và các trang non-dynamic được kiểm tra/phục vụ

7. `fallback` rewrites được kiểm tra/áp dụng, chúng được áp dụng trước khi render trang 404 và sau khi dynamic routes/tất cả static assets đã được kiểm tra. ## Tham số Rewrite

Khi sử dụng các tham số trong một rewrite, các tham số sẽ được truyền trong query theo mặc định khi không có tham số nào được sử dụng trong `destination`.

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      {
        source: '/old-about/:path*',
        destination: '/about', // The :path parameter isn't used here so will be automatically passed in the query
      },
    ]
  },
}
```

Nếu một tham số được sử dụng trong destination, không có tham số nào sẽ được tự động truyền trong query.

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      {
        source: '/docs/:path*',
        destination: '/:path*', // The :path parameter is used here so will not be automatically passed in the query
      },
    ]
  },
}
```

Bạn vẫn có thể truyền các tham số thủ công trong query nếu một tham số đã được sử dụng trong destination bằng cách chỉ định query trong `destination`.

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      {
        source: '/:first/:second',
        destination: '/:first?second=:second',
        // Since the :first parameter is used in the destination the :second parameter
        // will not automatically be added in the query although we can manually add it
        // as shown above
      },
    ]
  },
}
```

> **Nên biết**: Các trang tĩnh từ [Automatic Static Optimization](/docs/pages/building-your-application/rendering/automatic-static-optimization) hoặc [prerendering](/docs/pages/building-your-application/data-fetching/get-static-props) params từ rewrites sẽ được phân tích trên client sau khi hydration và được cung cấp trong query.

## Path Matching

Khớp đường dẫn được cho phép, ví dụ `/blog/:slug` sẽ khớp `/blog/hello-world` (không có nested paths):

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      {
        source: '/blog/:slug',
        destination: '/news/:slug', // Matched parameters can be used in the destination
      },
    ]
  },
}
```

### Wildcard Path Matching

Để khớp một wildcard path bạn có thể sử dụng `*` sau một tham số, ví dụ `/blog/:slug*` sẽ khớp `/blog/a/b/c/d/hello-world`:

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      {
        source: '/blog/:slug*',
        destination: '/news/:slug*', // Matched parameters can be used in the destination
      },
    ]
  },
}
```

### Regex Path Matching

Để khớp một regex path bạn có thể bọc regex trong dấu ngoặc đơn sau một tham số, ví dụ `/blog/:slug(\\d{1,})` sẽ khớp `/blog/123` nhưng không khớp `/blog/abc`:

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      {
        source: '/old-blog/:post(\\d{1,})',
        destination: '/blog/:post', // Matched parameters can be used in the destination
      },
    ]
  },
}
```

Các ký tự sau `(`, `)`, `{`, `}`, `[`, `]`, `|`, `\`, `^`, `.`, `:`, `*`, `+`, `-`, `?`, `$` được sử dụng cho regex path matching, vì vậy khi được sử dụng trong `source` như các giá trị không đặc biệt, chúng phải được escape bằng cách thêm `\\` trước chúng:

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      {
        // this will match `/english(default)/something` being requested
        source: '/english\\(default\\)/:slug',
        destination: '/en-us/:slug',
      },
    ]
  },
}
```

## Header, Cookie, và Query Matching

Để chỉ khớp một rewrite khi các giá trị header, cookie, hoặc query cũng khớp với trường `has` hoặc không khớp với trường `missing`. Cả `source` và tất cả các mục `has` phải khớp và tất cả các mục `missing` phải không khớp để rewrite được áp dụng.

Các mục `has` và `missing` có thể có các trường sau:

- `type`: `String` - phải là `header`, `cookie`, `host`, hoặc `query`.
- `key`: `String` - key từ loại đã chọn để khớp.
- `value`: `String` hoặc `undefined` - giá trị để kiểm tra, nếu undefined bất kỳ giá trị nào cũng sẽ khớp. Một chuỗi giống regex có thể được sử dụng để bắt một phần cụ thể của giá trị, ví dụ nếu giá trị `first-(?<paramName>.*)` được sử dụng cho `first-second` thì `second` sẽ có thể sử dụng được trong destination với `:paramName`.

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      // if the header `x-rewrite-me` is present,
      // this rewrite will be applied
      {
        source: '/:path*',
        has: [
          {
            type: 'header',
            key: 'x-rewrite-me',
          },
        ],
        destination: '/another-page',
      },
      // if the header `x-rewrite-me` is not present,
      // this rewrite will be applied
      {
        source: '/:path*',
        missing: [
          {
            type: 'header',
            key: 'x-rewrite-me',
          },
        ],
        destination: '/another-page',
      },
      // if the source, query, and cookie are matched,
      // this rewrite will be applied
      {
        source: '/specific/:path*',
        has: [
          {
            type: 'query',
            key: 'page',
            // the page value will not be available in the
            // destination since value is provided and doesn't
            // use a named capture group e.g. (?<page>home)
            value: 'home',
          },
          {
            type: 'cookie',
            key: 'authorized',
            value: 'true',
          },
        ],
        destination: '/:path*/home',
      },
      // if the header `x-authorized` is present and
      // contains a matching value, this rewrite will be applied
      {
        source: '/:path*',
        has: [
          {
            type: 'header',
            key: 'x-authorized',
            value: '(?<authorized>yes|true)',
          },
        ],
        destination: '/home?authorized=:authorized',
      },
      // if the host is `example.com`,
      // this rewrite will be applied
      {
        source: '/:path*',
        has: [
          {
            type: 'host',
            value: 'example.com',
          },
        ],
        destination: '/another-page',
      },
    ]
  },
}
```

## Rewriting đến một external URL

<details>
  <summary>Ví dụ</summary>

- [Using Multiple Zones](https://github.com/vercel/next.js/tree/canary/examples/with-zones)

</details>

Rewrites cho phép bạn rewrite đến một external URL. Điều này đặc biệt hữu ích cho việc áp dụng dần dần Next.js. Sau đây là một ví dụ rewrite để chuyển hướng route `/blog` của ứng dụng chính của bạn đến một trang web bên ngoài.

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return [
      {
        source: '/blog',
        destination: 'https://example.com/blog',
      },
      {
        source: '/blog/:slug',
        destination: 'https://example.com/blog/:slug', // Matched parameters can be used in the destination
      },
    ]
  },
}
```

Nếu bạn đang sử dụng `trailingSlash: true`, bạn cũng cần chèn một dấu gạch chéo ở cuối trong tham số `source`. Nếu server đích cũng mong đợi một dấu gạch chéo ở cuối, nó cũng nên được bao gồm trong tham số `destination`.

```js filename="next.config.js"
module.exports = {
  trailingSlash: true,
  async rewrites() {
    return [
      {
        source: '/blog/',
        destination: 'https://example.com/blog/',
      },
      {
        source: '/blog/:path*/',
        destination: 'https://example.com/blog/:path*/',
      },
    ]
  },
}
```

### Áp dụng dần dần Next.js

Bạn cũng có thể để Next.js dự phòng sang proxying đến một trang web hiện có sau khi kiểm tra tất cả các Next.js routes.

Bằng cách này, bạn không phải thay đổi cấu hình rewrites khi di chuyển nhiều trang hơn sang Next.js

```js filename="next.config.js"
module.exports = {
  async rewrites() {
    return {
      fallback: [
        {
          source: '/:path*',
          destination: `https://custom-routes-proxying-endpoint.vercel.app/:path*`,
        },
      ],
    }
  },
}
```

### Rewrites với hỗ trợ basePath

Khi tận dụng [hỗ trợ `basePath`](/docs/app/api-reference/config/next-config-js/basePath) với rewrites mỗi `source` và `destination` được tự động thêm tiền tố với `basePath` trừ khi bạn thêm `basePath: false` vào rewrite:

```js filename="next.config.js"
module.exports = {
  basePath: '/docs',

  async rewrites() {
    return [
      {
        source: '/with-basePath', // automatically becomes /docs/with-basePath
        destination: '/another', // automatically becomes /docs/another
      },
      {
        // does not add /docs to /without-basePath since basePath: false is set
        // Note: this can not be used for internal rewrites e.g. `destination: '/another'`
        source: '/without-basePath',
        destination: 'https://example.com',
        basePath: false,
      },
    ]
  },
}
```

### Rewrites với hỗ trợ i18n

Khi tận dụng [hỗ trợ `i18n`](/docs/pages/guides/internationalization) với rewrites mỗi `source` và `destination` được tự động thêm tiền tố để xử lý các `locales` đã cấu hình trừ khi bạn thêm `locale: false` vào rewrite. Nếu `locale: false` được sử dụng bạn phải thêm tiền tố `source` và `destination` với một locale để nó được khớp chính xác.

```js filename="next.config.js"
module.exports = {
  i18n: {
    locales: ['en', 'fr', 'de'],
    defaultLocale: 'en',
  },

  async rewrites() {
    return [
      {
        source: '/with-locale', // automatically handles all locales
        destination: '/another', // automatically passes the locale on
      },
      {
        // does not handle locales automatically since locale: false is set
        source: '/nl/with-locale-manual',
        destination: '/nl/another',
        locale: false,
      },
      {
        // this matches '/' since `en` is the defaultLocale
        source: '/en',
        destination: '/en/another',
        locale: false,
      },
      {
        // it's possible to match all locales even when locale: false is set
        source: '/:locale/api-alias/:path*',
        destination: '/api/:path*',
        locale: false,
      },
      {
        // this gets converted to /(en|fr|de)/(.*) so will not match the top-level
        // `/` or `/fr` routes like /:path* would
        source: '/(.*)',
        destination: '/another',
      },
    ]
  },
}
```
