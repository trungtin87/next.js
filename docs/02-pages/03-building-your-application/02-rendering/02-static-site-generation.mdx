Nếu một trang sử dụng **Tạo trang tĩnh**, HTML của trang sẽ được tạo tại **thời điểm build**. Điều đó có nghĩa là trong môi trường production, HTML của trang được tạo khi bạn chạy `next build`. HTML này sau đó sẽ được tái sử dụng cho mỗi yêu cầu. Nó có thể được lưu vào bộ nhớ đệm bởi một CDN.

Trong Next.js, bạn có thể tạo các trang tĩnh **có hoặc không có dữ liệu**. Hãy cùng xem xét từng trường hợp.

### Tạo trang tĩnh không có dữ liệu

Theo mặc định, Next.js render trước các trang bằng cách sử dụng Tạo trang tĩnh mà không cần tìm nạp dữ liệu. Đây là một ví dụ:

```jsx
function About() {
  return <div>About</div>
}

export default About
```

Lưu ý rằng trang này không cần tìm nạp bất kỳ dữ liệu bên ngoài nào để được render trước. Trong những trường hợp như thế này, Next.js tạo một tệp HTML duy nhất cho mỗi trang trong thời gian build.

### Tạo trang tĩnh có dữ liệu

Một số trang yêu cầu tìm nạp dữ liệu bên ngoài để render trước. Có hai tình huống, và một hoặc cả hai có thể áp dụng. Trong mỗi trường hợp, bạn có thể sử dụng các hàm này mà Next.js cung cấp:

1. **Nội dung** trang của bạn phụ thuộc vào dữ liệu bên ngoài: Sử dụng `getStaticProps`.
2. **Đường dẫn** trang của bạn phụ thuộc vào dữ liệu bên ngoài: Sử dụng `getStaticPaths` (thường ngoài `getStaticProps`).

#### Tình huống 1: Nội dung trang của bạn phụ thuộc vào dữ liệu bên ngoài

**Ví dụ**: Trang blog của bạn có thể cần tìm nạp danh sách các bài đăng trên blog từ một CMS (hệ thống quản lý nội dung).

```jsx
// TODO: Cần tìm nạp `posts` (bằng cách gọi một số điểm cuối API)
// trước khi trang này có thể được render trước.
export default function Blog({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li>{post.title}</li>
      ))}
    </ul>
  )
}
```

Để tìm nạp dữ liệu này khi render trước, Next.js cho phép bạn `export` một hàm `async` có tên là `getStaticProps` từ cùng một tệp. Hàm này được gọi tại thời điểm build và cho phép bạn chuyển dữ liệu đã tìm nạp đến `props` của trang khi render trước.

```jsx
export default function Blog({ posts }) {
  // Render bài đăng...
}

// Hàm này được gọi tại thời điểm build
export async function getStaticProps() {
  // Gọi một điểm cuối API bên ngoài để lấy bài đăng
  const res = await fetch('https://.../posts')
  const posts = await res.json()

  // Bằng cách trả về { props: { posts } }, thành phần Blog
  // sẽ nhận `posts` làm một prop tại thời điểm build
  return {
    props: {
      posts,
    },
  }
}
```

Để tìm hiểu thêm về cách `getStaticProps` hoạt động, hãy xem [Tài liệu tìm nạp dữ liệu](/docs/pages/building-your-application/data-fetching/get-static-props).

#### Tình huống 2: Đường dẫn trang của bạn phụ thuộc vào dữ liệu bên ngoài

Next.js cho phép bạn tạo các trang có **đường dẫn động**. Ví dụ: bạn có thể tạo một tệp có tên `pages/posts/[id].js` để hiển thị một bài đăng blog duy nhất dựa trên `id`. Điều này sẽ cho phép bạn hiển thị một bài đăng blog có `id: 1` khi bạn truy cập `posts/1`.

> Để tìm hiểu thêm về định tuyến động, hãy xem [Tài liệu định tuyến động](/docs/pages/building-your-application/routing/dynamic-routes).

Tuy nhiên, `id` nào bạn muốn render trước tại thời điểm build có thể phụ thuộc vào dữ liệu bên ngoài.

**Ví dụ**: giả sử bạn chỉ thêm một bài đăng trên blog (có `id: 1`) vào cơ sở dữ liệu. Trong trường hợp này, bạn chỉ muốn render trước `posts/1` tại thời điểm build.

Sau đó, bạn có thể thêm bài đăng thứ hai có `id: 2`. Khi đó bạn cũng muốn render trước `posts/2`.

Vì vậy, **đường dẫn** trang của bạn được render trước phụ thuộc vào dữ liệu bên ngoài. Để xử lý việc này, Next.js cho phép bạn `export` một hàm `async` có tên `getStaticPaths` từ một trang động (`pages/posts/[id].js` trong trường hợp này). Hàm này được gọi tại thời điểm build và cho phép bạn chỉ định đường dẫn nào bạn muốn render trước.

```jsx
// Hàm này được gọi tại thời điểm build
export async function getStaticPaths() {
  // Gọi một điểm cuối API bên ngoài để lấy bài đăng
  const res = await fetch('https://.../posts')
  const posts = await res.json()

  // Lấy các đường dẫn chúng ta muốn render trước dựa trên các bài đăng
  const paths = posts.map((post) => ({
    params: { id: post.id },
  }))

  // Chúng ta sẽ chỉ render trước các đường dẫn này tại thời điểm build.
  // { fallback: false } có nghĩa là các tuyến đường khác sẽ 404.
  return { paths, fallback: false }
}
```

Cũng trong `pages/posts/[id].js`, bạn cần export `getStaticProps` để bạn có thể tìm nạp dữ liệu về bài đăng có `id` này và sử dụng nó để render trước trang:

```jsx
export default function Post({ post }) {
  // Render bài đăng...
}

export async function getStaticPaths() {
  // ...
}

// Điều này cũng được gọi tại thời điểm build
export async function getStaticProps({ params }) {
  // params chứa `id` của bài đăng.
  // Nếu tuyến đường là /posts/1, thì params.id là 1
  const res = await fetch(`https://.../posts/${params.id}`)
  const post = await res.json()

  // Chuyển dữ liệu bài đăng đến trang thông qua props
  return { props: { post } }
}
```

Để tìm hiểu thêm về cách `getStaticPaths` hoạt động, hãy xem [Tài liệu tìm nạp dữ liệu](/docs/pages/building-your-application/data-fetching/get-static-paths).

### Khi nào tôi nên sử dụng Tạo trang tĩnh?

Chúng tôi khuyên bạn nên sử dụng **Tạo trang tĩnh** (có và không có dữ liệu) bất cứ khi nào có thể vì trang của bạn có thể được build một lần và được phục vụ bởi CDN, điều này làm cho nó nhanh hơn nhiều so với việc có một máy chủ render trang trên mỗi yêu cầu.

Bạn có thể sử dụng Tạo trang tĩnh cho nhiều loại trang, bao gồm:

- Trang marketing
- Bài đăng trên blog và portfolio
- Danh sách sản phẩm thương mại điện tử
- Trợ giúp và tài liệu

Bạn nên tự hỏi mình: "Tôi có thể render trước trang này **trước** yêu cầu của người dùng không?" Nếu câu trả lời là có, thì bạn nên chọn Tạo trang tĩnh.

Mặt khác, Tạo trang tĩnh **không** phải là một ý tưởng tốt nếu bạn không thể render trước một trang trước yêu cầu của người dùng. Có thể trang của bạn hiển thị dữ liệu được cập nhật thường xuyên và nội dung trang thay đổi theo mỗi yêu cầu.

Trong những trường hợp như thế này, bạn có thể thực hiện một trong những cách sau:

- Sử dụng Tạo trang tĩnh với **Tìm nạp dữ liệu phía máy khách:** Bạn có thể bỏ qua việc render trước một số phần của trang và sau đó sử dụng JavaScript phía máy khách để điền chúng. Để tìm hiểu thêm về phương pháp này, hãy xem [Tài liệu tìm nạp dữ liệu](/docs/pages/building-your-application/data-fetching/client-side).
- Sử dụng **Render phía máy chủ:** Next.js render trước một trang trên mỗi yêu cầu. Sẽ chậm hơn vì trang không thể được lưu vào bộ nhớ đệm bởi một CDN, nhưng trang được render trước sẽ luôn được cập nhật. Chúng ta sẽ nói về phương pháp này dưới đây.
