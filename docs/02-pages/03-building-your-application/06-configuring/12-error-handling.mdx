Tài liệu này giải thích cách bạn có thể xử lý các lỗi development, server-side và client-side.

## Xử lý lỗi trong Development

Khi có lỗi runtime trong giai đoạn development của ứng dụng Next.js của bạn, bạn sẽ gặp một **overlay**. Đó là một modal che phủ trang web. Nó **chỉ** hiển thị khi development server chạy bằng `next dev` thông qua `pnpm dev`, `npm run dev`, `yarn dev`, hoặc `bun dev` và sẽ không được hiển thị trong production. Sửa lỗi sẽ tự động loại bỏ overlay.

## Xử lý lỗi Server

Next.js cung cấp một trang 500 tĩnh theo mặc định để xử lý các lỗi server-side xảy ra trong ứng dụng của bạn. Bạn cũng có thể [tùy chỉnh trang này](/docs/pages/building-your-application/routing/custom-error#customizing-the-500-page) bằng cách tạo một tệp `pages/500.js`.

Có một trang 500 trong ứng dụng của bạn không hiển thị lỗi cụ thể cho người dùng ứng dụng.

Bạn cũng có thể sử dụng [trang 404](/docs/pages/building-your-application/routing/custom-error#404-page) để xử lý lỗi runtime cụ thể như `file not found`.

## Xử lý lỗi Client

React [Error Boundaries](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary) là một cách graceful để xử lý lỗi JavaScript ở phía client để các phần khác của ứng dụng tiếp tục hoạt động. Ngoài việc ngăn trang bị crash, nó cho phép bạn cung cấp một fallback component tùy chỉnh và thậm chí log thông tin lỗi.

Để sử dụng Error Boundaries cho ứng dụng Next.js của bạn, bạn phải tạo một class component `ErrorBoundary` và wrap prop `Component` trong tệp `pages/_app.js`. Component này sẽ chịu trách nhiệm:

- Render một fallback UI sau khi một lỗi được ném
- Cung cấp một cách để reset state của Application
- Log thông tin lỗi

Bạn có thể tạo một class component `ErrorBoundary` bằng cách extend `React.Component`. Ví dụ:

```jsx
class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props)

    // Define a state variable to track whether is an error or not
    this.state = { hasError: false }
  }
  static getDerivedStateFromError(error) {
    // Update state so the next render will show the fallback UI

    return { hasError: true }
  }
  componentDidCatch(error, errorInfo) {
    // You can use your own error logging service here
    console.log({ error, errorInfo })
  }
  render() {
    // Check if the error is thrown
    if (this.state.hasError) {
      // You can render any custom fallback UI
      return (
        <div>
          <h2>Oops, there is an error!</h2>
          <button
            type="button"
            onClick={() => this.setState({ hasError: false })}
          >
            Try again?
          </button>
        </div>
      )
    }

    // Return children components in case of no error

    return this.props.children
  }
}

export default ErrorBoundary
```

Component `ErrorBoundary` theo dõi một state `hasError`. Giá trị của biến state này là một boolean. Khi giá trị của `hasError` là `true`, thì component `ErrorBoundary` sẽ render một fallback UI. Nếu không, nó sẽ render các children components.

Sau khi tạo một component `ErrorBoundary`, hãy import nó trong tệp `pages/_app.js` để wrap prop `Component` trong ứng dụng Next.js của bạn.

```jsx
// Import the ErrorBoundary component
import ErrorBoundary from '../components/ErrorBoundary'

function MyApp({ Component, pageProps }) {
  return (
    // Wrap the Component prop with ErrorBoundary component
    <ErrorBoundary>
      <Component {...pageProps} />
    </ErrorBoundary>
  )
}

export default MyApp
```

Bạn có thể tìm hiểu thêm về [Error Boundaries](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary) trong tài liệu của React.

### Báo cáo lỗi

Để monitor các lỗi client, hãy sử dụng một dịch vụ như [Sentry](https://github.com/vercel/next.js/tree/canary/examples/with-sentry), Bugsnag hoặc Datadog.
