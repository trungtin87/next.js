`getServerSideProps` là một hàm của Next.js có thể được sử dụng để tìm nạp dữ liệu và hiển thị nội dung của một trang tại thời điểm yêu cầu.

## Ví dụ

Bạn có thể sử dụng `getServerSideProps` bằng cách xuất nó từ một Thành phần Trang. Ví dụ dưới đây cho thấy cách bạn có thể tìm nạp dữ liệu từ API của bên thứ 3 trong `getServerSideProps` và chuyển dữ liệu đó đến trang dưới dạng props:

```tsx filename="pages/index.tsx" switcher
import type { InferGetServerSidePropsType, GetServerSideProps } from 'next'

type Repo = {
  name: string
  stargazers_count: number
}

export const getServerSideProps = (async () => {
  // Tìm nạp dữ liệu từ API bên ngoài
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo: Repo = await res.json()
  // Chuyển dữ liệu đến trang thông qua props
  return { props: { repo } }
}) satisfies GetServerSideProps<{ repo: Repo }>

export default function Page({
  repo,
}: InferGetServerSidePropsType<typeof getServerSideProps>) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}
```

```jsx filename="pages/index.js" switcher
export async function getServerSideProps() {
  // Tìm nạp dữ liệu từ API bên ngoài
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  // Chuyển dữ liệu đến trang thông qua props
  return { props: { repo } }
}

export default function Page({ repo }) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}
```

## Khi nào tôi nên sử dụng `getServerSideProps`?

Bạn nên sử dụng `getServerSideProps` nếu bạn cần hiển thị một trang phụ thuộc vào dữ liệu người dùng được cá nhân hóa hoặc thông tin chỉ có thể được biết tại thời điểm yêu cầu. Ví dụ: tiêu đề `authorization` hoặc vị trí địa lý.

Nếu bạn không cần tìm nạp dữ liệu tại thời điểm yêu cầu hoặc muốn lưu vào bộ nhớ cache dữ liệu và HTML được kết xuất trước, chúng tôi khuyên bạn nên sử dụng [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props).

## Hành vi

- `getServerSideProps` chạy trên máy chủ.
- `getServerSideProps` chỉ có thể được xuất từ một **trang**.
- `getServerSideProps` trả về JSON.
- Khi người dùng truy cập một trang, `getServerSideProps` sẽ được sử dụng để tìm nạp dữ liệu tại thời điểm yêu cầu và dữ liệu được sử dụng để hiển thị HTML ban đầu của trang.
- `props` được chuyển đến thành phần trang có thể được xem trên máy khách như một phần của HTML ban đầu. Điều này là để cho phép trang được [hydrat hóa](https://react.dev/reference/react-dom/hydrate) một cách chính xác. Đảm bảo rằng bạn không chuyển bất kỳ thông tin nhạy cảm nào không nên có trên máy khách trong `props`.
- Khi người dùng truy cập trang thông qua [`next/link`](/docs/pages/api-reference/components/link) hoặc [`next/router`](/docs/pages/api-reference/functions/use-router), Next.js sẽ gửi một yêu cầu API đến máy chủ, yêu cầu này sẽ chạy `getServerSideProps`.
- Bạn không cần phải gọi một [API Route](/docs/pages/building-your-application/routing/api-routes) của Next.js để tìm nạp dữ liệu khi sử dụng `getServerSideProps` vì hàm này chạy trên máy chủ. Thay vào đó, bạn có thể gọi trực tiếp một CMS, cơ sở dữ liệu hoặc các API của bên thứ ba khác từ bên trong `getServerSideProps`.

> **Cần biết:**
>
> - Xem [tham chiếu API `getServerSideProps`](/docs/pages/api-reference/functions/get-server-side-props) để biết các tham số và đạo cụ có thể được sử dụng với `getServerSideProps`.
> - Bạn có thể sử dụng [công cụ loại bỏ mã tiếp theo](https://next-code-elimination.vercel.app/) để xác minh những gì Next.js loại bỏ khỏi gói phía máy khách.

## Xử lý lỗi

Nếu một lỗi được ném ra bên trong `getServerSideProps`, nó sẽ hiển thị tệp `pages/500.js`. Xem tài liệu về [trang 500](/docs/pages/building-your-application/routing/custom-error#500-page) để tìm hiểu thêm về cách tạo nó. Trong quá trình phát triển, tệp này sẽ không được sử dụng và lớp phủ lỗi phát triển sẽ được hiển thị thay thế.

## Các trường hợp đặc biệt

### Lưu vào bộ nhớ đệm với Kết xuất phía máy chủ (SSR)

Bạn có thể sử dụng các tiêu đề bộ nhớ đệm (`Cache-Control`) bên trong `getServerSideProps` để lưu vào bộ nhớ đệm các phản hồi động. Ví dụ: sử dụng [`stale-while-revalidate`](https://web.dev/stale-while-revalidate/).

```jsx
// Giá trị này được coi là mới trong mười giây (s-maxage=10).
// Nếu một yêu cầu được lặp lại trong vòng 10 giây tới,
// giá trị được lưu trong bộ nhớ cache trước đó sẽ vẫn mới. Nếu yêu cầu được lặp lại trước 59 giây,
// giá trị được lưu trong bộ nhớ cache sẽ cũ nhưng vẫn hiển thị (stale-while-revalidate=59).
//
// Ở chế độ nền, một yêu cầu xác thực lại sẽ được thực hiện để điền vào bộ nhớ cache
// với một giá trị mới. Nếu bạn làm mới trang, bạn sẽ thấy giá trị mới.
export async function getServerSideProps({ req, res }) {
  res.setHeader(
    'Cache-Control',
    'public, s-maxage=10, stale-while-revalidate=59'
  )

  return {
    props: {},
  }
}
```

Tuy nhiên, trước khi sử dụng `cache-control`, chúng tôi khuyên bạn nên xem liệu [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) với [ISR](/docs/pages/guides/incremental-static-regeneration) có phù hợp hơn với trường hợp sử dụng của bạn hay không.
