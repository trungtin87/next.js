Next.js router cho phép bạn thực hiện chuyển đổi route phía client (client-side route transitions) giữa các trang, tương tự như một ứng dụng single-page.

Một React component được gọi là `Link` được cung cấp để thực hiện chuyển đổi route phía client này.

```jsx
import Link from 'next/link'

function Home() {
  return (
    <ul>
      <li>
        <Link href="/">Home</Link>
      </li>
      <li>
        <Link href="/about">About Us</Link>
      </li>
      <li>
        <Link href="/blog/hello-world">Blog Post</Link>
      </li>
    </ul>
  )
}

export default Home
```

Ví dụ trên sử dụng nhiều links. Mỗi link ánh xạ một đường dẫn (`href`) tới một trang đã biết:

- `/` → `pages/index.js`
- `/about` → `pages/about.js`
- `/blog/hello-world` → `pages/blog/[slug].js`

Bất kỳ `<Link />` nào trong viewport (ban đầu hoặc thông qua cuộn) sẽ được prefetch theo mặc định (bao gồm dữ liệu tương ứng) cho các trang sử dụng [Static Generation](/docs/pages/building-your-application/data-fetching/get-static-props). Dữ liệu tương ứng cho các routes [server-rendered](/docs/pages/building-your-application/data-fetching/get-server-side-props) được fetch _chỉ khi_ `<Link />` được click.

## Liên kết đến dynamic paths

Bạn cũng có thể sử dụng nội suy (interpolation) để tạo đường dẫn, điều này rất tiện lợi cho [dynamic route segments](/docs/pages/building-your-application/routing/dynamic-routes). Ví dụ, để hiển thị danh sách các bài viết đã được truyền cho component dưới dạng prop:

```jsx
import Link from 'next/link'

function Posts({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>
          <Link href={`/blog/${encodeURIComponent(post.slug)}`}>
            {post.title}
          </Link>
        </li>
      ))}
    </ul>
  )
}

export default Posts
```

> [`encodeURIComponent`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/encodeURIComponent) được sử dụng trong ví dụ để giữ cho đường dẫn tương thích utf-8.

Ngoài ra, sử dụng một URL Object:

```jsx
import Link from 'next/link'

function Posts({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>
          <Link
            href={{
              pathname: '/blog/[slug]',
              query: { slug: post.slug },
            }}
          >
            {post.title}
          </Link>
        </li>
      ))}
    </ul>
  )
}

export default Posts
```

Bây giờ, thay vì sử dụng nội suy để tạo đường dẫn, chúng ta sử dụng một URL object trong `href` trong đó:

- `pathname` là tên của trang trong thư mục `pages`. `/blog/[slug]` trong trường hợp này.
- `query` là một object với dynamic segment. `slug` trong trường hợp này.

## Injecting the router

Để truy cập [`router` object](/docs/pages/api-reference/functions/use-router#router-object) trong một React component bạn có thể sử dụng [`useRouter`](/docs/pages/api-reference/functions/use-router) hoặc [`withRouter`](/docs/pages/api-reference/functions/use-router#withrouter).

Nói chung chúng tôi khuyên dùng [`useRouter`](/docs/pages/api-reference/functions/use-router).

## Imperative Routing

[`next/link`](/docs/pages/api-reference/components/link) sẽ có thể đáp ứng hầu hết các nhu cầu routing của bạn, nhưng bạn cũng có thể thực hiện điều hướng client-side mà không cần nó, hãy xem [tài liệu cho `next/router`](/docs/pages/api-reference/functions/use-router).

Ví dụ sau đây cho thấy cách thực hiện điều hướng trang cơ bản với [`useRouter`](/docs/pages/api-reference/functions/use-router):

```jsx
import { useRouter } from 'next/router'

export default function ReadMore() {
  const router = useRouter()

  return (
    <button onClick={() => router.push('/about')}>
      Click here to read more
    </button>
  )
}
```

## Shallow Routing

Shallow routing cho phép bạn thay đổi URL mà không cần chạy lại các phương thức data fetching, bao gồm [`getServerSideProps`](/docs/pages/building-your-application/data-fetching/get-server-side-props), [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props), và [`getInitialProps`](/docs/pages/api-reference/functions/get-initial-props).

Bạn sẽ nhận được `pathname` và `query` đã cập nhật thông qua [`router` object](/docs/pages/api-reference/functions/use-router#router-object) (được thêm bởi [`useRouter`](/docs/pages/api-reference/functions/use-router) hoặc [`withRouter`](/docs/pages/api-reference/functions/use-router#withrouter)), mà không làm mất state.

Để kích hoạt shallow routing, đặt tùy chọn `shallow` thành `true`. Xem xét ví dụ sau:

```jsx
import { useEffect } from 'react'
import { useRouter } from 'next/router'

// Current URL is '/'
function Page() {
  const router = useRouter()

  useEffect(() => {
    // Always do navigations after the first render
    router.push('/?counter=10', undefined, { shallow: true })
  }, [])

  useEffect(() => {
    // The counter changed!
  }, [router.query.counter])
}

export default Page
```

URL sẽ được cập nhật thành `/?counter=10` và trang sẽ không bị thay thế, chỉ state của route được thay đổi.

Bạn cũng có thể theo dõi các thay đổi URL thông qua [`componentDidUpdate`](https://react.dev/reference/react/Component#componentdidupdate) như hiển thị bên dưới:

```jsx
componentDidUpdate(prevProps) {
  const { pathname, query } = this.props.router
  // verify props have changed to avoid an infinite loop
  if (query.counter !== prevProps.router.query.counter) {
    // fetch data based on the new query
  }
}
```

### Caveats

Shallow routing **chỉ** hoạt động cho các thay đổi URL trong trang hiện tại. Ví dụ, giả sử chúng ta có một trang khác gọi là `pages/about.js`, và bạn chạy lệnh này:

```js
router.push('/?counter=10', '/about?counter=10', { shallow: true })
```

Vì đó là một trang mới, nó sẽ unload trang hiện tại, load trang mới và đợi data fetching ngay cả khi chúng ta yêu cầu thực hiện shallow routing.

Khi shallow routing được sử dụng với proxy, nó sẽ không đảm bảo trang mới khớp với trang hiện tại như đã làm trước đây mà không có proxy. Điều này là do proxy có thể rewrite động và không thể xác minh phía client mà không cần data fetch (cái mà bị bỏ qua với shallow), vì vậy một thay đổi route shallow phải luôn được coi là shallow.
