## Trang 404

Một trang 404 có thể được truy cập rất thường xuyên. Server-rendering một trang lỗi cho mỗi lần truy cập làm tăng tải của server Next.js. Điều này có thể dẫn đến tăng chi phí và trải nghiệm chậm.

Để tránh các cạm bẫy trên, Next.js cung cấp một trang 404 tĩnh theo mặc định mà không cần thêm bất kỳ tệp bổ sung nào.

### Tùy chỉnh trang 404

Để tạo một trang 404 tùy chỉnh, bạn có thể tạo một tệp `pages/404.js`. Tệp này được tạo tĩnh tại thời điểm build.

```jsx filename="pages/404.js"
export default function Custom404() {
  return <h1>404 - Page Not Found</h1>
}
```

> **Nên biết**: Bạn có thể sử dụng [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) bên trong trang này nếu bạn cần fetch dữ liệu tại thời điểm build.

## Trang 500

Server-rendering một trang lỗi cho mỗi lần truy cập thêm độ phức tạp vào việc phản hồi lỗi. Để giúp người dùng nhận được phản hồi lỗi nhanh nhất có thể, Next.js cung cấp một trang 500 tĩnh theo mặc định mà không cần thêm bất kỳ tệp bổ sung nào.

### Tùy chỉnh trang 500

Để tùy chỉnh trang 500, bạn có thể tạo một tệp `pages/500.js`. Tệp này được tạo tĩnh tại thời điểm build.

```jsx filename="pages/500.js"
export default function Custom500() {
  return <h1>500 - Server-side error occurred</h1>
}
```

> **Nên biết**: Bạn có thể sử dụng [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) bên trong trang này nếu bạn cần fetch dữ liệu tại thời điểm build.

### Tùy chỉnh trang lỗi nâng cao hơn

Lỗi 500 được xử lý cả client-side và server-side bởi component `Error`. Nếu bạn muốn ghi đè nó, hãy định nghĩa tệp `pages/_error.js` và thêm code sau:

```jsx
function Error({ statusCode }) {
  return (
    <p>
      {statusCode
        ? `An error ${statusCode} occurred on server`
        : 'An error occurred on client'}
    </p>
  )
}

Error.getInitialProps = ({ res, err }) => {
  const statusCode = res ? res.statusCode : err ? err.statusCode : 404
  return { statusCode }
}

export default Error
```

> `pages/_error.js` chỉ được sử dụng trong production. Trong development, bạn sẽ nhận được một lỗi với call stack để biết lỗi bắt nguồn từ đâu.

### Sử dụng lại trang lỗi tích hợp sẵn

Nếu bạn muốn render trang lỗi tích hợp sẵn, bạn có thể bằng cách import component `Error`:

```jsx
import Error from 'next/error'

export async function getServerSideProps() {
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const errorCode = res.ok ? false : res.status
  const json = await res.json()

  return {
    props: { errorCode, stars: json.stargazers_count },
  }
}

export default function Page({ errorCode, stars }) {
  if (errorCode) {
    return <Error statusCode={errorCode} />
  }

  return <div>Next stars: {stars}</div>
}
```

Component `Error` cũng nhận `title` làm thuộc tính nếu bạn muốn truyền một text message cùng với `statusCode`.

Nếu bạn có một component `Error` tùy chỉnh, hãy đảm bảo import component đó thay thế. `next/error` export component mặc định được sử dụng bởi Next.js.

### Caveats

- `Error` hiện tại không hỗ trợ các [Data Fetching methods](/docs/pages/building-your-application/data-fetching) của Next.js như [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props) hoặc [`getServerSideProps`](/docs/pages/building-your-application/data-fetching/get-server-side-props).
- `_error`, giống như `_app`, là một pathname được dành riêng. `_error` được sử dụng để định nghĩa các layout và hành vi tùy chỉnh của các trang lỗi. `/_error` sẽ render 404 khi được truy cập trực tiếp thông qua [routing](/docs/pages/building-your-application/routing) hoặc rendering trong một [custom server](/docs/pages/guides/custom-server).
