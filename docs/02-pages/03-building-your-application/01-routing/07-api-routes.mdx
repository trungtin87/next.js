> **Nên biết**: Nếu bạn đang sử dụng App Router, bạn có thể sử dụng [Server Components](/docs/app/getting-started/server-and-client-components) hoặc [Route Handlers](/docs/app/api-reference/file-conventions/route) thay vì API Routes.

API routes cung cấp một giải pháp để xây dựng một **public API** với Next.js.

Bất kỳ tệp nào bên trong thư mục `pages/api` được ánh xạ tới `/api/*` và sẽ được coi là một API endpoint thay vì một `page`. Chúng là server-side only bundles và sẽ không làm tăng kích thước client-side bundle của bạn.

Ví dụ, API route sau trả về một JSON response với status code là `200`:

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

type ResponseData = {
  message: string
}

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<ResponseData>
) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

```js filename="pages/api/hello.js" switcher
export default function handler(req, res) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

> **Nên biết**:
>
> - API Routes [không chỉ định CORS headers](https://developer.mozilla.org/docs/Web/HTTP/CORS), có nghĩa là chúng là **same-origin only** theo mặc định. Bạn có thể tùy chỉnh hành vi như vậy bằng cách bọc request handler với [CORS request helpers](https://github.com/vercel/next.js/tree/canary/examples/api-routes-cors).

- API Routes không thể được sử dụng với [static exports](/docs/pages/guides/static-exports). Tuy nhiên, [Route Handlers](/docs/app/api-reference/file-conventions/route) trong App Router có thể.
  > - API Routes sẽ bị ảnh hưởng bởi cấu hình [`pageExtensions`](/docs/pages/api-reference/config/next-config-js/pageExtensions) trong `next.config.js`.

## Tham số

```tsx
export default function handler(req: NextApiRequest, res: NextApiResponse) {
  // ...
}
```

- `req`: Một instance của [http.IncomingMessage](https://nodejs.org/api/http.html#class-httpincomingmessage)
- `res`: Một instance của [http.ServerResponse](https://nodejs.org/api/http.html#class-httpserverresponse)

## Các phương thức HTTP

Để xử lý các phương thức HTTP khác nhau trong một API route, bạn có thể sử dụng `req.method` trong request handler của mình, như sau:

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default function handler(req: NextApiRequest, res: NextApiResponse) {
  if (req.method === 'POST') {
    // Process a POST request
  } else {
    // Handle any other HTTP method
  }
}
```

```js filename="pages/api/hello.js" switcher
export default function handler(req, res) {
  if (req.method === 'POST') {
    // Process a POST request
  } else {
    // Handle any other HTTP method
  }
}
```

## Request Helpers

API Routes cung cấp các request helpers tích hợp sẵn để phân tích incoming request (`req`):

- `req.cookies` - Một object chứa các cookies được gửi bởi request. Mặc định là `{}`
- `req.query` - Một object chứa [query string](https://en.wikipedia.org/wiki/Query_string). Mặc định là `{}`
- `req.body` - Một object chứa body được phân tích bởi `content-type`, hoặc `null` nếu không có body nào được gửi

### Custom config

Mỗi API Route có thể export một object `config` để thay đổi cấu hình mặc định, như sau:

```js
export const config = {
  api: {
    bodyParser: {
      sizeLimit: '1mb',
    },
  },
  // Specifies the maximum allowed duration for this function to execute (in seconds)
  maxDuration: 5,
}
```

`bodyParser` được bật tự động. Nếu bạn muốn tiêu thụ body như một `Stream` hoặc với [`raw-body`](https://www.npmjs.com/package/raw-body), bạn có thể đặt nó thành `false`.

Một trường hợp sử dụng để vô hiệu hóa `bodyParsing` tự động là cho phép bạn xác minh raw body của một **webhook** request, ví dụ [từ GitHub](https://docs.github.com/en/developers/webhooks-and-events/webhooks/securing-your-webhooks#validating-payloads-from-github).

```js
export const config = {
  api: {
    bodyParser: false,
  },
}
```

`bodyParser.sizeLimit` là kích thước tối đa cho phép cho parsed body, ở bất kỳ định dạng nào được hỗ trợ bởi [bytes](https://github.com/visionmedia/bytes.js), như sau:

```js
export const config = {
  api: {
    bodyParser: {
      sizeLimit: '500kb',
    },
  },
}
```

`externalResolver` là một cờ rõ ràng cho server biết rằng route này đang được xử lý bởi một external resolver như _express_ hoặc _connect_. Bật tùy chọn này sẽ vô hiệu hóa cảnh báo cho các requests chưa được giải quyết.

```js
export const config = {
  api: {
    externalResolver: true,
  },
}
```

`responseLimit` được bật tự động, cảnh báo khi response body của API Routes vượt quá 4MB.

Nếu bạn không sử dụng Next.js trong môi trường serverless, và hiểu các tác động hiệu suất của việc không sử dụng CDN hoặc dedicated media host, bạn có thể đặt giới hạn này thành `false`.

```js
export const config = {
  api: {
    responseLimit: false,
  },
}
```

`responseLimit` cũng có thể nhận số byte hoặc bất kỳ định dạng chuỗi nào được hỗ trợ bởi `bytes`, ví dụ `1000`, `'500kb'` hoặc `'3mb'`.
Giá trị này sẽ là kích thước response tối đa trước khi cảnh báo được hiển thị. Mặc định là 4MB. (xem ở trên)

```js
export const config = {
  api: {
    responseLimit: '8mb',
  },
}
```

## Response Helpers

[Server Response object](https://nodejs.org/api/http.html#http_class_http_serverresponse), (thường được viết tắt là `res`) bao gồm một tập hợp các phương thức helper giống như Express.js để cải thiện trải nghiệm nhà phát triển và tăng tốc độ tạo các API endpoints mới.

Các helpers bao gồm:

- `res.status(code)` - Một hàm để đặt status code. `code` phải là một [HTTP status code](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes) hợp lệ
- `res.json(body)` - Gửi một JSON response. `body` phải là một [serializable object](https://developer.mozilla.org/docs/Glossary/Serialization)
- `res.send(body)` - Gửi HTTP response. `body` có thể là một `string`, một `object` hoặc một `Buffer`
- `res.redirect([status,] path)` - Chuyển hướng đến một path hoặc URL được chỉ định. `status` phải là một [HTTP status code](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes) hợp lệ. Nếu không được chỉ định, `status` mặc định là "307" "Temporary redirect".
- `res.revalidate(urlPath)` - [Revalidate một trang theo yêu cầu](/docs/pages/guides/incremental-static-regeneration#on-demand-revalidation-with-revalidatepath) sử dụng `getStaticProps`. `urlPath` phải là một `string`.

### Đặt status code của một response

Khi gửi một response trở lại client, bạn có thể đặt status code của response.

Ví dụ sau đặt status code của response thành `200` (`OK`) và trả về một thuộc tính `message` với giá trị `Hello from Next.js!` dưới dạng JSON response:

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

type ResponseData = {
  message: string
}

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<ResponseData>
) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

```js filename="pages/api/hello.js" switcher
export default function handler(req, res) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

### Gửi một JSON response

Khi gửi một response trở lại client bạn có thể gửi một JSON response, đây phải là một [serializable object](https://developer.mozilla.org/docs/Glossary/Serialization).
Trong một ứng dụng thực tế, bạn có thể muốn cho client biết trạng thái của request tùy thuộc vào kết quả của endpoint được yêu cầu.

Ví dụ sau gửi một JSON response với status code `200` (`OK`) và kết quả của hoạt động không đồng bộ. Nó được chứa trong một khối try catch để xử lý bất kỳ lỗi nào có thể xảy ra, với status code và thông báo lỗi thích hợp được bắt và gửi lại cho client:

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  try {
    const result = await someAsyncOperation()
    res.status(200).json({ result })
  } catch (err) {
    res.status(500).json({ error: 'failed to load data' })
  }
}
```

```js filename="pages/api/hello.js" switcher
export default async function handler(req, res) {
  try {
    const result = await someAsyncOperation()
    res.status(200).json({ result })
  } catch (err) {
    res.status(500).json({ error: 'failed to load data' })
  }
}
```

### Gửi một HTTP response

Gửi một HTTP response hoạt động giống như khi gửi một JSON response. Sự khác biệt duy nhất là response body có thể là một `string`, một `object` hoặc một `Buffer`.

Ví dụ sau gửi một HTTP response với status code `200` (`OK`) và kết quả của hoạt động không đồng bộ.

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  try {
    const result = await someAsyncOperation()
    res.status(200).send({ result })
  } catch (err) {
    res.status(500).send({ error: 'failed to fetch data' })
  }
}
```

### Chuyển hướng đến một path hoặc URL được chỉ định

Lấy một form làm ví dụ, bạn có thể muốn chuyển hướng client của mình đến một path hoặc URL được chỉ định sau khi họ đã gửi form.

Ví dụ sau chuyển hướng client đến path `/` nếu form được gửi thành công:

```ts filename="pages/api/hello.ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  const { name, message } = req.body

  try {
    await handleFormInputAsync({ name, message })
    res.redirect(307, '/')
  } catch (err) {
    res.status(500).send({ error: 'Failed to fetch data' })
  }
}
```

### Thêm TypeScript types

Bạn có thể làm cho API Routes của mình an toàn về kiểu hơn bằng cách import các types `NextApiRequest` và `NextApiResponse` từ `next`, ngoài ra, bạn cũng có thể type response data của mình:

```ts
import type { NextApiRequest, NextApiResponse } from 'next'

type ResponseData = {
  message: string
}

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<ResponseData>
) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}
```

> **Nên biết**: Body của `NextApiRequest` là `any` vì client có thể bao gồm bất kỳ payload nào. Bạn nên validate type/shape của body tại runtime trước khi sử dụng nó.

## Dynamic API Routes

API Routes hỗ trợ [dynamic routes](/docs/pages/building-your-application/routing/dynamic-routes), và tuân theo các quy tắc đặt tên tệp giống như được sử dụng cho `pages/`.

```ts filename="pages/api/post/[pid].ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default function handler(req: NextApiRequest, res: NextApiResponse) {
  const { pid } = req.query
  res.end(`Post: ${pid}`)
}
```

```js filename="pages/api/post/[pid].js" switcher
export default function handler(req, res) {
  const { pid } = req.query
  res.end(`Post: ${pid}`)
}
```

Bây giờ, một request đến `/api/post/abc` sẽ phản hồi với văn bản: `Post: abc`.

### Catch all API routes

API Routes có thể được mở rộng để bắt tất cả các paths bằng cách thêm ba dấu chấm (`...`) bên trong dấu ngoặc. Ví dụ:

- `pages/api/post/[...slug].js` khớp với `/api/post/a`, nhưng cũng khớp với `/api/post/a/b`, `/api/post/a/b/c` và v.v.

> **Nên biết**: Bạn có thể sử dụng tên khác ngoài `slug`, chẳng hạn như: `[...param]`

Các tham số phù hợp sẽ được gửi dưới dạng query parameter (`slug` trong ví dụ) đến trang, và nó sẽ luôn là một mảng, vì vậy, path `/api/post/a` sẽ có object `query` sau:

```json
{ "slug": ["a"] }
```

Và trong trường hợp của `/api/post/a/b`, và bất kỳ path phù hợp nào khác, các tham số mới sẽ được thêm vào mảng, như sau:

```json
{ "slug": ["a", "b"] }
```

Ví dụ:

```ts filename="pages/api/post/[...slug].ts" switcher
import type { NextApiRequest, NextApiResponse } from 'next'

export default function handler(req: NextApiRequest, res: NextApiResponse) {
  const { slug } = req.query
  res.end(`Post: ${slug.join(', ')}`)
}
```

```js filename="pages/api/post/[...slug].js" switcher
export default function handler(req, res) {
  const { slug } = req.query
  res.end(`Post: ${slug.join(', ')}`)
}
```

Bây giờ, một request đến `/api/post/a/b/c` sẽ phản hồi với văn bản: `Post: a, b, c`.

### Optional catch all API routes

Catch all routes có thể được làm tùy chọn bằng cách bao gồm tham số trong dấu ngoặc kép (`[[...slug]]`).

Ví dụ, `pages/api/post/[[...slug]].js` sẽ khớp với `/api/post`, `/api/post/a`, `/api/post/a/b`, và v.v.

Sự khác biệt chính giữa catch all và optional catch all routes là với optional, route không có tham số cũng được khớp (`/api/post` trong ví dụ trên).

Các objects `query` như sau:

```json
{ } // GET `/api/post` (empty object)
{ "slug": ["a"] } // `GET /api/post/a` (single-element array)
{ "slug": ["a", "b"] } // `GET /api/post/a/b` (multi-element array)
```

### Caveats

- Các API routes được định nghĩa trước được ưu tiên hơn các dynamic API routes, và dynamic API routes hơn catch all API routes. Hãy xem các ví dụ sau:
  - `pages/api/post/create.js` - Sẽ khớp `/api/post/create`
  - `pages/api/post/[pid].js` - Sẽ khớp `/api/post/1`, `/api/post/abc`, v.v. Nhưng không khớp `/api/post/create`
  - `pages/api/post/[...slug].js` - Sẽ khớp `/api/post/1/2`, `/api/post/a/b/c`, v.v. Nhưng không khớp `/api/post/create`, `/api/post/abc`

## Streaming responses

Mặc dù Pages Router hỗ trợ streaming responses với API Routes, chúng tôi khuyên bạn nên dần dần áp dụng App Router và sử dụng [Route Handlers](/docs/app/api-reference/file-conventions/route) nếu bạn đang ở Next.js 14+.

Đây là cách bạn có thể stream một response từ một API Route với `writeHead`:

```ts filename="pages/api/hello.ts" switcher
import { NextApiRequest, NextApiResponse } from 'next'

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-store',
  })
  let i = 0
  while (i < 10) {
    res.write(`data: ${i}\n\n`)
    i++
    await new Promise((resolve) => setTimeout(resolve, 1000))
  }
  res.end()
}
```
