Trong [Tài liệu về các trang](/docs/pages/building-your-application/routing/pages-and-layouts) và [Tài liệu về tìm nạp dữ liệu](/docs/pages/building-your-application/data-fetching), chúng ta đã nói về cách kết xuất trước một trang tại thời điểm xây dựng (**Tạo tĩnh**) bằng cách sử dụng `getStaticProps` và `getStaticPaths`.

Tạo tĩnh hữu ích khi các trang của bạn tìm nạp dữ liệu từ một CMS không đầu. Tuy nhiên, nó không lý tưởng khi bạn đang viết một bản nháp trên CMS không đầu của mình và muốn xem bản nháp ngay lập tức trên trang của bạn. Bạn muốn Next.js kết xuất các trang này tại **thời điểm yêu cầu** thay vì thời điểm xây dựng và tìm nạp nội dung nháp thay vì nội dung đã xuất bản. Bạn muốn Next.js bỏ qua Tạo tĩnh chỉ cho trường hợp cụ thể này.

Next.js có một tính năng gọi là **Chế độ nháp** giúp giải quyết vấn đề này. Dưới đây là hướng dẫn cách sử dụng nó.

## Bước 1: Tạo và truy cập tuyến API

> Hãy xem [tài liệu về Tuyến API](/docs/pages/building-your-application/routing/api-routes) trước nếu bạn chưa quen với các Tuyến API của Next.js.

Đầu tiên, tạo **tuyến API**. Nó có thể có bất kỳ tên nào - ví dụ: `pages/api/draft.ts`

Trong tuyến API này, bạn cần gọi `setDraftMode` trên đối tượng phản hồi.

```js
export default function handler(req, res) {
  // ...
  res.setDraftMode({ enable: true })
  // ...
}
```

Thao tác này sẽ đặt một **cookie** để bật chế độ nháp. Các yêu cầu tiếp theo chứa cookie này sẽ kích hoạt **Chế độ nháp** thay đổi hành vi cho các trang được tạo tĩnh (sẽ nói thêm về điều này sau).

Bạn có thể kiểm tra điều này theo cách thủ công bằng cách tạo một tuyến API như bên dưới và truy cập nó từ trình duyệt của bạn theo cách thủ công:

```ts filename="pages/api/draft.ts"
// ví dụ đơn giản để kiểm tra thủ công từ trình duyệt của bạn.
export default function handler(req, res) {
  res.setDraftMode({ enable: true })
  res.end('Chế độ nháp đã được bật')
}
```

Nếu bạn mở các công cụ dành cho nhà phát triển của trình duyệt và truy cập `/api/draft`, bạn sẽ nhận thấy một tiêu đề phản hồi `Set-Cookie` với một cookie có tên `__prerender_bypass`.

### Truy cập an toàn từ CMS không đầu của bạn

Trong thực tế, bạn sẽ muốn gọi tuyến API này _an toàn_ từ CMS không đầu của mình. Các bước cụ thể sẽ khác nhau tùy thuộc vào CMS không đầu bạn đang sử dụng, nhưng đây là một số bước phổ biến bạn có thể thực hiện.

Các bước này giả định rằng CMS không đầu bạn đang sử dụng hỗ trợ cài đặt **URL nháp tùy chỉnh**. Nếu không, bạn vẫn có thể sử dụng phương pháp này để bảo mật các URL nháp của mình, nhưng bạn sẽ cần phải tạo và truy cập URL nháp theo cách thủ công.

**Đầu tiên**, bạn nên tạo một **chuỗi mã thông báo bí mật** bằng cách sử dụng một trình tạo mã thông báo tùy chọn của bạn. Bí mật này sẽ chỉ được ứng dụng Next.js và CMS không đầu của bạn biết. Bí mật này ngăn những người không có quyền truy cập vào CMS của bạn truy cập các URL nháp.

**Thứ hai**, nếu CMS không đầu của bạn hỗ trợ cài đặt URL nháp tùy chỉnh, hãy chỉ định URL sau làm URL nháp. Điều này giả định rằng tuyến API nháp của bạn được đặt tại `pages/api/draft.ts`.

```bash filename="Terminal"
https://<your-site>/api/draft?secret=<token>&slug=<path>
```

- `<your-site>` phải là miền triển khai của bạn.
- `<token>` phải được thay thế bằng mã thông báo bí mật bạn đã tạo.
- `<path>` phải là đường dẫn cho trang bạn muốn xem. Nếu bạn muốn xem `/posts/foo`, thì bạn nên sử dụng `&slug=/posts/foo`.

CMS không đầu của bạn có thể cho phép bạn bao gồm một biến trong URL nháp để `<path>` có thể được đặt động dựa trên dữ liệu của CMS như sau: `&slug=/posts/{entry.fields.slug}`

**Cuối cùng**, trong tuyến API nháp:

- Kiểm tra xem bí mật có khớp không và tham số `slug` có tồn tại không (nếu không, yêu cầu sẽ không thành công).
-
- Gọi `res.setDraftMode`.
- Sau đó chuyển hướng trình duyệt đến đường dẫn được chỉ định bởi `slug`. (Ví dụ sau sử dụng [chuyển hướng 307](https://developer.mozilla.org/docs/Web/HTTP/Status/307)).

```js
export default async (req, res) => {
  // Kiểm tra bí mật và các tham số tiếp theo
  // Bí mật này chỉ nên được biết đến bởi tuyến API này và CMS
  if (req.query.secret !== 'MY_SECRET_TOKEN' || !req.query.slug) {
    return res.status(401).json({ message: 'Mã thông báo không hợp lệ' })
  }

  // Tìm nạp CMS không đầu để kiểm tra xem `slug` được cung cấp có tồn tại không
  // getPostBySlug sẽ triển khai logic tìm nạp cần thiết cho CMS không đầu
  const post = await getPostBySlug(req.query.slug)

  // Nếu slug không tồn tại, hãy ngăn chế độ nháp được bật
  if (!post) {
    return res.status(401).json({ message: 'Slug không hợp lệ' })
  }

  // Bật Chế độ nháp bằng cách đặt cookie
  res.setDraftMode({ enable: true })

  // Chuyển hướng đến đường dẫn từ bài đăng được tìm nạp
  // Chúng tôi không chuyển hướng đến req.query.slug vì điều đó có thể dẫn đến các lỗ hổng chuyển hướng mở
  res.redirect(post.slug)
}
```

Nếu thành công, trình duyệt sẽ được chuyển hướng đến đường dẫn bạn muốn xem với cookie chế độ nháp.

## Bước 2: Cập nhật `getStaticProps`

Bước tiếp theo là cập nhật `getStaticProps` để hỗ trợ chế độ nháp.

Nếu bạn yêu cầu một trang có `getStaticProps` với cookie được đặt (thông qua `res.setDraftMode`), thì `getStaticProps` sẽ được gọi tại **thời điểm yêu cầu** (thay vì tại thời điểm xây dựng).

Hơn nữa, nó sẽ được gọi với một đối tượng `context` trong đó `context.draftMode` sẽ là `true`.

```js
export async function getStaticProps(context) {
  if (context.draftMode) {
    // dữ liệu động
  }
}
```

Chúng tôi đã sử dụng `res.setDraftMode` trong tuyến API nháp, vì vậy `context.draftMode` sẽ là `true`.

Nếu bạn cũng đang sử dụng `getStaticPaths`, thì `context.params` cũng sẽ có sẵn.

### Tìm nạp dữ liệu nháp

Bạn có thể cập nhật `getStaticProps` để tìm nạp dữ liệu khác nhau dựa trên `context.draftMode`.

Ví dụ, CMS không đầu của bạn có thể có một điểm cuối API khác cho các bài đăng nháp. Nếu vậy, bạn có thể sửa đổi URL điểm cuối API như bên dưới:

```js
export async function getStaticProps(context) {
  const url = context.draftMode
    ? 'https://draft.example.com'
    : 'https://production.example.com'
  const res = await fetch(url)
  // ...
}
```

Vậy là xong! Nếu bạn truy cập tuyến API nháp (với `secret` và `slug`) từ CMS không đầu của bạn hoặc theo cách thủ công, bây giờ bạn sẽ có thể xem nội dung nháp. Và nếu bạn cập nhật bản nháp của mình mà không xuất bản, bạn sẽ có thể xem bản nháp.

Đặt đây làm URL nháp trên CMS không đầu của bạn hoặc truy cập theo cách thủ công, và bạn sẽ có thể xem bản nháp.

```bash filename="Terminal"
https://<your-site>/api/draft?secret=<token>&slug=<path>
```

## Thông tin thêm

### Xóa cookie Chế độ nháp

Theo mặc định, phiên Chế độ nháp kết thúc khi trình duyệt được đóng.

Để xóa cookie Chế độ nháp theo cách thủ công, hãy tạo một tuyến API gọi `setDraftMode({ enable: false })`:

```ts filename="pages/api/disable-draft.ts"
export default function handler(req, res) {
  res.setDraftMode({ enable: false })
}
```

Sau đó, gửi một yêu cầu đến `/api/disable-draft` để gọi Tuyến API. Nếu gọi tuyến này bằng [`next/link`](/docs/pages/api-reference/components/link), bạn phải chuyển `prefetch={false}` để ngăn việc vô tình xóa cookie khi tìm nạp trước.

### Hoạt động với `getServerSideProps`

Chế độ nháp hoạt động với `getServerSideProps` và có sẵn dưới dạng khóa `draftMode` trong đối tượng [`context`](/docs/pages/api-reference/functions/get-server-side-props#context-parameter).

> **Cần biết**: Bạn không nên đặt tiêu đề `Cache-Control` khi sử dụng Chế độ nháp vì nó không thể bị bỏ qua. Thay vào đó, chúng tôi khuyên bạn nên sử dụng [ISR](/docs/pages/guides/incremental-static-regeneration).

### Hoạt động với các Tuyến API

Các Tuyến API sẽ có quyền truy cập vào `draftMode` trên đối tượng yêu cầu. Ví dụ:

```js
export default function myApiRoute(req, res) {
  if (req.draftMode) {
    // lấy dữ liệu nháp
  }
}
```

### Duy nhất cho mỗi `next build`

Một giá trị cookie bỏ qua mới sẽ được tạo mỗi khi bạn chạy `next build`.

Điều này đảm bảo rằng cookie bỏ qua không thể được đoán.

> **Cần biết**: Để kiểm tra Chế độ nháp cục bộ qua HTTP, trình duyệt của bạn sẽ cần cho phép cookie của bên thứ ba và quyền truy cập bộ nhớ cục bộ.
