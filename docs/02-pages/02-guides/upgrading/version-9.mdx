Để nâng cấp lên phiên bản 9, hãy chạy lệnh sau:

```bash filename="Terminal"
npm i next@9
```

```bash filename="Terminal"
yarn add next@9
```

```bash filename="Terminal"
pnpm up next@9
```

```bash filename="Terminal"
bun add next@9
```

> **Nên biết:** Nếu bạn đang sử dụng TypeScript, hãy đảm bảo bạn cũng nâng cấp `@types/react` và `@types/react-dom` lên các phiên bản tương ứng của chúng.

## Kiểm tra Custom App File (`pages/_app.js`) của bạn

Nếu trước đây bạn đã sao chép ví dụ [Custom `<App>`](/docs/pages/building-your-application/routing/custom-app), bạn có thể loại bỏ `getInitialProps` của mình.

Việc loại bỏ `getInitialProps` khỏi `pages/_app.js` (khi có thể) là quan trọng để tận dụng các tính năng mới của Next.js!

`getInitialProps` sau đây không làm gì cả và có thể bị loại bỏ:

```js
class MyApp extends App {
  // Remove me, I do nothing!
  static async getInitialProps({ Component, ctx }) {
    let pageProps = {}

    if (Component.getInitialProps) {
      pageProps = await Component.getInitialProps(ctx)
    }

    return { pageProps }
  }

  render() {
    // ... etc
  }
}
```

## Những thay đổi đột phá (Breaking Changes)

### `@zeit/next-typescript` không còn cần thiết nữa

Next.js bây giờ sẽ bỏ qua việc sử dụng `@zeit/next-typescript` và cảnh báo bạn loại bỏ nó. Vui lòng loại bỏ plugin này khỏi `next.config.js` của bạn.

Loại bỏ các tham chiếu đến `@zeit/next-typescript/babel` khỏi `.babelrc` tùy chỉnh của bạn (nếu có).

Việc sử dụng [`fork-ts-checker-webpack-plugin`](https://github.com/Realytics/fork-ts-checker-webpack-plugin/issues) cũng nên được loại bỏ khỏi `next.config.js` của bạn.

TypeScript Definitions được publish cùng với gói `next`, vì vậy bạn cần gỡ cài đặt `@types/next` vì chúng sẽ xung đột.

Các types sau đây là khác nhau:

> Danh sách này được tạo bởi cộng đồng để giúp bạn nâng cấp, nếu bạn tìm thấy những khác biệt khác vui lòng gửi pull-request vào danh sách này để giúp những người dùng khác.

Từ:

```tsx
import { NextContext } from 'next'
import { NextAppContext, DefaultAppIProps } from 'next/app'
import { NextDocumentContext, DefaultDocumentIProps } from 'next/document'
```

thành

```tsx
import { NextPageContext } from 'next'
import { AppContext, AppInitialProps } from 'next/app'
import { DocumentContext, DocumentInitialProps } from 'next/document'
```

### Key `config` bây giờ là một export trên một trang

Bạn không thể export một biến tùy chỉnh có tên `config` từ một trang nữa (ví dụ: `export { config }` / `export const config ...`).
Biến được export này hiện được sử dụng để chỉ định cấu hình Next.js cấp trang như Opt-in AMP và các tính năng API Route.

Bạn phải đổi tên export `config` không dành cho mục đích Next.js thành một cái gì đó khác.

### `next/dynamic` không còn render "loading..." theo mặc định trong khi tải

Dynamic components sẽ không render bất cứ thứ gì theo mặc định trong khi tải. Bạn vẫn có thể tùy chỉnh hành vi này bằng cách đặt thuộc tính `loading`:

```jsx
import dynamic from 'next/dynamic'

const DynamicComponentWithCustomLoading = dynamic(
  () => import('../components/hello2'),
  {
    loading: () => <p>Loading</p>,
  }
)
```

### `withAmp` đã bị loại bỏ để ủng hộ configuration object được export

Next.js hiện có khái niệm cấu hình cấp trang, vì vậy higher-order component `withAmp` đã bị loại bỏ để nhất quán.

Thay đổi này có thể được **tự động di chuyển bằng cách chạy các lệnh sau trong thư mục gốc của dự án Next.js của bạn:**

```bash filename="Terminal"
curl -L https://github.com/vercel/next-codemod/archive/master.tar.gz | tar -xz --strip=2 next-codemod-master/transforms/withamp-to-config.js npx jscodeshift -t ./withamp-to-config.js pages/**/*.js
```

Để thực hiện việc di chuyển này bằng tay, hoặc xem những gì codemod sẽ tạo ra, xem bên dưới:

**Trước**

```jsx
import { withAmp } from 'next/amp'

function Home() {
  return <h1>My AMP Page</h1>
}

export default withAmp(Home)
// or
export default withAmp(Home, { hybrid: true })
```

**Sau**

```jsx
export default function Home() {
  return <h1>My AMP Page</h1>
}

export const config = {
  amp: true,
  // or
  amp: 'hybrid',
}
```

### `next export` không còn export các trang dưới dạng `index.html`

Trước đây, việc export `pages/about.js` sẽ dẫn đến `out/about/index.html`. Hành vi này đã được thay đổi để dẫn đến `out/about.html`.

Bạn có thể quay lại hành vi trước đó bằng cách tạo `next.config.js` với nội dung sau:

```js filename="next.config.js"
module.exports = {
  trailingSlash: true,
}
```

### `pages/api/` được xử lý khác biệt

Các trang trong `pages/api/` hiện được coi là [API Routes](https://nextjs.org/blog/next-9#api-routes).
Các trang trong thư mục này sẽ không còn chứa client-side bundle.

## Các tính năng đã Deprecated

### `next/dynamic` đã deprecate việc tải nhiều modules cùng lúc

Khả năng tải nhiều modules cùng lúc đã bị deprecate trong `next/dynamic` để gần hơn với implementation của React (`React.lazy` và `Suspense`).

Cập nhật code dựa trên hành vi này tương đối đơn giản! Chúng tôi đã cung cấp một ví dụ trước/sau để giúp bạn di chuyển ứng dụng của mình:

**Trước**

```jsx
import dynamic from 'next/dynamic'

const HelloBundle = dynamic({
  modules: () => {
    const components = {
      Hello1: () => import('../components/hello1').then((m) => m.default),
      Hello2: () => import('../components/hello2').then((m) => m.default),
    }

    return components
  },
  render: (props, { Hello1, Hello2 }) => (
    <div>
      <h1>{props.title}</h1>
      <Hello1 />
      <Hello2 />
    </div>
  ),
})

function DynamicBundle() {
  return <HelloBundle title="Dynamic Bundle" />
}

export default DynamicBundle
```

**Sau**

```jsx
import dynamic from 'next/dynamic'

const Hello1 = dynamic(() => import('../components/hello1'))
const Hello2 = dynamic(() => import('../components/hello2'))

function HelloBundle({ title }) {
  return (
    <div>
      <h1>{title}</h1>
      <Hello1 />
      <Hello2 />
    </div>
  )
}

function DynamicBundle() {
  return <HelloBundle title="Dynamic Bundle" />
}

export default DynamicBundle
```
