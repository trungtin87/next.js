Để nâng cấp lên phiên bản 11, hãy chạy lệnh sau:

```bash filename="Terminal"
npm i next@11 react@17 react-dom@17
```

```bash filename="Terminal"
yarn add next@11 react@17 react-dom@17
```

```bash filename="Terminal"
pnpm up next@11 react@17 react-dom@17
```

```bash filename="Terminal"
bun add next@11 react@17 react-dom@17
```

> **Nên biết:** Nếu bạn đang sử dụng TypeScript, hãy đảm bảo bạn cũng nâng cấp `@types/react` và `@types/react-dom` lên các phiên bản tương ứng của chúng.

### Webpack 5

Webpack 5 hiện là mặc định cho tất cả các ứng dụng Next.js. Nếu bạn không có cấu hình webpack tùy chỉnh, ứng dụng của bạn đã sử dụng webpack 5. Nếu bạn có cấu hình webpack tùy chỉnh, bạn có thể tham khảo [tài liệu Next.js webpack 5](/docs/messages/webpack5) để được hướng dẫn nâng cấp.

### Dọn dẹp `distDir` hiện là mặc định

Thư mục build output (mặc định là `.next`) hiện được xóa theo mặc định ngoại trừ Next.js caches. Bạn có thể tham khảo [RFC dọn dẹp `distDir`](https://github.com/vercel/next.js/discussions/6009) để biết thêm thông tin.

Nếu ứng dụng của bạn dựa vào hành vi này trước đây, bạn có thể vô hiệu hóa hành vi mặc định mới bằng cách thêm cờ `cleanDistDir: false` trong `next.config.js`.

### `PORT` hiện được hỗ trợ cho `next dev` và `next start`

Next.js 11 hỗ trợ biến môi trường `PORT` để đặt cổng mà ứng dụng chạy trên đó. Sử dụng `-p`/`--port` vẫn được khuyến nghị nhưng nếu bạn bị cấm sử dụng `-p` theo bất kỳ cách nào, bạn có thể sử dụng `PORT` như một giải pháp thay thế:

Ví dụ:

```
PORT=4000 next start
```

### Tùy chỉnh `next.config.js` để import hình ảnh

Next.js 11 hỗ trợ static image imports với `next/image`. Tính năng mới này dựa vào khả năng xử lý image imports. Nếu bạn trước đây đã thêm các gói `next-images` hoặc `next-optimized-images`, bạn có thể chuyển sang hỗ trợ tích hợp mới bằng cách sử dụng `next/image` hoặc vô hiệu hóa tính năng này:

```js filename="next.config.js"
module.exports = {
  images: {
    disableStaticImages: true,
  },
}
```

### Loại bỏ `super.componentDidCatch()` khỏi `pages/_app.js`

`componentDidCatch` của component `next/app` đã bị deprecate trong Next.js 9 vì nó không còn cần thiết và kể từ đó đã là no-op. Trong Next.js 11, nó đã bị loại bỏ.

Nếu `pages/_app.js` của bạn có phương thức `componentDidCatch` tùy chỉnh, bạn có thể loại bỏ `super.componentDidCatch` vì nó không còn cần thiết.

### Loại bỏ `Container` khỏi `pages/_app.js`

Export này đã bị deprecate trong Next.js 9 vì nó không còn cần thiết và kể từ đó đã là no-op với một cảnh báo trong quá trình phát triển. Trong Next.js 11, nó đã bị loại bỏ.

Nếu `pages/_app.js` của bạn import `Container` từ `next/app`, bạn có thể loại bỏ `Container` vì nó đã bị loại bỏ. Tìm hiểu thêm trong [tài liệu](/docs/messages/app-container-deprecated).

### Loại bỏ việc sử dụng `props.url` từ page components

Thuộc tính này đã bị deprecate trong Next.js 4 và kể từ đó đã hiển thị cảnh báo trong quá trình phát triển. Với sự ra đời của `getStaticProps` / `getServerSideProps`, các phương thức này đã không cho phép sử dụng `props.url`. Trong Next.js 11, nó đã bị loại bỏ hoàn toàn.

Bạn có thể tìm hiểu thêm trong [tài liệu](/docs/messages/url-deprecated).

### Loại bỏ thuộc tính `unsized` trên `next/image`

Thuộc tính `unsized` trên `next/image` đã bị deprecate trong Next.js 10.0.1. Bạn có thể sử dụng `layout="fill"` thay thế. Trong Next.js 11 `unsized` đã bị loại bỏ.

### Loại bỏ thuộc tính `modules` trên `next/dynamic`

Tùy chọn `modules` và `render` cho `next/dynamic` đã bị deprecate trong Next.js 9.5. Điều này được thực hiện để làm cho API `next/dynamic` gần hơn với `React.lazy`. Trong Next.js 11, các tùy chọn `modules` và `render` đã bị loại bỏ.

Tùy chọn này chưa được đề cập trong tài liệu kể từ Next.js 8 nên ít có khả năng ứng dụng của bạn đang sử dụng nó.

Nếu ứng dụng của bạn sử dụng `modules` và `render`, bạn có thể tham khảo [tài liệu](/docs/messages/next-dynamic-modules).

### Loại bỏ `Head.rewind`

`Head.rewind` đã là no-op kể từ Next.js 9.5, trong Next.js 11 nó đã bị loại bỏ. Bạn có thể loại bỏ việc sử dụng `Head.rewind` một cách an toàn.

### Moment.js locales bị loại trừ theo mặc định

Moment.js bao gồm các bản dịch cho rất nhiều locales theo mặc định. Next.js hiện tự động loại trừ các locales này theo mặc định để tối ưu hóa kích thước bundle cho các ứng dụng sử dụng Moment.js.

Để tải một locale cụ thể, hãy sử dụng đoạn mã này:

```js
import moment from 'moment'
import 'moment/locale/ja'

moment.locale('ja')
```

Bạn có thể chọn không tham gia mặc định mới này bằng cách thêm `excludeDefaultMomentLocales: false` vào `next.config.js` nếu bạn không muốn hành vi mới, nhưng lưu ý rằng rất khuyến khích không vô hiệu hóa tối ưu hóa mới này vì nó giảm đáng kể kích thước của Moment.js.

### Cập nhật việc sử dụng `router.events`

Trong trường hợp bạn đang truy cập `router.events` trong quá trình render, trong Next.js 11 `router.events` không còn được cung cấp trong quá trình pre-rendering. Đảm bảo bạn đang truy cập `router.events` trong `useEffect`:

```js
useEffect(() => {
  const handleRouteChange = (url, { shallow }) => {
    console.log(
      `App is changing to ${url} ${
        shallow ? 'with' : 'without'
      } shallow routing`
    )
  }

  router.events.on('routeChangeStart', handleRouteChange)

  // If the component is unmounted, unsubscribe
  // from the event with the `off` method:
  return () => {
    router.events.off('routeChangeStart', handleRouteChange)
  }
}, [router])
```

Nếu ứng dụng của bạn sử dụng `router.router.events` là một thuộc tính nội bộ không công khai, vui lòng đảm bảo sử dụng `router.events` thay thế.

## React 16 lên 17

React 17 giới thiệu một [JSX Transform](https://reactjs.org/blog/2020/09/22/introducing-the-new-jsx-transform.html) mới mang lại một tính năng Next.js lâu đời cho hệ sinh thái React rộng lớn hơn: Không cần phải `import React from 'react'` khi sử dụng JSX. Khi sử dụng React 17 Next.js sẽ tự động sử dụng transform mới. Transform này không làm cho biến `React` trở thành toàn cục, đây là một tác dụng phụ không mong muốn của triển khai Next.js trước đó. Một [codemod có sẵn](/docs/pages/guides/upgrading/codemods#add-missing-react-import) để tự động sửa các trường hợp bạn vô tình sử dụng `React` mà không import nó.

Hầu hết các ứng dụng đã sử dụng phiên bản mới nhất của React, với Next.js 11 phiên bản React tối thiểu đã được cập nhật lên 17.0.2.

Để nâng cấp bạn có thể chạy lệnh sau:

```
npm install react@latest react-dom@latest
```

Hoặc sử dụng `yarn`:

```
yarn add react@latest react-dom@latest
```
