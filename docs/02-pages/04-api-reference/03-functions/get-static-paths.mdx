Khi export một hàm có tên `getStaticPaths` từ một trang sử dụng [Dynamic Routes](/docs/pages/building-your-application/routing/dynamic-routes), Next.js sẽ pre-render tĩnh tất cả các paths được chỉ định bởi `getStaticPaths`.

```tsx filename="pages/repo/[name].tsx" switcher
import type {
  InferGetStaticPropsType,
  GetStaticProps,
  GetStaticPaths,
} from 'next'

type Repo = {
  name: string
  stargazers_count: number
}

export const getStaticPaths = (async () => {
  return {
    paths: [
      {
        params: {
          name: 'next.js',
        },
      }, // Xem phần "paths" bên dưới
    ],
    fallback: true, // false hoặc "blocking"
  }
}) satisfies GetStaticPaths

export const getStaticProps = (async (context) => {
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  return { props: { repo } }
}) satisfies GetStaticProps<{
  repo: Repo
}>

export default function Page({
  repo,
}: InferGetStaticPropsType<typeof getStaticProps>) {
  return repo.stargazers_count
}
```

```jsx filename="pages/repo/[name].js" switcher
export async function getStaticPaths() {
  return {
    paths: [
      {
        params: {
          name: 'next.js',
        },
      }, // Xem phần "paths" bên dưới
    ],
    fallback: true, // false hoặc "blocking"
  }
}

export async function getStaticProps() {
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  return { props: { repo } }
}

export default function Page({ repo }) {
  return repo.stargazers_count
}
```

## Giá trị trả về của getStaticPaths

Hàm `getStaticPaths` nên trả về một object với các thuộc tính **bắt buộc** sau:

### `paths`

Key `paths` xác định những paths nào sẽ được pre-rendered. Ví dụ, giả sử bạn có một trang sử dụng [Dynamic Routes](/docs/pages/building-your-application/routing/dynamic-routes) có tên `pages/posts/[id].js`. Nếu bạn export `getStaticPaths` từ trang này và trả về như sau cho `paths`:

```js
return {
  paths: [
    { params: { id: '1' }},
    {
      params: { id: '2' },
      // với i18n được cấu hình, locale cho path cũng có thể được trả về
      locale: "en",
    },
  ],
  fallback: ...
}
```

Sau đó, Next.js sẽ tạo tĩnh `/posts/1` và `/posts/2` trong quá trình `next build` bằng cách sử dụng page component trong `pages/posts/[id].js`.

Giá trị cho mỗi object `params` phải khớp với các tham số được sử dụng trong tên trang:

- Nếu tên trang là `pages/posts/[postId]/[commentId]`, thì `params` nên chứa `postId` và `commentId`.
- Nếu tên trang sử dụng [catch-all routes](/docs/pages/building-your-application/routing/dynamic-routes#catch-all-segments) như `pages/[...slug]`, thì `params` nên chứa `slug` (là một mảng). Nếu mảng này là `['hello', 'world']`, thì Next.js sẽ tạo tĩnh trang tại `/hello/world`.
- Nếu trang sử dụng [optional catch-all route](/docs/pages/building-your-application/routing/dynamic-routes#optional-catch-all-segments), sử dụng `null`, `[]`, `undefined` hoặc `false` để render route gốc nhất. Ví dụ, nếu bạn cung cấp `slug: false` cho `pages/[[...slug]]`, Next.js sẽ tạo tĩnh trang `/`.

Các chuỗi `params` **phân biệt chữ hoa chữ thường** và lý tưởng nên được chuẩn hóa để đảm bảo các paths được tạo chính xác. Ví dụ, nếu `WoRLD` được trả về cho một param, nó sẽ chỉ khớp nếu `WoRLD` là path thực tế được truy cập, không phải `world` hoặc `World`.

Tách biệt với object `params`, một trường `locale` có thể được trả về khi [i18n được cấu hình](/docs/pages/guides/internationalization), cấu hình locale cho path đang được tạo.

### `fallback: false`

Nếu `fallback` là `false`, thì bất kỳ paths nào không được trả về bởi `getStaticPaths` sẽ dẫn đến **404 page**.

Khi `next build` được chạy, Next.js sẽ kiểm tra nếu `getStaticPaths` trả về `fallback: false`, sau đó nó sẽ build **chỉ** các paths được trả về bởi `getStaticPaths`. Tùy chọn này hữu ích nếu bạn có một số lượng nhỏ paths để tạo, hoặc dữ liệu trang mới không được thêm thường xuyên. Nếu bạn thấy rằng bạn cần thêm nhiều paths hơn, và bạn có `fallback: false`, bạn sẽ cần chạy lại `next build` để các paths mới có thể được tạo.

Ví dụ sau pre-renders một bài đăng blog cho mỗi trang có tên `pages/posts/[id].js`. Danh sách các bài đăng blog sẽ được fetch từ CMS và được trả về bởi `getStaticPaths`. Sau đó, cho mỗi trang, nó fetch dữ liệu bài đăng từ CMS bằng cách sử dụng [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props).

```jsx filename="pages/posts/[id].js"
function Post({ post }) {
  // Render post...
}

// Hàm này được gọi tại thời điểm build
export async function getStaticPaths() {
  // Gọi một API endpoint bên ngoài để lấy posts
  const res = await fetch('https://.../posts')
  const posts = await res.json()

  // Lấy các paths chúng ta muốn pre-render dựa trên posts
  const paths = posts.map((post) => ({
    params: { id: post.id },
  }))

  // Chúng ta sẽ chỉ pre-render các paths này tại thời điểm build.
  // { fallback: false } có nghĩa là các routes khác nên 404.
  return { paths, fallback: false }
}

// Hàm này cũng được gọi tại thời điểm build
export async function getStaticProps({ params }) {
  // params chứa post `id`.
  // Nếu route là /posts/1, thì params.id là 1
  const res = await fetch(`https://.../posts/${params.id}`)
  const post = await res.json()

  // Truyền dữ liệu post cho trang thông qua props
  return { props: { post } }
}

export default Post
```

### `fallback: true`

Nếu `fallback` là `true`, thì hành vi của `getStaticProps` thay đổi theo các cách sau:

- Các paths được trả về từ `getStaticPaths` sẽ được render thành `HTML` tại thời điểm build bởi `getStaticProps`.
- Các paths chưa được tạo tại thời điểm build sẽ **không** dẫn đến trang 404. Thay vào đó, Next.js sẽ phục vụ một phiên bản ["fallback"](#fallback-pages) của trang trên request đầu tiên đến path đó. Web crawlers, như Google, sẽ không được phục vụ fallback và thay vào đó path sẽ hoạt động như trong [`fallback: 'blocking'`](#fallback-blocking).
- Khi một trang với `fallback: true` được điều hướng đến thông qua `next/link` hoặc `next/router` (phía client) Next.js sẽ _không_ phục vụ fallback và thay vào đó trang sẽ hoạt động như [`fallback: 'blocking'`](#fallback-blocking).
- Trong background, Next.js sẽ tạo tĩnh `HTML` và `JSON` của path được yêu cầu. Điều này bao gồm việc chạy `getStaticProps`.
- Khi hoàn thành, trình duyệt nhận `JSON` cho path được tạo. Điều này sẽ được sử dụng để tự động render trang với các props cần thiết. Từ góc độ của người dùng, trang sẽ được chuyển từ trang fallback sang trang đầy đủ.
- Đồng thời, Next.js thêm path này vào danh sách các trang đã pre-rendered. Các requests tiếp theo đến cùng một path sẽ phục vụ trang được tạo, giống như các trang khác được pre-rendered tại thời điểm build.

> **Nên biết**: `fallback: true` không được hỗ trợ khi sử dụng [`output: 'export'`](/docs/pages/guides/static-exports).

#### Khi nào `fallback: true` hữu ích?

`fallback: true` hữu ích nếu ứng dụng của bạn có một số lượng rất lớn các trang tĩnh phụ thuộc vào dữ liệu (như một trang web thương mại điện tử rất lớn). Nếu bạn muốn pre-render tất cả các trang sản phẩm, các bản build sẽ mất rất nhiều thời gian.

Thay vào đó, bạn có thể tạo tĩnh một tập hợp con nhỏ các trang và sử dụng `fallback: true` cho phần còn lại. Khi ai đó yêu cầu một trang chưa được tạo, người dùng sẽ thấy trang với một loading indicator hoặc skeleton component.

Ngay sau đó, `getStaticProps` hoàn thành và trang sẽ được render với dữ liệu được yêu cầu. Từ bây giờ, mọi người yêu cầu cùng một trang sẽ nhận được trang đã pre-rendered tĩnh.

Điều này đảm bảo rằng người dùng luôn có trải nghiệm nhanh trong khi vẫn bảo toàn các bản build nhanh và lợi ích của Static Generation.

`fallback: true` sẽ không _cập nhật_ các trang đã tạo, để làm điều đó hãy xem [Incremental Static Regeneration](/docs/pages/guides/incremental-static-regeneration).

### `fallback: 'blocking'`

Nếu `fallback` là `'blocking'`, các paths mới không được trả về bởi `getStaticPaths` sẽ đợi `HTML` được tạo, giống hệt như SSR (do đó tại sao _blocking_), và sau đó được cache cho các requests trong tương lai nên nó chỉ xảy ra một lần cho mỗi path.

`getStaticProps` sẽ hoạt động như sau:

- Các paths được trả về từ `getStaticPaths` sẽ được render thành `HTML` tại thời điểm build bởi `getStaticProps`.
- Các paths chưa được tạo tại thời điểm build sẽ **không** dẫn đến trang 404. Thay vào đó, Next.js sẽ SSR trên request đầu tiên và trả về `HTML` được tạo.
- Khi hoàn thành, trình duyệt nhận `HTML` cho path được tạo. Từ góc độ của người dùng, nó sẽ chuyển từ "trình duyệt đang yêu cầu trang" sang "trang đầy đủ được tải". Không có flash của loading/fallback state.
- Đồng thời, Next.js thêm path này vào danh sách các trang đã pre-rendered. Các requests tiếp theo đến cùng một path sẽ phục vụ trang được tạo, giống như các trang khác được pre-rendered tại thời điểm build.

`fallback: 'blocking'` sẽ không _cập nhật_ các trang đã tạo theo mặc định. Để cập nhật các trang đã tạo, sử dụng [Incremental Static Regeneration](/docs/pages/guides/incremental-static-regeneration) kết hợp với `fallback: 'blocking'`.

> **Nên biết**: `fallback: 'blocking'` không được hỗ trợ khi sử dụng [`output: 'export'`](/docs/pages/guides/static-exports).

### Fallback pages

Trong phiên bản "fallback" của một trang:

- Props của trang sẽ trống.
- Sử dụng [router](/docs/pages/api-reference/functions/use-router), bạn có thể phát hiện nếu fallback đang được render, `router.isFallback` sẽ là `true`.

Ví dụ sau cho thấy cách sử dụng `isFallback`:

```jsx filename="pages/posts/[id].js"
import { useRouter } from 'next/router'

function Post({ post }) {
  const router = useRouter()

  // Nếu trang chưa được tạo, điều này sẽ được hiển thị
  // ban đầu cho đến khi getStaticProps() hoàn thành việc chạy
  if (router.isFallback) {
    return <div>Loading...</div>
  }

  // Render post...
}

// Hàm này được gọi tại thời điểm build
export async function getStaticPaths() {
  return {
    // Chỉ `/posts/1` và `/posts/2` được tạo tại thời điểm build
    paths: [{ params: { id: '1' } }, { params: { id: '2' } }],
    // Kích hoạt việc tạo tĩnh các trang bổ sung
    // Ví dụ: `/posts/3`
    fallback: true,
  }
}

// Hàm này cũng được gọi tại thời điểm build
export async function getStaticProps({ params }) {
  // params chứa post `id`.
  // Nếu route là /posts/1, thì params.id là 1
  const res = await fetch(`https://.../posts/${params.id}`)
  const post = await res.json()

  // Truyền dữ liệu post cho trang thông qua props
  return {
    props: { post },
    // Re-generate post nhiều nhất một lần mỗi giây
    // nếu có request đến
    revalidate: 1,
  }
}

export default Post
```
