---

Export một hàm có tên `getStaticProps` sẽ pre-render một trang tại thời điểm build bằng cách sử dụng props được trả về từ hàm:

```tsx filename="pages/index.tsx" switcher
import type { InferGetStaticPropsType, GetStaticProps } from 'next'

type Repo = {
  name: string
  stargazers_count: number
}

export const getStaticProps = (async (context) => {
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  return { props: { repo } }
}) satisfies GetStaticProps<{
  repo: Repo
}>

export default function Page({
  repo,
}: InferGetStaticPropsType<typeof getStaticProps>) {
  return repo.stargazers_count
}
```

```jsx filename="pages/index.js" switcher
export async function getStaticProps() {
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  return { props: { repo } }
}

export default function Page({ repo }) {
  return repo.stargazers_count
}
```

Bạn có thể import các modules trong top-level scope để sử dụng trong `getStaticProps`. Các imports được sử dụng sẽ **không được đóng gói cho phía client**. Điều này có nghĩa là bạn có thể viết **mã server-side trực tiếp trong `getStaticProps`**, bao gồm cả việc fetch data từ database của bạn.

## Tham số Context

Tham số `context` là một object chứa các keys sau:

| Tên                | Mô tả                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `params`           | Chứa các route parameters cho các trang sử dụng [dynamic routes](/docs/pages/building-your-application/routing/dynamic-routes). Ví dụ, nếu tên trang là `[id].js`, thì `params` sẽ trông như `{ id: ... }`. Bạn nên sử dụng điều này cùng với `getStaticPaths`, mà chúng ta sẽ giải thích sau.                                                                                                                                                              |
| `preview`          | (Không dùng nữa cho `draftMode`) `preview` là `true` nếu trang đang ở [Preview Mode](/docs/pages/guides/preview-mode) và `false` nếu không.                                                                                                                                                                                                                                                                                                                 |
| `previewData`      | (Không dùng nữa cho `draftMode`) Dữ liệu [preview](/docs/pages/guides/preview-mode) được đặt bởi `setPreviewData`.                                                                                                                                                                                                                                                                                                                                          |
| `draftMode`        | `draftMode` là `true` nếu trang đang ở [Draft Mode](/docs/pages/guides/draft-mode) và `false` nếu không.                                                                                                                                                                                                                                                                                                                                                    |
| `locale`           | Chứa locale đang hoạt động (nếu được kích hoạt).                                                                                                                                                                                                                                                                                                                                                                                                            |
| `locales`          | Chứa tất cả các locales được hỗ trợ (nếu được kích hoạt).                                                                                                                                                                                                                                                                                                                                                                                                   |
| `defaultLocale`    | Chứa locale mặc định được cấu hình (nếu được kích hoạt).                                                                                                                                                                                                                                                                                                                                                                                                    |
| `revalidateReason` | Cung cấp lý do tại sao hàm được gọi. Có thể là một trong: "build" (chạy tại thời điểm build), "stale" (thời gian revalidate đã hết hạn, hoặc đang chạy trong [development mode](/docs/pages/building-your-application/data-fetching/get-static-props#runs-on-every-request-in-development)), "on-demand" (được kích hoạt thông qua [on-demand revalidation](/docs/pages/guides/incremental-static-regeneration#on-demand-revalidation-with-revalidatepath)) |

## Giá trị trả về của getStaticProps

Hàm `getStaticProps` nên trả về một object chứa `props`, `redirect`, hoặc `notFound` theo sau bởi một thuộc tính `revalidate` **tùy chọn**.

### `props`

Object `props` là một cặp key-value, trong đó mỗi giá trị được nhận bởi page component. Nó phải là một [serializable object](https://developer.mozilla.org/docs/Glossary/Serialization) để bất kỳ props nào được truyền, có thể được serialize với [`JSON.stringify`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/JSON/stringify).

```jsx
export async function getStaticProps(context) {
  return {
    props: { message: `Next.js is awesome` }, // sẽ được truyền cho page component như props
  }
}
```

### `revalidate`

Thuộc tính `revalidate` là số lượng giây sau đó việc re-generation trang có thể xảy ra (mặc định là `false` hoặc không có revalidation).

```js
// Hàm này được gọi tại thời điểm build trên server-side.
// Nó có thể được gọi lại, trên một serverless function, nếu
// revalidation được kích hoạt và một request mới đến
export async function getStaticProps() {
  const res = await fetch('https://.../posts')
  const posts = await res.json()

  return {
    props: {
      posts,
    },
    // Next.js sẽ cố gắng re-generate trang:
    // - Khi một request đến
    // - Nhiều nhất một lần mỗi 10 giây
    revalidate: 10, // Tính bằng giây
  }
}
```

Tìm hiểu thêm về [Incremental Static Regeneration](/docs/pages/guides/incremental-static-regeneration).

Trạng thái cache của một trang tận dụng ISR có thể được xác định bằng cách đọc giá trị của response header `x-nextjs-cache`. Các giá trị có thể là:

- `MISS` - path không có trong cache (xảy ra nhiều nhất một lần, trong lần truy cập đầu tiên)
- `STALE` - path có trong cache nhưng vượt quá thời gian revalidate nên nó sẽ được cập nhật trong background
- `HIT` - path có trong cache và chưa vượt quá thời gian revalidate

### `notFound`

Boolean `notFound` cho phép trang trả về trạng thái `404` và [404 Page](/docs/pages/building-your-application/routing/custom-error#404-page). Với `notFound: true`, trang sẽ trả về `404` ngay cả khi có một trang được tạo thành công trước đó. Điều này nhằm hỗ trợ các trường hợp sử dụng như nội dung do người dùng tạo bị xóa bởi tác giả của nó. Lưu ý, `notFound` tuân theo cùng hành vi `revalidate` [được mô tả ở đây](#revalidate).

```js
export async function getStaticProps(context) {
  const res = await fetch(`https://.../data`)
  const data = await res.json()

  if (!data) {
    return {
      notFound: true,
    }
  }

  return {
    props: { data }, // sẽ được truyền cho page component như props
  }
}
```

> **Nên biết**: `notFound` không cần thiết cho chế độ [`fallback: false`](/docs/pages/api-reference/functions/get-static-paths#fallback-false) vì chỉ có các paths được trả về từ `getStaticPaths` mới được pre-rendered.

### `redirect`

Object `redirect` cho phép chuyển hướng đến các tài nguyên nội bộ hoặc bên ngoài. Nó phải khớp với hình dạng của `{ destination: string, permanent: boolean }`.

Trong một số trường hợp hiếm hoi, bạn có thể cần gán một mã trạng thái tùy chỉnh cho các `HTTP` clients cũ để chuyển hướng đúng cách. Trong những trường hợp này, bạn có thể sử dụng thuộc tính `statusCode` thay vì thuộc tính `permanent`, **nhưng không cả hai**. Bạn cũng có thể đặt `basePath: false` tương tự như redirects trong `next.config.js`.

```js
export async function getStaticProps(context) {
  const res = await fetch(`https://...`)
  const data = await res.json()

  if (!data) {
    return {
      redirect: {
        destination: '/',
        permanent: false,
        // statusCode: 301
      },
    }
  }

  return {
    props: { data }, // sẽ được truyền cho page component như props
  }
}
```

Nếu các redirects được biết tại thời điểm build, chúng nên được thêm vào [`next.config.js`](/docs/pages/api-reference/config/next-config-js/redirects) thay thế.

## Đọc files: Sử dụng `process.cwd()`

Files có thể được đọc trực tiếp từ filesystem trong `getStaticProps`.

Để làm như vậy, bạn phải lấy đường dẫn đầy đủ đến một file.

Vì Next.js biên dịch mã của bạn vào một thư mục riêng biệt, bạn không thể sử dụng `__dirname` vì đường dẫn nó trả về sẽ khác với Pages Router.

Thay vào đó, bạn có thể sử dụng `process.cwd()` cung cấp cho bạn thư mục nơi Next.js đang được thực thi.

```jsx
import { promises as fs } from 'fs'
import path from 'path'

// posts sẽ được điền vào tại thời điểm build bởi getStaticProps()
function Blog({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li>
          <h3>{post.filename}</h3>
          <p>{post.content}</p>
        </li>
      ))}
    </ul>
  )
}

// Hàm này được gọi tại thời điểm build trên server-side.
// Nó sẽ không được gọi trên client-side, vì vậy bạn thậm chí có thể thực hiện
// các truy vấn database trực tiếp.
export async function getStaticProps() {
  const postsDirectory = path.join(process.cwd(), 'posts')
  const filenames = await fs.readdir(postsDirectory)

  const posts = filenames.map(async (filename) => {
    const filePath = path.join(postsDirectory, filename)
    const fileContents = await fs.readFile(filePath, 'utf8')

    // Thông thường bạn sẽ phân tích cú pháp/chuyển đổi nội dung
    // Ví dụ bạn có thể chuyển đổi markdown thành HTML ở đây

    return {
      filename,
      content: fileContents,
    }
  })
  // Bằng cách trả về { props: { posts } }, component Blog
  // sẽ nhận `posts` như một prop tại thời điểm build
  return {
    props: {
      posts: await Promise.all(posts),
    },
  }
}

export default Blog
```
