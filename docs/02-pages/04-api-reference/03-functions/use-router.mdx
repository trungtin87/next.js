Nếu bạn muốn truy cập [`router` object](#router-object) bên trong bất kỳ function component nào trong ứng dụng của bạn, bạn có thể sử dụng `useRouter` hook, hãy xem ví dụ sau:

```jsx
import { useRouter } from 'next/router'

function ActiveLink({ children, href }) {
  const router = useRouter()
  const style = {
    marginRight: 10,
    color: router.asPath === href ? 'red' : 'black',
  }

  const handleClick = (e) => {
    e.preventDefault()
    router.push(href)
  }

  return (
    <a href={href} onClick={handleClick} style={style}>
      {children}
    </a>
  )
}

export default ActiveLink
```

> `useRouter` là một [React Hook](https://react.dev/learn#using-hooks), có nghĩa là nó không thể được sử dụng với classes. Bạn có thể sử dụng [withRouter](#withrouter) hoặc wrap class của bạn trong một function component.

## `router` object

Sau đây là định nghĩa của `router` object được trả về bởi cả [`useRouter`](#top) và [`withRouter`](#withrouter):

- `pathname`: `String` - Đường dẫn cho tệp route hiện tại đến sau `/pages`. Do đó, `basePath`, `locale` và trailing slash (`trailingSlash: true`) không được bao gồm.
- `query`: `Object` - Query string được phân tích cú pháp thành một object, bao gồm các tham số [dynamic route](/docs/pages/building-your-application/routing/dynamic-routes). Nó sẽ là một object rỗng trong quá trình prerendering nếu trang không sử dụng [Server-side Rendering](/docs/pages/building-your-application/data-fetching/get-server-side-props). Mặc định là `{}`
- `asPath`: `String` - Đường dẫn như được hiển thị trong trình duyệt bao gồm search params và tôn trọng cấu hình `trailingSlash`. `basePath` và `locale` không được bao gồm.
- `isFallback`: `boolean` - Liệu trang hiện tại có đang ở [fallback mode](/docs/pages/api-reference/functions/get-static-paths#fallback-true) hay không.
- `basePath`: `String` - [basePath](/docs/app/api-reference/config/next-config-js/basePath) đang hoạt động (nếu được kích hoạt).
- `locale`: `String` - Locale đang hoạt động (nếu được kích hoạt).
- `locales`: `String[]` - Tất cả các locales được hỗ trợ (nếu được kích hoạt).
- `defaultLocale`: `String` - Locale mặc định hiện tại (nếu được kích hoạt).
- `domainLocales`: `Array<{domain, defaultLocale, locales}>` - Bất kỳ domain locales nào được cấu hình.
- `isReady`: `boolean` - Liệu các trường router có được cập nhật phía client và sẵn sàng để sử dụng hay không. Chỉ nên được sử dụng bên trong các phương thức `useEffect` và không để render có điều kiện trên server. Xem tài liệu liên quan cho trường hợp sử dụng với [các trang được tối ưu hóa tĩnh tự động](/docs/pages/building-your-application/rendering/automatic-static-optimization)
- `isPreview`: `boolean` - Liệu ứng dụng hiện có đang ở [preview mode](/docs/pages/guides/preview-mode) hay không.

> Sử dụng trường `asPath` có thể dẫn đến sự không khớp giữa client và server nếu trang được render bằng server-side rendering hoặc [automatic static optimization](/docs/pages/building-your-application/rendering/automatic-static-optimization). Tránh sử dụng `asPath` cho đến khi trường `isReady` là `true`.

Các phương thức sau được bao gồm bên trong `router`:

### router.push

Xử lý các chuyển đổi phía client, phương thức này hữu ích cho các trường hợp mà [`next/link`](/docs/pages/api-reference/components/link) không đủ.

```js
router.push(url, as, options)
```

- `url`: `UrlObject | String` - URL để điều hướng đến (xem [tài liệu Node.JS URL module](https://nodejs.org/api/url.html#legacy-urlobject) cho các thuộc tính `UrlObject`).
- `as`: `UrlObject | String` - Decorator tùy chọn cho đường dẫn sẽ được hiển thị trong thanh URL của trình duyệt. Trước Next.js 9.5.3, điều này được sử dụng cho dynamic routes.
- `options` - Object tùy chọn với các tùy chọn cấu hình sau:
  - `scroll` - Boolean tùy chọn, kiểm soát việc cuộn lên đầu trang sau khi điều hướng. Mặc định là `true`
  - [`shallow`](/docs/pages/building-your-application/routing/linking-and-navigating#shallow-routing): Cập nhật đường dẫn của trang hiện tại mà không chạy lại [`getStaticProps`](/docs/pages/building-your-application/data-fetching/get-static-props), [`getServerSideProps`](/docs/pages/building-your-application/data-fetching/get-server-side-props) hoặc [`getInitialProps`](/docs/pages/api-reference/functions/get-initial-props). Mặc định là `false`
  - `locale` - Chuỗi tùy chọn, chỉ định locale của trang mới

> Bạn không cần sử dụng `router.push` cho các URL bên ngoài. [window.location](https://developer.mozilla.org/docs/Web/API/Window/location) phù hợp hơn cho những trường hợp đó.

Điều hướng đến `pages/about.js`, là một route được định nghĩa trước:

```jsx
import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  return (
    <button type="button" onClick={() => router.push('/about')}>
      Click me
    </button>
  )
}
```

Điều hướng `pages/post/[pid].js`, là một dynamic route:

```jsx
import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  return (
    <button type="button" onClick={() => router.push('/post/abc')}>
      Click me
    </button>
  )
}
```

Chuyển hướng người dùng đến `pages/login.js`, hữu ích cho các trang đằng sau [authentication](/docs/pages/guides/authentication):

```jsx
import { useEffect } from 'react'
import { useRouter } from 'next/router'

// Ở đây bạn sẽ fetch và trả về user
const useUser = () => ({ user: null, loading: false })

export default function Page() {
  const { user, loading } = useUser()
  const router = useRouter()

  useEffect(() => {
    if (!(user || loading)) {
      router.push('/login')
    }
  }, [user, loading])

  return <p>Redirecting...</p>
}
```

#### Reset state sau khi điều hướng

Khi điều hướng đến cùng một trang trong Next.js, state của trang **sẽ không** được reset theo mặc định vì React không unmount trừ khi parent component đã thay đổi.

```jsx filename="pages/[slug].js"
import Link from 'next/link'
import { useState } from 'react'
import { useRouter } from 'next/router'

export default function Page(props) {
  const router = useRouter()
  const [count, setCount] = useState(0)
  return (
    <div>
      <h1>Page: {router.query.slug}</h1>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increase count</button>
      <Link href="/one">one</Link> <Link href="/two">two</Link>
    </div>
  )
}
```

Trong ví dụ trên, điều hướng giữa `/one` và `/two` **sẽ không** reset count. `useState` được duy trì giữa các lần render vì React component cấp cao nhất, `Page`, là giống nhau.

Nếu bạn không muốn hành vi này, bạn có một vài tùy chọn:

- Đảm bảo thủ công mỗi state được cập nhật bằng `useEffect`. Trong ví dụ trên, điều đó có thể trông như:

  ```jsx
  useEffect(() => {
    setCount(0)
  }, [router.query.slug])
  ```

- Sử dụng React `key` để [yêu cầu React remount component](https://react.dev/learn/rendering-lists#keeping-list-items-in-order-with-key). Để làm điều này cho tất cả các trang, bạn có thể sử dụng custom app:

  ```jsx filename="pages/_app.js"
  import { useRouter } from 'next/router'

  export default function MyApp({ Component, pageProps }) {
    const router = useRouter()
    return <Component key={router.asPath} {...pageProps} />
  }
  ```

#### Với URL object

Bạn có thể sử dụng URL object theo cách tương tự như bạn có thể sử dụng nó cho [`next/link`](/docs/pages/api-reference/components/link#passing-a-url-object). Hoạt động cho cả tham số `url` và `as`:

```jsx
import { useRouter } from 'next/router'

export default function ReadMore({ post }) {
  const router = useRouter()

  return (
    <button
      type="button"
      onClick={() => {
        router.push({
          pathname: '/post/[pid]',
          query: { pid: post.id },
        })
      }}
    >
      Click here to read more
    </button>
  )
}
```

### router.replace

Tương tự như prop `replace` trong [`next/link`](/docs/pages/api-reference/components/link), `router.replace` sẽ ngăn việc thêm một URL entry mới vào `history` stack.

```js
router.replace(url, as, options)
```

- API cho `router.replace` hoàn toàn giống với API cho [`router.push`](#routerpush).

Hãy xem ví dụ sau:

```jsx
import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  return (
    <button type="button" onClick={() => router.replace('/home')}>
      Click me
    </button>
  )
}
```

### router.prefetch

Prefetch các trang để có chuyển đổi phía client nhanh hơn. Phương thức này chỉ hữu ích cho các điều hướng không có [`next/link`](/docs/pages/api-reference/components/link), vì `next/link` tự động xử lý việc prefetch các trang.

> Đây là tính năng chỉ dành cho production. Next.js không prefetch các trang trong development.

```js
router.prefetch(url, as, options)
```

- `url` - URL để prefetch, bao gồm các routes rõ ràng (ví dụ: `/dashboard`) và dynamic routes (ví dụ: `/product/[id]`)
- `as` - Decorator tùy chọn cho `url`. Trước Next.js 9.5.3, điều này được sử dụng để prefetch dynamic routes.
- `options` - Object tùy chọn với các trường được phép sau:
  - `locale` - cho phép cung cấp một locale khác với locale đang hoạt động. Nếu `false`, `url` phải bao gồm locale vì locale đang hoạt động sẽ không được sử dụng.

Giả sử bạn có một trang login, và sau khi login, bạn chuyển hướng người dùng đến dashboard. Trong trường hợp đó, chúng ta có thể prefetch dashboard để có chuyển đổi nhanh hơn, như trong ví dụ sau:

```jsx
import { useCallback, useEffect } from 'react'
import { useRouter } from 'next/router'

export default function Login() {
  const router = useRouter()
  const handleSubmit = useCallback((e) => {
    e.preventDefault()

    fetch('/api/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        /* Form data */
      }),
    }).then((res) => {
      // Thực hiện chuyển đổi phía client nhanh đến trang dashboard đã được prefetch
      if (res.ok) router.push('/dashboard')
    })
  }, [])

  useEffect(() => {
    // Prefetch trang dashboard
    router.prefetch('/dashboard')
  }, [router])

  return (
    <form onSubmit={handleSubmit}>
      {/* Form fields */}
      <button type="submit">Login</button>
    </form>
  )
}
```

### router.beforePopState

Trong một số trường hợp (ví dụ: nếu sử dụng [Custom Server](/docs/pages/guides/custom-server)), bạn có thể muốn lắng nghe [popstate](https://developer.mozilla.org/docs/Web/API/Window/popstate_event) và làm điều gì đó trước khi router hành động trên nó.

```js
router.beforePopState(cb)
```

- `cb` - Hàm để chạy trên các sự kiện `popstate` đến. Hàm nhận state của sự kiện dưới dạng một object với các props sau:
  - `url`: `String` - route cho state mới. Đây thường là tên của một `page`
  - `as`: `String` - url sẽ được hiển thị trong trình duyệt
  - `options`: `Object` - Các tùy chọn bổ sung được gửi bởi [router.push](#routerpush)

Nếu `cb` trả về `false`, Next.js router sẽ không xử lý `popstate`, và bạn sẽ chịu trách nhiệm xử lý nó trong trường hợp đó. Xem [Vô hiệu hóa file-system routing](/docs/pages/guides/custom-server#disabling-file-system-routing).

Bạn có thể sử dụng `beforePopState` để thao tác request, hoặc buộc làm mới SSR, như trong ví dụ sau:

```jsx
import { useEffect } from 'react'
import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  useEffect(() => {
    router.beforePopState(({ url, as, options }) => {
      // Tôi chỉ muốn cho phép hai routes này!
      if (as !== '/' && as !== '/other') {
        // Để SSR render các routes xấu như 404.
        window.location.href = as
        return false
      }

      return true
    })
  }, [router])

  return <p>Welcome to the page</p>
}
```

### router.back

Điều hướng lùi trong lịch sử. Tương đương với việc nhấp vào nút back của trình duyệt. Nó thực thi `window.history.back()`.

```jsx
import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  return (
    <button type="button" onClick={() => router.back()}>
      Click here to go back
    </button>
  )
}
```

### router.reload

Tải lại URL hiện tại. Tương đương với việc nhấp vào nút refresh của trình duyệt. Nó thực thi `window.location.reload()`.

```jsx
import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  return (
    <button type="button" onClick={() => router.reload()}>
      Click here to reload
    </button>
  )
}
```

### router.events

Bạn có thể lắng nghe các sự kiện khác nhau xảy ra bên trong Next.js Router. Đây là danh sách các sự kiện được hỗ trợ:

- `routeChangeStart(url, { shallow })` - Kích hoạt khi một route bắt đầu thay đổi
- `routeChangeComplete(url, { shallow })` - Kích hoạt khi một route đã thay đổi hoàn toàn
- `routeChangeError(err, url, { shallow })` - Kích hoạt khi có lỗi khi thay đổi routes, hoặc việc tải route bị hủy
  - `err.cancelled` - Cho biết liệu điều hướng có bị hủy hay không
- `beforeHistoryChange(url, { shallow })` - Kích hoạt trước khi thay đổi lịch sử của trình duyệt
- `hashChangeStart(url, { shallow })` - Kích hoạt khi hash sẽ thay đổi nhưng không phải trang
- `hashChangeComplete(url, { shallow })` - Kích hoạt khi hash đã thay đổi nhưng không phải trang

> **Nên biết**: Ở đây `url` là URL được hiển thị trong trình duyệt, bao gồm [`basePath`](/docs/app/api-reference/config/next-config-js/basePath).

Ví dụ, để lắng nghe sự kiện router `routeChangeStart`, mở hoặc tạo `pages/_app.js` và subscribe vào sự kiện, như sau:

```jsx
import { useEffect } from 'react'
import { useRouter } from 'next/router'

export default function MyApp({ Component, pageProps }) {
  const router = useRouter()

  useEffect(() => {
    const handleRouteChange = (url, { shallow }) => {
      console.log(
        `App is changing to ${url} ${
          shallow ? 'with' : 'without'
        } shallow routing`
      )
    }

    router.events.on('routeChangeStart', handleRouteChange)

    // Nếu component bị unmounted, unsubscribe
    // khỏi sự kiện với phương thức `off`:
    return () => {
      router.events.off('routeChangeStart', handleRouteChange)
    }
  }, [router])

  return <Component {...pageProps} />
}
```

> Chúng ta sử dụng [Custom App](/docs/pages/building-your-application/routing/custom-app) (`pages/_app.js`) cho ví dụ này để subscribe vào sự kiện vì nó không bị unmounted khi điều hướng trang, nhưng bạn có thể subscribe vào các sự kiện router trên bất kỳ component nào trong ứng dụng của bạn.

Các sự kiện Router nên được đăng ký khi một component mounts ([useEffect](https://react.dev/reference/react/useEffect) hoặc [componentDidMount](https://react.dev/reference/react/Component#componentdidmount) / [componentWillUnmount](https://react.dev/reference/react/Component#componentwillunmount)) hoặc một cách bắt buộc khi một sự kiện xảy ra.

Nếu việc tải route bị hủy (ví dụ: bằng cách nhấp vào hai liên kết nhanh chóng liên tiếp), `routeChangeError` sẽ kích hoạt. Và `err` được truyền sẽ chứa một thuộc tính `cancelled` được đặt thành `true`, như trong ví dụ sau:

```jsx
import { useEffect } from 'react'
import { useRouter } from 'next/router'

export default function MyApp({ Component, pageProps }) {
  const router = useRouter()

  useEffect(() => {
    const handleRouteChangeError = (err, url) => {
      if (err.cancelled) {
        console.log(`Route to ${url} was cancelled!`)
      }
    }

    router.events.on('routeChangeError', handleRouteChangeError)

    // Nếu component bị unmounted, unsubscribe
    // khỏi sự kiện với phương thức `off`:
    return () => {
      router.events.off('routeChangeError', handleRouteChangeError)
    }
  }, [router])

  return <Component {...pageProps} />
}
```

## Export `next/compat/router`

Đây là cùng một `useRouter` hook, nhưng có thể được sử dụng trong cả thư mục `app` và `pages`.

Nó khác với `next/router` ở chỗ nó không throw lỗi khi pages router không được mount, và thay vào đó có kiểu trả về là `NextRouter | null`.
Điều này cho phép các nhà phát triển chuyển đổi các components để hỗ trợ chạy trong cả `app` và `pages` khi họ chuyển sang `app` router.

Một component trước đây trông như thế này:

```jsx
import { useRouter } from 'next/router'
const MyComponent = () => {
  const { isReady, query } = useRouter()
  // ...
}
```

Sẽ báo lỗi khi chuyển đổi sang `next/compat/router`, vì `null` không thể được destructured. Thay vào đó, các nhà phát triển sẽ có thể tận dụng các hooks mới:

```jsx
import { useEffect } from 'react'
import { useRouter } from 'next/compat/router'
import { useSearchParams } from 'next/navigation'
const MyComponent = () => {
  const router = useRouter() // có thể là null hoặc một NextRouter instance
  const searchParams = useSearchParams()
  useEffect(() => {
    if (router && !router.isReady) {
      return
    }
    // Trong `app/`, searchParams sẽ sẵn sàng ngay lập tức với các giá trị, trong
    // `pages/` nó sẽ có sẵn sau khi router sẵn sàng.
    const search = searchParams.get('search')
    // ...
  }, [router, searchParams])
  // ...
}
```

Component này bây giờ sẽ hoạt động trong cả thư mục `pages` và `app`. Khi component không còn được sử dụng trong `pages`, bạn có thể xóa các tham chiếu đến compat router:

```jsx
import { useSearchParams } from 'next/navigation'
const MyComponent = () => {
  const searchParams = useSearchParams()
  // Vì component này chỉ được sử dụng trong `app/`, compat router có thể được xóa.
  const search = searchParams.get('search')
  // ...
}
```

### Sử dụng `useRouter` bên ngoài ngữ cảnh Next.js trong pages

Một trường hợp sử dụng cụ thể khác là khi render các components bên ngoài ngữ cảnh ứng dụng Next.js, chẳng hạn như bên trong `getServerSideProps` trên thư mục `pages`. Trong trường hợp này, compat router có thể được sử dụng để tránh lỗi:

```jsx
import { renderToString } from 'react-dom/server'
import { useRouter } from 'next/compat/router'
const MyComponent = () => {
  const router = useRouter() // có thể là null hoặc một NextRouter instance
  // ...
}
export async function getServerSideProps() {
  const renderedComponent = renderToString(<MyComponent />)
  return {
    props: {
      renderedComponent,
    },
  }
}
```

## Lỗi ESLint tiềm năng

Một số phương thức có thể truy cập trên `router` object trả về một Promise. Nếu bạn có quy tắc ESLint, [no-floating-promises](https://typescript-eslint.io/rules/no-floating-promises) được kích hoạt, hãy xem xét vô hiệu hóa nó toàn cục, hoặc cho dòng bị ảnh hưởng.

Nếu ứng dụng của bạn cần quy tắc này, bạn nên `void` promise – hoặc sử dụng một hàm `async`, `await` Promise, sau đó void lời gọi hàm. **Điều này không áp dụng khi phương thức được gọi từ bên trong một `onClick` handler**.

Các phương thức bị ảnh hưởng là:

- `router.push`
- `router.replace`
- `router.prefetch`

### Giải pháp tiềm năng

```jsx
import { useEffect } from 'react'
import { useRouter } from 'next/router'

// Ở đây bạn sẽ fetch và trả về user
const useUser = () => ({ user: null, loading: false })

export default function Page() {
  const { user, loading } = useUser()
  const router = useRouter()

  useEffect(() => {
    // vô hiệu hóa linting trên dòng tiếp theo - Đây là giải pháp sạch nhất
    // eslint-disable-next-line no-floating-promises
    router.push('/login')

    // void Promise được trả về bởi router.push
    if (!(user || loading)) {
      void router.push('/login')
    }
    // hoặc sử dụng một hàm async, await Promise, sau đó void lời gọi hàm
    async function handleRouteChange() {
      if (!(user || loading)) {
        await router.push('/login')
      }
    }
    void handleRouteChange()
  }, [user, loading])

  return <p>Redirecting...</p>
}
```

## withRouter

Nếu [`useRouter`](#router-object) không phù hợp nhất với bạn, `withRouter` cũng có thể thêm cùng một [`router` object](#router-object) vào bất kỳ component nào.

### Cách sử dụng

```jsx
import { withRouter } from 'next/router'

function Page({ router }) {
  return <p>{router.pathname}</p>
}

export default withRouter(Page)
```

### TypeScript

Để sử dụng class components với `withRouter`, component cần chấp nhận một router prop:

```tsx
import React from 'react'
import { withRouter, NextRouter } from 'next/router'

interface WithRouterProps {
  router: NextRouter
}

interface MyComponentProps extends WithRouterProps {}

class MyComponent extends React.Component<MyComponentProps> {
  render() {
    return <p>{this.props.router.pathname}</p>
  }
}

export default withRouter(MyComponent)
```
