## Tại Sao Thông Báo Này Xuất Hiện

Bạn đã cố gắng sử dụng một hàm Next.js phụ thuộc vào Async Context (như `headers` hoặc `cookies` từ `next/headers`) nhưng nó không được liên kết với cùng một call stack như hàm đã chạy nó (ví dụ: gọi `cookies()` bên trong `setTimeout` hoặc `setInterval`).

Trong khi tạo các trang tĩnh, Next.js sẽ ném ra `DynamicServerError` nếu nó phát hiện việc sử dụng một hàm động, và bắt nó để tự động chọn tham gia render động cho trang. Tuy nhiên, khi nó không được bắt, nó sẽ dẫn đến lỗi build-time này.

## Async Context Là Gì?

[Async Context](https://github.com/tc39/proposal-async-context) là một cách để truyền dữ liệu trong cùng một call stack, ngay cả qua các hoạt động bất đồng bộ. Điều này rất hữu ích trong Next.js, nơi các hàm như cookies hoặc headers có thể được gọi từ bất kỳ đâu trong cây React component hoặc các hàm khác trong quá trình render React.

## Các Kịch Bản Có Thể Gây Ra Điều Này

- Hàm được gọi bên trong `setTimeout` hoặc `setInterval`, khiến giá trị được đọc bên ngoài call stack mà context đã được liên kết.
- Hàm được gọi sau một hoạt động bất đồng bộ, nhưng promise không được await. Điều này có thể khiến hàm được gọi sau khi hoạt động bất đồng bộ đã hoàn thành, dẫn đến một execution context mới và mất async context ban đầu.

### Ví Dụ Về Cách Sử Dụng Sai

```jsx filename="app/page.js"
import { cookies } from 'next/headers'

async function getCookieData() {
  return new Promise((resolve) =>
    setTimeout(async () => {
      // cookies sẽ được gọi bên ngoài async context, gây ra lỗi build-time
      const cookieStore = await cookies()
      resolve(cookieStore.getAll())
    }, 1000)
  )
}

export default async function Page() {
  const cookieData = await getCookieData()
  return <div>Hello World</div>
}
```

## Các Cách Có Thể Để Khắc Phục

**Quản Lý Execution Contexts Một Cách Chính Xác:** Các hoạt động JavaScript như `setTimeout`, `setInterval`, event handlers, và Promises tạo ra các execution contexts mới. Bạn cần duy trì async context khi sử dụng các hoạt động này. Một số chiến lược bao gồm:

- Gọi hàm phụ thuộc vào async context bên ngoài hàm tạo ra execution context mới.
- Đảm bảo rằng bạn await các Promises gọi một hàm phụ thuộc vào async context, nếu không hàm có thể được gọi sau khi hoạt động bất đồng bộ đã hoàn thành.

### Ví Dụ Về Cách Sử Dụng Đúng

```jsx filename="app/page.js"
import { cookies } from 'next/headers'

async function getCookieData() {
  const cookieStore = await cookies()
  const cookieData = cookieStore.getAll()
  return new Promise((resolve) =>
    setTimeout(() => {
      resolve(cookieData)
    }, 1000)
  )
}

export default async function Page() {
  const cookieData = await getCookieData()
  return <div>Hello World</div>
}
```
