## Tại Sao Lỗi Này Xảy Ra

Khi tính năng `cacheComponents` được bật, Next.js mong đợi một `Suspense` boundary cha bao quanh bất kỳ component nào chờ dữ liệu cần được truy cập trên mỗi yêu cầu của người dùng. Mục đích của yêu cầu này là để Next.js có thể cung cấp một fallback hữu ích trong khi dữ liệu này được truy cập và hiển thị.

Trong khi một số dữ liệu vốn chỉ có sẵn khi yêu cầu của người dùng đang được xử lý, chẳng hạn như request headers, Next.js giả định rằng theo mặc định, bất kỳ dữ liệu bất đồng bộ nào cũng được mong đợi sẽ được truy cập mỗi khi yêu cầu của người dùng được xử lý trừ khi bạn lưu trữ cụ thể nó bằng cách sử dụng `"use cache"`.

Cách sửa lỗi thích hợp cho lỗi cụ thể này phụ thuộc vào dữ liệu bạn đang truy cập và cách bạn muốn ứng dụng Next.js của mình hoạt động.

## Các Cách Có Thể Để Khắc Phục

### Truy Cập Dữ Liệu

Khi bạn truy cập dữ liệu bằng `fetch`, một database client, hoặc bất kỳ module nào khác thực hiện IO bất đồng bộ, Next.js diễn giải ý định của bạn là mong đợi dữ liệu tải trên mỗi yêu cầu của người dùng.

Nếu bạn đang mong đợi dữ liệu này được sử dụng trong khi prerendering hoàn toàn hoặc một phần trang, bạn phải cache nó bằng cách sử dụng `"use cache"`.

Trước:

```jsx filename="app/page.js"
async function getRecentArticles() {
  return db.query(...)
}

export default async function Page() {
  const articles = await getRecentArticles(token);
  return <ArticleList articles={articles}>
}
```

Sau:

```jsx filename="app/page.js"
import { cacheTag, cacheLife } from 'next/cache'

async function getRecentArticles() {
  "use cache"
  // Cache này có thể được xác thực lại bằng webhook hoặc server action
  // khi bạn gọi revalidateTag("articles")
  cacheTag("articles")
  // Cache này sẽ xác thực lại sau một giờ ngay cả khi không nhận được
  // hướng dẫn xác thực lại rõ ràng nào
  cacheLife('hours')
  return db.query(...)
}

export default async function Page() {
  const articles = await getRecentArticles(token);
  return <ArticleList articles={articles}>
}
```

Nếu dữ liệu này nên được truy cập trên mỗi yêu cầu của người dùng, bạn phải cung cấp một fallback UI bằng cách sử dụng `Suspense` từ React. Nơi bạn đặt Suspense boundary này trong ứng dụng của mình nên được thông báo bởi loại fallback UI bạn muốn hiển thị. Nó có thể nằm ngay phía trên component truy cập dữ liệu này hoặc thậm chí trong Root Layout của bạn.

Trước:

```jsx filename="app/page.js"
async function getLatestTransactions() {
  return db.query(...)
}

export default async function Page() {
  const transactions = await getLatestTransactions(token);
  return <TransactionList transactions={transactions}>
}
```

Sau:

```jsx filename="app/page.js"
import { Suspense } from 'react'

async function TransactionList() {
  const transactions = await db.query(...)
  return ...
}

function TransactionSkeleton() {
  return <ul>...</ul>
}

export default async function Page() {
  return (
    <Suspense fallback={<TransactionSkeleton />}>
      <TransactionList/>
    </Suspense>
  )
}
```

### Headers

Nếu bạn đang truy cập request headers bằng `headers()`, `cookies()`, hoặc `draftMode()`. Hãy xem xét liệu bạn có thể di chuyển việc sử dụng các API này sâu hơn vào cây component hiện có của mình hay không.

Trước:

```jsx filename="app/inbox.js"
export async function Inbox({ token }) {
  const email = await getEmail(token)
  return (
    <ul>
      {email.map((e) => (
        <EmailRow key={e.id} />
      ))}
    </ul>
  )
}
```

```jsx filename="app/page.js"
import { cookies } from 'next/headers'

import { Inbox } from './inbox'

export default async function Page() {
  const token = (await cookies()).get('token')
  return (
    <Suspense fallback="loading your inbox...">
      <Inbox token={token}>
    </Suspense>
  )
}
```

Sau:

```jsx filename="app/inbox.js"
import { cookies } from 'next/headers'

export async function Inbox() {
  const token = (await cookies()).get('token')
  const email = await getEmail(token)
  return (
    <ul>
      {email.map((e) => (
        <EmailRow key={e.id} />
      ))}
    </ul>
  )
}
```

```jsx filename="app/page.js"
import { Inbox } from './inbox'

export default async function Page() {
  return (
    <Suspense fallback="loading your inbox...">
      <Inbox>
    </Suspense>
  )
}
```

Ngoài ra, bạn có thể thêm một Suspense boundary phía trên component đang truy cập Request headers.

### Params và SearchParams

Layout `params`, và Page `params` và `searchParams` props là các promises. Nếu bạn await chúng trong Layout hoặc Page component, bạn có thể đang truy cập các props này ở mức cao hơn mức thực sự cần thiết. Hãy thử truyền các props này đến các component sâu hơn dưới dạng promise và await chúng gần hơn với nơi param hoặc searchParam thực tế được yêu cầu.

Trước:

```jsx filename="app/map.js"
export async function Map({ lat, lng }) {
  const mapData = await fetch(`https://...?lat=${lat}&lng=${lng}`)
  return drawMap(mapData)
}
```

```jsx filename="app/page.js"
import { cookies } from 'next/headers'

import { Map } from './map'

export default async function Page({ searchParams }) {
  const { lat, lng } = await searchParams;
  return (
    <Suspense fallback="loading your inbox...">
      <Map lat={lat} lng={lng}>
    </Suspense>
  )
}
```

Sau:

```jsx filename="app/map.js"
export async function Map({ coords }) {
  const { lat, lng } = await coords
  const mapData = await fetch(`https://...?lat=${lat}&lng=${lng}`)
  return drawMap(mapData)
}
```

```jsx filename="app/page.js"
import { cookies } from 'next/headers'

import { Map } from './map'

export default async function Page({ searchParams }) {
  const coords = searchParams.then(sp => ({ lat: sp.lat, lng: sp.lng }))
  return (
    <Suspense fallback="loading your inbox...">
      <Map coord={coords}>
    </Suspense>
  )
}
```

Ngoài ra, bạn có thể thêm một Suspense boundary phía trên component đang truy cập `params` hoặc `searchParams` để Next.js hiểu UI nào nên được sử dụng trong khi chờ dữ liệu yêu cầu này được truy cập.

### Short-lived Caches (Cache ngắn hạn)

`"use cache"` cho phép bạn mô tả một [`cacheLife()`](/docs/app/api-reference/functions/cacheLife) có thể quá ngắn để thực tế cho việc prerender. Tiện ích của việc làm này là nó vẫn có thể mô tả thời gian lưu trữ khác không cho bộ nhớ cache của router phía client để sử dụng lại mục nhập cache trong trình duyệt và nó cũng có thể hữu ích để bảo vệ các API ngược dòng trong khi gặp lưu lượng yêu cầu cao.

Nếu bạn mong đợi mục nhập `"use cache"` có thể prerender được, hãy thử mô tả `cacheLife()` dài hơn một chút.

Trước:

```jsx filename="app/page.js"
import { cacheLife } from 'next/cache'

async function getDashboard() {
  "use cache"
  // Cache này sẽ xác thực lại sau 1 giây. Nó quá ngắn
  // Next.js sẽ không prerender nó trên server nhưng client router
  // có thể sử dụng lại kết quả trong tối đa 30 giây trừ khi người dùng làm mới thủ công
  cacheLife('seconds')
  return db.query(...)
}

export default async function Page() {
  const data = await getDashboard(token);
  return <Dashboard data={data}>
}
```

Sau:

```jsx filename="app/page.js"
import { cacheLife } from 'next/cache'

async function getDashboard() {
  "use cache"
  // Cache này sẽ xác thực lại sau 1 phút. Nó đủ dài để
  // Next.js vẫn sẽ tạo ra một trang được prerender hoàn toàn hoặc một phần
  cacheLife('minutes')
  return db.query(...)
}

export default async function Page() {
  const data = await getDashboard(token);
  return <Dashboard data={data}>
}
```

Ngoài ra, bạn có thể thêm một Suspense boundary phía trên component đang truy cập dữ liệu được cache ngắn hạn này để Next.js hiểu UI nào nên được sử dụng trong khi truy cập dữ liệu này theo yêu cầu của người dùng.
