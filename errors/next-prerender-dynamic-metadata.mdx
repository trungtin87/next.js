## Tại Sao Lỗi Này Xảy Ra

Khi `cacheComponents` được bật, Next.js yêu cầu rằng `generateMetadata()` không phụ thuộc vào dữ liệu uncached hoặc dữ liệu Request trừ khi một số phần khác của trang cũng có yêu cầu tương tự. Lý do cho điều này là trong khi bạn thường kiểm soát ý định của mình về những gì được phép động bằng cách thêm hoặc xóa các Suspense boundaries trong các Layout và Page components của bạn, bạn không kiểm soát việc render metadata.

Heuristic mà Next.js sử dụng để hiểu ý định của bạn với `generateMetadata()` là xem xét các yêu cầu dữ liệu của phần còn lại của route. Nếu các components khác phụ thuộc vào dữ liệu Request hoặc dữ liệu uncached, thì chúng tôi cho phép `generateMetadata()` có các yêu cầu dữ liệu tương tự. Nếu phần còn lại của trang của bạn không phụ thuộc vào loại dữ liệu này, chúng tôi yêu cầu rằng `generateMetadata()` cũng không có sự phụ thuộc dữ liệu loại này.

## Các Cách Khắc Phục Có Thể

Để khắc phục vấn đề này, trước tiên bạn phải xác định mục tiêu của mình cho route bị ảnh hưởng.

### Caching Dữ Liệu Bên Ngoài

Nếu metadata của bạn không phụ thuộc vào bất kỳ request data nào, thì có thể bạn có thể chỉ ra rằng dữ liệu có thể cache được, điều này sẽ cho phép Next.js bao gồm nó trong prerender cho route này. Hãy xem xét sử dụng `"use cache"` để đánh dấu function tạo ra dữ liệu bên ngoài là có thể cache.

Trước đây:

```jsx filename="app/.../page.tsx"
import { cms } from './cms'

export async function generateMetadata() {
  // Việc tra cứu dữ liệu này hiện không được cached nên
  // Next.js sẽ hiểu điều này là cần được render
  // trên mỗi request.
  const { title } = await cms.getPageData('/.../page')
  return {
    title,
  }
}

async function getPageText() {
  'use cache'
  const { text } = await cms.getPageData('/.../page')
  return text
}

export default async function Page() {
  // Text này được cached nên nội dung chính của route này
  // có thể prerender được.
  const text = await getPageText()
  return <article>{text}</article>
}
```

Sau khi sửa:

```jsx filename="app/.../page.tsx"
import { cms } from './cms'

export async function generateMetadata() {
  // Bằng cách đánh dấu function này là có thể cache, Next.js
  // bây giờ có thể bao gồm nó trong prerender cho route này.
  'use cache'
  const { title } = await cms.getPageData('/.../page')
  return {
    title,
  }
}

async function getPageText() {
  'use cache'
  const { text } = await cms.getPageData('/.../page')
  return text
}

export default async function Page() {
  // Text này được cached nên nội dung chính của route này
  // có thể prerender được.
  const text = await getPageText()
  return <article>{text}</article>
}
```

### Nếu bạn phải truy cập Request Data hoặc dữ liệu bên ngoài của bạn không thể cache

Nếu metadata của bạn yêu cầu Request data hoặc phụ thuộc vào dữ liệu bên ngoài không thể cache thì Next.js sẽ cần render trang này động trên mỗi request. Tuy nhiên nếu bạn gặp lỗi này, phần còn lại của trang của bạn có thể hoàn toàn tĩnh. Điều này thường khá hiếm, nhưng nếu đây là ràng buộc thực tế của bạn, bạn có thể chỉ ra cho Next.js rằng trang nên được phép động bằng cách render bất kỳ component nào khác là động. Vì route của bạn không có nhu cầu thực sự về Request data, bạn có thể chỉ ra sự phụ thuộc có chủ ý vào một Request với `await connection()`. Điều này giống như nói với Next.js rằng component này không bao giờ có thể prerender được và phải được render trên mỗi request của người dùng.

Trước đây:

```jsx filename="app/.../page.tsx"
import { cookies } from 'next/headers'
import { getPersonalizedTitle } from './my-api'

export async function generateMetadata() {
  // Trong ví dụ này, chúng ta giả định rằng chúng ta phải fetch title của mình
  // từ một external API được bảo vệ. Mặc dù response có thể
  // cache được, nó vẫn yêu cầu truy cập token từ Request cookies.
  const token = (await cookies()).get('token')
  const response = await getPersonalizedTitle(token)
  return {
    title: getTitle(response),
  }
}

export default function Page() {
  return <article>This article is completely static</article>
}
```

Sau khi sửa:

```jsx filename="app/.../page.tsx"
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { connection } from 'next/server'

export async function generateMetadata() {
  const token = (await cookies()).get('token')
  const response = await fetch(..., { headers: { Authorization: token } })
  return {
    title: getTitle(response),
  }
}

async function DynamicMarker() {
  // Component này không render gì, nhưng nó sẽ luôn
  // là động vì nó chờ một connection thực tế.
  const Connection = async () => {
    await connection()
    return null
  }
  return (
    <Suspense>
      <Connection />
    </Suspense>
  )
}

export default function Page() {
  return (
    <>
      <article>This article is completely static</article>
      {/* Việc render DynamicMarker component này nói với Next.js rằng
          Page này có một số nội dung động. */}
      <DynamicMarker />
    </>
  )
}
```

Lưu ý: Lý do để cấu trúc `DynamicMarker` này như một Suspense boundary độc lập là để tránh chặn nội dung thực tế của trang khỏi việc được prerender. Khi Partial Prerendering được bật cùng với `cacheComponents`, static shell vẫn sẽ chứa tất cả nội dung có thể prerender được, và chỉ metadata sẽ stream vào động.
