title: Không thể truy cập thông tin Request đồng bộ trong route.js mà không await connection trước
---

## Tại Sao Lỗi Này Xảy Ra

Khi `cacheComponents` được bật, Next.js xử lý hầu hết việc truy cập vào thông tin Request như rõ ràng động. Tuy nhiên các routes có một đối tượng Request và bạn có thể đọc các giá trị như pathname hiện tại từ đối tượng đó đồng bộ. Nếu bạn cần truy cập thông tin Request trong một route handler, trước tiên bạn nên gọi `await connection()` để thông báo cho Next.js rằng mọi thứ sau điểm này là rõ ràng động.

Điều này chỉ cần thiết trong các `GET` handlers vì `GET` là handler duy nhất mà Next.js sẽ cố gắng prerender.

## Các Cách Khắc Phục Có Thể

Tìm kiếm việc truy cập đối tượng Request trong route.js của bạn và thêm `await connection()` trước khi bạn truy cập bất kỳ thuộc tính nào của Request.

Trước đây:

```jsx filename="app/.../route.js"
export default function GET(request) {
  const requestHeaders = request.headers
  return ...
}
```

Sau khi sửa:

```jsx filename="app/.../route.js"
import { connection } from 'next/server'

export default async function GET(request) {
  await connection()
  const requestHeaders = request.headers
  return ...
}
```

Không mong đợi rằng bạn sẽ chạy codemod và không chuyển đổi thành công tất cả các instance của `params` và `searchParams` sang async hoặc có một chuỗi đánh dấu để giúp bạn xác định vị trí các trường hợp chưa được chuyển đổi. Nếu bạn thấy mình trong tình huống này, vui lòng báo cáo điều này cho [Next.js trên Github](https://github.com/vercel/next.js/issues).
