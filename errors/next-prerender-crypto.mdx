## Tại Sao Lỗi Này Xảy Ra

Một API tạo ra giá trị ngẫu nhiên đồng bộ từ Web Crypto API hoặc từ package `crypto` của Node đã được sử dụng trong một Server Component trước khi truy cập dữ liệu uncached khác thông qua các API như `fetch()` và native database drivers, hoặc dữ liệu Request thông qua các API của Next.js như `cookies()`, `headers()`, `connection()` và `searchParams`. Việc truy cập các giá trị ngẫu nhiên đồng bộ theo cách này can thiệp vào khả năng prerendering và prefetching của Next.js.

## Các Cách Khắc Phục Có Thể

Nếu giá trị crypto ngẫu nhiên phù hợp để được prerender và prefetch, hãy xem xét di chuyển nó vào một Cache Component hoặc Cache Function với directive `"use cache"`.

Nếu giá trị crypto ngẫu nhiên được dự định để được tạo ra trên mỗi request của người dùng, hãy xem xét liệu có tồn tại một async API đạt được kết quả tương tự hay không. Nếu không, hãy xem xét liệu bạn có thể di chuyển việc tạo giá trị crypto ngẫu nhiên về sau, sau khi truy cập dữ liệu uncached hoặc dữ liệu Request hiện có khác. Nếu không có cách nào để làm điều này, bạn luôn có thể đặt trước việc tạo giá trị crypto ngẫu nhiên bằng cách truy cập dữ liệu Request bằng cách sử dụng `await connection()`.

### Cache giá trị token

Nếu bạn đang tạo một token để giao tiếp với một database mà bản thân nó nên được cached, hãy di chuyển việc tạo token vào bên trong `"use cache"`.

Trước đây:

```jsx filename="app/page.js"
async function getCachedData(token: string) {
  "use cache"
  return db.query(token, ...)
}

export default async function Page() {
  const token = crypto.getRandomUUID()
  const data = await getCachedData(token);
  return ...
}
```

Sau khi sửa:

```jsx filename="app/page.js"
async function getCachedData() {
  "use cache"
  const token = crypto.getRandomUUID()
  return db.query(token, ...)
}

export default async function Page() {
  const data = await getCachedData();
  return ...
}
```

### Sử dụng async API tại request-time

Nếu bạn yêu cầu giá trị ngẫu nhiên này là duy nhất cho mỗi Request và tồn tại phiên bản async của API, hãy chuyển sang sử dụng nó thay thế. Đồng thời đảm bảo rằng có một Suspense boundary cha định nghĩa fallback UI mà Next.js có thể sử dụng trong khi render component này trên mỗi Request.

Trước đây:

```jsx filename="app/page.js"
import { generateKeySync } from 'node:crypto'

export default async function Page() {
  const key = generateKeySync('hmac', { ... })
  const digestedData = await digestDataWithKey(data, key);
  return ...
}
```

Sau khi sửa:

```jsx filename="app/page.js"
import { generateKey } from 'node:crypto'

export default async function Page() {
  const key = await new Promise(resolve => generateKey('hmac', { ... }, key => resolve(key)))
  const digestedData = await digestDataWithKey(data, key);
  return ...
}
```

### Sử dụng `await connection()` tại request-time

Nếu bạn yêu cầu giá trị ngẫu nhiên này là duy nhất cho mỗi Request và không tồn tại phiên bản async của API, hãy gọi `await connection()`. Đồng thời đảm bảo rằng có một Suspense boundary cha định nghĩa fallback UI mà Next.js có thể sử dụng trong khi render component này trên mỗi Request.

Trước đây:

```jsx filename="app/page.js"
export default async function Page() {
  const uuid = crypto.randomUUID()
  return <RequestId id={uuid} />
}
```

Sau khi sửa:

```jsx filename="app/page.js"
import { connection } from 'next/server'

export default async function Page() {
  await connection()
  const uuid = crypto.randomUUID()
  return <RequestId id={uuid} />
}
```
