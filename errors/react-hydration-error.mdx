## Tại Sao Lỗi Này Xảy Ra

Trong khi render ứng dụng của bạn, đã có sự khác biệt giữa React tree được pre-render từ server và React tree được render trong lần render đầu tiên ở trình duyệt (hydration).

[Hydration](https://react.dev/reference/react-dom/client/hydrateRoot) là khi React chuyển đổi HTML đã được pre-render từ server thành một ứng dụng tương tác đầy đủ bằng cách gắn các event handlers.

### Các Nguyên Nhân Phổ Biến

Lỗi hydration có thể xảy ra do:

1. Lồng các thẻ HTML không chính xác
   1. `<p>` được lồng trong thẻ `<p>` khác
   2. `<div>` được lồng trong thẻ `<p>`
   3. `<ul>` hoặc `<ol>` được lồng trong thẻ `<p>`
   4. [Nội dung tương tác](https://html.spec.whatwg.org/#interactive-content-2) không thể được lồng vào nhau (`<a>` lồng trong thẻ `<a>`, `<button>` lồng trong thẻ `<button>`, v.v.)
2. Sử dụng các kiểm tra như `typeof window !== 'undefined'` trong logic render của bạn
3. Sử dụng các API chỉ dành cho trình duyệt như `window` hoặc `localStorage` trong logic render của bạn
4. Sử dụng các API phụ thuộc thời gian như constructor `Date()` trong logic render của bạn
5. [Browser extensions](https://github.com/facebook/react/issues/24430) sửa đổi HTML
6. Cấu hình không chính xác [thư viện CSS-in-JS](/docs/app/guides/css-in-js)
   1. Đảm bảo code của bạn tuân theo [các ví dụ chính thức của chúng tôi](https://github.com/vercel/next.js/tree/canary/examples)
7. Cấu hình Edge/CDN không chính xác cố gắng sửa đổi phản hồi html, chẳng hạn như Cloudflare [Auto Minify](https://developers.cloudflare.com/speed/optimization/content/troubleshooting/disable-auto-minify/)

## Các Cách Có Thể Để Khắc Phục

Các chiến lược sau có thể giúp giải quyết lỗi này:

### Giải pháp 1: Sử dụng `useEffect` để chỉ chạy trên client

Đảm bảo rằng component render cùng một nội dung phía server như nó làm trong lần render client-side ban đầu để ngăn chặn sự không khớp hydration. Bạn có thể chủ ý render nội dung khác nhau trên client với hook `useEffect`.

```jsx
import { useState, useEffect } from 'react'

export default function App() {
  const [isClient, setIsClient] = useState(false)

  useEffect(() => {
    setIsClient(true)
  }, [])

  return <h1>{isClient ? 'This is never prerendered' : 'Prerendered'}</h1>
}
```

Trong quá trình React hydration, `useEffect` được gọi. Điều này có nghĩa là các API trình duyệt như `window` có sẵn để sử dụng mà không gây ra sự không khớp hydration.

### Giải pháp 2: Vô hiệu hóa SSR trên các component cụ thể

Next.js cho phép bạn [vô hiệu hóa prerendering](/docs/app/guides/lazy-loading#skipping-ssr) trên các component cụ thể, điều này có thể ngăn chặn sự không khớp hydration.

```jsx
import dynamic from 'next/dynamic'

const NoSSR = dynamic(() => import('../components/no-ssr'), { ssr: false })

export default function Page() {
  return (
    <div>
      <NoSSR />
    </div>
  )
}
```

### Giải pháp 3: Sử dụng `suppressHydrationWarning`

Đôi khi nội dung chắc chắn sẽ khác nhau giữa server và client, chẳng hạn như timestamp. Bạn có thể tắt cảnh báo không khớp hydration bằng cách thêm `suppressHydrationWarning={true}` vào phần tử.

```jsx
<time datetime="2016-10-25" suppressHydrationWarning />
```

> **Cần biết:**
>
> - Điều này chỉ hoạt động ở độ sâu một cấp, và được dùng như một lối thoát (escape hatch). Đừng lạm dụng nó.
> - React sẽ **không** cố gắng vá nội dung văn bản không khớp khi `suppressHydrationWarning={true}` được thiết lập.

## Các vấn đề iOS phổ biến

iOS cố gắng phát hiện số điện thoại, địa chỉ email, và các dữ liệu khác trong nội dung văn bản và chuyển đổi chúng thành các liên kết, dẫn đến sự không khớp hydration.

Điều này có thể bị vô hiệu hóa với thẻ `meta` sau:

```jsx
<meta
  name="format-detection"
  content="telephone=no, date=no, email=no, address=no"
/>
```
