## Tại Sao Lỗi Này Xảy Ra

Trong khi prerender một trang trong quá trình `next build`, một lỗi đã xảy ra. Điều này có thể xảy ra vì nhiều lý do, bao gồm:

1. Cấu trúc file không chính xác hoặc các file không phải trang trong thư mục `pages/`
2. Mong đợi props được điền nhưng không có sẵn trong quá trình prerendering
3. Sử dụng các API chỉ dành cho trình duyệt trong các component mà không có kiểm tra phù hợp
4. Cấu hình không chính xác trong `getStaticProps` hoặc `getStaticPaths`

## Các Cách Có Thể Để Khắc Phục

### 1. Đảm bảo cấu trúc file chính xác và sử dụng App Router để colocation

#### Pages Router

Trong Pages Router, chỉ các file đặc biệt được phép tạo trang. Bạn không thể colocate các file khác (ví dụ: components, styles) trong thư mục `pages`.

Cấu trúc đúng:

```txt
  .
  ├── components/
  │   └── Header.js
  ├── pages/
  │   ├── about.js
  │   └── index.js
  └── styles/
      └── globals.css
```

#### App Router (Next.js 13+)

App Router cho phép [colocation](/docs/app/getting-started/project-structure#colocation) các trang và các file khác trong cùng một thư mục. Điều này cung cấp cấu trúc dự án trực quan hơn.

Ví dụ cấu trúc thư mục:

```txt
  .
  └── app/
      ├── about/
      │   └── page.tsx
      ├── blog/
      │   ├── page.tsx
      │   └── PostCard.tsx
      ├── layout.tsx
      └── page.tsx
```

### 2. Xử lý props không xác định và dữ liệu thiếu

#### Pages Router

Đối với Pages Router, sử dụng kiểm tra có điều kiện và trả về props phù hợp hoặc trang 404:

```jsx
export async function getStaticProps(context) {
  const data = await fetchData(context.params.id)
  if (!data) {
    return {
      notFound: true,
    }
  }
  return {
    props: { data },
  }
}
```

### 3. Xử lý fallback trong dynamic routes

Nếu bạn đang sử dụng `fallback: true` hoặc `fallback: 'blocking'` trong `getStaticPaths`, hãy đảm bảo component trang của bạn có thể xử lý trạng thái loading:

```jsx
import { useRouter } from 'next/router'

function Post({ post }) {
  const router = useRouter()

  if (router.isFallback) {
    return <div>Loading...</div>
  }

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </article>
  )
}
```

### 4. Tránh export các trang với server-side rendering

Nếu bạn đang sử dụng `next export` hoặc `output: 'export'` trong `next.config.js` của bạn, hãy đảm bảo rằng không có trang nào của bạn sử dụng `getServerSideProps`. Thay vào đó, hãy sử dụng `getStaticProps` để fetch dữ liệu:

```jsx
export async function getStaticProps() {
  const res = await fetch('https://api.vercel.app/blog')
  const data = await res.json()

  return {
    props: { data },
    revalidate: 60,
  }
}
```

### 5. Vô hiệu hóa server-side rendering cho các component sử dụng browser APIs

Nếu một component dựa vào các API chỉ dành cho trình duyệt như `window`, bạn có thể vô hiệu hóa server-side rendering cho component đó:

```jsx
import dynamic from 'next/dynamic'

const DynamicComponentWithNoSSR = dynamic(
  () => import('../components/BrowserOnlyComponent'),
  { ssr: false }
)

export default function Page() {
  return (
    <div>
      <h1>My page</h1>
      <DynamicComponentWithNoSSR />
    </div>
  )
}
```
