Khi chúng tôi làm việc để cải thiện Middleware cho General Availability (GA), chúng tôi đã thực hiện một số thay đổi đối với API Middleware (và cách bạn định nghĩa Middleware trong ứng dụng của mình) dựa trên phản hồi của bạn.

Hướng dẫn nâng cấp này sẽ giúp bạn hiểu các thay đổi, lý do tại sao chúng được thực hiện và cách di chuyển Middleware hiện có của bạn sang API mới. Hướng dẫn này dành cho các nhà phát triển Next.js, những người:

- Hiện đang sử dụng các tính năng beta Next.js Middleware
- Chọn nâng cấp lên phiên bản ổn định tiếp theo của Next.js (`v12.2`)

Bạn có thể bắt đầu nâng cấp việc sử dụng Middleware của mình ngay hôm nay với bản phát hành mới nhất (`npm i next@latest`).

> **Lưu ý**: Những thay đổi được mô tả trong hướng dẫn này được bao gồm trong Next.js `12.2`. Bạn có thể giữ cấu trúc trang web hiện tại của mình, bao gồm cả Middleware lồng nhau, cho đến khi bạn chuyển sang `12.2` (hoặc bản build `canary` của Next.js).

Nếu bạn đã cấu hình ESLint, bạn sẽ cần chạy `npm i eslint-config-next@latest --save-dev` để nâng cấp cấu hình ESLint của mình nhằm đảm bảo phiên bản tương tự đang được sử dụng như phiên bản Next.js. Bạn cũng có thể cần khởi động lại VSCode để các thay đổi có hiệu lực.

## Sử dụng Next.js Middleware trên Vercel

Nếu bạn đang sử dụng Next.js trên Vercel, các bản deploy hiện tại của bạn sử dụng Middleware sẽ tiếp tục hoạt động và bạn có thể tiếp tục deploy trang web của mình bằng Middleware. Khi bạn nâng cấp trang web của mình lên phiên bản ổn định tiếp theo của Next.js (`v12.2`), bạn sẽ cần làm theo hướng dẫn nâng cấp này để cập nhật Middleware của mình.

## Không có Middleware lồng nhau

### Tóm tắt các thay đổi

- Định nghĩa một file Middleware duy nhất bên cạnh thư mục `pages` của bạn
- Không cần thêm tiền tố gạch dưới cho file
- Một matcher tùy chỉnh có thể được sử dụng để định nghĩa các route khớp bằng cách sử dụng một đối tượng config được export

### Giải thích

Trước đây, bạn có thể tạo một file `_middleware.ts` dưới thư mục `pages` ở bất kỳ cấp độ nào. Việc thực thi Middleware dựa trên đường dẫn file nơi nó được tạo.

Dựa trên phản hồi của khách hàng, chúng tôi đã thay thế API này bằng một Middleware gốc duy nhất, cung cấp các cải tiến sau:

- **Thực thi nhanh hơn với độ trễ thấp hơn**: Với Middleware lồng nhau, một yêu cầu duy nhất có thể gọi nhiều hàm Middleware. Một Middleware duy nhất có nghĩa là một lần thực thi hàm duy nhất, hiệu quả hơn.
- **Ít tốn kém hơn**: Việc sử dụng Middleware được tính phí cho mỗi lần gọi. Sử dụng Middleware lồng nhau, một yêu cầu duy nhất có thể gọi nhiều hàm Middleware, nghĩa là nhiều khoản phí Middleware cho mỗi yêu cầu. Một Middleware duy nhất có nghĩa là một lần gọi cho mỗi yêu cầu và tiết kiệm chi phí hơn.
- **Middleware có thể lọc thuận tiện trên những thứ ngoài routes**: Với Middleware lồng nhau, các file Middleware được đặt trong thư mục `pages` và Middleware được thực thi dựa trên đường dẫn yêu cầu. Bằng cách chuyển sang một Middleware gốc duy nhất, bạn vẫn có thể thực thi mã dựa trên đường dẫn yêu cầu, nhưng giờ đây bạn có thể thực thi Middleware thuận tiện hơn dựa trên các điều kiện khác, như `cookies` hoặc sự hiện diện của một header yêu cầu.
- **Thứ tự thực thi xác định**: Với Middleware lồng nhau, một yêu cầu duy nhất có thể khớp với nhiều hàm Middleware. Ví dụ: một yêu cầu đến `/dashboard/users/*` sẽ gọi Middleware được định nghĩa trong cả `/dashboard/users/_middleware.ts` và `/dashboard/_middleware.js`. Tuy nhiên, thứ tự thực thi rất khó để suy luận. Chuyển sang một Middleware gốc duy nhất xác định thứ tự thực thi rõ ràng hơn.
- **Hỗ trợ Next.js Layouts (RFC)**: Chuyển sang một Middleware gốc duy nhất giúp hỗ trợ [Layouts (RFC) mới trong Next.js](/blog/layouts-rfc).

### Cách nâng cấp

Bạn nên khai báo **một file Middleware duy nhất** trong ứng dụng của mình, file này nên được đặt bên cạnh thư mục `pages` và được đặt tên **không có** tiền tố `_`. File Middleware của bạn vẫn có thể có phần mở rộng `.ts` hoặc `.js`.

Middleware sẽ được gọi cho **mọi route trong ứng dụng**, và một matcher tùy chỉnh có thể được sử dụng để định nghĩa các bộ lọc khớp. Sau đây là ví dụ cho một Middleware kích hoạt cho `/about/*` và `/dashboard/:path*`, matcher tùy chỉnh được định nghĩa trong một đối tượng config được export:

```ts filename="middleware.ts"
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function middleware(request: NextRequest) {
  return NextResponse.rewrite(new URL('/about-2', request.url))
}

// Hỗ trợ cả giá trị chuỗi đơn hoặc mảng các matchers
export const config = {
  matcher: ['/about/:path*', '/dashboard/:path*'],
}
```

Cấu hình matcher cũng cho phép regex đầy đủ để việc khớp như negative lookaheads hoặc khớp ký tự được hỗ trợ. Một ví dụ về negative lookahead để khớp tất cả ngoại trừ các đường dẫn cụ thể có thể được xem tại đây:

```ts filename="middleware.ts"
export const config = {
  matcher: [
    /*
     * Khớp tất cả các đường dẫn yêu cầu ngoại trừ các đường dẫn bắt đầu bằng:
     * - api (API routes)
     * - _next/static (static files)
     * - favicon.ico (favicon file)
     */
    '/((?!api|_next/static|favicon.ico).*)',
  ],
}
```

Mặc dù tùy chọn config được ưu tiên vì nó không được gọi trên mọi yêu cầu, bạn cũng có thể sử dụng các câu lệnh điều kiện để chỉ chạy Middleware khi nó khớp với các đường dẫn cụ thể. Một lợi thế của việc sử dụng các điều kiện là xác định thứ tự rõ ràng cho thời điểm Middleware thực thi. Ví dụ sau đây cho thấy cách bạn có thể hợp nhất hai Middleware lồng nhau trước đây:

```ts filename="middleware.ts"
import type { NextRequest } from 'next/server'

export function middleware(request: NextRequest) {
  if (request.nextUrl.pathname.startsWith('/about')) {
    // Logic này chỉ được áp dụng cho /about
  }

  if (request.nextUrl.pathname.startsWith('/dashboard')) {
    // Logic này chỉ được áp dụng cho /dashboard
  }
}
```

## Không có Body phản hồi

### Tóm tắt các thay đổi

- Middleware không còn có thể tạo ra body phản hồi
- Nếu Middleware của bạn _có_ phản hồi với một body, một lỗi runtime sẽ được ném ra
- Di chuyển sang sử dụng `rewrite`/`redirect` đến các pages/APIs xử lý phản hồi

### Giải thích

Để tôn trọng sự khác biệt trong điều hướng phía client và phía server, và để giúp đảm bảo rằng các nhà phát triển không xây dựng Middleware không an toàn, chúng tôi đang loại bỏ khả năng gửi body phản hồi trong Middleware. Điều này đảm bảo rằng Middleware chỉ được sử dụng để `rewrite`, `redirect`, hoặc sửa đổi yêu cầu đến (ví dụ: [thiết lập cookies](#cookies-api-revamped)).

Các mẫu sau đây sẽ không còn hoạt động:

```js
new Response('a text value')
new Response(streamOrBuffer)
new Response(JSON.stringify(obj), { headers: 'application/json' })
NextResponse.json()
```

### Cách nâng cấp

Đối với các trường hợp Middleware được sử dụng để phản hồi (chẳng hạn như xác thực), bạn nên di chuyển sang sử dụng `rewrite`/`redirect` đến các trang hiển thị lỗi xác thực, biểu mẫu đăng nhập, hoặc đến một API Route.

#### Trước

```ts filename="pages/_middleware.ts"
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'
import { isAuthValid } from './lib/auth'

export function middleware(request: NextRequest) {
  // Hàm ví dụ để xác thực auth
  if (isAuthValid(request)) {
    return NextResponse.next()
  }

  return NextResponse.json({ message: 'Auth required' }, { status: 401 })
}
```

#### Sau

```ts filename="middleware.ts"
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'
import { isAuthValid } from './lib/auth'

export function middleware(request: NextRequest) {
  // Hàm ví dụ để xác thực auth
  if (isAuthValid(request)) {
    return NextResponse.next()
  }

  const loginUrl = new URL('/login', request.url)
  loginUrl.searchParams.set('from', request.nextUrl.pathname)

  return NextResponse.redirect(loginUrl)
}
```

#### Edge API Routes

Nếu bạn trước đây đã sử dụng Middleware để chuyển tiếp headers đến một API bên ngoài, bây giờ bạn có thể sử dụng [Edge API Routes](/docs/pages/building-your-application/routing/api-routes):

```ts filename="pages/api/proxy.ts"
import { type NextRequest } from 'next/server'

export const config = {
  runtime: 'edge',
}

export default async function handler(req: NextRequest) {
  const authorization = req.cookies.get('authorization')
  return fetch('https://backend-api.com/api/protected', {
    method: req.method,
    headers: {
      authorization,
    },
    redirect: 'manual',
  })
}
```

## Cookies API được cải tiến

### Tóm tắt các thay đổi

| Đã thêm                  | Đã xóa        |
| ------------------------ | ------------- |
| `cookies.set`            | `cookie`      |
| `cookies.delete`         | `clearCookie` |
| `cookies.getWithOptions` | `cookies`     |

### Giải thích

Dựa trên phản hồi beta, chúng tôi đang thay đổi Cookies API trong `NextRequest` và `NextResponse` để phù hợp hơn với mô hình `get`/`set`. `Cookies` API mở rộng Map, bao gồm các phương thức như [entries](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Map/entries) và [values](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Map/entries).

### Cách nâng cấp

`NextResponse` hiện có một instance `cookies` với:

- `cookies.delete`
- `cookies.set`
- `cookies.getWithOptions`

Cũng như các phương thức mở rộng khác từ `Map`.

#### Trước

```ts filename="pages/_middleware.ts"
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function middleware(request: NextRequest) {
  // tạo một instance của class để truy cập các phương thức public. Điều này sử dụng `next()`,
  // bạn cũng có thể sử dụng `redirect()` hoặc `rewrite()`
  let response = NextResponse.next()
  // lấy cookies từ request
  let cookieFromRequest = request.cookies['my-cookie']
  // đặt `cookie`
  response.cookie('hello', 'world')
  // đặt `cookie` với options
  const cookieWithOptions = response.cookie('hello', 'world', {
    path: '/',
    maxAge: 1000 * 60 * 60 * 24 * 7,
    httpOnly: true,
    sameSite: 'strict',
    domain: 'example.com',
  })
  // xóa `cookie`
  response.clearCookie('hello')

  return response
}
```

#### Sau

```ts filename="middleware.ts"
export function middleware() {
  const response = new NextResponse()

  // đặt một cookie
  response.cookies.set('vercel', 'fast')

  // đặt một cookie khác với options
  response.cookies.set('nextjs', 'awesome', { path: '/test' })

  // lấy tất cả chi tiết của một cookie
  const { value, ...options } = response.cookies.getWithOptions('vercel')
  console.log(value) // => 'fast'
  console.log(options) // => { name: 'vercel', Path: '/test' }

  // xóa một cookie sẽ đánh dấu nó là hết hạn
  response.cookies.delete('vercel')

  return response
}
```

## User-Agent Helper mới

### Tóm tắt các thay đổi

- Truy cập user agent không còn khả dụng trên đối tượng request
- Chúng tôi đã thêm một helper `userAgent` mới để giảm kích thước Middleware đi `17kb`

### Giải thích

Để giúp giảm kích thước Middleware của bạn, chúng tôi đã trích xuất user agent từ đối tượng request và tạo một helper mới `userAgent`.

Helper được import từ `next/server` và cho phép bạn chọn tham gia sử dụng user agent. Helper cung cấp cho bạn quyền truy cập vào các thuộc tính tương tự đã có sẵn từ đối tượng request.

### Cách nâng cấp

- Import helper `userAgent` từ `next/server`
- Destructure các thuộc tính bạn cần làm việc với

#### Trước

```ts filename="pages/_middleware.ts"
import { NextRequest, NextResponse } from 'next/server'

export function middleware(request: NextRequest) {
  const url = request.nextUrl
  const viewport = request.ua.device.type === 'mobile' ? 'mobile' : 'desktop'
  url.searchParams.set('viewport', viewport)
  return NextResponse.rewrite(url)
}
```

#### Sau

```ts filename="middleware.ts"
import { NextRequest, NextResponse, userAgent } from 'next/server'

export function middleware(request: NextRequest) {
  const url = request.nextUrl
  const { device } = userAgent(request)
  const viewport = device.type === 'mobile' ? 'mobile' : 'desktop'
  url.searchParams.set('viewport', viewport)
  return NextResponse.rewrite(url)
}
```

## Không còn dữ liệu khớp trang (Page Match Data)

### Tóm tắt các thay đổi

- Sử dụng [`URLPattern`](https://developer.mozilla.org/docs/Web/API/URLPattern) để kiểm tra xem một Middleware có đang được gọi cho một khớp trang nhất định hay không

### Giải thích

Hiện tại, Middleware ước tính xem bạn có đang phục vụ một tài sản của một Trang hay không dựa trên manifest routes của Next.js (cấu hình nội bộ). Giá trị này được hiển thị thông qua `request.page`.

Để làm cho việc khớp trang và tài sản chính xác hơn, chúng tôi hiện đang sử dụng API tiêu chuẩn web `URLPattern`.

### Cách nâng cấp

Sử dụng [`URLPattern`](https://developer.mozilla.org/docs/Web/API/URLPattern) để kiểm tra xem một Middleware có đang được gọi cho một khớp trang nhất định hay không.

#### Trước

```ts filename="pages/_middleware.ts"
import { NextResponse } from 'next/server'
import type { NextRequest, NextFetchEvent } from 'next/server'

export function middleware(request: NextRequest, event: NextFetchEvent) {
  const { params } = event.request.page
  const { locale, slug } = params

  if (locale && slug) {
    const { search, protocol, host } = request.nextUrl
    const url = new URL(`${protocol}//${locale}.${host}/${slug}${search}`)
    return NextResponse.redirect(url)
  }
}
```

#### Sau

```ts filename="middleware.ts"
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

const PATTERNS = [
  [
    new URLPattern({ pathname: '/:locale/:slug' }),
    ({ pathname }) => pathname.groups,
  ],
]

const params = (url) => {
  const input = url.split('?')[0]
  let result = {}

  for (const [pattern, handler] of PATTERNS) {
    const patternResult = pattern.exec(input)
    if (patternResult !== null && 'pathname' in patternResult) {
      result = handler(patternResult)
      break
    }
  }
  return result
}

export function middleware(request: NextRequest) {
  const { locale, slug } = params(request.url)

  if (locale && slug) {
    const { search, protocol, host } = request.nextUrl
    const url = new URL(`${protocol}//${locale}.${host}/${slug}${search}`)
    return NextResponse.redirect(url)
  }
}
```

## Thực thi Middleware trên các yêu cầu nội bộ của Next.js

### Tóm tắt các thay đổi

- Middleware sẽ được thực thi cho _tất cả_ các yêu cầu, bao gồm `_next`

### Giải thích

Trước Next.js `v12.2`, Middleware không được thực thi cho các yêu cầu `_next`.

Đối với các trường hợp Middleware được sử dụng để xác thực, bạn nên di chuyển sang sử dụng `rewrite`/`redirect` đến các Trang hiển thị lỗi xác thực, biểu mẫu đăng nhập, hoặc đến một API Route.

Xem [Không có Body phản hồi](#no-response-body) để biết ví dụ về cách di chuyển sang sử dụng `rewrite`/`redirect`.
