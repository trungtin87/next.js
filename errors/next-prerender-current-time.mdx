---

## Tại Sao Lỗi Này Xảy Ra

`Date.now()`, `Date()`, hoặc `new Date()` đã được sử dụng trong một Server Component trước khi truy cập dữ liệu uncached khác thông qua các API như `fetch()` và native database drivers, hoặc dữ liệu Request thông qua các built-in API như `cookies()`, `headers()`, `connection()` và `searchParams`. Việc truy cập thời gian hiện tại theo cách này can thiệp vào khả năng prerendering và prefetching của Next.js.

## Các Cách Khắc Phục Có Thể

Nếu thời gian hiện tại đang được sử dụng cho mục đích chẩn đoán như logging hoặc theo dõi hiệu suất, hãy xem xét sử dụng `performance.now()` thay thế.

Nếu thời gian hiện tại phù hợp để được prerender và prefetch, hãy xem xét di chuyển nó vào một Cache Component hoặc Cache Function với directive `"use cache"`.

Nếu thời gian hiện tại được dự định để được truy cập động trên mỗi request của người dùng, trước tiên hãy xem xét liệu có phù hợp hơn không để truy cập nó trong một Client Component, điều này thường có thể là trường hợp khi đọc thời gian cho mục đích hiển thị. Nếu Client Component không phải là lựa chọn đúng thì hãy xem xét liệu bạn có thể di chuyển việc truy cập thời gian hiện tại về sau, sau khi truy cập dữ liệu uncached hoặc dữ liệu Request hiện có khác. Nếu không có cách nào để làm điều này, bạn luôn có thể đặt trước việc truy cập thời gian hiện tại bằng cách truy cập dữ liệu Request bằng cách sử dụng `await connection()`.

> **Lưu ý**: Đôi khi nơi truy cập thời gian hiện tại nằm bên trong code của bên thứ ba. Mặc dù bạn không thể dễ dàng chuyển đổi việc truy cập thời gian sang `performance.now()` nhưng các chiến lược khác có thể được áp dụng trong code dự án của riêng bạn bất kể thời gian được đọc sâu đến mức nào.

### Trường hợp sử dụng hiệu suất

Nếu bạn đang sử dụng thời gian hiện tại để theo dõi hiệu suất với thời gian đã trôi qua, hãy sử dụng `performance.now()`.

Trước đây:

```jsx filename="app/page.js"
export default async function Page() {
  const start = Date.now();
  const data = computeDataSlowly(...);
  const end = Date.now();
  console.log(`somethingSlow took ${end - start} milliseconds to complete`)

  return ...
}
```

Sau khi sửa:

```jsx filename="app/page.js"
export default async function Page() {
  const start = performance.now();
  const data = computeDataSlowly(...);
  const end = performance.now();
  console.log(`somethingSlow took ${end - start} milliseconds to complete`)
  return ...
}
```

> **Lưu ý**: Nếu bạn cần báo cáo thời gian tuyệt đối cho một công cụ observability, bạn cũng có thể sử dụng `performance.timeOrigin + performance.now()`.
> **Lưu ý**: Điều quan trọng là các giá trị được cung cấp bởi `performance.now()` không ảnh hưởng đến đầu ra được render của Component của bạn và không bao giờ được truyền vào Cache Functions dưới dạng arguments hoặc props.

### Các trường hợp sử dụng có thể cache

Nếu bạn muốn đọc thời gian khi một cache entry được tạo (chẳng hạn như khi một trang Next.js được render tại build-time hoặc khi revalidating một trang tĩnh), hãy di chuyển việc đọc thời gian hiện tại vào bên trong một cached function sử dụng `"use cache"`.

Trước đây:

```jsx filename="app/page.js"
async function InformationTable() {
  const data = await fetch(...)
  return (
    <section>
      <h1>Latest Info...</h1>
      <table>{renderData(data)}</table>
    </section>
  )
}

export default async function Page() {
  return (
    <main>
      <InformationTable />
      Last Refresh: {new Date().toString()}
    </main>
  )
}
```

Sau khi sửa:

```jsx filename="app/page.js"
async function InformationTable() {
  "use cache"
  const data = await fetch(...)
  return (
    <>
      <section>
        <h1>Latest Info...</h1>
        <table>{renderData(data)}</table>
      </section>
      Last Refresh: {new Date().toString()}
    </>
  )
}

export default async function Page() {
  return (
    <main>
      <InformationTable />
    </main>
  )
}
```

### Trường hợp sử dụng Request-time

#### Di chuyển thời gian sang client

Nếu thời gian hiện tại phải được đánh giá trên mỗi Request của người dùng, hãy xem xét di chuyển việc đọc thời gian hiện tại vào một Client Component. Bạn cũng có thể thấy rằng điều này thuận tiện hơn khi bạn muốn làm những việc như cập nhật thời gian độc lập với việc điều hướng trang. Ví dụ, hãy tưởng tượng bạn có một relative time component. Thay vì render relative time trong một Server Component trên mỗi Request, bạn có thể render relative time khi Client Component render và sau đó cập nhật nó định kỳ.

Nếu bạn đi theo cách tiếp cận này, bạn sẽ cần đảm bảo Client Component đọc thời gian trong quá trình render có một Suspense boundary phía trên nó. Bạn có thể cải thiện trải nghiệm loading bằng cách áp dụng một Suspense boundary có phạm vi hẹp hơn. Sử dụng phán đoán của bạn về loại trình tự loading UI mà bạn muốn người dùng của mình trải nghiệm để hướng dẫn quyết định của bạn ở đây.

Trước đây:

```jsx filename="app/page.js"
function RelativeTime({ when }) {
  return computeTimeAgo(new Date(), when)
}

export default async function Page() {
  const data = await ...
  return (
    <main>
      ...
      <Suspense>
        <RelativeTime when={data.createdAt} />
      </Suspense>
    </main>
  )
}
```

Sau khi sửa:

```jsx filename="app/relative-time.js"
'use client'

import { useReducer } from 'react'

export function RelativeTime({ when }) {
  const [_, update] = useReducer(() => ({}), {})
  const timeAgo = computeTimeAgo(new Date(), when)

  // Bất cứ khi nào giá trị timeAgo thay đổi, một timeout mới được
  // lên lịch để cập nhật component. Bây giờ thời gian có thể
  // render lại mà không cần Server Component render lại.
  useEffect(() => {
    const updateAfter = computeTimeUntilNextUpdate(timeAgo)
    let timeout = setTimeout(() => {
      update()
    }, updateAfter)
    return () => {
      clearTimeout(timeout)
    }
  })

  return timeAgo
}
```

```jsx filename="app/page.js"
import { RelativeTime } from './relative-time'

export default async function Page() {
  const data = await ...
  return (
    <main>
      ...
      <Suspense>
        <RelativeTime when={data.createdAt} />
      </Suspense>
    </main>
  )
}
```

> **Lưu ý**: Việc truy cập thời gian hiện tại trong một Client Component vẫn sẽ khiến nó bị loại trừ khỏi HTML server được prerender nhưng Next.js cho phép điều này trong Client Components vì nó có thể tính toán thời gian động khi người dùng request trang HTML hoặc trong trình duyệt.

#### Bảo vệ thời gian với `await connection()`

Có thể bạn muốn đưa ra một số quyết định rendering sử dụng thời gian hiện tại trên server và do đó không thể di chuyển việc đọc thời gian vào một Client Component. Trong trường hợp này, bạn phải hướng dẫn Next.js rằng việc đọc thời gian được dự định để được đánh giá tại request time bằng cách đặt trước nó bằng `await connection()`.

Next.js yêu cầu rằng nó luôn có thể tạo ra ít nhất một trang HTML ban đầu tĩnh một phần nên bạn cũng sẽ cần đảm bảo rằng có một Suspense boundary ở đâu đó phía trên component này để thông báo cho Next.js về fallback UI dự định sử dụng trong khi prerender trang này.

Trước đây:

```jsx filename="app/page.js"
export default async function Page() {
  const currentTime = Date.now()
  if (currentTime > someTriggerDate) {
    return <SpecialBanner />
  } else {
    return <NormalBanner />
  }
}
```

Sau khi sửa:

```jsx filename="app/page.js"
import { Suspense } from 'react'
import { connection } from 'next/server'

async function BannerSkeleton() {
  ...
}

export default async function Page() {
  return <Suspense fallback={<BannerSkeleton />}>
    <DynamicBanner />
  </Suspense>
}

async function DynamicBanner() {
  await connection();
  const currentTime = Date.now();
  if (currentTime > someTriggerDate) {
    return <SpecialBanner />
  } else {
    return <NormalBanner />
  }
}
```

> **Lưu ý**: Ví dụ này minh họa việc sử dụng `await connection()`, nhưng bạn cũng có thể di chuyển nơi một uncached fetch xảy ra hoặc đọc cookies trước đó.
