## Tại Sao Lỗi Này Xảy Ra

Bạn đang sử dụng [Cache Components](https://nextjs.org/docs/beta/app/api-reference/config/next-config-js/cacheComponents) trong ứng dụng Next.js của mình, và một trong các function `generateStaticParams` của bạn đã trả về một mảng rỗng, điều này gây ra lỗi build.

Khi Cache Components được bật, Next.js thực hiện xác thực tại build-time để đảm bảo các routes của bạn có thể được prerender đúng cách mà không có lỗi truy cập động runtime. Nếu `generateStaticParams` trả về một mảng rỗng, Next.js không thể xác thực rằng route của bạn sẽ không truy cập các giá trị động (như `await cookies()`, `await headers()`, hoặc `await searchParams`) tại runtime, điều này sẽ gây ra lỗi.

Yêu cầu nghiêm ngặt này đảm bảo:

- Xác thực tại build-time phát hiện các lỗi runtime tiềm ẩn sớm
- Tất cả các routes sử dụng Cache Components có ít nhất một biến thể tĩnh để xác thực
- Bạn không vô tình triển khai các routes sẽ thất bại tại runtime

## Các Cách Khắc Phục Có Thể

### Tùy Chọn 1: Trả về ít nhất một static param

Sửa đổi function `generateStaticParams` của bạn để trả về ít nhất một tập hợp các parameters. Đây là cách sửa phổ biến nhất và cho phép xác thực tại build-time hoạt động đúng cách.

```tsx filename="app/blog/[slug]/page.tsx"
// ❌ Điều này sẽ gây ra lỗi với Cache Components
export async function generateStaticParams() {
  return [] // Mảng rỗng không được phép
}

// ✅ Trả về ít nhất một param
export async function generateStaticParams() {
  return [{ slug: 'hello-world' }, { slug: 'getting-started' }]
}
```

### Tùy Chọn 2: Sử dụng placeholder param để xác thực

Nếu bạn không biết các giá trị thực tế tại build time nhưng vẫn muốn Cache Components, bạn có thể trả về một placeholder param để xác thực tại build-time:

> Điều này không được khuyến nghị và chỉ nên được sử dụng nếu bạn thực sự cần vì nó ngăn chặn xác thực tại build-time hoạt động, điều này có thể gây ra lỗi runtime.

```tsx filename="app/blog/[slug]/page.tsx"
export async function generateStaticParams() {
  // Trả về một placeholder để xác thực tại build-time
  // Các params thực tế sẽ được tạo tại runtime thông qua ISR
  return [{ slug: '__placeholder__' }]
}

export default async function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params

  // Xử lý trường hợp placeholder
  if (slug === '__placeholder__') {
    notFound()
  }

  // Logic trang thực tế của bạn
  const post = await getPost(slug)
  return <div>{post.title}</div>
}
```
