## Tại Sao Cảnh Báo Này Xảy Ra

Ở đâu đó trong code của bạn, bạn đã sử dụng một API chọn vào [dynamic rendering](/docs/app/guides/caching#dynamic-rendering).

Dynamic APIs là:

- Props `params` và `searchParams` được cung cấp cho pages, layouts, metadata APIs, và route handlers.
- `cookies()`, `draftMode()`, và `headers()` từ `next/headers`

Trong Next 15, các API này đã được làm bất đồng bộ. Bạn có thể đọc thêm về điều này trong [Hướng dẫn Nâng cấp](/docs/app/guides/upgrading/version-15) Next.js 15.

Ví dụ, đoạn code sau sẽ phát ra cảnh báo:

```jsx filename="app/[id]/page.js"
function Page({ params }) {
  // truy cập trực tiếp `params.id`.
  return <p>ID: {params.id}</p>
}
```

Điều này cũng bao gồm việc liệt kê (ví dụ: `{...params}`, hoặc `Object.keys(params)`) hoặc lặp qua giá trị trả về của các API này (ví dụ: `[...headers()]` hoặc `for (const cookie of cookies())`, hoặc rõ ràng với `cookies()[Symbol.iterator]()`).

## Các Cách Có Thể Để Khắc Phục

Codemod [`next-async-request-api`](/docs/app/guides/upgrading/codemods#next-async-request-api) có thể tự động sửa nhiều trường hợp này:

```bash filename="Terminal"
npx @next/codemod@canary next-async-request-api .
```

Codemod không thể bao gồm tất cả các trường hợp, vì vậy bạn có thể cần điều chỉnh một số code thủ công.

Nếu cảnh báo xảy ra trên Server (ví dụ: một route handler, hoặc một Server Component), bạn phải `await` dynamic API để truy cập các thuộc tính của nó:

```jsx filename="app/[id]/page.js"
async function Page({ params }) {
  // truy cập bất đồng bộ `params.id`.
  const { id } = await params
  return <p>ID: {id}</p>
}
```

Nếu cảnh báo xảy ra trong một synchronous component (ví dụ: một Client component), bạn phải sử dụng `React.use()` để unwrap Promise trước:

```jsx filename="app/[id]/page.js"
'use client'
import * as React from 'react'

function Page({ params }) {
  // truy cập bất đồng bộ `params.id`.
  const { id } = React.use(params)
  return <p>ID: {id}</p>
}
```

### Các Trường Hợp Không Thể Di Chuyển

Nếu codemod Next.js tìm thấy bất cứ điều gì không thể được di chuyển bởi codemod, nó sẽ để lại một comment với prefix `@next-codemod-error` và hành động được đề xuất, ví dụ:
Trong trường hợp này, bạn cần thủ công await lời gọi đến `cookies()`, và thay đổi function thành async. Sau đó refactor các cách sử dụng của function để được await đúng cách:

```ts
export function MyCookiesComponent() {
  const c =
    /* @next-codemod-error Manually await this call and refactor the function to be async */
    cookies()
  return c.get('name')
}
```

### Migration Được Thực Thi Với Linter

Nếu bạn không giải quyết các comments bắt đầu bằng `@next-codemod-error` được để lại bởi codemod, Next.js sẽ báo lỗi trong cả dev và build để thực thi bạn giải quyết các vấn đề.
Bạn có thể xem lại các thay đổi và làm theo đề xuất trong các comments. Bạn có thể thực hiện các thay đổi cần thiết và xóa comment, hoặc thay thế prefix comment `@next-codemod-error` bằng `@next-codemod-ignore`
Nếu không có hành động nào cần thực hiện, prefix comment `@next-codemod-ignore` sẽ bỏ qua lỗi build.

```diff
- /* @next-codemod-error <suggested message> */
+ /* @next-codemod-ignore */
```

> **Cần biết**:
>
> Bạn có thể trì hoãn việc unwrap Promise (bằng `await` hoặc `React.use`) cho đến khi bạn thực sự cần sử dụng giá trị.
> Điều này sẽ cho phép Next.js render tĩnh nhiều hơn trang của bạn.
