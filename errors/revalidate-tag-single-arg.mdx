title: revalidateTag Với Một Tham Số Đã Bị Loại Bỏ
---

## Tại Sao Lỗi Này Xảy Ra

Bạn đang sử dụng `revalidateTag` mà không cung cấp tham số thứ hai, điều này hiện đã bị loại bỏ. Hàm này hiện yêu cầu tham số thứ hai để chỉ định hành vi revalidation.

## Các Cách Khắc Phục Có Thể

### Tùy Chọn 1: Thêm tham số thứ hai

Cập nhật các lệnh gọi `revalidateTag` của bạn để bao gồm tham số thứ hai `"max"`:

```js
// Trước đây (đã loại bỏ)
revalidateTag('posts')

// Sau khi sửa
revalidateTag('posts', 'max')
```

### Tùy Chọn 2: Sử dụng updateTag trong Server Actions

Nếu bạn đang gọi điều này từ một Server Action và cần hết hạn ngay lập tức cho read-your-own-writes, hãy sử dụng `updateTag` thay thế:

```js
// Trong một Server Action
import { updateTag } from 'next/cache'

export async function createPost() {
  // ... tạo post ...

  // Hết hạn cache ngay lập tức
  updateTag('posts')
}
```

## Hành Vi Revalidation

- **`revalidateTag(tag, "max")` (khuyến nghị)**: Entry tag được đánh dấu là cũ, và lần tiếp theo một resource với tag đó được truy cập, nó sẽ sử dụng ngữ nghĩa stale-while-revalidate. Điều này có nghĩa là nội dung cũ được phục vụ trong khi nội dung mới được tải về trong nền.

- **`revalidateTag(tag, profile)`**: Đối với việc sử dụng nâng cao, bạn có thể chỉ định bất kỳ cache life profile nào mà ứng dụng của bạn đã định nghĩa trong `next.config` của bạn thay vì `"max"`, cho phép các hành vi revalidation tùy chỉnh.

- **`updateTag(tag)`**: Chỉ khả dụng trong Server Actions. Entry tag hết hạn ngay lập tức, và request tiếp theo đến resource đó sẽ là một blocking revalidate/cache miss. Điều này đảm bảo tính nhất quán read-your-own-writes.

- **`revalidateTag(tag)` không có tham số thứ hai (đã loại bỏ)**: Hành vi giống như `updateTag` nhưng hiển thị cảnh báo loại bỏ này.
