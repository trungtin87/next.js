## Tại Sao Lỗi Này Xảy Ra

Trong Next.js 15, các global functions cung cấp quyền truy cập vào thông tin Request Header như `cookies()`, `headers()`, và `draftMode()` giờ đây đều là `async` và trả về một `Promise` thay vì đối tượng liên quan trực tiếp.

Để hỗ trợ việc di chuyển sang các async API, Next.js 15 vẫn hỗ trợ việc truy cập các thuộc tính của đối tượng cơ bản trực tiếp trên Promise được trả về. Tuy nhiên khi `cacheComponents` được bật, việc làm như vậy là một lỗi.

## Các Cách Khắc Phục Có Thể

Nếu bạn chưa làm theo hướng dẫn nâng cấp Next.js 15 bao gồm việc chạy một codemod để tự động chuyển đổi sang dạng async cần thiết của các API này, hãy bắt đầu từ đó.

[Hướng Dẫn Nâng Cấp Next 15](/docs/app/guides/upgrading/version-15#async-request-apis-breaking-change)

Nếu bạn đã chạy codemod trên dự án của mình, hãy tìm các instance của chuỗi `@next-codemod-error` để xem nơi mà codemod không thể chuyển đổi sang dạng async. Bạn sẽ phải refactor code của mình thủ công ở đây để làm cho nó tương thích với kiểu kết quả mới.

Trước đây:

```jsx filename=".../token-utils.js"
// Function này là sync và codemod sẽ không làm cho nó async
// vì nó không biết về mọi callsite sử dụng nó.
export function getToken() {
  // @next-codemod-error ...
  return cookies().get('token')
}
```

```jsx filename="app/page.js"
import { getToken } from '.../token-utils'

export default function Page() {
  const token = getToken();
  validateToken(token)
  return ...
}
```

Sau khi sửa:

```jsx filename=".../token-utils.js"
export async function Page() {
  return (await cookies()).get(token)
}
```

```jsx filename="app/page.js"
import { getToken } from '.../token-utils'

export default async function Page() {
  const token = await getToken();
  validateToken(token)
  return ...
}
```

Nếu bạn không tìm thấy các instance của chuỗi này thì có thể việc sử dụng đồng bộ dữ liệu Request Header nằm bên trong một thư viện bên thứ ba. Bạn nên xác định thư viện nào đang sử dụng function này và xem liệu nó đã xuất bản phiên bản tương thích Next 15 tuân thủ kiểu trả về Promise mới hay chưa.

Như một phương án cuối cùng, bạn có thể thêm `await connection()` trước khi gọi function của bên thứ ba sử dụng API này. Điều này sẽ thông báo cho Next.js rằng mọi thứ sau await này nên được loại trừ khỏi prerendering. Điều này sẽ tiếp tục hoạt động cho đến khi chúng tôi xóa hỗ trợ cho việc truy cập đồng bộ dữ liệu Request, điều này dự kiến sẽ xảy ra trong phiên bản major tiếp theo.

Trước đây:

```jsx filename="app/page.js"
import { getDataFrom3rdParty } from '3rdparty'

export default function Page() {
  // Tưởng tượng function này truy cập Request data đồng bộ
  // bên trong ngay cả khi nó có một async external interface
  const token = await getDataFrom3rdParty();
  return ...
}
```

Sau khi sửa:

```jsx filename="app/page.js"
import { connection } from 'next/server'

export default async function Page() {
  await connection()
  // Mọi thứ từ đây trở xuống sẽ được loại trừ khỏi prerendering
  const token = await getDataFrom3rdParty();
  validateToken(token)
  return ...
}
```

Lưu ý rằng với `await connection()` và `cacheComponents`, vẫn yêu cầu rằng có một Suspense boundary ở đâu đó phía trên component sử dụng `await connection()`. Nếu bạn không có bất kỳ Suspense boundary cha nào, bạn sẽ cần thêm một nơi phù hợp để mô tả fallback UI.
